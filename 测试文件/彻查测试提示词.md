## 1. 三条方法论（违反任何一条，本轮结论不可信）

- **可执行优先**：任何"发现"必须落成一条能跑的断言，或一个可复现步骤。只给意见不给证据的，一律标 `未验证`，不计入结论。
- **枚举优先于扫读**：先让机器列出全部面（端点 / UI 控件 / 不变量 / 文件类型 / 解析入口），再逐面打勾。**没进清单的面 = 下一轮的漏网之鱼**。
- **盲区必须可见**：每轮结束必须写出"本轮新覆盖什么 / 还剩什么没覆盖"。清单长度下降就是成功。

## 2. 护栏（硬约束，来自 AGENTS.md）

- `content/` 是唯一不可再生资产。**任何测试都不得读写真实语料**——照 `tests/test_reader.py` 的做法用 `tempfile` 造迷你语料。
- 提交只用**显式 pathspec**：`git commit -F msg -- <自己改的文件>`。**禁止** `git add -A` / `git add .`。
- **不碰别的会话改过的文件**。开工前 `git status` 看归属；工作区脏就只提交自己的。同一文件混了别人的改动时，只提交自己那段。
- 未跑测试不得宣称"完成"；汇报要贴**原始命令输出**。
- 临时产物只进 `.qa/`（不进 git）；验证类脚本**不要落盘 txt**，直接看 stdout。
- 禁 `git push -f`、禁改写 main。`indexes/` 是纯派生缓存，可删不可手改。
- 新测试脚本沿用仓库风格：`# -*- coding: utf-8 -*-` + `sys.path.insert` + 独立可执行 + 失败时非 0 退出码。**不要擅自引入 pytest 生态**（除非按 P6 做出明确决策）。
- 需要 RAG 依赖时用 `.python\python.exe`（与 `start.bat` 同一套）；裸 `python` 可能缺 onnxruntime。
- 验证 UI 时起**临时实例**，绝不动用户的 5001：
  `python -c "import sys;sys.path.insert(0,'.');from app.app import create_app;a=create_app();a.run(host='127.0.0.1',port=5031)"`
  收工：`powershell -Command 'Get-NetTCPConnection -LocalPort 5031 -State Listen -EA SilentlyContinue | Select -Exp OwningProcess -Uniq | %{ Stop-Process -Id $_ -Force }'`
  **改了模板必须重启临时实例**（非 debug 模式 Jinja 缓存模板）。

## P0 · 建立覆盖面清单（必做第一步，零依赖，最高杠杆）

**目标**：把"要查什么"从主观变成机器枚举的清单。

1. **端点清单**（权威来源是 Flask url_map，不是 grep）：
   ```
   python -c "import sys;sys.path.insert(0,'.');from app.app import create_app;app=create_app();[print(sorted(r.methods-{'HEAD','OPTIONS'}),r.rule,'->',r.endpoint) for r in sorted(app.url_map.iter_rules(),key=lambda x:x.rule)]"
   ```
   与 `grep -rhoE '@[a-z_]+_bp\.(get|post|delete|put|route)\("[^"]+"' app/*.py | wc -l` 的数量对照，**对不上就说明有动态注册或被注释的死路由，本身就是发现**。
2. **UI 控件清单**：从 `app/templates/*.html` + `static/*.js` 提取 `id=` / `onclick=` / `data-act=` / `<button`，按面板分组（顶栏 / 左树 / 读数头 / 正文 / 右栏五页签 / 设置抽屉四页签 / 右键菜单 / 快捷键）。
3. **文件类型处理面**：`.md .html .txt .epub .pdf .xlsx .mobi`（`store.LIBRARY_EXTS` + WRITABLE_EXTS）+ 旁挂件 `.notes.md` / 同名 `.html` 美化版 —— 每种都要有"入口 / 渲染 / 编辑 / 删除 / 索引与否"四项结论。
4. **解析入口清单**（历史 bug 高发，注意**分侧**）：
   - Python 侧：`store.py` frontmatter 解析与写回、`_safe_rel` 路径校验、taxonomy 改名迁移、`fts.py` 双链解析、`rag.py` 切块/分词、`sm2.py` 排程。
   - **JS 侧**：`KBNOVEL.decodeTxt`（BOM→UTF-8→GB18030→Big5）、`normalizeEpub`（OPF/NCX href 解码）、`CHAP_RE`/`buildChapters`、`loadPos/savePos`。
     ⚠️ 这几个在浏览器里，**hypothesis / Atheris 打不到**，JS 侧测试走 P3-B / P7-B。
     （2026-09-24 轮次 14 更新：`normalizeEpub` 已拆成 `normalizeEpubBytes(buf)` + 薄壳 `normalizeEpub(href)`，
     连同 `buildChapters` / `CHAP_RE` / `ensureEpubLib` 一起挂到 `KBNOVEL.*`，P3-B 已落地
     `tests/test_js_props.py` —— 明细与定点变异验证见台账 §12。）
5. **不变量清单**：把 `AGENTS.md` 的 1-8 条逐条抄进台账，每条留"可执行化？是/否"列。
6. 全部写进 `测试文件/覆盖台账.md`。

**通过标准**：五类清单总数明确，每个条目都有"覆盖状态"列（未测 / 单测 / E2E / 人工 / 不适用+理由）。

## P1 · 静态层补漏（零到低成本，先抓现成漏洞）

**已知缺口（我已核实，直接验证并修）**：
- `npm run lint:js` 的路径清单**不含 `static/kb-novel.js`** → 小说引擎完全没被 eslint 扫过。
- `.githooks/pre-commit` **不跑 eslint 也不跑 stylelint** → JS/CSS 静态问题可无阻拦进主干。
- 建议：`lint:js` 补上 `static/kb-novel.js`；把 `npm run lint` 与 `lint:css` 接进 pre-commit（照 `check_dangling_tokens.py` 的"缺依赖就 SKIP 而非报错"风格，避免钩子一跑就挂）。

**可选加层**（`pip install bandit semgrep`，跨平台 OK）：
- `bandit -r app scripts` —— 盯 `subprocess`/`shell=True`/路径拼接/pickle。
- `semgrep --config p/default`（或离线缓存规则包）—— 路径穿越、`except Exception` 吞异常、未校验的 `request.form` 直用。
- 本仓库特别值得写的自定义规则：**`except Exception` 静默吞掉**（AGENTS.md 已记录 F821 被吞成错数的教训）。

**不建议**：给全仓上 `mypy --strict`。现有代码无注解，噪声成本远大于收益；若要用，只对新增 `tests/` 开。

**通过标准**：每条告警要么修、要么显式 ignore 并写明理由。禁止"看着不像问题"就跳过。

## P2 · 把不变量编译成可执行门禁（最高性价比，纯标准库，零新依赖）

**目标**：AGENTS.md 8 条不变量从"给人读的提醒"变成"违反了提不进去"。
新建 `tests/test_invariants.py`（独立脚本风格），逐条落断言：

- **I1 单一真相**：对临时语料调 `api_save` / `api_note` / `api_favorite` 后，断言磁盘文件内容与 frontmatter 确实变了；断言不存在任何"第二真相"存储路径。
- **I2 `_` 前缀不进树/不进索引**：临时语料放 `_foo/`、`_inbox/`、`_assets/`，断言 `build_tree()` 与 FTS/RAG 索引结果都不含它们。
- **I3 indexes/ 可弃**：`git check-ignore indexes/index.db` 为真；删光 `indexes/` 后重启能自动全量重建且结果一致。
- **I4 删除必走软删**：调 `/api/delete` 后断言文件出现在 `content/_trash/<ts>/` 且原路径消失。**并 grep 全仓 `os.remove` / `shutil.rmtree` / `Path.unlink` 调用点，逐个判定是否构成物理删除语料的路径** —— 这类"审计式 grep"最容易抓出真漏洞。
- **I5 分类学权威在 JSON**：改临时 `taxonomy.json` 某域显示名，断言读出新名；断言代码内字典只在 JSON 缺字段时兜底。
- **I6 frontmatter 不存运行时数据**：列出所有写 frontmatter 的字段白名单（title/source/collected/tags/favorite/status），断言无阅读统计类字段混入。
- **I7 切块/分词变更必须递增 `RAG_CODE_VERSION`**：做成 pre-commit 静态检查 —— 若 `git diff` 命中 `app/rag.py` 的切块/分词函数体而 `RAG_CODE_VERSION` 未变，拒绝提交。
- **I8 不依赖 cwd**：从 `C:\` 等别的工作目录跑 `python <绝对路径>/app/app.py --import-check` 必须通过（AGENTS.md 记录过"测试全绿但直启崩"的教训）。

**通过标准**：8 条各有 ≥1 条可执行断言，且接入 `.githooks/pre-commit` 与 `ci.yml`。

## P3 · 性质测试（property-based）

**A. Python 侧**（`pip install hypothesis`，纯 Python，Windows 无障碍；`@given` 不依赖 pytest，外面套 `main()` 即可保持脚本风格）

按"历史 bug 密度"排序的靶面：
1. `_safe_rel` 路径校验：任意输入（`../`、绝对路径、盘符、URL 编码、`~`、NUL、超长、空、仅斜杠、混合分隔符）必须**要么解析到 `content/` 内、要么明确拒绝**，永不越界。
2. frontmatter 解析↔写回 round-trip：任意 title/tags/source/status（含引号、冒号、换行、中文、`[[双链]]`、反斜杠、`---` 出现在正文）写入再读出必须等价，且**正文零污染**（配合 `scripts/agent/scan_fm.py`）。
3. taxonomy 改名/迁移：改名前后**文件总数不变、无丢失**、`subs` 键映射一致、域显示名生效。
4. `fts.py` 双链解析：代码块 / 行内 code 内的 `[[...]]` 不算链接；任意文本喂进去不抛异常。
5. `rag.py` 切块：切块拼接可还原原文（或长度守恒）；任意输入不崩。
6. `sm2.py` 排程：任意评分序列下间隔单调合理、不出现负数/NaN/死循环。

**B. JS 侧**（走 CDP，用现成 `scripts/agent/evalcdp.mjs`，别新造轮子）
- 前提：把 `normalizeEpub`、`buildChapters`、`CHAP_RE` 也挂到 `KBNOVEL.*`（目前只导出了 `decodeTxt`）—— **这本身就是一条可提的改进**。
- 性质：`decodeTxt` 对任意字节序列不得抛未捕获异常；带 BOM 的 UTF-8 必须按 UTF-8 解；`buildChapters` 对任意文本产出的章节数 ≥1 且段落无丢失。
- 畸形样本用 Python 生成到 `.qa/`，经 `/raw/` 提供，断言"不崩 + 有用户可见降级提示"。

**通过标准**：每条性质 ≥200 examples 通过；任何反例固化为**确定性**回归用例（不许只留在 hypothesis 的随机里）。

## P4 · 端到端冒烟（零新依赖，复用仓库 CDP 工具）

起 5031 临时实例（见 §2），用 `evalcdp.mjs` 遍历：

1. **每个端点**：GET 断 2xx / 预期重定向；POST 用最小合法 body 断 `ok:true`；非法入参断 4xx 且**错误信息不泄露绝对路径**。
2. **每种文档类型各一篇真语料**（md / html / txt / epub / pdf / xlsx / mobi）：断言无 console error、正文区非空、右栏目录非空、工具栏存在。
   - epub 至少覆盖：正常书 + **多看版畸形编码书**（`content/小说/` 下有现成样本）。
3. **每个域/子域至少一篇**；`_inbox` / `_trash` / `_meta` / `_unfiled` 行为单独断言。
4. **每个 UI 控件点一次**，断言：无 JS 异常、状态有变化、不越权写盘。
5. **断链**：全站内部链接可达（把 `check_dangling_tokens.py` 的思路从 CSS 令牌扩到 URL）。
6. **关键不变行为**（都是本仓库真实踩过的坑，必须长期断言）：
   - 改阅读偏好**不得**重置续读位置（epub `flow()` 教训）。
   - 书库页 crumb 按钮隐藏、md 页按钮齐全。
   - 长标题不被 ellipsis 截断。

**硬性要求**：把"无 CONSOLE_ERRORS"变成断言，不是"我看了一眼没报错"。本仓库历史 bug 大量表现为**静默 JS 异常**。

**通过标准**：P0 端点/控件清单里 **100%** 有记录（通过/失败/不适用+理由）。

## P5 · 视觉回归自动化（把手工 imgdiff 变批处理）

- 基线进 `.qa/qa-shots/`：**明/暗两态 × 关键页面**（阅读页 md/html/txt/epub、设置抽屉四页签、分类树、收件箱、统计、治理、复习、术语门户）。
- 写一个批处理（一次性放 `.qa/`；确认长期用再收进 `scripts/agent/`）：逐页 `shot.mjs` → `imgdiff.mjs`（默认 2% 容差）→ 热图落盘。

- 顺带覆盖窄窗（≤900px）与全屏态。

**通过标准**：P0 页面清单每页有基线，且一条命令可全量复跑。

## P6 · 变异测试（度量"现有断言到底咬不咬得住"，成本中高，有前置决策）

**现实约束（必须先决策）**：`mutmut` / `cosmic-ray` 都假设 pytest 运行器，而本仓库是独立脚本风格。二选一：

- **方案 B（推荐先做，零依赖、当天出结果）**：写 `.qa/mutate.py`，对 `app/store.py`、`app/rag.py`、`app/learn.py` 的关键判定做单点变异（`<`→`<=`、`==`→`!=`、`and`→`or`、删一个分支、边界 ±1），逐个跑现有 5 套 smoke，统计**存活变异体**。
- **方案 A（只有要把变异测试长期纳入 CI 才做）**：引入 pytest 作为**运行器**（不改测试逻辑，但需把断言整理成 `test_` 函数），再上 `mutmut`。工作量中等，属于架构决策，**动手前先跟用户对齐**。

**通过标准**：产出存活变异体清单，每条要么补测试、要么标注"等价变异（代码上无法区分）"并说明。

> 这一层是唯一直接回答"我为什么老漏 bug"的：**漏的不是因为你没看，是因为没有东西能证伪你的测试。**

## P7 · 解析器 fuzz（诚实评估平台限制）

- **Atheris 在 Windows 上构建困难**（需 clang 工具链）。别硬上。
- 有 WSL：Atheris 打 Python 侧解析器（frontmatter / `_safe_rel` / fts / rag 切块），5–10 分钟即有产出。
- **纯 Windows 方案（推荐）**：语料驱动伪 fuzz —— 收集 `content/` 真实 txt/epub + 手工构造畸形样本（截断 zip、缺 `container.xml`、href 指向不存在条目、OPF/NCX 编码不一致、BOM 变体、混合编码、超长行、NUL、空 spine），批量喂进解析入口（Python 侧直调、JS 侧走 P3-B），断言**不崩 + 降级路径给出用户可见提示**。
- 理由：本仓库最近三个 bug（txt 乱码、epub href 错乱致 No Section Found、封面图编码错乱致空白）**全在这条线上**，值得专列一层。

**通过标准**：畸形样本集进回归（不是一次性脚本）。

## P8 · 交互与美观（没有 oracle，只出问题清单，不出"分数"）

明确：这一层产不出证明，**不要拿它当质量指标**。但要用固定清单，避免每次凭感觉。

**通用走查（Nielsen 十则本地化）**：状态可见 / 系统↔现实一致 / 用户可控与退出 / 一致性与标准 / 防错 / 识别优于回忆 / 灵活高效 / 美观极简 / 错误可识别可恢复 / 帮助。

**本仓库专属检查项（历史踩坑，逐条过）**：
- 视觉口味：**黑字白底、边框克制**；禁灰字堆叠、禁绿色作主色、禁卡通插画/mascot。
- 动效须"不可能看不见"；任何 UI 改动跑 imgdiff 验"改 A 崩 B"。
- 中文/长文本不得被 ellipsis 截断（网文标题教训）。
- **改设置不得丢状态**（epub flow 教训）——凡设置面板，必测"改完前后用户位置/选中/展开态是否保持"。
- 空态 / 加载态 / 失败态三态是否都有明确呈现（骨架、提示、降级下载）。
- 破坏性操作是否有确认、是否可撤销、是否走软删。
- 窄窗 ≤900px 与全屏态各走一遍。

**通过标准**：清单 × 关键页面有结论；问题按 **数据丢失 > 功能错误 > 交互误导 > 美观** 排序，前两类必修。

## P9 · 固化（唯一会复利的动作）

1. 每个真实发现的 bug：**先写复现断言（红），再修（绿）**，永久留在 `tests/` 或 P4 清单里。
2. 可机械化的检查接进 `.githooks/pre-commit` 与 `.github/workflows/ci.yml`，照 `check_dangling_tokens.py` 的**纯标准库、缺依赖即 SKIP** 风格，别加脆弱依赖。
3. 更新 `测试文件/覆盖台账.md`：状态列从"未测"变"单测/E2E/门禁"。
4. 一轮彻查结束写一份 `docs/handoff-YYYYMMDDNN.md`（AGENTS.md 命名规范），含五节 + 台账快照。

## 5. 多轮策略（治"每次都有漏网之鱼"）

1. **分模块窄授权**：一个会话只查一个模块（如"只查 `store.py` + 其路由"），强制输出"读了哪些文件、跑了哪些检查、加了哪些断言、还剩哪些面没碰"。宽泛授权必然导致跳读。
2. **换模型做独立 pass**：同一模型两次彻查的盲区高度相关。第二轮换不同模型，只查第一轮台账里"未覆盖"的格子。
3. **禁止重复劳动**：每轮开工先读台账，**只碰"未测"状态项**。已覆盖项只在改动该模块时重跑，不重新"审查"。
4. **每轮必须有数字**：本轮覆盖 N 格 / 剩余 M 格 / M 比上轮减少多少。没有数字就无法判断有没有在变好。

## 6. 一句话给执行者

不要试图"一次查干净"。你的任务是：**把面枚举出来、把检查变成能跑的、把没覆盖的写下来**。清单长度单调下降，就是成功。
