# 知库彻查 · 覆盖台账

> 用途：把"查过了"从主观变成可计数。**每轮彻查开工前先读本文件，只碰"未测"项；收工必须更新本文件并给出覆盖数字。**
> 状态取值：`未测` / `单测` / `E2E` / `门禁`(pre-commit 或 CI 拦得住) / `人工` / `不适用+理由`
> 严重度：`数据丢失` > `功能错误` > `交互误导` > `美观`

**P0 填写口径（2026-09-23，重要）**
- P0 只做**枚举**，不执行任何行为验证。因此**除 §1 中"已有 smoke 真实发 HTTP 请求"的端点记为 `单测` 外，本轮所有格子一律 `未测`**。
- §1 `有测试?` 的判定标准是机器可复现的硬标准：该路径**以字面量形式出现在 `tests/*.py` 的真实 HTTP 调用里**（`app.test_client()` + `.get/.post("...")`），且调用点附近有 `check(...)` 断言。字符串出现在注释/文档里不算。
- §2 的四态列（正常/空/加载/失败）本轮**一律记 `未测`**，包括结构上不适用的控件——不设主观豁免，避免"我觉得它没有空态"式推断混进结论。四态由 P4/P8 填写。
- §4 的"可执行化?"回答的是"**现在是否已有**可跑断言"，**不是**"理论上能否做到"。因此 P0 阶段 8 条全为 `否`；P2 的产出目标是把它们变成 `是`。
- 本轮**未执行**任何 UI / 服务器 / 网络 / 装包操作；结论全部来自只读命令输出与代码通读。

> 控制组每跑一个变异体都要起一次浏览器（单轮约 40s × 146 ≈ 100 分钟）——按 §10 的边际判断不划算，
> 故只在 JS 侧做**定点手工变异 9 处**验证断言会红（§12.3）。

## 10. 变异测试明细（轮次 6 · P6 方案 B · 零依赖手工变异 · 2026-09-23）

> 工具：`.qa/mut_hook.py`（import 期源码注入）+ `.qa/mutate.py`（ast 定位 + 编排）+ `.qa/mut_child.py`（子进程入口）
> + `.qa/p6_verdicts.py`（终判）+ `.qa/p6_micro.py`（单点行为复核）。**全部在 `.qa/`，不进 git。**
> 原始数据：`.qa/p6-manifest.json`（149 条变异体坐标）、`.qa/p6-mutation-report.json`（逐条结果 + 证据尾）、
> `.qa/p6-cover.json`（8 套各自执行过的行）、`.qa/p6-run.log`（全量跑动日志）。

### 10.1 方法与口径

**变异注入方式（本轮最关键的工程决策，实测成立）**：**不复制仓库、不就地改文件**，而是注册一个
`importlib.abc.MetaPathFinder`，在目标模块被 import 时从磁盘读原始源码、按**字符偏移切片**替换一处 token、
`compile()` 后 `exec` 进模块字典。磁盘源码全程只读（收工复核见 §10.7 末）。

**定位方式**：`ast.walk` 遍历，只接受出现在 `If.test` / `While.test` / `IfExp.test` / `Return.value` /
`Assert.test` / `Subscript.slice` / `range(...)` 实参这些**判定位置**子树里的
`Compare` / `BoolOp` / `UnaryOp(Not)` / `Constant(int)` / `BinOp(Add|Sub)`，
按 `lineno`/`col_offset`/`end_*` 换算成源码偏移，再在该节点左右子节点的**间隙**里精确取运算符 token
（`gap_op`）。天然避开注释与字符串字面量，不靠裸 grep。

**算子集**：`<`→`<=`、`>`→`>=`、`<=`→`<`、`>=`→`>`、`==`→`!=`、`!=`→`==`、`and`<->`or`、删 `not `、
整常量 ±1（两个方向各算一个变异体）、`+`<->`-`。链式比较（`0 <= q <= 5`）逐算子出变异体。

**配额（总量 149，落在 80~150 预算内；文件内按 compare 3 / boolop 2 / not 2 / binop 1 / const 2 加权轮转取样）**

| 文件 | 物理行 | 原始候选 | 入池 | 优先级依据 |
|---|---|---|---|---|
| `app/sm2.py` | 93 | 41 | **41（全取）** | 排程边界，手册定的第一优先级 |
| `app/store.py` | 885 | 160 | **34** | frontmatter / 可见性谓词 / 路径 |
| `app/fts.py` | 271 | 45 | **28** | 双链解析 |
| `app/learn.py` | 1231 | 274 | **18** | 同步与抽卡 |
| `app/cards.py` | 713 | 159 | **14** | 切块与判分 |
| `app/rag.py` | 574 | 143 | **14** | 切块 `_flush`/`_merge_short`、分词 |
| **合计** | — | **822** | **149** | 入池按类别：compare 43 / const 60 / boolop 21 / not 18 / binop 7 |

**执行模型**：**每个变异体一个全新顶层子进程**，在其中依次跑 8 套 smoke（每套再各起独立进程，保证互不污染），
记录每套的 rc / 耗时 / 输出尾。子进程 `cwd` = 仓库根，**不设 `KB_ROOT`**（避免改变测试语义）。单套超时 120s。
全量 149 × 8 = **1192 次测试执行，实跑 2344s（39 分钟）**。

**对照**：同一套子进程外壳、同一份 env（含 `PYTHONIOENCODING=utf-8`）不带变异跑一遍 → **8/8 rc=0（12.7s）**。

**「杀死」判定（手册要求区分，本轮按此执行）**

| 判定 | 规则 | 是否算有效保护 |
|---|---|---|
| **断言式杀死 assert** | 输出里 `N failed` 且 N>0，或 traceback 含 `AssertionError` | **是**（主口径） |
| **崩溃式杀死 crash** | 非 0 退出 + traceback 但不是断言失败（TypeError / KeyError / ValueError / SyncBusy…） | 否（只证明"这行跑到了且改坏会炸"，不证明行为被比较过） |
| **挂起 hang** | 超 120s 被杀 | 否（本轮 0 条） |
| **存活 survived** | 8 套全 rc=0 | — |
| **作废 invalid** | `old` 定位失败（子进程硬退出 97）或 `compile()` 不过（生成期就过滤） | 不计入分母（本轮 0 条，故三个分母同为 149） |

**存活归因**：另跑一遍 `sys.settrace` 行覆盖（`.qa/p6-cover.json`），把每条存活变异所在的物理行
是否被哪几套执行过查出来 —— 由此才能把"存活"拆成**「完全无覆盖」**（该行从未执行，最有价值的发现）与
**「有执行无断言」**（跑到了但没人比较结果）。

### 10.7 本轮方法学踩的坑（写给下一轮，别重复交学费）

1. **夹具假杀死（最危险）**：`subprocess` 接管 stdout 后子进程默认按 **cp936** 编码，测试里打印 `U+FFFD`
   之类字符会抛 `UnicodeEncodeError`，被误记成"变异被杀死"。第一版 #76 就是这么被污染的。
   **修法**：子进程 env 固定 `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`，并且**对照跑必须走同一个外壳**
   （本轮收工前对照 = 8 套全 rc=0 / 12.7s，与变异跑同一代码路径）。
2. **`sys.settrace` 返回 `None` 会掐断传播**：只想采 6 个靶面文件，于是给非靶面帧返回 None →
   `tests → app.app → app.store` 的跨模块调用链整段采不到行（sm2 只记到 3 行）。**修法**：本地 trace 函数
   **每帧都返回自身**，按 `co_filename` 过滤记录。修好后 sm2 41 行 / store 523 行。
   教训：**覆盖数据错会伪装成"等价变异"，把真缺口洗白。**
3. **绝不能用 `id(src)` 做偏移缓存**：字符串对象会被回收，跨文件读源码时 `id()` 复用会让 `line_offsets`
   取到**另一个文件**的偏移，变异落在完全无关的位置。本轮第一版就有这颗雷，实测侥幸没炸
   （149 条全部逐条校验 `src[start:end] == old` 且整行内容与预期匹配，`mismatch=0`）。
   已改为显式传 `offs`；**改完重建 manifest 与改前逐字段 100% 相同**，故矩阵结论有效。
4. **变异未生效必须硬失败**：`arm_at` 定位失败若只返回 False，子进程会拿着未改的源码跑完 8 套全绿 →
   **伪装成"变异存活"**。现改为退出码 97 并在编排里记 `arm_failed` → 状态 `invalid`（本轮 0 条）。
5. **等价变异要靠"同位反证"**：`row[-1]`（#86）与 `row[1]`（#87）在同一行同一 token 上，一个存活一个被
   5 套咬死 —— 这种"孪生对"是证明"注入真的生效 + 该行真的被执行"的最硬证据。**下一轮判定等价前先找孪生对。**
6. **`.qa/` 不进 git**，所以本轮所有复现命令只在这台机器上有效。若要把 P6 变成可反复跑的常规（手册 §P9），
   须把 `mutate.py / mut_hook.py / mut_child.py` 收进 `scripts/agent/`（那里进 git），
   并决定"要不要把变异测试挂进 CI"（跑一次 39 分钟，只能当周期性门禁而非 pre-commit）——**这是架构决策，留给主控**。

**收工自检（本轮实测，全部零改动）**：`git status --short` 开工前后均为空；
`python .qa/mutate.py tree` 在开跑前后各跑一次，`content/` = **1769 文件 / 418,647,095 字节 /
滚动哈希 `10123332024072306501`，两次逐字节一致**；未起任何监听端口（全部走 `test_client()` / 直调函数）；
未安装任何依赖；`app/ static/ tests/ content/` 一字节未改。


> **主控复核补记（本轮踩到的第二个方法学坑，比 §10.7 前几条更阴）**：变异矩阵的杀伤归因**默认「无变异时 8 套全绿」这个控制组前提**。本轮我在给 `tests/test_rag.py` 补断言时新用了一次 `Path.unlink()`（临时目录里的清理），这恰好触发 `tests/test_invariants.py::I4` 的「删除类调用点白名单」——I4 未登记该调用点 → **控制组里 invariants 变红** → 此后每一个变异体都被记成「killed by invariants」，一批 18 个变异体的杀伤率被虚报成 **100%**。发现后把该清理换成 `write_bytes(b"")`、确认 `mutate.py control` 回到 8/8 再复跑，同一批的真实结果是 20/32。**教训：每补一次断言、每碰一次门禁，都必须先重跑 `mutate.py control`，控制组不绿时的任何杀伤数字都不可信。**下一轮应把「控制组先绿」做成 `run` 的硬前置（当前 `run` 不查控制组，只信 rc）。

| 切分 | 10 个章节文本：无章节、单章、120 章、超长标题、混合数字与楔子、CRLF、**末章只有标题**、**首标题前有正文**、纯空白、空串 | 章节数 ≥1；**逐行**口径"一行都不能丢"；每样本的**带标题章数**逐条钉死 |
| 续读 | 9 个 `savePos`/`loadPos` 探针：往返、覆盖写、键隔离、2000 字超长 rel、缺失键、循环引用、`undefined` 键、坏 JSON、存的不是对象 | 不抛 **且值对**（只断"不抛"会被 §12.4 第 1 条骗过去） |

### 12.3 定点变异验证（把 JS 改坏 9 处，看断言会不会红）

Python 侧有 146 个变异体做规模化度量，JS 侧没有变异器，所以用**手工定点**验证，逐条实跑：

| # | 把源码改成 | 结果 |
|---|---|---|
| 1 | `normalizeEpubBytes` 里 `dec(clean)` → `clean`（不再解码 href） | **1 红**（多看版样本） |
| 2 | `if (!fixes) return null` 改成恒不返回 null（正常书也被重写一遍） | **3 红** |
| 3 | container 判据取反 `if (container) return null` | **3 红**（含"不认识的包不动手"两条） |
| 4 | `loadPos` 的 try/catch 摘掉 | **2 红**（corruptJson / scalarStored 探针抛异常） |
| 5 | `savePos` 的 try/catch 摘掉 | **2 红**（circular 探针 `THREW: Converting circular structure to JSON`） |
| 6 | 末章 push 的 `||` 改 `&&` | **1 红**（`trailing-title` 的 titled 2→1） |
| 7 | 过渡 push 的 `||` 改 `&&` | **2 红**（`preamble` 的 n 3→2 且丢行） |
| 8 | `c.paras = c.lines.slice(1).join(...)`（每章吞掉首行） | **2 红**，明细里点名 7 个样本共 130 行丢失 |
| 9 | `decodeTxt` 的 BOM 分支摘掉 | **全绿 = 等价变异**：`new TextDecoder("utf-8")` 默认 `ignoreBOM:false`，本来就会吃掉前导 BOM。那条 `if` 不是错，只是"不依赖运行时默认值"的显式保险，**保留**；记在这里防下一轮把它当未覆盖分支乱改 |

**8 处改坏必红、1 处证明等价** —— 这条线从 0 网变成有网，且网眼逐个验过。

### 12.4 三条踩过的坑（不记就会有人重踩）

1. **"只断不抛"是假网**。第一轮 `KBNOVEL` 因缺 `static/` 根本没加载，10 个 epub 全 error，
   我的"不抛异常"断言照样全绿。任何畸形样本测试都必须同时断**"每个样本都有可判定的结论"**。
2. **"字符总量守恒"会被兜底路径骗过**（§11.2 那个教训的 JS 版）：`buildChapters` 在带标题章数
   < 2 时会整篇兜底成 1 章，把上一版丢掉的分片重新捞回来——于是字符数对得上而章节是错的。
   最后同时用两把尺：逐行"一行都不能丢" + 每样本带标题章数。第 6/7 两处变异就是这两把尺各咬住一个。
3. **红测试自己先崩**（§6 第 22 行）：`FAIL` 详情里带浏览器回来的 U+FFFD，GBK 控制台直接
   `UnicodeEncodeError`，traceback 盖掉了"哪条红了"。修法是打印路径上过一个 `_safe()`，
   不是去手挑字符——数据驱动的字符挑不干净。

### 12.5 接线、代价与残留

已进 `.githooks/pre-commit`（第 11 套，紧跟 `test_properties`）与 `ci.yml`；两处都靠脚本自探测
node/Chrome，缺任一个打 `SKIP` 返回 0，**不会因环境把钩子挂住**。本机全套约 40s（起临时实例占大头）。
**未进变异器 `SUITES`**：它是 JS 的驱动器，对 Python 变异池贡献为 0，而每跑一个变异体都要起一次浏览器
（约 40s × 146 ≈ 100 分钟）——不划算，故只做 §12.3 的定点手工变异。

残留（诚实登记）：`app.js` 的正文预处理（`sanitizeFences` / `enhanceArticleDOM`）仍未挂 window、仍无网；
`normalizeEpubBytes` 只测到字节层，"重写后的 ArrayBuffer 真能被 epub.js 渲染出章节"仍靠手工；
`epub.min.js` 渲染本身不在覆盖面内。§5 表里 JS 5 行因此是 4 行已覆盖 + 1 行未测。
