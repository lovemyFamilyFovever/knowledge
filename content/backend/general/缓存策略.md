# 缓存策略

## 缓存

**一句话定义：** 缓存是把常用数据存在快速访问位置，避免重复计算或查询的技术。

**通俗类比：** 缓存就像把常用的书放在书桌上——不用每次都去书架（数据库）找，直接从桌面（缓存）拿。

### 缓存层级

```
浏览器缓存（最快，最近）
    ↓
CDN缓存
    ↓
应用缓存（Redis/Memcached）
    ↓
数据库（最慢，最远）
```

### HTTP缓存

**强缓存：**
```
Cache-Control: max-age=3600    // 1小时内直接用缓存
Expires: Thu, 01 Dec 2024 16:00:00 GMT  // 过期时间
```

**协商缓存：**
```
Etag: "abc123"           // 文件指纹
If-None-Match: "abc123"  // 问服务器：变了吗？
→ 304 Not Modified       // 没变，用缓存
→ 200 + 新内容           // 变了，返回新的
```

### Redis缓存策略

**Cache Aside（旁路缓存）**
```python
def get_user(user_id):
    # 1. 先查缓存
    data = redis.get(f"user:{user_id}")
    if data:
        return json.loads(data)
    # 2. 缓存没有，查数据库
    user = db.query(User).get(user_id)
    # 3. 写入缓存
    redis.setex(f"user:{user_id}", 3600, json.dumps(user))
    return user
```

**Cache Penetration（缓存穿透）**
- 问题：查询不存在的数据，每次都穿透到数据库
- 解决：缓存空值（短过期时间）或使用布隆过滤器

**Cache Breakdown（缓存击穿）**
- 问题：热点key过期，大量请求同时打到数据库
- 解决：互斥锁（只让一个请求查库）或永不过期+后台更新

**Cache Avalanche（缓存雪崩）**
- 问题：大量key同时过期
- 解决：过期时间加随机值、多级缓存

### 缓存更新策略

| 策略 | 说明 | 适用 |
|------|------|------|
| Cache Aside | 先更新DB，再删缓存 | 通用 |
| Read/Write Through | 缓存代理DB操作 | 一致性要求高 |
| Write Behind | 异步批量写DB | 写多读少 |
