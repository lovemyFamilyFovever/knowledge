# 开源项目运营完全指南

## 1. 开源许可证选择

开源许可证是项目的法律基石，决定了他人如何使用、修改和分发你的代码。选择正确的许可证至关重要。

### 1.1 四大主流许可证对比

| 特性 | MIT | Apache 2.0 | GPL v3 | AGPL v3 |
|------|-----|------------|--------|---------|
| **使用自由度** | 极高 | 高 | 中 | 较低 |
| **是否允许闭源** | 是 | 是 | 否 | 否 |
| **专利保护** | 无 | 明确授权 | 明确授权 | 明确授权 |
| **传染性** | 无 | 弱传染 | 强传染 | 最强传染 |
| **修改后是否必须开源** | 否 | 否 | 是 | 是（含网络服务） |
| **典型项目** | React, jQuery | Android, Kafka | Linux, Git | MongoDB, Grafana |
| **商业化友好度** | ★★★★★ | ★★★★☆ | ★★☆☆☆ | ★☆☆☆☆ |

### 1.2 许可证详细解析

**MIT许可证**：
```text
MIT License

Copyright (c) [year] [fullname]

Permission is hereby granted, free of charge, to any person obtaining a copy
of this software and associated documentation files (the "Software"), to deal
in the Software without restriction, including without limitation the rights
to use, copy, modify, merge, publish, distribute, sublicense, and/or sell
copies of the Software, and to permit persons to whom the Software is
furnished to do so, subject to the following conditions:

The above copyright notice and this permission notice shall be included in all
copies or substantial portions of the Software.

THE SOFTWARE IS PROVIDED "AS IS", WITHOUT WARRANTY OF ANY KIND...
```

**Apache 2.0**：
- 包含专利授权条款，保护贡献者
- 要求保留原始版权声明和许可证
- 修改文件必须注明变更
- 包含明确的专利终止条款

**GPL v3**：
- 强传染性：使用GPL代码的衍生作品必须也采用GPL
- 必须提供源代码
- 包含反TiVo化条款（防止硬件锁定）

**AGPL v3**：
- 网络服务也需要提供源代码
- 适用于SaaS和云服务场景
- 最严格的开源许可证

### 1.3 许可证选择流程图

```
开始
│
├── 是否允许闭源商业使用？──┐
│   ├── 是 ──→ 需要专利保护？──┐
│   │   ├── 是 ──→ Apache 2.0
│   │   └── 否 ──→ MIT
│   └── 否 ──→ 网络服务需要开源？──┐
│       ├── 是 ──→ AGPL v3
│       └── 否 ──→ GPL v3
```

### 1.4 实际选择建议

1. **个人/学术项目**：MIT（简洁友好）
2. **企业基础设施工具**：Apache 2.0（平衡自由度与保护）
3. **希望创建生态系统的项目**：GPL v3（确保生态开放）
4. **SaaS/云服务项目**：AGPL v3（防止云厂商白嫖）

### 2.2 CONTRIBUTING.md - 贡献指南

```markdown
# 贡献指南

感谢您对本项目的兴趣！我们欢迎各种形式的贡献。

## 如何贡献

### 报告问题
1. 使用Issue模板报告bug
2. 提供最小复现示例
3. 包含环境信息

### 提交代码
1. Fork项目仓库
2. 创建特性分支：`git checkout -b feature/amazing-feature`
3. 提交更改：`git commit -m 'feat: add amazing feature'`
4. 推送分支：`git push origin feature/amazing-feature`
5. 创建Pull Request

### 代码规范
- 遵循ESLint配置
- 编写测试用例
- 更新相关文档
- 确保CI通过

### 提交规范
使用[Conventional Commits](https://www.conventionalcommits.org/)：
- `feat:` 新功能
- `fix:` 修复bug
- `docs:` 文档更新
- `style:` 代码格式调整
- `refactor:` 重构
- `test:` 测试相关
- `chore:` 构建/工具链更新

### 分支策略
- `main`: 稳定发布版本
- `develop`: 开发分支
- `feature/*`: 特性分支
- `hotfix/*`: 紧急修复分支
```

## 3. 版本管理

### 3.1 语义化版本（Semantic Versioning）

语义化版本格式：`MAJOR.MINOR.PATCH`

- **MAJOR**：不兼容的API修改
- **MINOR**：向下兼容的功能性新增
- **PATCH**：向下兼容的问题修正

**版本号更新规则**：
```bash
# 修复bug
1.0.0 → 1.0.1

# 新增功能（向下兼容）
1.0.1 → 1.1.0

# 破坏性更改
1.1.0 → 2.0.0

# 预发布版本
1.0.0-alpha.1
1.0.0-beta.1
1.0.0-rc.1
```

## 4. CI/CD自动化（GitHub Actions）

### 4.1 完整的发布流程示例

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    tags:
      - 'v*'

jobs:
  build-test-release:
    runs-on: ubuntu-latest
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
      with:
        fetch-depth: 0
    
    - name: Setup Node.js
      uses: actions/setup-node@v3
      with:
        node-version: '18'
        registry-url: 'https://registry.npmjs.org'
    
    - name: Install dependencies
      run: npm ci
    
    - name: Run tests
      run: npm test -- --coverage
    
    - name: Build project
      run: npm run build
    
    - name: Generate changelog
      id: changelog
      uses: mikepenz/release-changelog-builder-action@v3
      with:
        configuration: "changelog-config.json"
        fromTag: "v1.0.0"
        toTag: ${{ github.ref }}
      env:
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    
    - name: Create GitHub Release
      uses: actions/create-release@v1
      with:
        tag_name: ${{ github.ref }}
        release_name: Release ${{ github.ref }}
        body: |
          ${{ steps.changelog.outputs.changelog }}
          
          ## 📦 安装方式
          
          ```bash
          npm install your-package@${{ github.ref }}
          ```
          
          ## 🔗 相关链接
          - [文档](https://your-docs-site.com)
          - [API参考](https://your-docs-site.com/api)
          - [示例](https://github.com/your-org/examples)
          
          ## 👥 贡献者
          ${{ steps.changelog.outputs.contributors }}
        draft: false
        prerelease: false
      env:
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    
    - name: Publish to npm
      run: npm publish
      env:
        NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
    
    - name: Build Docker image
      uses: docker/build-push-action@v4
      with:
        context: .
        push: true
        tags: |
          your-org/your-package:latest
          your-org/your-package:${{ github.ref }}
        registry: docker.io
      env:
        DOCKER_USERNAME: ${{ secrets.DOCKER_USERNAME }}
        DOCKER_PASSWORD: ${{ secrets.DOCKER_PASSWORD }}
```

    - uses: actions/checkout@v3
    
    - name: Use Node.js ${{ matrix.node-version }}
      uses: actions/setup-node@v3
      with:
        node-version: ${{ matrix.node-version }}
    
    - run: npm ci
    - run: npm run lint
    - run: npm test -- --coverage

### 4.3 多平台构建

```yaml
# .github/workflows/build.yml
name: Build

on:
  push:
    branches: [ main ]

jobs:
  build-matrix:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        arch: [x64, arm64]
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Build for ${{ matrix.os }}-${{ matrix.arch }}
      run: |
        npm ci
        npm run build:${{ matrix.os }}-${{ matrix.arch }}
    
    - name: Upload artifacts
      uses: actions/upload-artifact@v3
      with:
        name: build-${{ matrix.os }}-${{ matrix.arch }}
        path: dist/

### 6.3 自动API文档生成

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import dts from 'vite-plugin-dts'

export default defineConfig({
  plugins: [
    dts({
      include: ['src/**/*.ts'],
      beforeWriteFile: (filePath, content) => {
        // 生成API文档
        generateApiDocs(content)
        return { filePath, content }
      }
    })
  ]
})

// scripts/generate-docs.ts
import * as ts from 'typescript'
import * as fs from 'fs'

function generateApiDocs(sourceCode: string) {
  // 解析TypeScript代码
  const sourceFile = ts.createSourceFile(
    'temp.ts',
    sourceCode,
    ts.ScriptTarget.Latest,
    true
  )
  
  // 提取接口、类型、函数等信息
  const apiDocs = []
  
  function visit(node: ts.Node) {
    if (ts.isInterfaceDeclaration(node)) {
      apiDocs.push({
        type: 'interface',
        name: node.name.text,
        documentation: ts.getJSDocTags(node).map(tag => tag.comment).join('\n')
      })
    }
    
    ts.forEachChild(node, visit)
  }
  
  visit(sourceFile)
  
  // 生成Markdown文档
  const markdown = apiDocs.map(doc => 
    `### ${doc.name}\n\n${doc.documentation}\n`
  ).join('\n')
  
  fs.writeFileSync('docs/api/generated.md', markdown)
}
```

// src/plugin-system.ts
export interface Plugin {
  name: string
  version: string
  install(api: PluginAPI): void
  uninstall(): void
}

export interface PluginAPI {
  registerCommand(name: string, handler: Function): void
  registerHook(hook: string, handler: Function): void
  getConfig(): object
}

export class PluginManager {
  private plugins = new Map<string, Plugin>()
  
  async loadPlugin(plugin: Plugin) {
    if (this.plugins.has(plugin.name)) {
      throw new Error(`Plugin ${plugin.name} already loaded`)
    }
    
    await plugin.install(this.createAPI(plugin.name))
    this.plugins.set(plugin.name, plugin)
    
    console.log(`Plugin ${plugin.name} loaded`)
  }
  
  async unloadPlugin(name: string) {
    const plugin = this.plugins.get(name)
    if (plugin) {
      await plugin.uninstall()
      this.plugins.delete(name)
    }
  }
  
  private createAPI(pluginName: string): PluginAPI {
    return {
      registerCommand: (name, handler) => {
        this.commands.set(`${pluginName}:${name}`, handler)
      },
      registerHook: (hook, handler) => {
        const hooks = this.hooks.get(hook) || []
        hooks.push({ pluginName, handler })
        this.hooks.set(hook, hooks)
      },
      getConfig: () => this.config[pluginName] || {}
    }
  }
}
```

  private tenants = new Map<string, Tenant>()

    // 根据套餐分配资源
    const resources = await this.allocateResources(plan)
    
    const tenant = {
      id: tenantId,
      plan,
      resources,
      createdAt: new Date()
    }
    
    this.tenants.set(tenantId, tenant)
    
    // 初始化数据库
    await this.initializeDatabase(tenantId)
    
    // 部署应用实例
    await this.deployInstance(tenantId, resources)
    
    return tenant
  }
  
  async scaleTenant(tenantId: string, newPlan: PricingPlan) {
    const tenant = this.tenants.get(tenantId)
    if (!tenant) throw new Error('Tenant not found')
    
    // 计算资源差异
    const diff = this.calculateResourceDiff(tenant.plan, newPlan)
    
    // 水平扩展
    if (diff.instances > 0) {
      await this.addInstances(tenantId, diff.instances)
    }
    
    // 垂直扩展
    if (diff.cpu > 0 || diff.memory > 0) {
      await this.upgradeResources(tenantId, diff.cpu, diff.memory)
    }
    
    tenant.plan = newPlan
  }
}
