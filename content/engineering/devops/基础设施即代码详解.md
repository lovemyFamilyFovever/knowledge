# 基础设施即代码详解

## 一句话定义（大白话）
把服务器、网络、数据库这些基础设施用代码文件描述出来，像管理应用代码一样管理它们。

## 通俗类比（生活场景）
想象你要装修房子。传统方式是亲自去建材市场挑选、施工（手动配置服务器）。IaC方式是先用设计软件画好图纸（编写代码），然后机器人按图纸自动采购、施工、验收（自动化部署）。

## 具体示例（代码、命令或操作场景）

**Terraform示例（创建AWS EC2实例）：**
```hcl
# main.tf
provider "aws" {
  region = "us-west-2"
}

resource "aws_instance" "web_server" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
  
  tags = {
    Name = "WebServer"
  }
  
  vpc_security_group_ids = [aws_security_group.web_sg.id]
  subnet_id              = aws_subnet.public_subnet.id
}

resource "aws_security_group" "web_sg" {
  name        = "web-security-group"
  description = "Allow HTTP and SSH"

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

**Ansible Playbook示例（配置Web服务器）：**
```yaml
# web-server.yml
---
- hosts: webservers
  become: yes
  vars:
    http_port: 80
    server_name: example.com

  tasks:
  - name: Install nginx
    apt:
      name: nginx
      state: present
      update_cache: yes

  - name: Copy nginx config
    template:
      src: templates/nginx.conf.j2
      dest: /etc/nginx/nginx.conf
    notify: Restart nginx

  - name: Ensure nginx is running
    service:
      name: nginx
      state: started
      enabled: yes

  handlers:
  - name: Restart nginx
    service:
      name: nginx
      state: restarted
```

## 为什么需要它（解决什么问题）
解决环境不一致、配置漂移、手动操作易出错、环境重建困难等问题。就像有了建筑图纸，无论盖多少栋楼都能保证质量一致。

## 与相关术语的对比和区分
- **Terraform vs Ansible**：Terraform侧重基础设施创建（声明式），Ansible侧重配置管理（过程式），两者可互补
- **声明式 vs 命令式**：声明式描述“要什么”（如创建3台服务器），命令式描述“怎么做”（如先创建VPC再创建子网）
- **配置管理 vs 编排**：配置管理关注单个节点状态，编排关注多节点协作和依赖关系
- **不可变基础设施 vs 可变基础设施**：不可变基础设施部署后不修改，需要更新时替换整个实例；可变基础设施则原地更新
- **GitOps vs 传统CI/CD**：GitOps以Git为唯一真相源，自动同步集群状态；传统CI/CD需要手动触发部署
