## pytest（Python 测试框架）

### 一句话定义（大白话）
pytest 是 Python 最流行的测试框架，语法简洁，功能强大，支持 fixture、参数化、插件扩展等特性。

### 通俗类比（生活场景）
就像一个多功能瑞士军刀——基础功能简单易用，但通过各种插件可以扩展出强大的能力。

### 具体示例

**fixture（测试前置/后置）：**
```python
import pytest

@pytest.fixture
def db_connection():
    """每个测试函数执行前创建连接，执行后关闭"""
    conn = create_connection()
    yield conn
    conn.close()

@pytest.fixture
def sample_user(db_connection):
    """依赖 db_connection fixture"""
    user = {"name": "张三", "email": "test@test.com"}
    db_connection.insert(user)
    return user

def test_get_user(sample_user):
    assert sample_user["name"] == "张三"
```

**parametrize（参数化测试）：**
```python
@pytest.mark.parametrize("input,expected", [
    (1, 2),
    (5, 10),
    (0, 0),
    (-3, -6),
])
def test_double(input, expected):
    assert double(input) == expected
```

**mark（标记测试）：**
```python
@pytest.mark.slow
def test_large_data_processing():
    """标记为慢速测试，可通过 -m slow 选择性运行"""
    pass

@pytest.mark.skip(reason="功能尚未实现")
def test_future_feature():
    pass

@pytest.mark.xfail(reason="已知bug，待修复")
def test_known_bug():
    pass
```

**conftest.py（共享 fixture）：**
```python
# conftest.py - 自动被 pytest 发现
import pytest

@pytest.fixture(scope="session")
def browser():
    """session 级别的 fixture，整个测试会话共享"""
    driver = webdriver.Chrome()
    yield driver
    driver.quit()
```

### 为什么需要它
pytest 简化了测试编写和执行，丰富的插件生态（pytest-cov、pytest-xdist）让测试工作流更高效。

## JUnit 5（Java 测试框架）

### 一句话定义（大白话）
JUnit 5 是 Java 生态的标准测试框架，提供了注解驱动的测试方式，支持参数化、嵌套测试、扩展机制等。

### 通俗类比（生活场景）
就像一个标准化的实验室——每个实验（测试）有明确的准备步骤、执行步骤和清理步骤，一切按规范来。

### 具体示例

```java
import org.junit.jupiter.api.*;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;

import static org.junit.jupiter.api.Assertions.*;

@TestMethodOrder(MethodOrderer.OrderAnnotation.class)
class UserServiceTest {

    private UserService userService;

    @BeforeEach
    void setUp() {
        userService = new UserService();
    }

    @AfterEach
    void tearDown() {
        // 清理每个测试后的状态
        userService.clear();
    }

    @Test
    @Order(1)
    @DisplayName("测试创建用户")
    void testCreateUser() {
        User user = userService.create("张三", "zhangsan@test.com");
        assertNotNull(user.getId());
        assertEquals("张三", user.getName());
    }

    @Test
    @Order(2)
    @DisplayName("测试查找用户 - 用户存在")
    void testFindUser Exists() {
        userService.create("李四", "lisi@test.com");
        User found = userService.findByName("李四");
        assertNotNull(found);
    }

    @Test
    @Order(3)
    @DisplayName("测试查找用户 - 用户不存在")
    void testFindUser NotExist() {
        User found = userService.findByName("不存在");
        assertNull(found);
    }

    @ParameterizedTest
    @CsvSource({
        "1, 2",
        "5, 10",
        "0, 0",
        "-3, -6"
    })
    @DisplayName("测试数字翻倍 - 参数化")
    void testDouble(int input, int expected) {
        assertEquals(expected, Calculator.double(input));
    }
}
```

### 为什么需要它
JUnit 5 是 Java 测试的事实标准，与 Maven/Gradle、IDE 深度集成，是 Java 项目不可或缺的工具。

## Jest（JavaScript 测试框架）

### 一句话定义（大白话）
Jest 是 Facebook 出品的 JavaScript 测试框架，开箱即用，自带断言库、Mock、覆盖率报告，特别适合 React 项目。

### 通俗类比（生活场景）
就像一个全套厨房——锅碗瓢盆、调料酱料全配齐，你只管做饭（写测试），不用到处找工具。

### 具体示例

```javascript
// math.js
export const add = (a, b) => a + b;
export const fetchData = async () => {
    const res = await fetch('/api/data');
    return res.json();
};

// math.test.js
describe('数学函数测试', () => {
    describe('add 函数', () => {
        it('应正确相加两个正数', () => {
            expect(add(2, 3)).toBe(5);
        });

        it('应处理负数', () => {
            expect(add(-1, -2)).toBe(-3);
        });

        it('应处理零', () => {
            expect(add(0, 0)).toBe(0);
        });
    });
});

// Mock 示例
jest.mock('./api');

describe('fetchData', () => {
    it('应返回正确数据', async () => {
        const mockData = { users: [{ id: 1, name: '张三' }] };
        fetch.mockResolvedValue({ json: () => mockData });

        const data = await fetchData();
        expect(data).toEqual(mockData);
        expect(fetch).toHaveBeenCalledWith('/api/data');
    });
});

// Spy 示例
describe('用户服务', () => {
    it('应调用保存方法', () => {
        const spy = jest.spyOn(userService, 'save');
        userService.create({ name: '张三' });
        expect(spy).toHaveBeenCalledTimes(1);
        expect(spy).toHaveBeenCalledWith(
            expect.objectContaining({ name: '张三' })
        );
    });
});
```

### 为什么需要它
Jest 让 JavaScript 测试变得简单，零配置即可运行，是前端项目的首选测试工具。

## Mocha / Chai

### 一句话定义（大白话）
Mocha 是一个灵活的 JavaScript 测试运行框架，Chai 是其常用搭配的断言库，两者组合提供丰富的测试能力。

### 通俗类比（生活场景）
Mocha 是舞台（测试运行器），Chai 是台词（断言方式）——舞台负责组织演出，台词负责表达对错。

### 具体示例

```javascript
const { expect } = require('chai');
const { Calculator } = require('./calculator');

describe('Calculator', function() {
    let calc;

    beforeEach(function() {
        calc = new Calculator();
    });

    afterEach(function() {
        calc.reset();
    });

    describe('#add()', function() {
        it('应返回两数之和', function() {
            expect(calc.add(2, 3)).to.equal(5);
        });

        it('应支持链式调用', function() {
            const result = calc.add(1).add(2).add(3);
            expect(result).to.equal(6);
        });
    });

    describe('#divide()', function() {
        it('除数为零时应抛出错误', function() {
            expect(() => calc.divide(10, 0))
                .to.throw('Division by zero');
        });

        it('应支持浮点数除法', function() {
            expect(calc.divide(10, 3))
                .to.be.closeTo(3.33, 0.01);
        });
    });
});
```

### 为什么需要它
Mocha/Chai 组合灵活度高，适合需要自定义测试行为的项目，尤其在 Node.js 后端测试中广泛使用。

## Selenium WebDriver

### 一句话定义（大白话）
Selenium WebDriver 是一个浏览器自动化工具，可以用代码控制浏览器操作，模拟用户行为进行 Web 测试。

### 通俗类比（生活场景）
就像一个遥控机器人——你可以远程操控它点击网页、填写表单、跳转页面，就像自己在操作一样。

### 具体示例

**元素定位与操作：**
```python
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

driver = webdriver.Chrome()
driver.get('https://example.com')

# 多种元素定位方式
element = driver.find_element(By.ID, 'username')
element = driver.find_element(By.CSS_SELECTOR, 'input[type="email"]')
element = driver.find_element(By.XPATH, '//button[contains(text(),"登录")]')
element = driver.find_element(By.LINK_TEXT, '忘记密码')

# 操作
element.send_keys('admin')
element.click()
```

**等待机制：**
```python
# 显式等待（推荐）
wait = WebDriverWait(driver, 10)
element = wait.until(
    EC.presence_of_element_located((By.ID, 'submit-btn'))
)
element.click()

# 隐式等待（全局）
driver.implicitly_wait(10)

# 自定义等待条件
from selenium.webdriver.support.expected_conditions import (
    element_to_be_clickable,
    visibility_of_element_located
)
```

**Page Object 模式：**
```python
class LoginPage:
    def __init__(self, driver):
        self.driver = driver
        self.username_input = (By.ID, 'username')
        self.password_input = (By.ID, 'password')
        self.login_button = (By.ID, 'login-btn')

    def enter_username(self, username):
        self.driver.find_element(*self.username_input).send_keys(username)
        return self

    def enter_password(self, password):
        self.driver.find_element(*self.password_input).send_keys(password)
        return self

    def click_login(self):
        self.driver.find_element(*self.login_button).click()
        return DashboardPage(self.driver)

# 使用
login_page = LoginPage(driver)
dashboard = login_page.enter_username('admin') \
                      .enter_password('pass') \
                      .click_login()
```

### 为什么需要它
Selenium 是 Web 自动化测试的行业标准，支持多语言、多浏览器，是 E2E 测试的核心工具。

## Cypress

### 一句话定义（大白话）
Cypress 是一个现代 Web 自动化测试工具，主打"时间旅行"调试和自动等待，让 E2E 测试更简单可靠。

### 通俗类比（生活场景）
就像一个录像机——测试每一步都自动截图保存，出问题时可以"倒带"回看每个瞬间，精确定位问题。

### 具体示例

```javascript
describe('电商购物流程', () => {
    beforeEach(() => {
        cy.visit('https://shop.example.com')
        cy.intercept('GET', '/api/products', { fixture: 'products.json' }).as('getProducts')
    })

    it('应能完成完整购物流程', () => {
        // 网络拦截 - 模拟 API 响应
        cy.wait('@getProducts')

        // 自动等待元素可交互
        cy.contains('iPhone 15').click()

        cy.get('[data-cy="add-to-cart"]').click()
        cy.get('[data-cy="cart-count"]').should('contain', '1')

        cy.get('[data-cy="checkout"]').click()
        cy.url().should('include', '/checkout')

        cy.get('[data-cy="shipping-form"]').within(() => {
            cy.get('#name').type('张三')
            cy.get('#address').type('北京市朝阳区')
        })

        cy.get('[data-cy="place-order"]').click()
        cy.contains('订单提交成功').should('be.visible')
    })

    it('应显示产品列表', () => {
        cy.wait('@getProducts')
        cy.get('.product-card').should('have.length.greaterThan', 0)
        cy.get('.product-card').first().within(() => {
            cy.get('.product-name').should('be.visible')
            cy.get('.product-price').should('match', /¥\d+/)
        })
    })
})
```

**时间旅行调试：**
```javascript
// 在 Cypress Test Runner 中：
// 1. 点击任意测试步骤
// 2. 查看该时刻的 DOM 快照
// 3. 查看网络请求/响应
// 4. 查看 console 输出
// 5. 查看 snapshotted state
```

### 为什么需要它
Cypress 解决了 Selenium 的等待问题和调试难题，让 E2E 测试开发体验大幅提升。

```python
        # 多标签页
        page.click('a[href="/products"]')

        # 多浏览器并行测试（pytest-playwright）
        # pytest -n auto 可并行运行
```

## Postman / Newman

### 一句话定义（大白话）
Postman 是 API 测试的可视化工具，Newman 是其命令行版本，用于在 CI/CD 中自动化运行 API 测试。

### 通俗类比（生活场景）
Postman 是 API 的"体检中心"——可视化操作检查每个接口；Newman 是"体检报告打印机"——把检查流程搬到命令行自动化执行。

### 具体示例

**Postman 测试脚本：**
```javascript
// Postman Tests 标签页
pm.test("状态码应为200", function() {
    pm.response.to.have.status(200);
});

pm.test("响应时间应小于500ms", function() {
    pm.expect(pm.response.responseTime).to.be.below(500);
});

pm.test("响应数据应包含用户信息", function() {
    const data = pm.response.json();
    pm.expect(data).to.have.property('name');
    pm.expect(data.name).to.equal('张三');
});

pm.test("响应头应包含正确的内容类型", function() {
    pm.response.to.have.header("Content-Type", "application/json");
});
```

**Newman 命令行运行：**
```bash
# 运行 Postman 集合
newman run collection.json -e environment.json

# 生成 HTML 报告
newman run collection.json \
    -e environment.json \
    --reporters cli,htmlextra \
    --reporter-htmlextra-export report.html

# 在 CI/CD 中使用（GitHub Actions 示例）
# - name: Run API Tests
#   run: |
#     newman run tests/api-collection.json \
#       -e tests/staging-env.json \
#       --reporters cli,junit \
#       --reporter-junit-export results.xml
```

### 为什么需要它
Postman 让 API 测试可视化、易上手；Newman 让 API 测试自动化、可集成到 CI/CD。

## JMeter（压力测试工具）

### 一句话定义（大白话）
JMeter 是 Apache 出品的压力测试工具，可以模拟大量用户并发访问系统，测试系统的性能和稳定性。

### 通俗类比（生活场景）

### 具体示例

**JMeter 测试计划结构：**

```
│   │   ├── HTTP请求 - 登录
│   │   ├── HTTP请求 - 查询商品
│   │   └── HTTP请求 - 下单
│   ├── 断言（Assertion）

│   ├── 定时器（Timer）

│       ├── 查看结果树
```

### 为什么需要它
JMeter 是性能测试的行业标准，免费开源，支持多种协议（HTTP、TCP、JDBC等），社区资源丰富。

## Mockito / Mock.js

### 一句话定义（大白话）
Mockito 是 Java 的 Mock 框架，Mock.js 是前端的 Mock 数据生成工具，两者分别解决后端和前端的测试数据模拟问题。

### 通俗类比（生活场景）
Mockito 是后厨的"样品菜"——外观和真菜一样但不用真食材；Mock.js 是"自动生成菜单"——随机生成各种菜名和价格。

### 具体示例

**Mockito（Java）：**
```java
import org.mockito.Mockito;
import static org.mockito.Mockito.*;

// 创建 Mock 对象
UserRepository mockRepo = mock(UserRepository.class);

// 设置行为
when(mockRepo.findById(1L))
    .thenReturn(Optional.of(new User(1L, "张三")));

// 验证交互
UserService service = new UserService(mockRepo);
User user = service.getUser(1L);
verify(mockRepo, times(1)).findById(1L);

// 捕获参数
ArgumentCaptor<User> captor = ArgumentCaptor.forClass(User.class);
mockRepo.save(captor.capture());
User savedUser = captor.getValue();
```

**Mock.js（JavaScript）：**
```javascript
const Mock = require('mockjs');

// 生成模拟数据
const data = Mock.mock({
    'users|10': [{
        'id|+1': 1,
        'name': '@name',
        'email': '@email',
        'age|18-60': 1,
        'city': '@city',
        'joinDate': '@date("yyyy-MM-dd")'
    }]
});

// 配合 axios-mock-adapter 使用
import MockAdapter from 'axios-mock-adapter';
import axios from 'axios';

const mock = new MockAdapter(axios);
mock.onGet('/api/users').reply(200, data);
```

### 为什么需要它
Mockito 解决后端单元测试中的外部依赖问题，Mock.js 解决前端开发中的后端接口未就绪问题。

## 测试数据管理

### 一句话定义（大白话）
测试数据管理是对测试过程中使用的数据进行创建、维护、清理的系统化方法，确保测试数据的可靠性、隔离性和可重复性。

### 通俗类比（生活场景）
就像实验室管理——每次实验前准备干净的器材（测试数据），实验后清洗归位（数据清理），保证下次实验结果准确。

### 具体示例

```python
# 数据工厂模式
class UserFactory:
    _counter = 0

    @classmethod
    def create(cls, **kwargs):
        cls._counter += 1
        default_data = {
            'name': f'测试用户{cls._counter}',
            'email': f'test{cls._counter}@example.com',
            'phone': f'138{cls._counter:08d}',
        }
        default_data.update(kwargs)
        return User(**default_data)

    @classmethod
    def create_batch(cls, count, **kwargs):
        return [cls.create(**kwargs) for _ in range(count)]

# 测试中使用
def test_user_search():
    users = UserFactory.create_batch(5)
    for user in users:
        db.save(user)

    results = search_users("测试用户")
    assert len(results) == 5

# pytest fixture 管理测试数据
@pytest.fixture
def test_data():
    # Setup: 创建测试数据
    data = create_test_data()
    yield data
    # Teardown: 清理测试数据
    cleanup_test_data(data)
```

### 为什么需要它
测试数据混乱会导致测试结果不可靠、测试间相互干扰、测试难以重复执行。

## 测试环境管理

### 一句话定义（大白话）
测试环境管理是对测试所需的服务器、数据库、配置、依赖服务等进行统一管理和维护的实践。

### 通俗类比（生活场景）
就像管理一个电影片场——灯光、道具、场景都要搭建好，拍完戏（测试完）要恢复原样，下次拍戏（下次测试）还要能用。

### 具体示例

```yaml
# docker-compose.test.yml - 测试环境配置
version: '3.8'
services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - DATABASE_URL=postgres://test:test@db:5432/testdb
      - REDIS_URL=redis://redis:6379
    depends_on:
      - db
      - redis

  db:
    image: postgres:15
    environment:
      - POSTGRES_USER=test
      - POSTGRES_PASSWORD=test
      - POSTGRES_DB=testdb
    volumes:
      - ./test-data/init.sql:/docker-entrypoint-initdb.d/init.sql

  redis:
    image: redis:7-alpine

  # 第三方服务 Mock
  mock-email:
    image: mailhog/mailhog
    ports:
      - "1025:1025"
      - "8025:8025"
```

```bash
# 测试环境启动与清理
docker-compose -f docker-compose.test.yml up -d
pytest --tb=short
docker-compose -f docker-compose.test.yml down -v
```

### 为什么需要它
环境不一致是测试失败的常见原因，统一的环境管理确保"在我电脑上能过"变成"在任何地方都能过"。

## 工具对比总览

### 单元测试框架对比

| 特性 | pytest | JUnit 5 | Jest |
|------|--------|---------|------|
| 语言 | Python | Java | JavaScript |
| 配置 | 纯代码，零配置 | 注解驱动 | 零配置 |
| Fixture | fixture 装置 | @BeforeEach/@AfterEach | beforeEach/afterEach |
| 参数化 | @pytest.mark.parametrize | @ParameterizedTest | test.each |
| Mock | unittest.mock | Mockito | jest.mock |
| 覆盖率 | pytest-cov | JaCoCo | 内置 |
| 插件 | 丰富 | 扩展模型 | 内置丰富 |

### E2E 测试工具对比

| 特性 | Selenium | Cypress | Playwright |
|------|----------|---------|------------|
| 架构 | WebDriver 协议 | 浏览器内运行 | CDP 协议 |
| 等待机制 | 手动等待 | 自动等待 | 自动等待 |
| 调试体验 | 一般 | 时间旅行 | Trace Viewer |
| 多浏览器 | 支持 | 仅 Chromium（部分支持） | Chromium/Firefox/WebKit |
| 速度 | 较慢 | 快 | 快 |
| 并行测试 | 需第三方 | 内置 | 内置 |
| 学习曲线 | 中等 | 低 | 低 |

### API 测试工具对比

| 特性 | Postman/Newman | JMeter | curl |
|------|----------------|--------|------|
| 可视化 | 丰富 | 一般 | 无 |
| 性能测试 | 有限 | 强大 | 无 |
| 自动化 | Newman CLI | CLI | Shell 脚本 |
| 适用场景 | API 调试、简单测试 | 压力测试 | 快速验证 |
| CI/CD 集成 | 支持 | 支持 | 支持 |

### Mock 工具对比

| 特性 | Mockito | Mock.js | unittest.mock |
|------|---------|---------|----------------|
| 适用语言 | Java | JavaScript | Python |
| 主要用途 | Mock 对象行为 | 生成模拟数据 | Mock 对象 |
| 学习曲线 | 中等 | 低 | 低 |
| 集成难度 | 低 | 低 | 低 |

---

## 总结：工具选型指南

```
你的项目是什么语言？
├── Python → pytest + requests/httpx + Playwright
├── Java → JUnit 5 + Mockito + Selenium/Playwright
├── JavaScript/TypeScript
│   ├── React → Jest + React Testing Library + Cypress
│   ├── Vue → Vitest + Vue Test Utils + Cypress
│   └── Node.js → Jest/Vitest + Supertest
└── 全栈/多语言 → Postman(API) + Playwright(E2E)
```

| 场景 | 推荐工具 |
|------|----------|
| 单元测试 | pytest / JUnit 5 / Jest |
| API 测试 | Postman / Newman / Supertest |
| E2E 测试 | Cypress / Playwright |
| 压力测试 | JMeter / k6 / Locust |
| Mock 数据 | Mock.js / Faker.js |
| CI/CD 集成 | Newman / JMeter CLI / k6 Cloud |
