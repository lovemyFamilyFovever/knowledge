# TS 泛型

## 一句话定义

把类型当参数传进去，让输入和输出类型联动。

## 面试官为什么问它

他想知道你的 TS 是不是只会写 any 和 interface——泛型约束与推断是分层的标志。

## 30 秒版回答

泛型是在定义处不写死类型，用类型参数占位，调用时由实参推断出来。价值是让一个函数适配很多类型还不丢具体性，比 any 好的地方是它保住了「传进去什么就返回什么」。关键手段是约束（`T extends { id: string }`）、默认类型、以及用 `keyof T` 把键和值类型绑起来。复杂了就要上条件类型和 infer。

## 被追问三层时的诚实边界

我实际写的是 API 层的响应类型和 store 的通用 getter 这类约束泛型；协变逆变、递归深度的边界情况我遇到过但靠拆类型解决，我的理解是泛型一旦要写注释才能看懂，就该退回具体的类型别名。
