# RESTful API

## 一句话定义

资源用名词、动作用 HTTP 方法、结果用状态码。

## 面试官为什么问它

简历写了 RESTful API（掌握），这是后端面的开场题，也是检查你有没有规范意识的地方。

## 30 秒版回答

核心是按资源建模：URI 是名词的层级，方法表达动作（GET 读、POST 建、PUT 全量替换、PATCH 部分更新、DELETE 删），状态码表达结果，服务无状态、身份靠认证头携带。真正的功力在细节：分页与过滤参数统一、错误响应体结构化（码、消息、可定位的字段）、版本策略（URL 或请求头，选一种别混）、幂等（POST 不幂等所以配幂等键）、以及不要把动词塞进 URL。我做过的补充是接口统一改造，把各家返回的错误体收敛成一份规范。

## 被追问三层时的诚实边界

我实际做过错误体与分页规范、也处理过网关把 HTTP 方法转换掉导致的问题；OAuth 授权服务器与 HATEOAS 我没有实操过，我的理解是后者在真实业务里几乎没人真正做到。
