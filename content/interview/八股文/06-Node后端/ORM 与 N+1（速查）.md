# ORM 与 N+1

## 一句话定义

ORM 用对象方式操作表；N+1 是一次查列表又逐条查关联。

## 面试官为什么问它

他想知道你是不是只会写 ORM 而不知道它发出的 SQL 长什么样。

## 30 秒版回答

ORM 把表映射成对象、把查询变成方法调用，收益是类型安全和迁移可控，代价是生成的 SQL 不总是最优、复杂查询表达困难。N+1 是它的经典病症：先查 1 条列表，再对每条各发一次关联查询，一页数据变成几十条 SQL。解法按优先级是 eager loading 一次 JOIN 出来、用 `IN` 批量取关联、或在数据层用 DataLoader 按批次合并同一轮请求内的重复查询。我会强调：判据是看日志里真实 SQL 数，不是看代码写法。

## 被追问三层时的诚实边界

我实际用的是 Drizzle——它贴近 SQL、生成的语句可读可控，我宁愿多写一点也要避免黑盒；GraphQL 场景下的 DataLoader 批处理我没有实操过，我的理解是它依赖请求级上下文才能正确攒批。
