# cluster 与 worker_threads

## 一句话定义

一个扛连接多个进程，一个把 CPU 活分给多线程。

## 面试官为什么问它

他实际问的是「Node 单线程怎么吃满多核」，以及你会不会选错工具。

## 30 秒版回答

Node 的 JS 执行是单线程，一台多核机器上默认只用一个核。cluster 是 fork 多个进程共享同一个监听端口（主进程或操作系统做连接分发），解决的是 I/O 型服务的多核利用——每个进程内存独立，崩溃互不影响。worker_threads 是在一个进程内起线程并通过消息或共享内存交换数据，适合 CPU 密集的单件任务：图像/视频处理、加解密、大 JSON 解析。选错的代价也很典型：用 worker 处理并发请求会带来同步开销，用 cluster 处理 CPU 密集则一个 worker 卡住仍影响整体。

## 被追问三层时的诚实边界

我实际做的是进程级并发加优雅退出这类部署形态，多线程算子没在 Node 里写过；GC 跨线程的边界我没有实操过，我的理解是消息传递型优于共享内存正是为了避开它。
