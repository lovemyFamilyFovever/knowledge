# 浏览器扩展 MV3

## 一句话定义

跑在浏览器里的程序，后台是短暂 Service Worker，权限要显式声明。

## 面试官为什么问它

简历有一行「Chrome MV3 插件」，他想知道你懂不懂 MV3 为什么把后台页面改成 SW。

## 30 秒版回答

MV3 相比 MV2 的三个硬变化：后台从常驻页面改成会被卸载的 Service Worker（所以内存态靠不住，一切要落存储）、阻塞式请求拦截换成声明式的 declarativeNetRequest、权限模型更严格且要用户确认。结构上分后台 SW、内容脚本、扩展页面三块，内容脚本运行在隔离世界，能读 DOM 但拿不到页面的 JS 变量，跨世界通信只能靠消息或注入。实操最烦的是生命周期：SW 醒来看不到之前的状态，长任务必须设计成可续跑。

## 被追问三层时的诚实边界

我实际做的是插件加本地服务加 Web 后台的多平台一键发布，踩过消息通信与状态丢失；chrome.debugger 这类高权限 API 我没有实操过，我的理解是它接近 CDP，能力强的同时商店审核也更严。
