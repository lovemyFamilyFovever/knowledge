# jQuery 与事件委托

## 一句话定义

选择器加链式操作的库；事件委托是把监听挂到共同祖先。

## 面试官为什么问它

简历写了多年 jQuery 实战，他会用事件委托这个点验你是不是真的写过老代码。

## 30 秒版回答

jQuery 的价值在当年：统一 DOM API、跨浏览器兼容、链式调用和动画。它的事件委托利用冒泡，把监听绑在父容器上，靠选择器判断目标，好处是一次绑定还能覆盖之后动态插入的节点、少绑很多监听器——这也是列表类页面最常见的写法。要能说清的边界是：委托只对冒泡型事件有效，focus 与 input 这类不冒泡（要用 capture 或换实现）。今天原生 API 够用，但维护遗留系统时这套思路完全不过时。

## 被追问三层时的诚实边界

我实际维护过 25 年遗留系统与大量 jQuery 页面，委托与解绑都是我写的；对 jQuery 源码级的 Sizzle 选择器实现我没有实操过，我的理解是它现在被 querySelectorAll 取代了。
