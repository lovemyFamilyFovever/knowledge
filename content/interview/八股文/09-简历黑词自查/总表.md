# 简历黑词自查 · 总表

> **口径**：名词全部取自 [[resume-master]]（专业技能五行 + 七块项目 + 三段工作经历），逐个核对 `01~08` 八类速查层的覆盖情况。
> **风险定义**：高 = 名词落在简历自我声称的能力域内（熟练/较强/掌握/亮点），面试官一句话就能问穿；中 = 会被问但有兜底答案；低 = 产品名、私有标识或业务词，不是通用黑词。
> **覆盖写法**：`词条` = 八股文层已有速查卡；`仅深挖` = 没有速查卡、但全库有深度文章（给双链）；`本轮补` = 核对时发现高风险缺失、这一轮新建的卡。
> **核对方法**：先用脚本抽出简历里全部 105 个 ASCII 技术 token 与中文技术名词逐一比对，再反向用脚本校验「凡标为高风险的都真有卡」，未命中项全部进了第四节的补录清单。
> 本表行数多于单张速查卡的 60 行上限是刻意的：它是**清单**不是词条，覆盖率高优先级于篇幅。

## 五、没建词条的名词与理由

不留悬念，逐条给理由，方便你判断要不要我再补：

- **产品与平台名**（阿里云百炼、飞书妙搭、Neo4j、Element Plus 的用法层面）：不是可背的黑词，答「为什么选它、代价是什么」比答名字有用，已在相邻词条里给了口径。
- **私有标识**（`WafBypassService`、`schema.ts`、`manual-schema.ts`、`isLocal`、`trade_view_rules`、`acw_sc__v2` 的具体串）：面试官不会说这些词，说了也只是你的项目细节；对应的通用概念（配置边界、挑战页与反爬）已有卡。
- **纯业务口径**（五维 100 分制、统一结算公式、曝光特权的具体规则）：是你的设计而非领域术语，答时要先说清「为什么这么定」。

## 六、这张表怎么用

1. **临场顺序**：先看第四节有没有你答不顺的卡，再看第一、二节的「高」行——面试官问穿的成本全在这里。
2. **每张卡只用 30 秒版**：这一层是广度层，卡的职责是「说出它是干嘛的 + 给一个可深挖方向」，深度全部在双链指向的文章里，别去背卡里的字。
3. **诚实边界那一段是给你自己的**：每张卡的第四段按「我实际用过的是 X，Y 我没实操过」写，面试时照这个说，别越界——越界被追穿一次，整场可信度就没了。
4. **想扩类目**：某一类想要更密的覆盖，就在那个子目录里按同一模板加 `术语（速查）.md`，跑一遍校验脚本确认双链不悬空即可。
5. **两处边界要知道**：① 文件名带「（速查）」是硬要求——阅读器按文件名唯一解析双链（`app/fts.py:116`），若用裸术语命名，全库约 800 条指向同名深度文章的双链会当场变悬空。② 有 9 条双链指向 `projects/AI金`、`projects/dsh-agent` 下的实现文档（CSRF / 洋葱模型 / 依赖注入 / SSE / 流式输出 / 知识图谱 / Token 计费 / 幂等迁移 / MCP）：本地阅读器能打开，但 `projects/` 不在发布白名单里，公开站上会是断链——这是刻意保留的「我自己的实现证据」，不是缺陷。
