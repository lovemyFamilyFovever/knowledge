# Tailwind 与原子化 CSS

## 一句话定义

样式直接写成工具类，编译时按需生成。

## 面试官为什么问它

简历列了 Tailwind（熟练），会被问「和 BEM 加 SCSS 比好处在哪、失控怎么办」。

## 30 秒版回答

Tailwind 把样式拆成原子类（如 flex gap-2 text-sm），构建时扫描模板只生成用到的规则，因此没有未使用 CSS、也不用给类起名字、不用处理命名冲突与层叠优先级之战。代价是类串长、HTML 可读性下降，所以我的做法是在组件里抽语义化封装，让业务代码看不到长串。另一条纪律是自定义扩展要收敛到主题配置，别在页面里到处写任意值，否则等于把 CSS 换个写法继续乱。

## 被追问三层时的诚实边界

我实际是在项目里用它做业务样式并把常用组合封成组件属性；构建期的 JIT 实现细节与插件编写我没有实操过，我的理解是它的体积优势主要来自按需生成，这跟传统 purge 是同一件事。
