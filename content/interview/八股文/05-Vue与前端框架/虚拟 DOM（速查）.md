# 虚拟 DOM

## 一句话定义

用 JS 对象描述界面，靠比较它来决定最小更新集。

## 面试官为什么问它

这题现在是「你知道 VDOM 的代价吗」——能不能说出收益与成本两面，而不是只讲好处。

## 30 秒版回答

虚拟 DOM 是把 UI 写成可比较的数据（VNode），每次重新渲染生成新树，和旧树 diff 出真实的最小 DOM 操作再打上去。收益是把「命令式改 DOM」变成「声明式描述结果」，跨端也能复用同一套 diff，还让批量更新成为可能。代价是仍然要重建整棵 VNode 树并比较，比手写精准 DOM 更新贵——所以现代做法靠编译期优化：静态提升、块级缓存、以及 Vue3 用 patch flags 记住可跳过哪些检查。

## 被追问三层时的诚实边界

我实际关心的是它带来的编程模型和 nextTick 行为，框架内部优化我没有实操过；我的理解是「VDOM 比原生 DOM 慢」这种说法要看场景，真正昂贵的是 DOM API 本身。
