# diff 与 key

## 一句话定义

同层比较新旧节点，key 告诉编译器哪些是同一个。

## 面试官为什么问它

这题他要看的是你知道「diff 是为了省更新」，也知道 key 用 index 为什么会导致状态错位——不是背算法名字。

## 30 秒版回答

Vue 的 diff 只同层比较、不做跨层移动（跨层等于销毁重建），因为完整树比对是 O(n^3)，同层加 key 匹配能降到接近 O(n)。新旧节点先按类型和 key 判断是否可复用；Vue3 还额外用最长递增子序列来减少移动。key 用 index 的问题在于：插入或删除会让 index 错位，于是本不该动的组件被当成另一个，轻则 diff 变慢，重则把内部状态、异步请求和 DOM 复用错配到别的条目上。

## 被追问三层时的诚实边界

我实际用的是「用业务上稳定的唯一 id 做 key」这条纪律，也处理过列表复用导致的表单串数据；Vue2 的双端指针细节我读过源码但记不牢，我的理解是 Vue3 的前缀后缀预处理才是它提速的主要来源。
