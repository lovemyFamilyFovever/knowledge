# Function Calling

## 一句话定义

模型按你给的函数签名输出结构化调用意图，执行权在你。

## 面试官为什么问它

他紧接着会问「模型会不会瞎编参数、执行失败怎么办」——工具调用的可靠性才是重点。

## 30 秒版回答

Function Calling 是给模型一份工具清单（名称、用途描述、参数 JSON Schema），它在判断需要时不直接回答，而是输出要调哪个函数、参数是什么。模型只负责决定「要调」，真正执行的是你的代码，结果再回填给模型继续生成。这套机制让大模型能查实时数据、写库、调接口。可靠性靠三件事兜住：参数用枚举和必填约束并做服务端校验；工具描述写得窄而清晰，工具多了要分组或让模型先规划；执行失败要把错误原样回传让它重试或改道。

## 被追问三层时的诚实边界

我实际用它做的是把采购自然语言解析成结构化参数再打分排序，输出纯 JSON 配正则校验加两层兜底；多工具并发调用与自主规划式的工具链我没有实操过，我的理解是工具一多，路由与描述质量就变成瓶颈。
