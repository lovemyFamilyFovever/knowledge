# Agent

## 一句话定义

模型循环地规划、调工具、看结果，直到任务完成。

## 面试官为什么问它

他要问的是边界：Agent 什么时候不可靠、你怎么防止它跑飞——这是能不能上生产的关键。

## 30 秒版回答

Agent 的核心是一个循环：拿目标和上下文，决定下一步动作（调工具或子任务），执行后把观察结果喂回去，再决定下一步，直到判定完成或超预算。常见骨架是 ReAct 这种「思考—动作—观察」，工程上会加计划与反思、记忆（短期会话、长期检索）、以及多 Agent 协作分工。不可靠来源很明确：错误会沿链条累积、终止条件模糊导致空转、工具描述含糊导致选错。所以我的做法是限定步数与预算、每步留可审计的输入输出、高风险动作要人工确认。

## 被追问三层时的诚实边界

我实际做的是受限场景里的工具化流程（前置规则路由决定走哪条通道）加多个编码 Agent 并行开发的工作流，并把文件所有权与联调顺序写进协作规范；开放式自主 Agent 我没有实操过，我的理解是它在缺乏可验证终止条件的业务里收益抵不上风险。
