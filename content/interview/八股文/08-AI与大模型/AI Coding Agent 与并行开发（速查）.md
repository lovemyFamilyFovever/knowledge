# AI Coding Agent 与并行开发

## 一句话定义

把编码 Agent 当成能读仓库、能跑命令的执行者，靠规范约束它。

## 面试官为什么问它

这是简历里最能引起追问的一段——他会问你怎么保证多个 Agent 不互相踩、怎么收口质量。

## 30 秒版回答

做法是把项目约束写成 Agent 必读的规范：不变量、红线、常用命令、文档导航，再加上文件所有权与联调顺序，让并行变成可能而不是混乱。我把重复的工程动作固化成技能（比如环境同步、幂等 DDL 生成加语法自检、发布前校验），Agent 执行、人总控收口。我的顺序是需求到规格到任务清单再到实现，每步都能被检查——因为 Agent 交付的「看起来完成」必须有测试和截图来证。

## 被追问三层时的诚实边界

我实际带一个应届生加多个编码 Agent 把一个平台推到上线，并写了项目级协作规范；对 Agent 自主规划与工具编排框架（LangChain 那一类）我没有实操过，我的理解是在有明确规范与验证闸门的仓库里，约束比框架更重要。
