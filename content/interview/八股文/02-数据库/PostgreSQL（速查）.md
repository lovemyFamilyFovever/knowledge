# PostgreSQL

## 一句话定义

类型与扩展最强的开源关系库，用快照隔离做到读不挡写。

## 面试官为什么问它

简历把数据库写成个人长板，他一定会问「你和 MySQL 怎么选、PG 的代价是什么」。

## 30 秒版回答

我选 PG 的理由都是实际用上的：一个库能同时装业务表、JSONB 半结构化内容和扩展能力（全文检索、向量），在只有一个数据库的受限平台上这决定了架构；类型系统严格，函数与 CTE 表达力强。要说代价：PG 每个连接是一个进程，比 MySQL 的线程模型贵，所以连接数必须收紧、必要时上池化中间件；另外 MVCC 会留死元组，长事务和大批量写要靠 vacuum 回收，表会膨胀。

## 被追问三层时的诚实边界

我实际在 PG 上做的是递归 CTE、JSONB、RLS、批量写入与迁移工程化；MySQL 的 binlog 复制体系与 InnoDB 参数调优我没有实操过，我的理解是两者差异主要在运维生态和默认行为，而不是 SQL 语法。
