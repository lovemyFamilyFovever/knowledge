# 能守卡 01 · AI 问答 RAG 链路（基于源码，2026-06 真实实现）

> 用途：面试前把这条链路"吃到能讲第 2–3 层机制"。所有内容都来自你桌面 `code/server/modules/ai/` 的真实代码，**没有一个字是编的**——这正是"准备真做过的东西"和"硬编一个技术名词"的区别。
> 核心模块：`ai-query-policy.ts`（路由）· `local-retrieval.service.ts`（本地检索）· `bailian.service.ts`（百炼/模型调用）· `chat-stream.service.ts`（SSE 编排）。

## 0. 电梯陈述（先背熟这一段，30 秒）
"AI 金问答不是简单地转发给大模型。我做了一条 **三段式链路**：先用 **query-policy 规则路由**判断问题该走哪条数据通道、能不能联网；再用 **本地检索服务**从 PostgreSQL 结构化数据 + 知识图谱里召回已审核素材，拼成带编号引用的上下文块；最后交给 **百炼大模型**（快速模式 qwen-turbo / 专家模式百炼应用 API 带知识库和工具），全程 **SSE 流式**输出，并做 **Token 计量**和**输出内容安全过滤**。目标是在一个不锈钢垂直领域里，把**可溯源、防幻觉**放在召回泛化之前。"

## 1. 端到端流程（面试可在白板画这张图）
```
用户问题
  │
  ├─(A) 快速模式 fast：qwen-turbo（OpenAI 兼容 /compatible-mode）
  │      · System Prompt 铁律：通用知识直接答；
  │        实时数据类问题不硬答，直接吐 "[切换到专家模式]" → 触发升级
  │
  └─(B) 专家模式 expert：
        ① query-policy 路由 decideAiQueryRoute(question)
              → 6 条 route + allowWebSearch + 强制路由 prompt + 拦截直答
        ② 本地检索 LocalRetrievalService.retrieve(question)
              关键词锚点抽取 → 并发检索5源 → 超时保护 → 去重 → 拼 contextBlock（带[101]式引用）
        ③ 百炼应用 App API（dashscope /api/v1/apps，带知识库/工具/可选联网）
              → 把 contextBlock 注入 prompt，要求逐句标引用编号
  │
  └─ SSE 流式回传 + 输出过滤(OutputGuard) + Token 用量记录
```

## 2. 面试官会怎么挖 · 逐层答案

### 【L1 · 是什么】"你这个 AI 问答大概怎么做的？"
→ 用第 0 段。再补一句双模式："**快模式**便宜、5 秒级、覆盖通用行业知识；**专家模式**走百炼应用 + 知识库 + 数据连接，处理要实时数据的问题。两者之间还做了**自动升级**——快模式判断自己答不了就吐一个标记切到专家模式，不用用户手动选。"

### 【L2 · 怎么实现】"query-policy 路由具体判什么？"
→ 关键名词：它是一个**规则/正则前置分类器**（不花 token、零延迟），把问题分成 `内部行业新闻 / 官方公开信息 / 内部行情数据 / 本地增量数据 / 通用 / 数据能力核查` 几条路。决定三件事：
1. **能不能联网** `allowWebSearch`；
2. **注入强制路由指令**：比如"内部新闻**只准查** `public.erp_cms_article_data` 这张表，**禁止**联网/知识库/模型记忆补全，查不到就明确说没查到"；
3. **直接拦截**：像"某某政府文件原文/文号"这类**官方可核验事实**，一旦命中直接回固定话术（"无经核实的公开信息"），**根本不让模型瞎编**。
→ 一句话拔高："这层的作用是**把模型的自由发挥空间收窄**，宁可不答也不让它编一个不存在的文件或价格。"

### 【L2 · 怎么实现】"本地检索怎么召回的？用向量库吗？"
→ **关键正解（平台约束，不是审美选择）**："我的部署平台（飞书妙搭）**只给了一个 PostgreSQL**，外挂 Neo4j / 向量库 / 文件存储**物理上都不支持**——我方案文档里明确写了'图谱用 PG 实现、不引入任何外部数据库'。所以我自建的知识库检索**全部压在 PG 上**：从问题用正则抽**强实体**（材质牌号 304/316L、钢厂名、地区、检修/停产等动作词，最多 5 个），再**并发**去 5 个源召回——PG 知识图谱的实体/关系、已定稿内容、事件、解读、日价。"
→ 工程细节（能讲到这层就很加分）：
   - **超时保护**：`Promise.race` 挂 1500ms 超时，检索拖了就返回空、不阻塞回答；
   - **去重**：每类结果按业务键 `uniqueBy` 去重；
   - **上下文预算**：单条截断 180 字、整块 4500 字，控 prompt 体积；
   - **引用编号段隔离**：本地引用用 **101 起**独立编号段，**不跟百炼知识库引用冲突**；
   - **溯源铁律**：注入 prompt 要求"用本地事实必须句末标 `[101]`、'待核验'图谱信息只当线索不当已确认事实"。

### 【L2 · 怎么实现】"你说的'自建知识库'具体是什么？"（**别和问答混为一谈，单独会讲**）
→ 这是你**另一条独立成果 = AI 金采集标注系统**（我另开会做卡，这里点到）："我搭了一套 **四层数据资产管线**——原始资料层 → 标准事实层 → 知识推理层 → 应用层：文章提交 → AI 类型路由 → Schema 约束抽取（字段级置信度 + 数据性质 FACT/OPINION/INFERENCE）→ 人工三态校核 → 入库 → **PG 实现的知识图谱**（实体归一、多跳、G6 可视化）。还有 **14 万+ 存量批处理管线**（去重/规整/路由/抽取/自动确认/回填，含熔断、断点续跑）。**一句话：把 14 万篇行业文章变成可验证、可检索、可溯源的结构化数据资产。**"

### 【L3 · 为什么这么取舍】（**这题答好直接封神**）"为什么不用向量库 / embedding / 混合检索？"
→ 你**懂、而且设计过**——先讲这个，再把约束摆出来（这才是真实力，别装"没想到"）：
1. **我早期方案里就设计过向量混合检索**：`Qdrant(向量) + Neo4j(图) + embedding + 向量召回 TopK + 图谱推理 + 结果融合去重`，切片还规划了 `summary+keywords+content` 拼接向量化（纯文本 embedding 召回精度低 15–20%）。
2. **但落地环境不允许**：飞书妙搭只暴露一个 PG，外挂向量库/图库**部署条件为零**，所以我**主动收敛成 PG 上的图谱 + 关键词混合检索**——在受限环境里把"能溯源"这条路走通。
3. **拿到真实数据库后我补做了**：8/30 才有自己的 PG 库（前面老技术负责人不给服务器/数据库，一次代码同步要 8 小时+），随后我**验证了自建混合检索的最小闭环**；没铺满是因为**原料（51bxg / 秀吗近千万条、25 年历史数据）当时还没能一次性导出**，巧妇难为无米之炊。
4. **取舍优先级**：行业问答最怕一本正经编数据，我把**可控 / 可溯源 / 防幻觉**排在**召回泛化**前——规则路由 + 强制引用 + 查不到就拒答，都服务这个目标。
> 若被追"关键词召回会漏召吧？"→ 大方认 + 给路线："纯关键词对长尾问法召回不足；我的补偿是快/专家模式 + 百炼知识库覆盖语义泛化，本地层只管**必须精确可溯源的结构化事实**。要再往前走，就是把我设计过的那版**向量+图谱混合检索**在自有 PG 上补齐（可上 pgvector），这是有数据和部署条件之后的自然演进，不是能力空白。" —— **能讲清'设计过、被环境卡住、拿到条件就开始验证'，比假装完美强十倍。**

### 【L2 · 怎么实现】"SSE 流式为什么？遇到过什么问题？"
→ "用 SSE 不是 WebSocket：单向流式服务端推 token 给前端，够用、更轻。改造 SSE 主要是解**飞书妙搭网关 504 超时**——同步等大模型回完会被网关掐断，改成边生成边推，首字延迟也下来了。"

### 【L2 · 怎么实现】"Token 成本怎么管的？"
→ "百炼 App API 和 OpenAI 兼容两种返回格式我都统一抽 `usage`（含 cached_tokens/cache_creation_tokens），按会话 `chatRoundCounter` 计数；有**当日 token 阈值拦截**（如日 640 万到顶就拦），后台有 Token 消耗统计页。"

## 3. STAR 版讲法（"讲一个你解决的技术难题"）
- **S 背景**：不锈钢垂直问答，直接套大模型会**乱报价格、编造官方文件**，业务侧不接受。
- **T 目标**：在 3 个月、飞书 FaaS、没自建向量服务的约束下，做一个**可溯源、防幻觉**的行业问答。
- **A 做法**：三段式——query-policy 规则路由收窄发挥空间、本地检索(关键词锚点+图谱/多表并发+超时/去重/引用编号隔离)、百炼模型流式生成，强制逐句标引用；查不到就明确拒答。
- **R 结果**：官方类/无据类问题被前置拦截，行情/新闻类走指定数据源，**答案带可点击来源编号**；上线支撑问答/配单/广场多场景。（能量化的补上：命中率、日均问答量、拦截误答数——记得回去取真实数，别虚报。）

## 5. 你要带走的 3 个记忆锚点
1. **双模式 + 自动升级**（fast 答不了吐 `[切换到专家模式]`）
2. **query-policy = 前置规则路由**，核心价值是**收窄模型自由发挥、防幻觉、可溯源**
3. **本地检索 = 关键词锚点 + 图谱/多表并发 + 超时/去重/引用编号隔离**，且**诚实说不为什么没上向量库**
