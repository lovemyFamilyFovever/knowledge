## 0. 电梯陈述（背熟，30 秒）
"公司沉淀了 **14 万+ 篇**不锈钢行业文章，非结构化、填不动也查不准。我从 0 设计了一套**采集标注系统**：核心思路是**把'填空式采集'变成'审校式采集'**——AI 按标准格式约束抽取、预填每个字段并给出**置信度 + 数据性质 + 原文证据**，人工**只审 AI 标红的低置信字段**；确认后结构化入库，并自动长出一张 **PostgreSQL 实现的知识图谱**。一条黄金路径从提交到多渠道成稿全自动，验收口径是**单篇操作 ≤ 3 分钟、人工改动 ≤ 3 处**。"

## 1. 黄金路径（可白板画）
```
① 提交文章
② AI 类型路由（9 类，MVP 实做 事件/日价/复合文）
③ AI 约束抽取 → 每字段带：置信度 × 性质(FACT/OPINION/INFERENCE) × 原文证据
④ 人工校核 → 三态🟢🟡🔴，全绿一键过，漏审硬拦截
⑤ 四轨结构化入库（日价/周库/月产/季需）
⑥ 知识图谱自动生长（实体+关系）
⑦ 多渠道内容生成（公众号/51APP/行业群…）
```
分期 P0 地基 → P1 最小闭环 → P2 图谱增强 → P3 输出增强 → P4 存量批量 → P5 问答接入。

## 2. 面试官会怎么挖 · 逐层答案

### 【L1】"这系统解决什么问题？"
→ 第 0 段。补一句业务价值："标准格式（洛歌定的三份）已经有了，**痛点是'标准有了，人填不动'**；我用 AI 预填把人的动作从'全量填写'降到'只审重点'。"

### 【L2】"AI 约束抽取具体抽什么？怎么保证可信？"
→ 关键设计，逐条讲：
1. **字段级三件事**：每个抽取字段带 **置信度 + 数据性质 + 原文证据**；
2. **三态性质纪律**：`FACT 原文事实` 才能进标准事实层；`OPINION 观点`、`INFERENCE AI推断` **永不污染事实层，只进知识层且需人工确认**——**这是数据可信的底线**；
3. **按置信度着色**：🟢正常/🟡建议确认/🔴必须确认，全绿可一键全过，含必填空或未确认项**硬拦截**杜绝漏审。
→ 拔高："本质是用**置信度把人工注意力精确分配到最该看的字段上**，而不是让 AI 全自动或直接让人全填。"

### 【L2】"知识图谱怎么建的？为什么不用 Neo4j？"
→ **和 RAG 卡同一句话术（平台约束）**："部署环境只给 PostgreSQL，Neo4j/向量库外挂**物理不可用**，所以我**用 PG 两张表实现图谱**：`kg_entities`(节点) + `kg_relations`(边)，**12 类实体 × 12 类关系**（钢厂/原料/政策/产品/区域…），配 **12 张字典表**统一管理枚举。"

### 【L2】"实体归一化怎么做？'太钢'和'太原钢铁'怎么合成一个？"
→ 真实逻辑（`kg.repository.createEntity`）：**MERGE 语义**——按 `name + entity_type + status=active` 查重，命中就**合并 `aliases`(别名) 和 `source_ids`(来源记录)** 后复用既有节点，不新建；配 **`dictEntityAlias` 别名词典**做归一。业务记录节点还优先按 `UNIQUE(biz_record_type, biz_record_id)` 去重。

### 【L2/L3】"多跳查询怎么实现？'太钢减产→为什么→影响谁'这种因果链 RAG 能做吗？"（**这题是这卡的杀手锏**）
→ "**纯 RAG 做不到多跳因果，图谱能做**——这正是我上图谱的核心理由。" 实现要讲准（⚠️ 见第 4 节陷阱）：
- **AI 问答注入用的是命中实体的『一跳关系』**（`searchContextForQa`），因为问答有 **1500ms 超时预算**，不能为深链拖慢响应；
- **完整多跳（限深 6，`MAX_DEPTH=6`）是在服务层做逐跳 BFS 展开**（`expand` 函数按 depth 迭代），支撑前端图谱『逐跳点开』看因果链；
- 换句话说：**深度是应用层遍历控制的，不是数据库一条递归 SQL 跑出来的**。

### 【L2】"一篇复合文章怎么处理的？"
→ **父子任务双状态机**：文章是父任务、拆出的业务记录是子记录，状态各自流转——一篇 mixed 复合文可拆多条记录、各自入库、各自可追溯。

### 【L2】"抽取完的数据后面干嘛？"
→ **内容工坊**：选定已确认素材 → 选渠道与风格（兼容矩阵校验）→ AI 生成 → 改/重生成 → 定稿；**同一条结构化数据自动出 公众号深度报道 / 51APP 卡片 / 行业群快讯**（P3-C 做到 6 渠道×6 风格）。→ 讲"数据一次结构化、多场景复用"。

### 【L1】"存了多少表、多少量？"
→ 采集标注**新增 20 张表**（业务表 + 12 字典表 + 图谱两表），后扩展至 **30+ 张**（含 041/043/044/045 迁移）。目标数据源 **14 万+ 篇文章**。

## 3. STAR 版（"讲一个你从 0 做的、最复杂的东西"）
- **S**：14 万篇非结构化行业文章，人工按标准格式逐字段填表填不动、还易错，无法支撑问答与分发。
- **T**：把它们变成**可验证、可检索、可溯源的结构化数据资产**，并在**只有 PG、无外部库、没服务器**的受限环境下落地。
- **A**：四层数据资产管线（原始资料→标准事实→知识推理→应用）+ AI 约束抽取（置信度×性质×原文证据）+ 三态人工校核硬拦截 + PG 两表知识图谱（MERGE 实体归一 + 别名词典 + 应用层逐跳多跳限深 6）+ 父子双状态机 + 内容工坊多渠道成稿。
- **R**：黄金路径全链路跑通，**单篇 ≤3 分钟、改动 ≤3 处**；图谱支撑多跳因果问答；已交付到 P5-1 本地问答注入。
> **注**：涉及准确率别用"≥95%"旧口径——你们后期**改用"误差率"口径、禁用"准确率"表述**（见第 4 节）。

## 4. ⚠️ 精确防守点 / 别踩的坑（这几个最容易翻车）
| 简历/deck 说法 | 真实实现 | 面试怎么说不翻车 |
|---|---|---|
| deck："**递归查询**支撑多跳" | 实际是**服务层逐跳 BFS、限深 6**；QA 只用**一跳** | 别说"我写了 SQL WITH RECURSIVE"。讲"深度在应用层逐跳遍历控制、限深 6，问答注入一跳保延迟"——**懂行的一问你就露，讲准了反显专业** |
| deck：核心字段"**准确率 ≥95%**" | 后期**改口径为误差率、禁用准确率** | 说"我们在做**金标准测试集**验收（2 人独立填标准答案逐字段比对），当前用误差率口径"；**没跑完就说在验收，别报死数字** |
| resume："**14 万篇全量处理流水线已落地**" | P4 存量批量在 deck 里是**规划中**，且受**近千万条历史数据未能一次性导出**限制 | 讲"我**设计**了存量批处理管线(去重/规整/路由/抽取/熔断/断点续跑)并做了部分验证，全量跑受数据导出进度限制"——**设计过+部分验证 ≠ 已跑完 14 万** |
| "多智能体协作/8 Agent" | Agent 是**你自己用 AI 编码代理并行开发**（kg 写=Agent2、查=Agent3…代码注释可见） | 讲"我制定文件所有权与联调规范，用多个 AI Coding Agent 并行开发、我做总控与收口"，**别说'带了 8 个人'** |

## 6. 你要带走的记忆锚点
1. **"填空式采集 → 审校式采集"**（AI 预填 + 人只审标红）
2. **FACT/OPINION/INFERENCE 三态纪律**（观点/推断永不进事实层）
3. **PG 两表知识图谱 + MERGE 实体归一**，**多跳是应用层逐跳限深 6、QA 用一跳**
4. **平台约束 = 你最强的故事线**（没有 Neo4j/向量库，就在 PG 上把它做出来）
