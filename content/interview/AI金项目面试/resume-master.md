## 项目经历

### ★ AI 金 · 不锈钢智能伙伴平台（2026.04 — 2026.09 ｜ 从 0 到 1 ｜ 技术负责人兼主开发）
面向不锈钢行业的一站式 AI 平台，覆盖 AI 问答、AI 配单、数据采集标注、知识图谱、智能广场、VIP 体系、ERP 后台等模块。技术栈：**Vue 3 + TypeScript + NestJS + PostgreSQL + Drizzle ORM + 阿里云百炼**，Monorepo，部署于飞书妙搭容器。

> 〔面试用·不上纸面〕这 3 个月是**在没有自己的服务器和数据库、飞书妙搭环境又慢又受限、跨部门不配合**的条件下，一个人从 0 搭起、后期带应届生 + 多 Agent 并行推到上线——面试讲"解决困难/抗压"时，这段是你的核弹素材（详见能守卡 03 第 5 节行为故事）。

**1）AI 问答系统（深度参与·可深挖）**
- 设计并落地**双模式架构**：快速模式（qwen-turbo 流式）+ 专家模式（百炼应用 API + 知识库/数据连接），并实现**快模式答不了自动升级专家模式**的智能路由。
- 实现 **query-policy 前置规则路由**：按问题类型收窄数据通道、禁联网/禁记忆补全、对无据可查的官方类问题直接拦截拒答，把模型的自由发挥空间压到最小，**显著抑制行业问答的"编数据/编文件"幻觉**。
- 自建**本地检索链路**：关键词锚点抽取 + PG 知识图谱/多业务表并发召回 + 超时保护(1500ms) + 去重 + 引用编号段隔离 + 强制逐句标注来源——做到**答案可溯源**。
- 推动 **SSE 流式**改造解决飞书网关 504 超时；建立 **Token 消耗计量与成本阈值拦截**。
- 沉淀 **RAG 质量工程**（不止于调 API）：自建 11 个正式知识库与《知识库整理规范》（知识块可独立召回答全"对象/结论/适用条件/例外/来源"、检索词与别名保全、稳定知识 vs 动态数据分流到 SQL）；自建 **ERP 批测台**（100 题 / 15 类、AI 初评 + 人工复核、可导出）与**七类问题诊断分类法**（固定定位顺序、只有最后一步才改 Prompt），把"答得准不准"做成可测、可定位、可迭代。

**2）数据采集标注系统 + 知识图谱（从 0 主导·可深挖）**
- 提出"**把填空式采集变成审校式采集**"：AI 按标准格式**约束抽取**（字段级置信度 × 数据性质 FACT/OPINION/INFERENCE × 原文证据）预填，人工**只审低置信字段**、全绿一键过、漏审硬拦截；纪律是"观点与 AI 推断永不污染事实层"。
- 在"**平台只给一个 PostgreSQL、不能外挂 Neo4j/向量库**"的硬约束下，用 **PG 两表实现知识图谱**（12 类实体 × 12 类关系），**MERGE 语义 + 别名词典做实体归一**，服务层逐跳遍历支撑"太钢减产→为什么→影响谁"的**多跳因果查询**（限深 6）——这是纯 RAG 做不到的。
- 设计 **14 万+ 存量文章的批处理结构化管线**（去重/规整/路由/抽取/自动确认/回填，含熔断保护与断点续跑）。
- 父子任务双状态机支持一篇复合文拆多条记录、各自入库与追溯。

**3）AI 智能配单（LLM 直通）**
- 两段式：**parse-enquiry-params**（大模型解析采购自然语言→结构化参数）+ **score-matches**（大模型按**五维 100 分制**评分排序），不写规则引擎，迭代快。
- 输出**分层推荐理由**（前 5 名详评 / 6-10 / 11-15），纯 JSON 正则解析 + 校验；**两层 Fallback**（LLM 失败退候选零分、前端再兜底）保证页面不白屏。
- 数据源应急改造：51bxg 接口被禁后，设计"手动导出 + 本地快照"零外部依赖方案，完成全量现货数据迁移入库。

**4）阿里云 WAF 逆向与接口打通（问题求解·可讲成高光）**
