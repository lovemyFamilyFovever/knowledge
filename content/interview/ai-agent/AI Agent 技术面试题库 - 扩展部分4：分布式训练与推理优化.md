# AI Agent 技术面试题库 - 扩展部分4：分布式训练与推理优化

> 分布式训练与推理优化（10 题）｜涵盖数据并行、模型并行、量化、推理加速等核心领域。
> 每题标注难度（初级 / 中级 / 高级），编号 1–10 连续，附参考解答与关键要点。

## 主题1：分布式训练（5 题）

### 1. 解释数据并行和模型并行的区别。｜中级

分布式训练通过并行计算加速大模型训练，主要有两种并行策略。

| 特性 | 数据并行 | 模型并行 |
|------|---------|---------|
| 划分方式 | 数据划分到不同设备 | 模型划分到不同设备 |
| 适用场景 | 模型能放入单卡 | 模型太大无法放入单卡 |
| 通信开销 | 梯度同步 | 激活值传输 |
| 实现复杂度 | 简单 | 复杂 |

> 🎯 关键要点：数据并行是最常用的分布式训练方式。
> 大模型通常需要结合多种并行策略。
> 通信效率是分布式训练的关键。

### 2. 解释 DeepSpeed ZeRO 优化的三个阶段。｜高级

DeepSpeed ZeRO 通过分片存储优化器状态、梯度和参数来减少显存占用。

**三个阶段：**

- **ZeRO-1**：分片优化器状态
- **ZeRO-2**：分片优化器状态 + 梯度
- **ZeRO-3**：分片优化器状态 + 梯度 + 参数

**显存节省（假设 N 个 GPU）：**

```text
ZeRO-1: 显存 ≈ 模型参数 + 优化器状态/N
ZeRO-2: 显存 ≈ 模型参数 + (优化器状态 + 梯度)/N
ZeRO-3: 显存 ≈ (模型参数 + 优化器状态 + 梯度)/N
```

> 🎯 关键要点：ZeRO 是大模型训练的关键技术。
> 阶段越高，显存节省越多，但通信开销越大。
> 需要根据硬件选择合适的阶段。

### 3. 什么是流水线并行？如何解决气泡问题？｜高级

流水线并行将模型的不同层分配到不同设备，按流水线方式执行。

**气泡问题：**

由于流水线各阶段执行时间不同，会导致部分设备空闲（气泡）。

**解决方法：**

- **微批次**：将一个 batch 分成多个 micro-batch
- **GPipe**：增加 micro-batch 数量减少气泡
- **1F1B 调度**：交替执行前向和反向传播

> 🎯 关键要点：流水线并行适合层间独立性强的模型。
> 气泡率是衡量效率的重要指标。
> 通常与数据并行结合使用。

### 4. 解释张量并行的原理。｜高级

张量并行将单个算子（如矩阵乘法）拆分到多个设备上并行计算。

**矩阵乘法并行：**

```text
# Y = XW
# 按列切分W
W = [W1, W2]
Y = X[W1, W2] = [XW1, XW2] = [Y1, Y2]

# 各设备独立计算后拼接
```

**优势：**

- 单层计算可以并行
- 通信量较小
- 适合 Transformer 的注意力层和 FFN 层

> 🎯 关键要点：张量并行需要 GPU 间高速通信。
> Megatron-LM 是张量并行的经典实现。
> 通常在单机多卡场景使用。

### 5. 什么是混合专家模型（MoE）？｜高级

MoE（Mixture of Experts）通过稀疏激活来扩展模型容量，同时保持计算效率。

**架构：**

```text
# MoE层
y = Σ G(x)_i × E_i(x)

# G是门控网络，选择Top-K个专家
# E_i是第i个专家网络
```

**特点：**

- 参数量大但每次只激活部分
- 计算量与激活专家数成正比
- 需要负载均衡机制

> 🎯 关键要点：MoE 是扩展模型容量的有效方式。
> GPT-4、Mixtral 使用 MoE 架构。
> 负载均衡是训练的关键挑战。

## 主题2：推理优化（5 题）

### 6. 解释模型量化的原理和方法。｜中级

模型量化将浮点数参数转换为低精度表示（如 INT8、INT4），减少存储和计算开销。

**常见方法：**

- **INT8 量化**：8 位整数表示
- **INT4 量化**：4 位整数表示
- **GPTQ**：训练后量化，保持精度
- **AWQ**：激活感知量化

**量化公式：**

```text
# 线性量化
x_q = round(x / scale) + zero_point
x ≈ (x_q - zero_point) × scale
```

> 🎯 关键要点：量化可以大幅减少显存占用。
> 需要在精度和效率之间平衡。
> GPTQ 和 AWQ 是目前最常用的量化方法。

### 7. 解释 vLLM 的 PagedAttention 机制。｜高级

PagedAttention 是 vLLM 的核心技术，通过分页管理 KV Cache 提高内存利用率。

**核心思想：**

- 将 KV Cache 分成固定大小的块（Page）
- 按需分配和释放
- 类似操作系统的虚拟内存管理

**优势：**

- 减少内存碎片
- 支持更大的 batch size
- 提高吞吐量

> 🎯 关键要点：vLLM 是目前最流行的推理引擎。
> PagedAttention 显著提高了显存利用率。
> 支持连续批处理。

### 8. 什么是连续批处理？｜中级

连续批处理（Continuous Batching）允许在推理过程中动态添加和移除请求。

| 特性 | 静态批处理 | 连续批处理 |
|------|-----------|-----------|
| 请求管理 | 固定 batch | 动态添加/移除 |
| GPU 利用率 | 低（等待最长序列） | 高 |
| 延迟 | 高 | 低 |

> 🎯 关键要点：连续批处理是高吞吐推理的关键。
> vLLM、TGI 都支持连续批处理。
> 需要配合 PagedAttention 使用。

### 9. 什么是投机采样（Speculative Decoding）？｜高级

投机采样使用小模型快速生成多个候选 token，然后用大模型验证，加速推理。

**流程：**

1. 小模型快速生成 K 个候选 token
2. 大模型并行验证这 K 个 token
3. 接受正确的 token，拒绝错误的

**优势：**

- 减少大模型的调用次数
- 保持输出质量不变
- 可以加速 2-3 倍

> 🎯 关键要点：投机采样需要小模型与大模型分布接近。
> 接受率是影响加速比的关键。
> 是推理加速的重要研究方向。

### 10. 比较不同的推理框架：vLLM、TGI、TensorRT-LLM。｜中级

| 框架 | 特点 | 适用场景 |
|------|------|---------|
| vLLM | PagedAttention，易用 | 通用推理服务 |
| TGI | HuggingFace 出品 | 与 HF 生态集成 |
| TensorRT-LLM | NVIDIA 优化，最快 | NVIDIA GPU 部署 |

> 🎯 关键要点：vLLM 是目前最流行的开源推理框架。
> TensorRT-LLM 性能最好但部署复杂。
> 选择取决于硬件和需求。
