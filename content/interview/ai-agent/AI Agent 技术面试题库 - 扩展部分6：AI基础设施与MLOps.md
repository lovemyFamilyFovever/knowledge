# AI Agent 技术面试题库 - 扩展部分6：AI基础设施与MLOps

> AI 基础设施与 MLOps（10 题）｜涵盖模型服务、监控、CI/CD、A/B 测试等核心领域。
> 每题标注难度（初级 / 中级 / 高级），编号 1–10 连续，附参考解答与关键要点。

## 主题1：模型服务与部署（5 题）

### 1. 比较不同的模型服务方式：REST API、gRPC、WebSocket。｜中级

| 方式 | 特点 | 适用场景 |
|------|------|---------|
| REST API | 简单、通用、无状态 | 通用推理服务 |
| gRPC | 高效、二进制、有类型 | 内部服务通信 |
| WebSocket | 全双工、实时 | 流式输出 |

> 🎯 关键要点：REST API 是最常用的模型服务方式。
> gRPC 适合高性能内部通信。
> WebSocket 适合实时流式场景。

### 2. 什么是模型版本管理？如何实现？｜中级

模型版本管理跟踪和管理不同版本的模型，支持回滚和 A/B 测试。

**实现方式：**

- **MLflow**：开源 ML 生命周期管理
- **Weights & Biases**：实验跟踪和模型管理
- **DVC**：数据版本控制
- **自建系统**：使用对象存储 + 数据库

**版本信息：**

```json
{
  "model_name": "text-classifier",
  "version": "1.2.0",
  "framework": "pytorch",
  "metrics": {"accuracy": 0.95, "f1": 0.93},
  "created_at": "2024-01-15",
  "artifact_path": "s3://models/text-classifier/v1.2.0/"
}
```

> 🎯 关键要点：版本管理支持快速回滚。
> 需要记录模型元数据和指标。
> MLflow 是常用的开源方案。

### 3. 解释 A/B 测试在模型部署中的应用。｜中级

A/B 测试通过对比新旧模型的表现，科学评估模型改进。

**实施步骤：**

1. 定义评估指标（准确率、延迟、用户满意度）
2. 将用户随机分配到不同组
3. 分别使用新旧模型服务
4. 收集数据并统计分析

**注意事项：**

- 样本量要足够大
- 分流要随机均匀
- 考虑统计显著性

> 🎯 关键要点：A/B 测试是模型上线的标准流程。
> 需要科学的实验设计。
> 统计显著性是关键。

### 4. 什么是模型网关（Model Gateway）？｜中级

模型网关是统一管理模型服务的中间层，提供路由、限流、监控等功能。

**核心功能：**

- **路由**：将请求路由到合适的模型
- **限流**：控制请求速率
- **负载均衡**：分散请求到多个实例
- **监控**：收集性能指标
- **缓存**：缓存重复请求

> 🎯 关键要点：模型网关简化了模型服务管理。
> 支持多模型统一管理。
> 提供企业级的运维能力。

### 5. 解释 Serverless 推理的优势和挑战。｜中级

Serverless 推理无需管理服务器，按需自动扩缩容。

**优势：**

- 无需运维服务器
- 按使用量付费
- 自动扩缩容

**挑战：**

- 冷启动延迟
- GPU 支持有限
- 大模型部署困难
- 成本可能高于预留实例

> 🎯 关键要点：适合小模型和低频请求。
> 冷启动是主要问题。
> 各大云厂商都提供相关服务。

## 主题2：MLOps 与监控（5 题）

### 6. 什么是 MLOps？与传统 DevOps 有什么区别？｜中级

MLOps 是将 DevOps 实践应用于机器学习的工程方法。

| 特性 | DevOps | MLOps |
|------|--------|-------|
| 产物 | 代码 | 代码 + 数据 + 模型 |
| 测试 | 单元测试、集成测试 | + 数据验证、模型评估 |
| 监控 | 系统指标 | + 模型性能、数据漂移 |
| 版本 | 代码版本 | + 数据版本、模型版本 |

> 🎯 关键要点：MLOps 需要管理数据、模型和代码。
> 自动化是 MLOps 的核心。
> 监控需要覆盖模型性能。

### 7. 什么是数据漂移和模型漂移？如何检测？｜高级

漂移是指数据分布或模型性能随时间变化的现象。

**数据漂移：**

- 输入数据分布变化
- 检测方法：统计检验、KL 散度

**概念漂移：**

- 输入和输出的关系变化
- 检测方法：监控模型性能

**应对策略：**

- 持续监控
- 定期重训练
- 在线学习

> 🎯 关键要点：漂移是生产环境的常见问题。
> 需要建立监控机制。
> 定期重训练是常用解决方案。

### 8. 解释 ML Pipeline 的概念和组件。｜中级

ML Pipeline 将机器学习工作流程自动化，包括数据处理、训练、评估和部署。

**典型组件：**

- **数据摄入**：从数据源获取数据
- **数据验证**：检查数据质量
- **特征工程**：数据预处理和特征提取
- **模型训练**：训练模型
- **模型评估**：评估模型性能
- **模型部署**：将模型部署到生产环境

**常用工具：**

- Kubeflow
- Airflow
- MLflow

> 🎯 关键要点：Pipeline 实现 ML 工作流自动化。
> 可重复性是关键目标。
> Kubeflow 是 Kubernetes 上的主流方案。

### 9. 如何监控 LLM 应用的性能？｜中级

LLM 应用的监控需要覆盖技术指标和业务指标。

**技术指标：**

- **延迟**：首 token 时间、总响应时间
- **吞吐量**：每秒请求数、每秒 token 数
- **错误率**：请求失败率
- **资源使用**：GPU 利用率、显存使用

**业务指标：**

- **准确率**：回答正确的比例
- **用户满意度**：用户反馈评分
- **幻觉率**：生成虚假信息的比例

> 🎯 关键要点：需要同时监控技术和业务指标。
> LangSmith 等工具提供 LLM 专用监控。
> 持续优化是目标。

### 10. 解释特征存储（Feature Store）的概念。｜中级

特征存储是管理和共享机器学习特征的中心化平台。

**核心功能：**

- **特征注册**：存储和版本管理特征
- **特征计算**：在线和离线特征计算
- **特征共享**：跨团队共享特征
- **特征服务**：低延迟特征获取

**代表产品：**

- Feast（开源）
- Tecton
- Hopsworks

> 🎯 关键要点：特征存储提高特征复用性。
> 避免训练-推理偏差。
> 是 MLOps 的重要组件。
