# 系统设计面试指南

## 方法论

```
Step 1: 需求澄清（功能/非功能需求，规模估算）
Step 2: 高层设计（API设计、数据模型、核心组件）
Step 3: 详细设计（算法选型、数据流、关键决策）
Step 4: 扩展优化（瓶颈识别、扩展方案、监控告警）
```

## 规模估算速查

| 指标 | 参考值 |
|------|--------|
| 1天秒数 | 86400 ≈ 10^5 |
| 1月秒数 | 2.6M ≈ 10^6 |
| QPS->月请求 | QPS x 2.6M |
| 1条推文大小 | ~1KB |
| 1亿用户数据 | ~100GB |
| 读写比 | 通常100:1（读远多于写） |

## 经典题目

### 设计Twitter

```
发推: POST /api/tweet {content} -> 写入Tweet表 + 推送到粉丝Timeline
拉取: GET /api/timeline -> 查Timeline表(推模式) 或 实时聚合(拉模式)

核心表:
- tweets(tweet_id, user_id, content, created_at)
- follows(follower_id, followee_id)
- timeline(user_id, tweet_id)

扇出策略:
- 推模式(写扩散): 发推时写入所有粉丝的Timeline，读快写慢
- 拉模式(读扩散): 读取时实时聚合关注者的推，写快读慢
- 混合模式: 大V用拉模式，普通用户用推模式
```

### 设计URL短链

```
POST /api/shorten {long_url} -> 生成短码 -> 存储映射 -> 返回短链
GET /{short_code} -> 查映射 -> 302重定向

短码生成:
- 自增ID + Base62编码
- 哈希(MD5/SHA256)取前6-7位
- 预生成ID池
```
