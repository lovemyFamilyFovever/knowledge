# DeepSeek Harness 插件开发完全指南

## 1. 插件系统架构解析：从“乐高积木”到“可编程宇宙”

DeepSeek Harness (DSH) 的插件系统并非一个简单的模块加载机制，而是一套基于**依赖注入 (DI)** 和**控制反转 (IoC)** 原则构建的、高度解耦的“可编程内核”。理解其架构是开发高质量插件的第一步。

**核心设计哲学：“一切皆插件”**
这意味着系统中没有“神圣不可侵犯”的核心组件。无论是底层的大模型调用接口、中间层的工具函数、数据存储适配器，还是上层的用户交互界面，都被抽象为具有统一生命周期的 `Plugin`。这种设计带来了极致的灵活性——你可以轻松替换默认的OpenAI适配器为本地部署的DeepSeek模型，或将命令行界面换成Web UI，而无需修改系统核心代码。

**架构分层图解：**

```
┌─────────────────────────────────────────────────────┐
│                 应用层 (Application)                  │
│    ┌───────────┐   ┌───────────┐   ┌───────────┐    │
│    │  UI 插件  │   │ 业务逻辑  │   │   ...      │    │
│    └───────────┘   └───────────┘   └───────────┘    │
├─────────────────────────────────────────────────────┤
│                 服务层 (Services)                     │
│    ┌───────────┐   ┌───────────┐   ┌───────────┐    │
│    │ 模型服务  │   │ 工具服务  │   │ 存储服务  │    │
│    └───────────┘   └───────────┘   └───────────┘    │
├─────────────────────────────────────────────────────┤
│                 插件内核 (Kernel)                     │
│    ┌───────────────────────────────────────────┐    │
│    │       Cordis 依赖注入容器 + 插件管理器       │    │
│    │  (Dependency Injection & Plugin Manager)  │    │
│    └───────────────────────────────────────────┘    │
├─────────────────────────────────────────────────────┤
│                 基础设施层 (Infrastructure)            │
│    ┌───────────┐   ┌───────────┐   ┌───────────┐    │
│    │ 配置管理  │   │ 日志系统  │   │   环境     │    │
│    └───────────┘   └───────────┘   └───────────┘    │
└─────────────────────────────────────────────────────┘
```

**Cordis 依赖注入框架的核心作用：**
Cordis 是 DSH 的“神经系统”，负责：
1.  **依赖解析**：自动扫描并注入插件声明所需的其他服务。
2.  **生命周期管理**：按照拓扑排序顺序初始化、启动和销毁插件。
3.  **作用域隔离**：通过 `ctx` (上下文) 为每个插件提供独立的服务树，防止全局污染。
4.  **热重载支持**：通过依赖关系智能地卸载和重新加载插件。

**工作空间结构 (pnpm workspace)：**
典型的 DSH 项目采用 monorepo 结构：
```
dsh-project/
├── packages/
│   ├── core/                 # 核心库
│   ├── plugins/              # 官方插件集合
│   │   ├── tool-calculator/  # 计算器工具插件
│   │   ├── provider-ollama/  # Ollama模型提供者插件
│   │   └── ui-web/           # Web界面插件
│   └── app/                  # 主应用（组装所有插件）
├── pnpm-workspace.yaml
└── package.json
```

## 2. 插件类型全景：定义你的“角色”

在 DSH 中，插件通过实现特定的 `Symbol` 或 `interface` 来表明自己的“角色”。以下是主要插件类型：

### 2.1 Tool Plugin (工具插件)
**职责**：为AI助手提供可调用的“手和脚”，扩展其与物理或数字世界交互的能力。
**典型实现**：
- 文件系统操作 (`readFile`, `writeFile`)
- 网络请求 (`httpGet`, `httpPost`)
- 代码执行 (`executePython`)
- 数据库查询
- 第三方API封装

**接口示例**：
```typescript
// @dsh/tools 是核心包定义的命名空间
import { Context } from '@dsh/core';

interface Tool {
  name: string;
  description: string;
  parameters: object; // JSON Schema
  execute: (params: Record<string, any>, ctx: Context) => Promise<any>;
}

// 声明此插件提供工具集
export const inject = ['dsh.tools'];

export function apply(ctx: Context) {
  // 向工具注册中心添加我们的工具
  ctx.dsh.tools.add({
    name: 'weather',
    description: '获取指定城市的天气信息',
    parameters: {
      type: 'object',
      properties: {
        city: { type: 'string', description: '城市名称' }
      },
      required: ['city']
    },
    execute: async ({ city }) => {
      // 调用天气API的实现
      const data = await fetchWeatherAPI(city);
      return `今天${city}天气：${data.condition}，温度${data.temp}°C`;
    }
  });
}
```

### 2.2 Provider Plugin (提供者插件)
**职责**：作为“供应商”，为系统提供某种核心服务的标准化接入。这是实现“可替换性”的关键。

**子类型**：
- **ModelProvider**: 提供大模型推理服务（如OpenAI、DeepSeek、Ollama、vLLM）。
- **EmbeddingProvider**: 提供文本向量化服务。
- **StorageProvider**: 提供持久化存储（如SQLite、Redis、文件系统）。
- **LoggerProvider**: 提供日志记录实现。

**ModelProvider 接口示例**：
```typescript
export interface ModelProvider {
  // 提供的模型列表
  getModels(): Promise<ModelInfo[]>;
  // 执行推理
  chat(options: ChatOptions): Promise<ChatResponse>;
  // 流式推理
  stream(options: ChatOptions): AsyncIterable<StreamChunk>;
}

export function apply(ctx: Context) {
  // 注册为模型提供者
  ctx.dsh.providers.register('deepseek', {
    getModels: async () => [
      { id: 'deepseek-chat', name: 'DeepSeek Chat', contextLength: 128000 }
    ],
    chat: async ({ model, messages }) => {
      // 调用 DeepSeek API 的具体实现
    }
  });
}
```

### 2.3 UI Plugin (界面插件)
**职责**：提供用户与DSH交互的渠道，可以是命令行、Web界面、桌面应用或API服务。

**关键特点**：
- 通常实现 `UIProvider` 接口。
- 负责将抽象的“对话流”和“工具调用”转化为具体的用户交互。
- 可能包含前端资源（HTML/CSS/JS）的构建和提供。

**CLI 插件简化示例**：
```typescript
export function apply(ctx: Context) {
  ctx.dsh.ui.register('cli', {
    start: () => {
      const rl = require('readline').createInterface(process.stdin, process.stdout);
      rl.on('line', async (input) => {
        const response = await ctx.dsh.core.processUserInput(input);
        console.log(`助手：${response}`);
      });
    }
  });
}
```

### 2.4 Core Plugin (核心插件)
**职责**：扩展系统内核能力，通常涉及核心流程的钩子。
**示例**：
- 上下文管理插件（维护对话历史）
- 提示词工程插件（自动构建系统提示）
- 安全过滤插件（内容审核）
- 插件商店/包管理器

### 2.5 Integration Plugin (集成插件)
**职责**：与外部系统深度集成。
**示例**：
- GitHub集成（创建Issue、PR）
- Slack/Teams消息机器人
- Jira任务管理
- 企业内部ERP系统连接器

### 3.3 实现核心服务
`src/services/retriever.ts`：
```typescript
import * as fs from 'fs/promises';
import * as path from 'path';
import glob from 'fast-glob';

export class KnowledgeRetriever {
  private basePath: string;
  private cache: Map<string, string> = new Map();

  constructor(basePath: string) {
    this.basePath = basePath;
  }

  async retrieve(query: string, limit: number = 3): Promise<string[]> {
    // 1. 加载或从缓存获取文档
    const documents = await this.loadDocuments();
    
    // 2. 简单的相关性计算（生产环境应使用向量相似度）
    const scored = documents
      .map(doc => ({
        content: doc.content,
        score: this.calculateRelevance(query, doc.content)
      }))
      .sort((a, b) => b.score - a.score)
      .slice(0, limit);

    // 3. 返回结果
    return scored.map(item => 
      `【来源】${item.source}\n${item.content}`
    );
  }

  private async loadDocuments(): Promise<Array<{path: string, content: string}>> {
    const files = await glob(['**/*.md', '**/*.txt'], {
      cwd: this.basePath,
      absolute: true
    });

    const documents = [];
    for (const filePath of files) {
      let content = this.cache.get(filePath);
      if (!content) {
        content = await fs.readFile(filePath, 'utf-8');
        this.cache.set(filePath, content);
      }
      documents.push({
        path: path.relative(this.basePath, filePath),
        content: content!
      });
    }

    return documents;
  }

  private calculateRelevance(query: string, content: string): number {
    // 简单的关键词匹配算法
    const queryTerms = query.toLowerCase().split(/\s+/);
    const contentLower = content.toLowerCase();
    
    let score = 0;
    for (const term of queryTerms) {
      if (contentLower.includes(term)) {
        score += 1;
      }
    }
    
    // 归一化
    return score / queryTerms.length;
  }
}
```

### 3.4 定义工具接口
`src/tools/knowledge.ts`：
```typescript
import { Tool } from '@dsh/tools';

export const knowledgeSearchTool: Tool = {
  name: 'search_knowledge_base',
  description: '在本地知识库中搜索相关信息。当用户询问关于项目文档、API说明、常见问题等基于文本知识的问题时使用此工具。',
  parameters: {
    type: 'object',
    properties: {
      query: {
        type: 'string',
        description: '搜索查询字符串，描述你想查找的信息'
      },
      max_results: {
        type: 'number',
        description: '返回的最大结果数量，默认为3',
        default: 3
      }
    },
    required: ['query']
  },
  execute: async (params, ctx) => {
    const { query, max_results = 3 } = params;
    
    // 从上下文中获取我们注册的服务
    const retriever = ctx.knowledgeRetriever;
    
    try {
      const results = await retriever.retrieve(query, max_results);
      
      if (results.length === 0) {
        return '未找到相关信息。';
      }
      
      return results.join('\n---\n');
    } catch (error) {
      ctx.logger.error(`知识检索失败: ${error}`);
      return '检索知识库时出现错误。';
    }
  }
};
```

### 3.5 插件主入口
`src/index.ts`：
```typescript
import { Context, Service } from '@dsh/core';
import { KnowledgeRetriever } from './services/retriever';
import { knowledgeSearchTool } from './tools/knowledge';

// 声明此插件需要的依赖
export const inject = ['dsh.tools', 'dsh.logger', 'dsh.config'];

// 定义插件配置接口
interface Config {
  knowledgeBasePath?: string;
  maxCacheSize?: number;
}

// 声明插件类型扩展
declare module '@dsh/core' {
  interface Context {
    knowledgeRetriever: KnowledgeRetriever;
  }
}

export function apply(ctx: Context, config: Config = {}) {
  // 1. 从配置中获取知识库路径，默认为项目根目录下的docs文件夹
  const knowledgeBasePath = config.knowledgeBasePath || 
    path.join(process.cwd(), 'docs');
  
  // 2. 创建服务实例
  const retriever = new KnowledgeRetriever(knowledgeBasePath);
  
  // 3. 将服务注册到上下文中，使其可被其他插件使用
  ctx.knowledgeRetriever = retriever;
  
  // 4. 注册工具
  ctx.dsh.tools.add(knowledgeSearchTool);
  
  // 5. 添加生命周期钩子（可选）
  ctx.on('ready', () => {
    ctx.logger.info(`知识检索插件已加载，文档路径: ${knowledgeBasePath}`);
  });
  
  // 6. 提供卸载时的清理逻辑
  ctx.on('dispose', () => {
    ctx.logger.info('知识检索插件正在卸载，清理缓存...');
    retriever.clearCache();
  });
}
```
