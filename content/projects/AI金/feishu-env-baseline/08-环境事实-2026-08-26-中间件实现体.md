## 1. UserContextMiddleware —— 平台用户身份注入

```js
// src/middlewares/user-context/index.ts（近似还原）
var UserContextMiddleware = class {
  use(req, _res, next) {
    const webUser = getWebUserFromHeader(req);          // ⭐ 从【请求头】解析平台 web 用户
    req.userContext = {
      userId: webUser?.user_id,
      tenantId: webUser?.tenant_id,
      appId: webUser?.app_id ?? "",
      loginUrl: webUser?.login_url ?? "",
      userType: webUser?.user_type ?? "",
      env: webUser?.env ?? "runtime",
      userName: webUser?.user_name?.zh_cn ?? "",
      userNameEn: webUser?.user_name?.en_us ?? "",
      userNameI18n: webUser?.user_name ?? {},
      isSystemAccount: webUser?.is_system_account ?? false,
      roles: webUser?.roles
    };
    next();
  }
};
```

### 📌 关键结论（平台身份体系）
- **平台的用户身份不是从 cookie/session 读**，而是**从请求头**经 `getWebUserFromHeader` 解析（网关会注入平台 web 用户相关头）。
- `req.userContext` 成为后续所有控制器/守卫取"平台当前用户"的单一来源。
- 若前端请求**没带平台会话头**，`req.userContext` 关键字段全为空（userId/appId 等空串）。
- 身份字段结构：userId / tenantId / appId / loginUrl / userType / env / userName(i18n) / isSystemAccount / roles。

## 2. ViewContextMiddleware —— 页面视图上下文（含应用元数据拉取）

```js
// src/middlewares/view-context/index.ts（近似还原）
var ViewContextMiddleware = class _ViewContextMiddleware {
  client;  logger = new Logger(_ViewContextMiddleware.name);
  constructor(client) { this.client = client; }                    // Inject(PLATFORM_HTTP_CLIENT)

  async getAppPublished(appId) {
    // 调平台 GET /b/{appId}/get_published_v2，拉应用发布元数据
    // 失败降级返回 null（不阻塞）
  }

  async use(req, res, next) {
    const { userId, tenantId, appId, loginUrl, userType } = req.userContext;
    const csrfToken = req.csrfToken;                                // ⭐ 来自 CsrfTokenMiddleware
    const environment = mapToWindowEnvironment(process.env.FORCE_FRAMEWORK_ENVIRONMENT);
    const basename = req.headers["x-miaoda-custom-host"] !== void 0
      ? "/"
      : `/app/${appId || ""}`;                                      // ⭐ 前端 basename（app 前缀）
    const appPublishedData = await this.getAppPublished(appId);
    const appInfo = appPublishedData?.app_info ?? null;

    req.__platform_data__ = {                                    // 平台全局数据（注入页面 script）
      csrfToken: csrfToken ?? "", userId, appId, tenantId,
      appName: appInfo?.app_name ?? "妙搭应用",                    // ⭐ 平台动态获取可换名
      appAvatar, appDescription, loginUrl, userType, environment,
      showBadge: appInfo?.show_badge !== false,
      appPublished: safeEscapeDeep(appPublishedData),              // 深 escape 防 script 注入
      basename
    };
    res.locals = { ...res.locals, csrfToken, userId, tenantId, loginUrl, userType,
                   appId, appName, appAvatar, appDescription, environment, basename };
    next();
  }
};
function mapToWindowEnvironment(input) {
  const v = (input || "").trim().toLowerCase();
  if (v === "boe") return "staging";
  if (v === "pre") return "gray";
  // ...(线上默认 'rc'/'production' 等映射)
}
```

### 📌 关键结论
- **basename 二选一**：请求头带 `x-miaoda-custom-host` → `/`；否则 → `/app/{appId}/`。这解释了前端路由的 base 来源。
- **CSRF token 串起来**：页面请求先经 CsrfTokenMiddleware 种 cookie 并设 `req.csrfToken` → ViewContext 读它注入 `req.__platform_data__.csrfToken` 与 `res.locals.csrfToken` → **前端脚本由此拿到 token**，放进 API 请求头完成双提交。链路闭环。
- **动态拉应用元数据**（`get_published_v2`）：appName/avatar/description 是平台实时给的，可换名。
- `req.__platform_data__` 前端全局注入，且用 `safeEscapeDeep` 防 app_description 等用户可控字段的 XSS。
- `environment` 由 `FORCE_FRAMEWORK_ENVIRONMENT` 映射（boe→staging, pre→gray）。

## 3. apiResponseInterceptor —— 防 API 落到 HTML 视图

```js
// src/middlewares/api-response/index.ts（近似还原）
function getApiPathPrefixes() {
  // 计算 api 前缀列表（由 CLIENT_BASE_PATH 导出 /api/ 与 /openapi/）
  return [ `${normalizedPrefix}/api/`, `${normalizedPrefix}/openapi/` ];
}
function apiResponseInterceptor(req, res, next) {
  const apiPrefixes = getApiPathPrefixes();
  if (!apiPrefixes.some((p) => req.baseUrl.startsWith(p))) return next();  // 非 api 放行
  res.render = function() {                       // ⭐ 劫持 res.render
    return res.status(404).json(createApiNotFoundResponse(req));
  };
  next();
}
```

### 📌 关键结论
- 对 `/api/*`、`/openapi/*` 请求，**把 `res.render` 替换成返回 404 JSON**，避免 API 误落到 HTML 视图模板。
- 非 api 前缀请求直接放行（不影响正常页面）。
- 是"API 与 View 边界"的护栏。

## 4. HtmlHotUpdateViewMiddleware —— 生产 HTML 热更新版本回退

```js
// src/middlewares/html-hot-update-view/index.ts（近似还原）
var HtmlHotUpdateViewMiddleware = class {
  use(_req, res, next) {
    if (process.env.NODE_ENV !== "production") return next();   // 仅生产启用
    const originalRender = res.render.bind(res);
    res.render = (view, options, callback) => {
      // 解析 options/callback 重载
      const activeVersion = getActiveHtmlVersion();
      const hotPath = activeVersion ? join(getHotUpdateVersionDir(activeVersion), `${view}.html`) : "";
      if (hotPath && existsSync(hotPath)) return originalRender(hotPath, ...);  // 用热更新版本
      return originalRender(view, options, callback);          // 用默认版本
    };
    next();
  }
};
```

### 📌 关键结论
- 仅生产环境生效（dev 直接 next）。
- 包装 `res.render`：若存在"活跃 HTML 热更新版本目录"里的同名模板，则优先渲染热更新版，否则回退默认模板。
- 是平台"可热替换线上页面壳"的机制（无需完整重新发布即可更新 HTML）。

## 6. 中间件矩阵（血肉版，更新）

| 中间件 | 所在 | 范围 | 职责（实现） | 门控 |
|---|---|---|---|---|
| UserContextMiddleware | core | /\* | 从请求头解析平台 web 用户，注入 req.userContext（userId/tenantId/appId/loginUrl/userType/roles…） | — |
| ViewContextMiddleware | core | 页面(非api) | 拉 get_published_v2 应用元数据；算 basename(`/app/appId` 或 `/` 若 x-miaoda-custom-host)；把 csrfToken+平台数据注入 req.__platform_data__ 与 res.locals | — |
| apiResponseInterceptor | core | /api/*,/openapi/* | 把 res.render 劫持为 404 JSON，防 API 落 HTML 视图 | — |
| HtmlHotUpdateViewMiddleware | core | 页面(非api) | 仅生产：优先渲染热更新版本 HTML，否则回退默认 | NODE_ENV=production |
| CsrfTokenMiddleware | core | 页面(非api) | 种 suda-csrf-token cookie，设 req.csrfToken（供 ViewContext/前端读取） | — |
| CsrfMiddleware | core | /api/* | 校验 header==cookie 双提交，失败 403 | enableCsrf!==false |
| SqlExecutionContextMiddleware | datapaas | /\* | 数据通道 SQL 执行上下文（trace） | DISABLE_DATAPASS |

## 7. 完整链路（页面 → token → API）

```
页面 GET /app/xxx/...
  CsrfTokenMiddleware → 种 suda-csrf-token cookie + req.csrfToken=token
  ViewContextMiddleware → 拉应用元数据; 注入 req.__platform_data__.csrfToken / res.locals
  → 前端脚本读 __platform_data__.csrfToken (或 cookie)
API POST /app/xxx/api/...
  前端带 header x-suda-csrf-token=token (与服务端 cookie 同值)
  CsrfMiddleware → 校验 header==cookie → 通过
  apiResponseInterceptor → res.render→404 JSON 护栏
  UserContextMiddleware → req.userContext (平台 web 用户，来自请求头)
  → 全局 AuthGuard(业务) → Controller
```

## 8. 对业务的影响（本项目）

- **前端请求必须让平台网关注入 web 用户头**，否则 `req.userContext` 空 → 依赖 `req.userContext.userId` 的逻辑拿不到用户。
- **页面首次访问会种 CSRF cookie**；前端做 API 双提交用的 token 从 `__platform_data__.csrfToken` 或 cookie 取。
- `basename`（前端路由 base）= `x-miaoda-custom-host` 存在时 `/`，否则 `/app/{appId}/`——若线上有自定义 host，前端路由 base 会变成 `/`（可能与 API 前缀分离）。
- 业务若新增页面视图，无需管 api 拦截器；但 **API 路由绝不能依赖 `res.render`**（会 404）。

> 敏感值不落库。
