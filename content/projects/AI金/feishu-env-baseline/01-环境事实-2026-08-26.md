## 4. npm scripts（package.json 关键字段）

```
dev:           ./scripts/dev.sh
dev:server:    cross-env NODE_ENV=development nest start --watch
dev:client:    cross-env NODE_ENV=development vite --config vite.config.ts
gen:db-schema: npx -y @lark-apaas/db-schema-sync@latest --output server/database/schema.ts --export-custom-types
gen:openapi:   echo 'UNSUPPORTED, SKIP'
build:         ./scripts/build.sh               ← 发布编译真正入口
build:prod:    npm run build:server && npm run build:client
build:server:  NODE_ENV=production nest build
build:client:  NODE_ENV=production vite build --config vite.config.ts
start:         NODE_ENV=production node dist/server/main.js
test:          jest
type:check:    concurrently server(client)  → tsc --noEmit (tsconfig.node.json / tsconfig.app.json)
lint:          node ./scripts/lint.js
format:        prettier --write "{server,client,test}/**/*.{js,ts,tsx,json,md}"
prepare:       git config core.hooksPath .githooks 2>nul || ver>nul
precommit:     node scripts/hooks/run-precommit.js
postinstall:   echo 'Skipped: fullstack-cli action-plugin init'
dev:local:     node ./scripts/dev-local.js       ← 本地启动入口
```

### 🔎 解析
- **schema.ts 生成器** = `@lark-apaas/db-schema-sync`（`--export-custom-types`），平台版本由 `db-schema-sync@latest`，故本地需对齐此工具行为。
- **`build` = `./scripts/build.sh`**：平台发布走的编译脚本，本地只有 `build:prod`（nest build + vite build），两者可能**不一致**——平台很可能在 build.sh 里做了平台专属处理（如注入、剥敏感、拷贝平台资产）。**必须读 build.sh**。
- **本地启动走 `./scripts/dev-local.js`**（非 dev.sh），说明平台对「本地」「沙箱」用了不同脚本——`dev-local.js` 正是我们在本地复现的关键。
- `prepare` 设 hooks path = `.githooks`；我们本地此前改过 hooks，需对照飞书原版确认是否一致。
- `postinstall` 平台默认跳过 `fullstack-cli action-plugin init`。

## 5. miaoda CLI

版本 `0.1.38`，描述「妙搭平台 CLI，提供数据服务、文件存储等命令行操作」。

```
Commands:
  app        应用元数据管理：查看 / 修改 / 初始化 / 升级平台资产
  deploy     触发发布；支持 --wait 阻塞到终态。子命令：get / history / error-log
  db         应用数据库（PostgreSQL）命令行操作集合
  file       应用文件存储（TOS）命令行操作集合（UGC 资源）
  observability  可观测性：查询线上日志、链路、监控指标、运营指标
  skills     本地 agent skills（含 steering）维护
  registry   组件 registry：列出 / copy-in SDK 文件
Global Flags:
  --version / --json [fields] / --output pretty|json / --verbose / -y / -h
```

### 🔎 解析
- 关键子命令：**`deploy get|history|error-log`**（看发布结果/历史/报错）、**`db`**（数据库）、**`observability`**（线上日志/链路——排查线上问题利器）、**`registry copy-in SDK 文件`、（也许可把平台 SDK 拉回本地研究）。
- 后续探针：`miaoda deploy --help`、`miaoda db --help`、`miaoda observability --help`、`miaoda registry --help`。
