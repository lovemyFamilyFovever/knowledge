# 07-跨环境同步指南

> 最后更新：2026-08-02
>
> 目的：说明本地开发环境（`C:\Users\liuxi\Desktop\code`）与飞书生产环境之间的代码同步流程。
>
> **核心原则**：本地和飞书两地的 `client/`、`server/`、`shared/`、`erp/` 四个文件夹 + `.env` 保持同步。飞书多维表格 API 通过 `FeishuBitableService`（@Global）+ `.env` 中的 `BITABLE_*` 配置调用，**本地和飞书环境都能直接调用**，无需到飞书平台上操作。

## 一、同步流程（简化版）

### 标准同步操作

将本地代码同步到飞书，只需复制以下 4 个文件夹 + 1 个配置文件：

```
client/      →  前端代码
server/      →  后端代码
shared/      →  共享类型与工具
erp/         →  ERP 后台
.env         →  环境变量配置
```

**操作步骤**：

1. 本地开发完成，确认 `npm run type:check` 无错误
2. 将上述文件夹和 `.env` 复制覆盖到飞书工作台对应位置
3. 在飞书平台构建并验证功能

### 少数需按环境修改的文件

| 文件 | 差异点 |
|------|--------|
| `.env` | `SUDA_DATABASE_URL`、`SERVER_PORT` 等按环境；`BITABLE_*`、`BAILIAN_*` 等两地一致 |

> **提示**：得益于 `isLocal` 机制，`app.module.ts`、`main.ts`、`index.html`、`vite.config.ts` 两地代码一致，无需手动适配。详细文件分类见 `03-部署与同步规范.md`。

## 三、`isLocal` 机制说明

```typescript
const isLocal = !process.env.SUDA_DATABASE_URL;
```

| 环境 | `SUDA_DATABASE_URL` | `isLocal` | 行为 |
|------|-------------------|-----------|------|
| 本地 | 空 | `true` | `main.ts` 走本地静态资源 + hbs 渲染；跳过 `PlatformModule` |
| 飞书 | 自动注入 | `false` | `main.ts` 调用 `configureApp`；加载 `PlatformModule.forRoot()` |

**要点**：同一份代码复制到飞书后，`isLocal` 自动变为 `false`，走生产分支，不需要修改代码。

## 五、飞书多维表格本地调用说明

飞书多维表格 API 通过 `FeishuBitableService`（`@Global` 模块）调用，本地和飞书环境都能直接使用。

```
本地代码 → FeishuBitableService → 飞书多维表格 API（云端）
              ↑ 读取 .env 中的 BITABLE_* 配置
```

### 支持的飞书多维表格

| 业务 | 环境变量前缀 | 用途 |
|------|------------|------|
| VIP 套餐 | `BITABLE_VIP_*` | 用户/套餐/功能特性/购买记录/成员关系/操作日志（6 张表） |
| AI 反馈 | `BITABLE_FEEDBACK_*` / `BITABLE_SITE_FEEDBACK_*` | 站点反馈同步 |
| 统计 | `BITABLE_STATS_*` | 页面访问/运营统计 |
| Token 统计 | `BITABLE_TOKEN_STATS_*` | Token 消耗 |
| ~~数据大屏~~ | ~~`BITABLE_ACQUISITION_*` / `BITABLE_SUCCESS_*` / `BITABLE_KEY_ACCOUNT_*` / `BITABLE_TARGET_*`~~ | ~~部门 KPI 与月度目标~~（**已下线** 2026-08-18） |
| AI 广场 | `BITABLE_PLAZA_*` | 帖子/评论/点赞/关注等（12 张表） |
| 聊天记录 | `BITABLE_CHAT_*` | 客服/问答记录 |
| 店铺装修 | `BITABLE_STORE_DECORATION_*` | 店铺装修 |

### 本地调用要求

以 VIP 为例，`.env` 中需配置：

```bash
BITABLE_MAIN_APP_TOKEN=<APP_TOKEN>
BITABLE_VIP_USERS_TABLE_ID=<TABLE_ID>
BITABLE_VIP_PACKAGES_TABLE_ID=<TABLE_ID>
BITABLE_VIP_FEATURES_TABLE_ID=<TABLE_ID>
BITABLE_VIP_PURCHASES_TABLE_ID=<TABLE_ID>
BITABLE_VIP_MAPPING_TABLE_ID=<TABLE_ID>
BITABLE_VIP_OPERATION_LOG_TABLE_ID=<TABLE_ID>
```

配置后本地开发时对应业务即可直接读写飞书多维表格，无需到飞书平台上操作。

## 六、常见问题

### Q: 本地修改了代码，复制到飞书会怎样？

A: 只要不破坏 `isLocal` 判断结构（`app.module.ts`、`main.ts`），复制后自动走生产分支。建议只改 `modules/`、`common/` 下的业务代码。

### Q: 本地能调用飞书多维表格吗？

A: ✅ 能。通过 `FeishuBitableService` + `.env` 的 `BITABLE_*` 配置，本地可直接调用，无需到飞书平台操作。

### Q: VIP 模块需要同步到飞书吗？

A: ✅ 需要。`server/modules/vip/` 和前端 VIP 相关文件与其他业务代码一样复制即可，`VipService` 通过 `FeishuBitableService` 调用多维表格，两地都能正常工作。

### Q: 本地如何测试飞书特有功能？

A: 依赖飞书集群的能力（飞书认证、消息通知）本地无法测试；多维表格可本地直接调用测试。其余需部署到飞书后验证。

### Q: 新增了 API 接口，飞书怎么同步？

A: 新增接口若不在 `isLocal` 判断块内，复制后自动可用。若写进了 `if (isLocal)` 块，飞书端不会执行——需去掉条件或写 `else` 分支。

---

## 七、代码规范

1. **飞书特有代码**：用 `isLocal` 条件包裹，确保本地跳过但飞书正常执行
2. **本地特有代码**：放 `if (isLocal)` 块内，或写在飞书不需要的文件中
3. **共同代码**：不做条件判断，两地都能运行
4. **资源路径**：生产用 `client/public/`（logo、lib 等），本地开发路径需一致
