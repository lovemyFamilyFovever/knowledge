## 一、环境配置类

### 2026-06-17：飞书白屏 - index.html 路径错误

**现象**：飞书部署后页面白屏，`#app` 容器为空。

**根因**：本地 `index.html` 脚本路径是 `/src/main.ts`，飞书需要 `/client/src/main.ts`。

**现状**：已统一为 `/client/src/main.ts`（根目录 `index.html` 与 `client/index.html` 一致），此坑已消除。

---

### 2026-06-10：VITE_REQUIRE_AUTH=false 不生效

**现象**：设置 `VITE_REQUIRE_AUTH=false` 后重启服务仍跳登录页。

**根因**：旧版 `vite.config.local.ts` 缺少 `envDir`，Vite 从 `client/` 查找 `.env`，而 `.env` 在项目根目录。

**现状**：`vite.config.local.ts` 已删除，Vite 配置统一在根目录 `vite.config.ts`，`.env` 在项目根目录，此坑已消除。

---

### 2026-06-09：本地接口地址配错

**现象**：本地代理请求远程接口失败，超时或连接拒绝。

**根因**：旧版 `.env` 中 `BXG_API_HOST` 等配错（当时本地走内网地址）。

**现状**：`.env` 已统一使用公网地址（`https://www.51bxg.com` / `https://www.xiuma.com`），本地直连真实接口。

---

### ⚠️ 修改 `.env` 后不生效

`.env` 修改后必须**重启后端**（`npm run dev:server` 或 `scripts/restart-server.ps1`）。前端 `VITE_*` 变量由 Vite 启动时读取，修改后需重启 `dev:client`。

### ⚠️ PowerShell 不支持 `set NODE_ENV=xxx && ...`

Windows PowerShell 不支持该语法。npm scripts 一律用 `cross-env`，或直接 `npm run dev:server` / `npm run dev:client`。

## 二、AI 功能类

### 2026-06-19：AI 返回原始 JSON 格式

**现象**：飞书 AI 问答返回 `{"type":"thinking","content":"..."}` 原始 JSON。

**根因**：飞书 `ai.controller.ts` 是旧版本，缺少 delta JSON 解析逻辑，本地版本有。

**解决**：将本地 `ai.controller.ts` 同步到飞书（现在两地已统一为一份代码）。

---

### 2026-06-10：AI 接口 500 错误

**现象**：判行情页面调用 AI 分析返回 500。

**根因**：页面调用 `/api/ai/sync`，但服务器只有 `/api/ai/chat`（当时未实现 sync）。

**解决**：改调流式接口。当前 `/api/ai/sync` 已实现，但页面统一走 `createStreamConnection`（SSE）。

---

### 2026-07：AI SSE 事件类型缺失与类型定义修复

**现象**：TS 编译报错，`ChatMessage`/`StreamCallbacks` 字段缺失；进度条、图表无法渲染。

**根因**：前端类型定义与后端 SSE 实际事件不一致，SSE 处理器缺少 `analysis_progress` 和 `chart` 事件分发。

**服务端 SSE 事件**（当前 `/api/ai/chat` 已全部处理）：

| 事件 type | 说明 | 客户端处理 |
|-----------|------|:---:|
| `start` | 会话开始 | ✅ |
| `delta` | 文本增量 | ✅ |
| `thinking` | 思考过程 | ✅ |
| `analysis_progress` | 分析进度（identify/data_query/answer_generation/chart_generation） | ✅ |
| `keywords` | 关键词 | ✅ |
| `chart` | 结构化图表 | ✅ |
| `done` | 完成（requestId/totalTokens/references/durationMs） | ✅ |
| `error` | 错误 | ✅ |

**经验**：新增 SSE 事件时必须同步更新 `client/src/api/ai.ts` 的类型定义与分发逻辑。

---

### 2026-07-12：词典服务并发竞态 / CSRF 令牌 / 缓存刷新

词典模块（`server/modules/ai/dictionary.service.ts` 等）曾存在并发竞态、写操作缺 `x-suda-csrf-token`、缓存失效不全等问题。

**现状**：该模块代码已删除，词典能力由 ERP「AI 问答词典管理」承接。相关经验保留：
- 写操作请求必须带 `x-suda-csrf-token`（从 cookie 读取）
- 并发写要注意原子性；缓存变更要及时失效

## 三、登录注册类

### 2026-06-19：登录页面按钮无反应

**现象**：飞书「立即注册」「忘记密码」按钮点击无反应。

### 2026-06-10：登录成功后不跳转

**根因**：`handleLogin` 有冗余的 `auth.isLoggedIn` 检查，登录后 localStorage 尚未更新导致检查失败。

**解决**：移除冗余检查，仅判断 `res.success`。

## 四、编码类

### 2026-06-22：flex + overflow-hidden 阻断移动端滚动链

**现象**：AI 测价等页面移动端无法滚动，内容被截断。

**根因**：父容器 `overflow-hidden` + flex 包裹 `overflow-y-auto` 子元素，父级 `overflow: hidden` 阻断子滚动容器触摸事件传递（iOS Safari 常见）。

**修复方案**：
- 父容器仅用于 flex 裁剪时移除 `overflow-hidden`（子容器独立滚动）
- 弹窗场景将 `overflow-hidden` 改为 `overflow-y-auto`（保留圆角裁剪且不阻断滚动）
- 使用 `min-h-0` 而非 `overflow-hidden` 启用 flex 子元素收缩

### 2026-06-21：PowerShell Set-Content 损坏 UTF-8 中文

**现象**：Vite 报 `Utf8Error`，`.vue` 中文字符变乱码（`登录` → `登�?`）。

**根因**：`Set-Content` 未指定 `-Encoding`，中文 Windows 默认 GBK 写回 UTF-8 文件，字节边界错位。

**修复/预防**：
- PowerShell 写文件必须显式 `-Encoding UTF8`
- 涉及中文内容优先用 Node.js 脚本处理文件

## 五、代理服务类

### 2026-06-09：51bxg WAF 拦截

**现象**：代理请求 51bxg 返回 HTML（阿里云 WAF 挑战）而非 JSON，响应含 `aliyun_waf_aa`。

**根因**：服务器 IP 被阿里云 WAF Bot 检测拦截。

**WAF 绕过原理**：
1. WAF 返回 HTML 含两个 `<script>`：第一个定义 `setCookie()`/`reload()`，第二个是高度混淆的 JS 计算 cookie 值
2. 执行混淆 JS 后设置 `acw_sc__v2` cookie（`10位+横杠+40位`，共 51 字符）
3. 携带正确 cookie 重试通过验证

> ⚠️ **不能简单取 `arg1` 拼接 cookie**，必须完整执行混淆 JS。`arg1` 只是中间变量。

**当前实现**（`server/common/services/waf-bypass.service.ts`，@Global）：
- `isChallenge(html)`：检测是否 WAF 挑战页
- `solve(html, origin)`：jsdom 模拟 DOM 执行混淆 JS，返回 cookie
- 51bxg 与 xiuma 各自缓存 cookie（`wafCookie` / `wafCookieXiuma`）

**注意事项**：
- jsdom 不是真实浏览器，WAF 目前只查 cookie；若 WAF 升级要求浏览器指纹（WebGL/Canvas），需升级 Playwright/Puppeteer
- 飞书服务器 IP 可能已在白名单，不一定触发

### ⚠️ 51bxg 登录会话 Cookie（sessionStore）

ProxyService 按 `loginName` 保存 51bxg `Set-Cookie`，TTL 2 小时。会话过期后接口可能返回未登录错误，重新登录即可恢复。

### 2026-08-14：登录返回“服务器返回了无效的响应 (HTTP 201)”

**现象**：前后端可以正常启动，但账号登录时前端提示服务端返回了无效响应；`POST /api/auth/login` 的状态码为 201，响应体为空。

**根因**：51bxg WAF 在登录 API 前新增了一次 301 同源跳转，`Location` 会在原 URL 后追加 `_d_id`，并通过 `Set-Cookie` 下发 `acw_tc`。Node.js 原生 `http.request` 不会自动跟随跳转，ProxyService 因而把 301 的空响应体返回给 NestJS；POST 路由默认显示为 HTTP 201。

**修复**：`ProxyService.doRequest` 最多跟随 5 次同源 3xx，保持 POST 请求体，并把每一跳的 Cookie 合并到后续请求。禁止跨源跳转，避免认证请求体被转发到其他站点。密码登录和短信登录路由显式返回 HTTP 200。

## 常见问题速查

| 问题 | 可能原因 | 排查方法 |
|------|---------|---------|
| 飞书白屏 | 构建/路由问题 | 检查浏览器控制台资源加载、`/client/src/main.ts` 路径 |
| 接口返回 HTML | WAF 拦截 | 检查响应是否含 `aliyun_waf_aa`，看 waf-bypass 日志 |
| 接口 404 | 路由未注册 | 检查 controller 是否已 import 到模块、路径前缀 |
| 登录后权限为空 | 多维表格未配置 | 检查 `.env` 中 `BITABLE_VIP_*`，后端 `permission` 是否注入 |
| 前端连不上后端 | 端口不匹配 | 后端 `SERVER_PORT` 与 `vite.config.ts` 的 `/api` 代理目标（8000）一致 |
| 端口被占用 | 旧进程残留 | `netstat -ano \| findstr :8000` 后 `taskkill`，或跑 `restart-server.ps1` |
| 修改 .env 不生效 | 未重启 | 重启后端 / 前端 Vite |
| ERP 接口测试页白屏 | 鉴权放行 | `/erp/api-test` 在路由守卫中跳过鉴权，确认未改回 |
