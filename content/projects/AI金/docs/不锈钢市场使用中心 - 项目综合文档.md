## 三、数据源接口

项目中有两个外部数据源，调用方式不同：

### 3.1 51bxg（REST API）

| 维度 | 说明 |
|------|------|
| 协议 | REST API（HTTP POST） |
| Content-Type | `application/x-www-form-urlencoded` |
| Body 格式 | `z_data=JSON.stringify(params)` |
| 代理路径 | `/api/proxy/51bxg/{controller}/{method}` |

**接口地址格式：**
```
{BXG_API_HOST}/api_web/{controller}/{method}?z_access_mode=web_service
```

**返回格式：**
```json
{
  "WS_RET_CODE": 0,
  "WS_RET_MSG": null,
  "WS_RET_PLAT": "PC",
  "WS_RET_DATA": { ... }
}
```

**已知接口清单：**

| Controller | Method | 用途 |
|------------|--------|------|
| `General` | `PostLogin` | 用户登录 |
| `ArticleCommon` | `PostAnalysisComment` | 获取分析评论/资讯 |

### 3.2 xiuma（SOAP WebService）

| 维度 | 说明 |
|------|------|
| 协议 | SOAP 1.1（HTTP POST） |
| Content-Type | `text/xml; charset=utf-8` |
| SOAPAction | `http://tempuri.org/{method}` |
| 参数格式 | JSON 字符串放在 `<strParams>` 标签中 |
| 代理路径 | `/api/proxy/xiuma/{method}` |

**接口地址格式：**
```
{XIUMA_API_HOST}:{XIUMA_API_PORT}{asmx_path}
```

**xiuma 有两个 .asmx 服务（无默认，按方法映射）：**

| .asmx 路径 | 方法 | 用途 |
|------------|------|------|
| `/api/product_manage.asmx` | `GetEnquiryList` | 获取询价单/配单列表 |
| `/api/product.asmx` | `QueryRecommendProductInfo` | 查询推荐产品信息 |

> **注意**：xiuma 接口没有默认 .asmx 路径，每个方法必须在 `proxy.service.ts` 的 `getXiumaPath()` 中配置映射。

**SOAP 请求格式示例：**
```xml
<?xml version="1.0" encoding="utf-8"?>
<soap:Envelope xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
               xmlns:xsd="http://www.w3.org/2001/XMLSchema"
               xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <GetEnquiryList xmlns="http://tempuri.org/">
      <strParams>{"USER_ID":"1459155812416838","page_num":0,"page_size":10}</strParams>
    </GetEnquiryList>
  </soap:Body>
</soap:Envelope>
```

### 3.3 前端统一调用方式

```typescript
import { fetchProxyApi } from '@/api/proxy'

// 51bxg 接口
const result = await fetchProxyApi({
  source: '51bxg',
  controller: 'General',    // Controller 名
  method: 'PostLogin',      // 方法名
  body: { loginName: '...', Password: '...' },
  skipToken: true,          // 登录接口不需要传认证信息
})

// xiuma 接口
const result = await fetchProxyApi({
  source: 'xiuma',
  method: 'GetEnquiryList', // 方法名
  body: { USER_ID: '...', page_num: 0, page_size: 10 },
})
```

### 3.4 代理链路

```
前端 → NestJS 后端 → 目标 API
         ↑
    代理转发层
```

**51bxg 代理流程：**
```
POST /api/proxy/51bxg/{controller}/{method}
→ NestJS ProxyController
→ ProxyService.forwardTo51bxg()
→ POST {BXG_API_HOST}/api_web/{controller}/{method}?z_access_mode=web_service
→ 返回 { code, msg, data }
```

**xiuma 代理流程：**
```
POST /api/proxy/xiuma/{method}
→ NestJS ProxyController
→ ProxyService.forwardToXiuma()
→ 查找 method → asmx 路径映射
→ 构建 SOAP XML → POST {XIUMA_API_HOST}:{PORT}{asmx_path}
→ 解析 SOAP XML 响应
→ 返回 { code, msg, data }
```

## 七、阿里云 WAF 绕过方案

### 7.1 背景

NestJS 后端代理请求到 51bxg.com。公司 IP 不受 WAF 挑战（白名单/低风险池），但家庭 IP 会被阿里云 WAF Bot 检测拦截，返回 JS 挑战页面而非 JSON 数据。

拦截标记：响应中包含 `aliyun_waf_aa`。

### 7.2 原理

1. WAF 返回的 HTML 包含两个 `<script>` 块：
   - 第一个定义 `setCookie()` / `reload()` 函数
   - 第二个是高度混淆的 JS，真正计算 cookie 值
2. 客户端执行混淆 JS 后设置 `acw_sc__v2` cookie，格式为 `10位+横杠+40位`（共 51 字符）
3. 携带正确 cookie 重试即可通过 WAF 验证

**重要**：不能简单取 `arg1` 拼接 cookie，必须完整执行混淆 JS。`arg1` 只是中间变量，最终 cookie 值由多个变量运算得出。

### 7.3 实现方式

使用 **jsdom**（非真实浏览器）在 Node.js 中模拟 DOM 环境，执行 WAF 下发的混淆 JS。

**依赖安装**：
```
npm install jsdom
```

**核心逻辑**（`server/modules/proxy/proxy.service.ts`）：

| 方法 | 作用 |
|------|------|
| `isWafChallenge()` | 检测响应是否包含 `aliyun_waf_aa` 或 `acw_sc__v2` |
| `solveWafChallenge()` | 用 JSDOM 加载 WAF 页面 → 执行 JS → 读取 `document.cookie` |
| `forwardTo51bxg()` | WAF 检测 → 解挑战 → 缓存 cookie → 重试 |

**Cookie 优先级**：重试时传入的 > `this.wafCookie` 缓存 > `BXG_COOKIE` 环境变量

```typescript
// solveWafChallenge 核心代码
private solveWafChallenge(html: string): string | null {
  const dom = new JSDOM(html, {
    url: 'https://www.51bxg.com/',
    referrer: 'https://www.51bxg.com/',
    runScripts: 'dangerously',
  })
  const cookie = dom.window.document.cookie
  dom.window.close()
  return cookie || null
}
```

### 7.4 测试验证

- 测试账号：18066085130 / xyh123456
- jsdom 成功执行 WAF 混淆 JS，`document.cookie` 获取到正确 cookie
- 重试成功拿到真实 JSON，`code=0` 登录成功
- cookie 缓存在 `this.wafCookie`，后续请求复用，直到过期才重新挑战
- jsdom 执行时有 "Not implemented: navigation to another Document" 警告，不影响结果

### 7.5 注意事项

- jsdom **不是真实浏览器**，只是 DOM 模拟。WAF 目前只检查 cookie，不查高级浏览器指纹（WebGL、Canvas 等）
- 如果 WAF 未来升级检测策略（例如要求执行 WebGL 指纹），jsdom 方案可能失效，届时需升级为 Playwright/Puppeteer 等真实浏览器方案
- 本地测试工具（`E:\chen\code\api-test\proxy.js`）也已同步此 WAF 绕过能力
- 部署到飞书妙搭时，飞书的服务器 IP 可能已在白名单中，不一定需要此方案

## 八、常见问题

### 8.1 `.env` 配置错误导致接口失败

**问题**：误将 `.env` 中的接口地址配为生产环境（`https://www.51bxg.com`、`https://www.xiuma.com`），导致本地代理请求远程接口失败。

**正确配置**：
```env
BXG_API_HOST=http://127.0.0.1
XIUMA_API_HOST=http://www.zerp.cn:88
XIUMA_API_PORT=88
```

**排查方法**：检查 `.env` 中 `BXG_API_HOST` 是否为 `http://127.0.0.1`，修改后需重启后端服务。

### 8.2 `XYH_USER_ID` 取不到（非秀吗用户）

**问题**：登录成功后，`AiStockPage.vue` 等页面无法获取 `USER_ID`。

**原因**：该账号 `IS_XYH` 为 `false`，登录返回数据中没有 `XYH_USER_ID` 字段，导致：
1. `auth.ts` 中 `xyhUserId.value` 被设为空字符串 `''`
2. `persist()` 因空字符串为 falsy 值，不写入 localStorage
3. 页面中 `if (authStore.xyhUserId)` 条件为假，不传递 `USER_ID`

**典型返回（非秀吗用户）**：
```json
{
  "WS_RET_DATA": {
    "IS_XYH": false,
    "XYH_USER_ID": null
  }
}
```

**排查方法**：在浏览器控制台检查登录接口返回数据中 `IS_XYH` 是否为 `true`。非秀吗账号无法获取 `XYH_USER_ID`，属于账号本身问题，非代码 BUG。

### 8.3 `VITE_REQUIRE_AUTH` 不生效

**问题**：设置 `VITE_REQUIRE_AUTH=false` 后重启服务，仍然跳转到登录页。

**原因**：`vite.config.local.ts` 中需添加 `envDir: path.resolve(__dirname)`，否则 Vite 从 `client/` 目录查找 `.env`，而 `.env` 在项目根目录。

## 十二、其他注意事项

1. **CSRF Token**：前端请求会自动携带 `x-suda-csrf-token` header（从 cookie 读取），飞书妙搭平台要求此字段。
2. **USER_ID 可选**：xiuma 的 `GetEnquiryList` 接口中 `USER_ID` 可不传，不传时返回全部数据。
3. **搜索字段模糊匹配**：`MATERIAL_CODE`、`SURFACE_CODE`、`SPEC_CODE` 支持模糊搜索。
4. **百炼 API**：通过后端代理调用百炼 API（详见 `bailian.service.ts`）。
