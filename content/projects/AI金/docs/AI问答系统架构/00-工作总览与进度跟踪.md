## 一、项目背景

### 1.1 项目定位
公司基于阿里千问百炼平台开发不锈钢垂直领域大模型"AI金"，目标是成为不锈钢行业的智能伙伴。

### 1.2 当前状态
- ✅ 已完成：百炼 App 2.0、知识库与数据连接器、数据权限治理、能力核验、canonical 结构化图表、关键指标、一句话结论、SSE 稳定渲染、PostgreSQL 聊天记录/Token/反馈、历史会话同步与侧栏交互

### 1.3 核心问题诊断（历史结论，仍成立）
**一句话诊断**：早期把"检索增强生成（RAG）"当成了"AI 智能体（Agent）"用。

**五个病因（v2.x 时期）**：
| # | 问题 | 具体表现 |
|---|------|----------|
| 1 | 过度依赖RAG，抑制了模型推理 | Prompt里写死了"只能基于以下context回答" |
| 2 | 没有Query Understanding | 用户问"304下周会涨吗"被原样送去做向量检索 |
| 3 | 没有工具调用（Function Calling） | 既查不了价格数据库，也搜不了实时新闻 |
| 4 | 数据形态单一 | 结构化数据（价格/库存）当文档用，需要SQL查询 |
| 5 | 没有推理层（ReAct/Plan-and-Execute） | 单次检索→直接生成，遇到复合问题就崩 |

## 二、架构（v3.0）

```
用户提问 → AiController(/api/ai/chat) → PipelineService
    → AiGovernanceService（INTERNAL/EXTERNAL + 敏感数据 + 能力核验）
    → 路由决策（能力核验/内部新闻/外部官方信息/内部市场数据/通用）
    → BailianService（快速模式 qwen-turbo / 专家模式 百炼App）
    → 百炼 Agent 2.0（SQL + 知识库 + 受控来源）
    → observation 汇总与 canonical 数据口径
    → SSE（delta/content + analysis_progress/thinking + chart/metrics/conclusion + done）
    → 前端任务级暂存、固定渲染顺序和完整快照校正
    → PostgreSQL（ai_chat_records + ai_token_records + ai_feedbacks）
```

**设计原则**：
- 信任模型的语义理解能力，不在本地加正则/词典/小模型做预处理
- 后端保留「权限与内容治理 + 轻量路由 + 结构化数据构建 + 展示清洗 + 数据持久化」职责
- 联网搜索受限白名单，竞品平台不作为依据
- 图表、指标、核心数据表和价格结论必须共用同一 canonical series
- SSE 事件允许乱序到达，前端必须按任务绑定合并，不能依赖发送时序

## 五、意图路由（v3.0 query-policy）

v3.0 不再使用本地 QU 分类器。当前先经过 `AiGovernanceService`，再进入 `ai-query-policy.ts` 的轻量路由：

| 路由 | 匹配示例 | 行为 |
|------|----------|------|
| `data-capability-check` | “AI金有没有镍价数据” | 实际核验内部来源，返回四态能力结果 |
| `internal-industry-news` | "51不锈钢最近有什么新闻"、"不锈钢行业动态" | 强制注入内部资讯查询提示，禁用联网 |
| `external-official-public-info` | "政府/协会/上市公司公告" | 返回直接响应「暂未检索到可核实的公开信息」 |
| `internal-market-data` | "304无锡什么价"、"近期库存走势" | 注入图表规则指令，可能生成折线/柱状/饼图 |
| `general` | 材质知识、通用问题 | 透传，百炼自主决定 |

同时由 `price-chart-policy.ts` 判定图表意图（line/bar/pie/none），由 `search-source-policy.ts` 管理联网白名单。

> 设计取舍：v3.0 初版是"纯直通"（无路由），后续发现外部官方信息查询需要白名单 + 内部资讯需要强制路由，才补回这一层轻量策略。它不解析用户实体、不做语义分类，只是边界约束。

## 七、关键决策记录

| 日期 | 决策 | 原因 |
|------|------|------|
| 2026-06-24 | 使用 Agent 2.0 而非 1.0 | Agent 2.0 将 KB 和 MCP 统一为工具，模型自主规划 |
| 2026-06-27 | System Prompt 必须包含 schemaName=public | 模型默认填连接器名称 bxgvip，导致查询失败 |
| 2026-06-27 | System Prompt 必须包含字段映射规则 | 模型把"2B"对应到 productsortname 而非 surfacename |
| 2026-06-27 | System Prompt 必须包含安全规则 | 模型会输出 SQL 语句 |
| 2026-06-27 | 百炼平台星号会被解析为 markdown | 提示词被破坏，统一用字母 x 代替 |
| 2026-07-20 | **v3.0：移除本地预处理链路，百炼直通** | 规则引擎比 LLM 脆弱，删 7 个文件（-1658行），System Prompt 升 v8 |
| 2026-07 | **补回 query-policy 轻量路由** | 外部官方信息需白名单约束、内部资讯需强制路由、图表需意图判定 |
| 2026-07 | **结构化图表由后端生成** | 模型自由输出 ECharts 不可控，改由 ai-chart-builder 从查询结果构建，前端只渲染 |
| 2026-08 | **聊天记录/Token 统计持久化** | 支持 ERP 审计，未登录用户不保存 |
| 2026-08 | **AI 业务持久化统一到 PostgreSQL** | 避免 Bitable 容量和跨环境差异，统一通过 `AiRepository` |
| 2026-08 | **价格结构化组件共用 canonical series** | 消除图表、指标、表格和结论的价格口径漂移 |
| 2026-08 | **SSE 接收与展示解耦** | chart/metrics/conclusion 可能乱序，前端按任务暂存并固定布局 |
| 2026-08-21 | **走势结论由内部数据计算** | 避免模型开场白或思考过程被误当作 AI 结论 |
