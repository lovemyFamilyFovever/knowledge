# 历史记录、会话同步与侧边栏交互

> 当前实现快照：2026-08-21  
> 存储：PostgreSQL `ai_chat_records` + 浏览器 localStorage 兼容层

## 一、当前方案

当前聊天记录不再以飞书多维表格作为正式存储。`ChatRecordService` 通过 `AiRepository` 和 Drizzle ORM 写入 PostgreSQL 表 `ai_chat_records`。

浏览器仍保留 `historyChat_guest`，用于即时交互、离线兼容和旧数据迁移；登录用户的跨设备历史以 PostgreSQL 为准。

```text
新问答完成
  → ChatRecordService.upsertRecord()
  → ai_chat_records

打开 AI 问答页
  → 本地 historyChat_guest 立即展示
  → GET /api/ai/chat-history 同步服务端会话摘要
  → 点击会话时 GET /messages 懒加载完整消息
```

## 二、表结构

`server/database/schema.ts` 中的 `ai_chat_records` 主要字段：

| 字段 | 说明 |
|---|---|
| `id` | UUID 主键 |
| `session_id` | 会话 ID，已建索引 |
| `message_id` | assistant 消息 ID，唯一键 |
| `member_code` | 账号统一标识，已建索引 |
| `title` | 会话标题 |
| `question` / `answer` | 一问一答正文 |
| `charts_json` | `AiStructuredPresentation` JSON，含图表、指标和结论 |
| `answer_mode` | 快速模式或专家模式 |
| `model_name` | 模型名称 |
| `token_consumed` | 本条记录 Token 数 |
| `chat_time` | 问答时间 |
| `status` | `active` 或 `deleted`，用于软删除 |

索引：`message_id` 唯一索引，以及 `session_id / member_code / chat_time` 普通索引。

## 三、写入规则

`ChatRecordService.saveChatRecord()`：

- 未登录或 `anonymous` 不保存。
- 以 `messageId` 查重，存在则更新，不存在则创建。
- 快速模式、专家模式和 directResponse 分支均会保存。
- 广场 AI 辅助不在每次润色时写聊天表；用户发布时由广场模块汇总写入 `plaza_ai_helpers`。
- 结构化内容以版本化 JSON 保存，当前版本为 `version: 1`。

## 四、历史接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/ai/chat-history` | 当前用户会话摘要，按时间倒序 |
| `GET` | `/api/ai/chat-history/:sessionId/messages` | 当前用户指定会话消息 |
| `PATCH` | `/api/ai/chat-history/:sessionId` | 重命名会话 |
| `DELETE` | `/api/ai/chat-history/:sessionId` | 单会话软删除 |
| `POST` | `/api/ai/chat-history/batch-delete` | 批量软删除会话 |
| `POST` | `/api/ai/chat-history/delete` | 按 messageId 删除，供重问/刷新清理 |
| `POST` | `/api/ai/chat-history/import` | 导入旧 localStorage 历史 |

所有读写都使用服务端鉴权得到的 `MEMBER_CODE` 限定归属，不能接受前端任意指定其他用户。

## 五、服务端同步策略

`ChatSidebar.vue` 挂载后调用 `syncFromServer()`：

1. 拉取会话摘要，不立即下载所有问答正文。
2. 按 `sessionId` 与本地记录查重。
3. 服务端有、本地没有时创建占位会话。
4. 点击占位会话时调用 `syncSessionMessages()` 懒加载完整记录。
5. 从 `charts_json` 恢复图表、指标和结论。

这种摘要 + 懒加载方式避免首次打开页面时下载全部长回答。

## 六、旧数据无感迁移

`AiQaPage.vue` 在页面挂载约 2 秒后执行 `silentMigrate()`：

- 读取 `historyChat_guest`。
- 未登录时跳过且不写完成标记，登录后仍可重试。
- 按 UTF-8 实际字节数动态切批，每批不超过约 30KB。
- 全部批次成功后写入 `historyChat_uploaded=true`。
- 失败、停止或中断的 bot 消息不导入。

## 七、删除、批量管理和重命名

侧边栏支持：

- 单会话删除。
- 批量选择和批量删除。
- 会话重命名。
- 置顶（当前为本地历史属性）。
- 删除当前会话后自动新建空白会话。

服务端删除采用 `status='deleted'` 软删除，并限定 `member_code`；列表和消息查询只返回未删除记录。

## 八、桌面端可调宽度

历史侧边栏右边缘支持左右拖动：

| 项目 | 值 |
|---|---|
| 默认宽度 | 230px |
| 最小宽度 | 200px |
| 最大宽度 | 420px |
| 本地键名 | `ai-qa-history-sidebar-width` |

交互能力：

- 鼠标或 Pointer 左右拖动。
- 拖动时禁用文本选择并显示 `col-resize` 光标。
- 双击恢复默认宽度。
- 键盘左右方向键每次调整 10px，按住 Shift 调整 20px。
- `Home / End` 跳到最小/最大宽度。
- 使用 `role='separator'` 及 ARIA 数值属性支持辅助技术。

该功能仅作用于桌面端；移动端保持抽屉模式和左滑收起。

## 十、兼容与注意事项

- 旧记录的 `charts_json` 可能是图表数组，解析时必须兼容。
- 已保存的旧结论不会因新结论算法自动回写；重新生成的回答才使用新逻辑。
- 服务端同步失败不阻塞本地历史使用。
- 不要移除 localStorage 兼容层，除非已经完成全量迁移和失败回退设计。
- 飞书生产环境的所有前端请求必须继续遵守项目 CSRF 规则，优先使用统一 `aiRequest`。
