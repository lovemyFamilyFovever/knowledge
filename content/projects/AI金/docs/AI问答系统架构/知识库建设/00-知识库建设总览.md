## 一、知识库在 AI金中的位置

AI金不是“只查知识库”的问答系统。现行专家模式由后端轻量路由进入百炼 Agent 2.0，再由应用根据问题选择结构化查询、知识库检索或其他能力。知识库承担的是**稳定、可复用、已经确认的专业知识**，不承担所有数据。

```text
用户问题
  → 意图识别与路由
  → SQL / 百炼知识库 / 资讯 / AI测价等能力
  → 回答生成
  → 输出校验
```

各层职责如下：

| 层级 | 主要职责 | 本项目对应实现或资料 |
|---|---|---|
| 意图识别与路由 | 判断问题属于行情、知识、企业、资讯、测价或复合问题 | `PipelineService`、`ai-query-policy.ts`、百炼应用 System Prompt |
| SQL | 查询价格、库存、进出口量、原料报价等结构化动态数据 | `executeQuerySql` 及项目已接入的数据表 |
| 百炼知识库 | 检索牌号标准、采购规则、计算口径、企业属性、分析方法、术语等稳定知识 | 本目录“正式知识库”中的 11 个文件 |
| 资讯 | 查询新闻、钢厂动态、政策动态等时效内容 | 内部资讯表；符合边界时再使用合规公开信息 |
| AI测价 | 处理未来价格、目标价、买卖时点等专项测算 | AI测价独立链路 |
| 回答生成 | 汇总已取得的有效依据，回答显性问题并处理必要的上下文 | 百炼 Agent 2.0 |
| 输出校验 | 检查数据真实性、口径、路由、内部信息泄露和回答完整性 | 后端清洗、人工复核、标准问题批测 |

## 二、数据源边界

选择数据源时先看“信息是否会快速变化”，再看“是否适合按字段精确查询”。

| 问题类型 | 首选能力 | 处理原则 |
|---|---|---|
| 牌号、标准、成分、采购规则、行业术语、计算口径 | 知识库 | 使用已核验或同事确认的专业口径，不凭模型常识补精确数值 |
| 当前或历史价格、库存、原料报价、进出口数量 | SQL | 按日期、市场、材质、规格、单位等字段查询，不把一次查询结果固化为长期知识 |
| 新闻、钢厂近期动态、市场事件 | 资讯 | 内部资讯优先；时效问题不写入长期知识库 |
| 未来价格、目标成交价、买卖时点 | AI测价 | AI问答不自行生成确定的未来价格 |
| 企业主营、地区、产品、名称别名 | 知识库/企业数据 | 先做名称归一化，再使用企业资料；联系人、库存和报价以有权限的实时数据为准 |
| 进出口政策与规则 | 知识库 + 必要的最新官方核验 | 知识库保存政策口径和编码；询问“当前是否仍有效”时必须核验时效 |
| 产量与产能 | 结构化数据优先，知识库作为现有历史资料 | 必须带时间、状态、单位和统计范围；“预估”不能表述成已发生事实 |

知识库不是动态数据库的替代品。尤其不能把今天的价格、某周库存、当月进出口量、即时运费或一篇新闻长期固化后继续当作“当前数据”回答。

## 五、建设原则

1. **正确优先**：专业口径以同事确认、标准文件、质保书或明确来源为准。
2. **稳定知识入库**：动态价格、库存、数量和新闻进入对应实时链路。
3. **每块可独立理解**：检索到单个段落或单行时，仍能判断对象、条件、单位、时间和例外。
4. **检索词完整**：保留钢厂简称、别名、旧牌号、英文简称和市场叫法。
5. **正式文件唯一**：固定文件名覆盖更新，不产生“最新版”“最终版”“V2”等并列正式文件。
6. **先定位再修复**：回答错误时先区分知识、召回、上下文、路由和生成层，不直接把所有问题归因于 Prompt。
