# AI金知识库整理规范

> 最后更新：2026-08-06  
> 目标：把业务资料整理成可检索、可核验、可维护的 RAG 正式文件

---

## 一、整理结果的验收标准

一段 Markdown 或一行 Excel 被单独召回时，维护人员应能回答以下问题：

1. 说的是哪个对象、牌号、钢厂、产品或政策？
2. 结论或规则是什么？
3. 适用条件、单位、时间和统计范围是什么？
4. 有哪些例外、限制或待确认项？
5. 来源和核验状态是否足以支持回答？

缺少这些关键信息的内容不能直接进入正式知识库。

## 二、知识块写法

### 2.1 一个知识块脱离上下文也能理解

错误写法：

```text
它一般按这个标准执行，上述情况除外。
```

推荐写法：

```text
304 冷轧钢板和钢带的验收应绑定具体产品标准；GB/T 20878-2024 是牌号与化学成分基础标准，不能替代 GB/T 3280-2015 的冷轧板带产品要求。
```

知识块中要重新写出必要的对象名称，不依赖前一段才能成立。少用“上述、它、其、该产品、该企业、前者、后者”等跨块指代。

### 2.2 标题必须包含对象和主题

推荐：

- `### 304L 不锈钢按 GB/T 20878-2024 的化学成分`
- `### 300 系库存去库的判断条件`
- `### 青山集团无锡区域包送与自提规则`

不推荐：

- `### 化学成分`
- `### 原因`
- `### 其他情况`

标题不仅用于阅读，也是重要检索词。对象、主题和必要的版本应尽量出现在标题中。

### 2.3 关联条件不要拆散

以下内容通常应保留在同一知识块或同一 Excel 行：

- 参数及其适用范围、单位、时间；
- 主结论及例外情况；
- 牌号、产品形态、执行标准和交货状态；
- 钢厂名称、发货地、包送区域、运费规则和最低发货量；
- 政策的贸易方向、国家、产品、企业主体、生效日期和资料更新时间；
- 产量/产能的月份或年份、数据状态、统计范围、单位和来源。

强相关内容被切成两个独立块后，模型可能只召回结论而漏掉限制，导致回答虽然“有来源”但仍然错误。

## 三、检索词与实体处理

### 3.1 保留真实业务检索词

不得为了语言整齐删除以下内容：

- 钢厂简称和别名：东特、张浦、北港新材等；
- 一对多简称：例如“太钢”必须保留歧义说明；
- 牌号旧称和市场叫法：0Cr18Ni9、J1/J2/J3/J4/J5 等；
- 中英文简称：NPI、MHP、RKEF、HPAL、AOD、SS、LME；
- 标准企业名称、历史/关联名称和英文主体名。

正式名称用于回答和归一化，简称、旧称和别名用于召回。两者不能相互替代。

### 3.2 不自行制造映射

名称映射只能来自业务资料、已确认关系或正式来源。遇到相同简称对应多个主体时保留多行并标记歧义，不用 AI 常识强行选一个。

## 四、清洗规则

### 4.1 应删除或修复的内容

- 重复段落、重复行和无差异的重复表头；
- PDF/Word 转换产生的页眉、页脚、页码和目录噪声；
- 空列、纯展示列、无业务含义的序号和无效字段；
- 乱码、断行造成的词语拆分、不可见控制字符；
- 与当前文件分类无关的动态数据或其他主题内容；
- 同一知识在多个正式文件中无必要的重复副本。

删除前先确认其不承担来源、单位、状态或检索词作用。不能因“看起来冗余”删除别名、时间、例外和核验备注。

### 4.2 不允许的“优化”

- 不凭 AI 常识修改公司同事确认的专业口径；
- 不把“待确认”“预估”“近似对应”改成确定事实；
- 不把万吨擅自改写为万吨/年；
- 不给原始资料补造适用范围、税率、系数、标准编号或更新时间；
- 不用外部搜索结果静默覆盖内部口径。

发现疑点时保留原始事实，在“待确认”、数据质量备注或维护记录中说明，由业务负责人决定是否修订。

## 五、Markdown 整理规则

1. 一个文件只保留一个一级标题，标题与正式文件主题一致。
2. 二级标题划分业务主题，三级标题写明具体对象和问题。
3. 段落先给结论，再给适用条件、例外、示例和来源。
4. 同一主题下的短表格与解释放在一起，不把表格说明放到远处。
5. 公式使用代码格式，紧接着解释每个变量、单位、适用范围和待确认状态。
6. 对政策、标准等会变化的内容写明版本、生效日期、资料更新时间和核验边界。
7. 章节过长时按用户问题拆分，但不得把参数和限制分开。

正式 Markdown 的标题层级是百炼分段的重要语义线索；具体上传分段方式见 [03-知识库上传百炼指南](./03-知识库上传百炼指南.md)。

## 六、Excel 整理规则

### 6.1 一行是一条可独立检索的事实

当前正式 Excel 已采用以下模式：

- 企业库：一行一家企业；
- 映射词典：一行一个“检索词 → 标准企业名称”关系；
- 物流规则：一行一家钢厂的完整物流规则；
- 产量产能：一行一个“时间 × 钢厂 × 产品 × 系别”的事实或一个产能项目。

禁止把多个实体塞进一个单元格后依赖视觉排版理解，也不要用颜色代替“数据状态”“优先级”等真实字段。

### 6.2 字段要求

按资料类型保留必要字段：

- 实体：正式名称、简称/别名、地区、类别；
- 数值：数值、单位、时间、数据状态、统计口径；
- 规则：适用对象、规则内容、限制、更新时间；
- 来源：来源文件/工作表或核验状态；
- 质量：冲突、歧义、待确认项、清洗备注。

首行必须是清晰、唯一的字段名。日期和数字保持可识别类型；企业代码、HS 编码等可能含前导零的标识符按文本处理。

### 6.3 工作表处理

- 多工作表承担不同语义时保留，例如“文档说明”“待确认”和数据明细。
- 上传前确认百炼能够解析所有需要的工作表，不能只看到第一个工作表就判定成功。
- 大表重点检查表头是否被正确识别、行是否完整、长备注是否被截断。
- 公式结果不是稳定知识源；如原文件依赖公式，应先确认平台读取的是公式还是显示值。本次四个正式 Excel 均未发现公式。

## 七、Markdown / Excel / CSV 的选择

| 判断问题 | 建议格式 |
|---|---|
| 是否需要连续解释、标题层级、条件和例外？ | Markdown |
| 是否是一行一实体/映射/时间事实，字段高度统一？ | Excel |
| 是否为单表、无多工作表说明、无复杂格式，且转换不丢信息？ | 可评估 CSV |

格式转换不是整理目标。当前正式文件没有 CSV；只有在实际召回测试证明 CSV 更合适时，才可在原固定分类内变更格式，并同步更新上传配置和回归测试。

## 八、稳定知识与动态数据分流

| 内容 | 去向 |
|---|---|
| 牌号标准、采购规则、分析方法、术语、企业静态属性 | 知识库 |
| 当前/历史价格、当前库存、进出口数量、原料报价 | SQL |
| 新闻和近期企业动态 | 资讯 |
| 未来价格和目标成交价 | AI测价 |
| 规则解释 + 当前市场表现的复合问题 | 知识库说明规则，SQL/资讯提供当下数据 |

产量与产能正式文件是当前已有的结构化历史资料。使用时必须带时间、状态和统计范围；若后续接入权威产量 SQL 表，当前数据应以 SQL 为准，知识库继续保留口径、历史和来源说明。

## 九、整理完成检查表

- [ ] 文件归入现有 11 个分类之一，未擅自新增分类。
- [ ] 单个知识块或单行脱离上下文仍能理解。
- [ ] 标题包含对象和主题。
- [ ] 简称、别名、旧称、英文简称等检索词被保留。
- [ ] 参数、单位、适用范围和例外没有拆散。
- [ ] 重复、页眉页脚、空列和无效字段已清理。
- [ ] 动态价格、库存、数量和新闻未混入长期知识。
- [ ] 待确认和预估状态没有被改成确定事实。
- [ ] 同事确认的专业口径没有被 AI 常识改写。
- [ ] 正式文件名保持不变。
- [ ] 已按 [05-知识库测试与效果验证](./05-知识库测试与效果验证.md) 准备测试问题。
