# AI金知识库更新维护流程

> 最后更新：2026-08-06  
> 标准流程：识别分类 → 清洗 → 合并已有知识库 → 上传 → 测试

---

## 一、正式文件管理规则

1. 正式分类和文件名以 [01-知识库分类与目录说明](./01-知识库分类与目录说明.md) 列出的 11 个文件为准。
2. 更新时修改对应固定文件，不在正式目录并列保存“最新版、最终版、V2、修订版、带日期版”。
3. 原始资料、清洗中间表、对比文件、上传截图、测试结果放在正式目录之外。
4. 版本历史依靠 SVN/团队发布记录或可追溯备份管理，不靠并列文件名管理。
5. 本次口径下，`D:\工作\AI问答\AI金知识库\待上传` 是业务正式来源，本项目 `正式知识库/` 是部署和交接快照。后续必须指定唯一主维护源，不能两边同时独立编辑。

## 二、收到新资料后的完整流程

### 第一步：识别分类和数据源

先回答两个问题：

1. 资料是否属于现有 11 个正式分类？
2. 资料是稳定专业知识，还是价格、库存、数量、新闻等动态信息？

| 新资料内容 | 处理去向 |
|---|---|
| 牌号、标准、计算、采购、分析方法、术语、企业静态属性 | 合并到对应知识库 |
| 当前/历史价格、实时库存、原料报价、进出口数量 | SQL 数据链路 |
| 新闻、钢厂近期动态、政策即时变化 | 资讯；稳定规则经核验后再进入知识库 |
| 未来价格、目标价、买卖时点 | AI测价 |
| 无法归入现有 11 类 | 暂不新建正式分类，提交负责人确认 |

### 第二步：登记来源和权限

记录资料名称、提供人、收到日期、适用范围、是否已由业务同事确认、可否对外使用、是否替代旧资料。缺少授权或专业确认的资料不能直接成为正式知识。

### 第三步：清洗和结构化

按 [02-知识库整理规范](./02-知识库整理规范.md) 执行：

- 删除重复、页眉页脚、无效字段和转换噪声；
- 保留钢厂简称、别名、牌号旧称和英文简称；
- 补齐知识块自身需要的对象、条件、单位、时间和来源；
- 把强相关的参数、适用范围和例外保留在一起；
- 标记“待确认”“预估”“近似对应”等状态；
- 不凭 AI 常识修正同事确认的业务口径。

### 第四步：与现有正式文件合并

更新现有固定文件，而不是新建并列文件：

- Markdown：定位到对应主题，去重后补充或替换完整章节；同步更新标题、适用范围和来源。
- Excel：按业务主键判断新增或更新。企业以标准企业名称为核心，名称映射以“检索词 + 标准名称”为核心，产量产能以时间/钢厂/产品/系别等组合为核心，物流以钢厂主体为核心。
- 有冲突时：保留已确认口径；不能确认的内容进入“待确认”或数据质量备注，不静默覆盖。

### 第五步：本地复核

- 核对文件名、格式、工作表、行数和必要字段；
- 检查是否误混入临时文件、缓存、测试结果或动态数据；
- 抽查新增知识块能否脱离上下文理解；
- 检查旧知识是否被意外删除；
- 生成或记录文件校验信息，确认同步副本与主文件一致。

### 第六步：上传百炼

按 [03-知识库上传百炼指南](./03-知识库上传百炼指南.md) 替换固定文件，等待解析和索引完成，确认目标知识库仍挂载到 AI金当前应用。

### 第七步：测试和发布

按 [05-知识库测试与效果验证](./05-知识库测试与效果验证.md) 依次完成：

```text
单知识测试 → 标准问题批测 → 召回检查 → 最终回答检查 → 修复 → 回归测试
```

测试通过后才算更新完成；“文件已上传”不是完成标准。

## 三、问题归属与修复入口

| 现象或需求 | 责任层 | 优先动作 |
|---|---|---|
| 专业知识缺失或口径错误 | 知识库 | 补充/修订对应固定文件并重新索引 |
| 当前价格、库存、原料、进出口数量错误 | SQL/数据 | 检查数据表、日期、字段、单位和查询条件 |
| 新闻不新或企业近期动态缺失 | 资讯 | 检查内部资讯和合规实时来源，不把新闻长期写入知识库 |
| 未来价格或目标价进入普通问答 | 路由/产品边界 | 路由到 AI测价 |
| 知识库检索正确但最终回答错误 | Prompt/生成逻辑 | 保留正确知识，检查生成约束和回答组合 |
| SQL 问题误走知识库，或知识问题误走 SQL | 路由 | 检查 query-policy、百炼工具选择和 System Prompt |
| 召回片段缺少限制条件 | 资料结构/切分 | 合并强相关知识块，调整标题或平台分段 |

不要一看到回答错误就直接修改 Prompt。先确定知识是否存在、是否被解析、是否被召回、路由是否正确，最后才判断生成层。

## 四、不同角色的检查重点

| 角色 | 主要职责 |
|---|---|
| 知识库维护人员 | 分类、去重、结构化、固定文件更新、上传记录、单知识测试 |
| 数据分析人员 | 动态数据口径、单位、时间范围、SQL 结果和统计口径核验 |
| 开发人员 | 路由、工具调用、百炼应用配置、批测接口、输出清洗和日志定位 |
| 业务/专业负责人 | 专业口径、冲突项、待确认项和对外表达边界的最终确认 |

## 五、回滚与异常处理

### 5.1 何时回滚

- 新文件解析失败或只索引部分工作表；
- 核心旧问题大面积不再召回；
- 新旧知识冲突且无法立即定位；
- 正式文件误混入未确认或敏感信息；
- 路由或最终回答出现明显高风险错误。

### 5.2 如何回滚

1. 在百炼应用中停止使用有问题的新索引/文件。
2. 从版本管理或发布备份恢复上一份固定文件。
3. 保持正式文件名不变，重新上传并确认索引完成。
4. 复测导致回滚的问题和相关标准问题。
5. 在维护记录中写明原因、影响范围和后续修复项。

回滚副本不留在 `正式知识库/` 作为第二份正式文件。

## 六、现有待确认事项的维护要求

`产量与产能知识库.xlsx` 已记录 6 项待确认问题，包括广青/青山产能口径、国内炼钢总产能两套汇总、江苏德龙与溧阳主体关系、鑫海名称关系、冷轧项目年度小计标签和更新时间不一致。维护时应：

- 优先由产量/产能数据负责人确认；
- 未确认前保留原文件的处理方式和状态；
- 不因模型回答需要而临时选一套数字；
- 确认后同步更新数据行、“待确认”工作表、上传文件和回归用例。
