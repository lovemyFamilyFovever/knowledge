# AI金知识库测试与效果验证

> 最后更新：2026-08-06  
> 测试目标：同时验证“知识存在、能够召回、路由正确、最终回答正确”

---

## 一、测试总流程

```text
知识库更新
  → 上传百炼
  → 单知识测试
  → 标准问题批测
  → 检查召回
  → 检查最终回答
  → 定位问题
  → 修复
  → 回归测试
```

每一层的证据不同：正式文件证明“知识存在”，百炼调试区证明“索引和召回正常”，AI金 expert 链路证明“路由和生成正常”，标准问题批测证明“改动没有破坏其他场景”。

### 2.2 ERP 批量测试

AI金现有 ERP 页面：`/erp/ai-qa-optimization`，测试对象为当前 AI金调用的百炼 expert 链路。

后端接口：

```text
POST /api/internal/ai-test/run
```

当前实现约束：

- 仅支持 `expert` 模式；
- 单批最多 100 条；
- 并发数范围 1—10；
- 测试题至少包含 `question`，可带 `id`、`business_category` 等字段；
- 可选 AI 自动初评，结果仍需人工复核；
- 页面可导出 JSON 和 Excel，当前结果会保存到本地批次历史。

在 ERP 的“JSON 测试题”输入框中使用 100 题 JSON 数组文件。若直接调用后端接口，则按接口请求体包装 `batch`、`mode`、`concurrency`、`autoReview` 和 `cases`。

## 三、测试分层

### 3.1 文件层检查

上传前确认：

- 文件名、格式和工作表完整；
- 新增知识在正式文件中真实存在；
- 时间、单位、状态、范围和例外齐全；
- 没有并列旧版本、临时文件和缓存；
- Excel 大表行数和表头符合预期。

### 3.2 单知识库召回测试

在百炼控制台对目标知识库直接检索，查看实际召回片段。每个改动至少准备：标准问法、简称问法、条件变化问法、反例和边界问法。

本次 11 个正式文件的代表性检查点：

| 文件 | 代表性测试 | 应检查的召回要点 |
|---|---|---|
| 不锈钢标准与牌号 | “J2 是不是国标 201？” | 国标 201 与 J 系列边界、不能自动等同 |
| 板/卷计算与价格折算 | “管材理论重量公式是什么？” | 当前资料未提供管材公式，不得补造 |
| 采购常识 | “3 吨 304 拆卷开平应该找钢厂还是贸易商？” | 吨位、现货/期货、加工和交期条件 |
| 企业信息 | “佛山有哪些做 430 的企业？” | 地区、产品/材质、企业字段；不得出现文件中没有的电话 |
| 名称映射 | “太钢指哪家公司？” | 一对多歧义和上下文消歧 |
| 库存分析 | “库存下降是否说明需求变好了？” | 需求、提货、物权转移等替代解释 |
| 产量与产能 | “2026 年 8 月某钢厂产量是多少？” | 月份、钢厂、产品/系别、万吨、预估状态 |
| 进出口政策与规则 | “初裁和终裁能否当成同一税率？” | 政策阶段、主体、产品和时效边界 |
| 废钢废料 | “精铸料和统料有什么区别？” | 分类特征完整，不带实时回收价 |
| 基础行业术语 | “RKEF 和 HPAL 有什么区别？” | 两个术语的准确对象和工艺定义 |
| 钢厂物流与包送 | “酒钢原厂直发是否包送？” | 发货地、含运口径、超范围询价、更新时间 |

### 3.3 路由测试

使用同主题、不同意图的问题验证路由：

| 问题 | 期望能力 |
|---|---|
| “304 和 304L 有什么区别？” | 知识库 |
| “今天无锡 304 冷轧多少钱？” | SQL |
| “上周无锡 300 系库存变化？” | SQL 提供数据，知识库提供分析方法 |
| “最近某钢厂有什么新闻？” | 内部资讯 |
| “下周 304 目标成交价是多少？” | AI测价 |
| “某出口政策目前是否仍有效？” | 知识库解释规则，必要时核验最新官方信息 |

若预期路由不是知识库，不应为了“提高知识库命中率”修改问题或把动态数据塞入知识库。

### 3.4 最终回答测试

召回正确后继续检查：

- 是否直接回答用户核心问题；
- 是否正确使用了时间、单位、市场、材质、产品和统计范围；
- 是否保留“预估、待确认、近似对应、需单独询价”等限制；
- 是否将不同来源的冲突数据强行合并；
- 是否编造知识库中没有的联系人、价格、运费或公式；
- 是否泄露 SQL、表名、知识库名称、检索词和内部路由；
- 复合问题是否分别使用正确能力，而非只查一个库硬答。

## 四、问题分类与定位方法

| 问题类型 | 识别证据 | 修复位置 |
|---|---|---|
| 知识缺失 | 正式文件中没有答案或必要条件 | 补充对应正式文件，经业务确认后重传 |
| 有知识但未召回 | 文件中存在，索引完成，但目标查询没有命中 | 改标题、补检索词、重组自包含知识块，检查索引和挂载 |
| 召回错误 | 命中了其他牌号、钢厂、国家、年份或相似主题 | 强化对象/主题标题、别名消歧、字段和过滤条件 |
| 上下文不完整 | 只召回数值或结论，缺单位、范围、例外、状态 | 合并强相关段落或 Excel 字段，调整分段 |
| 召回正确但回答错误 | 召回片段足以回答，但模型误读、漏限制或错误组合 | 检查 System Prompt、生成逻辑和回答模板，不改正确知识 |
| SQL/知识库路由错误 | 动态问题走知识库，或专业知识问题只查 SQL | 检查 query-policy、百炼工具选择和当前生效 Prompt |
| 时效信息错误走长期知识库 | 回答使用过期价格、库存、新闻、运费或政策状态 | 删除/隔离不应固化的动态内容，改走 SQL/资讯/最新核验 |

定位顺序固定为：

```text
正式文件是否有知识
  → 文件是否解析和挂载
  → 查询是否召回正确片段
  → 路由是否选择正确能力
  → 最终回答是否正确使用依据
```

只有最后一步出错时，才优先修改 Prompt 或生成逻辑。

## 五、标准问题批测执行

1. 记录更新前的基线批次和已知问题。
2. 上传并完成单知识库测试。
3. 在 ERP 配置页粘贴 100 题 JSON 数组，填写可追溯批次名。
4. 使用 expert 模式执行；并发按环境承载能力设置，不超过系统上限。
5. 如开启 AI 自动初评，仍逐项人工复核高风险、低置信和不准确结果。
6. 按一级分类查看准确性、编造、错误类型和耗时。
7. 对知识库相关题检查召回，对 SQL/资讯/测价题检查路由。
8. 将问题归入第四节的诊断类型，分别修复。
9. 使用相同题集和相同链路回归，确认目标问题修复且其他分类未退化。

标准问题库中的 Q011“理计、过磅、基价或米价折算”、材质/标准类、企业/供应商类、采购物流类等可作为知识库重点回归；价格和趋势题同时承担 SQL 与路由回归，不应全部按知识库准确率统计。

## 六、通过标准

项目现有资料没有定义统一的知识库召回分数、Top-K、分段长度或批测准确率阈值，因此不在本文件编造数值。每次发布至少满足：

- 目标新增/修订知识能稳定召回；
- 关键限制、状态、单位和时间随答案保留；
- 不应命中的动态或越界问题没有被长期知识硬答；
- 100 题批测完成，并对知识库、SQL、资讯、AI测价路由分别复核；
- 高风险编造和已知回归问题已处理或明确阻断发布；
- 测试批次、召回证据、最终回答和未解决项可追溯。

## 七、测试记录建议字段

| 字段 | 说明 |
|---|---|
| 批次/日期 | 对应知识库更新和百炼应用版本 |
| 文件名/知识库 | 本次变更对象 |
| 问题/分类 | 单知识问题或标准题号 |
| 期望路由/实际路由 | 知识库、SQL、资讯、AI测价等 |
| 召回片段 | 百炼调试区观察到的关键依据 |
| 最终回答 | AI金 expert 输出 |
| 问题类型 | 知识缺失、未召回、错误召回等 |
| 修复动作 | 文件、索引、路由或生成层变更 |
| 回归结果 | 通过、失败、待业务确认 |

测试结果文件不放入 `正式知识库/`，避免被百炼误上传为业务知识。
