# AI金知识库上传百炼指南

> 最后更新：2026-08-06  
> 适用应用：AI金专家模式所调用的百炼 Agent 2.0 应用

---

## 一、上传前确认

项目代码在专家模式下调用百炼应用，知识库挂载和 `knowledgeBaseSearch` 工具由百炼应用侧管理；后端没有逐文件读取本目录。上传前必须确认：

1. 使用的是 AI金当前线上/测试负责人指定的百炼应用，不凭本地文件名猜测应用版本。
2. 已确认当前生效的 System Prompt。项目索引文档仍把 v11 标为权威，而目录中另有包含细分知识库路由的 `bailian-app-system-prompt-v13.md`，两者未统一前不要擅自替换线上 Prompt。
3. 待上传文件来自本目录 [正式知识库](./正式知识库/)，文件名和格式未被改写。
4. 同一知识库中不存在“最新版、最终版、V2”等并列正式文件。
5. 本次变更、负责人、来源和待验证问题已有记录。

百炼控制台界面名称可能随平台版本变化，以下按操作目标描述，不依赖某个固定按钮文案。

## 二、上传流程

### 2.1 选择知识库

1. 登录阿里云百炼控制台。
2. 进入知识库管理区域。
3. 选择与正式文件对应的现有知识库；如平台尚未建立对应库，先由应用负责人确认名称和挂载方案，不自行创建新分类。
4. 核对旧正式文件、更新时间和应用挂载关系。

### 2.2 上传或替换文件

1. 从 `正式知识库/` 选择固定文件名的文件。
2. 上传后等待解析、切分、向量化/索引流程完成。
3. 检查文件状态，不以“上传请求成功”代替“解析和索引成功”。
4. 替换更新时确认旧版本已停止参与检索，避免同一知识产生重复或冲突召回。
5. 在百炼应用中确认目标知识库已挂载，并允许 Agent 的知识库检索工具使用。

### 2.3 应用联调

1. 在百炼应用调试区先做单知识库检索测试。
2. 再通过 AI金 expert 链路测试路由和最终回答。
3. 记录本次文件、测试问题、召回片段、最终回答和结论。
4. 全部通过后再进入标准问题批测。

## 三、Markdown 处理

### 3.1 标题层级

- 一级标题：文件主题，只保留一个。
- 二级标题：业务大类，例如“库存数据口径与基础字段”。
- 三级标题：具体对象和问题，例如“304L 不锈钢按 GB/T 20878-2024 的化学成分”。
- 四级标题：仅用于确有必要的子例或来源说明，不用空泛标题占层级。

平台若提供按标题分段的选项，应优先让标题成为切分边界；若平台只提供自动分段，也要在上传前确保每个标题下的正文自包含。

### 3.2 分段原则

- 同一段只解决一个明确问题。
- 对象、规则、适用条件、例外和来源尽量处于同一段。
- 不在公式与变量说明之间切分。
- 不在政策主体、税率/措施、时间和适用产品之间切分。
- 不在物流规则的钢厂、库点、区域、运补和最低发货量之间切分。
- 内容过长时按用户问题拆分，不按固定字数机械截断。

项目没有保存一套已确认的统一分段长度、重叠长度或召回条数参数，本指南不编造数值。参数应以百炼当前配置和实测结果为准，并在维护记录中留档。

### 3.3 表格与代码

- Markdown 表格前写明表格对象和口径，表后补充使用限制。
- 公式用代码格式，并紧跟变量、单位和例外说明。
- 避免把大段内容放入代码块，防止平台按不可检索文本处理。

## 四、Excel 处理

### 4.1 通用要求

- 首行是字段名，字段名不能空白或重复。
- 一行是一条可独立理解的事实。
- 时间、单位、状态、来源、备注等不能仅靠颜色或批注表达。
- 不使用合并单元格组织数据区，不保留纯展示空行和重复表头。
- 上传后必须检查每个工作表是否被解析。

### 4.2 本次四个 Excel 的检查重点

| 文件 | 上传后重点检查 |
|---|---|
| 不锈钢企业信息库（完整版）.xlsx | 是否识别“企业信息”工作表及 9 个字段；企业简称、地区、主营、产品、材质是否能组合召回；不得声称文件含联系人电话 |
| 钢厂名称／简称映射词典.xlsx | “名称映射”和“说明”两个工作表是否可检索；“太钢”一对多歧义是否被保留 |
| 不锈钢钢厂物流与包送规则知识库.xlsx | 一次召回是否带出同一钢厂的发货地、包送区域、运补、限制和更新时间；不得只召回一个运费数字 |
| 产量与产能知识库.xlsx | 六个业务工作表及“文档说明/待确认”是否可检索；大表表头是否正确；“历史统计/预估”、单位和统计范围是否随数值一同召回 |

“产量与产能知识库.xlsx”的月度产量明细行数较大，上传成功后要对早期月份、最新月份、不同钢厂、不同产品/系别和预估状态分别抽查，防止只索引了局部数据。

## 五、CSV 处理

当前正式知识库没有 CSV，不需要为统一格式把 Excel 强制转成 CSV。

以后只有在以下条件同时满足时才评估 CSV：

- 资料是单一数据表，不依赖多个工作表说明；
- 中文编码、日期、前导零、长文本和分隔符不会丢失；
- 一行仍是完整事实；
- 与 Excel 对比测试后，百炼解析或召回效果更好。

若改变正式文件格式，仍使用原分类的固定基础文件名，并同步更新本目录说明、百炼挂载和回归基线。

## 六、上传后检索测试

### 6.1 单知识库测试

在百炼控制台直接对目标知识库提问，检查返回的片段，而不只看模型答案。每个文件至少覆盖：

- 标准问法；
- 简称/别名问法；
- 带限制条件的问法；
- 不应命中的反例；
- 文件内已标记待确认或预估的边界问题。

例如：

- “J2 是不是国标 201？”应召回 J 系列边界，不应把 J2 自动等同为国标 201。
- “太钢指哪家企业？”应暴露一对多歧义，不应只给唯一主体。
- “2026 年 8 月某钢厂产量是多少？”若命中，应同时看到“预估”状态。
- “不锈钢管重量怎么计算？”当前计算文件应表明未提供管材公式，而不是补造公式。

### 6.2 AI金链路测试

单库通过后，通过 AI金 expert 链路复测。注意现行后端会对部分问题强制路由：

- 行业新闻优先走内部资讯，不走知识库；
- 市场价格、库存等问题优先走内部结构化数据；
- 一般知识问题由百炼应用决定是否调用知识库；
- 未来价格问题应进入 AI测价边界。

因此“知识库没被调用”不一定是上传失败，也可能是路由正确地选择了 SQL、资讯或 AI测价。定位方法见 [05-知识库测试与效果验证](./05-知识库测试与效果验证.md)。

## 七、常见问题

| 现象 | 优先检查 |
|---|---|
| 文件已上传，但完全搜不到 | 解析/索引是否完成、是否挂载到当前应用、应用是否有知识库工具权限 |
| 能搜到相邻内容，搜不到目标内容 | 标题是否包含对象和主题；别名、旧称是否保留；知识块是否过度依赖上文 |
| 召回了结论，没召回限制 | 参数、适用范围、例外被拆分；Excel 同一事实被拆成多行或多表 |
| 同一问题召回多个冲突版本 | 旧文件未移除、存在“V2/最新版”等并列正式文件 |
| Excel 只有部分内容可检索 | 工作表未全部解析、表头识别错误、大表索引不完整 |
| “太钢”等简称答错主体 | 映射词典的一对多关系未命中，或回答生成忽略歧义 |
| 产量数字正确但状态错误 | “预估/历史统计”、月份、单位或口径没有随数值共同召回 |
| 物流回答给出永久精确运费 | 忽略更新时间和“需单独询价”限制，把历史规则当实时承诺 |
| 知识库检索正确但答案仍错 | 进入生成层或 Prompt 诊断，不要继续改知识文件 |

## 八、上传完成记录

至少记录以下内容：

- 上传日期和操作人；
- 百炼应用/知识库名称；
- 正式文件名及校验信息；
- 替换的旧文件；
- 解析/索引状态；
- 单知识库测试问题和召回结果；
- 标准问题批次及回归结论；
- 未解决的待确认项。

记录可放在团队维护单、发布单或版本管理记录中，不在 `正式知识库/` 旁边生成新的并列正式文件。
