# 数据治理、能力核验与内容安全

> 当前实现快照：2026-08-21

## 一、治理目标

当前 AI 问答不是把所有用户问题直接交给百炼。`PipelineService` 先调用 `AiGovernanceService.inspectQuery()`，根据用户权限、问题内容和内部能力登记结果决定是否继续、限制数据范围或直接返回。

治理链路：

```text
用户问题
  → 用户 INTERNAL / EXTERNAL 数据范围
  → 敏感问题拦截
  → 数据能力核验识别
  → query-policy 业务路由
  → 工具 observation 过滤
  → 正文流式过滤与完整文本复核
  → 引用来源过滤
```

## 二、数据访问范围

`AiGovernanceService` 根据登录用户的 VIP feature 判定：

| 范围 | 行为 |
|---|---|
| `INTERNAL` | 可以在后续业务规则允许的范围内访问内部数据 |
| `EXTERNAL` | 禁止检索或输出配置中的内部敏感资源 |

未登录用户、`anonymous` 或权限读取失败一律按 `EXTERNAL` 处理。权限读取失败采用收紧策略，不扩大数据范围。

治理前缀会注入最终 Prompt，但后端输出过滤仍然必须执行，不能只依赖模型遵守提示词。

## 三、数据能力核验

用户问“AI金有没有某项数据”“系统里能不能查某指标”时，`DataCapabilityRegistry` 会匹配 `config/data-capabilities.ts` 中登记的能力。

标准状态：

| 状态 | 含义 |
|---|---|
| `FOUND` | 已实际查询内部来源并找到有效记录 |
| `NOT_FOUND` | 能力存在，但本次条件未查到记录 |
| `NOT_SUPPORTED` | 能力没有登记或明确不支持 |
| `PERMISSION_DENIED` | 系统存在该能力，但当前用户无访问权限 |

能力核验的关键约束：

- 禁止联网搜索。
- 禁止使用模型记忆或外部估算替代内部记录。
- `FOUND` 必须有有效 tool observation，不能由模型自行宣称。
- 空数组、空对象、0 rows、查询失败或权限不足均不能判为 `FOUND`。
- 能力检查回答只返回状态和能力名称，不透传模型补充的外部数字。

## 四、业务路由

治理通过后，`ai-query-policy.ts` 继续执行轻量业务路由：

| route | 行为 |
|---|---|
| `data-capability-check` | 强制内部能力核验 |
| `internal-industry-news` | 仅查询内部资讯表，禁用联网和其他来源 |
| `external-official-public-info` | 当前直接返回“暂未检索到可核实的公开信息” |
| `internal-market-data` | 内部市场数据与价格图表规则 |
| `general` | 通用知识和其他问题 |

该路由只做边界约束和图表意图，不替代模型做完整实体理解。

## 五、受限第三方来源

受限实体及别名由 `config/ai-governance.config.ts` 配置，环境变量可追加。规则区分：

- 用户未主动询问：禁止主动提及、推荐或引用受限第三方平台。
- 用户主动询问：可以介绍企业本身，但不能把其报价、报告、指数或渠道作为 AI金回答依据。

过滤同时覆盖：

- 工具 observation。
- 流式正文完整句段。
- 最终完整正文。
- references 来源。

## 六、流式输出治理

`AiGovernedStreamFilter` 缓存尚未形成完整句子的 delta，只对完整句段执行过滤，避免敏感实体被拆成多个 chunk 后绕过检测。

最终 `filterCompleteText()` 会对模型完整回答再检查一次。如果流式内容与最终安全文本不同，服务端发送 `content` 快照让前端校正。

## 七、展示层清洗

治理过滤解决“能不能展示”，`shared/ai-display-sanitizer.ts` 解决“正式界面应该展示什么”。当前会移除：

- SQL、schema、内部表名。
- `executeQuerySql` 等工具名和参数。
- 调试信息和内部路由细节。
- “我需要查询、让我选取数据、正在整理趋势”等模型过程性独白。

原版思考模式同样经过 `AiGovernanceService` 的流式过滤，不允许绕过权限和来源约束。

## 八、失败策略

| 场景 | 策略 |
|---|---|
| 权限服务异常 | 按 `EXTERNAL` 处理 |
| observation 命中受限来源 | 丢弃并记录 warning |
| 最终正文被全部过滤 | 返回安全兜底文案 |
| 图表 canonical 校验失败 | 不发送图表和价格指标，正文仍可完成 |
| 外部官方来源不可核实 | 不生成猜测性回答 |

## 九、配置与关键文件

| 文件 | 作用 |
|---|---|
| `pipeline.service.ts` | 治理优先、再进入 query-policy |
| `ai-governance.service.ts` | 权限、敏感内容、受限实体、流式和最终过滤 |
| `data-capability-registry.ts` | 能力问题识别和状态解析 |
| `config/data-capabilities.ts` | 内部能力登记表 |
| `config/ai-governance.config.ts` | 权限 feature、敏感规则、受限实体 |
| `search-source-policy.ts` | 联网来源 URL 白名单 |
| `shared/ai-display-sanitizer.ts` | 正式展示内容清洗 |

## 十、测试要求

修改治理逻辑时至少执行：

```bash
npx jest server/modules/ai/ai-governance.service.spec.ts --runInBand
npm run type:check
```

若改动涉及结构化内容，还需执行 `ai-data-insight-builder.spec.ts`、`price-chart-regression.spec.ts` 和 `structured-insight-sse.spec.ts`。
