# AI 问答数据保存方案（PostgreSQL 现行版）

> 最后更新：2026-08-21  
> 状态：已实施  
> 历史说明：早期 Bitable 方案已废弃，当前实现以 PostgreSQL + Drizzle 为准。

## 一、目标

- 登录用户跨设备查看 AI 问答历史。
- 保存正文、图表、关键指标和 AI 结论。
- 支持会话摘要同步、消息懒加载、重命名、单删、批量删除和重问清理。
- 兼容浏览器 `historyChat_guest` 旧数据并无感迁移。
- 所有服务端读写按 `MEMBER_CODE` 隔离用户。

## 二、总体架构

```text
POST /api/ai/chat
  → SSE 正文和结构化内容
  → ChatRecordService.saveChatRecord()
  → AiRepository
  → PostgreSQL ai_chat_records

AI 问答页加载
  → 本地 localStorage 立即恢复
  → GET /api/ai/chat-history 拉取会话摘要
  → 点击会话后 GET /messages 拉取完整记录
```

## 三、数据库表

权威 Schema：`server/database/schema.ts` 的 `aiChatRecords`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键，默认随机 UUID |
| `session_id` | varchar(255) | 会话 ID，索引 |
| `message_id` | varchar(255) | assistant 消息 ID，唯一索引 |
| `member_code` | varchar(100) | 用户统一账号，索引 |
| `title` | varchar(255) | 会话标题 |
| `question` | text | 用户问题 |
| `answer` | text | 清洗后的正式回答 |
| `charts_json` | text | 版本化结构化展示 JSON |
| `answer_mode` | varchar(50) | 快速模式 / 专家模式 |
| `model_name` | varchar(100) | 模型名称 |
| `token_consumed` | numeric | 本条记录 Token 数 |
| `chat_time` | timestamptz | 问答时间 |
| `status` | varchar(20) | `active` / `deleted` |
| `created_at / updated_at` | timestamptz | 审计时间 |

## 四、结构化内容存储

`chat-record.service.ts` 将结构化内容序列化为：

```typescript
interface AiStructuredPresentation {
  version: 1;
  charts?: AiStructuredChart[];
  metrics?: AiMetricCardGroup;
  conclusion?: AiConclusionCard;
}
```

序列化结果写入 `charts_json`。字段名为兼容历史保留，实际已经不仅包含 chart。

无图表、指标和结论时写空字符串。读取历史时兼容旧版直接保存 `AiStructuredChart[]` 的格式。

## 五、写入流程

`ChatRecordService.saveChatRecord()` 接收会话/消息 ID、`memberCode`、标题、模式、模型、问题、回答、结构化内容和 totalTokens。

规则：

1. `memberCode` 为空或 `anonymous` 时跳过。
2. 以 `messageId` 查询现有记录。
3. 存在则更新，不存在则创建。
4. 专家模式保存治理、图表移除和展示清洗后的 `answerToDisplay`。
5. 保存失败仅记录 warning，不阻塞已完成的 SSE 响应。

快速模式、专家 directResponse 和专家常规流程均会写记录。广场 AI 发布辅助走独立的 `plaza_ai_helpers`，不在每次润色时写聊天记录。

## 六、历史接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/ai/chat-history/import` | 导入旧 localStorage 历史 |
| `GET` | `/api/ai/chat-history` | 会话摘要列表 |
| `GET` | `/api/ai/chat-history/:sessionId/messages` | 会话消息列表 |
| `PATCH` | `/api/ai/chat-history/:sessionId` | 更新会话标题 |
| `DELETE` | `/api/ai/chat-history/:sessionId` | 软删除单个会话 |
| `POST` | `/api/ai/chat-history/batch-delete` | 批量软删除会话 |
| `POST` | `/api/ai/chat-history/delete` | 按 messageId 批量清理记录 |

服务端使用登录态 `MEMBER_CODE` 限定归属；不得信任前端传入的任意用户 ID。

## 七、查询与删除语义

- 会话摘要：每个 session 返回一条最新摘要，按 `chat_time` 倒序。
- 会话消息：按时间顺序返回该 session 的全部 active 记录。
- 重命名：更新该用户、该 session 的全部记录标题。
- 删除：将 `status` 置为 `deleted`，保留审计和恢复空间。
- 重问/刷新：按旧 assistant `messageId` 清理被替换记录。

## 八、本地历史迁移

`AiQaPage.vue` 的 `silentMigrate()`：

1. 延迟约 2 秒执行，避免阻塞首屏。
2. 读取 `historyChat_guest`。
3. 未登录时跳过且不写完成标记。
4. 按 UTF-8 字节数切分为约 30KB 批次。
5. 逐批调用 import 接口。
6. 全部成功后写 `historyChat_uploaded=true`。

失败、停止和中断状态的 bot 消息不导入。

## 九、历史同步与懒加载

`ChatSidebar.vue` 首次挂载只同步服务端会话摘要。服务端有、本地无的会话先建立空消息占位；用户点击后才请求完整消息，并从 `charts_json` 恢复结构化展示。

该设计降低首屏数据量，同时保留本地历史快速显示和服务端历史跨设备恢复能力。

详见 [10-历史记录会话同步与侧边栏交互.md](./10-历史记录会话同步与侧边栏交互.md)。

## 十、Token 与反馈

Token 和反馈不再写 Bitable：

| 能力 | 表 | 服务 |
|---|---|---|
| Token 统计 | `ai_token_records` | `TokenRecordService`，PostgreSQL `ON CONFLICT` 原子累加 |
| 二级反馈 | `ai_feedbacks` | `FeedbackService`，按 `message_id` upsert |
| 聊天记录 | `ai_chat_records` | `ChatRecordService` |

聊天记录的 `token_consumed` 仅用于单条记录展示；运营统计以 `ai_token_records` 为准。

## 十一、验证清单

- 新问答在 `ai_chat_records` 创建一条记录。
- 相同 messageId 重写时为 update，不重复创建。
- `charts_json` 能恢复 chart、metrics、conclusion。
- 其他用户不能读取、重命名或删除该会话。
- 单删和批量删除后列表不再返回记录。
- localStorage 迁移成功后写完成标记，失败时可重试。
- `npm run type:check` 通过。
