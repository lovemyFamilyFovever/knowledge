# AI问答代码精读指南（当前实现）

> 版本：v3.0 增量版 | 最后更新：2026-08-21  
> 注意：旧版行号和“Bitable/OpenAPI controller”描述已失效，以下以当前仓库为准。

---

## 架构概览

```
用户问题
    ↓
AiController (/api/ai/chat, SSE)
    ├── fast 模式：BailianService.askFastStream（qwen-turbo，兼容API）
    └── expert 模式：
          PipelineService.process()
            → AiGovernanceService（权限/能力/来源治理）
            → decideAiQueryRoute()（轻量路由）
          BailianService.askStream() → 百炼App 2.0 API
    ↓
SSE 事件流：start → analysis_progress/thinking → delta/content
            → chart/metrics/conclusion → done
    ↓
后端清洗与持久化：
    sanitizeAiAnswerCharts（@shared/ai-chart）
    sanitizeAiAnswerForDisplay（@shared/ai-display-sanitizer）
    ChatRecordService.saveChatRecord（PostgreSQL）
    TokenRecordService.record（PostgreSQL 原子 upsert）
```

## 核心文件

### server/modules/ai/pipeline.service.ts

核心顺序不是直接进入 query-policy，而是“治理优先、路由其次”：

```typescript
const governance = await governanceService.inspectQuery(query, memberCode);
// 敏感数据或能力状态可直接返回；能力核验可强制内部查询。
const decision = decideAiQueryRoute(query);
return { ...decision, accessScope: governance.accessScope };
```

输出 `PipelineResult`：
- `route`: `data-capability-check | internal-industry-news | external-official-public-info | internal-market-data | general`
- `allowWebSearch`: 当前所有路由均返回 `false`（联网由平台侧 `enableWebSearch` 控制，白名单过滤在后端）
- `chartIntent`: `line | bar | pie | none`
- `finalPrompt`: 内部新闻路由会强制注入「仅查 erp_cms_article_data」的提示；市场数据路由会追加图表规则指令
- `directResponse`: query-policy、敏感数据或能力核验可直接结束
- `accessScope`: `INTERNAL | EXTERNAL`
- `capabilityCheck`: 能力 ID、名称、内部来源和状态

### server/modules/ai/ai-governance.service.ts + data-capability-registry.ts

- 从 VIP feature 解析 INTERNAL/EXTERNAL；异常按 EXTERNAL 收紧。
- 敏感问题直接拒绝，受限第三方来源同时过滤 observation、流式正文、最终正文和 references。
- 数据能力问题返回 `FOUND / NOT_FOUND / NOT_SUPPORTED / PERMISSION_DENIED`，其中 FOUND 必须有真实内部 observation。
- 详细规则见 [09-数据治理能力核验与内容安全.md](./09-数据治理能力核验与内容安全.md)。

### server/modules/ai/ai-query-policy.ts

四类路由决策：
- `isExternalOfficialQuery()`：政府政策 / 行业协会通知公告 / 上市公司公告 / 企业官方公告 → 返回 `directResponse`（不调用模型）
- `isInternalIndustryNewsQuery()`：51不锈钢/不锈钢行业+新闻资讯动态 → 注入 `buildInternalNewsPrompt` 强制内部表查询
- `INTERNAL_MARKET_TERMS` 或 `decidePriceChartPlan().isPriceQuery` → internal-market-data
- 其余 → general

### server/modules/ai/price-chart-policy.ts

判定是否价格问题 + 图表意图：

| 触发词 | 意图 |
|--------|------|
| 占比/比例/构成/份额/分布 | pie |
| 对比/比较/价差/不同市场/各市场 + 多口径 | bar |
| 最近/近期/本周/走势/涨跌 + 价格主体 | line |
| 单一价格/无趋势 | none |

- `buildInstruction(intent)` 生成注入模型的「后端图表规则」文本（含「禁止输出 ECharts JSON」约束）
- `selectInternalPriceEvidence()` 从 toolObservations 中筛出价格证据行

### server/modules/ai/search-source-policy.ts + config/search-source-allowlist.ts

联网来源白名单治理：
- 默认白名单：`gov.cn / cninfo.com.cn / sse.com.cn / szse.cn / hkexnews.hk`
- `BAILIAN_SEARCH_ALLOWED_DOMAINS` 可扩展
- `filterAllowedSearchSources` / `normalizeAllowedSourceUrl` 过滤受限域名、危险重定向参数
- `buildVerifiedSearchContext` 构建可核实的搜索上下文，无结果返回 `NO_VERIFIED_PUBLIC_INFO_MESSAGE = '暂未检索到可核实的公开信息'`

### server/modules/ai/analysis-progress.service.ts

SSE 阶段进度的上下文工厂。6 种任务类型：

| kind | 触发 |
|------|------|
| news | 内部新闻路由 |
| price-trend | chartIntent=line |
| price-comparison | chartIntent=bar/pie |
| price-current | internal-market-data |
| knowledge | 材质/区别/成分/牌号等 |
| general | 兜底 |

- `createAnalysisContext(question, route, chartIntent)` 生成各阶段标题（识别→查询→整理→回答）
- `buildRecognizedConditionDetail()` 从问题中提取市场/材质/表面/产品/时间条件
- 前端阶段顺序：identify(10) → data_query(20) → data_organization(30) → chart_generation(40) → answer_generation(50)

### server/modules/ai/ai-chart-builder.ts

从 `toolObservations` 构建结构化图表（后端权威图表源）：
- `extractPriceRows()`：递归提取带 `price` 或 `minPrice/maxPrice` 的记录；区间报价统一换算为 `(min + max) / 2`，不使用上限代替代表价
- 趋势 canonical scope 必须锁定材质、品类、表面、完整规格（厚度×宽度×卷/板）、边部和价格类型；单市场时市场也属于锁定口径，同规格多市场时市场只作为拆分维度，每个市场生成独立 series，禁止跨市场平均；`transactionstatusname` 表示毛边/切边，不是价格类型
- 用户未指定厚度/规格时，按日期连续性、覆盖日期数和最新日期选择唯一单一规格，禁止跨 `spec_model` 聚合
- `buildLineChart()`：只从 canonical series 生成；同一天同一完整口径存在多条报价时才允许计算区间中点，选最多 4 组系列
- `buildBarChart()`：选比较维度（规格/市场/材质/表面/产品/产地），最新日期口径，最多 12 类
- `buildPieChart()`：提取 share/ratio/占比 行，最多 12 类
- 价格关键指标卡和正文“核心数据”表直接复用折线图的 canonical series；图表在输出前逐市场校验最新日期末值，失败则记录 `PriceCanonicalMismatch` 并禁止输出图表与价格指标
- 运行时记录最新日期的原始行、问题条件过滤行、canonical 规格行，以及旧版跨规格 min/max 会使用的贡献记录，便于追溯异常值来源
- 结果带 `priceRowCount` / `distinctDateCount` / `reason`，生成失败会发 `chart_generation/failed` 进度

### server/modules/ai/ai-data-insight-builder.ts

- `buildMetricCardsFromObservations()`：从 observation 生成价格、库存、产量、进口、出口关键指标。
- 价格指标必须复用 `CanonicalPriceSeriesResult`，不得另算口径。
- `buildPriceTrendConclusionFromCanonical()`：根据区间趋势、最新一期变化和最新报价生成单句结论，`source='internal'`。
- `buildConclusionCardFromAnswer()`：其他结构化回答在完整正文完成后提取第一句有效结论，并跳过查询/整理过程话术。
- 详细见 [07-结构化回答与价格数据一致性.md](./07-结构化回答与价格数据一致性.md)。

### server/modules/ai/bailian.service.ts

百炼 API 引擎：
- `askFastStream()`：快速模式，兼容API 调 qwen-turbo；`FAST_MODEL='qwen-turbo'`、`FAST_MAX_HISTORY=5`、`INJECT_INTERVAL=5`；System Prompt 内置「[切换到专家模式]」围栏
- `askFastSync()`：同步版（配单/测价）
- `askStream()`：专家模式，App Completion API（`APP_API_BASE=https://dashscope.aliyuncs.com/api/v1/apps`），回调 onToolStart/onToolObservation/onAnswerStart，`REVIEW_APP_ID=6640056532744a0885c60011d0999e65`（复核）
- 价格趋势主请求若因百炼累计 `thoughts` 丢失 SQL 参数或只返回跨规格均价而无法构建 canonical，`queryCanonicalPriceTrendObservations()` 会在 `done` 前发起一次固定结构化补查：只返回同一完整规格、同一边部和同一价格类型的无锡/佛山双市场数据；结果仍须经过原 canonical 选择和逐市场 `PriceCanonicalMismatch` 校验
- 后端记录 canonical、chart/metrics build result 和实际发送的 SSE 类型；前端在终态记录实际收到的 SSE 类型，便于区分“未发送”和“收到未渲染”
- 前端不依赖 SSE 固定顺序：`useChatSession.ts` 在任务级暂存 chart/metrics/conclusion，assistant 消息创建后及每次 content/delta/done 都重新挂载；正文快照只更新文本字段，不替换消息对象。浏览器日志 `SseEventReceived`、`StructuredMessageLifecycle`、`StructuredMessageFinalState`、`StructuredPresentationRenderState` 可串联检查接收、挂载、终态与组件渲染判定
- `textToSpeech()`：TTS（POST /api/ai/tts）
- 通过 `readEnvFile` 读取 `.env`

`/api/ai/chat` 专家模式关键流程：
1. `pipelineService.process()` → `promptToSend = finalPrompt || question`
2. `createAnalysisContext(question, route, chartIntent)`
3. `directResponse` 存在则直接 delta + done 结束
4. `askStream()` 流式返回正文、思考和工具 observation；每段先经过治理过滤
5. 汇总最终 observations，必要时执行 canonical 价格补查
6. 构建并校验 `chart`，再生成同源 `metrics`
7. `sanitizeAiAnswerCharts()` + `sanitizeAiAnswerForDisplay()`，必要时发送 `content` 完整快照校正
8. 价格趋势从 canonical 生成一句话 `conclusion`，其他结构化回答从完整正文提取
9. 保证 chart/metrics/conclusion 均在 `done` 前完成
10. PostgreSQL 保存正文与 `AiStructuredPresentation`，记录 Token

## 共享类型与清洗（shared/）

### shared/ai-chat.ts
```typescript
type AnalysisProgressStatus = 'running' | 'completed' | 'failed';
interface AnalysisProgressEvent { stage; status; title; detail?; timestamp; }
type AiStructuredChartType = 'line' | 'bar' | 'pie';
interface AiStructuredChart { id; type: 'chart'; chartType; title; xAxis; series; unit; source: 'internal'; }
interface AiMetricCardGroup { id; type: 'metrics'; title: '关键指标'; items; source: 'internal'; }
interface AiConclusionCard { id; type: 'conclusion'; title: 'AI结论'; text; source: 'model' | 'internal'; }
interface AiStructuredPresentation { version: 1; charts?; metrics?; conclusion?; }
```

### shared/ai-chart.ts
- `validateAiChartOption(rawOption, options)`：校验 ECharts option（类型白名单、series 数≤8、数据点≤200、禁止 `__proto__`、evidence 可核验）
- `sanitizeAiAnswerCharts(text, options)`：移除 ```` ```echarts ```` 代码块，只保留第一个合法图表，返回 `{ text, chartGenerated, chartType, rejectedChartCount }`

### shared/ai-display-sanitizer.ts
- `sanitizeAiAnswerForDisplay(text)`：删除 SQL/表名/工具参数，以及“准备查询、提取、选取、整理数据”等过程性独白，返回 `{ text, removedInternalDetailCount }`

### client/src/utils/structured-message-flow.ts

- 结构化 SSE 可以乱序到达，前端不按事件顺序排版。
- 有图表或指标时等待 conclusion 后统一释放，`done` 兜底强制释放。
- `content` 快照只替换正文，不替换整个消息对象，避免丢失已经挂载的结构化内容。
