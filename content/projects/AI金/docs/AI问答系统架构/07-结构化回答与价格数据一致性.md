# 结构化回答与价格数据一致性

> 当前实现快照：2026-08-21  
> 适用范围：AI 问答专家模式中的价格趋势、价格对比、占比及其他可结构化数据回答

## 一、为什么需要结构化回答

早期回答仅包含 Markdown 正文和模型自由生成的 ECharts。该方式存在三个问题：图表代码不可控、图表与正文可能使用不同价格口径、重要结论容易混入模型的查询过程。

当前实现将一轮回答拆成四类内容：

| 内容 | SSE 类型 | 数据来源 | 前端组件 |
|---|---|---|---|
| 正文 | `delta` / `content` | 经治理和展示清洗后的模型回答 | `BotMessage.vue` |
| 图表 | `chart` | 后端从工具 observation 构建 | `EChartsBlock.vue` |
| 关键指标 | `metrics` | 后端从 observation 或 canonical series 计算 | `AiMetricCards.vue` |
| AI 结论 | `conclusion` | 价格趋势使用内部数据计算，其他结构化回答从完整正文提取 | `AiConclusionCard.vue` |

共享类型定义在 `shared/ai-chat.ts`，持久化载体为 `AiStructuredPresentation`：

```typescript
interface AiStructuredPresentation {
  version: 1;
  charts?: AiStructuredChart[];
  metrics?: AiMetricCardGroup;
  conclusion?: AiConclusionCard;
}
```

## 二、价格趋势的 canonical 口径

`server/modules/ai/ai-chart-builder.ts` 负责从百炼工具返回的 observation 中提取价格行，并选择唯一可信的 canonical series。

canonical 规则：

1. 价格区间使用 `(minPrice + maxPrice) / 2`，不把区间上限当代表价。
2. 锁定材质、品类、表面、完整规格、边部、价格类型等维度。
3. 未指定规格时，按共同日期、连续覆盖和最新日期选择一个稳定规格，禁止跨规格求平均。
4. 多市场趋势以市场作为 series 维度，其他价格口径必须一致，禁止无锡与佛山跨市场平均。
5. 至少需要 3 个有效日期；同规格多市场共同日期不足时不退化为单市场图。
6. 图表生成后使用 `validateChartLatestAgainstCanonical()` 逐系列校验最新值；不一致时拒绝发送图表和价格指标。

canonical 同时驱动：

```text
canonical price series
    ├─ 折线图 chart
    ├─ 关键指标 metrics
    ├─ 正文“核心数据”表
    └─ 一句话价格走势 conclusion
```

因此，这四处展示不能各自重新解析或重新聚合价格。

## 三、结构化图表

图表意图由 `price-chart-policy.ts` 判定：

| 意图 | 典型问题 | 图表 |
|---|---|---|
| `line` | 最近、近期、走势、变化、涨跌 | 多序列折线图 |
| `bar` | 单一时点的市场、材质、规格对比 | 柱状图 |
| `pie` | 占比、比例、构成、份额 | 饼图 |
| `none` | 单一当前价格或非价格问题 | 不生成图表 |

模型输出的 ```` ```echarts ```` 代码不进入正式展示。`sanitizeAiAnswerCharts()` 会移除模型自由图表，正式图表只接受后端生成且 `source='internal'` 的结构化对象。

当主请求的工具 observation 不足以生成稳定价格趋势时，`BailianService.queryCanonicalPriceTrendObservations()` 会在 `done` 之前执行一次固定结构补查。补查结果仍需经过同一 canonical 选择和末值校验，不能绕过质量门槛。

## 四、关键指标卡

`server/modules/ai/ai-data-insight-builder.ts` 的 `buildMetricCardsFromObservations()` 负责生成指标卡。

价格趋势常见四项：

- 单序列：最新价格、较上一期变化、区间最高、区间最低。
- 多市场：各市场最新价格，并补充全区间最高、最低。
- 涨跌方向使用 `up / down / flat`，前端映射为语义色和箭头。
- 价格趋势必须传入已校验的 canonical series；canonical 缺失时不得另起一套聚合逻辑。

非价格场景目前支持库存、产量、进口量、出口量等可比较时间序列；明确要求多个指标时，需要等待所需指标全部到齐后再生成，避免只展示半套数据。

## 五、一句话 AI 结论

### 5.1 价格趋势

`buildPriceTrendConclusionFromCanonical()` 直接根据 canonical series 计算：

- 区间趋势：整体偏强、整体偏弱、整体震荡、震荡偏强、震荡偏弱或走势分化。
- 最新变化：各系列最新值与上一期的差值。
- 最新报价：与图表末值和指标卡完全一致。

示例：

> 近期304 · 2B · 2.0*1219*C价格整体偏弱，佛山市场、无锡市场较上一期均下跌25元/吨，最新报价为佛山市场15,700元/吨、无锡市场15,550元/吨。

该结论为单句，`source='internal'`，不从模型开场白或思考过程截取。

### 5.2 其他结构化回答

`buildConclusionCardFromAnswer()` 在完整回答完成后提取第一句有效结论，并跳过“我要查询、选取数据、整理趋势”等过程性话术。流式阶段不再提前锁定正文第一句，避免过程描述抢占结论卡。

## 六、正文清洗

`shared/ai-display-sanitizer.ts` 清理以下内容：

- SQL、表名、schema、工具名和接口参数。
- 模型调用工具、准备查询、提取或整理数据的内部独白。
- 非 ECharts 代码块中的内部实现细节。

`AiGovernanceService` 还会按用户数据范围过滤敏感数据和受限第三方来源。最终正文使用 `content` 快照校正已经发送的流式 `delta`，所以清洗规则在完整回答阶段仍然有效。

## 七、持久化与历史恢复

`ChatRecordService` 将 `charts + metrics + conclusion` 序列化为版本化 JSON，写入 `ai_chat_records.charts_json`。历史加载时兼容两种格式：

1. 当前格式：`AiStructuredPresentation` 对象。
2. 旧格式：直接保存的 `AiStructuredChart[]` 数组。

## 九、修改红线

- 禁止直接使用模型自由 ECharts 作为正式图表。
- 禁止图表、指标、核心数据表、结论分别计算价格。
- 禁止在 observation 尚未完整时提前固化价格指标。
- 禁止将模型的查询计划、工具调用过程或整理步骤作为 AI 结论。
- 修改 SSE 结构化事件时，必须同步检查共享类型、前端暂存逻辑、持久化和历史恢复。
