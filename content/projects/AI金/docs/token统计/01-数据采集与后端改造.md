# Token 统计 — 数据采集与后端改造

> 版本: v1.1 | 日期: 2026-07-27 | 状态: 已实现

## 一、千问 API 可返回的字段分析

### 1.1 字段来源取决于调用协议

千问 / 百炼有三种调用协议，返回的 usage 结构完全不同：

#### 协议 A：OpenAI 兼容（`qwen-turbo`、`qwen3.7-plus`）

用于：快速模式问答、测价

```json
{
  "usage": {
    "prompt_tokens": 26,
    "completion_tokens": 66,
    "total_tokens": 92,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_creation_input_tokens": 0
    }
  }
}
```

**可提取字段：** 输入 token、输出 token、总计、缓存命中 token、缓存创建 token

#### 协议 B：DashScope App API

用于：专家模式问答

```json
{
  "usage": {
    "models": [
      {
        "model_id": "qwen-max",
        "input_tokens": 453,
        "output_tokens": 94
      }
    ]
  }
}
```

**可提取字段：** 输入 token、输出 token（需自行汇总为 totalTokens）、模型名
**不可用：** `cached_tokens`（App API 不返回此字段）

#### 协议 C：多模态生成 API（TTS）

用于：语音播报

**无 usage 字段，不纳入统计**

### 1.2 字段可用性矩阵

| 字段 | 快速模式 (qwen-turbo) | 专家模式 (App API) | 测价 (qwen3.7-plus) | TTS |
|------|:---:|:---:|:---:|:---:|
| `totalTokens` | ✅ | ✅（计算） | ✅ | ❌ |
| `inputTokens` | ✅ | ✅ | ✅ | ❌ |
| `outputTokens` | ✅ | ✅ | ✅ | ❌ |
| `cachedTokens` | ✅ | ❌ | ✅ | ❌ |
| `cacheCreationTokens` | ✅ | ❌ | ✅ | ❌ |
| `modelName` | ✅ | ✅ | ✅ | ❌ |

### 1.3 建议采集的字段

| 字段 | 来源 | 必选 |
|------|------|:---:|
| `totalTokens` | 全部调用 | ✅ |
| `inputTokens` | 全部调用（除 App API） | ✅ |
| `outputTokens` | 全部调用（除 App API） | ✅ |
| `cachedTokens` | OpenAI 兼容协议 | 推荐 |
| `cacheCreationTokens` | OpenAI 兼容协议 | 推荐 |
| `modelName` | 全部调用 | 推荐 |
| `apiCallCount` | 后端自行累加 | ✅ |

## 二、数据模型

### 2.1 存储粒度

**每天 + 每个用户 + 每个功能分类 = 一条记录**（行）。

同一天的多次调用累加到同一条记录的对应数值字段上。

### 2.2 Bitable 表字段设计

表名：`ai_token_stats`，环境变量：`BITABLE_TOKEN_STATS_TABLE_ID`

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `日期` | 日期 | 统计日期，如 `2026-07-26` |
| `用户ID` | 文本 | x-user-id（MEMBER_CODE） |
| `用户名` | 文本 | x-user-name |
| `功能分类` | 文本 | 问答 / 测价 / 配单 |
| `调用次数` | 数字 | 当天该分类 API 调用总次数 |
| `总Token` | 数字 | totalTokens 累加 |
| `输入Token` | 数字 | inputTokens 累加 |
| `输出Token` | 数字 | outputTokens 累加 |
| `缓存命中Token` | 数字 | cachedTokens 累加（仅 qwen-turbo / qwen3.7-plus） |
| `缓存创建Token` | 数字 | cacheCreationTokens 累加（仅 qwen-turbo / qwen3.7-plus） |
| `最近调用时间` | 日期时间 | 当天最后一次调用的时间 |

#### 示例数据

| 日期 | 用户ID | 用户名 | 功能分类 | 调用次数 | 总Token | 输入Token | 输出Token | 缓存命中Token | 最近调用时间 |
|------|--------|--------|----------|----------|---------|-----------|-----------|---------------|-------------|
| 2026-07-26 | user_001 | 张三 | 问答 | 15 | 45000 | 28000 | 17000 | 2000 | 2026-07-26 17:30 |
| 2026-07-26 | user_001 | 张三 | 测价 | 3 | 18000 | 12000 | 6000 | 0 | 2026-07-26 16:45 |
| 2026-07-26 | user_001 | 张三 | 配单 | 8 | 12000 | 8000 | 4000 | 500 | 2026-07-26 15:20 |
| 2026-07-26 | user_002 | 李四 | 问答 | 30 | 90000 | 55000 | 35000 | 4000 | 2026-07-26 18:00 |

### 2.3 累加语义（Upsert）

每次 API 调用完成后，在服务端执行 **upsert** 逻辑：

```
1. 查询"今天 + 该用户 + 该功能分类"的记录
2. 存在 → UPDATE：调用次数 +1，各 token 字段累加，更新最近调用时间
3. 不存在 → INSERT 新记录
```

### 2.4 唯一性约束

多维表格没有数据库级别的 UNIQUE 约束，需要在服务端代码中做「先查后写」保证幂等。公式列作为兜底校验。

## 三、后端改造清单

### 3.1 TokenRecordService

文件：`server/modules/ai/token-record.service.ts`

职责：
- `record(category, userId, userName, tokens)` — 写入/更新 Bitable 记录（先查后写 + 内存写锁）
- `getUserStats(userId, days?)` — 查询指定用户的统计
- `getAllUsersStats(startDate?, endDate?)` — 查询所有用户统计（ERP 后台用）

### 3.2 内存写锁（并发控制）

```typescript
private writeLocks = new Map<string, Promise<void>>()

async record(params: TokenRecordParams): Promise<void> {
  const key = `${params.date}_${params.userId}_${params.category}`
  const prev = this.writeLocks.get(key) ?? Promise.resolve()
  const next = prev.then(() => this.doRecord(params))
  this.writeLocks.set(key, next)
  await next
  this.writeLocks.delete(key)  // 写入完成后清理，防止 Map 无限增长
}
```

- 同一 key 的写入严格串行，不同 key 之间并行
- 写入完成后立即清理，不会内存泄漏

### 3.3 改造 BailianService — extractUsage()

文件：`server/modules/ai/bailian.service.ts`

改造 `extractUsage()` 方法，返回完整的 Token 信息结构：

```typescript
interface TokenUsage {
  totalTokens: number
  inputTokens?: number
  outputTokens?: number
  cachedTokens?: number
  cacheCreationTokens?: number
  modelName?: string
}
```

不同协议的适配：

| 协议 | input/output 来源 | cached 来源 |
|------|-------------------|-------------|
| App API | `usage.models[0].input_tokens / output_tokens` | ❌ 不返回 |
| OpenAI 兼容 | `usage.prompt_tokens / completion_tokens` | `usage.prompt_tokens_details.cached_tokens` |
| DashScope 原生 | `usage.input_tokens / output_tokens` | `usage.prompt_tokens_details.cached_tokens` |

### 3.4 改造 forecast.service.ts

`callBailianForecast()` 改动两处：

1. **请求体增加**：`"stream_options": { "include_usage": true }` — 确保 SSE 最后一个 chunk 携带 usage
2. **SSE 解析增加**：在 `data: [DONE]` 之前的最后一个合规 chunk 中提取 `parsed.usage`
3. **返回类型改为**：`Promise<{ text: string; usage: TokenUsage }>`

### 3.5 改造 ai.controller.ts — 补齐缺失的 token 记录

在每个 AI 接口方法末尾，调用 `recordTokenUsage()` 私有方法：

```typescript
private recordTokenUsage(req: Request, category: TokenCategory, usage: any, question?: string): void {
  if (!usage?.totalTokens) return;
  const userId = (req.headers['x-user-id'] as string) || 'anonymous';
  const userName = (req.headers['x-user-name'] as string) || '';
  this.tokenRecordService.record({
    category, userId, userName,
    totalTokens: usage.totalTokens,
    inputTokens: usage.inputTokens,
    outputTokens: usage.outputTokens,
    cachedTokens: usage.cachedTokens,
    cacheCreationTokens: usage.cacheCreationTokens,
    model: usage.modelName,
    question: question?.substring(0, 50),
  }).catch(err => this.logger.warn(`Token 记录失败: ${err.message}`));
}
```

| 接口 | 改造项 |
|------|--------|
| `POST /api/ai/chat` — 快速模式 | done 事件含 totalTokens，调用 record() |
| `POST /api/ai/chat` — 专家模式 | done 事件含 totalTokens，调用 record() |
| `POST /api/ai/v1/forecast` | 修改 `callBailianForecast()` 返回 usage |
| `POST /api/ai/v1/forecast/stream` | 同上 |
| `POST /api/ai/v1/forecast/export` | 同上 |
| `POST /api/ai/parse-enquiry-params` | 透传 `result.totalTokens` |
| `POST /api/ai/score-matches` | 透传 `result.totalTokens` |
| `POST /api/ai/stock-query` | 透传 `result.totalTokens` |
