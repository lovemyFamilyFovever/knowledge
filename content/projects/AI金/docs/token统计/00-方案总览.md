# Token 统计 — 方案总览

> 版本: v1.1 | 日期: 2026-07-27 | 状态: 已实现（数据采集 + 前台展示 + ERP 后台）

## 一、需求概述

统计整个项目中每个用户的 AI Token 消耗，按三大功能分类：

| 分类 | 功能 | 调用方式 | 模型 |
|------|------|----------|------|
| **问答** | `/api/ai/chat`（快速模式 + 专家模式） | SSE 流式 | `qwen-turbo` / 百炼 App API |
| **测价** | `/api/ai/v1/forecast` / `stream` / `export` | 同步 / SSE 流式 | `qwen3.7-plus` |
| **配单** | `/api/ai/parse-enquiry-params` + `/api/ai/score-matches` | 同步 | `qwen-turbo` |

**关键约束：**

- 以 **天** 为粒度，每个用户每天一条记录（当天多次调用累加到同一条记录）
- 前端用户只能看到自己的统计，ERP 后台管理员可以看到所有用户
- 前端只显示每日总量，ERP 后台显示各功能模块详细信息
- 不计入：TTS（语音合成无 token 返回）、反馈（不调 AI）
- 不处理历史数据

## 二、架构总览

### 2.1 调用链路

```
[用户操作] → [前端页面] → [Controller] → [BailianService / ForecastService] → [百炼 API]
                                                                                      ↑
                                                                              返回 usage
                                                                                      ↓
                                          [Controller 末尾] ← [TokenRecordService.record()]
                                                 ↓
                                          [Bitable 多维表格]
                                                 ↓
[TokenStatsPage] ← [GET /api/ai/token-stats/my] ← [TokenRecordService.getUserStats()]
[ERP后台]       ← [GET /api/ai/token-stats/all] ← [TokenRecordService.getAllUsersStats()]
```

### 2.2 存储方案：飞书多维表格

选择飞书多维表格而非 SQLite 的原因：

| 维度 | SQLite | 多维表格 |
|------|--------|---------|
| 并发 | 单写，多读 | 飞书托管，支持并发 |
| 接入成本 | 需引入 `better-sqlite3`，管理 db 文件 | 已有 `feishu-bitable.service.ts`，复用 |
| 前端查询 | 需要 API 接口读取 | 可直接通过 Bitable API 或前端 SDK 查询 |
| ERP 后台 | 需额外 API | 飞书多维表格本身就是后台视图 |
| 可视化管理 | 需额外页面 | 多维表格自带视图筛选 |
| 每日一条的写入频率 | 完全够用 | 完全够用 |

## 三、已决策事项

### 3.1 多维表格唯一性校验 ✅

飞书多维表格支持公式列实现唯一性校验。**最终方案**：先查后写（2 次 Bitable API）+ 公式列兜底标记重复记录。

### 3.2 并发控制 ✅ 内存写锁

同一天同一个用户同一分类的多次并发调用，通过**内存写锁**保证串行写入，避免插入重复记录。同一 key 的写入严格串行，不同 key 之间并行。写入完成后立即清理，不会内存泄漏。

### 3.3 数据量 ✅ 暂不处理

前期数据量不大（预估每天 ~150 条），后期切到数据库后再做归档策略。

### 3.4 ERP 后台 ✅ 独立实现

ERP 后台 Token 统计看板已实现，通过 `/api/erp/token-stats/*` 接口读取数据。详见 `docs/erp/07-AI用量统计与计费.md`。

### 3.5 缓存 Token 统计维度 ✅ 系统负载统计

关注「系统负载统计」维度，`totalTokens` 按实际调用的全部 token 计算（含缓存命中和缓存创建），不计费率折扣。在多维表格和前端展示中单独列出 `缓存命中Token` 和 `缓存创建Token` 字段，便于分析缓存效果。
