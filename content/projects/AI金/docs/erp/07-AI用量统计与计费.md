# AI 用量统计与计费方案

> 版本: v1.1 | 日期: 2026-07-27 | 状态: ERP Token 消耗统计已实现，计费层方案设计中

## 一、背景与目标

AI金项目当前所有 AI 调用（问答、测价、配单）免费向用户开放，缺乏用量追踪和成本核算能力。随着用户增长和调用量上升，需要建立完整的用量统计与计费体系。

核心目标：

- 精确统计每个用户在各功能模块的 Token 消耗量
- 建立"用量 → 成本 → 套餐抵扣 → 超额计费"的完整链路
- 为未来按量计费或套餐制提供数据基础
- 在 ERP 后台提供管理员可见的全平台用量大盘

技术前提：Token 采集与存储方案已在 `docs/token统计/设计方案.md` 中完成设计。本文档聚焦计费层的定价模型、费用计算、账单体系和 ERP 后台展示，不重复讨论 Token 采集细节。

## 二、定价模型

### 2.1 模型定价

当前项目使用的模型及百炼平台刊例价（2026年7月）：

| 模型 | 用途 | 输入价格（元/千Token） | 输出价格（元/千Token） |
|------|------|------------------------|------------------------|
| qwen-turbo | 快速问答、配单 | 0.0003 | 0.0006 |
| qwen-plus | 专家模式问答 | 0.0008 | 0.002 |
| qwen3.7-plus | 测价 | 0.003 | 0.012 |

### 2.2 成本计算公式

```
单次调用成本 = 输入Token × 输入单价 + 输出Token × 输出单价

当日成本 = Σ(当日所有调用成本)
月度成本 = Σ(当月所有调用成本)
```

缓存命中 Token 不计费（百炼平台对 `cached_tokens` 不收费），但仍记录在统计中用于分析缓存效果。

### 2.3 价格维护策略

初期将价格硬编码在配置文件或常量中，后续可迁移到飞书多维表格中由运营人员维护，实现价格变动时无代码发布：

```
BITABLE_PRICE_CONFIG_TABLE
├── 模型名称 (文本)
├── 输入单价 (数字，元/千Token)
├── 输出单价 (数字，元/千Token)
├── 生效日期 (日期)
└── 备注 (文本)
```

ERP 后台提供"价格配置"页面供管理员增改历史价格。

## 三、计费体系设计

### 3.1 计费模式：套餐制 + 超额按量

当前设计分两个阶段推进：

**阶段一（MVP）：纯统计，不扣费**

只做用量追踪和成本展示，用户不感知费用，管理员在后台查看全局数据。目的是验证数据准确性和评估成本规模。

**阶段二（收费上线后）：套餐制**

| 维度 | 规则 |
|------|------|
| 基础套餐 | 每个套餐绑定月度 Token 额度（如基础版 10万Token/月，专业版 50万Token/月） |
| 额度共享 | 同一 VIP 套餐下的所有成员共享额度池 |
| 超额处理 | 超出额度后：方案A — 拒绝服务提示升级；方案B — 自动按量计费 |
| 计费周期 | 自然月，每月 1 号重置额度 |
| 账单日 | 每月 2 号生成上月账单 |

**关于方案A与方案B的选择：**

方案A（超限拒绝）实现简单，但用户体验差。建议初期采用方案A，后期视运营策略切换为方案B。

### 3.2 数据流

```
每次 AI 调用
  → TokenRecordService.record() 写入飞书 Bitable（token统计表，已设计）
  → CostCalculatorService.calculate() 计算本次调用成本
  → 写入飞书 Bitable 计费明细表（本文档设计）
  → 更新用户当月总成本汇总（内存缓存 + Bitable）
  → 检查套餐额度（阶段二启用）
    → 未超额：正常返回
    → 超额：触发超额策略（拒绝 / 标记超额）
```

### 3.3 计费明细表设计（飞书多维表格）

**表名：** `ai_cost_records`（新增）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 日期 | 日期 | 调用日期 |
| 时间 | 日期时间 | 调用时间戳 |
| 用户ID | 文本 | x-user-id |
| 用户名 | 文本 | x-user-name |
| 功能分类 | 单选 | 问答 / 测价 / 配单 |
| 子功能 | 文本 | 快速模式 / 专家模式 / parse-enquiry-params / score-matches / forecast_sync / stock-query |
| 模型 | 文本 | qwen-turbo / qwen-plus / qwen3.7-plus |
| 输入Token | 数字 | input_tokens |
| 输出Token | 数字 | output_tokens |
| 缓存命中Token | 数字 | cached_tokens（不计费但记录） |
| 本次费用 | 数字 | 调用成本（元，保留6位小数） |
| 套餐ID | 文本 | 关联的套餐ID（阶段二启用） |
| 超额标记 | 复选框 | 是否为超额调用（阶段二启用） |

**与 Token 统计表的关系：**

`ai_cost_records` 是每次调用的明细记录，`ai_token_stats` 是按天+用户+分类的汇总记录。两者互补：

- 明细表：用于追溯单次调用成本、精准计费
- 汇总表：用于趋势分析、仪表盘展示

## 四、后端实现设计

### 4.1 新增服务

**CostCalculatorService**（`server/modules/ai/cost-calculator.service.ts`）

```typescript
interface CostResult {
  inputCost: number     // 输入Token成本
  outputCost: number    // 输出Token成本
  totalCost: number     // 总成本
  cachedTokensFree: number  // 缓存节省的成本
}

calculateCost(modelName: string, inputTokens: number, outputTokens: number): CostResult
getPriceConfig(modelName: string): PriceConfig
```

**BillingService**（`server/modules/ai/billing.service.ts`，阶段二启用）

```typescript
interface BillingCheckResult {
  allowed: boolean
  remainingQuota: number
  overageTokens: number
}

checkQuota(userId: string): BillingCheckResult
getMonthlyBill(userId: string, month: string): MonthlyBill
generateMonthlyBills(): void  // 定时任务调用
```

### 4.2 改造现有流程

在 `TokenRecordService.record()` 调用链中增加成本计算步骤：

```typescript
// 在 ai.controller.ts 各方法末尾
const cost = this.costCalculator.calculateCost(
  usage.modelName,
  usage.inputTokens,
  usage.outputTokens
)

await this.tokenRecordService.record({ ...usage })
await this.billingService.recordCost({ ...usage, ...cost })  // 写入明细表

// 阶段二：检查额度
const quota = await this.billingService.checkQuota(userId)
if (!quota.allowed) {
  // 触发超额策略
}
```

### 4.4 定时任务

阶段二需要新增一个月度账单生成任务：

- **执行时间：** 每月 2 号凌晨 2:00
- **任务内容：** 遍历所有活跃套餐用户，汇总上月 Token 消耗，生成账单记录写入 `ai_monthly_bills` 表
- **实现方式：** `@nestjs/schedule` 装饰器或外部 cron 触发

## 五、ERP 后台展示

### 5.1 页面结构

```

├── 用量概览（仪表盘）
│   ├── 今日 Token 消耗总量 + 环比
```

### 5.2 关键指标卡片

| 指标 | 说明 |

## 八、待决策事项

1. **超额策略**：超限后是直接拒绝服务，还是允许超额并标记（后续手动处理）？建议 MVP 阶段先拒绝，配合友好提示引导用户升级套餐。
2. **价格配置维护方式**：初期硬编码还是直接上 Bitable 配置表？建议硬编码先跑通，1-2周后迁移到配置表。
3. **缓存 Token 是否计入套餐额度**：不产生费用，但占用了服务资源。建议不计入额度（鼓励缓存利用）。
4. **成本精度**：Token 单价极低，费用需要保留到小数点后6位。汇总展示时可以四舍五入到后2位。
