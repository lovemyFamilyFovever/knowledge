# 03-操作日志与审计追踪

> 版本: v1.0 | 日期: 2026-07-27 | 状态: 已实现

## 一、目标

记录管理员在 ERP 后台的所有关键操作，形成完整的审计追踪链路，满足运营管理和安全合规需求。

## 二、功能范围

- 自动记录管理员的关键操作（登录、订单创建/取消/退款、数据导出、缓存清除等）
- 支持按操作人、操作类型、操作结果、关联订单号、日期范围筛选
- 30 秒缓存优化查询性能
- 前端支持自动刷新和手动刷新

## 三、数据模型

### 3.1 操作日志表（飞书多维表格）

环境变量：`BITABLE_VIP_OPERATION_LOG_TABLE_ID`

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 操作时间 | 数字 | 操作时间戳（毫秒） |
| 操作人 | 文本 | 管理员标识 |
| 操作类型 | 文本 | 操作类型枚举值 |
| 操作描述 | 文本 | 可读的操作描述 |
| 操作结果 | 文本 | success / fail |
| 关联订单号 | 文本 | 可选，关联的订单编号 |
| IP地址 | 文本 | 可选，操作来源 IP |

### 3.2 操作类型枚举

| 类型 | 说明 |
|------|------|
| `login` | 管理员登录 |
| `create_order` | 创建订单（手动开通） |
| `cancel_order` | 取消订单 |
| `refund_order` | 标记退款 |
| `export` | 数据导出 |
| `clear_cache` | 清除缓存 |
| `create_user` | 创建用户 |
| `system` | 系统操作 |

## 四、后端实现

### 4.1 文件

```
erp/server/
├── erp-operation-log.service.ts    ← 日志 CRUD + 缓存
├── erp-operation-log.controller.ts ← API 接口
```

### 4.2 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/erp/operation-logs` | 查询日志列表（分页+筛选） |
| POST | `/api/erp/operation-logs` | 记录操作日志（系统内部调用） |
| GET | `/api/erp/operation-logs/clear-cache` | 清除日志缓存 |

### 4.3 查询参数

| 参数 | 类型 | 说明 |
|------|------|------|
| page | number | 页码（默认 1） |
| pageSize | number | 每页条数（默认 20，最大 100） |
| operator | string | 操作人（模糊搜索） |
| operationType | string | 操作类型 |
| result | string | 操作结果 |
| startDate | string | 开始日期 |
| endDate | string | 结束日期 |
| relatedOrderNo | string | 关联订单号（模糊搜索） |

### 4.4 缓存策略

- 日志列表缓存 TTL 30 秒
- 每次写入新日志后不自动清除缓存（由定时 TTL 自然过期）
- 提供 `clear-cache` 接口供手动清除

## 五、前端实现

### 5.1 文件

```
erp/operation-log/
├── index.vue    ← 日志列表页（筛选+表格+自动刷新）
├── api.ts       ← API 调用
└── types.ts     ← 类型定义
```

### 5.2 页面功能

- 筛选条件：操作人、操作类型、操作结果、关联订单号、日期范围
- 表格列：操作时间、操作人、操作类型、操作描述、操作结果、关联订单号
- 自动刷新开关（Toggle）
- 分页

### 5.3 侧边栏

位于「系统管理」分组下，菜单项「操作日志」，路由 `/erp/operation-log`。
