## 二、各岗位职责细则

### 1. 技术负责人（我）
- 职责：**AI 配单**（保交付最小链路、跳转秀吗成交等，涉及交易/外部依赖/与结算财务相关，亲自做最稳）+ 架构、代码/数据库管理、飞书代码同步、数据库维护与优化、版本发布。
- 现状：最早搭建整套系统，长期一人熬夜兜底。
- 本次目标：借分工把执行层下沉，退到**决策层 + 终验 + 架构判断**，破除"每件事最后都归我收"。
- 兜底机制：**当事人负责到底 + 交叉互测独立把关**，我只做终验。

### 2. 夏康乐 —— 主开发
- 内容：**广场（内容/推荐/搜索/发布体验/消息/收藏/个人主页等）+ 用户画像 + VIP/个人中心**——延续其既有负责模块，工作量随王雪照抽离移动端而增加。
- 价值：做开发比做测试更能学透业务，匹配"副手培养"目标。
- 收口：其模块的用户交互部分由黄颖交叉测试。

### 3. 黄颖 —— AI 问答线 + 移动端设计
- 内容：
  1. **AI 问答线**（她的主场，AI 问答架构已定），三项细化：
     - **智能问答优化**：回答精准度提升（Prompt 调优 + 上下文增强）、结构化回答与价格数据一致性、图表/数据分析能力增强（P1，可降级为简易版）；
     - **知识库检索增强**：知识库补全（盘点缺的钢种/行情资料并补齐）、检索增强（回答关联广场帖子/历史问答，P1）；
     - **对话历史总结**：历史会话同步完善、历史对话摘要/总结生成。
  2. **移动端设计图**：为移动端出设计原型图，供王雪照照图优化。
- **设计图流程（Codex）**：
  1. 黄颖用 Codex 生成设计原型图，一般出 **3~4 张**供负责人挑选；
  2. 负责人确认没问题后，让 Codex 把选中原型图**转成 HTML 静态文件（使用 mock 数据）**；
  3. 负责人再把该 HTML 合并进业务代码。
  - 出图按 TDesign 组件风格、含交互/间距说明，确保可落地、王雪照能直接对得上。
- **设计图首批范围**（配合王雪照骨架/样板页节奏）：
  - **首批（8/31 前交付，配合骨架定稿）**：51 智能广场移动端核心页——广场首页/信息流、搜索页（顶部搜索 + "问 AI"切换）、发布页（AI 一键分析 → 二次确认）、个人中心/会员主页；
  - **第二批（9/4 前）**：消息/收藏/私聊等其余页面。
- 价值：她是团队唯一 AI 深度专家，AI 问答线最不浪费；设计图是她的真长板，也顺带解决移动端缺设计规范问题。
- 关注：她习惯"做完不核对"（删功能没删净、UI 调整改坏业务）——用夏康乐互测 + 我终验兜住。

### 4. 王雪照 —— 移动端重构（TDesign，三阶段）

### 5. 朱铮勋 —— AI 测价 + 智能采销预研

## 三、Agent 协同开发约法（明早开会讲）

> 内核：别让 Agent 靠记忆写代码，让它每次开工先读仓库里最新文件；改动分级授权——红区守门、绿区放手。

- **R1 开工起手式**：新任务前先 `svn update` + `git pull`；开工指令硬性要求 Agent 先读关联文件（接口/数据结构/服务/实现）再动手，并声明"上下文以仓库当前文件为准，禁用旧记忆里的接口参数"。
- **R2 小步快合**：功能分支活不过 1~2 天，每天下班并入主分支（裹进 30 分钟会）→ 人人每天基于最新代码开工，避免"旧上下文造出对不上新接口"的 bug。
- **R3 跨模块改动通知**：如 AI 问答消费广场用户行为 + 用户画像（推荐联动），跨模块依赖的改动前知会相关人、同步会说明，消灭"我改了你不知道"。
- **R4 分级授权**（改动处理三区）：
  - **绿区 · 当场改，不用问**：纯 UI 样式、文案、布局、视觉细节、mock 数据、性能微调；改完同步会说一句"我改了 XX"即可。
  - **黄区 · 拿不准就改，同步会提**：改了接口参数、组件行为、数据展示逻辑；改完同步会带"我改了 X，原因 Y"。
  - **红区 · 必须先上报，负责人拍板**：**数据库结构/迁移、涉及金额/交易/权限/安全、跨模块公共逻辑**；Codex 再强也不许当场动。
  - **机制**：所有当场改的 commit 信息写清楚（scope + 说明）；每天同步会扫 commit log 批量确认——红区一个不漏、绿区不卡效率。
- **落点**：把"能跑通 + 互测通过 = 完成"（DoD）做在每个功能完成当下，不攒到 9/10 前集中爆雷。

## 四、协作与验收链路

```
开发（夏康乐 / 黄颖 / 王雪照 / 朱铮勋 / 许晓雨 / 我）
        │ 交付
        ▼
交叉互测（边界明确、互不重叠）
        ├─ 黄颖 → 测 AI 相关（问答 / 测价 / 画像 AI 逻辑）
        ├─ 夏康乐 → 测用户交互（广场 / 配单 / VIP / 移动端）
        ├─ 简单 UI 问题 → 双方自行修复
        └─ 算法 / 数据库 / 业务逻辑 → 上报负责人商议后改
        │
        ▼
负责人统一终验 + 版本发布
```

- **DoD（完成定义，不可松）**：能跑通 + 互测通过 = 完成。
- **互测必须"各测各的、不重叠"**，防"你好我也好"互相放水；负责人终验是最后一道闸。
