# 08. 数据源改造与同步方案

> 最后更新：2026-08-16
> 状态：**第一阶段已完成并通过实际数据验证**（2026-08-16）

## 一、背景

AI金 配单功能（`AiStockPage.vue`、`daily-recommend.service.ts`）此前通过 `queryXiumaProductSearch` → proxy → `51bxg CustomerData.PostQueryData`（`UI_ID=1784553230838779`）→ 后端直查秀吗 `ZERP_ERP` 库实时取数。

**2026-08 该接口被彻底禁用**（前领导判定该 SQL 拖垮数据库：原 SQL 含 `OUTER APPLY` 对 `ERP_MEMBER_PAY_LEVEL` 全表扫描、跨库四段式访问、隐式类型转换等性能问题）。同时接口报错会自动发邮件告警，调接口极其敏感。

## 二、核心决策（2026-08-16 确认）

1. **AI金只展示，成交回秀吗**：AI金 不承载最终交易，配单卡片跳转秀吗商品详情页下单。因此**不存在双向状态同步问题**，只需单向数据新鲜度（日更即可，卡片标注同步时间）。
2. **数据通道改为"手动导出 + 定时导入"**：完全不再调用被禁的 `CustomerData` 接口。
3. **PRODUCT_ID 通过数据库只读映射获取**（见下文第五节）。

## 三、数据通道方案

```
┌─ 主通道：秀吗 ERP 后台导出 CSV（人工，每日一次）
│     用户登录 https://xiuma.com/erp/modules/erp/product_information/product_info.aspx
│     → 筛选上架时间=今天 → 点"下载结果" → 得到 当日新增货品 Excel/CSV
│     → 放入约定目录 / 上传到 AI金
│
├─ 定时任务：每天中午12点（AI金 本地逻辑，不调任何外部接口）
│     @Cron('0 12 * * *') 扫描导入目录新文件
│     → 解析写入 xiuma_product_snapshot 快照表（新增/更新）
│     → 状态对账：快照表中在秀吗已下架/售罄的货品标记失效
│
└─ 兜底：首次全量导入 + PRODUCT_ID 映射表
      ｜
      ├─ 全量货品：从 product_info 页面导出全量上架货品
      └─ PRODUCT_ID 映射：数据库只读 SELECT PRODUCT_CODE→PRODUCT_ID（见第五节）
```

### 4.2 联系方式来源

秀吗 ERP 的 `supplier_info.aspx` 页面（供应商信息管理）有独立 `download_result` 导出，列含 `SUPPLIER_ID / SUPPLIER_NAME / TELEPHONE / FAX`。按供应商名关联货品，补全 `telephone / supplier_id`。

### 4.3 会员联系方式用户表 `xiuma_member_contact`（2026-08-16 新增）

**定位**：秀吗会员/供应商联系方式的完整电话库，货品导入时**自动回填缺失电话**（主联系人优先）。

- 建表脚本：`server/database/sql/024-create-xiuma-member-contact.sql`
- 字段对齐 `member_contact.aspx`（CRM → 会员联系方式）导出：公司全称/联系人编号/名称/职位/固定电话/移动电话/主联系人/决策人/信息状态/备注/创建时间
- 数据来源两种：
  1. **种子数据**：旧 SQL 导出 `yonghu.csv`（ERP_MEMBER_INFO 会员表，无表头 6 列），已导入 26771 行（有电话的会员），`source='seed_yonghu'`
  2. **日常更新**：`member_contact.aspx` 页面"下载结果" → AI金「秀吗数据导入」→「会员联系方式」上传（中文表头解析）
- **自动回填**：货品导入（`import-product`）后自动查用户表补齐快照表缺失电话；回填规则：主联系人（`main_contact=true`）固定电话 → 主联系人移动 → 任一联系人固定电话 → 任一移动电话；**只补缺失，不覆盖已有**
- 导入接口：`POST /api/xiuma-sync/import-member-contacts`
- 数据层：`server/database/xiuma-member-contact.repository.ts`（`importContacts` / `getBackfillPhoneByMemberName` / `backfillSnapshotTelephone` / `stats`）

**注意事项**：
1. 秀吗**新增客户/新增电话**不会自动同步——需重新导出 member_contact 文件上传
2. 一条货源可能对应多个联系人（多行），回填只取主联系人；无主联系人取第一条有电话的
3. 快照表 2 家供应商（佛山市念天地金属科技有限公司/无锡梦想不锈钢有限公司，共 91 条货品）在 yonghu.csv 中无电话，需等 member_contact 真实数据补

## 五、PRODUCT_ID 获取（数据库只读映射）

导出文件**没有数字 PRODUCT_ID**（只有货品编码），但跳转秀吗详情页（`sell_fixed_price_detail_new.aspx?id=` 需 `CheckInt64`）和成交下架定位都需要它。

**方案：数据库只读 SELECT，建立 PRODUCT_CODE → PRODUCT_ID 映射**

```sql
SELECT P.PRODUCT_CODE, P.PRODUCT_ID
FROM [ZERP_ERP].[dbo].[ERP_PRODUCT_INFO] P (NOLOCK)
WHERE P.PRODUCT_TYPE = 0;
```

- 只读 SELECT，不写任何数据；`(NOLOCK)` 不加锁
- 导出为 CSV，导入时与货品快照按 `product_code` 关联补 `product_id`
- 执行时机：首次初始化 + 每日定时任务一并生成（不调接口）
