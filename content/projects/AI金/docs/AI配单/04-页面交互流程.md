# 页面交互流程

> 最后更新：2026-07-22
> 状态：已重写为 LLM 直通架构

## 一、页面与入口

| 项 | 值 |
| --- | --- |
| 页面文件 | `client/src/pages/AiStockPage.vue` |
| API 封装 | `client/src/api/ai.ts`（`parseEnquiryParams`、`scoreMatches`） |
| 搜索封装 | `client/src/api/proxy.ts`（`queryXiumaProductSearch`） |
| 价格指数 | `fetchCoilPriceIndex`（与搜索并行拉取） |

页面核心状态：
- `queryText`：自然语言输入框
- `parsedParams`：解析后的结构化参数
- `editForm`：可编辑的查询表单（材质/表面/厚度区间/宽度区间/城市/钢厂/重量/预算/品类）
- `productResults`：搜索返回的全部商品
- `rankedDisplay`：评分排序后的 Top 3 展示列表（含 `product` / `score` / `reason` / `dimensions`）
- `shopResults` / `priceResults`：配套的店铺与价格信息

## 二、完整交互流程

### 步骤 1：输入自然语言

用户在输入框输入一句采购需求，例如：

```
无锡 304 2B 1.2mm 50吨 预算14500
```

点击「分析」触发 `doAnalyze()`。

### 步骤 2：AI 解析（parse-enquiry-params）

`doAnalyze()` 调用 `parseEnquiryParams(queryText)`，发起 `POST /api/ai/parse-enquiry-params`：

```typescript
const result = await parseEnquiryParams(queryText.value.trim())
parsedParams.value = result
syncEditForm()   // 回填到 editForm
doSearch()       // 自动触发搜索
```

后端用 `qwen-turbo` 解析出 `material_code` / `surface_code` / `spec_code` / `thick_range` / `width_range` / `factory_name` / `city_name` / `quantity` / `budget` / `category_name`，找不到的字段为 `null`。

**解析失败兜底**：catch 后将 `parsedParams` 置为全 `null` 的空结构并 `syncEditForm()`，让用户手动填写表单继续。

### 步骤 3：表单确认 / 修改

`syncEditForm()` 把 `parsedParams` 回填到 `editForm`（材质、表面、厚度区间拆成 min/max、宽度区间拆成 min/max、城市下拉、钢厂下拉、重量区间、预算、品类多选）。

用户可在此校正 AI 解析结果（例如改城市、调预算、补厚度），然后触发搜索。当前实现中 `doAnalyze` 解析成功后会自动衔接 `doSearch()`，用户也可基于修改后的表单重新搜索。

### 步骤 4：搜索商品（queryXiumaProductSearch）

`doSearch()` 用 `buildRecommendProductParams(parsedParams)` 构造查询参数，并发起两个并行请求：

```typescript
const [productRes, priceRes] = await Promise.allSettled([
  queryXiumaProductSearch(queryParams),
  fetchCoilPriceIndex({ category: 'ALL' }),
])
```

- `queryXiumaProductSearch`：调用秀玛商品搜索 API，返回 `XiumaProductSearchData`。
- 商品原始项通过 `mapXiumaItemToRecommendItem` 映射为统一的 `RecommendProductItem`，存入 `productResults`。

> 注：秀玛数据中 `Factory` 字段当前映射为空字符串（数据源未提供厂家），`Supplier` 信息虽存在于原始数据但 **不会进入评分候选数组**。

### 步骤 5：构造候选并 AI 评分（score-matches）

当 `allProducts.length > 0` 时，构造评分候选数组（**仅包含商品本身字段，不含 Supplier**）：

```typescript
const candidates: ScoreMatchCandidate[] = allProducts.map(p => ({
  productId: p.ProductId,
  material: p.Material,
  surface: p.Surface,
  spec: p.SpecCode,
  thick: p.ReferenceThick,
  price: p.Price === 0 ? '面议' : p.Price,   // 价格为 0 视为面议
  weight: p.Weight,
  house: p.House,
  factory: p.Factory,
  city: p.CityName,
  auctionType: p.AuctionType,
}))

const scoreResult = await scoreMatches({
  query: queryText.value.trim(),
  parsed: parsedParams.value!,
  candidates,
})
```

后端 `POST /api/ai/score-matches` 用 `qwen-turbo` 选出 Top 3 + 4 维评分 + 推荐理由（详见 `02-LLM评分逻辑.md`）。

### 步骤 6：结果展示

将 `scoreResult.ranked` 与 `productResults` 通过 `productId` 关联，得到 `rankedDisplay`：

```typescript
const productMap = new Map(allProducts.map(p => [p.ProductId, p]))
rankedDisplay.value = scoreResult.ranked.map(r => ({
  product: productMap.get(r.productId)!,
  score: r.score,
  reason: r.reason,
  dimensions: r.dimensions,
})).filter(r => r.product)
```

展示内容包含三部分：

1. **总匹配度得分**：`score`（0-100）突出显示。
2. **雷达图**：基于 `dimensions`（materialMatch / priceAdvantage / locationMatch / stockLevel）用 ECharts radar 图渲染四维能力图。每个排名项通过 `setRadarRef(idx, el)` 收集 DOM 引用，在 `nextTick` 后统一初始化/更新实例（`radarInstances`）。
3. **推荐理由**：`reason`（50-80 字口语化采购建议）。
4. **得分明细**：四维拆解分数。

### 步骤 7：配套数据展示

除 Top 3 评分结果外，`doSearch` 还会：
- 按 `SupplierId` 聚合 `productResults`，取商品数最多的 Top 3 供应商，调用 `getShopInfo({ SUPPLIER_ID })` 拉取店铺信息存入 `shopResults`。
- `fetchCoilPriceIndex` 的结果存入 `priceResults`，作为价格行情参考。

## 三、异常与兜底

| 场景 | 行为 |
| --- | --- |
| AI 解析失败 | `parsedParams` 置空，回填空表单，用户手动填写后搜索 |
| 搜索无结果 | `productResults` 为空，不触发评分，`rankedDisplay` 为空，展示 empty-state |
| 评分接口失败（前端 catch） | 用搜索结果前 3 条构造零分结构（score=0、reason 空、四维全 0）填入 `rankedDisplay` |
| 评分 LLM 失败（后端 catch） | 后端返回前 3 条候选零分结构，`success: true`，前端正常展示商品但无评分理由 |

## 四、阶段六预告

当前候选数组不含 Supplier，因此店铺聚合与评分排序是两条独立链路。阶段六将把企业身份与曝光特权（`priorityRecommend`）注入评分候选，使 VIP 企业商品在 Top 3 排序中获得加权，雷达图四维体系保持不变。
