# 数据结构与接口

> 最后更新：2026-07-22
> 状态：已重写为 LLM 直通架构

> 类型定义集中位于 `client/src/api/proxy.types.ts`，接口实现位于 `server/modules/ai/ai.controller.ts`，前端封装位于 `client/src/api/ai.ts`。本文档已移除旧的 90 分制 `scores` 结构，统一为 4 维 100 分制。

## 一、接口清单

| 接口 | 方法 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- | --- |
| `/api/ai/parse-enquiry-params` | POST | `{ query }` | `ParseEnquiryParamsResult` | LLM 解析自然语言为结构化参数 |
| `/api/ai/score-matches` | POST | `{ query, parsed, candidates }` | `ScoreMatchResult` | LLM 评分排序 Top 3 |
| `/api/ai/stock-query` | POST | `{ query }` | `{ text }` | 通用文本查询（非核心流程） |

所有接口统一返回包装：`{ success: boolean, data?: T, error?: string }`。

## 二、parse-enquiry-params

### 请求

```json
{ "query": "无锡 304 2B 1.2mm 50吨 预算14500" }
```

### 响应 data：`ParseEnquiryParamsResult`

```typescript
interface ParseEnquiryParamsResult {
  material_code: string | null   // 材质代码，如 "304"、"316L"
  surface_code: string | null    // 表面代码，如 "2B"、"NO.1"
  spec_code: string | null       // 规格，如 "1.2*1219*C"（需同时有厚度+宽度才拼接）
  thick_range: number[] | null   // [最小厚度, 最大厚度]
  width_range: number[] | null   // [最小宽度, 最大宽度]
  factory_name: string | null    // 厂家名，如 "太钢"
  city_name: string | null       // 目标城市，如 "无锡"
  quantity: number | null        // 需求量（吨）
  budget: number | null          // 预算上限（元/吨）
  category_name: string[] | null // 品类，从 ["卷","板","管","带","型","管件"] 选取
}
```

找不到的字段一律为 `null`。`category_name` 后端可能返回字符串或数组，前端 `doAnalyze` 会归一化为数组。

## 三、score-matches

### 请求

```typescript
interface ScoreMatchRequest {
  query: string                       // 用户原始自然语言需求
  parsed: ParseEnquiryParamsResult    // 解析后的结构化参数
  candidates: ScoreMatchCandidate[]   // 候选商品数组（不含 Supplier）
}
```

#### `ScoreMatchCandidate`（候选商品，**不含 supplier 字段**）

```typescript
interface ScoreMatchCandidate {
  productId: number
  material: string
  surface: string
  spec: string
  thick: number
  price: number | '面议'    // 秀玛返回 0 时前端转成 '面议'
  weight: number
  house: string
  factory: string           // 字段保留，当前秀玛数据映射为空字符串
  city: string
  auctionType: string
}
```

> 重要：当前 `candidates` 数组 **没有 `supplier` 字段**，LLM 评分仅基于商品本身属性。这是阶段六要解决的问题——届时会补充企业身份与曝光特权字段。

请求示例：

```json
{
  "query": "无锡 304 2B 1.2mm 50吨 预算14500",
  "parsed": { "material_code": "304", "surface_code": "2B", "city_name": "无锡", "budget": 14500, "quantity": 50, "...": "..." },
  "candidates": [
    { "productId": 12345, "material": "304", "surface": "2B", "spec": "1.2*1219*C",
      "thick": 1.2, "price": 12800, "weight": 52, "house": "无锡XX库",
      "factory": "", "city": "无锡", "auctionType": "" }
  ]
}
```

### 响应 data：`ScoreMatchResult`

```typescript
interface ScoreMatchResult {
  ranked: ScoreMatchRankedItem[]
}

interface ScoreMatchRankedItem {
  productId: number
  score: number                  // 总匹配度 0-100
  reason: string                 // 50-80 字推荐理由
  dimensions: {
    materialMatch: number        // 材质/表面/规格匹配 0-100
    priceAdvantage: number       // 价格竞争力 0-100
    locationMatch: number        // 仓库距离匹配 0-100
    stockLevel: number           // 库存满足度 0-100
  }
}
```

`ranked` 长度 1-3，按 `score` 从高到低排序。

响应示例：

```json
{
  "success": true,
  "data": {
    "ranked": [
      {
        "productId": 12345,
        "score": 92,
        "reason": "304/2B 规格与需求完全一致……无锡本地库免去跨省运输，52 吨库存远超 50 吨需求，建议优先采购。",
        "dimensions": { "materialMatch": 95, "priceAdvantage": 90, "locationMatch": 100, "stockLevel": 85 }
      }
    ]
  }
}
```

### Fallback 响应（LLM 失败时）

后端 catch 仍返回 `success: true`，`ranked` 取 `candidates` 前 3 条，所有分数为 0、`reason` 为空：

```json
{
  "success": true,
  "data": {
    "ranked": [
      { "productId": 12345, "score": 0, "reason": "",
        "dimensions": { "materialMatch": 0, "priceAdvantage": 0, "locationMatch": 0, "stockLevel": 0 } }
    ]
  }
}
```

## 四、前端展示结构

前端将 `ranked` 与搜索结果通过 `productId` 关联，构造 `rankedDisplay`：

```typescript
interface RankedDisplayItem {
  product: RecommendProductItem   // 完整商品信息（含 Supplier 等，仅用于展示）
  score: number
  reason: string
  dimensions?: ScoreMatchRankedItem['dimensions']
}
```

> 注意区分：`ScoreMatchCandidate`（发给 LLM 的精简候选，无 supplier）与 `RecommendProductItem`（搜索返回的完整商品，含 Supplier/SupplierId，仅用于前端展示与店铺聚合）。两者通过 `productId` 关联。

## 五、已移除的旧结构

以下旧结构在 LLM 直通架构中 **已不存在**，本文档不再描述：

- 90 分制 `scores` 结构（旧的 `{ price, material, location, stock }` 90 分制）
- 规则引擎中间产物（匹配规则命中等）
- `ai-service.ts` / `match-engine.ts` 相关的内部数据类型

## 六、阶段六预告

阶段六将在 `ScoreMatchCandidate` 中补充企业字段（如 `supplierId` / `supplierName` / `priorityRecommend`），让 LLM 评分能感知企业曝光特权。`ScoreMatchRankedItem` 的 4 维 `dimensions` 结构保持不变，企业加权通过 `score` 总分或后处理排序体现。
