## 一、会议确认的规则（2026-08-17）

### 1.1 成交判定（已实现）
- 查看供应商联系方式 = 认定意向成交，系统按标准模板自动生成合同（模板洛哥后续提供）
- 买方两条路径二选一：直接付款 / 平台保交付（前期所有订单统一走保交付）
- 现状：查看即绑定+下架已实现（`view-bind`）；合同生成等模板到位后接结算系统

### 1.2 联系方式查看限制（⚠️ 与现有实现不同，需改造）
- **按钢种维度：单个钢种单日最多查看 2 次**，全用户统一（含免费用户）；换钢种分别计数
- 配单/搜索本身**不限制**，随时配随时查；仅"查看联系方式"这个动作受限
- **成交前供应商名称隐藏**（原话："企业名给他隐藏掉"）——⚠️ 当前详情卡展示供应商名，需确认是否打码（见待确认项）
- 问答模块涉及联系方式的询问统一引导到配单模块（需排查问答 prompt/知识库）
- 现状冲突：当前实现是"套餐 N 天 M 次（默认 3 天 1 次）、无钢种维度"，需改造

### 1.3 违约判定
- 查看即生成合同后：现货 24 小时 / 期货 48 小时内未付款 → 违约
- 违约确认机制：卖方确认未收款即记违约（卖方点"违约"按钮）
- 首次违约：豁免提醒（不处罚）；第二次起：扣信用分 + 查看联系方式需卖方同意
- 信用分：正常成交累计加分，违约扣减，影响后续平台权限

### 1.4 结算系统边界
- 结算系统（上传识别/入库/节点跳转等四环节已完成约 40-50%）**先公司内部试点，暂不接入 AI 金**
- 违约判定最终要与结算系统关联；接入前用简化判定过渡

### 1.5 其他
- 秀吗认证商家发布货源**必填收款账号**
- 3980/9980 套餐增加历史数据调用年限限制（口径待定）
- 当前最高优先级：敲定底层数据结构与信息流转 SOP（前端填字段 → AI 加工 → 多场景分发）

## 二、限次规则改造方案（第一步，小改）

**规则**：全用户统一，单钢种单日 ≤2 次；配单不限次。

**实现**（基于现有表，改动小）：
- `trade_contact_view_logs` 已有 product_id → 关联快照表取材质（钢种）
- 限次校验改为：`该用户 + 该材质 + 当日` 计数 ≥2 → 拦截，提示"今日该钢种查看次数已用完"
- 套餐配额机制（view_window_days/view_max_count）保留，与钢种限次**取严**叠加
- 成交前供应商名称是否打码：**待确认**（见待确认项 1）

**数据模型**：无需新表；限次查询在现有 view_logs 上加材质维度聚合即可。

## 三、违约判定 MVP（自动判定方案，工作量约 1-1.5 天）

**一期采用"自动判定 + 客服可纠错"**，不依赖卖方操作入口（卖方可能无 AI 金账号）：

| 项 | 方案 |
| --- | --- |
| 定时任务 | cron 每小时扫描：`payment_status='unpaid'` 且超过付款时限（现货 24h，期货字段预留）→ 标记 `timeout` |
| 字段 | trade_deal_records 增加 `payment_deadline`、`violation_count`（累计违约次数）、`first_warned`（首次豁免提醒标记） |
| 首次豁免 | 首次超时仅发提醒（站内提示），不计违约 |
| 二次违约 | violation_count ≥2 → 拦截查看联系方式，提示联系客服 |
| 纠错 | 客服/运营可手动重置（复用现有付款登记入口扩展） |
| 卖方确认版 | 需卖方操作入口，工作量翻倍且卖方未必有账号，**一期不做**；结算系统接入后再演进 |

## 四、买卖互动功能分期

### 一期：轻量意向交互（约 1-2 天）
- 查看联系方式后，双方建立"交易会话"上下文
- 三个结构化动作按钮：**同意 / 还价（填数字）/ 确认买卖意向**，不做自由文本
- 状态机：待响应 → 已报价 → 已同意 → 已确认（触发合同生成流程）
- 通知：动作触发时给对方发站内通知

### 二期：自由文本议价（约 3-4 天，可选）
- 表：议价会话表 + 消息表（2 张）
- 接口：建会话/发消息/历史/列表/未读数（5 个）+ SSE 实时推送（复用测价 SSE 经验）
- 前端：聊天气泡窗口 + 商品上下文卡 + 未读角标 + 会话列表入口
- ⚠️ **最大产品风险**：秀吗货源的卖家可能没有 AI 金账号，消息无人接收。
  缓解方案：查看联系方式时双向暴露（"你看了他，他也能知道你"），卖家侧用短信通知；
  该问题不解决，自由聊天价值有限——**建议一期先上轻量按钮验证需求，二期再评估**

### 工作量对比（回应"自由议价会话工作量大么"）

| 方案 | 工作量 | 说明 |
| --- | --- | --- |
| 轻量意向按钮（一期） | 1-2 天 | 3 个按钮 + 状态机 + 通知 |
| 自由文本聊天（二期） | 3-4 天 | 2 表 + 5 接口 + 聊天窗 + SSE +1 天、报价卡片 +0.5 天 |

## 五、落地顺序

1. **限次改造**：钢种维度每日 2 次（全用户统一）+ 问答模块联系方式排查 —— 小改
2. **违约判定 MVP**：自动超时判定 + 首次豁免 + 二次拦截 + 客服纠错
3. **轻量意向交互**：同意/还价/确认三按钮
4. **等外部输入**：标准合同模板、3980/9980 历史数据年限口径、展示配额算法细则（付费优先 + 活跃用户每日保 1-2 次曝光 + 正反馈通知）
5. **远期**：自由文本聊天（先验证一期需求再评估）、信用分体系、结算系统对接

## 六、确认结论（2026-08-18）

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 成交前供应商名称 | **直接不显示**（排名表/详情卡/移动卡片/对比区全部隐藏） |
| 2 | 每日 2 次为全用户统一 | ✅ |
| 3 | 违约判定 | 自动判定 + 客服 ERP 纠错（卖方确认版后置） |
| 4 | 一期互动 | 轻量三按钮（同意/还价/确认意向），自由聊天二期 |
| 5 | 标准合同模板 | 先做占位模板展示，正式模板到位后替换 |
| 6 | 3980/9980 历史数据年限 | 属于 AI 问答范畴，配单不涉及 |
| 7 | 展示配额算法 | 待上述功能上线后再讨论 |
