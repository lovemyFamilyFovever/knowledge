> 最后更新：2026-07-22

## 一、文件清单（实际存在）

AI 配单功能由以下文件构成，部署/移植时需整体携带：

### 前端

| 文件 | 说明 |
| --- | --- |
| `client/src/pages/AiStockPage.vue` | 配单页面（输入、解析表单、搜索、评分结果、雷达图） |
| `client/src/api/ai.ts` | `parseEnquiryParams`、`scoreMatches` 等 fetch 封装 |
| `client/src/api/proxy.ts` | `queryXiumaProductSearch`、`getShopInfo`、`fetchCoilPriceIndex` 等代理封装 |
| `client/src/api/proxy.types.ts` | `ParseEnquiryParamsResult`、`ScoreMatchCandidate`、`ScoreMatchResult` 等类型 |

### 后端

| 文件 | 说明 |
| --- | --- |
| `server/modules/ai/ai.controller.ts` | `AiController`（`@Controller('api/ai')`），含 `parseEnquiryParams`、`scoreMatches`、`stockQuery` |
| `server/modules/ai/bailian.service.ts` | `BailianService`，封装百炼调用；`FAST_MODEL = 'qwen-turbo'`；`askFastSync` 同步返回文本 |

> 已移除的旧文件引用：**不存在** `match-engine.ts`、`ai-service.ts` 等独立规则引擎或 AI 匹配服务文件；`client/src/ai-match/` 目录已不存在。如迁移来源残留这些文件，应删除以免混淆。

## 二、环境变量

| 变量 | 用途 | 必填 |
| --- | --- | --- |
| 百炼 API Key | `BailianService` 调用 qwen-turbo 的鉴权凭据 | 是 |

> 具体变量名以 `bailian.service.ts` 实际读取为准（百炼 SDK 通常通过 `DASHSCOPE_API_KEY` 或百炼应用配置注入）。部署前确认该 Key 已在运行环境注入，否则 `askFastSync` 会抛错并由 fallback 兜底（返回零分结果）。

## 三、依赖项

- **后端**：NestJS（`@nestjs/common` 等）、阿里云百炼 SDK
- **前端**：Vue 3、ECharts（雷达图渲染）、`@lark-apaas/client-toolkit`（飞书妙搭运行时）

移植前确认目标环境已安装上述依赖。

## 四、接口路由

所有 AI 配单接口挂在 `/api/ai` 下：

| 路由 | 方法 | 用途 |
| --- | --- | --- |
| `/api/ai/parse-enquiry-params` | POST | 自然语言 → 结构化参数 |
| `/api/ai/score-matches` | POST | 候选商品 → Top 3 评分排序 |
| `/api/ai/stock-query` | POST | 通用文本查询（非核心流程） |

前端通过 `getApiBase()` 从 `window.location.pathname` 解析 `/app/app_xxx` 前缀，拼接路由；并通过 `getCsrfToken()` 从 cookie 读取 `suda-csrf-token` 作为请求头。移植到非飞书妙搭环境时需替换这两处逻辑。

## 五、飞书妙搭移植注意事项

1. **网关超时**：飞书妙搭正式环境网关约 30s 超时。`score-matches` 为同步接口，单次 `qwen-turbo` 调用通常秒级返回，一般不会触发超时；若候选数量极大导致 prompt 过长，需控制 `candidates` 数组长度。
2. **CSRF Token**：前端所有 POST 请求需携带 `x-suda-csrf-token` 头，从 cookie `suda-csrf-token` 读取。移植时若目标环境无此机制，需移除该校验或替换为对应鉴权方案。
3. **API Base 前缀**：飞书妙搭下接口路径需带 `/app/app_xxx` 前缀，由 `getApiBase()` 动态解析。脱离妙搭环境需将该前缀置空或改为实际网关前缀。
4. **后端部署**：NestJS 服务需部署到能被妙搭网关转发的后端实例，确保 `/api/ai/*` 路由可达，且百炼 API Key 已注入后端运行环境。
5. **代理接口**：`queryXiumaProductSearch` 依赖秀玛代理服务，移植时需确认代理配置（`proxy.ts` 中的 source/controller）在目标环境可用。

## 六、校验清单

部署/移植完成后，按以下顺序验证：

- [ ] 后端 `/api/ai/test?action=bailian` 返回百炼连接成功
- [ ] 前端输入「无锡 304 2B 1.2mm 50吨 预算14500」，`parse-enquiry-params` 正确回填表单
- [ ] 搜索返回商品列表，`score-matches` 返回 1-3 条带评分与理由的结果
- [ ] 雷达图正确渲染四维分数
- [ ] 断开百炼 API Key 后，页面仍能展示搜索结果（fallback 零分结构），不白屏

## 七、阶段六预告

阶段六引入企业曝光特权（`priorityRecommend`）后，文件清单会新增/改动：
- 后端：`scoreMatches` 的 prompt 组装与候选注入逻辑（补充企业字段）
- 前端：`ScoreMatchCandidate` 类型补充企业字段，候选构造处同步补字段
- 数据源：需在企业/商品数据中提供 VIP 等级与曝光特权标记

部署时需同步更新企业权限相关配置，详见 `../VIP系统/` 中 AI 配单曝光特权相关文档。
