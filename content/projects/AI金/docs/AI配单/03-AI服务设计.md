# AI 服务设计

> 最后更新：2026-07-22
> 状态：已重写为 LLM 直通架构

## 一、服务层总览

AI 配单不设独立的 `ai-service.ts`，所有 LLM 能力直接由控制器 `AiController` 调用 `BailianService` 完成。`BailianService` 是对阿里云百炼 SDK 的薄封装。

| 组件 | 文件 | 角色 |
| --- | --- | --- |
| 控制器 | `server/modules/ai/ai.controller.ts` | 接收 HTTP 请求、组装 prompt、解析 LLM 返回的 JSON |
| AI 服务 | `server/modules/ai/bailian.service.ts` | 封装百炼调用；`askFastSync` 使用 `qwen-turbo` 同步返回文本 |

## 二、BailianService.askFastSync

配单流程的两个 LLM 接口都走 **快通道同步调用**：

```typescript
const result = await this.bailianService.askFastSync(prompt, [], 'session-tag');
// result: { text, sessionId, requestId, totalTokens }
```

- **模型**：`FAST_MODEL = 'qwen-turbo'`（定义于 `bailian.service.ts`）
- **入参**：`(prompt: string, history: [], sessionId: string)`
  - 配单场景不传对话历史，`history` 固定为空数组
  - `sessionId` 作为 topic 标签用于日志追踪，配单场景传入语义化标签
- **返回**：`{ text, sessionId, requestId, totalTokens }`，业务只用 `text`

### Session 标签约定

| 接口 | sessionId 标签 |
| --- | --- |
| parse-enquiry-params | `enquiry-parse` |
| score-matches | `score-matches` |
| parse-query | `parse-query` |

## 三、parse-enquiry-params 接口的 Prompt 设计

**接口**：`POST /api/ai/parse-enquiry-params`（控制器 197-232 行）
**入参**：`{ query: string }`
**职责**：从用户自然语言描述中提取结构化采购参数。

### Prompt 结构

```
你是一个不锈钢采购需求解析器。从用户描述中提取结构化参数，只返回JSON。

字段说明（找不到的设为null）：
- material_code: 材质代码，如"304"、"316L"、"2205"
- surface_code: 表面代码，如"2B"、"NO.1"、"BA"
- spec_code: 规格，如"1.2*1219*C"。只有用户明确提及厚度和宽度时才尝试拼接，否则填null
- thick_range: [最小厚度, 最大厚度]
- width_range: [最小宽度, 最大宽度]
- factory_name: 厂家名，如"太钢"、"张浦"
- city_name: 目标城市，如"无锡"、"佛山"
- quantity: 需求量（吨）
- budget: 预算价格上限（元/吨）
- category_name: 品类分类，从["卷","板","管","带","型","管件"]中选择

直接返回JSON，不要Markdown代码块。

用户描述：${body.query}
```

### 设计要点

1. **强约束 JSON 输出**：明确「只返回 JSON，不要 Markdown 代码块」，但仍用正则 `\{[\s\S]*\}` 兜底提取首个 JSON 对象，防止模型偶发包裹代码块。
2. **找不到即 null**：避免模型编造字段值，未提及的字段一律 `null`，由前端表单留空让用户补填。
3. **规格拼接克制**：`spec_code` 仅在用户明确提及厚度和宽度时才拼接（如「1.0mm 厚度 1220 宽度」→ `1.0*1220*C`），否则填 `null`，避免错误拼接污染搜索。
4. **品类枚举约束**：`category_name` 限定在 6 个固定品类中选取，保证后续搜索参数合法。

## 四、score-matches 接口的 Prompt 设计

**接口**：`POST /api/ai/score-matches`（控制器 234-301 行）
**入参**：`{ query, parsed, candidates }`
**职责**：从候选商品中选出 Top 3 并给出 4 维 100 分制评分 + 推荐理由。

### Prompt 结构（要点）

```
你是一个资深不锈钢采购顾问。根据以下用户需求和候选商品列表，
选出最匹配的 Top 3 并按匹配度从高到低排序。

用户原始需求：${body.query}
结构化参数：${parsedJson}
候选商品（JSON数组）：${candidatesJson}

评估要点：[材质/表面/规格匹配、价格预算、面议处理、仓库距离、库存、品牌、厚度±0.3mm公差]

推荐理由要求（50-80字）：[口语化、含规格/价格/距离/库存四要素]

四维评分（每个维度 0-100）：
- materialMatch / priceAdvantage / locationMatch / stockLevel

输出要求：
1. 只选真正匹配的（最少1条，最多3条）
2. 直接返回纯JSON，不要```json代码块
3. 格式：{"ranked":[{"productId":...,"score":...,"reason":...,"dimensions":{...}}]}
```

### 设计要点

1. **双上下文注入**：同时给 LLM 原始 `query`（保留自然语言语义）和 `parsed` 结构化参数（提供精确的预算/城市/数量阈值），让 LLM 既能理解意图又有量化基准。
2. **候选商品序列化**：`JSON.stringify(body.candidates, null, 2)` 带缩进序列化，便于 LLM 逐字段阅读。
3. **评估要点显式枚举**：把所有软性规则（公差、品牌、面议、距离）写进 prompt，作为 LLM 打分的约束清单。
4. **输出格式强约束**：要求纯 JSON、无代码块、字段固定，后端正则提取 + `JSON.parse` + `ranked` 数组校验三重保障。
5. **Fallback 兜底**：解析失败时返回前 3 条候选的零分结构（详见 `02-LLM评分逻辑.md`）。

## 五、其他相关接口

| 接口 | 方法 | 用途 | 调用 |
| --- | --- | --- | --- |
| `/api/ai/stock-query` | `askSync` | 配单通用文本查询（非核心配单流程） | `bailianService.askSync(body.query)` |
| `/api/ai/parse-query` | `askFastSync` | 快速文本解析 | `bailianService.askFastSync(query, [], 'parse-query')` |

> 核心配单流程仅依赖 `parse-enquiry-params` + `score-matches` 两个接口；`stock-query` 使用 `askSync`（非 fast 通道），为预留的通用查询入口。

## 六、阶段六预告

阶段六将在 `score-matches` 的 prompt 或后处理中引入企业曝光特权（`priorityRecommend`），对 VIP 企业商品做加权。届时 `BailianService` 调用方式不变，变化集中在 controller 的 prompt 组装与候选数据注入（补充 Supplier / 企业等级字段）。
