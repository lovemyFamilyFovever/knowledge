## 一、功能概述

用量统计是 AI金 个人中心的核心功能之一，展示用户在使用 AI 功能（问答、配单、测价、广场助手）时的 Token 消耗情况。支持日期范围筛选、趋势图查看、功能分类占比分析和详细明细查看。

**核心能力：**
- 4 个统计卡片：今日 Token 消耗、调用次数、AI 问答次数、AI 配单/测价次数
- 趋势图：支持按天/按周聚合、柱状图/折线图切换
- 功能分类占比环图：按 Token 消耗展示各功能占比
- 用量明细表：展示各功能的 Token 消耗和调用次数占比
- 日期范围筛选：近 7 天/30 天/90 天/本月/上月/自定义

**入口路由：**
- `/personal/token-stats` — 个人中心入口（标题：用量统计）
- `/ai/token-stats` — 主应用入口（标题：Token 统计）

两个路由加载同一个组件 `TokenStatsPage.vue`。

## 四、数据模型

### 4.1 数据库表 `ai_token_records`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键，自动生成 |
| `date_key` | DATE | 日期（北京时间 YYYY-MM-DD） |
| `member_code` | VARCHAR(100) | 用户 MEMBER_CODE |
| `category` | VARCHAR(50) | 功能分类（qa/forecast/matching/plaza-helper） |
| `call_count` | NUMERIC | 调用次数 |
| `total_tokens` | NUMERIC | 总 Token 消耗 |
| `input_tokens` | NUMERIC | 输入 Token |
| `output_tokens` | NUMERIC | 输出 Token |
| `cached_tokens` | NUMERIC | 缓存命中 Token |
| `cache_creation_tokens` | NUMERIC | 缓存创建 Token |
| `last_active_at` | TIMESTAMPTZ | 最近调用时间 |
| `created_at` | TIMESTAMPTZ | 创建时间 |
| `updated_at` | TIMESTAMPTZ | 更新时间 |

### 4.2 唯一约束

```sql
UNIQUE INDEX idx_ai_token_records_unique ON (date_key, member_code, category)
```

同一用户在同一天、同一分类只有一条记录，通过 `ON CONFLICT` 原子累加。

### 4.3 索引

| 索引名 | 字段 | 用途 |
|--------|------|------|
| `idx_ai_token_records_category` | `category` | 按分类查询 |
| `idx_ai_token_records_date_key` | `date_key` | 按日期查询 |
| `idx_ai_token_records_member_code` | `member_code` | 按用户查询 |

## 五、后端服务

### 5.1 TokenRecordService

文件位置：`server/modules/ai/token-record.service.ts`

#### 5.1.1 记录 Token 消耗

```typescript
async record(params: TokenRecordParams): Promise<void>
```

**参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `category` | `TokenCategory` | 功能分类 |
| `memberCode` | `string` | 用户 MEMBER_CODE |
| `model` | `string?` | 模型名称 |
| `totalTokens` | `number` | 总 Token |
| `inputTokens` | `number?` | 输入 Token |
| `outputTokens` | `number?` | 输出 Token |
| `cachedTokens` | `number?` | 缓存命中 Token |
| `cacheCreationTokens` | `number?` | 缓存创建 Token |

**核心逻辑：**
1. 获取北京时间当天日期
2. 调用 Repository 的 `upsertTokenRecord` 原子 upsert
3. 存在则累加，不存在则创建

```typescript
// Repository 层 SQL
INSERT INTO ai_token_records (...)
VALUES (...)
ON CONFLICT (date_key, member_code, category)
DO UPDATE SET
  call_count = call_count + 1,
  total_tokens = total_tokens + ${totalTokens},
  ...
```

#### 5.1.2 查询用户统计

```typescript
async getUserStats(memberCode: string, days?: number): Promise<TokenStatsSummary>
```

**返回结构：**

```typescript
interface TokenStatsSummary {
  today: {
    totalTokens: number
    callCount: number
    byCategory: Record<string, { totalTokens: number; callCount: number }>
  }
  daily: Array<{
    date: string
    totalTokens: number
    callCount: number
    byCategory: Record<string, { tokens: number; calls: number }>
  }>
}
```

**聚合逻辑：**
- 按 `date_key` + `category` 聚合
- 计算今日（北京时间）数据
- 按日期倒序排列，取最近 N 天

#### 5.1.3 查询所有用户统计（ERP 用）

```typescript
async getAllUsersStats(startDate?: string, endDate?: string)
```

**返回结构：**

```typescript
{
  summary: {
    totalTokens: number
    totalCalls: number
    activeUsers: number
    byCategory: Record<string, { totalTokens: number; callCount: number }>
  }
  byUser: Array<{
    memberCode: string
    totalTokens: number
    callCount: number
    qaTokens / qaCalls
    forecastTokens / forecastCalls
    matchingTokens / matchingCalls
    lastActiveAt?: string

  daily: Array<{...}>
}
```

## 十、已知限制

1. **数据延迟**：数据每小时更新一次，统计结果存在延迟
2. **历史数据**：只统计功能上线后的 Token 消耗，上线前的历史数据不回填
3. **存储限制**：依赖 PostgreSQL，清理数据库会丢失所有统计记录
4. **聚合粒度**：按天聚合，不支持按小时查看
5. **分类限制**：当前只展示 4 个分类（qa/forecast/matching/plaza-helper），新增分类需同步更新前后端
6. **日期范围**：单次查询最多 90 天，更长时间范围需分段查询
7. **ERP 后台**：ERP 用户明细列目前仅展示 qa/forecast/matching，缺少 plaza-helper 列
8. **性能**：数据量大时查询可能较慢，建议增加索引优化
