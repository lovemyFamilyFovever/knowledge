# 报价直填（采集工作台·报价模块）方案与业务流程确认

> 状态：**一期范围已冻结**（六个关键决策全部拍板），方案讨论收敛完成，进入开发前阶段。一期货款范围见 §8。

## 1. 背景与目标

- 采集工作台「报价」模块长期只有表单、无业务逻辑（前端调 `/api/collect/articles/quick-price`，后端为空端点，已记为已知限制 D5）。
- 复用老平台（51不锈钢 ERP）已成熟的「报价录入」，老板要求：**以后所有报价统一在新平台录入**。
- 功能分两步：
  1. **报价直填入库**：在基价基础上做增/减，保存到数据表。
  2. **自动转新闻**：把「部分钢种」价格自动转成含表格的新闻，发布到前台页面（**智能广场**）。

业务边界（用户已定）：
- 最终理想是迭代完直接转老平台，但数据联通不现实；**折中**：老平台照旧，新平台**再操作一遍**；新平台数据**自产自销**、存自己库、不干预老平台。
- 表名可参照老平台，前缀须一致；新平台操作**越简单越好**。

## 3. 老平台业务梳理（含老平台大模型 13 项查证结果）

### 3.0 补充说明
老平台 LLM 澄清了两点修正：
- 新闻主表实际是 **`ERP_CMS_ARTICLE_DATA`**（不是 BXG_ARTICLE_DATA）。
- 板卷规格表 `SheetCoilPriceSettingThink` **没有** IsShow 列。

### 3.1 Q1/Q2 — 规则（Setting）与基价/数据表语义
- **规则表不存价格**，是「维度组合定义」（市场×厂家×材质×表面×宽度×长度×含税×单位×交易状态×产品分类…）。`SheetCoilPriceSettingData` 关键字段：`SheetCoilSettingCode`(业务主键)、MarketCode/Name、FactoryCode/Name、MaterialCode/Name、SurfaceCode/Name、WidthCode/Name、LengthCode/Name、`IsTax`(0=不含税)、`PriceUnit`(0=元/吨)、`Remark`、`TransactionStatus`、`ProductSort`、`Status`(0=正常/-1=停用)、`AMLastTime/PMLastTime`(上午/下午最后录入时间)。
- **数据表只存最终价**。`SheetCoilPriceBaseData`：`SheetCoilSettingCode`、`ThinkCode/ThinkName`(厚度)、`IsAm`(0上午/1下午)、`PriceDate`、`Price`(最终价 元/吨)、`Status`、`Remark`。
- **基价 = 动态取昨日/上次同维度价**，只在录入界面当参考；系统算 `最终价 = 基价 + 增减`，**只存最终价**（基价与增减不留库）。另有疑似基准价表 `SheetCoilBasePriceData`（待 API 曾提示可 `SELECT TOP 3` 确认，本次未查）。
- 变动对新平台的含义见 §7 表结构草案与 §6-A。

### 3.2 Q3 — IsAm 与唯一键
- `IsAm`：0=上午价，1=下午价；同一天同规则允许上、下午各报一次。
- 老平台**无联合唯一约束**（仅 ID 主键）；重复录入叠加成多版本，防重靠前端 + `AMLastTime/PMLastTime`。
- → 新平台 `data_daily_price` **有** `uq_data_daily_price_biz` 唯一索引，需要用 upsert/覆盖语义接「当日可改」（见 §6-A3）。

### 3.3 Q4 — 录入交互（老平台推断，未截图确认）
一条一条录／一个钢种→所有厚度批量表格／逐行填价后一次提交。老平台交互以实际操作为准。

### 3.4 Q5 — 单位与含税
`PriceUnit`、`IsTax` 在**规则表固定**，录入时不需要每次选。→ 新平台可放体现在日期的维度里或作为单据级默认。

### 3.5 Q6 — 「出齐」判定（差异）
- **板卷**：只查「当天有报价」；「必须全部出齐」那段被**注释掉**（厚度太多难同天出齐）。
- **钢厂 / 管材**：要求该分组**所有规则当天都报价**才转新闻。

### 3.6 Q7 — AutoPublishNews 开关
| 表 | 粒度 |
|---|---|
| SheetCoilPriceSettingThink | 板卷·厚度级 |
| SteelMillPriceRule | 钢厂·规则级 |
| PipePriceSettingStantard | 管材·规格级 |
| StripPriceSetting | 带材·规则级 |

### 3.7 Q8 — 模板（StringTemplate）
- 语法：Antlr3.ST，变量 `<变量名>`，列表迭代 `<list:{item | <item.字段>}>`。
- 模板存 **CMS「新闻属性配置」**表（标题/内容/摘要），不在代码硬编码。
- 标题标量变量：`<PriceDate><MarketName><MaterialName><SurfaceName><ProductSortName><FactoryName><Variety><DeliveryName>`。
- 内容列表项变量：`<Price><RisePrice><AveragePrice><ThinkName><WidthName><LengthName><TransactionStatusName><FactoryName><MarketName><OutsideDiameterName><WallThicknessName>`。
- 示例标题：「【`<PriceDate>`】`<MarketName>``<MaterialName>`板卷基价指引」；内容为含 `<item.…>` 价格表格的 HTML。

### 3.8 Q9 — 涨跌与五日均价
- 涨跌额 = `今日价 - 昨日价`（金额差，非百分比）；任一价 = -1（**封盘**）显示「-」。
- 五日均价 = 近 5 天数据中 `Price != -1` 的平均；不足 5 天有多少算多少；全封盘显示「-」。

### 3.9 Q10 — 写库与 Redis 防重（`ERP_CMS_ARTICLE_DATA`）
- 默认：ARTICLE_STATUS=1(已审核)、ARTICLE_SHOW=1(已上架)、CREATE_BY='sys'、ARTICLE_HITSNUM=random(50,150)、ARTICLE_STATEMENT='1'；标签/打开方式/新闻去向来自 CMS 配置。
- Redis `PRICE_TO_NEWS`(Hash)：Field=规则编码（板卷用 SettingCode / 钢厂用 FactoryCode），生成后 HSet 防重。

### 3.10 Q11 — 「部分钢种才转」的多条件叠加
`AutoPublishNews=1` **+** `Status=0` **+** 「出齐」检查（钢厂/管材）**+** 时间窗（Cron 8:00-17:00 工作日）**+** Redis 防重。

### 3.11 Q12 — 全量表名录
- **BXG_**：价格指数（BXG_PRICE_INDICES_DATA/FACTORY/MARKET/SETTING）。
- **ERP_**：ERP_CMS_ARTICLE_DATA（新闻主表）+ ERP_CMS_*、ERP_MODEL_PRICE / ERP_PRICE_AWRULE / ERP_PRICE_STRUCT / ERP_TEMP_PRODUCT_PRICE。
- **无前缀（核心价格表）**：

| 板卷 | SheetCoilPriceSettingData | SheetCoilPriceBaseData | SheetCoilPriceSettingThink |

## 5. 方案评估

- **总体可行**，两步切分与新平台「采集存数 + 内容发布」架构吻合。
- **一期最简闭环建议（待用户确认，见 B1）**：直填→入库 `data_daily_price`，直接以维度组合为一"行"（等价于按钢种批量填一组规格价），**不预先建规则表**；基价显示昨日同维度价，只存最终价 + 涨跌额；配合「当日改/查询/导出」即为一期。
- 规则层（维度组合预设、AutoPublishNews、出齐判定、转智能广场）作为**二期**在转前台时引入。
- **关键矛盾点**：D5/D10「沿用 data_daily_price」×「7 类全做」×「查询导出」，三者需先定表结构方案（§6-A）。
- **开源复刻注意**：老平台 StringTemplate / Redis 防重 / Cron 定时，在新平台用 Node 侧定时任务 + 数据库 upsert 幂等替代，不必照搬 Redis。

## 6. 仍待确认的问题（阻塞点，按优先级）

### 6-A 表结构（已定调：沿用 data_daily_price，剩「维度列 + 唯一键」技术缺口）——需你/老板确认 2 点
用户已拍板 D13：**直接沿用现有 `data_daily_price`，不新建 7 组报价表**。据此收敛承载方向 =「A1-① 的精简版」：

- 在 `data_daily_price` 上做**最小扩展**：
  - 加 `price_type`（标识 7 类：sheet/steel/pipe/bar/strip/tube/futures）；
  - 加几个**可空**通用列承载老平台特有维度：`surface`(表面)、`width`(宽度)、`thickness`(厚度)、`variety`(品种/管材)、`delivery`(交货方式)；期货合约代码可先塞 `spec` 或留二期。
  - 现有可复用列：market、category、grade(材质)、brand_short_name(厂家)、spec、price、unit、tax_status、origin/region、mom_change(涨跌额)、data_source、ai_draft(jsonb)。
- 现状 `uq_data_daily_price_biz` 唯一键 =（price_date, category, grade, brand_short_name, origin, region, market, spec, tax_status, unit）。Postgres 里 **NULL 不入唯一键**，所以新加的 surface/width/thickness 默认 NULL 不会撞键，但也会导致**同维度多版本无法用唯一键覆盖当日价**。

- **A3（关键，需确认）「当日可改」的覆盖语义**：
  - 方案①（推荐）：把新维度列(含 price_type + 已扩展的 surface/width/thickness/…)纳入唯一键，写入时统一 `COALESCE(列,'')` 使其参与判重 → 同一天同维度再报 = **覆盖当日价**（契合 D8「录错当日改」）。
  - 方案②：不改唯一键，直填一律显式写空字符串而非 NULL 到原键列，靠应用层先查后更；实现绕，键仍覆盖不了「表面/厚度」维度，不推荐。
  - → 需确认采用方案①（改唯一键 + 覆盖语义）。
- **A2（需确认）期货是否随一期 7 类一起做**：数据维度特殊（合约代码+垂直价格），若坚持塞进复用表会把 schema 撑得很难看。建议**一期先做除期货外的 6 类，期货二期独立 `futures` 表**；但用户已定「7类全做」，故需与你/老板最终确认是否一期纳入（若纳入，建议单列一张期货表，复用主表仅存通用维度）。

### 6-B 自动转前台（二期）范围与顺序——我已给推荐，等你/老板确认
- **B1（我的推荐分期，回应你 D(c) 的讨论）**：
  **一期：报价直填闭环（入库＋当日改＋查询＋导出），先不上自动转前台。**
  **二期：自动转前台（智能广场）**，且建议把「文章提交自动发前台」与「报价自动转新闻」**在二期一起做，复用同一条广场发布链**。
  理由：①报价录入是老板硬性要求、独立闭环、不依赖广场即有价值；②自动发广场依赖 `plaza` 发布链路，与「文章提交自动发布」天然耦合，分开做会重复造轮子；③先直填落地最快见效，转前台等发布链成熟。
  与你倾向「先做价格的吧」一致 → 建议按此分期执行，需你/老板确认。
- **B2 触发与「出齐」**：板卷「只查有价」vs 钢厂/管材「全出齐」的差异，新平台照搬，还是简化统一（例如都按分组出齐）？（影响二期定时任务设计）
- **B3 转出门户复用**：新平台直接复用 `plaza` 发布（article 类型 + 含价格表格 HTML）？标题/内容模板用固定模板起步即可，还是需要可视化配置？
- **B4 涨跌/均价封盘**：新平台是否引入「封盘」概念（Price=-1）？涨跌=今日-昨日（存 `mom_change`）、五日均价=近5交易日非封盘均值，是否照搬？

### 10.1 老平台分组与出新闻规则（记忆核对，从老平台大模型 13 项查证结果整理）
- **分组方式**：老平台按「规则（Setting）」分组，一条规则 = 一组维度组合（**市场×厂家×材质×表面×宽度×长度×含税×单位×交易状态×产品分类**），用规则编码做业务主键（板卷 `SheetCoilSettingCode` / 钢厂 `FactoryCode`）。
- **生成粒度**：每条规则当天满足条件 → 生成一条新闻；`AutoPublishNews` 开关粒度：板卷·厚度级 / 钢厂·规则级 / 管材·规格级 / 带材·规则级。
- **出齐判定（差异）**：板卷只查「当天有报价」即转；钢厂/管材要求该分组**所有规则当天都报价**才转（§3.5 Q6）。
- **触发多条件叠加**：`AutoPublishNews=1` + `Status=0` + 出齐检查 + 时间窗（Cron **工作日 8:00-17:00**）+ Redis 防重（§3.10 Q11）。
- **防重**：Redis `PRICE_TO_NEWS`(Hash)，Field = 规则编码，生成后 HSet（§3.9 Q10）→ 新平台用「确定性 newsId + 数据库唯一键」替代。
- **模板（§3.7 Q8）**：存 CMS「新闻属性配置」表，不硬编码；标题标量变量 = 价格日期/市场/材质/表面/品种/厂家/交货；内容为含 `<item.*>` 价格表格的 HTML。
- **落库默认值（§3.9 Q10）**：已审核、已上架、CREATE_BY='sys'、阅读数随机 50-150、标签/新闻去向来自 CMS 配置。
- **涨跌与五日均价（§3.8 Q9）**：涨跌额 = 今日价-昨日价；任一价 = -1（**封盘**）显示「-」；五日均价 = 近 5 天 `Price != -1` 的均值，不足 5 天有多少算多少。

### 11.3 表样式修复（T7）
- **根因**：`PlazaService.sanitizeArticleContent` 会剥离富文本全部标签属性（含 class/inline style），且桌面端广场详情 `PlazaPostDetailPage.vue` 的 `.article-rich-content table` **仅有 margin、无单元格样式**，故价格表以浏览器默认状态渲染（无边框、无间距）→「挤在一起」。
- **修复**：桌面 `PlazaPostDetailPage.vue` 与移动 `MobilePlazaDetail.vue` 统一为**圆角卡片式网格表**（表头品牌底色+加粗+`nowrap`、单元格仅表头不换行、`nth-child(even)` 斑马纹、容器 `overflow-x:auto` 兜底横向滚动）。单元格去掉强制 `nowrap`，让 8 列表格在窄屏上随容器自适应、不再横向挤在一起；价格例（第 6 列「价格」）右对齐 + 加粗，突出价格可读性。样式作用于 `.article-rich-content :deep(table/th/td)` 可覆盖所有富文本表格，无需内联样式（属性会被 `sanitizeArticleContent` 清洗）。
