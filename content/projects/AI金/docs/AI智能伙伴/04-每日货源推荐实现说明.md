# AI智能伙伴每日货源推荐实现说明
> 最后更新：2026-08-26

## 一、接口与目标

页面通过 `GET /api/ai/daily-recommend` 获取每日推荐，后端从当前登录用户的引导资料读取主要钢种和地区，目标是返回最多 3 条可直接查看的真实货源。

返回项目包含：材质、表面、规格、厚度、价格、重量、仓库、厂家、供应商、城市、会员等级、匹配分、推荐理由、跳转地址和来源标记。

`source` 取值为：

- `xiuma`：秀吗 ERP 手动导入的本地货品快照。
- `demand`：智能广场中已审核、未过期的供应挂单。

## 二、候选查询与降级

候选查询只读取本地快照和本地广场供需表，不调用已禁用的 51bxg `CustomerData.PostQueryData`：

1. 先按“材质 + 城市”查询。
2. 候选不足时放宽为“材质”。
3. 仍不足时放宽为全部有效货源。
4. 广场供应挂单以兼容字段并入候选池，与秀吗货源一起参与排序。

候选池最多取前 20 条交给模型评分。模型根据材质、价格、目标城市、库存、厂家和供应商等级等因素筛选最多 3 条，并为每条生成推荐理由。

## 三、异常兜底

模型调用失败、返回 JSON 不合法或返回不存在的货品 ID 时，服务端按候选原顺序返回最多 3 条真实货源，并生成通用推荐理由。没有候选时返回空数组，前端显示“暂无合适的推荐货源”和完善采购偏好的入口。

## 四、缓存策略

后端按用户、主要钢种和地区在当天缓存结果；用户偏好变化会形成新的缓存键。前端 `useDailyRecommend` 使用版本化的 `localStorage` 缓存：

```text
plaza_recommend_v3_{MEMBER_CODE}_{YYYY-MM-DD}
```

空结果不写入长期缓存，以便库存或会话短暂异常恢复；非当天缓存会在加载时清理。同一页面的顶部数量和右侧推荐卡片共享同一份响应式数据。

## 五、跳转与来源

- `xiuma` 货源跳转至秀吗商品详情页，并在新窗口打开。
- `demand` 货源跳转至 `/promo/plaza/demand/:id`，在 AI 金内打开详情。
- 推荐卡片展示“广场供应”标识，避免用户误以为所有项目都来自秀吗。
