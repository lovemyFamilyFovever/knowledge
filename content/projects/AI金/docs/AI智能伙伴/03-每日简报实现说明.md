# AI智能伙伴每日简报实现说明
> 最后更新：2026-09-03

## 一、接口与返回结构

页面通过 `GET /api/ai/daily` 获取当日简报。接口要求登录，后端从请求头的 `x-user-id` 取得当前 `MEMBER_CODE`；未登录时返回失败，不生成匿名日报。

成功数据结构如下：

```ts
interface AiDailyData {
  date: string
  headline: string
  summary: string
  priceInsights: string[]
  news: string[]
  chart: {
    title: string
    dates: string[]
    series: Array<{ name: string; data: Array<number | null> }>
  }
  strategies: Array<{ title: string; content: string }>
  strategyFocus?: 'purchase' | 'sales'
}
```

## 二、生成流程

后端 `AiDailyService.generateReport()` 会合并用户引导资料与 `user_profiles` 中达到消费阈值的 V2 行为画像，解析唯一业务方向为采购或销售，并将首选钢种、市场、主题、业务意图、行为摘要和报告生成提示交给百炼日报应用；模型结合其可查询的行情数据生成结构化 JSON。日报调用显式关闭联网搜索，市场资讯只允许查询内部表 `erp_cms_article_data`，禁止访问 51bxg 网站或接口。服务端随后进行字段规范化：

- 日报、周报、月报均按无状态任务调用百炼，每次生成使用新会话，避免历史数据库故障上下文污染重新生成；首次未取得有效行情时自动以新会话重试一次。

- 价格要点和资讯统一转换为字符串数组；模型返回对象时转换为可展示文本。
- 资讯只保留标题和摘要；服务端兜底清除 51bxg 来源标签、域名及原始 URL，内部表没有有效资讯时返回空数组。
- 图表缺失或结构不完整时使用空图表结构，避免前端渲染异常。
- 日报只保留与 `strategyFocus` 相符的方向，并由服务端补足到固定 3 条；周报和月报不输出策略。
- 模型输出异常、内容异常或调用失败时，返回静态临时日报和方向匹配的策略，不再依赖额外外部行情兜底。

## 三、缓存策略

服务端使用内存缓存：日报按 `MEMBER_CODE:任务类型` 保存，并额外校验基础资料与 V2 行为画像签名；画像变化后当前日报重新生成。周报、月报仅按 `MEMBER_CODE:任务类型` 和 `reportKey` 复用同一自然周期的首份结果，周期内画像变化不会触发重新生成；进程重启后缓存清空。

浏览器端 `useAiDaily` 使用 `localStorage` 缓存当日结果：

```text
plaza_ai_daily_v9_{MEMBER_CODE}_{YYYY-MM-DD}
plaza_ai_period_report_v2_{MEMBER_CODE}_{weekly|monthly}
```

页面会删除不是当天的旧日报缓存，并按 `reportKey` 验证周报、月报是否属于当前周期。登录、注册、飞书登录或恢复有效登录态后，如果用户已完成画像且当前周期报告尚未缓存，前端会在不阻塞登录的情况下依次静默预热周报和月报。后台预热与报告弹窗共享同一个进行中请求，避免用户点击时重复调用百炼。缓存版本变更时应同步升级对应前缀。

## 四、前端展示

- `PlazaAiPushRail` 负责卡片标题、日期、加载骨架、错误重试和 `AiDailyContent` 容器。
- `AiDailyContent` 负责标题、摘要、价格要点、资讯与图表的具体展示。
- `PlazaStrategyCard` 根据 `strategyFocus` 显示“采购策略”或“销售策略”，每条策略可独立展开。
- 页面顶部的“资讯推送”和“采购策略”数量分别取 `news.length` 与 `strategies.length`。
