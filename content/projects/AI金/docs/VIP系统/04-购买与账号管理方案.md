## 二、完整业务流程

### 2.1 阶段 A：免费用户状态

```
4 个免费用户首次登录
  → 51bxg API 验证账号密码
  → VipService.ensureUser：检查用户表是否存在
    → 不存在 → createUser（创建记录，注册来源=51bxg登录，账号状态=active）
    → 已存在 → 更新最后登录时间
  → 查询成员关系表 → 无记录 → 返回免费用户权限
  → 前端：可以查看套餐对比页，但无购买记录、无子账号管理入口
```

### 2.2 阶段 B：购买流程

```
18066085130 购买 3980 入门版套餐
  → 套餐对比页 → 点击「立即购买」（入门版 3980 元/年）
  → 购买确认弹窗：
    ├─ 套餐名称：入门版
    ├─ 年费：¥3,980
    ├─ 能力清单：7 项能力
    ├─ 共享账号数：3 个
    ├─ 支付方式：微信支付 / 支付宝 / 银行转账
    └─ 确认按钮 → 创建订单
  → 支付页面（独立页面）：
    ├─ 微信/支付宝：展示二维码
    └─ 银行转账：展示转账信息
  → 支付完成 → 回调/轮询
  → 支付成功页：
    ├─ 套餐已激活
    ├─ 到期时间：购买日期 + 365 天
    └─ 按钮：「管理我的套餐」→ 跳转到我的套餐页
  → 后端：
    ├─ 创建购买记录（状态=active）
    ├─ 创建成员关系（用户=18066085130，角色=owner，状态=active）
    └─ 清除 getUserPermission 缓存
```

### 2.3 阶段 C：分配子账号

```
18066085130（主账号）进入「我的套餐」→ 「子账号管理」Tab
  → 看到：已用 1 / 共 3 个共享名额（主账号自身占 1 个名额）
  → 点击「添加子账号」
  → 添加子账号弹窗：
    ├─ 输入手机号：17573893738
    ├─ 查询用户表 → 用户存在
    ├─ 查询成员关系表 → 该用户未关联任何套餐
    └─ 确认添加
  → 后端：
    ├─ 创建成员关系（用户=17573893738，购买记录=该套餐，角色=member，状态=active）
    └─ 清除子账号的 getUserPermission 缓存
  → 名额用完后，「添加子账号」按钮置灰，提示"共享名额已用完"
```

### 2.4 阶段 D：使用阶段

```
子账号 17573893738 登录
  → 51bxg API 验证账号密码
  → VipService.ensureUser（已存在，更新最后登录时间）
  → getUserPermission：
    ├─ 查询成员关系表 → 找到记录（角色=member，状态=active）
    ├─ 查询购买记录 → 状态=active → 套餐=入门版
    └─ 返回入门版权限（pageAccess + features）
  → 前端：享有入门版全部权限
  → 我的套餐页：
    ├─ 显示：当前套餐=入门版（由主账号共享）
    ├─ 显示：主账号=18066085130
    └─ 不显示：子账号管理 Tab（仅主账号可见）
```

## 四、弹窗设计

### 4.1 PurchaseModal — 购买确认弹窗

**触发**：套餐对比页点击「立即购买」

**内容**：
- 套餐名称 + 年费
- 能力清单摘要（简要列出 7 项能力）
- 共享账号数
- 支付方式选择：支付宝 / 微信支付 / 银行卡（Radio 组）
- 实付金额：¥3,980.00
- **协议确认**：☐ 我已阅读并同意《商用授权协议》（必选，未勾选时「确认购买」按钮置灰）
  - 点击协议名称 → 在新标签页打开 `/vip/agreement`
- 按钮：「确认购买」+ 「取消」
- 确认后 → 创建订单 → 跳转到 PaymentPage

### 4.2 AgreementPage — 商用授权协议单页

**路由**：`/vip/agreement`

**内容**：
- 页面标题：商用授权协议
- 协议正文（静态 Markdown 渲染，内容可配置）
- 底部：版本号 + 生效日期
- 返回按钮：← 返回

**设计要点**：
- 独立页面，新标签页打开（从 PurchaseModal 的协议链接跳转）
- 纯展示内容，无交互表单
- 协议内容可以放在 `client/src/data/agreement.md` 或直接硬编码

**触发**：子账号管理 Tab 点击「添加子账号」

- 搜索结果：显示用户信息（显示名称、企业名称）
- 确认按钮：「添加为子账号」
- 错误提示：
  - "该用户已是其他套餐的子账号"
  - "该用户已是本套餐的子账号"

## 七、支付流程技术设计

### 7.1 整体架构

```
用户点击「立即购买」
  → 前端 PurchaseModal 弹窗
  → 用户选择支付方式 + 勾选协议
  → 调用 POST /api/vip/purchase
    → 后端创建订单
    → 写入飞书「购买记录表」（状态：pending）
    → 根据支付方式调用对应支付网关
      → 支付宝：生成支付页面 URL
      → 微信：生成 Native 支付二维码链接
    → 返回 orderId + 支付参数
  → 前端跳转 PaymentPage
    → 展示二维码 / 支付链接
    → 15 分钟倒计时
  → 用户扫码支付
  → 支付网关异步通知后端
    → 后端验证签名
    → 更新飞书「购买记录表」状态为 active
    → 写入飞书「成员关系表」（主账号关联）
    → 清除用户权限缓存
  → 前端轮询获取支付结果
  → 跳转 PaymentResultPage
```

### 7.2 模块划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 购买控制器 | `server/modules/vip/vip.controller.ts` | 新增 POST /api/vip/purchase |
| 购买服务 | `server/modules/vip/vip.service.ts` | 新增 createOrder / handlePaymentCallback |
| 支付宝服务 | `server/modules/payment/alipay.service.ts` | 支付宝沙箱对接 |
| 微信支付服务 | `server/modules/payment/wechat-pay.service.ts` | 微信支付沙箱对接 |
| 支付控制器 | `server/modules/payment/payment.controller.ts` | 支付回调接口 |
| 支付模块 | `server/modules/payment/payment.module.ts` | 模块组装 |

### 7.3 核心接口

#### POST /api/vip/purchase — 创建购买订单

**请求体**：

```typescript
{
  packageId: string        // 套餐 ID（飞书套餐表 record_id）
  paymentMethod: 'alipay' | 'wechat' | 'bank_card'
  agreementAccepted: boolean  // 协议是否已勾选（后端二次校验，必须为 true）
}
```

**响应**：

```typescript
{
  success: boolean
  data: {
    orderId: string          // 订单号，如 VIP20260726143025001
    packageName: string      // 套餐名称
    amount: number           // 金额（分）
    paymentMethod: string    // 支付方式
    paymentUrl?: string      // 支付宝：支付页面 URL
    qrCodeUrl?: string       // 微信：二维码链接
    expireTime: number       // 订单过期时间戳（15 分钟后）
  }
  error?: string
}
```

**后端处理流程**：
1. 校验 `agreementAccepted === true`
2. 查询当前用户是否已有有效套餐（active 状态的购买记录），如有则返回错误
3. 从飞书套餐表获取套餐信息（名称、年费、等级）
4. 生成订单号：`VIP` + yyyyMMddHHmmss + 3位随机数
5. 写入飞书「购买记录表」（状态：pending，过期时间：创建时间 + 15 分钟）
6. 根据支付方式调用对应支付网关
7. 返回订单信息 + 支付参数

#### GET /api/vip/payment/status/:orderId — 查询支付状态

**用途**：前端轮询支付结果

**响应**：

```typescript
{
  success: boolean
  data: {
    status: 'pending' | 'paid' | 'cancelled' | 'failed'
    packageName?: string
    expiryDate?: string
  }
}
```

#### POST /api/payment/callback/alipay — 支付宝异步通知

**处理流程**：
1. 验证签名（使用支付宝公钥）
2. 校验订单号、金额是否匹配
3. 更新飞书购买记录状态为 active
4. 写入成员关系表（用户 ↔ 购买记录，role=owner）
5. 清除用户权限缓存
6. 返回 `success` 给支付宝

#### POST /api/payment/callback/wechat — 微信支付异步通知

**处理流程**：
1. 验证签名（使用微信 APIv3 平台证书）
2. 解密回调数据
3. 校验订单号、金额是否匹配
4. 更新飞书购买记录状态为 active
5. 写入成员关系表
6. 清除用户权限缓存
7. 返回 `{"code": "SUCCESS"}` 给微信

### 7.4 订单超时处理

**方案：惰性过期 + 定时任务**

- **惰性过期**：在查询订单状态时检查是否超时
  - GET /api/vip/payment/status/:orderId 时，如果 pending 且超过过期时间，更新状态为 cancelled
- **定时任务**：每 5 分钟扫描一次
  - 查询飞书购买记录表中 status=pending 且过期时间 < 当前时间的记录
  - 批量更新状态为 cancelled
  - 对于支付宝/微信，调用关单接口（可选）

```typescript
// server/modules/vip/vip.service.ts
@Cron('*/5 * * * *')  // 每 5 分钟
async handleOrderTimeout() {
  // 查询 pending 且过期的订单
  // 更新状态为 cancelled
}
```

## 九、UI 决策汇总

| 决策点 | 建议 | 理由 |
|--------|------|------|
| 购买确认 | 弹窗（PurchaseModal） | 信息量适中，保持用户在套餐对比页的上下文 |
| 支付页面 | 独立页面 | 支付流程复杂（三选一支付方式+积分+发票），需要独立 URL |

| 我的套餐 | 多 Tab 重构（4 个 Tab） | 权限、子账号、购买记录、更多功能高度相关，合并减少导航 |
| 订单详情 | 弹窗（OrderDetailModal） | 信息量小，弹窗即可 |
| 添加子账号 | 弹窗（AddMemberModal） | 操作简单，弹窗 + 搜索交互流畅 |
| 账号编辑 | 弹窗（EditProfileModal），从 Header 进入 | 快速编辑，Header 下拉菜单「账号设置」入口 |
| 购买记录 | 合并到我的套餐 Tab 3 | 与套餐信息高度相关 |
| 子账号管理 | 合并到我的套餐 Tab 2 | 与套餐信息高度相关 |
| 权限查看 | 合并到我的套餐 Tab 1 | 默认展示，用户最常看 |
| 发票/升级/续费/积分 | 合并到我的套餐 Tab 4 | 搭架子，未来功能入口集中管理 |
| 协议确认 | PurchaseModal 内 checkbox + 独立页面 | 必选，未勾选时按钮置灰；点击协议名在新标签页打开 |
