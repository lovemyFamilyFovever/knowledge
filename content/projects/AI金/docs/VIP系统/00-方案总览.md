# VIP权限方案 — 总览

> 最后更新：2026-07-27

## 一、背景

系统为不锈钢行业用户提供多档年费制 VIP 套餐（8档：免费/试用/入门版/进阶版/专业版/企业版/旗舰版/尊享定制版），通过双层权限模型控制页面访问和功能特性。VIP 数据存储在飞书多维表格中，前端通过 `vip store` 管理权限状态。

## 二、方案架构

### 双层权限模型

| 类型 | 控制方式 | 示例 |
|------|----------|------|
| 页面访问 | 按套餐等级控制路由 | `pageAccess['/ai/qa']` |
| 功能特性 | 按 featureKey 控制页面内行为 | `hasFeature('ai_stock_priority_recommend')` |
| 业务曝光特权 | 在 AI 配单/问答结果排序中加权 | `priorityRecommend` 字段 |

详见 `01-多账号共享VIP套餐方案.md`。

**阶段五设计决策**：

- **套餐对比页定位**：工具型纯展示（已登录用户），与 style-mint 营销落地页（未登录访客）区分；去掉购买按钮，改为 12 能力×8 套餐的对比矩阵表

- **不创建 LockGate 组件**：不需要锁定覆盖层组件

## 七、历史变更

### 2026-07：删除 ERP VIP 页面权限管理

**背景**：旧版 VIP 权限体系通过飞书 Bitable 存储 8 级（L0–L7）页面权限矩阵，前台 `useVipStore` 在登录时拉取配置并控制路由拦截和菜单显隐。后因新版多账号共享 VIP 套餐方案上线，旧权限体系被取代。

**删除范围**（8 个文件 + 1 目录）：
- `erp/vip-permission/index.vue` — ERP 后台管理页
- `erp/vip-permission/vipService.ts` — ERP 后台 API 客户端
- `erp/server/erp-vip.controller.ts` — NestJS Controller
- `erp/server/erp-vip.service.ts` — NestJS Service
- `client/src/api/vip.ts` — 前台 API 客户端
- `client/src/stores/vip.ts` — 前台 Pinia store
- `client/src/pages/VipRequiredPage.vue` — VIP 权限提示页
- `erp/server/erp.module.ts` — 移除注册（修改）

**间接修改**（4 个文件）：
- `erp/ErpLayout.vue` — 侧边栏移除「VIP页面权限」菜单项
- `client/src/router/index.ts` — 移除路由守卫中的 VIP 拦截逻辑
- `client/src/stores/auth.ts` — 移除登录/登出中的 VIP store 调用
- `client/src/components/AppSidebar.vue` — 移除 Lock 图标和 VIP 可见性检查

### 2026-07：阶段五 — 套餐对比页定位变更

**背景**：初始阶段五方案将 VipPackagesPage 设计为卡片式套餐展示页（含购买按钮）。后因与 style-mint 营销落地页功能重叠，重新定位为纯工具型对比矩阵。

**关键决策**：
- 与 style-mint 营销定位区分（工具型 vs 营销型）
- 购买不在主项目做，去掉无意义的购买按钮
- 数据从后端 API 动态拉取，与飞书表格保持一致
- 当前套餐列高亮（背景色 + "当前"徽章）
