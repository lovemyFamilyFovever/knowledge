## 一、后端接口设计

所有接口路径前缀为 `/api/vip`，身份识别通过 `x-login-name` header。

### 通用返回格式

```typescript
{ success: boolean; code: number; message: string; data: T | null }
```

### 1.1 子账号管理（4 个接口）

飞书操作对象：`VIP成员关系表`（BITABLE_VIP_MAPPING_TABLE_ID）

#### POST /api/vip/members — 添加子账号

```
请求: { loginName: string }
响应: { member: { recordId, loginName, role, status, joinedAt } }
校验:
  1. 操作者 x-login-name 必须是某个 active 订单的 owner
  2. 被添加用户必须存在
  3. 被添加用户不能已是同一订单的成员
  4. 成员数不能超过 maxAccounts
写入: 成员关系表新增一条（登录名=被添加者, 主账号登录名=owner, 角色=member, 状态=active）
副作用: 清除被添加者的权限缓存
```

#### DELETE /api/vip/members/:memberId — 移除子账号

```
校验: 操作者必须是该成员所在订单的 owner
操作: 更新成员关系记录状态为 inactive
副作用: 清除被移除者的权限缓存
```

#### PUT /api/vip/members/:memberId/toggle — 启用/停用子账号

```
请求: { status: 'active' | 'inactive' }
校验: 操作者必须是 owner
操作: 更新状态字段
副作用: 清除被操作者的权限缓存
```

#### GET /api/vip/members — 获取子账号列表

```
响应: { members: MemberItem[], quota: QuotaInfo }
权限: 仅主账号（owner）可见
```

### 1.2 购买记录（2 个接口）

飞书操作对象：`VIP购买记录表`（BITABLE_VIP_PURCHASES_TABLE_ID）

#### GET /api/vip/purchases — 获取购买记录列表

```
响应: PurchaseItem[]
数据来源: 通过成员关系表找到当前用户的所有订单编号 → 查购买记录表
```

#### GET /api/vip/purchases/:purchaseId — 订单详情

```
参数: purchaseId 为订单编号
响应: 单条购买记录完整信息
```

### 1.3 账号信息（1 个接口）

飞书操作对象：`VIP用户表`（BITABLE_VIP_USERS_TABLE_ID）

#### PUT /api/vip/profile — 更新账号信息

```
请求: { nickname?: string; displayName?: string; enterpriseName?: string; email?: string }
操作: 更新用户表可编辑字段
```

### 1.4 共享名额（1 个接口）

#### GET /api/vip/quota — 获取共享名额使用情况

```
响应: { maxAccounts: number; used: number; remaining: number }
数据来源: 通过成员关系表找到当前用户的有效订单 → 查套餐的 maxAccounts → 统计 active 成员数
```

### 1.5 支付状态与回调（3 个接口）

#### GET /api/vip/payment/status/:orderId — 查询支付状态

```
用途: 前端轮询支付结果
响应: { status: 'pending' | 'paid' | 'cancelled' | 'failed', packageName?, expiryDate? }
惰性过期: 查询时如果 pending 且超过过期时间 → 自动更新为 cancelled
```

#### POST /api/payment/callback/alipay — 支付宝异步通知

```
处理流程:
  1. 验证签名（使用支付宝公钥）
  2. 校验订单号、金额是否匹配
  3. 更新飞书购买记录状态为 active
  4. 写入成员关系表（用户 ↔ 购买记录，role=owner）
  5. 清除用户权限缓存
  6. 返回 success 给支付宝
```

#### POST /api/payment/callback/wechat — 微信支付异步通知

```
处理流程:
  1. 验证签名（使用微信 APIv3 平台证书）
  2. 解密回调数据
  3. 校验订单号、金额是否匹配
  4. 更新飞书购买记录状态为 active
  5. 写入成员关系表
  6. 清除用户权限缓存
  7. 返回 {"code": "SUCCESS"} 给微信
```

### 1.6 订单超时处理

**方案：惰性过期 + 定时任务**

- **惰性过期**：GET /api/vip/payment/status/:orderId 时检查超时
- **定时任务**：每 5 分钟扫描 pending 且过期时间 < 当前时间的订单，批量更新为 cancelled

```typescript
// server/modules/vip/vip.service.ts
@Cron('*/5 * * * *')
async handleOrderTimeout() {
  // 查询 pending 且过期的订单 → 更新状态为 cancelled
}
```
