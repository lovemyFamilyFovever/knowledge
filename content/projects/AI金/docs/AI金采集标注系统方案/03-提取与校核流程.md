# 03 — 提取与校核流程

> 目的：定义一篇文章（或一条手工报价）从上传到入库的完整流程。核心原则：**AI 预填、人工只审标红、一键全过、批量处理**。本版按"工作台信息架构"组织——不是重后台表单，而是业务人员 5 分钟完成一篇的工作流。
> **V1.2 修订**（按外部复审意见 + 老板业务决策）：补充字段级审核状态（field_reviewed）、跳过/放弃语义、failed→手动填表→confirmed 状态链、INFERENCE 硬规则、路由阈值可配置、按模板配置的核心字段缺失规则、复制上次约束、批量校核约束。

---

## 一、工作台信息架构（三页）

**所有操作不出三页，任何页面不做多级菜单、不做复杂筛选。**

```
工作台首页（默认页）
  ├─ 待处理队列卡片：今日待处理 N 篇 / 类型分布 / 已过期
  └─ 快捷入口：提交文章 / 数据快填
        ↓ 点击待处理项
处理页（核心，占 90% 使用时间）
  ├─ 左侧：文章原文（可滚动，AI 抽取时高亮引用位置）
  ├─ 右侧：结构化表单（AI 已填，低置信度标红，黄标核心字段）
  └─ 底部操作条：一键全过 / 提交 / 存草稿 / 跳过 / 放弃
        ↓ 提交后
我的记录页
  └─ 已完成列表：每篇展开看生成了哪些记录（追溯入口）
```

### 1.1 工作台首页

| 元素 | 说明 |
|---|---|
| 待处理队列卡片 | 待校核 N 篇（含抽取失败重试、已跳过未处理项）、今日新增、按类型分布 |
| 快捷入口 | 提交文章（粘贴/上传/自写）、数据快填 |
| 批量入口 | 多选待处理项 → 连续逐条快速确认（**禁止跨记录批量 confirmed**，见 5.4） |

### 1.2 处理页（核心交互）

| 区域 | 说明 |
|---|---|
| 左侧原文 | 文章全文，AI 抽取时记录"字段←原文位置"，点字段跳到原文对应段落 |
| 右侧表单 | AI 预填全部字段；颜色规则见"审核组合判定表"；每条字段旁有"AI 依据"（引用原文片段）+ 审核状态角标 |
| 顶部状态条 | 高置信度 x 项 / 中 x 项 / 低 x 项（黄/红一眼可见）+ 待确认字段 x 项 |
| 底部操作条 | **一键全过**（硬拦截条件不满足时可用）/ 提交 / 存草稿 / 跳过 / 放弃 |

**mixed 文章**（一文多记录）：右侧表单按"子记录标签页"组织——如"子记录 1：事件 A 钢厂类""子记录 2：日价 304/2B"。每条子记录独立状态（可分别提交/跳过/放弃）。

### 1.3 我的记录页

- 列表：标题 / 类型 / 状态（含 skipped/rejected 子记录） / 校核人 / 时间
- 展开查看：生成了哪些业务记录（事件/日价等）、关联了哪些实体
- 跳转：文章详情 → 图谱页（该文相关实体高亮）

## 二、流程总览（7 步）

```
① 提交文章/报价 → ② 入库去重 → ③ 类型路由 → ④ 约束抽取 → ⑤ 人工校核 → ⑥ 图谱写入 → ⑦ 输出
（同事）        （系统）      （AI）       （AI）       （同事，最轻） （系统）    （AI/自动）
```

**同事只做 3 件事**：提交文章 → 校核标红字段（或一键全过）→ 需要时点"生成文章草稿"。其余全部系统/AI 完成。

## 三、步骤详解

### 第 1 步：提交文章/报价（同事）

**入口**：工作台首页。

**两种提交方式**：
1. **文章提交**：粘贴原文 / 上传文件（md/txt/docx）/ 填写来源链接。系统自动抓取正文。
2. **报价直填（数据快填）**：无文章的纯数值报价（如"304/2B 无锡 14200 含税"），直接走"数据快填"表单，只填必填核心字段（品类/钢种/市场/价格/日期），其他由系统补全。数据快填记录无 source_article_id（不产生父任务）。

> **【待办】049-是否必填 接入报价直填表单**：当前报价直填（采集工作台 index.vue「报价直填」tab）的必填校验仍为硬编码
> （报价日期/品类/钢种/市场/价格/含税状态/计价单位），尚未接入词典 is_required 动态判定（需关联选填/必填信息）。
> 需求未明确，暂保持现状，后续按词典级必填语义改造（词典存在必填词条 → 字段必填）。

**降工作量设计**：支持批量上传（一次多篇）；自写文章可在页内编辑器撰写。

**输出**：一条 data_articles 记录，状态=待提取。

---

### 第 2 步：入库去重（系统，自动）

**动作**：对正文计算 SHA-256 内容 hash，查重。

| 情况 | 处理 |
|---|---|
| 完全重复（hash 相同） | 状态=duplicate，提示"已有同文"，不重复处理 |
| 部分重复（标题/正文相近） | 提示疑似重复，让同事确认"继续处理 / 视为新文章" |
| 新文章 | 进入下一步 |

---

### 第 3 步：类型路由（AI）

**动作**：AI 读文章标题+正文，判断文章类型。**路由置信度为可配置参数（默认 80%），最终值待 P1 金标准测试集校准后确定**；达到阈值静默通过，低于阈值弹人工确认。

| 路由结果 | 含义 | 走向 |
|---|---|---|
| event | 事件类（7 大类之一） | 事件抽取模板 |
| data_price | 价格数据 | 日价模板 |
| data_inventory / data_production / data_demand | 库存/产量/需求数据 | 对应模板（MVP 仅建表，P2 扩展） |
| mixed | 混合（如"减产+价格"） | **多模板同时抽取，产生多条子记录** |
| analysis / forecast | 分析预测类 | 对应模板（MVP 仅建表，P2 扩展） |
| unknown | 无法判定 | 转人工选择 |

---

### 第 4 步：约束抽取（AI）

**动作**：按命中的模板 Schema（字段+枚举+示例+填空模板）调用 LLM，输出 JSON。

**抽取流程**：
1. 加载模板（如"事件-钢厂类"：A 大类必填 E1-E11 + 可选 O1-O11）
2. 组装提示词：角色定义 + Schema 说明（字段名、类型、枚举、必填性、示例值）+ 填空模板 + 文章正文
3. LLM 输出严格 JSON（字段与 Schema 一一对应；**无证据字段必须返回 null，禁止猜测；推断值必标低置信度**）
4. 解析校验：字段缺失/类型不符 → 自动重试（最多 2 次，仍失败标记 failed）
5. **每个字段标注两个元数据**：
   - **置信度**（高/中/低）：
     - 文中原文出现 → 高
     - 推断得出（如摘要、影响程度）→ 中或低（推断类字段如影响程度、趋势判断 → 中；无依据猜测 → 低）
     - 无证据 → null
   - **数据性质**（FACT / OPINION / INFERENCE，见 01 文档第六章）：
     - 原文事实 → FACT
     - 原文观点 → OPINION
     - AI 推断 → INFERENCE（置信度必低，自动标红）
   - **evidence 证据链**：每个非空字段记录原文片段 + 位置（供"点字段跳原文"与校核验证）
6. 自动执行老板文档阈值规则（事件 E11≥3 星 → 建议配套 A 类解读；数据环比>±2% → 建议填原因）

**触发建议边界（审查意见采纳）**：阈值规则**只生成待办/提示，不自动生成 confirmed 业务记录**。如 E11≥3 星 → 创建 A 类解读 draft（不自动 confirmed）；环比超阈值 → 提示填写原因字段。避免自动生成大量垃圾记录。

**INFERENCE 硬规则（全局总规则）**：
> **任何 INFERENCE 性质字段不得在无人审核情况下进入 confirmed/active 状态。** AI 直通（数据轨 active）仅限"高置信度 + FACT 性质"字段；判断类字段（E11 等）即使高置信度也必须人工确认（见第 5 步）。

**A/B/P/Q/R 的抽取 vs 生成规则**（老板确认：两者都有，必须区分来源）：

| 场景 | 处理 | 标记 |
|---|---|---|
| 原文本身写了分析/预测 | AI **抽取**原文观点 | content_source = extracted（性质 OPINION） |
| 原文只是事实素材，无分析/预测 | AI **基于事实生成**草稿 | content_source = ai_generated（性质 INFERENCE），人工校核后定稿 |
| 人工分析师直接撰写 | 表单直填 | content_source = manual |

**输出**：data_articles.confidence_summary + 各业务表 draft 记录（可能多条，各自独立状态）。

---

### 第 5 步：人工校核（同事，最轻的一步）

**入口**：工作台首页 → 待处理队列 → 打开记录（进入处理页）。

**颜色规则（审核判定 = 置信度 + 数据性质 + 字段风险等级的"组合判定规则"，非乘法评分）**：

| 置信度 | 数据性质 | 字段类别 | 展示 | 人工动作 | 一键全过 |
|---|---|---|---|---|---|
| 高 | FACT | 任意 | 绿 | 不看 | 直接通过 |
| 高 | FACT | 判断类字段* | 绿+标识 | **必须过目**（AI 置信度≠业务验证） | **硬拦截** |
| 中 | FACT/OPINION | 核心字段 | 黄 | 必须过目 | 可通过，但提示并留痕 |
| 中 | FACT/OPINION | 描述字段 | 默认 | 不看 | 直接通过 |
| 低 / INFERENCE | 任意 | 任意 | 红 | 必须审核 | **硬拦截，禁止** |

> *判断类字段（必须人工确认，即使高置信度）：E10 数据影响方向、E11 影响程度、I1-I4 影响判断、A13/B13 置信度、P5/Q5/R5 预测数值、P12 预测置信度。原因：这些是主观判断/未来推断，AI confidence 高不等于业务正确。

**核心字段清单**：见 01 文档第七章（每张表预定义；如日价 = 日期/品类/钢种/市场/价格/单位/含税；事件 = 标题/大类/子类/时间/主体/影响方向/影响程度）。

#### 5.0 UI 三态呈现（五轮复审采纳：后台复杂、前台简单）

> 后台完整保留 confidence / nature / risk_level / evidence 元数据；**前端只向业务人员表现三种状态**，不暴露"置信度=中、数据性质=INFERENCE、风险等级=高"这类概念——这是"AI 工作台"与"AI 数据录入后台"的分水岭。

| 前端状态 | 展示形式 | 含义 |
|---|---|---|
| 🟢 正常 | 字段直接显示值（如"价格 14,200 元/吨"） | 高置信度 FACT，无需关注 |
| 🟡 建议确认 | 字段值 + [AI 依据] 链接（点开显示原文片段） | 核心字段中置信度，建议过目 |
| 🔴 必须确认 | 字段值 + [必须确认] 标识，拒绝提交直至确认 | 低置信度 / INFERENCE / 判断类字段 |

#### 5.0.1 AI 修改建议（五轮复审采纳）

> 人工对 AI 值不认同时，不让用户从零重填——系统给"建议值"一键采纳。

```
影响程度
AI 判断：★★★☆☆

建议修改：★★★★☆

[采纳建议] [保持 AI 结果]
```

- 建议值来源：同一事件的关联证据 / 历史同类事件值 / 词典规则（MVP 先做"历史同类 + 规则"两类，LLM 生成建议值 P2）
- 无论采纳或保持，diff 都记录（AI 初值 → 人工终值）到 ai_draft（field_reviewed=modified 或 confirmed），作为 Prompt 优化与字段准确率统计的训练数据

#### 5.1 人工确认的粒度与字段审核状态（field_reviewed）

**确认粒度（老板决策：子记录级确认）**：用户进入子记录 → 过目黄/红字段（含判断类字段）→ 点"一键全过/提交" = 该子记录所有待审字段完成人工确认。**不做强制逐字段点击**。

**字段级审核状态（field_reviewed，审计留痕用，存 ai_draft 每字段）**：

| 状态 | 含义 |
|---|---|
| unreviewed | 未人工过目（AI 初值，高置信度 FACT 可带此状态直接通过） |
| confirmed | 人工过目且采纳 AI 值（不改） |
| modified | 人工修改过（记录 diff：AI 原值 → 人工终值） |
| rejected | 人工明确否决（该字段清空或标无效） |

- 子记录提交时：所有"必须过目"字段（黄/红/判断类）自动标记 confirmed 或 modified（取决于是否改动）
- 用户主动修改过的字段 → modified（diff 存 ai_draft，用于 prompt 迭代）
- 数据轨 AI 直通场景：高置信度 FACT 字段保持 unreviewed 即进入 active（符合 B2 决策）

#### 5.2 跳过与放弃（老板决策：跳过=暂不处理，放弃=永久废弃）

| 动作 | 语义 | 子记录状态 | 后续 |
|---|---|---|---|
| **跳过** | 暂时不处理本次 | skipped | **回到待处理队列**，之后可再次打开校核 |
| **放弃** | 这条子记录是 AI 误识别/不需要入库，永久不处理 | rejected | 不再进入待处理队列；标记原因（可选）可追溯；图谱不写入 |

**注意**：跳过≠放弃。跳过不影响父任务聚合（该子记录仍计入"待处理"）；放弃后父任务聚合将该子记录视为 terminated（既非 confirmed 也非 failed，父任务按剩余子记录重算）。

#### 5.3 一键全过硬性拦截条件（任一存在即禁用按钮）

1. 存在低置信度字段（红）或 INFERENCE 性质字段
2. 存在必填字段为空（null 且必填）
3. 路由结果 unknown 或 mixed 未确认
4. 数值格式校验失败（价格非数字、日期非法等）
5. 存在判断类字段（E11 影响程度等）未人工确认
6. 存在 INFERENCE 性质字段未人工确认（全局硬规则）

#### 5.4 三种操作模式 + 批量约束

| 模式 | 操作 | 适用 |
|---|---|---|
| 一键全过 | 系统自动检查全部硬拦截条件 → 通过则整条子记录直接 confirmed（高置信度 FACT 数据轨子记录甚至无需打开即可由系统直通） | 无拦截项（大多数情况） |
| 提交 | 用户修改字段后提交当前子记录（提交前同样执行硬拦截检查） | 有修改时 |
| 深度编辑 | 任意字段自由修改/清空/备注 | 特殊复杂文章 |

> **一键全过 ≠ 提交**：一键全过 = 未做任何修改、系统检查通过后整条确认；提交 = 用户已修改字段后确认当前子记录。

**批量校核约束（审查意见采纳）**：
> **MVP 禁止跨记录批量直接 confirmed。** 批量操作只支持"连续逐条快速确认"模式：多选 → 逐条打开 → 各条单独执行一键全过/提交 → 下一条。防止一次误确认污染几十条记录。

#### 5.5 降工作量设计汇总

1. 只审标红字段（通常 0-3 个）
2. 一键全过（零操作提交）
3. 复制上次（**只复制模板结构与描述类字段**：字段布局/原因模板/说明模板；**主体/日期/价格/钢种/地区/影响方向/影响程度等业务事实字段一律不复制，必须重新确认**，防静默沿用旧值）
4. 批量校核（连续逐条快速确认，不批量 confirmed）
5. 表单联动（选大类自动带出子类枚举；选钢种自动带出字典候选）
6. 原文定位（点字段跳原文对应段落，依据 evidence 证据链）
7. mixed 分标签页，逐子记录独立处理

**输出**：子记录 draft → confirmed（数据轨为 AI 直通 active，仅低置信度/异常转 draft）；跳过 → skipped（回队列）；放弃 → rejected；父任务按聚合函数更新（见 02 文档 3.1）。

---

### 第 6 步：图谱写入（系统，自动）

**触发**：每条子记录 **confirmed**（数据轨为 active）时触发，不等待父任务完成。

**动作**：03 只负责 trigger——触发后由图谱模块完成：业务记录创建对应图谱节点（kg_entities，业务记录图谱化见 02 文档 8.1）+ 抽取实体与关系写入 kg_entities / kg_relations。**业务记录与图谱节点的映射规则、关系生成逻辑见 04 文档，不在本文定义。**

- 实体：钢厂/工厂（太钢）、原料（镍铁）、政策（环保限产）、下游行业（家电）、区域（无锡）等
- 关系：事件 CAUSED_BY 检修、事件 IMPACTS 价格、实体 LOCATED_IN 区域等（关系方向规范见 04 文档 3.3）
- 幂等：实体按标准名 MERGE（已存在则补别名/来源，不重复建）；关系按 (起点,终点,类型) 去重
- 低置信度实体/关系标记待核验，进入核验队列（图谱页可批量确认）
- **rejected（放弃）的子记录不触发图谱写入**

### 第 7 步：输出（见 05 文档，MVP 到草稿即止）

---

## 四、异常与兜底

| 异常 | 处理 |
|---|---|
| AI 抽取失败（超时/格式错 2 次） | 状态=failed，进入重试队列，人工可一键"重新抽取"或"手动填表"（状态链见下） |
| 路由 unknown | 弹人工选择类型 |
| 核心字段缺失 | 按**每张表模板配置的核心字段缺失门槛**判断（见下） |
| mixed 部分子记录失败 | 成功的保留入库，失败的单独重试（父任务 partial） |
| 校核中人工大幅修改 | 记录 diff（AI 原值 vs 人工终值）到 ai_draft（field_reviewed=modified），用于 prompt 迭代 |

**failed → 手动填表状态链（审查意见采纳，明确转换）**：

```
AI failed（子记录）
   ↓ 人工点"手动填表"
draft（人工填写完成，仍未审核）
   ↓ 人工确认
confirmed / active（正式数据）
```

- "手动填表"产生的记录**不自动 confirmed**，必须经过正常确认步骤
- 数据轨手动填表：填写完成即 draft；若字段全部为人工填写（无 AI 值），确认时只需过目核心字段
- "重新抽取"则丢弃人工改动，重新走 AI 抽取

**核心字段缺失规则（审查意见采纳：按模板配置，不统一 ≥2）**：
- 每张表模板定义自己的"核心字段清单" + "缺失门槛"：
  - 事件模板：核心字段缺 1 个可正常校核提示，缺 ≥2 个提示"信息量不足"
  - 日价模板：**价格字段缺失 = 该条数据无价值**，直接提示放弃或删除（无需等待其他字段）
  - 其他数据模板（周库/月产/季需）：核心数值字段（库存量/产量/需求量）缺失即提示"数据不完整"
- 描述字段缺失不计数
