## 三、老板确认的业务决策（本方案依据）

| 问题 | 确认结果 |
|---|---|
| 原文中 A/B/P/Q/R 是"抽取"还是"生成"？ | **两者都有，必须区分来源**：原文有分析/预测则抽取（OPINION），原文只是事实素材则由 AI 生成草稿（INFERENCE），人工校核定稿 |
| P/Q/R 与现有 AI 金预测能力的关系？ | **统一进入 data_forecast 一张表**：用 forecaster（人=分析师姓名 / AI=AI 金模型版本号）+ model_type（AI金LLM/历史规律/专家经验/综合）区分来源 |
| 转载文章去重（二轮，问题 A） | **不同来源 + 相同正文 → 视为不同文章都保留**（去重键 content_hash + source_name），记录转载链（duplicate_of 标记），不做合并 |
| 数据轨人工审核（二轮，问题 B） | **AI 抽取后直接进入正式数据层（active）**，仅低置信度/异常转 draft 待人工确认；事件/分析/预测仍强制 draft→confirmed |
| "跳过"语义（三轮，问题 ①） | **跳过 = 暂不处理，回待处理队列**（状态 skipped）；另增"放弃"= 永久不处理（状态 rejected） |
| 人工确认粒度（三轮，问题 ②） | **子记录级确认**：进入子记录 → 过目黄/红字段 → 一键全过/提交 = 全部待审字段完成确认；field_reviewed 只做审计留痕，不做强制逐字段点击 |
| 路由阈值（三轮，问题 ③） | **80% 为暂定值**，可配置参数，P1 金标准测试集校准后确定最终值 |
| 中间状态节点模型（四轮，问题 ①） | **不新增节点类型**："减产/供给收紧/价格上涨"等由关系属性（direction/magnitude/description）+ 数据记录节点 + 分析记录节点承载 |
| PREDICTS 预测对象（四轮，问题 ②） | **主边指向具体业务记录节点**（P→daily_price、Q→inventory、R→production/demand），不存在时指向标准实体；properties 存完整 target |
| 同关系多条边（四轮，问题 ③） | **允许多条带时间/来源的关系边**（8 月检修影响、9 月扩产影响各自成边），唯一性由 relation_id 保证，不合并 |
| 生成文章归属（五轮，问题 ①） | **生成内容独立对象 data_content**（不混入 data_articles），独立状态机 draft→editing→confirmed→archived + data_content_citations 素材引用表 |
| 生成素材范围（五轮，问题 ②） | **只允许 confirmed（数据轨 active）素材**；draft/archived 一律不可用 |
| 渠道×风格组合（五轮，问题 ③） | **兼容矩阵**（渠道有风格白名单），非任意笛卡尔积；无效组合 UI 置灰 |
