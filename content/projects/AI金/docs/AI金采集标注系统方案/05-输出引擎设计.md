# 05 — 输出引擎设计

> 目的：定义两个输出方向的工程化实现：(a) 多平台多风格文章生成（老板文档的核心目的）；(b) AI 金问答（结构化命中 + 图谱推理）。
> **MVP 范围（明早演示）**：内容生成工作台（素材选择 → 渠道/风格选择 → AI 生成 → 人工修改 → 定稿存档），**不接分发**；AI 问答接入推迟。
> **V1.2 修订**（按五轮复审意见 + 老板业务决策）：
> - 生成内容独立对象 data_content（不再混入 data_articles）
> - 生成素材只允许 confirmed/active；"已有即引用、缺失不补造"
> - 渠道 × 风格兼容矩阵（非笛卡尔积）
> - 版本机制（v1/v2/v3）+ 素材引用表（可追溯）
> - 素材中心概念；AI 问答未命中不得自动入库

---

## 一、输出总览

```
                     ┌─ 出口A：内容生成（老板核心需求）
结构化记录 + 图谱 ──┤   素材中心 → 渠道/风格模板 → 内容草稿 → 人工修改 → 定稿存档
                     └─ 出口B：AI 金问答（P4 接入）
                          结构化命中 / 图谱推理 → 直接回答（可溯源）
```

## 二、出口 A：内容生成

### 2.1 生成内容对象（data_content，独立于 data_articles）

> **老板决策（五轮问题①）：生成内容不进 data_articles。** data_articles 永远只代表"输入原始文章"（采集素材 + 任务容器）。AI 生成内容产物是独立对象，生命周期独立。

**表：data_content（生成内容产物，见 02 文档）**

| 属性 | 说明 |
|---|---|
| content_id | 对外 ID（CTN-YYYYMMDD-XXX） |
| title / content | 标题 / 正文 |
| content_type | 文章 / 事件卡片 / 快讯 / 短视频脚本 |
| channel | 渠道（dict_channel） |
| style | 风格（dict_article_style） |
| version | 版本号（v1/v2/v3…，重新生成递增） |
| source_record_ids | 素材业务记录 ID 列表（事件/数据/分析/预测） |
| citations | JSONB 引用标注 [{record_id, record_type, position, evidence}] |
| reviewer / status | 审核人 / draft→editing→confirmed→archived |
| generation_history | JSONB [{version, prompt_params, model, created_at}] |

**素材引用表：data_content_citations**（content_id + record_type + record_id + 引用位置）——保证"生成文章 → 业务记录 → 原始文章 → evidence"全链路可追溯。**MVP 生成文章不进图谱**（仅保存引用关系），P2 再考虑内容产物图谱化（BASED_ON 边）。

### 2.2 素材规则（老板决策：只允许 confirmed）

> **生成素材池 = confirmed 业务记录（数据轨 active）。draft 与 archived 一律不可用。** 写死规则：生成引擎只读取 confirmed/active 记录，绕开人工校核机制 = AI 把未确认数据写进文章，是内容生产不可接受的污染。

**素材引用核心规则（"已有即引用、缺失不补造"）**：
> 生成引擎只允许基于**已确认素材**进行内容组织；**不因素材链缺失而自动虚构事件、数据、分析或预测**。
> - 只有日价记录 → 文章只写价格，不编造原因
> - 事件+日价+解读 → 完整引用，链上有哪个引用哪个
> - 防止 AI 为了"补齐 事件→数据→解读→预测 链路"产生不存在的内容（违反 01 的 FACT/OPINION/INFERENCE 纪律）

### 2.4 生成流程（MVP 核心闭环）

```
① 选素材 → ② 选渠道+风格 → ③ 素材中心聚合 → ④ AI 生成 → ⑤ 人工修改/重生成 → ⑥ 定稿存档
```

| 步骤 | 动作 | 参与者 | 说明 |
|---|---|---|---|
| ① 选素材 | 从已确认事件/数据/分析/预测中选择（可多选） | 人 | 只显示 confirmed/active 记录 |
| ② 选渠道+风格 | 勾选渠道（多选）、选择风格（单选），无效组合置灰 | 人 | 按 2.3 兼容矩阵校验 |
| ③ 素材中心聚合 | 系统从结构化表+图谱拉取素材包：核心事实/时间/钢厂/产品/影响方向/影响程度/价格数据/历史对比/相关事件/来源 | 系统 | **素材中心**（见 2.5） |
| ④ AI 生成 | 按渠道+风格模板生成草稿，**带来源标注**（正文事实引用 [来源：EVT-xxx]） | AI | 每素材带 record_id 引用 |
| ⑤ 人工修改 | 内容编辑工作台：可改、可重生成（换风格/更专业/更口语），版本递增 v1→v2 | 人 | 生成历史保留（generation_history） |
| ⑥ 定稿存档 | 定稿存 data_content（status=confirmed），**不接分发** | 系统 | MVP 到定稿止 |

**生成入口统一（审查采纳）**：一个核心动作"**生成内容**"→ 选择渠道（单渠道/全渠道勾选）+ 风格 → 生成。不再有"生成文章/生成公众号/生成全渠道"多个入口。

### 2.5 素材中心（MVP 必做）

> 审查采纳：不让 LLM 直接"看一堆结构化数据自己写"，而是先聚合成**素材包**，渠道模板只是不同 Renderer。

```
事件（已确认）
  ↓
素材包
 ├── 核心事实（事件简述）
 ├── 时间
 ├── 钢厂/主体
 ├── 产品/钢种
 ├── 影响方向 / 影响程度
 ├── 价格数据（关联日价 + 环比同比）
 ├── 历史对比（如有）
 ├── 相关事件（如有）
 └── 来源（record_id 列表）
       ↓
┌──────────────┐
│ 微信模板      │
│ 抖音模板      │
│ APP 模板      │
│ 行业群模板    │
└──────────────┘
```

- 素材包 = 生成 API 的输入结构（见 08 文档 API 契约）
- 素材包中每条事实带 record_id + evidence，生成时强制引用标注
- 降低"AI 胡编"概率：AI 只能改写素材包内容，不能引入素材包之外的事实

### 2.6 降工作量设计

- **一键生成**：选中记录 → 勾选渠道+风格 → 生成内容（草稿即出）
- **草稿重写**：不满意点"换一种风格/更专业/更口语"重新生成（版本递增，旧稿可回看）
- **素材自动聚合**：素材包自动带出数据卡片、事件 ID、来源，同事不用翻资料
- **渠道版本并排**：同一素材的多渠道版本同页展示对比
- **内容编辑工作台**（明早演示核心页）：原始素材/引用 → AI 生成文章 → 人工修改 → [重新生成][保存草稿][定稿]

### 2.7 MVP 演示范围（明早只演示 3 个成品 + 编辑工作台）

| 演示项 | 内容 |
|---|---|
| ① 公众号 | 标题 + 正文 + 数据引用 + 来源 |
| ② 51 号 APP | 标题 + 核心结论 + 影响星级 |
| ③ 行业群 | 一句话快讯 |
| 内容编辑工作台 | 素材 → AI 生成 → 人工修改 → 重新生成（版本）→ 定稿 |

> 抖音口播模板已抽象（代码存在），演示时口播"模板可复用扩展"，不演示。**不展示 12 个版本**——演示 3 个成品比 12 个半成品专业。

## 三、出口 B：AI 金问答（P4 接入，MVP 不做）

### 3.1 问答路由（结构化命中优先）

```
用户提问
  ↓
① 结构化命中检测（轻量、快）
  ├─ 命中预测记录（"还会涨吗"）→ 直接返回最新预测 + 依据
  ├─ 命中分析记录（"为什么涨"）→ 返回解读 + 关联链
  ├─ 命中数据记录（"现在什么价"）→ 返回最新数据 + 环比同比
  └─ 未命中 → ②
② 图谱推理（多跳）
  ├─ 识别问题中实体（太钢/304/镍铁）→ 图谱展开 2-4 跳
  ├─ 链路命中 → 组织答案（事实链 + 来源）
  └─ 未命中 → ③
③ 降级：LLM 直接回答（现有 AI 问答能力兜底）
```

**定位（审查意见采纳）：本模块是现有 AI 问答系统的"数据增强层"，不是重建问答系统。**

- 不新建第二套 Prompt / 知识 / 回答策略 / 引用 / 缓存
- 在现有问答链路上游插入"结构化命中层"：命中即补充结构化上下文（或直接返回），未命中走原链路
- 结构化数据同时作为现有百炼知识库的高质量语料来源（可回流刷新）

### 3.2 命中规则（P4 落地）

| 问题类型 | 命中对象 | 回答策略 |
|---|---|---|
| "304 为什么涨" | 分析 A/B 类 | 返回解读核心结论 + 关联事件 + 数据对比 |
| "304 还会涨吗" | 预测 P 类 | 返回最新预测（目标价+幅度+窗口+置信度+依据） |
| "现在 304 什么价" | 数据日价 | 返回最新价 + 环比同比 + 来源日期 |
| "库存什么时候降" | 预测 Q 类 | 返回库存预测 + 依据 |
| "太钢检修有什么影响" | 图谱多跳 | 展开 IMPACTS/LEADS_TO 链路 |
| "镍铁涨价会影响什么" | 图谱多跳 + 分析 | 成本传导链路 + 相关解读 |

**命中排序规则**（多条候选时加权排序）：
1. 对象匹配：钢种/地域与问题实体一致（权重最高）
2. 数据新鲜度：记录时间距离当前越近越优先
3. 时间相关性：问题含时间词（"本周/上月"）时对齐
4. 影响程度：星级越高越优先（≥4 星前置）
5. 来源性质：confirmed（人工确认）> draft
6. 同分时按时间倒序取最新

**关系性质过滤（V1.2 补充，配合 04 关系 nature）**：
- 问答默认只用 FACT 性质关系回答事实类问题
- OPINION/INFERENCE 关系仅用于"观点/预测"类问题，且回答中明示"这是分析师观点/AI 推断"

### 3.3 回答质量保障（P4 落地）

- **时效性**：事件有效期按事件类型可配置（validity_days 属性，默认 30 天；valid_until = event_date + validity_days，见 02 文档），过期降权或标历史
- **可溯源**：回答自动附来源（事件 ID/数据记录/文章链接），点击可跳图谱页查看完整链路
- **未命中回退（V1.2 修订：禁止自动沉淀）**：未命中由现有 AI 问答能力兜底；**AI 回答结果不得自动作为事实类数据入库**。如需沉淀，必须走人工确认的采集/分析流程（避免"AI 生成→AI 入库→AI 又当事实"的自循环污染）

## 四、报告自动生成（P3 后期，MVP 不做）

| 报告 | 频率 | 素材 | 输出 |
|---|---|---|---|
| 日报 | 每日 | 当日事件（按影响程度排序）+ 日价数据 + 当日解读 | 摘要 + 数据卡片 |
| 周报 | 每周 | 本周事件汇总 + 库存变化 + 数据异动归因 + 周度预测复盘 | 长文 + 图表 |
| 月报 | 每月 | 本月重大事件（≥3星）+ 产量复盘 + 价格走势归因 + 预测复盘（误差率口径） | 深度报告 |
| 季报 | 每季 | 行业大事记 + 供需平衡分析 + 季度预测复盘 + 下季展望 | 完整报告 |

**核心能力：预测复盘（数据飞轮）**——每期报告自动对比"预测 vs 实际"，统计各预测模型/分析师准确率，回写预测记录 forecast_error_pct 字段，沉淀为"预测准确率报告"（老板文档场景 2 要求）。

> ⚠️ 口径统一：上表及本段中"准确率"表述在全链路已统一为**误差率**（口径：误差率 = |预测-实际|/|实际|，越低越准；详见 19 号文档）。实际落库字段为 `forecast_error_pct`，月报对外表述统一为"本月预测复盘"（见 20 号文档 Task #47）。
