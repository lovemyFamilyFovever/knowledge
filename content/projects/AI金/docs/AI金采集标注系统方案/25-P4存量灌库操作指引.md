> 关联文档：《24-P4存量批量处理方案》§2.3/§2.4、`.qoder-archive/handoff/05-environment.md` §3
> 迁移脚本：`server/database/sql/046-create-import-staging.sql`（建表）、`047-create-batch-runs.sql`（批次日志）、`048-refine-import-staging.sql`（索引对齐领取三谓词 + import_batch_runs 增列 fail_rate/halt_reason + process_status 注释补 duplicate）

## 〇、导入模型（先看这个）

系统**不做文件上传、不做 CSV 解析**。完整流程：

1. 用户从旧平台数据库导出 CSV（几百 MB～几个 G）；
2. 用户用图形化工具（pgAdmin / Navicat / pgcli 等）把 CSV **灌入本应用本地 PG 库的暂存表 `import_staging`**；
3. 在本系统「存量批量导入」页（`/#/erp/data-collect/batch-import`）**登记批次**——系统自动体检（总行数、空正文、重复 ID、超长行抽样）并分配批次号；
4. 后续批处理（P4-2）以批次为单位消费暂存数据。

本文档交付第 2 步所需的全部约定：建表 DDL、CSV 列格式、导入工具要点、灌库后登记操作。

## 一、建表 DDL（指向 046/047/048 脚本）

暂存表由迁移脚本 **046** 创建、**047** 建批次日志表、**048** 精修（索引/增列/注释），执行方式（仅本地/飞书 dev 库，严禁 online）：

```bash
node scripts/run-collect-migrations.mjs 046 048
```

表结构摘要（以 `046-create-import-staging.sql` + `048-refine-import-staging.sql` 为准）：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | UUID 主键 | 默认 `gen_random_uuid()`，**灌库时不要提供** |
| `legacy_article_id` | VARCHAR(100) NOT NULL | 旧平台 article_id，**唯一索引**（防重导幂等基石） |
| `article_content` | TEXT | 旧平台 article_content 原始 HTML 全文，整块灌入 |
| `batch_no` / `bucket` | VARCHAR | 留空，由系统登记批次时回写 |
| `parse_status` / `process_status` | VARCHAR | 默认 `raw` / `pending`，无需提供 |
| `data_article_id` / `error_info` | — | 处理后系统回填 |
| `_created_at/_updated_at/_created_by/_updated_by` | — | 审计列，有默认值 |

**灌库只需提供两列：`legacy_article_id`、`article_content`**，其余列全部走默认值。

表前缀定案为 `import_`（独立于 `data_` 业务域）：暂存数据是临时缓冲层，不进素材池、不参与业务查询，独立前缀便于识别与后续整体清理。

### 1.1 process_status 状态语义（登记后由系统流转）

| 状态 | 含义 |
|---|---|
| `pending` | 待处理（登记圈定后的初始状态） |
| `processing` | 处理中（批处理原子领取后置位，断点恢复权威状态） |
| `done` | 已产出（入库成功，回填 `data_article_id`） |
| `skipped` | 跳过——**内容不可用**（正文为空/无法规整等，主动放弃） |
| `failed` | 失败（解析/抽取异常，`error_info` 留痕） |
| `duplicate` | **内容级重复**——与 `data_articles` 既有内容哈希比对命中。区别于两类近义概念：① 灌库级重复（同一 `legacy_article_id` 重复灌入，被唯一索引 `uq_import_staging_legacy_id` 直接拦截，根本不进表）；② `skipped`（内容不可用，与重复无关） |

## 二、CSV 列格式约定（导出时照此执行）

| 项 | 约定 |
|---|---|
| 列 | 恰好两列，顺序：`legacy_article_id, article_content` |
| 表头 | **含表头**（首行 `legacy_article_id,article_content`），导入工具勾选 header |
| 编码 | **UTF-8**（推荐无 BOM；若工具导出带 BOM 的 UTF-8，导入前确认工具按 UTF-8 解析，防止首列名被污染） |
| 分隔符 | 英文逗号 `,` |
| 引号 | 双引号 `"`（RFC 4180） |
| 富文本 | `article_content` 整体作为**一个带引号字段**；HTML 内嵌的换行、逗号、引号依赖 RFC 4180 规则：字段整体用 `"` 包裹，字段内部的 `"` 写成 `""` |
| 换行 | 字段内嵌换行**必须**在引号包裹之内（导出工具默认行为即是，勿手工拆行） |
| legacy_article_id | 非空、≤100 字符；同一 ID 全库只允许出现一次（唯一索引，重导会被数据库拒绝） |

样例（第 2 行正文含换行与内嵌引号）：

```csv
legacy_article_id,article_content
10001,"<p>今日304冷轧报价持稳。</p>"
10002,"<p>市场消息：""钢厂限价""上调。</p>
<p>详情见正文……</p>"
```

> 提示：几百 MB～几个 G 的单文件可以分卷导出（按 ID 区间切多个 CSV），逐卷灌入同一张表即可；唯一索引保证重复卷不会二次入库。

## 三、灌库工具要点

### 3.1 pgAdmin（图形化，推荐）

1. 连接本应用 PG 库（连接信息见工作区 `.env` 的 `DATABASE_URL`，本地/团队共享库）；
2. 右键 `import_staging` 表 → **Import/Export Data**；
3. 关键参数：
   - Format：`csv`
   - Filename：选择导出的 CSV（超大文件建议分卷）
   - Header：**Yes**
   - Encoding：**UTF-8**
   - Delimiter：`,`
   - Quote：`"`
   - 其余默认；
4. 完成后在 Query Tool 执行核对：`SELECT COUNT(*) FROM import_staging;`

### 3.2 pgcli / psql（命令行）

```sql
\copy import_staging (legacy_article_id, article_content)
  FROM 'C:\path\to\export.csv'
  WITH (FORMAT csv, HEADER true, DELIMITER ',', QUOTE '"', ENCODING 'UTF8');
```

> `\copy`（客户端 COPY）比服务端 `COPY` 更适合本地文件；大文件耗时以分钟计属正常。

### 3.3 常见报错

| 报错 | 原因与处置 |
|---|---|
| `duplicate key value violates unique constraint "uq_import_staging_legacy_id"` | 该旧平台 ID 已灌入过（重导/卷间重复）。处置：确认已入库行数后，从 CSV 去掉重复行重灌，或分卷隔离 |
| `invalid byte sequence for encoding "UTF8"` | 文件不是 UTF-8（常见 GBK 导出）。处置：用导出工具另存为 UTF-8 再灌 |
| `extra data after last expected column` / 错行 | 富文本内嵌换行/逗号未被引号包裹。处置：确认导出时 article_content 整列带引号（RFC 4180） |
| `value too long for type character varying(100)` | legacy_article_id 超过 100 字符。处置：与旧平台核对 ID 口径 |

## 四、灌库后在本系统登记批次

1. 打开 **存量批量导入** 页：`/#/erp/data-collect/batch-import`（ERP 侧栏「采集标注」组，或采集工作台头部「存量批量导入」按钮）；
2. 页面顶部「暂存数据概览」核对：暂存总量、未登记量、空正文行、重复旧平台 ID（口径：因重复多出的行数 = `sum(cnt - 1)`）；
3. 填写登记表单（均可留空走缺省）：
   - 批次号：留空自动生成 `B-YYYYMMDD-序号`；提供时仅允许字母/数字/下划线/连字符，≤64 字符；
   - 桶名：如「不锈钢-2024Q1」（对应分桶维度：行业/时间段，≤64 字符）；
   - 分桶规则：备注说明（≤255 字符）；
   - **旧平台 ID 前缀（条件圈定，可选）**：只圈定 `legacy_article_id` 匹配该前缀的未登记行（如分卷灌库后按卷登记）；
   - **圈定行数上限（条件圈定，可选）**：本批最多圈定的行数（正整数），便于把大批次拆小试跑；
4. 点击「登记并体检」——系统默认圈定**全部未登记行**（`batch_no IS NULL`），填写条件圈定参数时按前缀/上限收窄；体检与圈定同范围，输出体检报告：总行数、空正文计数与样例、重复 legacy_article_id 计数与样例（计数为全量口径、样例取 Top-5）、超长行抽样 3 条（预览前 200 字符）；
5. 登记全程单事务，批次号唯一索引兜底：并发登记同一批次号时后到者整体回滚；登记的操作人随批次日志留痕（`import_batch_runs._created_by`）；
6. 体检报告随批次留痕（`import_batch_runs.intake_report`），批次列表可随时回看。

对应接口（前端已封装，直接调用亦可）：

- `POST /api/collect/batch/intake/register`：`{ batch_no?, bucket?, bucket_rule?, legacy_id_prefix?, max_rows? }` → 体检报告；
- `GET /api/collect/batch/intake/status`：暂存概览 + 批次列表（含各状态行数聚合：pending/processing/done/skipped/failed/duplicate）。

## 五、边界说明

- 本指引**只提供材料与约定，不提供灌库脚本**（灌库动作由用户用图形化工具完成）；
- 标题、发布时间等其他字段不在本期导入范围（旧平台仅导出 article_id + article_content 两字段）；
- 暂存数据整块保留原始 HTML、不预清洗，清洗规则迭代后可凭暂存表重放；
- `duplicate`（内容级重复）由 P4-2 批处理与既有内容哈希比对后置位，P4-1 登记阶段不会产生该状态；
- 飞书 online 库冻结中：本表迁移与灌库仅在本地/飞书 dev 库进行。
