## 二、核心采集流程（P0 + P1）

### TC-01 文章提交与去重

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 打开采集工作台页面 `#/erp/data-collect` | 页面加载，显示待处理队列（可能为空） |
| 2 | 点击"提交文章"按钮，粘贴**文章 A** 正文，选择来源名称，点击提交 | 弹出成功提示，文章出现在待处理列表，状态为 `pending` |
| 3 | 记录文章 ID（如 `art-xxx`），**再次提交完全相同的内容** | 系统提示"疑似重复"或自动标记 `duplicate_of`，不创建新文章 |
| 4 | 提交**文章 B**（不同内容） | 正常入库，状态 `pending` |
| 5 | 提交**文章 C**（复合文） | 正常入库，状态 `pending` |

**接口验证**：
- `POST /api/collect/articles` → 返回 `{code:0, data:{id, status:'pending'}}`
- `GET /api/collect/workbench/todos?tab=pending&page=1` → stats 中 pending 计数 +1

### TC-02 AI 类型路由

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 在工作台待处理列表中，点击**文章 A** 进入处理页 | 显示文章内容 + AI 处理区域 |
| 2 | 点击"AI 类型路由"按钮（或系统自动路由） | 路由结果：文章 A → `event`（事件类），状态变为 `processing`（路由完成，抽取自动推进） |
| 3 | 对**文章 B** 执行路由 | 路由结果：文章 B → `data_price`（日价类），状态变为 `processing` |
| 4 | 对**文章 C** 执行路由 | 路由结果：文章 C → `mixed`（复合类），状态变为 `processing` |
| 5 | 点击"我已确认类型路由"按钮（选择对应类型下拉） | 调用 `POST /api/collect/articles/:id/route-confirm` 成功，状态持久化 |

**接口验证**：
- `POST /api/collect/articles/:id/route` → 返回 `{code:0, data:{route:'event'|'data_price'|'mixed'}}`
- `POST /api/collect/articles/:id/route-confirm` → 返回 `{code:0, data:{success:true}}`

### TC-03 AI 约束抽取

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 文章 A（event）路由确认后，等待自动触发抽取（route-confirm 后系统自动执行抽取管线，无需手动点击） | 系统调用百炼 API 抽取事件字段，生成 1 条 `data_events` 子记录（draft 状态），文章状态 → `reviewing` |
| 2 | 查看子记录详情 | 显示 AI 抽取结果：事件类型、涉及钢种（304）、涉及企业（太钢）、价格变动方向、置信度、evidence 证据链 |
| 3 | 文章 B（data_price）执行抽取 | 生成 1 条 `data_daily_price` 子记录，含多规格报价 |
| 4 | 文章 C（mixed）执行抽取 | 生成 **多条** 子记录（事件 + 日价各一条），体现 mixed 复合特性 |
| 5 | 检查字段级标注 | 每个字段显示：置信度（高/中/低）、性质标（FACT/OPINION/INFERENCE）、evidence 来源 |

**接口验证**：
- `POST /api/collect/articles/:id/extract` → 返回 `{code:0, data:{...}}`
- `GET /api/collect/articles/:id` → sub_records 数组包含抽取结果

### TC-04 人工校核与提交

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 进入文章 A 的校核页面 | 显示字段列表，每个字段有 AI 初值 + 三态标记（绿=已确认/黄=未审核/红=需修改） |
| 2 | 修改一个 AI 抽取错误的字段值 | 字段标记从"未审核"变为"已修改"（黄色→绿色），显示"已偏离 AI 初值"标签 |
| 3 | 确认其他字段（点击确认按钮） | 字段标记变为"已确认"（绿色） |
| 4 | 检查必填项是否全部处理 | 所有必填字段必须为"已确认"或"已修改"状态才能提交 |
| 5 | 点击"提交审核结果"按钮 | 调用 `POST /api/collect/records/:id/review`，硬拦截校验通过后子记录状态 → `confirmed`（事件）/ `active`（日价），父任务聚合状态更新 |
| 6 | 检查图谱写入 | 调用 `GET /api/kg/stats`，确认实体和关系数量增加 |

**硬拦截校验**：
- 必填字段未审核 → 提交被拦截，返回错误信息
- 价格字段值明显异常（如负数价格） → 标红提醒

**接口验证**：
- `POST /api/collect/records/:id/review` → 返回 `{code:0, data:{status:'confirmed'|'active'}}`
- 图谱：`GET /api/kg/stats` → 节点/关系数增加
- 状态说明：事件记录提交后为 `confirmed`，日价记录为 `active`（价格类数据走"活跃"状态，符合领域语义）

### TC-05 跳过与放弃

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 对文章 B 的子记录点击"跳过" | 子记录状态 → `skipped`，回到待处理队列末尾 |
| 2 | 对文章 B 的子记录点击"放弃"，填写原因（选填） | 子记录状态 → `rejected`，不写图谱，永久不处理 |

**接口验证**：
- `POST /api/collect/records/:id/skip` → `{code:0, data:{status:'skipped'}}`
- `POST /api/collect/records/:id/reject` → `{code:0, data:{status:'rejected'}}`

### TC-06 我的记录页

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 打开 `#/erp/data-collect/records` | 显示已处理文章列表（confirmed/skipped/rejected） |
| 2 | 按状态筛选"已确认" | 列表仅显示 confirmed 状态的记录 |
| 3 | 搜索关键词（如"太钢"） | 列表按标题/文章 ID 过滤 |
| 4 | 展开某条记录查看详情 | 显示子记录摘要 + 溯源信息 |

**接口验证**：
- `GET /api/collect/records/mine?status=confirmed&keyword=太钢` → 返回过滤后的记录数组

### TC-07 强制删除与作废

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 在工作台对某文章执行"强制删除" | 文章及其所有子记录物理删除，不可恢复 |
| 2 | 对另一文章执行"强制作废" | 文章状态 → `voided`，不再出现在任何待处理队列 |

**接口验证**：
- `POST /api/collect/articles/:id/force-delete` → `{code:0, data:{deleted:{article:true, events:N, prices:M}}}`
- `POST /api/collect/articles/:id/force-void` → `{code:0, data:{id, status:'voided'}}`

## 十五、异常与边界场景

### TC-27 异常输入处理

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 空内容提交 | 提交空正文 | 返回 `{code:-1, msg:'参数缺失：content'}` |
| 无效文章 ID | 访问不存在的文章详情 | 返回错误信息 |
| 缺少批次号 | 调用 process/pause/resume 不传 batch_no | 返回 `{code:-1, msg:'缺少批次号'}` |
| 抽检判定非法值 | judge 传 status='invalid' | 返回 `{code:-1, msg:'判定状态仅支持 pass/fail'}` |
| 未知数据轨 | yoy/backfill 传 table='unknown' | 返回错误提示，列出可选数据轨 |
| 无 ERP token | 不携带 Authorization header | 被 ErpAuthGuard 拦截，返回 401 |

### TC-28 并发与幂等

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 重复登记同一暂存数据 | 两次 register 相同条件 | 第二次提示无新的未登记行 |
| 重复提交相同内容 | 同内容 hash 二次提交 | 去重机制生效，标记 duplicate_of |
| 并发时间片 | 同时触发两个 process 请求 | 分片软抢占，不会重复处理同一行 |
