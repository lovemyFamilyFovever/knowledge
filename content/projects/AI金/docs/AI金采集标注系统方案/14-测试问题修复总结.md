## 三、各项详细说明

### Q1 字典表动态生成 vs 预维护

- **用户原始描述**：询问字典表（钢种、区域、事件分类等 12 张 dict 表）的数据是动态生成还是预维护。
- **最终修复方案**：初期结论为"预维护的静态种子数据"（SQL 迁移脚本 035-040 幂等预插入）。第二轮修复升级为**动态加载 + 硬编码兜底**模式：
  - 后端：`collect.service.loadDicts()` 提供 5 分钟内存缓存，新增 `getDicts()` 公开 API（`GET /api/collect/dicts`），返回 snake_case 结构（grades、grades_short、regions、event_categories、event_sub_categories 等）。
  - 前端：`field-config.ts` 引入响应式 `DICT` 对象，初始化用硬编码数组，运行时调用 `loadDictsFromApi()` 覆盖；接口失败时静默回落硬编码。
- **具体改动点**：
  - `collect.controller.ts`：新增 dicts 路由
  - `collect.service.ts`：暴露 loadDicts 缓存结果
  - `field-config.ts`：DICT 响应式对象 + 加载函数
- **commit**：88dcf11（后端接口）、56aa6eb（前端接入）

### Q2 下拉列表缺"热卷"

- **用户原始描述**：dict_grade 表中存在"热卷"，但审核页钢种下拉列表找不到。
- **最终修复方案**：根因是前端 GRADE_OPTIONS / GRADE_SHORT 为硬编码数组，未包含"热卷"。第一步直接补充"热卷"选项；随后随 Q1 一并改为 dict API 动态加载，根治"新增钢种需同时改 SQL 和前端代码"的不一致风险。
- **具体改动点**：`field-config.ts` 中 GRADE_OPTIONS / GRADE_SHORT 数组补项 + 运行时字典覆盖逻辑。
- **commit**：3a1f9a4（补"热卷"）、56aa6eb（动态加载接入）

### Q3 "提交"与"一键全过"双按钮重复

- **用户原始描述**：两个按钮功能疑似重复，用户分不清该点哪个。
- **最终修复方案**：经讨论决定**合并为单一"提交审核结果"按钮**，由后端逻辑自动分流：全部为高置信 FACT 字段且用户未修改 → 走快速通道；否则走正常提交审核流程。用户无需感知两条通道的差异。
- **具体改动点**：`review.vue` 删除"一键全过"按钮及相关逻辑，统一提交入口内部分流。
- **commit**：56aa6eb

### Q4 渠道兼容性降级

- **用户原始描述**：渠道×风格组合存在 forbidden（禁止）项，限制过严。
- **最终修复方案**：经讨论，将 douyin×deep、group×daily_review、group×deep 三个 forbidden 组合**全部改为 degraded（降级适配）**，如深度报道降级为精简图文摘要。前后端矩阵必须同步修改，否则会出现"前端可选但后端报错"的新问题。
- **具体改动点**：
  - 前端：`content-studio/config.ts` 的 COMPAT_MATRIX 三级矩阵调整 + 降级提示文案
  - 后端：`content.service.ts` 的 CHANNEL_STYLE_MATRIX（中文字段键）同步调整 + fallbackDraft 简化内容模板
- **commit**：b2ed037、88dcf11

### Q5 内容生成中刷新导致丢失

- **用户原始描述**：内容生成过程中刷新页面，生成结果丢失。
- **最终修复方案**：直接修复——添加浏览器原生 `beforeunload` 拦截，生成中刷新/关闭页面时弹出确认提示。
- **具体改动点**：`content-studio/index.vue` 注册/卸载 beforeunload 监听（生成开始时挂载，结束/离开时清理）。
- **commit**：3a1f9a4、f685e9a

### Q6 生成过程显示思考进度

- **用户原始描述**：生成内容时只有 spinner，希望看到类似 AI 测价的思考进度。
- **最终修复方案**：直接修复，采用轻量方案——5 条轮播提示文案每 4.5s 切换，模拟进度感知；暂不改造为 SSE 流式输出（成本中等，后续按需评估）。
- **具体改动点**：`content-studio/index.vue` 生成中状态区增加轮播文案组件与定时器。
- **commit**：3a1f9a4、f685e9a

### Q7 素材库重复内容

- **用户原始描述**：素材库出现大量重复内容（如"太钢 1780 热轧产线 8 月检修 15 天"出现 6 条）。
- **最终修复方案**：直接修复，三层处理：
  1. **入库层**：标题归一化（trim + 去多余空白）后重算 SHA-256 contentHash，解决"正文微小差异不被判重"的问题；
  2. **展示层**：素材库查询按标题分组去重（取最新一条）；
  3. **前端**：重复内容增加计数标签提示。
- **具体改动点**：`collect.service.ts`（hash 归一化）、`content.service.ts`（fetchMaterials 去重）、`content-studio/index.vue`（重复计数标签）。
- **commit**：fddda75

### Q8 一键演示 mock 数据（含 Q13）

- **用户原始描述**：一键演示按钮使用 mock 数据生成成品，不尊重用户选择的素材。
- **最终修复方案**：经评估该功能价值有限且易误导，**彻底删除** `demoThree()` 函数及"一键演示 3 渠道成品"按钮。Q13（希望演示基于用户所选素材）合并至此，随功能删除一并关闭。
- **具体改动点**：`content-studio/index.vue` 删除 demoThree() 及对应 UI 元素。
- **commit**：b2ed037

### Q9 事件记录页三个子问题

- **用户原始描述**：
  - a) 修改字段后顶部统计数字（红/黄/绿计数）不动态更新；
  - b) pending=0 即显示"全部就绪"，但仍有红/黄字段未处理，提示误导；
  - c) 必填字段点"否决"会清空值，与硬拦截校验冲突，操作冗余。
- **最终修复方案**：
  - a) **fieldTone 逻辑修正**：confirmed / modified 状态优先返回 green，消除"红计数不减"的 Bug；同时 onConfirm / onReject 补上缺失的 state 创建（原先对未初始化字段点击为死按钮）；
  - b) **"全部就绪"条件收紧**：仅 pending=0 且 red=0 且 yellow=0 时渲染；
  - c) **必填项隐藏否决按钮**：FieldRow 的否决清空按钮加 `v-if="!config.required"`。
- **具体改动点**：`field-config.ts`（fieldTone）、`review.vue`（就绪条件、state 创建）、`components/FieldRow.vue`（否决按钮条件渲染）。
- **commit**：56aa6eb、3a1f9a4

### Q10 "已偏离 AI 初值"判定 + 子记录 ID 显示

- **用户原始描述**：询问"已偏离 AI 初值"标签的判定标准；卡片底部显示的一串 ID 是什么。
- **最终修复方案**：
  - 判定标准明确为 `JSON.stringify(value) !== JSON.stringify(aiValue)`（当前值与 AI 原始抽取值序列化后不一致，且字段已审核），判定逻辑随第二轮修复校准；
  - 卡片底部字符串为子记录 ID（非 UUID），对用户无业务价值，建议隐藏——本轮**未单独提交修复，保留现状**，列入后续优化。
- **具体改动点**：`components/FieldRow.vue` 偏离判定逻辑。
- **commit**：判定逻辑随 56aa6eb 校准；隐藏子记录 ID 暂无独立 commit。

### Q11 "我已确认类型路由"按钮无效 + 提取失败

- **用户原始描述**：点击"我已确认类型路由"按钮后页面状态不变，刷新后失效；部分文章提取失败后无出路。
- **最终修复方案**：经讨论重新设计——按钮由"仅设置前端局部变量 routeAck"改为**调用后端持久化接口**：
  - 后端新增 `POST /api/collect/articles/:id/route-confirm`，接收 `{ route: string }`，校验 MVP 支持类型后更新 `data_articles.article_type`，推进状态（pending_route → pending_extract）并触发提取管线；
  - 前端增加 8 类路由下拉选择（event / data_price / mixed 等），调用 API 成功后才置 routeAck=true，失败 toast 提示。
- **具体改动点**：`review.vue`（路由下拉 + API 调用）、`collect.controller.ts`（新路由）、`collect.service.ts`（route-confirm 逻辑）、`api.ts`（前端请求封装）。
- **commit**：88dcf11、56aa6eb、2d47a10（前端路由下拉）、fd04ee5（后端路由确认后异步触发抽取管线）

### Q12 文章卡在"AI 处理中"

- **用户原始描述**：文章提交后长时间停留在"AI 处理中"，进入详情显示"无可校核子记录"，无法重新编辑或删除。
- **最终修复方案**：直接修复，三重兜底：
  1. **超时机制**：processing 状态超过 30 分钟自动标记为 failed；
  2. **强制处置 API**：新增强制删除 / 作废接口；
  3. **前端入口**：卡死文章卡片提供"强制删除 / 作废"操作按钮。
- **具体改动点**：`collect.service.ts`（超时扫描 + 强制处置逻辑）、`collect.controller.ts`（对应 API）、`review.vue`（操作按钮）。
- **commit**：024a5a8

### Q13 一键演示基于用户所选素材

- **用户原始描述**：希望一键演示生成的成品基于用户所选素材，而非 mock 数据。
- **最终修复方案**：**合并入 Q8** —— 演示功能整体删除，该项随之关闭。
- **commit**：b2ed037
