# 01 — 与标准格式文档对齐表

> 目的：把洛歌 3 份标准格式文档的**每个字段**逐项落到数据库表与处理流程，防止方案跑偏。审核本文件时请对照洛歌原文档逐字段核对。

---

## 一、对齐总原则

| 洛歌文档的要素 | 本方案落地方式 | 是否保留 |
|---|---|---|
| 字段清单 | 数据库表列（列名 = 字段名，类型按文档定义） | 100% 保留 |
| 单选选项 | 枚举字典表 / 数据库 CHECK 约束 | 100% 保留 |
| 多选选项 | 数组字段 / 关联字典表 | 100% 保留 |
| 文本输入 | TEXT 列 | 100% 保留 |
| 必填/可选 | 表列约束 + 表单必填校验 | 100% 保留 |
| 填空模板（如 E9 事件简述） | AI 抽取时提示词内嵌模板，输出按模板填 | 100% 保留 |
| 同比/环比 4 衍生字段 | 系统自动计算；无历史数据留空标记"待补" | 计算规则不变，计算人变机器 |
| 人工填写 | AI 预填 + 人工校核（只审标红项） | 字段与界面保留，动作变轻 |

## 六、数据性质定义（FACT / OPINION / INFERENCE）

> 审查建议采纳：所有字段提取结果必须标注三种性质之一。**AI 不能把 INFERENCE 伪装成 FACT**。这是"标准事实层"可信度的根基。

| 性质 | 含义 | 示例 | 允许进入 |
|---|---|---|---|
| FACT | 原文明确陈述的事实 | "太钢宣布 8 月检修 15 天" | ✅ 标准事实层（数据/事件表） |
| OPINION | 文章作者/市场人士的观点 | "市场人士认为价格短期有上涨压力" | ❌ 不得混入事实层；可进分析层并标来源 |
| INFERENCE | AI 基于事实的推断 | AI 判断"检修 → 304 价格可能上涨" | ❌ 不得混入事实层；只进分析/预测层并标 AI 来源 |

**执行规则**：
1. 抽取时每个字段同时带"置信度"和"数据性质"两个元数据
2. 原文出现 → FACT + 置信度高
3. 原文有观点表述 → OPINION（置信度按表述清晰度）
4. 原文无依据、AI 推断 → INFERENCE + 置信度必为低，且该字段自动标红
5. 第二层（数据/事件）只接受 FACT；OPINION/INFERENCE 只能进入第三层（分析/预测）
6. 人工校核时可以"升级/降级"性质（如把 AI 的 INFERENCE 改为 FACT，需在原文中找到依据）

### 6.1 各表字段性质分布（默认）

| 表 | 默认 FACT | 允许 OPINION/INFERENCE |
|---|---|---|
| data_events | E1-E9（ID/标题/类型/时间/主体/简述） | E10 影响方向、E11 影响程度（推断属性，AI 填需标 INFERENCE） |
| data_daily_price 等数据表 | 数值类全部 | I1-I4 影响判断（OPINION/INFERENCE） |
| data_analysis | —（整表为分析） | 全部字段（核心结论=分析师判断，标 OPINION 或 INFERENCE+校核） |
| data_forecast | —（整表为预测） | 全部字段（预测=INFERENCE，人工=OPINION） |
| kg_entities / kg_relations | 实体名（别名归一化后） | 关系（由 INFERENCE 产生需低置信度标记） |

| 中 × 核心 | 黄 | 必须过目 | 可通过，但提示并留痕 |
| 中 × 描述 | 默认 | 不看 | 直接通过 |
| 低 × 任意 | 红 | 必须审核 | **硬拦截，禁止** |

### 6.4 无证据铁律

- **无证据 → 返回 null（留空）**，禁止 AI 猜测补全
- **AI 做推断 → 给值但必标低置信度（红）且性质为 INFERENCE**
- 推断即红、无据即空，没有中间态
- 必填字段为空时系统提示"信息不足"，由人工决定补填或放弃

## 八、明确差异点（有意为之，供洛歌确认）

| # | 差异 | 原因 | 是否影响文档目标 |
