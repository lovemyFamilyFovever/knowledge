## 一、页面总览

结算系统共 4 个页面 + 1 个识别弹窗，全部挂在 `AppLayout` 子路由下（路由定义见 `client/src/router/index.ts`）：

| 页面 | 路由 | 交互重点 |
| --- | --- | --- |
| 结算中心 | `/settlement/workbench` | 待办/指标/图表/预警聚合 + 快速导航（合同管理/采销全链路/财务配置 3 卡） |
| 采销全链路 | `/settlement/sales-pipeline` | 四阶段时间线（销售看收款 / 采购看付款）+ 我的角色列 + **板块/金额/毛利列** + 行展开详情 + **阶段操作区**（签订/收款或付款/交付/开票就地操作） |
| 合同管理 | `/settlement/contract` | 台账（含板块/含税总额/毛利/税率列）+ 详情弹窗（节点/交付双 tab + 财务信息）+ AI 审查/对比 + 新建/编辑/删除（含财务字段） |
| **财务配置** | `/settlement/config/tax-rate` | **（2026-08-25 新增）** 全局税率（销售/采购两档）+ 4 槽板块显示名编辑；入口 = 结算中心快速导航（侧边栏不加） |

## 二、结算中心（入口页）

自上而下布局：

1. **待办统计（3 卡）**：待审批 → 合同管理；到期预警 / 待核销 → 采销全链路（2026-08-18 起，节点操作已并入全链路）。数据源 `getTodoStats`。
2. **业务指标（6 卡，2026-08-25 起）**：本月新增合同额 / 应收总额 / 应付总额 / 结算完成率（带进度条）/ **本月毛利合计** / **本月税金合计**（新 2 卡）。数据源 `getKpi`。布局：待办 3 卡 + 指标 6 卡分两个 section（st-grid-3 / st-grid-6，1440px 下 6 列一行）。
3. **图表区**：左「合同金额趋势」双轴图（柱=金额、线=数量，近 6 月）、右「收付款分布」环形图（已收/待收/已付/待付/逾期）。数据源 `getChartData`，ECharts 按需引入（BarChart/LineChart/PieChart）。
4. **AI 今日待办 + 风险预警（两栏）**：左侧 AI 待办列表（审批/预警/核销三类型图标 + 优先级徽章）、右侧风险预警列表（逾期/金额异常/合作方风险三类型 + 严重度配色）。数据源 `getAiTodayTasks` / `getAiRiskWarnings`（2026-08-24 起由真实数据派生：待签订合同数 / 7 天内到期节点数 / 逾期节点聚合）。
5. **快速导航（3 卡，2026-08-25 起一行）**：合同管理 / **采销全链路**（名称与页面对齐，2026-08-25）/ **财务配置**（新增入口；侧边栏不单独加入口）。

## 三、采销全链路（核心展示页）

### 主表结构

每行 = 一份订单，列：合同（订单编号+服务名称，内置 mock 记录带「示例」徽章）、交易对象（公司名称）、**我的角色**（我是销售方/我是采购方，按合同类型，2026-08-21）、**板块**（徽章，2026-08-25）、金额、**毛利**（sale 绿色，2026-08-25）、负责人、**全链路进度时间线**。表格启用固定列宽（table-layout: fixed，展开行不挤动列，2026-08-25）。

### 四阶段时间线

```
签订（已签订/未签订）→ 收款 / 付款（销售合同：已收款/部分收款/待收款；采购合同：已付款/部分付款/待付款）→ 交付（已交付/交付中/待交付）→ 开票（已开票/待开票，销售合同=销项发票 / 采购合同=进项发票）
```

- 阶段状态机由 `getStages(record)` 计算：已签订/已收款（已付款）/已交付/已开票为 `done`（绿勾），部分收款（部分付款）/交付中为 `active`（蓝时钟），其余 `pending`（灰点）。
- **采销区分（2026-08-21）**：收款阶段按合同类型切换为「收款」或「付款」（sale 看 `getCollectionStats`，purchase 看 `getPaymentStats`）；开票阶段销售合同显示「销项发票」、采购合同显示「进项发票」。
- 收款（付款）阶段附带 `已到款（已付款） / 销售价` 明细，开票阶段附带金额。
- 顶部 4 张统计卡按状态聚合：合同签订 / **收款·付款**（采购合同按已付款统计）/ 交付 / 开票（已完成数量 + 占比进度条）。

### 页头与拍照识别入口（2026-08-12 迁移，2026-08-21 标题改版）

页头左侧为标题「**采销全链路**」+ 副标题「每一笔交易，按你在这笔单里的角色（销售方 / 采购方）展示全流程」，右侧为「拍照识别合同 / 发票」按钮（含 AI 徽章），点击打开 `OcrRecognizeModal` 弹窗。识别入口统一收敛在采销全链路页。路由/menu 名称已统一为「采销全链路」（2026-08-25）。

### 展开详情（点击行）

- **基本信息**：标价、合同签订时间、付款周期（月）、开票状态徽章。
- **四阶段卡片**：每阶段展示日期/负责人/金额（收款·付款与开票卡带金额；收款/开票卡片标题按合同类型显示「收款/付款」「销项/进项发票」）。
- **金额汇总**：合同金额 / 已收金额·已付金额（按合同类型，绿色）/ 收款·付款完成率（进度条）。
- **阶段操作区（仅真实合同可操作，内置 mock 记录只读）**：见第四节「并入全链路的节点/交付/开票操作」。

### 筛选

- 关键词搜索（订单编号/服务名称/公司名称）
- **合同类型筛选（2026-08-21）**：全部合同 / 销售合同（我是销售方）/ 采购合同（我是采购方）
- 状态筛选（进行中=存在 active/warning 阶段；已完成=全部 done）

## 四、管理类页面交互

### 合同管理（ContractManage.vue）

- 列表：合同编号 / 类型徽章 / **板块徽章** / 合作方（首字头像，2026-08-25）/ 金额（不含税）/ **含税总额（exclusive 显示 +税金）** / **毛利** / **税率** / 付款条款 / 结算进度（进度条）/ 状态徽章
- 详情弹窗：合同信息（含签订日期/商品明细 + **业务板块/税率·税金/毛利**财务信息块）+ 收支节点 tab + 交付核销 tab
- AI 审查（`aiContractReview`）：风险点 / 建议 / 关键条款
- AI 对比（`aiContractCompare`）：与同合作方历史合同的相似/差异/建议
- 新建合同弹窗：合同编号 / 合作方（下拉）/ 类型 / **业务板块（必填 4 槽下拉）** / 金额（不含税）/ **成本价（仅 sale）** / **税率（默认按类型带出全局值，可改）** / **含税价·毛利（只读派生）** / 付款条款 / 签订日期 / 商品明细 —— **支持拍照识别预填**（见第五节）
- **合作方自动创建**：拍照识别出的合作方名称匹配不到现有列表时，系统自动调用 `createPartner` 创建（sale 合同→customer，purchase→supplier），填入下拉并给出绿色提示「已自动创建合作方」，无需手动新增

### 收支节点 / 交付核销（已并入全链路阶段操作区，2026-08-18）

原收支节点页（PaymentManage.vue）与交付核销页（DeliveryManage.vue）已删除，对应能力全部收敛到采销全链路展开行的**阶段操作区**（`PipelineStageActions.vue`，仅真实合同可操作）：

- **收款 / 付款**：按合同类型显示节点列表（定金/进度款/尾款，带计划金额；已完成节点显示实收/实付金额）；pending 节点可「登记收款 / 登记付款」（实收/实付金额默认按计划金额、日期默认今天，2026-08-21 起采购合同显示为付款）；无节点时可「新增收款节点 / 新增付款节点」，方向支持 **自动（按合同类型推导：sale→应收 / purchase→应付）/ 应收 / 应付**
- **交付核销**：交付记录列表（交付物/交付日期/验收通过或未通过）+ 「新建交付核销」弹窗（交付物描述/交付日期/验收结果/勾选核销节点；该合同无可核销的待支付节点时提示先新增节点）
- **登记开票**：发票号码/开票金额（默认合同金额）/开票日期，提交后合同标记已开票（`registerInvoice`）；卡片标题按合同类型显示「销项发票」或「进项发票」
- **标记已签订**：合同签订状态为未签订时显示「标记已签订」按钮（`PATCH contracts/:id` 置 `in_progress`）

### 财务配置（TaxRateConfig.vue，2026-08-25 新增）

- **两档税率**：销售税率 / 采购税率（%），默认 13/13；说明「销售=销项税，采购=进项税；新建合同时按类型自动带出；历史合同保持当时快照税率不变」
- **4 槽板块显示名**：changjin（长金工厂）/ internal_1/2/3（板块一/二/三），显示名可自由修改
- 保存调用 `PUT /config/tax-rates` + `PUT /config/boards`，成功后更新前端全局缓存
- 页头样式与采销全链路一致（无左侧图标，2026-08-25）；顶部有「返回工作台」按钮

## 五、AI 拍照识别交互（2026-08-12 新增，2026-08-14 流程优化，2026-08-25 财务字段扩展）

### 入口与弹窗

采销全链路页页头按钮「拍照识别合同 / 发票」→ 打开 `OcrRecognizeModal.vue` 弹窗，四步交互：

```
① 选类型（合同 / 发票）
   │
   ▼
② 上传图片（拖拽 / 点击选择，支持拍照；JPG/PNG/WEBP，≤8MB，前端校验+后端二次校验）
   │
   ▼
③ 开始识别（调 POST /api/settlement/ai-ocr/recognize）
   │
   ▼
④ 核对结果 → 合同：弹窗内直接创建合同；发票：关联合同标记已开票
```

### 识别结果核对（2026-08-25 字段扩展）

- 识别结果以**可编辑表单**展示：
  - 合同：类型 / 编号 / 对方主体 / 签订日期 / **合同金额（不含税）** / **税额（识别值可改）** / **税率（下拉，默认全局）** / **业务板块（下拉）** / 付款条款 / 商品明细
  - 发票：类型 / 日期 / 价税合计 / **税率** / **不含税金额** / **税额** / 代码 / 号码 / 购买方 / 销售方 / 项目摘要
- 右上角显示置信度百分比；「查看 AI 原始识别文本」可展开/折叠
- 识别不到的字段为空、可手动补填

### 确认动作（2026-08-14 起）

| 类型 | 确认行为 | 说明 |
| --- | --- | --- |
| **合同** | 弹窗内**直接创建合同**（`confirmAndCreateContract`）：校验编号+金额 → 合作方匹配现有 partners，匹配不到自动 `createPartner`（sale→customer / purchase→supplier）→ `createContract` 落库（`status: in_progress`，识别即已签订；**2026-08-25 起带 taxRate/taxAmount/board**）→ 跳转 `/settlement/contract` | 省去「跳转新建页 → 再点创建」两步；创建失败在弹窗内提示 |
| **发票** | 弹窗内**选择/匹配合同 → 标记已开票**（`confirmAndMarkInvoice`）：识别结果下方出现「关联合同」下拉（**2026-08-25 起按含税总额自动匹配**——合同 amount 已改不含税，发票价税合计需换算；±1 元容差命中标绿徽章；可手动改选）→ `registerInvoice(contractId, { invoiceNo, invoiceAmount, invoiceDate })` 标记合同已开票 → 跳转 `/settlement/contract` | 发票是外部已有数据（拍照识别录入），系统只做关联标记，不自己开票 |

> 注：
> - 原「合同走 localStorage 预填新建表单」流程已移除（`settlement_ocr_contract` key 不再使用）
> - 原「发票跳转收支节点预填」流程已移除（`settlement_ocr_invoice` key 不再使用，PaymentManage 不再读取），发票改为直接标记合同开票
> - 开票状态在合同详情展示（已开票/待开票 + 发票信息），并驱动采销全链路「开票」阶段（已开票/待开票）

### 状态与异常

- 识别中：按钮转加载态，弹窗显示「AI 正在识别图片，请稍候」
- 失败：显示错误横幅（图片格式/大小/接口错误/JSON 解析失败均有明确文案）
- 识别中禁止关闭弹窗（防误操作中断请求）
