> 最后更新：2026-08-26
> 状态：9 个 service（含 MockStoreService 本地持久化 + ConfigService 全局配置）+ 拍照识别接口（真实 AI）+ 按用户隔离（2026-08-24）+ 财务维度（2026-08-25）

## 一、模块结构

后端模块位于 `server/modules/settlement/`，路由统一挂在 `/api/settlement/*`：

```
SettlementModule（imports: AiModule —— 拍照识别复用 BailianService；exports: Contract/Payment/Delivery/ConfigService —— ERP 后台结算预埋）
 ├── SettlementController    路由与响应包装
 ├── PartnerService          合作方台账 + AI 评分/评级（规则降级）
 ├── ContractService         合同台账 + 详情 + AI 审查/对比（规则降级）+ 财务字段派生（2026-08-25）
 ├── PaymentService          收支节点 CRUD + 收款/付款汇总（getCollectionStats / getPaymentStats，2026-08-20）+ AI OCR/NLP/异常（空壳/规则）
 ├── DeliveryService         交付核销 + AI 异常检查（规则降级；节点数据源=PaymentService，2026-08-14 打通）
 ├── DashboardService        工作台待办/KPI/图表/风险预警（真实聚合，2026-08-19/24/25）
 ├── SalesPipelineService    采销全链路（内置 mock + 实时聚合合同/收款·付款/交付/开票状态；2026-08-21 区分采销 + view 视角过滤；2026-08-24 按用户隔离认领 mock；2026-08-25 映射毛利/税金/含税总额/板块）
 ├── ConfigService           全局配置：税率 + 板块显示名（2026-08-25 新增，持久化 config.json）
 ├── MockStoreService        内存 mock 的本地 JSON 持久化（2026-08-14，接入全部业务数组 + config）
 └── OcrService              AI 拍照识别（百炼 qwen-vl-max，真实 AI；2026-08-25 合同/发票字段扩展）
```

**响应包装统一**：`{ success: boolean, code: number, message: string, data: T }`，由 controller 私有方法 `ok()` 生成。

**鉴权约定**：2026-08-24 起**全部接口走全局 AuthGuard（未登录 401）**，不再有 `@Public()` 白名单。所有 handler 用 `@CurrentUserId()` 取登录用户 memberCode（只认 token 解析的 userContext，防 `x-user-id`/body.userId 伪造）。

**按用户隔离**（2026-08-24）：结算中心只显示当前登录用户的合同订单。Contract 新增 `ownerMemberCode`，创建（手动/OCR）时自动绑定当前用户；无主历史数据由首个访问用户惰性认领（幂等落盘）；节点/交付记录归属随合同。全量方法 `findAllRaw()/getAllNodes()/getAllRecords()` 保留为管理用途（未来 ERP 后台结算系统用，已预埋 SettlementModule exports）。

**财务维度**（2026-08-25 领导评价）：合同 `amount` 改为**不含税**（新增 `priceType: 'inclusive'|'exclusive'`，旧数据默认 inclusive 不重算）；新增 `taxRate`（创建时快照，13%）、`taxAmount`（OCR 识别税额优先，否则派生 = round2(amount × taxRate / 100)）、`costPrice`（销售合同用，手工录入不参与 OCR）、`grossMargin`（派生 = amount - costPrice，purchase=0）、`board` + `boardName`（4 槽枚举：长金工厂/内部三板块）。`DashboardKpi` 加 `monthNewGrossMargin` / `monthNewTaxAmount`。`SalesPipelineRecord` 加 4 字段（毛利/税金/含税总额/板块）。税率和板块显示名通过 `GET /api/settlement/config` + `PUT /api/settlement/config/tax-rates` + `PUT /api/settlement/config/boards` 后台可改。详见 `ConfigService`（持久化 `server/data/settlement/config.json`）。

**数据来源双轨**（2026-08-26 用户明确）：长金线下数据走 AI 拍照识别录入；内部三模块数据在线上数据库，规划导入接口（见 `05-数据真实化路线.md` 第五节）。

## 三、规则降级实现（当前 AI 能力现状）

以下接口在迁移时决定「暂不迁移 AI」，当前为规则计算，后续可逐个替换为百炼调用：

| 能力 | 降级逻辑 |
| --- | --- |
| 信用评分 `credit-score` | 基于注册资本/诉讼次数/经营年限/活跃状态的加权分，含因子拆解 |

| 合同审查 `ai-review` | 规则：金额 >300 万提示风险、未开始状态提示启动风险、进度 0-100 提示关注结算节点 |

## 四、AI 拍照识别（OcrService + BailianService.recognizeImage）

### 调用链路

```
前端 OcrRecognizeModal
  → POST /api/settlement/ai-ocr/recognize { imageBase64, docType }
  → OcrService.recognizeContract / recognizeInvoice
      ├─ 校验 base64（非空、≤8MB）
      ├─ 推断 MIME（jpeg/png/webp 魔数）
      └─ BailianService.recognizeImage(base64, prompt, mime)
           → POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
             model: qwen-vl-max
             messages: [{ role: user, content: [
               { type: image_url, image_url: { url: data:image/jpeg;base64,... } },
               { type: text, text: 识别 prompt }
             ]}]
  → 解析模型输出 JSON → 字段清洗（金额去符号、日期归一化 YYYY-MM-DD、枚举校验）
  → { fields, rawText, confidence: 0.9 }
```

### 识别 Prompt 要点

- 要求「只输出一个 JSON 对象，不要解释文字、不要 markdown 代码块」
- 字段契约（与 `04-AI能力设计.md` 第二节一致，2026-08-25 财务字段扩展）：
  - 合同 → `contractType(purchase|sale) / contractNo / partnerName / signDate / amount(不含税) / taxAmount(税额，仅价税合计时用 价税合计−不含税反算) / paymentTerms / itemsSummary / taxRate(识别不到可用 税额÷不含税金额 反算) / board(4 槽)`——**无 costPrice**（成本价是手工字段，合同上不会印，2026-08-25 移除）
  - 发票 → `invoiceType(special|general) / invoiceCode / invoiceNo / date / amount(价税合计) / exclusiveAmount(不含税金额) / taxAmount(税额) / taxRate / purchaserName / sellerName / projectSummary`——**无 contractNo**（发票图上没有合同编号，prompt 明确要求不要编造）
- **识别不到必须输出 null，不要编造**——保证回填数据干净
- 温度 0.1（低随机性，保证结构化输出稳定）

### 字段清洗规则（OcrService）

| 字段 | 清洗 |
| --- | --- |
| 金额 amount | 去逗号/货币符号，`Number()` 校验正数 |
| 日期 date | 兼容 `2026/07/10`、`2026-07-10`、`2026.07.10`，归一化 `YYYY-MM-DD` |
| 合同类型 contractType | 白名单 purchase/sale，否则 null |
| 发票类型 invoiceType | 白名单 special/general，否则 null |
| 字符串字段 | trim 后空串转 null |

### 错误处理

- base64 为空 / 超 8MB → `BadRequestException` 明确文案
- 模型调用失败 → 记错误日志 + 抛「识别失败」透传
- 模型输出非 JSON / JSON 解析失败 → 「识别结果不是有效 JSON，请重试」
