## 核心决策（用户已确认 2026-08-01）

1. **数据归属**：本地 PGSQL 为主存储，51bxg 仅作迁移源，迁移完成后完全切断读
2. **迁移范围**：9 张源表全迁（用户/会员/投稿/图片/视频/点赞/收藏/关注/分组），橱窗/上架商品/评论/问答不迁
3. **51bxg 读**：迁移完成后完全切断，所有读只走本地
4. **AI 结构化数据**：AI 提取即落库（status=draft）→ 用户确认改 status=confirmed
5. **视频表**：单独建 `plaza_videos`（对应 LD_FLASH）
6. **评论/问答表**：本轮建表壳但不迁数据，新项目从0开始累积

### 1.3 设计目标

- **可迁移**：保留 51bxg 原始 ID（`STAGE_ID`/`MemberCode`/`NEWS_ID`/`FLASH_ID`），支持旧数据平滑迁入。
- **可结构化**：用户自由文本发布 → AI 提取结构化字段 → 用户二次确认 → 落库，供 AI配单/问答/决策消费。
- **可扩展**：为分销佣金、企业信誉、AI智报历史、用户画像预留字段与表位。
- **可切断**：迁移完成后完全脱离 51bxg 读，所有读只走本地。

## 二、设计原则

| 原则 | 说明 |
|------|------|
| 主键用业务可读 ID | 对外用 `xxx_code`（如 `post-20260801-x7y8z9`）；内部关联用 bigserial |
| 保留 51bxg 原始 ID | 所有迁移表带 `bxg_xxx_id` 字段并建唯一索引，类型 bigint（与源库一致） |
| 同步状态显式化 | 迁移表带 `sync_status` / `last_synced_at`，迁移完成后可清理 |
| 软删除优先 | `deleted_at` 可空，物理删除仅在清理脚本中执行 |
| 时间戳统一 | `created_at` / `updated_at` 用 `customTimestamptz`（schema.ts 已定义） |
| 不过度抽象 | 一次性使用的字段不拆表；Phase 3 才用的字段先预留列位但不建独立表 |
| 字段命名 | PGSQL 用 `snake_case` 英文（与 drizzle schema 一致） |

## 六、关键设计决策

### 6.1 数据归属（已确认）

本地 PGSQL 为主存储，51bxg 仅作迁移源。所有迁移表保留 `bxg_xxx_id` + `sync_status` + `last_synced_at`，迁移完成后可清理。**完全切断 51bxg 读**。

### 6.2 视频单独建表（已确认）

`plaza_videos` 对应 LD_FLASH，`plaza_posts.flash_id` 外键关联。保留视频独立性和复用能力。

### 6.3 评论/问答建表壳不迁数据（已确认）

51bxg 生产库无评论表、无问答表（在迁移范围外）。本轮建表壳，新项目从0开始累积。

### 6.4 结构化数据独立表 + status 流转（已确认）

`plaza_post_structured` 独立表，status 流转 `draft → confirmed`，旧数据 `legacy`。

### 6.5 评论回复用邻接表

`parent_id` 邻接表，AI智能伙伴评论层级浅（2级），路径枚举过度设计。

### 6.6 业务可读 ID 生成规则

| 表 | 规则 | 示例 |
|----|------|------|
| plaza_stages | `stage-` + 6位短码 | `stage-a1b2c3` |
| plaza_posts | `post-YYYYMMDD-` + 6位短码 | `post-20260801-x7y8z9` |
| plaza_comments | `cmt-` + 雪花短码 | `cmt-9k8m7n` |


> 短码用 nanoid 或 hashids。

### 6.7 暂不建的表（Phase 3 预留）

| 表 | 原因 |
|----|------|
| `plaza_credit_personal` / `plaza_credit_enterprise` | 信誉体系依赖成交数据，Phase 3 |
| `plaza_transactions` | 成交链路未定，Phase 3 |
| `plaza_commissions` | 佣金模式未定，Phase 3 |
