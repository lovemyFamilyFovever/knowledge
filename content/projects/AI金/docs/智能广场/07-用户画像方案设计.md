## 一、概述

用户画像系统分为三个阶段：

1. **数据采集** — 引导页采集基础信息 + 四大模块采集行为数据
2. **AI提炼** — 按需调用百炼大模型，将基础信息 + 行为数据提炼为结构化标签 + 自然语言摘要
3. **反向赋能** — 画像结果反哺AI问答、AI配单、AI智能伙伴（AI智能伙伴）三个场景

本文所述“首期飞书多维表格、后期 SQL Server”的存储设想已过期。当前画像相关数据使用 PostgreSQL（包括 `users`、`user_profiles`、`user_behavior_records`、`user_recent_views`），不以本段历史设想作为实施依据。

### 2.2 表 B：用户行为记忆表（用户每天一条）

**设计思路**：每个用户每天一条记录，各模块行为以JSON字段存储，节省行数。500个用户每天产生约500行，多维表格38,000行上限可支撑约76天。

| 字段 | 类型 | 说明 |
|------|------|------|
| 用户ID | 文本 | MEMBER_CODE |
| 日期 | 数字 | YYYYMMDD，如 20260801 |
| 问答记录 | JSON | 当天AI问答的提问列表 |
| 配单记录 | JSON | 当天AI配单的需求列表 |
| 测价记录 | JSON | 当天AI测价查询的钢种列表 |
| 作品点击记录 | JSON | 当天在AI智能伙伴点击的作品标题 |
| 点赞记录 | JSON | 当天在AI智能伙伴点赞的作品标题 |
| 评论记录 | JSON | 当天在AI智能伙伴评论的作品标题+评论内容 |
| 关注记录 | JSON | 当天在AI智能伙伴关注的作者 |
| 创建时间 | 数字 | |

**各JSON字段结构示例**：

```json
// 问答记录
[
  {"time": "09:30", "question": "304热轧今日价格走势如何？"},
  {"time": "14:20", "question": "316L和304的价差分析"}
]

// 配单记录
[
  {"time": "10:15", "demand": "需要304冷轧1.0mm无锡交货"}
]

// 测价记录
[
  {"time": "09:35", "steel": "304/2B"},
  {"time": "14:25", "steel": "316L/NO.1"}
]

// 作品点击记录
[
  {"time": "11:00", "title": "304热轧价格反弹信号出现"},
  {"time": "15:30", "title": "某钢厂减产对市场的影响分析"}
]

// 收藏记录
// 收藏记录已合并到点赞记录中（点赞即表示兴趣）
// 另：AI智能伙伴暂无收藏功能，后续可通过作品点击 + 点赞数据综合判断用户偏好

// 点赞记录

[
  {"time": "14:30", "title": "304热轧价格反弹信号出现", "content": "请问这个数据来源是哪里？"}

// 关注记录

  {"time": "10:00", "author": "老陈看钢市", "memberCode": "10086"}
```

## 三、数据采集

### 3.1 采集方式汇总

| 模块 | 采集方式 | 采集时机 | 写入字段 |
|------|----------|----------|----------|
| 引导页 | 前端表单提交 | 首次进入AI智能伙伴 | 写入基础画像表 |
| AI问答 | 后端Controller拦截 | 用户发送问题时 | 行为记忆表.问答记录 |
| AI配单 | 后端Controller拦截 | 用户输入配单需求时 | 行为记忆表.配单记录 |
| AI测价 | 后端Controller拦截 | 用户查询价格预测时 | 行为记忆表.测价记录 |
| AI智能伙伴 | 后端Controller拦截 | 点击/点赞/评论/关注 | 行为记忆表.对应字段 |

### 3.2 引导页

**触发时机**：用户首次进入 `/promo/plaza` 路由时，检查基础画像表的 `是否完成引导` 字段。

**流程**：
1. 前端路由守卫检查是否已完成引导
2. 未完成 → 展示引导页（全屏弹窗/step向导）
3. 必填字段：姓名、企业名称、关注的钢种
4. 可选字段：职位、企业规模、所在地区、业务方向、月采购量
5. 提交后写入基础画像表，标记完成，跳转AI智能伙伴

### 3.3 后端拦截（AI问答/配单/测价）

在现有 Controller 中，已有行为发生的位置追加行为记录写入逻辑：

- **AI问答**（`POST /api/ai/chat`）：在获取到 `question` 参数后，异步写入行为记忆表
- **AI配单**（`POST /api/ai/parse-enquiry-params`）：在解析用户需求后，写入行为记忆表
- **AI测价**（`POST /api/ai/v1/forecast`）：在获取到 `materialName` 参数后，写入行为记忆表

写入时机均为异步非阻塞，不阻塞主流程。

### 3.4 后端拦截（AI智能伙伴）

AI智能伙伴已迁移至AI金自有服务（`server/modules/plaza`），广场业务数据当前存储在 PostgreSQL 的 `plaza_*` 表中；用户画像与行为数据使用 `users`、`user_profiles`、`user_behavior_records`、`user_recent_views` 等表。用户认证通过 `authorization` header + AI金本地 HMAC session token，服务端会话中包含 `memberCode`。

在 `plaza.controller.ts` 中已有接口处追加行为记录写入：

| 接口 | 行为类型 | 记录内容 |
|------|----------|----------|
| `GET /api/plaza/posts?newsId=xxx` | 作品点击 | 当 `newsId` 参数存在时，记录用户点击查看作品详情 |
| `POST /api/plaza/posts/:newsId/like` | 点赞 | 记录用户点赞的作品标题 |
| `POST /api/plaza/posts/:newsId/comments` | 评论 | 记录用户评论的作品标题+评论内容 |
| `POST /api/plaza/members/:memberCode/follow` | 关注 | 记录用户关注的作者 |

**不需要前端埋点**，所有行为在 Controller 层自动拦截。

## 四、AI画像提炼

### 4.1 触发方式

**按需触发**，仅在用户触发以下操作时执行：

1. AI问答 — 用户发送问题后，回答完成前
2. AI配单 — 用户提交配单需求后，评分排序前
3. AI智能伙伴推荐 — 用户进入AI智能伙伴推荐页时
4. 其他指定操作（后续可扩展）

**不触发**的场景：点赞、收藏、点击等轻量交互，只写入行为记录，不触发AI提炼。

### 4.2 提炼流程

```
用户触发AI问答/配单/推荐
        ↓
后端读取行为记忆表(当天+近N天数据)
        ↓
后端读取用户基础画像表(已填字段+已有AI画像)
        ↓
拼接提示词 → 调用百炼大模型
        ↓
输出结构化标签 + 自然语言摘要
        ↓
覆盖更新基础画像表的 AI画像标签 / 摘要 / 更新时间
```

**关键设计**：
- 当前行为触发提炼时，最新行为的数据一并传入，不需等写入Bitable再读
- 提炼结果覆盖更新，不保留历史版本，避免Bitable行数膨胀
- 提炼结果自带缓存效果（覆盖更新），下次再触发时历史画像已就绪

### 4.3 提炼提示词模板

```
你是一位用户画像分析师。根据以下用户的
【基础信息】和【近期行为记录】，提炼出该用户的画像。

基础信息：
{基础画像表字段}

近{N}天行为记录：
{行为记忆表数据}

输出格式：
1. 结构化标签（JSON）：{身份, 关注钢种, 业务偏好, 活跃度, ...}
2. 自然语言摘要（200字以内，自然流畅的语气）
```

## 五、反向赋能（首期3个场景）

### 5.1 AI问答 → 内容推荐

**触发时机**：流式回答结束后，SSE推送 `recommend` 事件。

**实现**：
```json
{
  "type": "recommend",
  "items": [
    {"title": "304热轧出口退税政策调整影响", "reason": "根据您关注的304钢种推荐"},
    {"title": "不锈钢现货市场最新报价", "reason": "您近期多次查询价格行情"}
  ]
}
```

前端在回答底部展示推荐卡片，用户点击可跳转相关内容。

### 5.2 AI配单 → 个性化适配分析

**触发时机**：配单评分排序完成后。

**实现**：结合用户画像（企业规模、所在地区、关注钢种、月采购量等），在配单结果返回的点评区追加一段个性化分析：

> "根据贵企业的采购需求（304冷轧，月均采购约500吨，无锡地区），本次匹配结果中 A 供应商的304/2B 1.0mm 无锡仓库，¥12,800/吨，库存充足，建议优先考虑。B 供应商价格低¥200但佛山仓库，到无锡运费约¥80/吨，综合性价比略低。"

**可扩展的适配维度**：

| 画像维度 | 配单适配策略 |
|----------|--------------|
| 企业规模(大) | 优先推荐大钢厂直供，关注长期合作 |
| 企业规模(小) | 推荐贸易商，关注灵活性和价格 |
| 所在地区 | 优先推荐本地仓库，降低物流成本 |
| 关注钢种 | 优先展示匹配钢种的商品 |
| 月采购量 | 高采购量关注库存充足度，低采购量关注最小起订量 |
| 历史配单 | 推荐历史合作过的供应商 |

### 5.3 AI智能伙伴 → 个性化推荐

**触发时机**：用户进入AI智能伙伴推荐页。

**实现**：后端提供一个推荐接口，根据画像标签筛选作品：
- 匹配用户关注钢种的作品优先展示
- 匹配用户业务方向（采购/销售/行情）的作品靠前
- 不匹配但热门的作品靠后展示

## 七、技术要点

### 7.1 行为记录写入

- 后端拦截：在现有 Controller 中追加异步写入，不阻塞主流程
- AI智能伙伴行为：在 `plaza.controller.ts` 的点赞/评论/关注/查看详情接口中追加写入
- 当日记录不存在则创建，已存在则追加JSON数组

### 7.2 引导页检测

- 前端路由守卫检查 `用户基础画像表.是否完成引导`
- 可以通过 `GET /api/behavior/onboarding-status` 接口查询
- 未完成：展示引导页，完成后跳转AI智能伙伴

### 7.3 AI提炼

- 提炼结果覆盖更新，不保留历史版本
- 每次提炼前读取最新行为数据（当天+近N天）
- 百炼大模型调用失败时：降级处理，跳过画像更新，不阻塞主流程

### 7.4 历史存储限制（不适用于当前 PostgreSQL）

- 飞书多维表格单表最大行数：38,000行
- 行为记忆表：500用户 × 每天1条 ≈ 500条/天，约76天写满
- 基础画像表：每个用户1条，无行数压力
- 满后策略：定期归档旧数据，或提前迁移至SQL Server

## 八、行为模块当前 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/behavior/onboarding-status` | GET | 查询当前会话用户是否已完成引导 |
| `/api/behavior/onboarding` | POST | 提交当前会话用户的引导资料 |
| `/api/behavior/onboarding/nickname-parse` | POST | 使用 qwen-turbo 解析自然语言昵称，失败时由前端本地规则兜底 |

当前没有 `/api/behavior/profile` 接口；画像展示通过 VIP 个人资料接口和上述引导状态数据组合完成。AI问答、配单、测价及广场互动的行为记录由各自模块异步写入行为表。
