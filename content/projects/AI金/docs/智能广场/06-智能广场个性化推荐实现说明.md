# 智能广场个性化推荐实现说明
> 最后更新：2026-08-26

> 实施范围：第一版规则型个性化推荐  
> 数据库变更：无，不新增表、不修改字段

## 一、目标与边界

智能广场“推荐”流由原来的纯时间倒序升级为基于用户画像与近期行为的个性化排序。第一版仅复用 PostgreSQL 现有数据，不在请求期间调用百炼，不引入向量库、协同过滤或推荐曝光表。

非推荐流、作品详情、搜索、我的作品、点赞、收藏和观看历史继续沿用原查询逻辑。

## 二、使用的数据

| 数据表 | 推荐用途 |
|---|---|
| `user_profiles` | 高频钢种、AI 画像标签、画像摘要、行为标签 |
| `users` | 用户填写的关注钢种、业务方向和地区 |
| `user_behavior_records` | 近 30 天问答、配单、测价和广场点击主题 |
| `user_recent_views` | 浏览兴趣与已看内容降权 |
| `plaza_likes` | 点赞内容兴趣，权重 4 |
| `plaza_favorites` | 收藏内容兴趣，权重 5 |
| `plaza_comments` | 评论内容兴趣，权重 3 |
| `plaza_follows` | 关注作者偏好 |
| `plaza_posts` | 候选作品内容、热度与发布时间 |

## 三、请求流程

推荐请求继续复用广场列表接口：

```text
GET /api/plaza/posts?feed=recommended&page=0&pageSize=20&refreshSeed=xxx
```

同一轮下拉分页保持同一个 `refreshSeed`；用户点击顶部“推荐”刷新时生成新值。服务端将用户、日期、刷新批次和作品 ID 哈希为稳定探索分，因此刷新可以调整相近候选的顺序，同时分页不会随机跳动。

处理步骤：

1. 并行读取最多 400 条候选作品、用户画像和近期行为。
2. 候选池由 75% 最新公开作品和 25% 热门公开作品组成并去重。
   历史迁移作品的 `visibility` 为空，按原广场规则兼容为公开；明确标记为 `private` 或 `friends` 的作品不进入推荐候选池。
3. 将收藏、点赞、评论和浏览对应的作品还原为钢种、地区、业务主题及作者偏好。
4. 对候选作品计算画像匹配、行为匹配、作者关系、热度、时效和探索分。
5. 对近期已看、已点赞或已收藏作品降权，排除用户自己发布的作品。
6. 通过贪心重排降低连续同作者、同钢种内容。
7. 只对当前页作品查询图片、视频、作者和互动状态。

## 四、评分规则

有有效画像或行为信号时：

```text
推荐分 =
  画像内容匹配（最高 35）
+ 近期行为匹配（最高 25）
+ 作者偏好（最高 10）
+ 内容热度（最高 10）
+ 发布时间（最高 10）
+ 稳定探索分（最高 5）
- 已看与重复内容惩罚
```

用户没有画像或未登录时自动降级：热门 35 分、时效 55 分、探索 10 分。画像或任一行为查询失败时，广场列表仍由原有三次重试机制处理，不改变接口错误约定。

观看降权规则：24 小时内减 30 分、7 天内减 15 分、30 天内减 5 分。已经点赞或收藏的作品额外减 8 分，但不彻底排除，避免用户无法重新找到感兴趣的内容。

## 五、代码位置

| 文件 | 职责 |
|---|---|
| `server/modules/plaza/plaza-recommendation.service.ts` | 画像整理、评分、降权、多样性重排和分页 |
| `server/database/plaza.repository.ts` | 候选池与近期互动的参数化数据库查询 |
| `server/modules/plaza/plaza.service.ts` | 将 `feed=recommended` 接入现有内容组装链路 |
| `server/modules/plaza/plaza.controller.ts` | 接收并限制 `refreshSeed` |
| `client/src/api/plaza.ts` | 发送推荐类型和刷新批次 |
| `client/src/pages/PlazaShellPage.vue` | 推荐刷新时更新批次并保持分页稳定 |

## 六、已知限制

1. 没有新增曝光表，因此第一版不能准确计算推荐曝光点击率，也不能严格排除“用户看到但未打开”的内容。
2. 推荐使用规则与关键词匹配，暂不包含语义向量相似度。
3. 候选池上限为 400 条，以首页响应速度优先；更早且热度不高的历史作品通常不会进入候选池。
4. 推荐权重集中定义在推荐服务中，后续应结合线上点击、收藏和评论数据继续调整。
