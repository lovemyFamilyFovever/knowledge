## 一、当前最大的结构性问题：数据平台与应用平台的边界

SOP 里明确标了「待确认」：AI智能伙伴要成为统一自有数据归集平台，但现在数据散在四个地方：

- PGSQL：AI问答、价格历史
- 飞书多维表格：秀店铺装修、部分配置
- 百炼知识库：AI问答知识文档
- API 代理：51bxg、秀吗商品

老板说 AI智能伙伴 = 私域（写入端、数据生产），AI金 = 公域（读取端、数据消费）。这个定位清晰，但技术上意味着：**AI智能伙伴是写入端，AI金是读取端**。

**判断：在动手写任何代码之前，需要先和负责AI智能伙伴平台重构的同事对齐数据模型。** 不是对齐技术细节，而是对齐「AI智能伙伴存什么字段、AI金需要什么字段」。这个对齐如果拖到后期，两边都写完了发现对不上，返工成本极高。具体要做的事：

1. 输出一份「AI金需要的数据字段清单」给AI智能伙伴团队
2. AI智能伙伴团队确认这些字段在采集端如何产生
3. 双方对齐字段命名、单位、口径（参考SOP第7章数据标准）

## 二、GU（用户画像）是系统的入口卡点

老板三问的第一问就是「我是谁」。GU 没定义，AI智能伙伴就没有采集目标，AI 配单就没有匹配依据。

**建议当前阶段重点盯一件事：推动 GU 字段定稿。** 至少明确：

- 必填字段：身份（买/卖/管理）、经营钢种、所在城市
- 行为字段：浏览记录、发布频率、互动频次
- 信誉字段：企业信誉、个人信誉分开（老板新提的）

依赖链：GU 定了 → AI智能伙伴知道让用户填什么 → AI金知道匹配什么维度。GU 卡住，后面全卡住。

补充：7月30日会议已定画像的采集方式——首次进入可选可跳过，系统按3天行为自动完善。这解决的是「怎么采集」，GU 字段定稿解决的是「采集什么」。两者互补，字段定义要先行。

## 三、内容发布机制：自由文本 → 结构化数据

老板要求「每天发一条自由文本的销售信息」（产品、产地、重量、价格、交货地）。对 AI 配单来说，自由文本需要提取才能变成可匹配的结构化数据。

两种路径：

| 路径 | 做法 | 风险 |
|------|------|------|
| A. AI 提取 | 用户发自由文本 → AI 提取材质/规格/价格/产地 → 结构化存储 | 准确率非100%，需容错 |
| B. 半结构化 | 大输入框 + AI 辅助识别 + 用户二次确认（7/30会议已定此方案） | 多一步确认，体验稍重 |

7月30日会议已经选了 B 路径，方向是对的。**需要关注的点是：二次确认后的结构化数据存在哪、怎么和配单引擎对接。** 如果AI智能伙伴存一套、AI金又存一套，数据就会再次分裂。

## 四、企业信誉 + 个人信誉分开：一个被低估的设计

老板说「企业信誉和个人信誉单列，不重合计」。这是一个巧妙的设计：

- 个人在AI智能伙伴不展示公司名，只展示个人 IP
- 成交时可以看到背后公司 → 公司信誉作为背书
- 个人跳槽？个人信誉跟着走，公司信誉留在公司

数据模型里需要两条信誉链：

```
个人信誉 = 个人发布频率 + 成交记录 + 互动活跃度 + AI金GU评分
企业信誉 = 企业资质 + 企业成交记录 + 企业履约率
```

**两者关联但不合并。** 这是 B2B 行业的差异化设计——不锈钢行业买家最终信的是「货」不是「人」，和抖音/小红书式的个人网红模式本质不同。

## 五、AI智能伙伴卖别人货的佣金模式：未来最大变量

老板提了「可以卖自己发布的货，也可以卖秀吗的其他人的货，提取佣金」。本质是一个**分销网络**：

```
A 在AI智能伙伴发布304热轧 → B 在AI智能伙伴看到，转发到自己的AI智能伙伴卖 → 成交后 B 抽佣金
```

如果跑通，AI智能伙伴就不只是信息平台，而是**交易撮合 + 分销裂变**。但目前秀吗的商品数据能不能被AI智能伙伴调用、佣金比例怎么定、结算流程怎么走，都还没讨论。

**建议标记为 Phase 3，不急于在原型阶段落实，但架构上预留扩展空间**（比如商品要有「来源标识」字段，区分自营/代销）。

## 六、分阶段优先级建议

不考虑原型（由其他同事负责），从统筹角度：

### Phase 1（现在就做）：对齐数据模型
- 和AI智能伙伴团队对齐用户数据字段
- 和 GU 需求对齐画像维度
- 输出「AI金需要的数据字段清单」给AI智能伙伴团队

### Phase 2（并行推进）：核心引擎就绪
- AI 配单匹配引擎确认 GU 维度
- AI智能伙伴发布内容的 AI 结构化管线搭建
- 搜索/问答新建百炼应用（7/30会议决策）

### Phase 3（集成验证）：数据流跑通
- AI智能伙伴发布一条数据 → AI金能读到 → AI配单能匹配 → AI问答能引用
- 端到端验证，不追求量，追求链路通

### Phase 4（扩展）：佣金 + 分销 + 智能采销
- 秀吗商品可被AI智能伙伴转发
- 成交链路 + 佣金结算
- 智能采销接入

## 七、先定义成功标准

SOP 反复强调「价值树」和「验收指标」。建议这一轮规划就定一个简单可衡量的标准：

> 一个用户在AI智能伙伴发了一条「304热轧 4.0×1500 太钢产 无锡天洋库 ¥15,800」，过了多久、经过几步，另一个买家在 AI金里能看到这条信息并联系上他？

这个端到端时间就是整个系统的核心体验指标。现在是 0（数据未打通），目标是「实时」。
