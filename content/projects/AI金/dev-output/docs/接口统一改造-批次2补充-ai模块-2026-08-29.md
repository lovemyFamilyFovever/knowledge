# 接口统一改造 · 批次2补充 · ai 模块成功/失败信封统一

日期：2026-08-29
范围：`server/modules/ai/ai.controller.ts`（2067 行）
目标：把 ai 模块路由处理器原本的 `{success,data} / {success,error}` 响应统一为共享信封 `{code, message, data}`（成功 `ok()` / 失败 `fail()`），成功信封 `code===0`、失败信封 `data:null`。

## 背景

ai 模块体积大（2067 行）、包含 SSE 流式响应，且本轮之前已存在 2 个基线用例失败（`PipelineService` 三参签名），故单独作为小批次推进，与整体铺开隔离降风险。

前端 `aiRequest`（`client/src/api/ai.ts` L157-161）此前已兼容双格式：
`if (result.success === false || (result.code !== undefined && result.code !== 0)) throw ...`
改造后后端返回 `ok()/fail()` 信封，字段命中 `code===0` / 失败 `message`，前端无需改动。

## 改动内容

### 后端 `ai.controller.ts`
- 新增导入：`import { ok, fail } from '../../../shared/envelope';` 与 `import type { ApiEnvelope } ...`。
- 将**路由处理器**（带 `@Get/@Post/@Delete` 装饰器、且返回值即 HTTP 响应体）的返回点统一：
  - `return { success: true, data: X }` → `return ok(X);`
  - `return { success: false, error: '文案/msg/err.message' }` → `return fail(...);`
- 共 77 处返回点切换；另归一本 `importChatHistory` 未登录分支 `{success:false, error, skipped:0}` → `fail('请先登录后再导入历史记录')`（失败路径 `skipped` 对前端无效，前端 `aiRequest` 失败即抛错）。
- 语义与 HTTP 状态码保持不变。

### 保留不动（非 JSON 信封）
1. SSE 流式端点：`chat`、`plaza-search-insight/stream`、`v1/forecast/stream`（`res.write`/`res.end` 写帧，非 JSON 信封）。
2. `@Res()` 调试端点：`test`、`auto-test`（`res.json({success, logs, ...})` 调试信息）。
3. 私有辅助方法：`plazaSearchFallback`（其返回 `{success,data}` 被内部调用方读取，不属于路由响应信封）。
4. 结果/数据对象内部的 `success` 字段（如 `result.success` 导入记录、SSE `res.status(400).json` 内部 success）。

### 类型注解
- `v1/forecast`、`v1/forecast/export` 的显式返回类型由 `Promise<{success,data?,error?}>` 修正为 `Promise<ApiEnvelope<...>>`，保证 type 检查通过（仅类型调整，未动业务逻辑）。
