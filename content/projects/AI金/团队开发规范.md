# 团队开发规范

## 版本控制（SVN + git 双轨）

团队当前使用 SVN 与 git 双轨版本控制：

| 工具 | 角色 | 用途 |
|------|------|------|
| SVN | 团队协作主仓库 | 发布/共享，团队同步主分支 |
| git | 本地开发版本控制 | commit 详细日志，用户后期统一 push |

### 双轨工作流

1. 本地用 git 提交：每个功能一个 commit，commit message 遵循规范（见"提交规范"章节）
2. 定期同步到 SVN：将本地完成的特性集合同步到 SVN 主仓库供团队共享
3. 拉取代码：优先从 SVN 拉取最新代码，再在本地用 git 跟踪改动

### 不应提交的文件

以下文件已配置 `svn:ignore`，不要手动 `svn add`：

| 类别 | 文件/目录 | 说明 |
|------|-----------|------|
| 依赖 | `node_modules/` | `npm install` 安装 |
| 构建产物 | `dist/` | `npm run build` 生成 |
| 缓存 | `*.tsbuildinfo` `.eslintcache` | 自动生成 |
| 日志 | `logs/` `*.log` | 运行时产生 |
| IDE | `.vscode/` `.idea/` | 个人设置 |
| AI | `.trae/` `.agent/` | AI 工具缓存 |

### 配置文件变更规则

1. `package.json`、`vite.config.ts`、`nest-cli.json`、`eslint.config.js` 等关键配置文件的改动，应在 commit message 中注明原因
2. `package-lock.json` **必须与** `package.json` 一起提交，不可忽略
3. 依赖变更应单独 commit，不要混入业务代码
4. 提交前检查改动了哪些文件

### 如果有成员安装新依赖，其他同事执行

```bash

npm install                           # 其他人拉取代码后执行
```

## 开发环境

### Node 版本一致性

在项目根目录创建 `.nvmrc`（已提交）：

```
22.23.1
```

每人安装 [nvm-windows](https://github.com/coreybutler/nvm-windows)，进入项目后执行：

```bash
nvm use
```

`package.json` 中已配置 `engines` 字段，`npm install` 时版本不匹配会警告。

### 本地环境配置

1. `.env` **不要提交**

## AI 工具使用约束

1. 不要让 AI 自动修改 `package.json`、`vite.config.ts`、`nest-cli.json`、`eslint.config.js` 等配置文件
2. AI 生成的测试文件放到独立目录，不要提交到主干
3. AI 生成的临时日志、调试输出不要提交
4. 提交前检查是否有 AI 意外引入的文件

## 提交规范

### SVN commit message

- 依赖变更：`chore: 新增 xxx 依赖 @xxx/xxx`
- Bug 修复：`fix: 简要说明`
- 功能：`feat: 简要说明`

### git commit 规范

git 提交用于本地开发记录，每个功能一个 commit，便于追溯。

**格式：**

```
type(scope): subject
```

**type 取值：**

| type | 含义 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `refactor` | 重构（无功能变化） |
| `docs` | 文档变更 |
| `chore` | 构建/依赖/杂项 |

**scope 取值（模块名）：**

`vip` / `auth` / `ai` / `client` / `server` / `proxy` / `erp` 等

**示例：**

```
feat(vip): 新建 VIP 套餐与权限模块（阶段二）
fix(auth): 修复登录态过期未跳转问题
refactor(ai): AI 测价改造为 SSE 流式响应
docs(client): 补充 VIP 页面路由说明
```

### 提交前检查清单

- [ ] 没有误提交 `node_modules/`、`dist/`、`*.log`
- [ ] `package.json` 的改动是有意为之
- [ ] 运行 `npm run type:check` 无 TypeScript 错误
- [ ] `svn diff` 确认只包含预期改动的文件
