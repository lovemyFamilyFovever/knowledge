## 任务内容（整段粘贴给飞书大模型）

请帮我导出飞书妙搭**开发库（dev）**的完整数据库结构（不含任何表数据），并输出**权威 JSON** 到沙箱代码目录。

### 一、权威 JSON 输出要求

JSON 结构必须按 PostgreSQL 系统目录的真实口径（`information_schema` / `pg_catalog`），**不要凭记忆编造**：

```jsonc
{
  "schema": "workspace_xxx",      // 业务表所在 schema
  "export_time": "2026-08-25T..",
  "table_count": 40,               // 与下方 tables 数组长度一致
  "tables": [                      // 每张业务表一个对象，按表名升序
    {
      "name": "users",
      "comment": "用户主表",
      "columns": [                 // 按 ordinal_position 升序
        {
          "name": "id",
          "data_type": "uuid",
          "udt_name": "uuid",
          "char_max_length": null, // varchar/text 的长度；非字符类型填 null
          "is_nullable": false,
          "column_default": "gen_random_uuid()",
          "ordinal_position": 1,
          "comment": "主键"
        }
      ],
      "primary_key": ["id"],
      "unique_constraints": [
        { "name": "..", "columns": [".."], "definition": "CREATE UNIQUE INDEX ..." }
      ],
      "indexes": [
        { "name": "..", "columns": [".."], "definition": "CREATE INDEX ..." }
      ],
      "has_rls": false,
      "audit_columns": ["_created_at", "_updated_at", "_created_by", "_updated_by"]
    }
  ],
  "all_relations_audit": [         // 全 schema 表清单，用于防漏表
    { "schema": "workspace_xxx", "table": "users" }
  ]
}
```

口径要点：
- **`data_type` / `udt_name` 用真实值**；`varchar` 有长度就填 `char_max_length`；`ARRAY` 用真实元素类型（如 `_text`、`_varchar`），`bytea`、`jsonb` 如实标注。
- **索引/唯一取 `pg_indexes.indexdef`** 原样（含排序方向、部分索引 `WHERE`、唯一条件）；主键/唯一同时用 `pg_constraint` 核对，避免重复或遗漏。
- 判断**是否非空**与实际 `column_default`，不要臆断。
- **RLS 状态**用 `pg_class.relrowsecurity = true` 判断。
- 平台约定的 4 个审计列（`_created_at/_updated_at/_created_by/_updated_by`）凡存在都列出。

### 二、必需的全 schema 表清单（防漏表，务必输出）

请执行下面语句，把**所有非系统 schema** 的表都列进 `all_relations_audit`：

```sql
SELECT n.nspname AS schema, c.relname AS table, c.relkind
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE c.relkind IN ('r','p')
  AND n.nspname NOT LIKE 'pg\_%'
  AND n.nspname <> 'information_schema'
ORDER BY n.nspname, c.relname;
```

### 三、重点确认项（写在这份 JSON 旁边或回复里明确说明）

- **采集域是否存在**：`dict_*`、`data_*`、`kg_*`、`import_*` 这些采集表在 dev 库是否存在？以及 `batch_daily_token`、`erp_user_account`、`report_user_skill`、`price_hongwang`、`price_kucun`、`price_stock_*`。若不在 `all_relations_audit` 里就是**真缺失**，请明确标注"缺失"；若只是在别的 schema，请给出所在 schema。

### 四、执行约束（miaoda / 平台规范）

- 只用只读查询，**不改任何数据与结构**。
- 表名不带 schema 前缀；`SELECT` 用标准 PG 语法；`varchar` 长度、分号、`--` 注释遵循 PG。
- `SELECT` 单次返回 ≤ 1000 行，结果大就**分批**（按表或按 chunk）。
- 生成的文件：写入沙箱代码目录（如 `docs/feishu-dev-structure.json`），并在回复中附上：`table_count`、`all_relations_audit` 里表总数、以及采集域是否缺失的结论。

### 五、online 库重复

生成完 dev 后，请用 `--env online` 对**线上库**再完整跑一遍同样流程，输出 `docs/feishu-online-structure.json`。
