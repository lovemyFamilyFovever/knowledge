# 现代前端工程化完全指南


> 📌 **导航**：本文是 **现代前端工程化完全指南** 词条，属于 frontend-frameworks 术语集。相关枢纽：[[GraphQL从入门到精通]]、[[WebAssembly完全指南]]、[[Web性能优化]]、[[现代前端工程化完全指南]]。

## 定义

**一句话定义：** 现代前端工程化是四条链路的合称——依赖怎么装（包管理与 workspace）、代码怎么合（构建与转换检查）、产物怎么增量交付（任务图与缓存）、组件怎么对外发布（组件库）；本页由一份六节巨型汇编收敛成能力索引枢纽，各段机制归口已有专条，本页只独家承载新一代打包器、依赖落盘差异、缓存接线、规范门禁与状态管理的第三范式。

**通俗类比：** 像工厂的车间导览图：原料入库、加工、质检、装配各在一个车间，图纸只标"这道工序去哪个车间"，怎么开车写在各车间的词条里。

## 为什么需要它

原稿 19016 字 / 22 围栏 / 985 行配置，讲的几乎不是"新工具"而是"接缝"：工程化真正的失效信号全出现在两处交界——loader 与 plugin 的先后、锁文件与 workspace 的解析、ESLint 与 Prettier 抢同一个字符、缓存键与依赖图对不对得上。这些接缝没有单独的工具词条，所以本页留作索引与接线图；机制本体一律双链出去，不在此重复承载。

1. **新一代打包器分两路**：Turbopack 走增量计算（Rust、只算变化的部分、函数级缓存与按需编译，原稿引 Vercel 口径称比 Webpack 快 700 倍），Rspack 走兼容路线（Rust 重写却保留 Webpack 的 loader/plugin 生态，用 `builtin:swc-loader` 顶替 babel-loader）；判据是迁移成本——存量重配置项目换引擎看 Rspack，新起 Next.js 才谈 Turbopack，Webpack/Vite 本体见 [[JavaScript 构建工具（Webpack 与 Vite）]]。
2. **包管理器的差异全在依赖怎么落盘**：概念与锁文件口径见 [[包管理器与构建工具]]，本页只补原稿 §2 的三条实测：pnpm 用内容寻址存储加硬链接让同一版本只存一份，且默认禁止访问未声明依赖；yarn v2+ 的 Plug'n'Play 干脆取消 node_modules（`nodeLinker: node-modules` 可退回旧布局）；npm 到 v7 才有 workspaces。
3. **Monorepo 的收益来自任务图与缓存，不是目录**：仓库组织与共享代码见 [[前端工程化]]；原稿 §3 的 Turborepo/Nx 实操全在 `dependsOn: ["^build"]` 加 `outputs` 声明出的依赖图、以及按内容哈希命中的可共享远程缓存（Nx 侧是 `cacheableOperations`，dev 这类长驻任务要标成不缓存），缺这两样时 Monorepo 只是把 N 个仓库塞进一个目录每次全量构建。
4. **规范要成为门禁才算体系**：ESLint 与 Prettier 的分界（管对错 vs 管格式）见 [[代码规范与转换工具链（Babel · ESLint · PostCSS）]]；原稿 §4 独家是 CSS 侧的 Stylelint（recess-order 管属性顺序、`selector-class-pattern` 用正则管类名、把 `no-descending-specificity` 降为 warning）与 lint-staged + husky 把三套检查按文件类型分派到 pre-commit——只在改动文件上跑 `--fix`，规范才从文档里的约定变成过不去的钩子。
5. **状态管理的第三档是"按值订阅"**：两种范式与选型见 [[前端状态管理]]；原稿 §6 独家补一档——Redux Toolkit 用 `createSlice` + `createAsyncThunk` 把 pending/fulfilled/rejected 三态与实体表结构写成样板，Zustand 用中间件栈（devtools/persist/immer）拼 store 并以 `partialize` 挑要落盘的字段，Jotai 的原子与 Solid 的 Signal 把"原子 + 派生"当最小订阅单位，React 侧靠 `useSyncExternalStore` 落同一语义：订阅粒度决定谁跟着重渲染。
6. **组件库是这条链路唯一对外交付的一段**：设计令牌三层、变体函数、运行时换肤与 Storybook 契约面收在新词条 [[组件库开发与设计系统]]，它是构建、规范、Monorepo 三段同时生效的地方。

## 具体示例

一次典型接线（原稿六节的顺序）：`pnpm init -w` 起 workspace → 新应用用 Vite，存量 Webpack 项目按第 1 条判据决定是否换引擎 → ESLint/Prettier/Stylelint 三份配置只管定义写法，husky 的 pre-commit 挂 lint-staged 让改动文件必须过 → Turborepo 把 build/test/lint 写进 `turbo.json` 的 pipeline 并共享远程缓存 → 组件库以设计令牌与变体 API 独立发版，应用只消费语义令牌 → 状态管理先问"要不要全局"再选范式。每一跳只查一个词条。

## 何时用与何时不用

- **用**：多包多端、团队协作为主、样式与规范需要跨人跨包保持一致时，按上表逐段接线（组织侧判据见 [[前端工程化]]）。
- **不用**：单页活动页一个 HTML 加 CDN 就够；工具链数量应与团队规模匹配——四套检查、三套打包器同时上，收益会被维护成本吃掉。

## 优劣与代价

✅ 接缝被显式化：依赖布局、任务图、门禁各有配置，"我这能跑"变成可复现的确定流程。
✅ 缓存与增量把等待摊薄，规范前置到提交动作，review 可以只谈设计。
⚠️ 工具链本身是负债：每多一个环节就多一处版本与配置漂移，升级要按链路整体评估。
⚠️ 索引型结构的代价是"没有一处讲全"——本页只承载接线与判据，深入必须跳走。

## 与相关概念的区别

- **vs [[前端工程化核心概念]]**：那条是概念侧的四轴索引（构建 / 转换与检查 / 样式组织 / 交付），本页是交付链路的接线与独家判据（新一代打包器、依赖落盘、任务图、门禁、订阅粒度），二者不重复承载。
- **vs [[构建流水线与 CI-CD 工具]]**：那边管仓库到环境的自动交付，本页管仓库内的依赖与产物怎么长出来。
- **vs [[Web性能优化]]**：工程化决定产物是什么，性能侧决定产物怎么被加载（体积口径见 [[前端构建优化策略]]）。

## 常见误区

- 以为换上 Vite 或 Rspack 之后生产构建也会同样变快。
- 以为装了 ESLint 团队风格就自动统一，Stylelint 与提交钩子只是锦上添花。
- 以为用了 Monorepo 工具就有增量构建，不必声明 dependsOn 与 outputs。

## 面试速答

> 🎯 工程化四条链路：依赖（pnpm 内容寻址 + 锁文件）、构建（Vite 开发态不打包、Rspack 兼容迁移、Turbopack 增量）、规范（ESLint 对错、Prettier 格式、lint-staged 成门禁）、组织（Monorepo 靠任务图与缓存），末端是组件库对外交付。
