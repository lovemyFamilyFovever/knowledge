# Next.js 缓存与再验证

> 📌 **导航**：本文是 **Next.js 缓存与再验证** 词条，属于 frontend-frameworks 术语集。相关枢纽：[[Next.js全栈开发实战]]、[[缓存策略]]。

## 定义

**一句话定义：** Next.js 缓存分三层——数据缓存（`fetch` 结果、跨请求持久）、完整路由缓存（构建时产出的静态 HTML/RSC 载荷）、路由缓存（客户端会话内缓存已访问路由的 RSC 载荷）；`revalidatePath`/`revalidateTag` 是按需让前两层失效的开关，于是"缓存"与"数据正确性"被绑定在一起。

**通俗类比：** 三层像仓库（数据缓存）、成衣货架（路由静态 HTML）、随身背包（客户端路由缓存）——改了布料（数据库）得同时通知"重新上架"和"回收旧款"，否则顾客背包里还是旧货；revalidate 就是那张"这批号下架"的调度单。

## 为什么需要它

把内容尽量推到构建时与边缘（CDN）能换来最快首屏与最低源站成本，但真实数据会变。若只有缓存没有失效，用户会长期读到旧页面——这类"陈旧"故障比"慢"更隐蔽也更致命。Next.js 因此把三层缓存与两种再验证（按路径、按标签）做成一体，目标是"该静态的静态、该实时的一次别漏"；通用缓存概念（穿透/击穿/雪崩、一致性）见 [[缓存策略]]。

## 核心机制

| 层 | 存什么 | 位置 | 失效方式 |
|---|---|---|---|
| 数据缓存 | `fetch` 响应 | 服务端、跨请求持久 | `revalidate` 秒数 / `revalidateTag` |
| 完整路由缓存 | 静态 HTML + RSC 载荷 | 构建产物 / CDN | 重新部署、`revalidatePath/Tag`、用到动态 API |
| 路由缓存 | 会话内已访问路由的 RSC 载荷 | 浏览器内存 | 约 5 分钟（静态）/30 秒（动态）过期、Server Action 后全清 |

- **默认缓存 fetch**：`fetch` 结果默认进数据缓存；`{ cache: 'no-store' }` 强制每次请求重取（SSR 语义），`{ next: { revalidate: N } }` 每 N 秒再生（ISR 语义）。
- **revalidatePath vs revalidateTag**：前者按路由失效、使该路径的完整路由缓存作废并在下次请求时按声明再验证；后者按标签做更细粒度失效（一次改动只掀相关数据，如所有含 `products` 标签的查询）。写操作成功后要显式调用，否则改了库缓存仍返回旧值。
- **隐式失效**：一旦路由用到 `cookies()`/`headers()` 或 `no-store`，它落出完整路由缓存、每次请求动态渲染（渲染策略见 [[Next.js App Router 与渲染策略]]）。
- **边缘分发**：完整路由缓存产物可缓存到 CDN（见 [[内容分发网络]]），因此再验证在多实例部署下需保证传播一致。

## 具体示例

```tsx
const data = await fetch(url, { next: { tags: ['products'] } })  // 打标签取数
// 改库之后（常在 Server Action 末尾）：
revalidateTag('products')   // 只失效带此标签的数据缓存与依赖它的路由
```

## 何时用与何时不用

- **用**：内容变化频率决定档位——几乎不变默认静态、定期变化用 `revalidate`、每次必须实时用 `no-store`；写路径统一在变更后 `revalidatePath/Tag`。
- **不用**：需要强一致读的地方别依赖缓存（用 `no-store` 或直接查库）；别把路由缓存当持久缓存，它只在浏览器会话内存、刷新或过期即失。

## 优劣与代价

✅ 三层各司其职：构建期静态最快、数据缓存省下游、路由缓存让前进后退零延迟。
✅ Tag 级失效让"一处改动只掀相关页面"成为可能，比全量重部署细粒度得多。
⚠️ 缓存层多、失效隐式，"数据改了页面没变"与"以为静态却每次 SSR"是两大高频 bug。
⚠️ fetch 的默认缓存语义在各版本间有调整，须以所用版本的官方文档为准。

## 与相关概念的区别

- **vs [[缓存策略]]**：那是缓存的跨领域总纲（穿透/击穿/雪崩、一致性与淘汰）；本页专承 Next.js 三层缓存的分工与 revalidate 语义。
- **vs 浏览器 HTTP 缓存**：数据/路由缓存是框架层的，非 `Cache-Control`；只有边缘 CDN 才复用 HTTP 缓存。
- **vs [[资源加载优化]]**：加载优化管资源如何更快到浏览器，本页管内容如何更少地重新生成。

## 常见误区

- 改了数据库却不调用 `revalidatePath`/`revalidateTag`，误以为 Next.js 会自动感知数据变化并刷新页面。
- 把路由缓存（客户端会话内存）当成跨用户的服务端缓存，期望它长期驻留。
- 以为 `revalidate` 是"每隔 N 秒主动重生成"，实为陈旧后按需再生（stale-while-revalidate 式），并非定时任务。

## 面试速答

> 🎯 Next.js 三层缓存：数据缓存（fetch、跨请求持久）、完整路由缓存（构建静态 HTML/RSC）、路由缓存（浏览器会话内 RSC）；revalidatePath/Tag 按需失效前两层，no-store 每次重取、revalidate=N 定期再生，隐式动态 API 会落出静态缓存。
