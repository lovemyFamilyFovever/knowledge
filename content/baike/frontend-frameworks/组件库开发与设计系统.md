# 组件库开发与设计系统

> 📌 **导航**：本文是 **组件库开发与设计系统** 词条，属于 frontend-frameworks 术语集。相关枢纽：[[现代前端工程化完全指南]]。

## 定义

**一句话定义：** 组件库开发是把一组 UI 组件做成可对外发布的制品：设计令牌承载视觉决策、变体函数收敛样式分支、CSS 变量做运行时换肤、Storybook 交付文档与用例，并在 Monorepo 里独立发版。

**通俗类比：** 像成衣厂的尺码表加样衣间——令牌是尺码表，组件是按尺码表做的成衣，Storybook 是给经销商看的样衣间；换季只改尺码表。

## 为什么需要它

没有令牌层时，"品牌蓝"以十六进制字面量散在几百个文件里，换肤要全局搜索；样式分支靠 if/else 拼 className，加到第五次没人敢动；库与业务同仓同版本时，一次业务改动就把库版本一起推走。工程化把成本收进四层：令牌（数据）、props 与变体（接口）、主题（外观）、Storybook（验证）。

## 核心机制

- **设计令牌分三层，组件只碰语义层**：原始层是可枚举的字面量（primary 的 50/500/900、spacing 阶梯、圆角与阴影），语义层给它起名（success/warning/error/info、background/primary-foreground），组件层只消费语义名——换主题时语义不变、值变。
- **变体是函数不是分支**：`cva(base, { variants: { variant, size }, defaultVariants })` 把"样式 = 变体的函数"写成声明，类型由 `VariantProps` 反推回 props，拼错变体名编译期就红。
- **asChild 与 Slot 让出标签权**：`forwardRef` 把 ref 透传到真实 DOM，`asChild` 为真时渲染 Slot 而非 button，链接伪装成按钮时不再出现 `a` 嵌 `button` 的非法 DOM（可访问性口径见 [[无障碍访问]]）。
- **主题靠 CSS 变量在运行时落地**：light/dark 两套语义令牌展开成 `--color-*` 注入即可换肤；Provider 同时给 `theme`（可为 system）与已判定的 `resolvedTheme`，`useTheme` 在 Provider 外取值直接抛错，把"忘包 Provider"变成启动即暴露的故障。
- **Storybook 是库的公共契约面**：`Meta` + `StoryObj` 配 `argTypes` 声明控件，`tags: ['autodocs']` 出文档；每个变体留一条 story，改版才有视觉回归基线。

## 具体示例

```typescript
// packages/design-tokens 独立成包，组件库只引语义
const buttonVariants = cva("inline-flex rounded-md transition-colors", {
  variants: { variant: { default: "bg-primary text-primary-foreground",
                         outline: "border border-input hover:bg-accent" } },
  defaultVariants: { variant: "default", size: "default" }
});
// theme.ts —— generateCSSVariables("dark") 产出 { "--color-primary": ... }
```

发布约定也是接口：`main`/`types` 指 `dist/`、`files` 只收 `dist/**`，源码不进包（多入口产物见 [[JavaScript 构建工具（Webpack 与 Vite）]]）。

## 何时用与何时不用

- **用**：组件被两个以上业务复用、需要换肤或暗色、要对外发版——令牌与变体的边际成本一次付清。
- **不用**：单页三五个私有组件，抽库只会把改动成本摊到两个仓库；设计未稳定就打视觉基线等于描移动靶。组织侧判据见 [[前端工程化]]。

## 优劣与代价

✅ 换肤与品牌改版收敛为"改一层令牌"；变体可枚举、可类型检查。
⚠️ 令牌分层是长期税：语义名起歪（把 `blue-500` 当语义用），所有组件继承这个错。
⚠️ 独立发版带来版本漂移，库与应用不齐时定位要跨两个仓库。

## 与相关概念的区别

- **vs [[组件化与微前端]]**：那条管应用内部怎么拆与组合，本条管组件怎么作为制品对外交付。
- **vs [[CSS 预处理与模块化（Sass·Less·CSS Modules）]]**：那层是编译期的写法与作用域隔离，本条主题层是运行时换肤（变量侧另见 [[CSS 变量与动画]]）。
- **vs [[前端状态管理]]**：Provider 在此只承载注入配置（主题），不是共享业务态；展开/选中仍属组件局部态。

## 常见误区

- 把令牌写成 `--blue-500` 这类字面值名，换主题时改的还是同一批色值位。
- 以为变体越多越好，往 cva 里塞业务专用 variant，库开始反向依赖业务。
- 以为有了 Storybook 就等于有了测试，基线不接 CI 照样回归漏光。

## 面试速答

> 🎯 组件库=可发布制品，四层收敛：设计令牌（原始/语义/组件，换肤只改语义层）、变体函数（cva 声明样式映射）、运行时主题（CSS 变量 + Provider）、Storybook（契约与视觉基线）；asChild/Slot 让出标签权。
