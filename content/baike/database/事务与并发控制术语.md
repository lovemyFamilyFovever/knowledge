# 事务与并发控制术语

> 📌 **导航**：本文是 **事务与并发控制术语** 枢纽页。原十二个并列术语已按族拆分——[[事务与 ACID]]、[[并发读异常（脏读·不可重复读·幻读）]]、[[乐观锁与悲观锁]]、[[Redo Log 与 Undo Log]]；隔离级别见 [[事务隔离级别]]、MVCC 见 [[多版本并发控制]]、死锁见 [[死锁]]。本页只索引与串联。

## 定义

**一句话定义：** 事务与并发控制术语是数据库并发正确性的索引枢纽，把事务/ACID、三类并发读异常、隔离级别、MVCC、乐观/悲观锁、死锁、Redo/Undo Log 等概念归口到各自词条，本页给出全景与因果串联。

**通俗类比：** 像"并发安全"这章的目录：先讲事务要满足什么(ACID)、并发读会出什么乱子(三类异常)、用什么级别和 MVCC 挡、写冲突怎么处理(乐观/悲观锁)、崩了怎么恢复(Redo/Undo)、互等怎么破(死锁)——每节详解在各分册。

## 为什么需要它

并发正确性的概念彼此咬合又极易混（隔离 vs MVCC vs 锁、Redo vs Undo）。一张把它们串成因果链的地图，能让学习者按需进入各词条、不被十几个平铺小节淹没，也让枢纽自身聚焦"这些机制如何相互配合"，而非重复每篇细节。

## 具体示例

"扣库存并下单"：由 [[事务与 ACID]] 保证多步原子；高并发防超卖用 [[乐观锁与悲观锁]]（悲观 `FOR UPDATE` 或 version 乐观）；普通查询靠 [[多版本并发控制]] 快照读不阻塞写、其一致视图又决定会不会撞上 [[并发读异常（脏读·不可重复读·幻读）]]；[[Redo Log 与 Undo Log]] 保证提交不丢、回滚可撤；两个事务交叉持锁可能触发 [[死锁]] 被回滚其一。按主线即可定位每环去哪查。

## 常见误区

- 事务、隔离级别、MVCC、锁讲的是同一件事的不同叫法。
- 并发正确性只要把隔离级别调到最高就一劳永逸。
- Redo Log 与 Undo Log 都只用于崩溃恢复，与回滚和快照读无关。

## 面试速答

> 🎯 并发控制按因果串七族：事务/ACID → 脏读·不可重复读·幻读 → 隔离级别 → MVCC 快照 → 乐观/悲观锁 → 死锁 → Redo/Undo Log。各归独立词条(隔离/死锁等已有专条)，本页只索引；强一致靠高隔离+锁、并发靠 MVCC，写冲突乐观/悲观二选一，崩溃恢复 Redo、回滚与历史版本 Undo。细节进对应子条。
