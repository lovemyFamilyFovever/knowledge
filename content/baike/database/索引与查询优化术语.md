# 索引与查询优化术语

> 📌 **导航**：本文是 **索引与查询优化术语** 枢纽页。其术语的归口已在专门词条：聚簇/二级/覆盖/最左前缀/ICP/MRR 与失效场景见 [[MySQL 索引类型与优化]]、结构见 [[B+树]]、哈希/全文索引见 [[哈希表]]/[[倒排索引]]/[[ElasticSearch搜索]]、执行计划与优化器见 [[查询优化器与执行计划]]。本页只做术语索引。

## 定义

**一句话定义：** 索引与查询优化术语是"用索引加速查询"相关概念的索引枢纽，把聚簇/二级/覆盖/联合索引、最左前缀、ICP/MRR、EXPLAIN 与慢查询等术语归口到已建立的专门词条，本页只给术语到词条的映射。

**通俗类比：** 像"索引优化"这一章的词条索引页：列一张"术语→去哪看"的清单，每个术语的详细定义/示例/坑都在对应分册，这里不重抄。

## 为什么需要它

索引相关术语多且彼此关联，散在长文里会与 MySQL/存储引擎专条大量重复。把它们收敛成一层索引：既给读者"有哪些概念、各自去哪"的入口，又遵循"同一实质内容只在一处承载"，避免多处复述导致的口径漂移。

## 具体示例

慢查询"按 name 前缀 + age 过滤却全表扫"：查 [[MySQL 索引类型与优化]] 知 `(name, age)` 联合索引可覆盖、`WHERE age>… AND name LIKE '张%'` 因不满足最左前缀(跳过 name 等值)而退化；再依 [[查询优化器与执行计划]] 看统计与选计划，必要时补索引或改写。术语的定义与参数都在专条，本页不重复。

## 常见误区

- 索引术语得在每一处都完整讲一遍才算全。
- 覆盖索引就是给所有列建一个大索引，反正越全越好。
- EXPLAIN 显示走了索引，查询就一定最快。
