# 搜索引擎爬虫设计

> 📌 **导航**：本文是 **搜索引擎爬虫设计** 词条，属于 database 术语集。相关枢纽：[[搜索引擎技术详解]]、[[倒排索引]]、[[ElasticSearch搜索]]、[[一致性哈希]]、[[NoSQL 数据库术语]]。

## 定义

**一句话定义：** 搜索引擎爬虫是自动从 Web 发现并下载页面的程序：以 URL 队列为核心，经规范化、去重、robots 合规、下载、解析再回灌新链接，把全网内容源源不断喂给索引环节。

**通俗类比：** 像一张自动扩边的采集网：从几颗种子页出发，每下一张页面就把它页里的链接再挂进"待抓清单"，边抓边把重复的、不让抓的、抓过的滤掉，网越撒越大。

## 为什么需要它

搜索的源头是"把内容抓下来"。无节制抓取会重复劳动、压垮目标站、触犯 robots 甚至法律。爬虫要解决：URL 规范化让等价地址合一、去重防无限循环、优先级让重要页早抓、robots/crawl-delay 守规矩、分布式把吞吐扩到多机——这些决定了索引拿到的语料是否新鲜、合法、覆盖广。

## 核心机制

- **抓取闭环：** 取 URL → 合法性/robots/去重三重检查 → 下载 → 解析出正文与新链接 → 新链接回灌队列。
- **URL 规范化：** 小写化、去默认端口、去 #片段、合并多余斜杠、解析相对链接，让同一页只抓一次。
- **URL 去重：** 海量 URL 精确存不现实，用布隆过滤器判"是否已见"（有假阳性、无假阴性）；正文近似重复用 SimHash + 汉明距离。
- **优先级与调度：** 用优先队列按域名/新鲜度等打分决定抓取顺序；礼貌抓取控制速率。
- **robots 合规：** 解析各站 robots.txt 的 Allow/Disallow 与 Crawl-delay，禁抓则跳过。
- **分布式：** 多 worker 共享一个 Redis（或队列）做 URL 分发与 visited 去重、水平扩吞吐。

## 具体示例

种子页入队后：规范化把 `HTTP://A.com//x#top` 归一为 `http://a.com/x`；查布隆过滤器未见 → 查 robots 允许 → 下载解析 → 抽出新链接再判重入队，并把该 URL 记入 visited。多机时各 worker 从 Redis 队列 `lpop` 领任务、`sadd` 标记已访问，实现去重与并行。近似重复的转载页再用 SimHash 指纹、汉明距离 ≤3 判重后丢弃。

## 何时用 / 何时不用

- **用：** 需要对外部/内部大量页面持续采集入索引（站内搜索、监控、数据聚合）。
- **注意：** 尊重 robots 与频率限制，避免被封与法律风险；布隆去重有假阳（可换计数器布隆或精确集合换空间）；抓取 ≠ 抽取质量，正文抽取另需解析。

## 优劣与代价

✅ 自动扩边、去重与合规内建、分布式可横向扩吞吐，保障语料新鲜与覆盖。
⚠️ 布隆假阳性会漏抓少量新页；礼貌/反爬与域名限速压低抓取速率。
⚠️ 大规模分布式去重与状态共享有运维复杂度。

## 与相关概念的区别

- **通用爬虫 vs 站内定向：** 本文侧重 Web 级广域采集与合规，垂直站内抓取可简化优先级/robots 部分。
- **布隆去重 vs SimHash：** 前者判"URL 是否见过"（精确集合的省内存替代），后者判"正文内容是否近似重复"。
- **vs 索引 [[倒排索引]]：** 爬虫产出原始文档，倒排索引负责可检索结构，是下游环节。

## 常见误区

- 布隆过滤器说"没见过"的 URL，可能其实已经抓过。
- 爬虫可以无视 robots.txt，只要技术上能抓就抓。
- URL 只要字符串完全相同才算同一个，无需规范化。

## 面试速答

> 🎯 爬虫=URL 队列驱动的抓取闭环：规范化(小写/去端口/去片段/解相对)→布隆过滤器去重(无假阴性)+SimHash 近似去正文重→robots/Crawl-delay 合规→下载解析回灌新链接→优先队列控序、多 worker 经 Redis 分布式分发。要点是合法、去重、新鲜、可扩展。
