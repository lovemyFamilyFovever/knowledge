# 事务隔离级别


> 📌 **导航**：本文是 **事务隔离级别** 词条，属于 database 术语集。相关枢纽：[[MySQL从入门到架构师]]、[[MySQL深入]]、[[Redis深入]]、[[Redis深度解析与实战指南]]、[[SQL 基础术语]]。

## 定义

**一句话定义：** 事务隔离级别（Transaction Isolation Level）是 SQL 标准定义的、衡量并发事务之间相互隔离程度的等级，用于在一致性（避免脏读、不可重复读、幻读）与并发性能之间做权衡；级别越高越一致，但并发越差。

**通俗类比：** 像多人同时编辑同一份文档的"可见性规则"——是允许你看到别人尚未保存的草稿（脏读），还是只能看到已定稿的内容（更高隔离）；规则越严，冲突越少，但大家越要排队等待。

> 多义说明：SQL 标准定义四级：读未提交、读已提交、可重复读、串行化；各数据库的实现与默认级别不同（如 MySQL InnoDB 默认可重复读，Oracle/PostgreSQL 默认读已提交）。本文按标准讲解。

## 为什么需要它

并发事务同时读写同一数据时，若不约束彼此能看到什么，就会出现读到未提交值、两次读不一致、统计行数凭空增减等异常。隔离级别提供一档可调的"标准旋钮"：在数据正确性与系统吞吐之间取平衡——低级别放行更多并发、承担更多异常风险，高级别更干净但逼事务串行化。

## 核心机制

- **三类并发读问题：**
  - 脏读：读到他人未提交的数据。
  - 不可重复读：同一事务内两次读同一行结果不同（他人 UPDATE 并提交）。
  - 幻读：同一事务内两次范围查询行数不同（他人 INSERT/DELETE 并提交）。
- **四个隔离级别（由低到高）：**
  - Read Uncommitted（读未提交）：可能出现脏读、不可重复读、幻读。
  - Read Committed（读已提交）：避免脏读；仍可能不可重复读、幻读。
  - Repeatable Read（可重复读）：避免脏读与不可重复读；标准下仍可能幻读（InnoDB 借 MVCC + 间隙锁基本消除）。
  - Serializable（串行化）：最高，避免上述全部，事务近似串行执行，并发最低。
- **实现手段：** 锁（两阶段锁 2PL）或 MVCC（见 [[多版本并发控制]]）。

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|----------|------|-----------|------|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 避免 | 可能 | 可能 |
| Repeatable Read | 避免 | 避免 | 可能* |
| Serializable | 避免 | 避免 | 避免 |

（\*InnoDB 的可重复读基本消除幻读。）

## 具体示例

事务 A 要"读余额→扣款→写日志"三步保持一致：READ COMMITTED 下，A 第一次读余额 500，B 中间提交了一笔改成 800，A 第二次读到 800（不可重复读），扣款逻辑可能算错。换 REPEATABLE READ，A 在第一次读时生成 ReadView，之后无论 B 怎么提交都仍看到 500，三步基于同一快照，账才平。若 A 做的是"统计某区间订单数"而 B 在区间内插了一条，RR 快照读下 A 两次统计一致，但 A 若用当前读（`FOR UPDATE`）就可能撞上幻影行，此时靠间隙锁把区间锁住。

## 何时用 / 何时不用

- **用：** 数据库事务的隔离级别配置、并发一致性设计；金融、订单等对一致性敏感的场景据业务选择合适级别（多数用 RR 或 RC + 应用层控制）。
- **不用（即不盲目上调）：** 高并发只读报表用 Serializable 会把吞吐打死；能接受"读最新已提交值"的场景不必上 RR。

## 优劣与代价

✅ 提供一致性与并发之间的可调权衡，且已被 SQL 标准统一。
⚠️ 高级别降低并发、增加锁竞争与死锁概率。
⚠️ 各级别语义在不同数据库存在差异（尤其幻读处理），选择不当会引入 anomalies。

## 与相关概念的区别

- **不可重复读 vs 幻读：** 前者针对 UPDATE（同一行值变了），后者针对 INSERT/DELETE（范围内行数变了）。
- **隔离级别 vs MVCC：** 隔离级别是"要达到的规则"，MVCC 与锁是实现它的"手段"（见 [[多版本并发控制]]）。
- **标准 vs 实现：** 标准规定 RR 仍可能幻读，但 MySQL InnoDB 通过 MVCC+间隙锁基本消除，属实现强于标准。

## 常见误区

- 事务隔离级别越高越好，应该一律设成 Serializable。
- 可重复读隔离级别一定能彻底杜绝幻读。
- 不可重复读和幻读是同一回事。

## 面试速答

> 🎯 隔离级别=SQL 标准在一致性与并发间的旋钮，四级由低到高 RU/RC/RR/Serializable，逐级消除脏读、不可重复读、幻读；靠锁(2PL)或 MVCC(ReadView) 实现，MySQL 默认 RR 且用间隙锁基本消除幻读，并非越高越好。
