# 存储过程与触发器


> 📌 **导航**：本文是 **存储过程与触发器** 词条，属于 database 术语集。相关枢纽：[[MySQL从入门到架构师]]、[[MySQL深入]]、[[Redis深入]]、[[Redis深度解析与实战指南]]、[[SQL 基础术语]]。

## 定义

**一句话定义：** 存储过程(Stored Procedure)是预先编译并存储在数据库中、可被调用执行的一段 SQL/过程化代码;触发器(Trigger)是与表绑定、在特定事件(INSERT/UPDATE/DELETE)发生时自动执行的特殊存储过程;二者都把业务逻辑下沉到数据库端。

**通俗类比：** 存储过程像银行柜台预设好的"一站式办理流程"(你报个需求,柜员按既定流程一次办完,不用你来回跑);触发器像"自动感应门"——某个动作发生时(如余额变动),它自动被触发执行预设的后续动作(如记一笔流水)。

> 多义说明:存储过程需**显式调用**;触发器由**事件自动触发**。二者都是数据库端的过程化对象。本文并述。

## 原理与机制

- **存储过程:** 用 PL/SQL、T-SQL、PL/pgSQL 等编写,含参数、控制流与事务;通常预编译(执行计划可缓存),一次调用完成多步,减少网络往返。
- **触发器:** 定义时机(BEFORE / AFTER / INSTEAD OF)× 事件(INSERT / UPDATE / DELETE);可访问 OLD / NEW 行值;常用于审计、级联、约束校验、自动填充。
- **执行位置:** 都在数据库服务器端执行。

## 关键组成

| 组成 | 说明 |
|------|------|
| 存储过程 | 参数、预编译、显式调用 |
| 触发器 | 事件 + 时机(BEFORE/AFTER) |
| OLD / NEW | 触发器访问变更前后行值 |
| 过程化 SQL | 控制流、变量、事务 |

## 应用场景

- 复杂业务逻辑封装、批处理
- 数据审计(触发器记日志)
- 级联更新、数据校验
- 减少客户端与数据库的往返

## 优点与局限

- 优点:逻辑集中、减少网络往返、预编译性能好、可复用。
- 局限:业务逻辑入库后难以版本控制/测试/调试;可移植性差(绑定特定数据库);数据库易成瓶颈且变"胖";触发器隐式执行易埋坑(难追踪);维护复杂。

## 常见误区

- 存储过程需显式调用,触发器自动触发(后者易被忽视)。
- 触发器的隐式执行可能造成意外的级联或性能问题。
- 把过多业务逻辑放进数据库常被视为反模式(现代多放在应用层)。
- 不同数据库的过程语言与触发器语法差异很大。
