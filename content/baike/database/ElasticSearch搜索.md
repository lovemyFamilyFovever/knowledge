# ElasticSearch搜索


> 📌 **导航**：本文是 **ElasticSearch搜索** 词条，属于 database 术语集。相关枢纽：[[MySQL从入门到架构师]]、[[MySQL深入]]、[[Redis深入]]、[[Redis深度解析与实战指南]]、[[SQL 基础术语]]。

## 定义

**一句话定义：** Elasticsearch（ES）是基于 Lucene 的分布式搜索与分析引擎，以**倒排索引**为核心，提供近实时的全文检索、结构化搜索、分析与聚合能力。

**通俗类比：** 普通数据库像逐页翻书找关键词；ES 像书末的"索引页"——先建好"词 → 出现在哪些文档"的倒排表，查词时直接定位，速度极快。

> 多义说明：本文是 ES 的**核心用法速览**；搜索引擎的完整原理（倒排索引、分词、相关性评分、Lucene 段合并等）见 [[搜索引擎技术详解]]。

## 为什么需要它

关系数据库的 LIKE 走全表扫描，无法应对海量文本的"任意词命中 + 相关性排序 + 聚合分析"。ES 用倒排索引把"包含某词的文档"预计算成一张可直接命中的表，再叠加 Lucene 的相关性评分、分布式分片与聚合框架，让全文检索、日志分析（ELK）、向量语义检索在同一套引擎里近实时完成——这是把它从主库旁独立出来的核心理由。

## 核心机制

- **倒排索引：** 正排是"文档 → 词"，倒排是"词 → 文档列表（posting list）"，是全文检索的核心。
- **分词（Analysis）：** 写入时对文本分词建倒排，查询时对查询串分词再匹配，索引与搜索可用不同分词策略。
- **近实时（NRT）：** 文档写入后需 refresh（默认约 1s）才可被搜索；底层 Lucene 段（segment）不可变，定期合并。
- **分布式：** 索引切成主分片分布到各节点，副本分片提供高可用与读扩展。

以"机器学习"三篇文档为例，倒排表形如：

| 词项 | 包含文档 |
|------|----------|
| 机器 | 文档1、文档3 |
| 学习 | 文档1、文档2、文档3 |
| 深度 | 文档2 |

## 何时用 / 何时不用

- **用：** 站内搜索/日志检索（ELK）、可观测性（日志/指标/追踪）、聚合分析、语义检索与 RAG（结合 [[向量数据库技术]]）。
- **不用：** 需要事务与强一致的主库/OLTP（应交给 MySQL，ES 作二级索引）；对写入即可见的强实时场景（有 refresh 延迟）；超高频点查 KV（Redis 更合适）。

中文分词器选型：

| 分词器 | 特点 | 适用 |
|--------|------|------|
| standard | 按空格/标点切分 | 英文 |
| ik_max_word | 最细粒度穷举 | 中文**索引** |
| ik_smart | 智能粗粒度 | 中文**搜索** |

## 具体示例

一次典型 bool 组合查询：`must` 里的 match 对 title 分词命中并影响评分，`filter` 里的 range 只做价格过滤不计分且可缓存，`should` 命中则加分。

```json
{
  "query": {
    "bool": {
      "must":   [ { "match": { "title": "机器学习" } } ],
      "filter": [ { "range": { "price": { "gte": 50 } } } ],
      "should": [ { "term": { "category": "AI" } } ]
    }
  }
}
```

语义/向量检索则用 `knn` 指定 embedding 字段、查询向量、k 与 num_candidates，在向量索引里取 Top-K 近邻。

## 优劣与代价

✅ 全文检索强、水平扩展、近实时、聚合丰富、生态完善（Kibana/Logstash/Beats）。
⚠️ 非事务型、最终一致，不适合当主库；写入有 refresh 延迟、资源消耗大。
⚠️ 深分页 `from+size` 在超过一定深度时要协调大量文档，易慢甚至 OOM。

## 与相关概念的区别

- **vs 关系数据库：** 面向全文检索与分析而非事务，作旁路二级索引；强一致与写回仍以主库为准。
- **vs 倒排/BM25 检索：** ES 在其上封装了分片、副本、聚合、kNN 向量检索等分布式工程细节。
- **vs Redis：** Redis 是内存点查/缓存，ES 是磁盘倒排检索与聚合，二者常互补。

## 常见误区

- Elasticsearch 事务与强一致性足够好，可以直接替换 MySQL 当主库。
- 对 text 字段用 term 查询和 match 查询效果一样。
- 翻页时把 from 设得很大也无所谓，性能不会明显下降。

## 面试速答

> 🎯 ES=基于 Lucene 的分布式近实时检索引擎，核心是倒排索引 + 分词 + bool 查询，覆盖全文/日志/聚合/向量检索；定位是主库旁的检索分析引擎，事务仍交给数据库，深分页用 search_after 规避。
