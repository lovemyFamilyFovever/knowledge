# MySQL从入门到架构师

> 📌 **导航**：本文是 **MySQL从入门到架构师** 枢纽页。原按存储引擎/索引/事务隔离/锁/查询优化五大主题展开，现各归其条：[[InnoDB 存储引擎结构]]、[[MySQL 索引类型与优化]]、[[MySQL 锁机制]]、[[事务隔离级别]]、[[多版本并发控制]]，原理速览见 [[MySQL深入]]。

**一句话定义：** 本文是 MySQL（InnoDB）的知识地图枢纽，把原先一部长篇拆成存储引擎、索引优化、事务与 MVCC、锁机制、查询优化五个主题并各指其条，本页只负责全景串联与选型导航、不重复子条内容。

## 为什么需要它

MySQL 的性能与正确性问题会分散在存储引擎、索引、事务隔离、锁、执行计划五层，任何单条都只讲一层。新手常"某点查一下、全貌没有"，缺一张把五层串起来的地图。枢纽页正提供这条主线：数据怎么存、怎么查得快、并发怎么保序不出错、慢查询怎么定位，再指向各层的专条。

## 具体示例

一条"扣库存"语句走到哪一层：先由 [[MySQL 索引类型与优化]] 判断走主键还是二级索引、是否回表；[[MySQL 锁机制]] 决定 `FOR UPDATE` 加行锁还是临键锁、如何避免间隙锁死锁；[[多版本并发控制]] 决定普通 SELECT 走快照读不加锁；[[InnoDB 存储引擎结构]] 解释提交为何要 Redo 刷盘 + Binlog 两阶段提交；最后用 EXPLAIN/慢查询回顾是否命中索引。遇到具体问题，按这条链跳进对应子条。

## 常见误区

- MySQL 性能全看索引，跟存储引擎的刷盘、日志策略无关。
- 有了 MVCC，读操作在任何情况下都不需要加锁。
- 事务隔离级别越高就一定越好，并发性能不会受影响。
