# 数据库连接池


> 📌 **导航**：本文是 **数据库连接池** 词条，属于 database 术语集。相关枢纽：[[MySQL从入门到架构师]]、[[MySQL深入]]、[[Redis深入]]、[[Redis深度解析与实战指南]]、[[SQL 基础术语]]。

## 定义

**一句话定义：** 数据库连接池(Database Connection Pool)是一种在应用启动时预先创建并复用一批数据库连接、按需借出与归还的技术,避免为每次数据库操作都新建和销毁连接,从而显著降低连接开销、提升性能与资源利用率。

**通俗类比：** 像出租车公司——不必每位乘客来了都现造一辆车(新建连接),而是预先备一批车在停车场(连接池),乘客来了直接派一辆(借连接),到站后车归还待命(还连接),下一位接着用。

> 多义说明:连接池是"对象池/资源池"模式的一种;各语言/框架都有实现(HikariCP、Druid、DBCP、SQLAlchemy pool 等)。本文讨论通用机制。

## 原理与机制

- **初始化:** 预创建最小数量的连接放入池中,维护空闲/使用中状态。
- **借用与归还:** 应用请求时借出一个空闲连接,用完归还(而非关闭),由池管理其生命周期。
- **参数:** 最小/最大连接数、获取超时、空闲回收、连接有效性检测(如 validationQuery / testOnBorrow)、泄漏检测。
- **为何有效:** 数据库建连(TCP + 认证 + 会话初始化)开销大,复用连接省去重复建连成本。

## 关键组成

| 组成 | 说明 |
|------|------|
| 空闲 / 活跃连接 | 池中的连接状态 |
| 最小 / 最大连接数 | 池容量控制 |
| 借用 / 归还 | 连接的取用与回收 |
| 连接校验 | 剔除失效连接 |
| 超时与泄漏检测 | 防止耗尽与死等 |

## 应用场景

- Web 应用与后端服务的数据库访问
- ORM 框架
- 高并发系统的连接管理
- 微服务

## 优点与局限

- 优点:大幅降低建连开销、提升吞吐与响应、控制并发连接数(保护数据库)、复用资源。
- 局限:连接数配置需权衡(过大压垮数据库、过小则排队);连接失效/泄漏需处理;长连接占用资源;分布式下每实例各有池,总量需统一控制。

## 常见误区

- 连接池不是越大越好(超过数据库承载会拖垮它)。
- 用完必须归还,否则连接泄漏会耗尽池。
- 连接可能失效,需校验/心跳。
- 连接池复用"连接",并不改变 SQL 本身的效率。
