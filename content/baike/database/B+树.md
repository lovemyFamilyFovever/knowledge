# B+树

## 定义

**一句话定义：** B+树是一种自平衡的多路搜索树,其所有数据(或指向数据的指针)都存储在叶子节点、内部节点只存索引键,且叶子节点通过指针相连形成有序链表;它是关系型数据库索引(如 MySQL InnoDB)的主流底层结构。

**通俗类比：** 像一本书的多级目录——先查大章节(内部节点,只给方向和页码范围),再翻到具体页(叶子节点,才有正文);而且所有"正文页"还用书签串成一条顺序带(叶子链表),方便从头到尾连续翻阅(范围查询)。

> 多义说明:需区分 **B树(B-tree)**(数据分布在所有节点)与 **B+树**(数据只在叶子、且叶子有链表);本文讨论 B+树。

## 原理与机制

- **多路平衡(高扇出):** 每个节点可容纳多个键与子指针,使树非常"矮胖"——通常 3~4 层即可索引千万级行,从而把磁盘 I/O 降到很低。
- **内部节点只存键:** 不存数据,单个节点能放下更多键 → 扇出更大、树更矮。
- **叶子节点存全部数据/指针,并用链表相连:** 使范围扫描与顺序访问非常高效。
- **自平衡:** 插入/删除通过节点分裂与合并维持平衡,查询代价稳定为 O(log n)。

## 关键组成

| 组成 | 作用 |
|------|------|
| 内部节点 | 仅存键 + 子指针,负责导航 |
| 叶子节点 | 存全部键 + 数据(或数据指针) |
| 叶子链表 | 连接叶子,支持高效范围查询 |
| 阶(order)/扇出 | 每节点的最大子节点数 |
| 分裂 / 合并 | 维持平衡的动态调整 |

## 应用场景

- 关系数据库的主键索引与二级索引(如 InnoDB 的聚簇/二级索引)
- 文件系统与存储引擎的索引结构
- 需要频繁范围查询、排序与顺序扫描的场景

## 优点与局限

- 优点:树矮、磁盘 I/O 少;范围查询与有序遍历高效;查询代价稳定 O(log n)。
- 局限:写入需维护结构、可能触发页分裂;随机写友好度不如 LSM-Tree;节点空间可能产生碎片与浪费。

## 常见误区

- B+树 ≠ B树:关键差异在于数据存储位置(仅叶子)与叶子链表。
- B+树是为**磁盘/块存储**设计(按页读写),不同于内存中的二叉搜索树。
- 范围查询快是因为叶子链表,而非在树内部逐层遍历。
