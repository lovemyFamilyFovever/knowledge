# 多版本并发控制


> 📌 **导航**：本文是 **多版本并发控制** 词条，属于 database 术语集。相关枢纽：[[MySQL从入门到架构师]]、[[MySQL深入]]、[[Redis深入]]、[[Redis深度解析与实战指南]]、[[SQL 基础术语]]。

## 定义

**一句话定义：** 多版本并发控制（Multi-Version Concurrency Control，MVCC）是一种数据库并发控制技术，它为数据维护多个历史版本，使读操作访问某个一致性快照而无需阻塞写操作，从而实现"读不阻塞写、写不阻塞读"，大幅提升并发吞吐。

**通俗类比：** 像在线协作文档的历史版本——你阅读时看到的是打开那一刻的版本（快照），别人同时编辑新版本并不影响你；你不必等对方"保存完"才能看，系统为不同读者保留各自需要的版本。

> 多义说明：MVCC 是一种并发控制策略，与基于锁的并发控制（如两阶段锁 2PL）相对；不同数据库（PostgreSQL / MySQL InnoDB / Oracle）实现细节不同。本文讲通用机制。

## 为什么需要它

若读也加锁，一个长读查询会阻塞写、写又阻塞读，OLTP 高并发下吞吐被锁拖垮。MVCC 让每个事务读"自己快照里的版本"、写时生成新版本而不覆盖旧版本，读写各看各的版本、互不等待，从而在不牺牲一致性的前提下把读写并发度拉到最高——这是现代数据库能扛高并发的关键。

## 核心机制

- **版本化：** 每行数据保留多个版本，附带事务 ID / 时间戳（如 PostgreSQL 的 xmin/xmax，或 InnoDB 的 undo log 版本链）。
- **快照读：** 事务在开始（或语句开始）时获得一个快照（read view），读取时按可见性规则选择对其可见的版本。
- **写入：** 写操作创建新版本，旧版本保留给仍在读的事务；通过 undo log（InnoDB）或多版本元数据（PostgreSQL）实现。
- **版本回收：** 旧版本由 VACUUM（PostgreSQL）或 purge（InnoDB）回收，避免存储膨胀。
- **隔离级别：** MVCC 常用于实现读已提交（RC）、可重复读（RR）与快照隔离（SI）。

| 组成 | 作用 |
|------|------|
| 数据多版本 | 保留历史以支持一致性读 |
| 事务 ID / 时间戳 | 标记版本归属与先后 |
| 快照 / read view | 决定本事务可见哪些版本 |
| undo log / 版本链 | 组织与回溯旧版本 |
| 版本回收（VACUUM/purge） | 清理不再需要的旧版本 |

## 具体示例

InnoDB 中一行被事务 100 改成 name=A，事务 90、80 的旧值经 DB_ROLL_PTR 串成版本链。事务 101 做快照读时生成 ReadView（活跃事务、min/max trx_id），沿版本链从新到旧找第一个对自己可见的版本返回，全程不加读锁；此时事务 100 正在改的写锁不影响 101 的读。等没有任何活跃事务再需要 90/80 的旧版本，purge 线程才回收这些 undo，控制回滚段不无限膨胀。

## 何时用 / 何时不用

- **用：** 主流关系数据库（PostgreSQL、MySQL InnoDB、Oracle、SQL Server）的高并发读写、一致性快照查询、OLTP 减少读写锁争用（多由引擎默认提供，无需手写）。
- **不用/注意：** 需要"读到自己未提交修改的实时值"或强串行化写偏斜敏感的场景，快照隔离不足，需当前读 + `FOR UPDATE` 或提升到 Serializable。

## 优劣与代价

✅ 读不阻塞写、写不阻塞读，并发吞吐高，提供一致性快照读。
⚠️ 写产生多版本 → 存储与回收开销，PostgreSQL 依赖 VACUUM 防表膨胀。
⚠️ 写–写仍需冲突处理；快照隔离下存在写偏斜（write skew）问题。

## 与相关概念的区别

- **vs 2PL/锁并发控制：** 2PL 靠读写锁互斥，读写相互阻塞；MVCC 靠版本快照让读不走锁，二者对写仍可能配合加锁。
- **vs 隔离级别：** 隔离级别是"对外承诺的规则"，MVCC 是实现 RC/RR 的手段（见 [[事务隔离级别]]）。
- **实现差异：** InnoDB 用 undo log 版本链 + ReadView，旧版本在回滚段；PostgreSQL 把多版本存在表内元组 + VACUUM，长期不回收会膨胀。

## 常见误区

- MVCC 实现了完全无锁，写与写之间也绝不会冲突。
- MVCC 的快照读读到的总是数据的最新值。
- 有了 MVCC 就不用回收旧版本，存储不会受影响。

## 面试速答

> 🎯 MVCC=每行存多版本、读走一致性快照不阻塞写、写生成新版本不覆盖旧值，靠隐藏 trx_id+回滚指针/时间戳和 ReadView 判可见性，实现"读写互不阻塞"的高并发；旧版本靠 undo/VACUUM 回收，写–写与写偏斜仍要锁或提升隔离级别。
