# LSM 树


> 📌 **导航**：本文是 **LSM 树** 词条，属于 database 术语集。相关枢纽：[[MySQL从入门到架构师]]、[[MySQL深入]]、[[Redis深入]]、[[Redis深度解析与实战指南]]、[[SQL 基础术语]]。

## 定义

**一句话定义：** LSM 树（Log-Structured Merge Tree，日志结构合并树）是一种面向**写优化**的存储数据结构，它把随机写转化为顺序写：新数据先写入内存表并追加日志，再周期性刷入磁盘分层文件并在后台合并，广泛用于 NoSQL 与新型数据库的存储引擎。

**通俗类比：** 像记账——你不会每笔支出都跑去改总账本（随机写磁盘），而是先记在手边便签（内存），攒够一批再一次性誊到账本（顺序落盘），后台再慢慢把多本账合并整理；这样"写"永远很快。

> 多义说明：LSM 树是存储引擎数据结构，与 [[B+树]]（读优化、原地更新）是两条不同技术路线；本文讨论 LSM。

## 为什么需要它

B+树更新一条记录要原地改页，随机写叠加页分裂，写放大严重，在 SSD/机械盘上都成了写密集场景的瓶颈。LSM 反其道而行：把一切写变成内存缓冲 + 顺序追加日志 + 顺序刷出的不可变文件，用后台合并消化乱序，从而把随机写彻底转成顺序写，换来高写入吞吐与高压缩比——代价是要在读路径上做多文件查找。

## 核心机制

- **写入：** 先写 WAL（预写日志）保证持久性，再写入内存中的 MemTable（常用跳表）；MemTable 满后冻结为不可变表并 flush 成磁盘上有序的 SSTable 文件。
- **读取：** 依次查 MemTable → 各层 SSTable；用布隆过滤器（Bloom filter）快速跳过不含目标键的文件。
- **合并（Compaction）：** 后台把多层 SSTable 归并、去重、清理过期与删除数据，控制层数与读放大。
- **删除：** 用墓碑标记（tombstone）记录删除，合并时真正清除。
- **权衡：** 需在写放大、读放大、空间放大三者间平衡。

| 组成 | 作用 |
|------|------|
| WAL | 崩溃恢复，保证持久性 |
| MemTable | 内存有序写缓冲（跳表） |
| SSTable | 磁盘上的有序不可变数据文件 |
| 分层（Level） | 组织 SSTable，控制读放大 |
| Compaction | 后台归并、去重、清理 |
| 布隆过滤器 | 加速判断键是否可能存在 |

## 具体示例

写入 key=k：先顺序追加 WAL，再插入内存 MemTable，返回即完成（此时磁盘 SSTable 还没有它）。读取 k：查 MemTable，未命中再逐层查 SSTable，用布隆过滤器跳过明显不含 k 的文件。删除 k：写入一条 tombstone 而非物理删除，等该键进入 compaction 时才真正清掉——所以删除后的短窗口里读仍能看到墓碑被过滤。

## 何时用 / 何时不用

- **用：** 写多读少、日志与时序数据、大规模键值存储，以及需要高写入吞吐与高压缩比的引擎（LevelDB、RocksDB、Cassandra、HBase、ClickHouse、TiDB 等）。
- **不用：** 读多、点查/范围要稳定、需要强事务与原地更新的场景（更偏 [[B+树]]）；数据量小到全内存可放时，用普通结构即可。

## 优劣与代价

✅ 顺序写、写吞吐高，对 SSD/磁盘友好，数据有序且压缩比高。
⚠️ 读可能需查多个文件（读放大，靠布隆过滤器与分层缓解）。
⚠️ 后台 compaction 占用 CPU/IO；存在空间放大；点查与范围查询稳定性不如 B+树。

## 与相关概念的区别

- **vs B+树：** B+树原地更新、读与范围稳定、随机写代价高；LSM 顺序写、写吞吐高、读需合并多文件。
- **vs 单纯 WAL：** WAL 只提供崩溃恢复的顺序日志，LSM 在此之上组织出可查询的分层 SSTable 与 compaction。
- **Compaction 策略：** size-tiered（相似大小归并，空间放大低但写/峰值高）与 leveled（分层固定大小，读放大低但写放大高）是同一权衡的两种取向。

## 常见误区

- LSM 树只优化写入、完全不管读性能。
- 在 LSM 里删除一条记录会立即把数据从磁盘物理清除。
- LSM 与 B+树有绝对优劣，写多读多都能无脑选 LSM。

## 面试速答

> 🎯 LSM=写优化结构：MemTable+WAL 接住写、顺序 flush 成不可变 SSTable、后台 compaction 归并；用布隆过滤器与分层缓解读放大，核心是在写放大/读放大/空间放大间权衡。写多读少选 LSM，读多强事务偏 B+树。
