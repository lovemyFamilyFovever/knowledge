# 列族数据库（HBase 与 Cassandra）

> 📌 **导航**：本文是 **列族数据库（HBase 与 Cassandra）** 词条，属于 database 术语集。相关枢纽：[[NoSQL 数据库术语]]、[[LSM 树]]、[[分布式存储术语百科]]、[[数据仓库]]、[[数据湖]]。

## 定义

**一句话定义：** 列族数据库是按"列族"组织数据的宽列（BigTable 系）分布式存储，一行由若干列族构成、稀疏列不占空间，面向海量数据的水平扩展与列式读写，代表为 HBase 与 Cassandra。

**通俗类比：** 普通表格按行整排存放；列族库像把同类的列（基本信息、行为记录）分别装订成册，某行某列没值就真的不落存储，读某类信息时只翻那一册，适合又宽又稀疏的超大表。

## 为什么需要它

关系表列数固定、行存对"稀疏宽表 + 只读少数列"很不经济，单机也难以撑到数十亿行。列族模型允许每行动态加列、稀疏列不占空间，配合分布式分片与 [[LSM 树]] 存储（顺序写、高吞吐），把"海量宽表 + 写密集 + 按列取数"这类需求做到可线性扩展，是大数据平台与时间线/画像类存储的常见底座。

## 核心机制

- **数据模型：** 行键 + 列族（列限定符），一个行键下的列族内可动态增列；稀疏即不存。
- **HBase：** 依赖 HDFS 存储 + ZooKeeper 协调，RegionServer 按行键范围分片（Region），强一致、随机读写强，常作离线/大数据组件。
- **Cassandra：** 无中心对等节点、一致性哈希 + 可调一致性（Quorum），写扩展与多数据中心复制强、AP 取向。
- **共同底层：** 多为 LSM 式结构，顺序写换高吞吐、列式压缩省空间。

## 具体示例

用户行为画像：以 user_id 作行键，列族 `basic`（年龄、地区）与 `event`（可动态增列 event:2026-09-click）分别存放——新用户没有 event 时该列族根本不占空间。分析时可按列族批量扫描，海量行靠 HBase 的 Region 或 Cassandra 的分片横向扩到几十亿行。

## 何时用 / 何时不用

- **用：** 超大规模稀疏宽表、写密集、按列族读、需水平扩展与多活（画像、时序事件、消息存储、监控指标）。
- **不用：** 需要复杂多表事务与即席 SQL（用关系型/[[数据仓库]]）；小数据集（运维成本不值）；强一致金融账务（Cassandra 的 AP 需谨慎配一致性）。

## 优劣与代价

✅ 稀疏宽表省空间、动态列灵活、水平扩展与写吞吐强、多数据中心友好。
⚠️ 无 JOIN、弱事务（相对 RDBMS）、二级索引能力有限；运维与数据建模门槛高。
⚠️ HBase 依赖 ZK/HDFS、Cassandra 需自行处理一致性取舍。

## 与相关概念的区别

- **列族 vs 关系表：** 列族按列族聚簇、稀疏不存、动态列；关系表列固定、强 schema、擅长 JOIN 与事务。
- **HBase vs Cassandra：** HBase 强一致 + HDFS、适合集中式大数据栈；Cassandra 去中心 + 可调一致性、适合多活写扩展。
- **vs [[数据湖]]：** 列族是面向实时读写的在线存储，数据湖是面向批量分析的多格式归档。

## 常见误区

- 列族数据库和"列式存储（如 ClickHouse）"是完全一样的东西。
- Cassandra 默认就能保证跨所有节点的强一致。
- 列族数据库像关系型一样擅长多表 JOIN 与复杂事务。

## 面试速答

> 🎯 列族数据库=BigTable 式宽列：行键+列族、稀疏列不占空间、动态加列，配 LSM 顺序写换高吞吐与水平扩展。HBase 强一致+HDFS、适合大数据栈；Cassandra 去中心、可调一致性、多活写扩展偏 AP。适合海量稀疏宽表与写密集；不擅长 JOIN 与复杂事务。
