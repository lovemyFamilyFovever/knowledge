# 正则表达式


> 📌 **导航**：本文是 **正则表达式** 词条，属于 cs-basics 术语集。相关枢纽：[[P 与 NP]]、[[信息论基础]]、[[图灵机]]、[[布尔逻辑与逻辑门]]、[[形式语言与文法]]。

## 定义

**一句话定义：** 正则表达式（Regular Expression，regex / regexp）是用一串符号来描述、匹配字符串中符合某种模式的一类文本的形式化表达；它能简洁地表示"一个字符串集合"，广泛用于文本查找、校验、提取与替换。

**通俗类比：** 像用一张"填空模板 + 通配规则"去套字符串——比如"3 个数字-4 个数字"能匹配某种电话号码格式，`*` / `+` / `?` 表示重复次数，`[abc]` 表示任选其一；凡符合模板的字符串都被"网"住。

> 多义说明：正则表达式（记法）对应理论上的正则语言（由正则文法 / 有限状态自动机识别）；工程实现有 POSIX / PCRE / RE2 等不同方言。本文兼顾理论与工程。

## 为什么需要它

"从文本里找出符合某形状的片段、或校验输入格式"若用普通字符串比较，要写大量循环与分支。正则把"模式"压成一串紧凑符号，一行就能描述并匹配 email、电话、日志字段等一类文本，是文本处理的通用利器。

## 核心机制

- **语法要素：** 字符类（`[abc]`、`\d`、`\w`）、量词（`*` `+` `?` `{n,m}`）、锚点（`^` `$`）、分组与捕获（`( )`、`(?: )`）、或（`|`）、反向引用。
- **理论基础：** 正则表达式 ⟺ 正则语言 ⟺ 有限状态自动机（Kleene 定理，见 [[有限状态机]]），匹配可由 NFA / DFA 实现。
- **匹配引擎：** 回溯型（如 PCRE，支持反向引用但可能"灾难性回溯"）与自动机型（如 RE2，线性时间但功能受限）。
- **能力边界：** 纯正则无法匹配需要计数的语言（如任意层数的括号配对，那属于上下文无关语言）。

## 具体示例

校验手机号 `^1[3-9]\d{9}$`：^ $ 锚定整串、1 开头、第二位 3-9、后 9 位数字。但用 `.*` 贪婪匹配嵌套括号会"吞"过界，且正则根本配不平任意嵌套；ReDoS 攻击正是利用回溯引擎在精心构造的输入上指数级卡死，服务端正则要警惕。

## 何时用与何时不用

- **用：** 文本搜索与替换、输入校验（邮箱、手机号）、日志解析、爬虫抽取、词法分析、命令行工具（grep / sed / awk）。
- **不用：** 解析 HTML / 嵌套语法等规则语言（该用真正的解析器）；不可信输入上慎用回溯引擎的复杂正则（防 ReDoS），可换 RE2。

## 优劣与代价

✅ 表达紧凑、强大灵活，几乎所有语言与工具都支持。
⚠️ 复杂正则可读性差；回溯引擎可能出现灾难性回溯（ReDoS）；纯正则能力有限；方言差异导致移植问题。

## 与相关概念的区别

vs [[有限状态机]]：正则表达式是描述正则语言的记法、DFA / NFA 是识别它的机器，二者等价（Kleene 定理）；vs 通配符 glob：`*` / `?` 的 glob 只匹配文件名式模式、能力弱于正则；vs 完整解析器：正则处理不了嵌套结构。

## 常见误区

- 正则表达式什么字符串模式都能匹配。
- `.*`（贪婪）和 `.*?`（懒惰）的匹配结果总是一样的。
- 所有语言 / 工具的正则语法完全通用。

## 面试速答

> 🎯 正则表达式 = 描述"一类字符串"的紧凑记法，理论等价于正则语言 / 有限状态自动机（Kleene 定理）：字符类 / 量词 / 锚点 / 分组 / 或；匹配引擎分回溯型（PCRE、支持反向引用但有 ReDoS 风险）与自动机型（RE2、线性但受限）；配不了需计数的任意嵌套结构。
