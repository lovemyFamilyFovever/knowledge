# 计算理论

## 计算理论概述

**一句话定义：** 计算理论（Theory of Computation）用严格的数学模型研究「什么问题能被计算解决」「用什么抽象机器计算」以及「解决它需要多少资源（时间/空间）」，是可计算性、复杂度与自动机理论的总称。

**通俗类比：** 计算理论像在给「可解的谜题」画地图：有些谜题根本没有通用解法（不可判定，如停机问题），有些有解法却要跑到天荒地老（不可行，如指数级），还有一大批「验证答案很快、找到答案却很难」的谜题（NP）。

> 多义说明：本文指计算机科学中的**理论分支**（自动机 / 可计算性 / 复杂度），而非某一种具体算法或工程实践。

### 三大分支

| 分支 | 核心问题 | 关键概念 |
|------|----------|----------|
| 自动机与形式语言 | 用什么抽象机器识别 / 生成语言 | 有限自动机、下推自动机、图灵机、乔姆斯基谱系 |
| 可计算性理论 | 什么问题**能 / 不能**被算法解决 | 可判定、不可判定、归约、停机问题 |
| 计算复杂度理论 | 解决问题**需要多少资源** | 时间 / 空间复杂度、P、NP、NP 完全 |

### 计算模型（详见对应词条）

- **图灵机（Turing Machine）**：无限纸带 + 读写头 + 有限控制器 + 转移规则，是可计算性的标准模型；详见 [[图灵机]]。
- **有限状态机（FSM）**：无外部存储、只「记住」当前状态，识别正则语言；详见 [[有限状态机]]。
- **乔姆斯基谱系（Chomsky Hierarchy）**：按文法生成能力从强到弱分为 0 型（递归可枚举 / 图灵机）、1 型（上下文有关 / 线性有界自动机）、2 型（上下文无关 / 下推自动机）、3 型（正则 / 有限自动机）。

### 可计算性：能算与不能算

- **可判定（decidable）**：存在算法，对任意输入都能在有限步内给出「是 / 否」并停机。
- **不可判定（undecidable）**：不存在这样的算法。经典例子是**停机问题**（Turing, 1936）——无法写出通用算法判断任意程序对任意输入是否会停机；其他如 Busy Beaver、Post 对应问题。
- **丘奇–图灵论题（Church–Turing Thesis）**：凡「有效可计算」的函数都能由图灵机计算。它是**论题而非定理**（因「有效可计算」无法形式化证明），但被广泛接受。

### 复杂度：算得起与算不起

```
第一条轴 —— 可计算性（能不能算）：
  可判定   ── 存在算法总能给出答案并停机（再按第二条轴细分）
  不可判定 ── 停机问题、Post 对应问题…（无通用算法）

第二条轴 —— 复杂度（在可判定问题内部，要花多少资源，按多项式时间归约）：
  P ⊆ NP ⊆ PSPACE ⊆ EXPTIME
  ├── P：确定型图灵机多项式时间可解（排序、最短路径、素性判定 AKS）
  ├── NP：给定答案可多项式时间验证（SAT、旅行商判定版、子集和、团问题）
  │     └── NP 完全（NPC）= NP ∩ NP-hard（SAT、3-SAT、哈密顿回路…）
  └── NP-hard：至少和 NP 中最难的一样难，未必属于 NP，甚至可能不可判定
```

> 关键澄清：**可判定性**与**复杂度**是两条不同的轴。NP-hard 是「难度下界」概念——一个可判定问题可以是 NP-hard；而停机问题是**不可判定**的，不能简单画成「可计算问题里的一个 NP-hard 子类」（原文档此处混淆，已修正）。由**时间层次定理**可知 P ⊊ EXPTIME（至少有一个包含是严格的），但 P 是否等于 NP、NP 是否等于 PSPACE 等仍是未解问题。

### P vs NP 问题

- **P**：能在多项式时间内**求解**的问题（「容易」）。
- **NP**：能在多项式时间内**验证**一个给定答案的问题（不一定容易求）。
- **核心问题**：P = NP？即「凡能快速验证的，是否也能快速求解？」
- **地位**：克雷数学研究所（Clay Mathematics Institute）2000 年公布的**千禧年七大数学难题**之一，悬赏 100 万美元；其理论基石是 Cook–Levin 定理（Cook 1971、Levin 1973 独立证明 SAT 是 NP 完全的）。
- **共识**：绝大多数理论计算机科学家相信 **P ≠ NP**，但至今无人证明。

### 时间复杂度速查

| 复杂度 | 名称 | 示例 |
|--------|------|------|
| O(1) | 常数 | 哈希表查找（平均） |
| O(log n) | 对数 | 二分查找 |
| O(n) | 线性 | 遍历数组 |
| O(n log n) | 线性对数 | 归并排序、快速排序（平均） |
| O(n²) | 平方 | 冒泡 / 插入排序 |
| O(2ⁿ) | 指数 | 子集穷举 |
| O(n!) | 阶乘 | 全排列穷举、旅行商暴力解 |

## 应用场景

- 编译器与语言设计：词法 / 语法分析建立在自动机与形式语言理论之上。
- 算法设计与分析：复杂度类指导「这个问题值不值得求精确解、要不要用近似 / 启发式」。
- 密码学：许多方案的安全性建立在「某些问题计算上困难」的假设（如大整数分解、离散对数）。
- 程序分析：静态分析中很多问题是不可判定的，工具只能做保守近似（宁可误报不漏报）。

## 优点与局限

- 优点：为「计算」「算法」「难度」提供了严格、与具体机器无关的数学定义；揭示了计算的**根本边界**（不可判定性）与**现实瓶颈**（复杂度）。
- 局限：模型高度理想化（无限纸带、忽略常数因子与实际硬件），不直接刻画工程效率；P vs NP 等核心问题悬而未决；「理论难解」与「实际难解」并不总是一致。

## 常见误区

- 把「NP」误解为「Non-Polynomial（非多项式）」。NP 指**非确定型多项式时间可验证**，且 P ⊆ NP，NP 里也有属于 P 的问题。
- 把「NP-hard」与「不可判定」混为一谈：前者是难度下界（可判定问题也能是 NP-hard），后者是根本无法判定，二者是不同的轴。
- 认为「不可判定 = 实际算不了」：不可判定指**没有对所有输入都正确的通用算法**，但很多具体实例仍可解或可近似。
- 认为复杂度类刻画的是「真实运行时间」：它描述随输入规模增长的**渐进上界**，忽略常数与低阶项。
