# 有限状态机


> 📌 **导航**：本文是 **有限状态机** 词条，属于 cs-basics 术语集。相关枢纽：[[P 与 NP]]、[[信息论基础]]、[[图灵机]]、[[布尔逻辑与逻辑门]]、[[形式语言与文法]]。

## 定义

**一句话定义：** 有限状态机（Finite State Machine，FSM）是一种抽象计算模型，由有限个状态、一个输入字母表、状态转移函数、一个初始状态和一组接受状态构成；它读取输入符号并据此在状态间转移，用于识别模式、建模行为与控制流程。

**通俗类比：** 像一台自动售货机：投币、选择、出货、找零是几个固定"状态"，你的每个操作（输入）让它从一个状态跳到另一个状态，只有走到"出货"这类特定状态才算完成——它的"记忆"仅限于当前处在哪个状态。

> 多义说明：本文以确定型有限自动机（DFA）为主线、并提及非确定型（NFA），二者识别能力等价；FSM 也常指工程中描述对象行为的状态图（state machine）。

## 为什么需要它

很多系统本质是"根据当前状态和输入决定下一步"：词法扫描、协议握手、UI 流程、硬件控制器。FSM 用有限状态 + 转移函数把这类行为精确、可穷举地刻画下来，既能识别正则模式，又能让"当前态 + 事件 → 下一态"的逻辑清晰可验证。

## 核心机制

- **运行：** 从初始状态起，每读入一个符号按 δ(当前状态, 输入) 转移到下一状态；输入读完时若停在接受状态则接受、否则拒绝。
- **DFA vs NFA：** DFA 每个 (状态, 输入) 只有唯一转移；NFA 允许多转移或 ε 转移，可通过子集构造转换为等价 DFA，二者表达能力等价。
- **能力边界：** FSM 无外部存储、只能"记住"当前状态，故能识别的语言恰是正则语言，与正则表达式等价。

| 符号 | 含义 |
|------|------|
| Q | 有限状态集合 |
| Σ | 输入字母表 |
| δ: Q × Σ → Q | 状态转移函数 |
| q₀ ∈ Q | 初始状态 |
| F ⊆ Q | 接受（终止）状态集合 |

## 具体示例

TCP 连接就是一个状态机：CLOSED→LISTEN→SYN_RCVD→ESTABLISHED→…，每个报文段（输入）触发一次确定转移；编译器词法器用 DFA 识别标识符 / 数字 / 关键字。但要匹配"任意层数括号"需要计数，超出 FSM 能力，得用下推自动机。

## 何时用与何时不用

- **用：** 编译器词法分析、正则表达式匹配引擎、通信协议与硬件控制器、游戏 AI / UI 状态 / 业务流程编排、连接状态跟踪。
- **不用：** 需要任意深度记忆 / 计数的任务（嵌套括号、aⁿbⁿ）FSM 做不到，要用下推自动机或图灵机（见 [[形式语言与文法]]）。

## 优劣与代价

✅ 模型简单直观、易于分析与实现；行为确定、可穷举验证；是正则语言的精确刻画。
⚠️ 无外部存储、处理不了需任意深度记忆的任务；DFA 状态数在最坏情况下可能指数膨胀。

## 与相关概念的区别

vs [[正则表达式]]：正则表达式是描述正则语言的记法，DFA / NFA 是识别它的机器，二者等价可互转；vs [[图灵机]]：FSM 无存储带、能力弱得多，图灵机有无限纸带、可算一切可计算函数；vs 工程状态图：后者偏行为建模，理论自动机有严格语言识别定义。

## 常见误区

- 有限状态机能识别任意模式、所有语言。
- NFA 比 DFA 能识别更多语言。
- 工程里的"状态图"和理论的"自动机"是完全一样的东西。

## 面试速答

> 🎯 FSM = (Q,Σ,δ,q₀,F)：无外部存储、只记当前状态，按输入在有限状态间转移、停在接受态即接受；DFA 每步唯一转移、NFA 可多路/ε 但子集构造后与 DFA 等价；识别能力恰为正则语言（≈正则表达式），处理不了需任意计数 / 嵌套的语言。
