# P 与 NP


> 📌 **导航**：本文是 **P 与 NP** 词条，属于 cs-basics 术语集。相关枢纽：[[P 与 NP]]、[[信息论基础]]、[[图灵机]]、[[布尔逻辑与逻辑门]]、[[形式语言与文法]]。

## 定义

**一句话定义：** P 与 NP 是计算复杂度理论中的两个核心问题类——P 指能在多项式时间内被确定型图灵机**求解**的问题,NP 指其"是"的答案能在多项式时间内被**验证**的问题;"P = NP?" 即"能快速验证的问题是否也能快速求解",是计算机科学最著名的未解问题之一。

**通俗类比：** 拼图游戏——把打乱的拼图拼好可能很费劲(求解),但别人拼好后你一眼就能核对对不对(验证)。P = NP 的问题就是:凡是"核对很快"的拼图,是否也一定能"拼得很快"?

> 多义说明:需区分 P、NP、NP-完全(NP-complete)、NP-难(NP-hard);NP 中的 N 指 **nondeterministic(非确定型)**,不是 "no polynomial"。

## 原理与机制

- **P:** 存在多项式时间算法的问题,如排序、最短路径、线性规划。
- **NP:** 给定一个"证书(witness)",可在多项式时间内验证其正确性,如 SAT、哈密顿回路、子集和。显然 P ⊆ NP。
- **NP-完全:** NP 中"最难"的一类,任何 NP 问题都能在多项式时间内归约到它;Cook–Levin 定理证明了 SAT 是 NP-完全的。
- **P = NP?:** 至今未解,主流猜想是 P ≠ NP。只要有一个 NP-完全问题存在多项式算法,则 P = NP。

## 关键组成

| 概念 | 含义 |
|------|------|
| P | 多项式时间可求解 |
| NP | 多项式时间可验证 |
| NP-完全 | NP 中最难、可被所有 NP 问题归约 |
| NP-难 | 至少和 NP-完全一样难(未必属于 NP) |
| 多项式归约 | 把一个问题转换为另一个的手段 |

## 应用场景

- 算法设计与选型(判定问题是否可能有高效精确解)
- 密码学(安全性依赖某些问题的计算困难性)
- 调度、路径规划、组合优化(常遇 NP-完全问题)
- 近似算法与启发式算法的理论动机

## 优点与局限

- 优点:作为理论框架精确刻画问题"难易",指导算法策略与工程取舍。
- 局限:多项式时间忽略了常数因子与实际可行性(如 O(n^100) 理论上是 P 却不实用);基于最坏情况,不涵盖平均情形与概率算法。

## 常见误区

- NP 不是"不可解"或"非多项式(non-polynomial)"的缩写。
- NP-难问题不一定属于 NP(有的连"验证"都不快)。
- "P = NP 尚未被证明"不等于"P ≠ NP 已被证明",两者都还是开放问题。
