# P 与 NP


> 📌 **导航**：本文是 **P 与 NP** 词条，属于 cs-basics 术语集。相关枢纽：[[P 与 NP]]、[[信息论基础]]、[[图灵机]]、[[布尔逻辑与逻辑门]]、[[形式语言与文法]]。

## 定义

**一句话定义：** P 与 NP 是计算复杂度理论中的两个核心问题类——P 指能在多项式时间内被确定型图灵机求解的问题，NP 指其"是"的答案能在多项式时间内被验证的问题；"P = NP?" 即"能快速验证的问题是否也能快速求解"，是计算机科学最著名的未解问题之一。

**通俗类比：** 拼图游戏——把打乱的拼图拼好可能很费劲（求解），但别人拼好后你一眼就能核对对不对（验证）。P = NP 问的就是：凡是"核对很快"的拼图，是否也一定能"拼得很快"？

> 多义说明：需区分 P、NP、NP-完全（NP-complete）、NP-难（NP-hard）；NP 中的 N 指 nondeterministic（非确定型），不是 "no polynomial"。

## 为什么需要它

工程上判断"这个问题有没有高效精确解"决定策略：能多项式求解就求最优，是 NP-完全就得转近似 / 启发式 / 指数算法。复杂度类给"难易"一个不依赖具体机器的精确定义，也是密码学"计算困难性"假设的理论根基。

## 核心机制

- **P：** 存在多项式时间算法的问题，如排序、最短路径、线性规划。
- **NP：** 给定一个"证书（witness）"，可在多项式时间内验证其正确性，如 SAT、哈密顿回路、子集和；显然 P ⊆ NP。
- **NP-完全：** NP 中"最难"的一类，任何 NP 问题都能在多项式时间内归约到它；Cook–Levin 定理证明 SAT 是 NP-完全的。
- **NP-难：** 至少和 NP-完全一样难，但未必属于 NP（如停机问题、TSP 的优化版）。
- **P = NP?：** 至今未解，主流猜想是 P ≠ NP；只要有一个 NP-完全问题存在多项式算法，则 P = NP。

| 概念 | 含义 |
|------|------|
| P | 多项式时间可求解 |
| NP | 多项式时间可验证 |
| NP-完全 | NP 中最难、可被所有 NP 问题归约 |
| NP-难 | 至少和 NP-完全一样难，未必属于 NP |
| 多项式归约 | 把一个问题转换为另一个的手段 |

## 具体示例

SAT（布尔可满足性）是第一个被证明的 NP-完全问题：任何 NP 问题都能多项式归约到它，所以"SAT 有没有多项式算法"等价于"P = NP 吗"；实践中 TSP、图着色被判为 NP-完全后，工程上转用近似 / 退火而非死磕精确解。

## 何时用与何时不用

- **用：** 算法设计与选型（判定问题是否可能有高效精确解）、密码学（安全性依赖计算困难性）、调度 / 路径 / 组合优化、近似与启发式算法的理论动机。
- **注意：** 多项式时间忽略常数与实际可行性（O(n^100) 理论属 P 却不实用）；基于最坏情况，不含平均情形与概率算法。

## 优劣与代价

✅ 作为理论框架精确刻画问题的"难易"，指导算法策略与工程取舍。
⚠️ 多项式不保证实际快；只看最坏情况；NP 是渐近概念，对小规模实例未必适用。

## 与相关概念的区别

vs [[图灵机]]：P / NP 用（确定 / 非确定）图灵机的时间界定复杂度；vs [[计算理论]]：可计算性问"能不能算"，复杂度问"算得快不快"，P vs NP 属后者；vs 多项式归约：归约是"证明 NP-完全"的工具，不是复杂度类本身。

## 常见误区

- NP 是"非多项式（non-polynomial）"问题的缩写。
- NP-难问题一定属于 NP。
- "P = NP 尚未被证明"就等于"P ≠ NP 已被证明"。

## 面试速答

> 🎯 P = 多项式时间可求解、NP = 多项式时间可验证（N 是 nondeterministic 非"非多项式"），P⊆NP；NP-完全最难、可被所有 NP 归约（Cook–Levin 证 SAT），NP-难未必属于 NP；P=NP? 未解、主流猜 ≠，工程上判 NP-完全就转近似 / 启发式。
