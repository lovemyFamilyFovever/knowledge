# 数制与编码

## 进制系统

**一句话定义：** 进制（进位计数制）是用有限个数字符号、按「逢基数进一」的规则表示数值的方法；计算机内部用二进制，人类常用十进制，二者之间借助八 / 十六进制便捷转换。

**通俗类比：** 进制就是数数的「循环规则」——十进制逢 10 进 1（0~9 用完就进位），二进制逢 2 进 1（0、1 用完就进位）。

### 常见进制

| 进制 | 基数 | 符号 | 典型用途 |
|------|------|------|----------|
| 二进制 | 2 | 0,1 | 计算机底层（电平高 / 低） |
| 八进制 | 8 | 0-7 | Unix/Linux 文件权限（如 755） |
| 十进制 | 10 | 0-9 | 人类日常 |
| 十六进制 | 16 | 0-9,A-F | 颜色值、内存地址、字节的紧凑书写 |

> 为什么计算机用二进制：电子器件最容易稳定表达「通 / 断」两种状态，抗干扰强、实现简单；而十六进制与二进制转换方便（1 位十六进制 = 4 位二进制），故常作二进制的紧凑写法。

### 进制转换

**十进制 → 二进制：除 2 取余，逆序读**
```
13 ÷ 2 = 6 余 1
 6 ÷ 2 = 3 余 0
 3 ÷ 2 = 1 余 1
 1 ÷ 2 = 0 余 1
结果：1101（从下往上读）
```

**二进制 ↔ 十六进制：每 4 位一组**
```
1101 0101 = D 5 = 0xD5
```

## 有符号数的表示：原码、反码、补码

计算机普遍用**补码（two's complement）**表示有符号整数：
- **原码（sign-magnitude）**：最高位为符号位（0 正 1 负），其余为数值绝对值。
- **反码（ones' complement）**：正数同原码；负数为符号位不变、数值位按位取反。
- **补码（two's complement）**：正数同原码；负数 = 反码 + 1（等价于「绝对值按位取反再加 1」）。

```
以 8 位为例：
+5 的原/反/补码相同：0000 0101
-5：原码 1000 0101 → 反码 1111 1010 → 补码 1111 1011
```

**为何用补码：**
- 加减法可统一为加法（`a − b` = `a + (−b 的补码)`），硬件无需单独的减法器；
- 零只有唯一表示（0000 0000），避免原码 / 反码的「+0 与 −0」两套表示问题；
- n 位补码表示范围为 **−2^(n−1) ~ 2^(n−1) − 1**（8 位：−128 ~ +127），比原码 / 反码多表示一个最小负数。

## 字符编码

> 关键区分：**字符集（character set）**给每个字符分配一个**码点（code point）**；**字符编码（encoding）**才决定码点如何落成字节。二者不是一回事。

| 名称 | 类型 | 长度 | 说明 |
|------|------|------|------|
| ASCII | 字符集 + 编码 | 1 字节（7 位有效） | 128 个字符，英文与控制符 |
| Unicode | **字符集**（非编码） | 码点 U+0000~U+10FFFF | 给全球字符统一编号，共 1,114,112 个码点 |
| UTF-8 | Unicode 的一种编码 | 1~4 字节（变长） | 兼容 ASCII，互联网最常用 |
| UTF-16 | Unicode 的一种编码 | 2 或 4 字节（变长） | Windows / Java 内部常用 |
| UTF-32 | Unicode 的一种编码 | 固定 4 字节 | 定长，空间开销大 |
| GB2312 / GBK | 中文字符集 + 编码 | 1~2 字节 | 国标中文编码 |

**UTF-8 变长规则（按码点范围）：**
- U+0000–U+007F（ASCII）→ 1 字节；
- U+0080–U+07FF（拉丁扩展、希腊、西里尔等）→ 2 字节；
- U+0800–U+FFFF（绝大多数中日韩汉字）→ 3 字节；
- U+10000–U+10FFFF（生僻字、emoji 等）→ 4 字节。

## 应用场景

- 底层编程：位运算、掩码、字节序（大端 / 小端）、颜色与地址的十六进制书写。
- 数据存储与传输：整数以补码存储，文本以某种编码（多为 UTF-8）序列化。
- 跨系统交换：编码不一致是「乱码」的根源，统一采用 UTF-8 是主流做法。

## 优点与局限

- 优点：二进制物理实现简单可靠；补码统一了加减运算；十六进制便于读写二进制；Unicode + UTF-8 基本解决了全球文本的统一表示。
- 局限：进制 / 编码转换是常见 bug 源（字节序、编码猜错导致乱码）；UTF-8 变长使「随机访问第 n 个字符」需从头扫描；历史遗留编码（GBK、Latin-1 等）仍造成兼容问题。

## 常见误区

- **Unicode ≠ UTF-8，也不是「占 2~4 字节的编码」**：Unicode 是**字符集 / 码点空间**，UTF-8/16/32 才是它的**编码实现**；「Unicode 占 2-4 字节」是常见错误说法（原文档此处有误，已修正）。
- 认为「一个字符恒等于一个字节」：UTF-8 下一个汉字常占 3 字节，一个 emoji 常占 4 字节。
- 混淆**码点、字节、字形**：一个「字」可能由多个码点组合（如带音标字符、emoji ZWJ 序列），却显示为一个字形。
