# 数制与编码


> 📌 **导航**：本文是 **数制与编码** 词条，属于 cs-basics 术语集。相关枢纽：[[P 与 NP]]、[[信息论基础]]、[[图灵机]]、[[布尔逻辑与逻辑门]]、[[形式语言与文法]]。

## 定义

**一句话定义：** 数制与编码是计算机表示数值与字符的基础——进制按"逢基数进一"用有限符号表示数、计算机内部用二进制，有符号整数普遍用补码表示，字符则经编码映射为字节。

**通俗类比：** 进制是数数的"循环规则"——十进制逢 10 进 1、二进制逢 2 进 1；编码像电报密码本，把每个字符换成约定的字节序列。

> 多义说明：本文涵盖进制与转换、有符号数的原码 / 反码 / 补码、字符集与 UTF-8 编码三块。

## 为什么需要它

硬件只能存比特：数值要用某种进制编码、负数要选一种能让减法变加法的表示（补码）、全球字符要统一映射成字节（Unicode + UTF-8）。这些约定是位运算、字节序、乱码、颜色值等一切底层编程的地基。

## 核心机制

### 进制与转换

常用进制：二进制（基数 2、计算机底层）、八进制（0-7、Unix 文件权限如 755）、十进制、十六进制（0-9,A-F、颜色 / 内存地址）。计算机用二进制是因为电子器件最易稳定表达"通 / 断"两态；1 位十六进制 = 4 位二进制，故十六进制是二进制的紧凑写法。十进制→二进制：除 2 取余、逆序读（13 → 1101）；二进制↔十六进制：每 4 位一组（1101 0101 = 0xD5）。

| 进制 | 基数 | 符号 | 典型用途 |
|------|------|------|----------|
| 二进制 | 2 | 0,1 | 计算机底层（电平高 / 低） |
| 八进制 | 8 | 0-7 | Unix 文件权限（755） |
| 十进制 | 10 | 0-9 | 人类日常 |
| 十六进制 | 16 | 0-9,A-F | 颜色值、内存地址 |

### 有符号数：原码 / 反码 / 补码

原码最高位为符号位、其余为绝对值；反码负数符号位不变、数值位取反；补码负数 = 反码 + 1。以 8 位为例：+5 三者同 0000 0101；-5 原 1000 0101 → 反 1111 1010 → 补 1111 1011。用补码是因为：加减统一为加法（a − b = a + (−b 的补码)，硬件无需减法器）、零只有唯一表示、n 位范围为 −2^(n−1) ~ 2^(n−1) − 1（8 位 −128 ~ +127）。

### 字符编码

字符集（给每个字符分配码点）≠ 字符编码（码点如何落成字节）。Unicode 是字符集（码点 U+0000~U+10FFFF，共 1,114,112 个），UTF-8 / UTF-16 / UTF-32 是其编码；UTF-8 变长且兼容 ASCII：ASCII 段 1 字节、拉丁扩展 2 字节、绝大多数 CJK 3 字节、生僻字 / emoji 4 字节。另有 ASCII（128 字符）与 GB2312 / GBK（中文）。

## 具体示例

汉字"中"码点 U+4E2D、UTF-8 编码占 3 字节——按"字节数 = 字符数"算长度会把中英混排算错，这是"字符串长度 / 切片乱码"类 bug 的根源；网络与文件统一用 UTF-8，正是为消除跨系统乱码。

## 何时用与何时不用

- **用：** 位运算 / 掩码、字节序（大端 / 小端）、颜色与地址的十六进制书写；整数以补码存储、文本以 UTF-8 序列化、跨系统交换统一 UTF-8。
- **注意：** UTF-8 变长使"随机访问第 n 个字符"需从头扫描；字节序 / 编码猜错是乱码主因；历史编码 GBK / Latin-1 仍存兼容问题。

## 优劣与代价

✅ 二进制物理实现简单可靠；补码统一加减；十六进制便于读写；Unicode + UTF-8 基本解决全球文本统一表示。
⚠️ 进制 / 编码转换是常见 bug 源；UTF-8 变长不利随机访问；历史遗留编码造成兼容负担。

## 与相关概念的区别

vs 字符集 vs 编码：Unicode 是字符集（码点编号）、UTF-8/16/32 才是编码（码点→字节），"Unicode 占 2-4 字节"是错误说法；vs [[布尔逻辑与逻辑门]]：那是比特间的逻辑运算，本文是比特如何组织成数与字符。

## 常见误区

- Unicode 就是 UTF-8、是一种占 2~4 字节的编码。
- 一个字符恒等于一个字节。
- 一个字符就一定是一个码点、一个字形。
