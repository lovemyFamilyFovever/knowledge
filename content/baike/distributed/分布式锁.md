# 分布式锁


> 📌 **导航**：本文是 **分布式锁** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** 分布式锁(Distributed Lock)是在分布式系统中协调多个节点/进程对共享资源进行互斥访问的机制,保证同一时刻只有一个客户端持有锁,从而避免并发操作导致的数据不一致。

**通俗类比：** 像多人共用一间会议室——门口挂一把钥匙(锁),谁拿到钥匙才能进去使用,用完挂回;这样即使大家不在同一栋楼(不同节点),也不会同时挤进去抢白板。

> 多义说明:单机锁(synchronized / mutex)只在单进程内有效;跨节点互斥需要分布式锁。常见实现基于 Redis、ZooKeeper、etcd 或数据库。本文综述。

## 原理与机制

- **核心要求:** 互斥(同一时刻仅一个持有)、防死锁(持有者崩溃后能自动释放)、可重入、高性能与高可用。
- **Redis 实现:** 用 `SET key value NX PX <ttl>` 原子地"加锁 + 设过期";value 存唯一持有者标识;释放时用 Lua 脚本校验标识再删除,避免误删他人锁;Redlock 用多节点投票(存在争议)。
- **ZooKeeper / etcd 实现:** 临时顺序节点 + watch,或 lease + revision;会话断开可自动释放,天然处理客户端失联。
- **难点:** 网络分区、时钟漂移、GC 停顿可能导致"锁已过期但持有者仍以为持有",可用 fencing token(单调递增令牌)缓解。

## 关键组成

| 组成 | 作用 |
|------|------|
| 锁存储(Redis/ZK/etcd) | 保存锁状态 |
| 原子加/解锁操作 | 保证互斥与防误删 |
| TTL / 租约 | 防死锁、自动过期 |
| 唯一持有者标识 | 只允许持有者释放 |
| 看门狗续期 | 业务未完成时延长锁 |
| fencing token | 防止过期持有者写入 |

## 应用场景

- 分布式定时任务防重复执行
- 库存扣减、秒杀等临界区互斥
- 分布式事务与 leader 选举
- 缓存击穿时的重建互斥

## 优点与局限

- 优点:提供跨节点互斥、保护共享资源、是实现关键并发控制的手段。
- 局限:引入额外依赖与延迟;正确性依赖时钟/网络假设;Redis 主从切换可能丢锁;实现复杂、易出死锁/误删/续期等 bug。

## 常见误区

- `SETNX` + `EXPIRE` 两步非原子(应使用 `SET NX PX` 一步完成)。
- 不设 TTL 会因持有者崩溃而造成死锁。
- 释放锁必须校验持有者标识,否则可能删掉别人的锁。
- 分布式锁在网络分区下不能保证绝对安全(参见对 Redlock 的批评)。
