# 缓存三大问题

> 📌 **导航**：本文是 **缓存三大问题** 词条，由 [[分布式ID与缓存术语百科]] 拆分而来；读写姿势与层级总览见 [[缓存策略]]。

## 定义

**一句话定义：** 缓存三大问题指缓存系统中导致请求绕过缓存、直击数据库的三类事故——穿透（查询本就不存在的数据）、击穿（单个热点 key 过期瞬间被高并发回源）、雪崩（大批 key 同时过期或缓存整体宕机），三者成因与对策各不相同。

**通俗类比：** 把数据库想成银行金库、缓存是前台：有人来查一个根本不存在的账户（穿透）、热门业务恰在系统重启瞬间全挤进来（击穿）、或前台整层突然停电所有人涌向金库（雪崩）——都会把后端打爆。

## 为什么需要它

缓存的价值在于挡在数据库前面吸收读流量。一旦这层"挡不住"，回源洪峰直达后端就是宕机事故。穿透 / 击穿 / 雪崩正是缓存最典型的三种失效模式，面试与实战都高频，必须分清成因、对症下药。

## 核心机制

- **缓存穿透：** 查的是根本不存在的数据，缓存与库都没有，每次请求都直达 DB。对策：对空结果也缓存（短 TTL，如 60s）、用布隆过滤器先拦掉必然不存在的 key、加参数校验。注意布隆过滤器有假阳性、且不支持删除，判"可能存在"时仍需回源确认。
- **缓存击穿：** 单个热点 key 过期的一瞬间，大量并发同时发现未命中、一起回源。对策：互斥锁 / singleflight 只放一个请求去重建、其余等待；或热点 key 用逻辑过期（值里带过期时间，过期后异步刷新、读旧值不阻塞）。
- **缓存雪崩：** 大批 key 在同一时刻过期，或缓存实例整体宕机，造成回源洪峰。对策：TTL 加随机抖动错峰、缓存集群高可用（多节点 + 副本）、多级缓存兜底、并配熔断限流降级（见 [[限流]]）。

## 具体示例

秒杀商品详情接口：缓存设 1h 基础 TTL + 0–5min 随机抖动防雪崩；对 itemId 先用布隆过滤器拦截不存在的伪造 ID 防穿透；最热的几个 SKU 用互斥锁重建或逻辑过期防击穿。三者叠加，才能把"缓存层"这道闸守稳。

## 何时用与何时不用

- **用：** 高并发读多、缓存前置的接口（商品详情、榜单、社交动态）都应默认按这三类事故设计防护。
- **不用：** 低频、内部、QPS 极低的场景不必堆全套（布隆过滤器 + 互斥锁 + 抖动），按需取舍以免徒增复杂度。

## 优劣与代价

✅ 针对性防护能让缓存在高并发下持续挡住后端，避免被雪崩式打穿。
⚠️ 布隆过滤器有假阳性与删除难题、且占内存；互斥锁降低并发重建速度；逻辑过期会短时读到旧值；防护手段叠加会增加复杂度。

## 与相关概念的区别

vs [[缓存策略]]：缓存策略讲读写的总体姿势（Cache-Aside 等）与层级，本文专讲它失效时的三类事故与对策；vs 缓存一致性：那关心"写后读到的值新不新"，本文关心"读请求会不会绕过缓存打到 DB"，是两个不同维度（见 [[分布式缓存]]）。

## 常见误区

- 缓存穿透、击穿、雪崩是同一个问题的三种叫法。
- 布隆过滤器说"可能存在"就一定存在，可以放心直接返回。
- 给所有 key 设同一个过期时间最省心。

## 面试速答

> 🎯 缓存三大问题=穿透（查不存在数据→空值短 TTL + 布隆过滤器）、击穿（热点 key 过期瞬间并发回源→互斥锁 / singleflight 或逻辑过期）、雪崩（大批 key 同时过期或宕机→TTL 抖动 + 高可用 + 熔断限流）。
