# CAP 定理


> 📌 **导航**：本文是 **CAP 定理** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** CAP 定理指出,一个分布式数据存储系统在网络分区(P)不可避免的前提下,一致性(C)与可用性(A)不可兼得——当分区发生时,系统只能在"保证数据一致"与"保证服务可用"之间二选一。

**通俗类比：** 两家连锁分店之间通讯中断(分区)时:要么暂停营业直到能核对库存(牺牲可用性保一致),要么照常卖货各记各的、事后再对账(牺牲一致保可用)——通讯既然断了,你无法既实时同步又照常营业。

> 多义说明:此处 C(一致性,常指线性一致/强一致)、A(可用性,每个未故障节点对请求都给出响应)、P(分区容错,网络分区下仍继续运作)。**CAP 的 C 与 ACID 的 C 含义不同**。

## 原理与机制

- 在真实网络中,分区(P)无法根除,故实际权衡发生在 **C 与 A 之间**:
  - **CP 系统:** 分区时拒绝可能返回不一致结果的请求(牺牲 A),如基于强一致共识的存储。
  - **AP 系统:** 分区时继续响应,但可能返回旧数据(牺牲 C),事后通过最终一致收敛。
- **无分区时**,C 与 A 可同时满足。
- 延伸模型 **PACELC:** 分区(P)时在 A 与 C 间权衡;否则(E)在延迟(L)与一致性(C)间权衡——补充了 CAP 未覆盖的正常期权衡。

## 关键组成

| 维度 | 含义 |
|------|------|
| Consistency(一致性) | 所有节点同一时刻看到相同数据(强/线性一致) |
| Availability(可用性) | 每个未故障节点对请求都返回(非错误)响应 |
| Partition tolerance(分区容错) | 网络分区(节点间通信中断)时系统仍能运作 |

## 应用场景

- 分布式数据库/存储选型(CP:强一致共识系统;AP:最终一致的 NoSQL)
- 多副本与共识协议设计(如 Raft/Paxos 语境下的取舍)
- 跨区域部署与 SLA/容灾设计
- 缓存与数据同步策略权衡

## 优点与局限

- 优点:提供清晰、简洁的分布式设计权衡框架,指导架构选型。
- 局限:易被过度简化误解(C/A 并非绝对二元,而是程度问题);仅描述分区发生时的取舍,忽略延迟(PACELC 补充);不适用于无分区场景。

## 常见误区

- 误以为"三选二可任选":P 在分布式网络中几乎必选,实际是 C 与 A 的二选一。
- 把 CAP 的"一致"等同于 ACID 的"一致":前者关乎副本间数据一致,后者关乎事务约束完整。
- 认为 CAP 否定同时兼顾 C 与 A:在**无分区**时二者可兼得,CAP 只约束分区发生时。
