# 心跳检测


> 📌 **导航**：本文是 **心跳检测** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** 心跳检测(Heartbeat)是分布式系统中节点间周期性发送小型"存活信号"以监测彼此健康状态的机制;若在一定时间内未收到某节点的心跳,则判定其疑似失效,从而触发故障转移、剔除或告警。

**通俗类比：** 像值班时定期"报平安"——每个人每隔一会儿喊一声"我还在"(心跳);若某人很久没出声,就判定他可能出事了(掉线/宕机),启动预案由别人顶上。

> 多义说明:心跳用于服务注册、集群管理、主从探活、连接保活等,常与超时(timeout)、健康检查配合。本文讨论心跳机制。

## 原理与机制

- **机制:** 被监控节点周期性(如每 N 秒)向监控方/注册中心发送心跳;监控方记录最后心跳时间,超过阈值(如 3N)未收到即判失效。
- **应用点:** 服务注册与发现(实例心跳续约,失联则摘除)、集群 leader 探活、长连接保活(TCP keepalive、WebSocket ping/pong)、主从复制探活。
- **权衡:** 心跳间隔与超时阈值——太频繁增加开销,太稀疏则故障发现慢;需处理网络抖动导致的误判。

## 关键组成

| 组成 | 说明 |
|------|------|
| 心跳周期 | 发送存活信号的间隔 |
| 超时阈值 | 多久未收到判定失效 |
| 存活判定 | 依据最后心跳时间 |
| 失联处理 | 摘除 / 切换 / 告警 |
| 抖动处理 | 避免网络波动误判 |

## 应用场景

- 服务注册中心(Eureka / Nacos / Consul 心跳)
- 集群高可用(主从切换)
- 长连接保活
- 消息中间件节点探活、负载均衡健康检查

## 优点与局限

- 优点:及时发现失效节点、支撑故障转移与高可用、实现简单。
- 局限:心跳有延迟(非实时);网络抖动/假死会致误判;间隔与阈值需权衡;心跳本身有开销。

## 常见误区

- 心跳超时 ≠ 节点一定宕机(可能网络分区/假死,需结合其他判断)。
- 心跳间隔与超时阈值要权衡(发现速度 vs 开销/误判)。
- "收到心跳"只证明节点活着,不证明它能正常提供服务(需业务级健康检查)。
- 脑裂场景下心跳可能双向失联。
