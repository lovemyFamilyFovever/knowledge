# 分布式 ID

## 定义

**一句话定义：** 分布式 ID 是在分布式系统中为数据生成全局唯一标识的方案;当业务分库分表或多服务并行写入时,数据库自增主键不再适用,需要一种能跨节点保证唯一、且通常兼顾趋势递增、高性能与高可用的 ID 生成机制。

**通俗类比：** 像多个网点同时开单却要求单号全局不重复——不能各网点都从 1 开始(会撞号),得有一套统一规则(如"网点编号 + 时间 + 序号"),保证全国所有单号既唯一又大致有序。

> 多义说明:区别于单库自增 ID;常见实现有 UUID、数据库号段、Redis INCR、雪花算法(Snowflake)等。本文综述。

## 原理与机制

- **UUID:** 128 位、本地生成、无中心依赖;但无序(作主键伤索引性能)、占空间、可读性差。
- **数据库自增 / 号段模式:** 中心发号或批量取号段缓存到本地;简单,但中心有压力/单点风险。
- **Redis INCR:** 原子自增,性能高,但依赖 Redis 的可用性与持久化。
- **雪花算法(Snowflake):** 64 位 = 时间戳 + 机器 ID + 序列号;本地生成、趋势递增、高性能;依赖时钟(时钟回拨需处理)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 全局唯一 | 跨节点不重复 |
| 趋势递增 | 利于索引与排序 |
| 高性能 / 高可用 | 生成效率与可用性 |
| 生成方式 | UUID / 号段 / Redis / Snowflake |
| 时钟回拨处理 | Snowflake 的关键难点 |

## 应用场景

- 分库分表的全局主键
- 订单号 / 流水号
- 分布式系统的消息 ID
- 去重与幂等的业务键

## 优点与局限

- 优点:支撑水平扩展、跨节点唯一、可趋势递增(利于 B+ 树索引)。
- 局限:各方案均有权衡(UUID 无序、中心发号有单点、Snowflake 依赖时钟);迁移/兼容成本高;需处理时钟回拨与机器 ID 分配。

## 常见误区

- 分布式 ID 不必严格连续,趋势递增即可。
- UUID 全局唯一但无序,作主键会损害 B+ 树插入性能。
- Snowflake 依赖机器时钟,回拨会生成重复或倒退的 ID,需特殊处理。
- 机器 ID 分配需要协调,避免重复。
