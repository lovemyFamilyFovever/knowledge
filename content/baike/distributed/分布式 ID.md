# 分布式 ID


> 📌 **导航**：本文是 **分布式 ID** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** 分布式 ID 是在分布式系统中为数据生成全局唯一标识的方案——分库分表或多服务并行写入时数据库自增主键失效，需要跨节点唯一、且通常兼顾趋势递增、高性能与高可用的发号机制。

**通俗类比：** 像多个网点同时开单却要求单号全国不重复——不能各网点都从 1 开始（会撞号），得有统一规则（网点编号 + 时间 + 序号），既唯一又大致有序。

> 多义说明：区别于单库自增 ID；常见实现有 UUID、数据库号段、Redis INCR、雪花算法（Snowflake）等。

## 为什么需要它

一旦分库分表或微服务多节点并行写，单库 `AUTO_INCREMENT` 会跨库撞号。业务又需要全局唯一主键做订单号、消息 ID、幂等键，还要尽量趋势递增以喂饱 B+ 树索引——这就是分布式 ID 要同时满足的唯一性、有序性、性能与可用性。

## 核心机制

- **UUID：** 128 位本地生成、无中心依赖；但完全无序（作主键伤 B+ 树）、占空间、可读性差。
- **数据库自增 / 号段模式：** 中心批量发号段、缓存到本地再取，减少 DB 压力；简单但中心有单点风险。
- **Redis INCR：** 原子自增、性能高；依赖 Redis 的可用性与持久化。
- **雪花算法 Snowflake：** 64 位 = 时间戳 + 机器 ID + 序列号，本地生成、趋势递增、高性能；难点在时钟回拨处理与机器 ID 分配。

## 具体示例

订单号用 Snowflake：41 位毫秒时间戳 + 10 位机器 ID + 12 位序列号，同一毫秒最多 4096 个号，本机内存发号无网络往返，整体随时间趋势递增、利于索引。

## 何时用与何时不用

- **用：** 分库分表全局主键、订单 / 流水号、消息 ID、去重与幂等键。
- **不用：** 单库单表用自增即可；对外暴露时也别直接给可猜测的连续自增（防遍历）。

## 优劣与代价

✅ 支撑水平扩展、跨节点唯一、可趋势递增利于 B+ 树索引。
⚠️ 各方案都有取舍：UUID 无序、中心发号有单点、Snowflake 依赖时钟；还要处理时钟回拨与机器 ID 分配。

## 与相关概念的区别

vs 单库自增主键：自增只在单实例内唯一且连续，跨库会撞号；分布式 ID 用"放弃严格连续"换"全局唯一 + 趋势递增"。

## 常见误区

- 分布式 ID 必须严格连续递增。
- UUID 最适合直接当数据库主键。
- 雪花算法不怕服务器时钟回拨。

## 面试速答

> 🎯 分布式 ID = 跨节点全局唯一 + 趋势递增的发号方案：UUID 无序、号段 / Redis 有中心、Snowflake（时间戳 + 机器 ID + 序列号）本地高性能但怕时钟回拨。
