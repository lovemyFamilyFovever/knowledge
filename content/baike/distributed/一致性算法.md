# 一致性算法


> 📌 **导航**：本文是 **一致性算法** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 分布式一致性

**一句话定义：** 一致性算法（更精确地说是**共识算法**，Consensus）让分布式系统中的多个节点对「某个值或某一操作序列」达成一致，即使部分节点发生故障或消息延迟，也能保证结果的正确与一致。

**通俗类比：** 就像一群人投票决定一件事——即使有人中途离场或通信中断，只要多数人还在且遵守规则，最终也能达成一个大家都承认、且不会自相矛盾的结果。

> 多义说明：中文常把 Consensus（共识）与 Consistency（一致性）都译作「一致性」，但二者不同——**共识**是「多节点就某值达成一致」的**过程/协议**（Paxos、Raft）；CAP 里的 **Consistency** 是「读到最新写入」的**数据属性**。本文讨论的是前者（共识算法）。

## 原理与机制

### Paxos

**角色：** Proposer（提案者，提出方案）、Acceptor（接受者，投票）、Learner（学习者，获知最终决议）。

**两阶段（Basic Paxos）：**
1. **Prepare 阶段**：Proposer 选一个全局递增的提案编号 n 发出 Prepare；Acceptor 承诺不再接受编号 < n 的提案，并回传已接受的最大提案。
2. **Accept 阶段**：Proposer 据此选定值发出 Accept；获得**多数派（quorum）**接受后，该值被选定。

### Raft（更易理解，工程中更常用）

**Leader 选举：** 节点初始为 Follower；超时未收到心跳则转为 Candidate 发起投票；获得多数票成为 Leader；Leader 定期发心跳维持权威（每个任期 term 至多一个 Leader）。

**日志复制：**
```
Client → Leader → 追加到本地日志
       → 并行发送 AppendEntries 给所有 Follower
       → 多数派确认后 Commit
       → 应用到状态机并返回结果给 Client
```

**安全性保证：** 选举限制（只有日志足够新的节点才能当选）、日志匹配（相同索引与任期的日志条目内容一致）。

### 理论边界（FLP 与故障模型）

- **FLP 不可能定理**（Fischer-Lynch-Paterson, 1985）：在**纯异步**系统中，即使只有一个进程可能崩溃，也**不存在**保证在有限步内终止的确定性共识算法。实践中靠「部分同步假设 + 超时 + 随机化」绕开。
- **故障模型**：Paxos / Raft 处理的是**崩溃故障**（crash fault，节点只会「停止响应」）；若节点可能作恶（**拜占庭故障**），需 PBFT 等拜占庭容错算法（区块链常用）。

## 关键组成（Raft 角色）

| 角色 | 职责 |
|------|------|
| Leader | 处理客户端请求、发起日志复制、发心跳 |
| Follower | 被动响应 Leader / Candidate，不主动发起请求 |
| Candidate | 选举过程中的中间态，争取成为 Leader |
| Term（任期） | 逻辑时钟，用于识别过期的 Leader 与选票 |

## 应用场景

- 分布式协调与配置中心：etcd、Consul（Raft），ZooKeeper（**ZAB**，与 Paxos 同源但非同一算法），Google Chubby（Paxos）。
- 复制状态机（replicated state machine）、元数据管理、Leader 选举、分布式锁。
- 数据库 / 存储的多副本强一致复制。

## 优点与局限

- 优点：为分布式系统提供**强一致**与容错基础，是众多一致性系统的理论基石；Raft 相比 Paxos 更易理解与正确实现。
- 局限：需要多数派在线（无法容忍超过半数节点故障）；写路径需多轮通信，**牺牲部分可用性与性能**；集群规模通常取奇数（3/5/7）以平衡容错与开销。

## 常见误区

- 把 ZooKeeper 说成「用 Paxos」：ZooKeeper 用的是 **ZAB**（ZooKeeper Atomic Broadcast），与 Paxos/Raft 同属共识但实现不同（原文档此处已修正）。
- 混淆「共识（consensus）」与 CAP 的「一致性（consistency）」：前者是协议过程，后者是数据属性。
- 以为 Paxos/Raft 能防作恶节点：它们只容忍**崩溃故障**，拜占庭场景需 PBFT 等。
- 认为「多数派」是多数在线节点：应是**全体节点的多数**（N/2+1），故 5 节点集群最多容忍 2 个故障。
