# 一致性算法

## 分布式一致性

**一句话定义：** 一致性算法让多个节点对某个值达成共识，即使部分节点故障。

**通俗类比：** 就像一群人要投票决定一件事——即使有人中途离场或通信中断，最终也要达成一个大家都能接受的结果。

### Paxos

**角色：**
- Proposer（提案者）：提出方案
- Acceptor（接受者）：投票
- Learner（学习者）：学习最终决定

**两阶段：**
1. Prepare阶段：Proposer发提案，Acceptor承诺
2. Accept阶段：Proposer发最终值，Acceptor接受

### Raft（更易理解）

**核心机制：**

**Leader选举：**
- 所有节点初始为Follower
- 超时没收到心跳→变为Candidate
- 发起投票，获得多数票→成为Leader
- Leader定期发心跳维持权威

**日志复制：**
```
Client → Leader → 写入本地日志
       → 并行发送给所有Follower
       → 多数确认后Commit
       → 返回结果给Client
```

**安全性保证：**
- 选举限制：只有日志最全的才能当选
- 日志匹配：相同索引和任期的日志条目内容相同

### 对比

| 特性 | Paxos | Raft |
|------|-------|------|
| 理解难度 | 难 | 较易 |
| 实现复杂度 | 高 | 较低 |
| 工程应用 | Chubby, ZooKeeper | etcd, Consul |
| 一致性 | 强一致 | 强一致 |
