# 一致性算法


> 📌 **导航**：本文是 **一致性算法** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** 一致性算法（更准确地说是共识算法 Consensus）让分布式中多个节点就某个值或操作序列达成一致，即使部分节点故障或消息延迟，仍保证结果正确且不自相矛盾。

**通俗类比：** 像一群人投票定一件事——即使有人中途离场或通信中断，只要多数人在且遵守规则，最终也能达成一个大家都承认、不会自相矛盾的结果。

> 多义说明：中文把 Consensus（共识）与 Consistency（一致性）都译作"一致性"，但二者不同——共识是"多节点就某值达成一致"的协议过程（Paxos、Raft），CAP 的 Consistency 是"读到最新写入"的数据属性。本文讲共识算法。

## 为什么需要它

多副本系统必须在部分节点宕机、网络延迟下，仍对"谁当主、这条日志排第几、值是什么"达成唯一共识，否则会脑裂、丢数据。共识算法是分布式锁、配置中心与强一致复制的理论基石。

## 核心机制

### Paxos

角色为 Proposer（提案者）、Acceptor（接受者投票）、Learner（获知决议）。Basic Paxos 分两阶段：Prepare 阶段 Proposer 选全局递增提案号 n 发 Prepare，Acceptor 承诺不再接受更小编号并回传已接受的最大提案；Accept 阶段据此选定值发 Accept，获多数派（quorum）接受后该值被选定。

### Raft（更易理解，工程常用）

把共识拆成 Leader 选举、日志复制与安全性。选举：节点初始为 Follower，超时未收到心跳转 Candidate 发起投票，过半票者成为 Leader，每个任期 term 至多一个 Leader。下面的流程演示一次客户端请求如何被多数派确认后落状态机：

```
Client → Leader：追加本地日志
       → 并行 AppendEntries 发给所有 Follower
       → 多数派确认后 Commit
       → 应用到状态机并返回结果给 Client
```

安全性靠选举限制（只有日志足够新的节点能当选）与日志匹配（相同索引与任期的条目内容一致）保证。Raft 的三类角色职责如下：

| 角色 | 职责 |
|------|------|
| Leader | 处理客户端请求、发起日志复制、发心跳 |
| Follower | 被动响应 Leader / Candidate，不主动发起 |
| Candidate | 选举过程中的中间态，争取成为 Leader |
| Term（任期） | 逻辑时钟，识别过期的 Leader 与选票 |

### 理论边界与故障模型

FLP 不可能定理（Fischer-Lynch-Paterson，1985）指出：纯异步系统里哪怕只有一个进程可能崩溃，也不存在保证在有限步内终止的确定性共识算法；实践靠"部分同步假设 + 超时 + 随机化"绕开。故障模型上，Paxos / Raft 只处理崩溃故障（节点停止响应）；若节点可能作恶（拜占庭故障），需 PBFT 等拜占庭容错算法（区块链常用）。

## 具体示例

etcd / Consul 用 Raft、ZooKeeper 用 ZAB、Google Chubby 用 Paxos，都为选主、配置一致性与复制状态机提供强一致底座。

## 何时用与何时不用

- **用：** 需要跨节点对单一事实达成强一致——选主、分布式锁、元数据 / 配置中心、多副本强一致复制。
- **不用：** 只需最终一致的读多写少场景（用复制 + 仲裁读写更省）；集群无法容忍过半节点下线时也别硬上，多数派在线是前提。

## 优劣与代价

✅ 提供强一致与容错基础，是众多一致性系统的理论基石；Raft 比 Paxos 更易理解与正确实现。
⚠️ 需多数派（N/2+1）在线，容忍不了过半故障；写路径多轮通信，牺牲部分可用性与性能；集群规模通常取奇数 3/5/7。

## 与相关概念的区别

vs CAP 的 Consistency：共识是"达成一致"的协议过程，CAP 一致性是数据属性，二者不同；vs 2PC：2PC 依赖单一协调者、有单点与阻塞问题，共识算法去中心化、能容忍协调者故障。

## 常见误区

- ZooKeeper 用的是 Paxos 算法。
- "共识（consensus）"和 CAP 的"一致性（consistency）"是一回事。
- Paxos / Raft 能防住会作恶的拜占庭节点。

## 面试速答

> 🎯 一致性算法 = 共识协议（Paxos 两阶段 / Raft 选举+日志复制），让多数节点就某值达成一致、容忍崩溃故障；靠 quorum 保强一致，受 FLP 限制、用超时+随机化绕开。
