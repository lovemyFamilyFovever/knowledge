# 异地多活

## 定义

**一句话定义：** 异地多活是一种高可用架构,指在地理上分散的多个数据中心同时对外提供服务(都为"活"节点),任一机房故障时流量可切换到其他机房、业务不中断;区别于"主备/冷热备"(备节点平时不承接流量)。

**通俗类比：** 像一家连锁银行在多个城市都设了能独立办理全部业务的网点(都在营业),某城市网点停电时客户可无缝转到其他城市继续办理;而不是"一个总行营业、其他锁门等总行倒了才开"(主备)。

> 多义说明:按范围与活节点数有同城双活、两地三中心、异地多活(单元化);按流量分配有就近接入。本文讨论异地多活。

## 原理与机制

- **多机房同时承载读写**(而非仅主机房),就近接入(如 DNS / GSLB 按地理路由)。
- **数据同步:** 跨机房数据复制(同步/异步);核心难点是一致性与延迟的权衡(跨地域延迟高,强一致代价大)。
- **单元化(set / 单元):** 按用户/业务维度把流量与数据切分到"单元",单元内闭环处理,减少跨单元调用与数据冲突。
- **故障切换:** 某机房故障时,流量与数据切到其他机房(需处理数据补齐、防脑裂)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 多活数据中心 | 同时对外服务 |
| GSLB / 就近接入 | 按地理调度流量 |
| 跨机房数据复制 | 同步 / 异步 |
| 单元化 | 流量与数据按单元闭环 |
| 流量切换 / 防脑裂 | 故障转移与一致性保护 |

## 应用场景

- 大型互联网的高可用与容灾
- 金融核心系统
- 跨地域低延迟服务
- 超大规模业务的水平扩展

## 优点与局限

- 优点:机房级容灾、业务几乎不中断、就近访问降延迟、资源利用率高(多机房都在服务)。
- 局限:架构与运维极复杂;跨地域数据一致性难(延迟 vs 一致);成本高;需单元化改造业务;切换演练与数据补齐复杂。

## 常见误区

- 异地多活 ≠ 主备:主备的备节点平时不承接流量,切换有损。
- 跨地域强一致代价极高(受光速/延迟限制),多采用最终一致 + 单元化。
- 多活不是"简单部署多份",需数据同步、流量调度、单元化、防脑裂一整套。
- 异地多活与 [[CAP 定理]] 的取舍密切相关(分区时在一致与可用间权衡)。
