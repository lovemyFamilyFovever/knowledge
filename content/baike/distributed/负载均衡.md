# 负载均衡


> 📌 **导航**：本文是 **负载均衡** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** 负载均衡(Load Balancing)是将进入系统的请求或工作负载按一定策略分发到多个后端服务器(或资源)上的技术,用以避免单点过载、提升整体吞吐与可用性,并支撑水平扩展。

**通俗类比：** 像银行大厅的叫号引导员——客人(请求)来了,引导员(负载均衡器)看哪个窗口(服务器)空闲就把人引过去,避免所有人挤在一个窗口排长队,同时让多个窗口都在干活。

> 多义说明:负载均衡可指硬件设备、软件(Nginx/HAProxy/LVS)、云服务 LB,也包括客户端负载均衡;按 OSI 层次又分四层(传输层)与七层(应用层)。本文综合讨论。

## 原理与机制

- **调度算法:** 轮询(round robin)、加权轮询、最少连接(least connections)、IP 哈希、随机、一致性哈希等。
- **工作层次:** L4 基于 IP/端口转发(性能高、不解析内容);L7 基于 URL/Header/Cookie(更灵活,可做内容路由)。
- **健康检查:** 周期探测后端存活,自动摘除故障节点、恢复后再纳入。
- **会话保持(sticky session):** 将同一用户的请求固定到同一后端,以应对有状态服务。

## 关键组成

| 组成 | 作用 |
|------|------|
| 负载均衡器 | 接收并分发请求 |
| 后端服务器池 | 实际处理请求的节点集合 |
| 调度算法 | 决定请求发往哪个后端 |
| 健康检查 | 剔除/恢复后端节点 |
| 会话保持 | 维持用户与后端的对应 |
| 虚拟 IP(VIP) | 对外统一入口地址 |

## 应用场景

- Web/API 流量分发与微服务网关
- 数据库读写分离、缓存层扩展
- CDN 与全局负载均衡(GSLB)
- 高可用与容灾架构

## 优点与局限

- 优点:提升吞吐与可用性、支持水平扩展、实现故障转移、对外隐藏后端拓扑。
- 局限:负载均衡器自身可能成为瓶颈或单点(需再为其做高可用);会话保持增加复杂度;L7 处理带来额外开销。

## 常见误区

- 负载均衡 ≠ 自动扩容:前者分发流量,后者增减实例,二者常配合使用。
- 有负载均衡 ≠ 高可用:还需健康检查、冗余与故障转移共同保障。
- 轮询未必最优:后端能力不均时应使用加权或最少连接等策略。
