# 一致性哈希

## 定义

**一句话定义：** 一致性哈希(Consistent Hashing)是一种特殊的哈希策略,它把哈希值空间组织成一个环,将节点与数据都映射到环上,数据归属于顺时针方向的第一个节点;当增减节点时只影响环上相邻的一小段数据,从而大幅减少数据迁移量。

**通俗类比：** 像把节点和数据都放到一个钟表盘上,每份数据交给它顺时针遇到的第一个"负责人"(节点);当某个负责人离开或加入,只有他附近那一小段数据需要改派,而不是所有人重新洗牌。

> 多义说明:一致性哈希用于分布式哈希表(DHT)、分布式缓存与负载均衡的分片;区别于普通取模哈希(节点数变化会导致大量重映射)。本文讨论一致性哈希。

## 原理与机制

- **普通取模的问题:** `hash(key) % N`,当节点数 N 变化时,几乎所有 key 的归属都变 → 大规模缓存失效/数据迁移。
- **哈希环:** 把 0 ~ 2³²−1 的哈希空间首尾相连成环;节点按 hash(节点) 落环,数据按 hash(key) 落环并顺时针找最近的节点。
- **局部影响:** 增删节点只影响环上相邻区段的数据(迁移量约 K/N)。
- **虚拟节点:** 每个物理节点映射多个虚拟节点到环上,解决数据倾斜、使分布更均匀。

## 关键组成

| 组成 | 作用 |
|------|------|
| 哈希环 | 组织节点与数据的空间 |
| 节点映射 | 节点落到环上位置 |
| 顺时针归属 | 数据归属最近的顺时针节点 |
| 虚拟节点 | 均衡分布、减少倾斜 |

## 应用场景

- 分布式缓存(如一致性哈希分片的 Redis / Memcached 集群)
- 分布式哈希表 DHT(Dynamo、Cassandra 的分区)
- 负载均衡、分库分表的路由

## 优点与局限

- 优点:节点增减时迁移量小、可扩展、缓解缓存雪崩。
- 局限:节点少时可能数据不均(需虚拟节点);实现比取模复杂;环大小与哈希函数选择影响分布;本身不解决热点问题。

## 常见误区

- 一致性哈希的"一致性"指映射的稳定性,与 CAP 中的"一致性(consistency)"无关。
- 不使用虚拟节点时容易数据倾斜。
- 它减少迁移量,但不能完全避免迁移。
- 哈希环大小与哈希函数需合理选择。
