# 一致性哈希


> 📌 **导航**：本文是 **一致性哈希** 词条，属于 distributed 术语集。相关枢纽：[[BASE 理论]]、[[CAP 定理]]、[[MapReduce]]、[[Saga 与 TCC]]、[[一致性哈希]]。

## 定义

**一句话定义：** 一致性哈希把哈希值空间组织成一个环，节点与数据都映射到环上、数据归属顺时针方向的第一个节点；增减节点只影响环上相邻的一小段数据，从而大幅减少迁移量。

**通俗类比：** 像把节点和数据放到钟表盘上，每份数据交给顺时针遇到的第一个"负责人"；某负责人离开或加入，只有他附近那一小段需要改派，而不是全体重新洗牌。

> 多义说明：一致性哈希用于 DHT、分布式缓存与负载均衡的分片；区别于普通取模哈希（节点数变化会导致大量重映射）。

## 为什么需要它

缓存 / 存储集群扩缩容是常态。取模哈希 `hash(key) % N` 一旦 N 变化，几乎所有 key 的归属都变，引发大规模缓存雪崩或数据迁移。一致性哈希把改动局部化到环上一小段，让扩缩容代价可控。

## 核心机制

- **哈希环：** 把 0 到 2^32-1 的哈希空间首尾相连成环，节点按 hash(节点) 落位、数据按 hash(key) 落位并顺时针找最近节点。
- **局部影响：** 增删一个节点只影响它与前驱节点之间那段 key，迁移量约 K/N。
- **虚拟节点：** 每个物理节点映射多个虚拟节点上环，解决节点少时的数据倾斜、让分布更均匀。

## 具体示例

Memcached 客户端一致性哈希分片 / Redis 集群按 slot：加一台机器时只有环上一小段 key 迁到新节点，其余缓存不因拓扑变化而整体失效。

## 何时用与何时不用

- **用：** 节点数常变的分布式缓存、DHT（Dynamo/Cassandra 分区）、分库分表路由、负载均衡。
- **不用：** 节点固定且要范围查询的场景（范围分区更简单）；它本身也不解决热点 key 问题。

## 优劣与代价

✅ 扩缩容时迁移量小、可扩展、缓解缓存雪崩。
⚠️ 节点少时易数据不均（需虚拟节点）；实现比取模复杂；不解决热点问题。

## 与相关概念的区别

vs 普通取模哈希：取模在 N 变化时几乎全量重映射，一致性哈希只改动环上相邻一段；vs [[分布式缓存]] 的分片：一致性哈希用"环 + 虚拟节点"换取比固定分段更平滑的扩缩容。

## 常见误区

- 一致性哈希的"一致性"就是 CAP 中的一致性。
- 不加虚拟节点也能保证数据均匀分布。
- 一致性哈希能完全避免数据迁移。

## 面试速答

> 🎯 一致性哈希 = 把节点和 key 都映到 0~2^32 的环上、key 归顺时针首个节点；增删只影响相邻一段（约 K/N），用虚拟节点纠偏；讲的是"映射稳定"，与 CAP 的一致性无关。
