# 时间复杂度

> 📌 **导航**：本文是 **时间复杂度** 词条，属于 algorithms 术语集。相关枢纽：[[复杂度分析]]、[[基础数据结构]]、[[排序与搜索]]、[[算法思想]]、[[空间复杂度]]。

## 定义

**一句话定义：** 时间复杂度是用大 O 记号描述的**增长率**——输入规模 n 趋于无穷时，算法基本操作次数随 n 变化的阶，它忽略常数系数与低阶项，因此与机器、语言、具体数据无关。

**通俗类比：** 比较两座山的"陡峭程度"而不是海拔：大 O 说的是山往上爬得多快，不告诉你从山脚到山顶要走几分钟。

## 为什么需要它

实测运行时间依赖硬件、编译器、缓存与数据集，换台机器结论就可能翻转，无法作为跨环境的判据。增长率则只依赖算法本身：一旦确认 n 会到 10⁶ 以上，O(n²) 的 10¹² 次操作与 O(n log n) 的 2×10⁷ 次之间是"11 天"和"20 秒"的差别，这个量级差任何工程优化都补不回来。所以选算法时先看阶，再看常数。

## 计算逻辑

- **数操作**：以规模无关的基本操作计数，单层循环 O(n)，嵌套则相乘。
- **取最高阶、丢常数**：`3n² + 5n + 10 → O(n²)`；`n² + n log n → O(n²)`。
- **串行相加、嵌套相乘**：两段独立循环是 `O(n + m)`，两层嵌套是 `O(n·m)`。
- **留意被隐藏的循环**：`in`、`list.remove`、`sum()`、切片本身都可能带 O(n)；递归要看递推式（见 [[主定理]]）。

| 阶 | n=10⁶ 时约需操作 | 直觉 |
|---|---|---|
| O(n) | 10⁶ | 亚秒 |
| O(n log n) | 2×10⁷ | 数秒 |
| O(n²) | 10¹² | 十余天 |
| O(2ⁿ) | 天文数字 | 不可行 |

## 具体示例

同求两数之和，哈希表把嵌套循环换成一次遍历，是典型的用空间换时间：

```python
def two_sum(nums, target):
    seen = {}                          # 值 -> 下标
    for i, x in enumerate(nums):
        if target - x in seen:         # dict 查表平均 O(1)
            return [seen[target - x], i]
        seen[x] = i
```

朴素双层写法是 O(n²)，这里每轮只做常数次哈希操作，整体 O(n)，额外空间 O(n)。

## 何时用与何时不用

- **用**：判断算法在预期数据规模下是否可行；评审时质疑复杂度阶；据规模反推可接受的阶（n≤50 随便写，n≤10⁴ 容忍 O(n²)，n≥10⁶ 必须 O(n) 或 O(n log n)）。
- **不用**：n 恒定很小、或瓶颈在 I/O 与网络时，大 O 分析意义有限；常数因子与缓存行为在同等阶的实现之间才是决定因素。

## 优劣与代价

✅ 与硬件无关、可比、能在写代码之前预判可行性，是算法分析的统一语言。
⚠️ 只描述渐近上界，不反映常数与实测差距，小规模下可能给出相反结论。
⚠️ 平均情况常难算，工程上多用最坏情况兜底，可能低估实际表现。

## 与相关概念的区别

- **大 O vs Θ vs Ω**：O 是上界、Ω 是下界、Θ 是同阶紧确界；日常说的"复杂度"通常指 O。
- **时间复杂度 vs [[空间复杂度]]**：一个数操作次数、一个数量额外内存，二者常互为筹码。
- **最坏 vs 平均 vs 最好**：同一算法三者可不同——快排平均 O(n log n)、最坏 O(n²)，插入排序最好可到 O(n)。
- **复杂度 vs 运行时间**：前者是函数阶，后者还包含常数与机器因素。

## 常见误区

- O(2n) 比 O(n) 慢一倍，所以要把循环里的常数优化掉。
- 平均复杂度低，就可以放心用它处理任意输入。
- 算法的时间复杂度相同，运行速度就必然一样。

## 面试速答

> 🎯 时间复杂度用大 O 描述操作次数随规模的增长率，丢常数取最高阶；选算法先看阶再看常数，注意 `in`、`remove` 等隐藏的 O(n)，最坏与平均可能差一个量级。
> 🔍 追问：为什么 O(2n) 和 O(n) 是同一阶？
> 🔍 追问：快排最坏 O(n²) 何时发生、如何规避？
