# 并查集


> 📌 **导航**：本文是 **并查集** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 并查集（Union-Find / Disjoint Set Union，DSU）是一种维护"不相交集合"的数据结构，支持两种核心操作：查找某元素所属集合的代表（find）与合并两个集合（union），常用于动态连通性问题。

**通俗类比：** 像管理一群人的"朋友圈归属"——每个人最终都指向一个"群主"（代表）；判断两人是否同群就看群主是否相同；两群合并，就让一个群主指向另一个群主。

> 多义说明：并查集是 DSU 的中文常称；本文讨论带路径压缩与按秩合并的近似 O(1) 实现。

## 为什么需要它

动态连通性——不断"加一条边/合并一组"并随时问"两点是否相连"——若每次用 DFS 判断是 O(V+E)。并查集把每个集合维护成一棵带代表元的树，find/union 两个操作在路径压缩 + 按秩合并下均摊近乎 O(1)，让"合并 + 查询"能高效穿插进行，是 Kruskal、分组、判环等的基础。

## 核心机制

- **结构：** 用数组 `parent[]` 表示一片森林，每个集合是一棵树，树根即代表元。
- **find(x)：** 沿 parent 上溯到根；路径压缩把路径上的节点直接挂到根，压平树。
- **union(x,y)：** 合并两棵树；按秩/按大小合并把矮树挂到高树下，避免退化。
- **复杂度：** 单独操作最坏 O(log n)；路径压缩 + 按秩合并后均摊近似 O(α(n))（反阿克曼函数，实际近乎常数）。

| 组成 | 作用 |
|------|------|
| parent 数组 | 表示森林中的父指针 |
| find（路径压缩） | 查找代表并压平路径 |
| union（按秩/大小） | 合并两集合、控制树高 |
| 秩 / 大小 | 决定合并方向 |
| 代表元（根） | 集合的唯一标识 |

## 具体示例

Kruskal 最小生成树：把边按权升序，对每条边用 find 判断两端是否已同连通分量，不同则 union 并选入该边——靠并查集 O(α) 地维护"是否已连通"。判无向图是否有环：加边时若两端 find 同根，说明会成环。加路径压缩后，一棵原本可能退化成链的树会被压平，后续 find 近乎 O(1)。

## 何时用 / 何时不用

- **用：** 动态/增量无向连通性、Kruskal、等价类合并、无向图判环、朋友圈分组、离线 LCA。
- **不用：** 有向图强连通（用 Tarjan/Kosaraju）；需要支持撤销 union（用可撤销/可持久化并查集）；需要集合内有序遍历或区间信息（换结构）。

## 优劣与代价

✅ 合并与查询极快（近 O(1) 均摊）、实现简洁、内存紧凑。
⚠️ 只维护"是否同集合"，标准实现不支持撤销。
⚠️ 不保存集合内顺序或附加信息（需扩展）；不做优化会退化。

## 与相关概念的区别

- **vs DFS/BFS 连通性：** 静态一次查询用遍历；频繁"合并 + 查询"交替时并查集增量维护更高效。
- **vs 平衡 BST：** 并查集只判归属、不做有序查询。
- **优化两件套：** 按秩合并控制树高、路径压缩摊平查询，二者叠加才有 O(α(n)) 均摊（Tarjan 的经典分析）。

## 常见误区

- 不做路径压缩和按秩合并，并查集的单次操作也稳定是近乎常数时间。
- 标准并查集可以直接、无需额外处理地支持撤销（un-union）操作。
- 并查集适合用来高效判断有向图的强连通性。

## 面试速答

> 🎯 并查集 DSU 维护不相交集合，find 沿 parent 上溯到代表元、union 合并两棵树；路径压缩（find 时挂到根）+ 按秩/大小合并（矮树挂高树）使操作均摊近 O(α(n))。典型用于动态无向连通性、Kruskal 判连通、判环与等价类合并。注意只管无向（强连通用 Tarjan）、标准实现不可撤销。
