# 查找算法

> 📌 **导航**：本文是 **查找算法** 词条，属于 algorithms 术语集。相关枢纽：[[排序与搜索]]、[[复杂度分析]]、[[二分查找]]、[[基础数据结构]]、[[哈希表]]。

## 定义

**一句话定义：** 查找算法是在一组记录中定位满足条件的元素的算法族——线性、[[二分查找]]、插值、二叉搜索树、哈希——区别只在**对数据预先做了什么**，以及由此换来的每次查询代价。

**通俗类比：** 找一本书：一本本翻（线性）、先按字母分区再二分（二分/ BST）、直接问管理员要架位号（哈希）。方法不同的根源是你手里有没有"已经组织好"这件事。

## 为什么需要它

查找是几乎所有系统的热点：主键定位、缓存命中、去重判存、外键校验。把"每次 O(n) 扫全表"换成"平均 O(1) 查哈希"或"O(log n) 二分"，是数据库索引、布隆过滤器、LRU 缓存、跳表这一整套工程设施的理论起点。更重要的是它揭示了**预处理与查询的分工**：越常查的数据越值得先组织好。

## 核心机制

- **线性查找**：逐个比对，O(n)、无需任何前提，无序或链表唯一可行；也可用于无法比较、只能判等的场景。
- **二分查找**：要求**有序 + 随机访问**，每次折半，O(log n)；变体 lower/upper_bound 找边界。
- **插值查找**：按 `(target-min)/(max-min)` 估位置，均匀分布时期望 O(log log n)，偏斜分布退化到 O(n)。
- **树查找**：BST/[[AVL 树]]/[[红黑树]] 查找 O(log n)，额外支持有序遍历、范围查询与前驱后继。
- **哈希查找**：`[[哈希表]]` 平均 O(1)，但无序、需处理冲突与扩容，不支持范围查询。

| 方法 | 时间 | 前提 | 支持范围查询 |
|---|---|---|---|
| 线性 | O(n) | 无 | 否 |
| 二分 | O(log n) | 有序 + 随机访问 | 是 |
| 插值 | 期望 O(log log n) | 有序且均匀分布 | 是 |
| BST/平衡树 | O(log n) | 可比较 | 是 |
| 哈希 | 平均 O(1) | 可哈希 | 否 |

## 具体示例

Python 的 `in` 对 list 是线性查找、对 set/dict 是哈希查找，这一行之差常是性能问题的根因：

```python
target in [1, 2, 3]   # O(n)：逐个比对
target in {1, 2, 3}   # 平均 O(1)：哈希定位
```

同一批数据被查一次就直接扫；要反复查就先排序用二分，或建哈希表——排序 + 二分的预处理成本 O(n log n)，只要查询次数足够多就能摊回来。

## 何时用与何时不用

- **用**：一次性或无序数据 → 线性；静态有序数组高频点查 → 二分；要有序遍历与范围查询 → 平衡树；只做判存在与点查 → 哈希；海量判存可容忍误判 → 布隆过滤器前置。
- **不用**：数据无序又只有极少数查询时，为二分而整体排序是亏的；哈希表在键分布恶劣或需有序输出时不适用；插值查找在偏斜/稀疏数据上不如老实二分。
- **别忘**：链表没有随机访问，二分不适用，应改跳表。

## 优劣与代价

✅ 把"查找"从线性开销降到对数或常数，是索引与缓存全部设计的理论基础。
✅ 不同方法对应不同数据前提，选型空间清晰可推理。
⚠️ 快的查找靠预处理买来的：排序、建树、建哈希都有成本，写入频繁时会成为负担。
⚠️ 平均 O(1) 的哈希存在最坏 O(n)，工业实现须防哈希碰撞攻击。

## 与相关概念的区别

- **查找 vs [[排序算法]]**：排序是预处理、查找是消费；先排好再二分，本质是用一次 O(n log n) 换多次 O(log n)。
- **二分 vs 插值**：都要求有序，二分固定取中点、最坏有保证，插值按值估点、依赖均匀分布。
- **哈希 vs 树**：哈希最快但无序、无范围查询；树稍慢但有序、支持范围与前驱后继。
- **精确查找 vs 近似判存**：布隆过滤器只回答"可能存在/一定不存在"，用于挡穿透。

## 常见误区

- 二分查找一定比线性查找快，所以任何时候都该用它。
- 哈希表查找是 O(1)，所以它比平衡树在任何场景都更优。
- 链表上也能对半切，所以可以对链表做二分查找。

## 面试速答

> 🎯 查找方法按数据前提分层：无序线性 O(n)、有序且可随机访问二分 O(log n)、均匀分布可插值、需有序与范围查询用平衡树、纯点查用哈希平均 O(1)；越常查越值得先做预处理组织数据。
