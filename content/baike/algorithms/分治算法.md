# 分治算法


> 📌 **导航**：本文是 **分治算法** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 分治算法（Divide and Conquer）是一种把原问题递归地分解为若干个规模更小、结构相同的子问题，分别求解后再合并子问题的解，从而得到原问题解的算法范式。

**通俗类比：** 像"分而治之"地整理一大摞卡片——把大摞分成几小摞分别排好（分、治），再把排好的小摞两两合并成有序大摞（合）；大事化小、各个击破，最后合起来。

> 多义说明：分治三步为**分（divide）、治（conquer）、合（combine）**；与动态规划（子问题重叠）有别——分治的子问题通常相互独立。本文讨论分治。

## 为什么需要它

很多问题直接解很复杂，但拆成若干同结构的小实例后，小实例更易解、且能并行；再设计一个合并步骤把子解拼回原解，就能以"递归 + 合并"高效求解。归并排序正是靠此把 O(n²) 的插入排序降到 O(n log n)——分治把"难在大处"转化为"易在小处 + 一次合并"。

## 核心机制

- **分：** 把问题划分为若干规模更小的相同子问题。
- **治：** 递归求解子问题；规模足够小时用 base case 直接求解。
- **合：** 合并子问题的解得到原问题的解。
- **复杂度分析：** 常用主定理（Master Theorem）；如归并排序 T(n)=2T(n/2)+O(n)=O(n log n)。
- **经典实例：** 归并排序、快速排序、[[二分查找]]、快速傅里叶变换、Karatsuba 大整数乘法、最近点对。

| 组成 | 说明 |
|------|------|
| 分解（divide） | 拆成更小子问题 |
| 递归求解（conquer） | 分而治之 |
| 合并（combine） | 由子解得原解 |
| base case | 递归终止条件 |
| 主定理 | 分析递归复杂度 |

## 具体示例

归并排序：把数组对半分成左右两半（分），各自递归排好（治），再把两个有序半部分用双指针线性合并成一个有序数组（合）。递推式 T(n)=2T(n/2)+O(n)，主定理得 O(n log n)。快速排序则相反——划分时就让 pivot 就位，"合"是常数，平均 O(n log n)。

## 何时用 / 何时不用

- **用：** 问题可拆成相互独立、同结构的子问题且有高效合并/划分步骤——排序、二分、大数乘、FFT、最近点对，以及子问题可并行的计算。
- **不用：** 子问题大量重叠（应改用 [[动态规划]]/记忆化避免重复计算）；无法有效"合"或 base case 难定义时。

## 优劣与代价

✅ 思路清晰、常很高效（O(n log n) 一类）；子问题独立，天然易于并行。
⚠️ 递归有栈开销；合并/划分步骤可能复杂、决定总成本。
⚠️ 子问题重叠时若无记忆化会指数级重复计算，此时 DP 更优。

## 与相关概念的区别

- **vs 动态规划：** 分治子问题相互独立；DP 处理重叠子问题，用表格/记忆化各解一次。
- **vs 减治：** 减治每次只求解一个子问题（如 [[二分查找]] 折半取一边）；分治通常求解多个再合并。
- **vs 贪心：** 贪心每步做局部最优选择、不回溯、无合并；与分治结构不同。

## 常见误区

- 只要能写成递归的算法都属于分治。
- 分治的子问题可以任意重叠，重叠也不影响效率。
- 二分查找会同时递归求解左右两个子问题再合并结果。

## 面试速答

> 🎯 分治=把问题递归拆成若干独立、同结构的小子问题，分别解（分/治）到 base case，再合并子解得原解（合），复杂度常用主定理分析（归并 T=2T(n/2)+O(n)=O(n log n)）。关键区分：子问题独立才用分治、重叠改用 DP；二分/减治每次只解一个子问题是特例。代价是递归栈与合并成本。
