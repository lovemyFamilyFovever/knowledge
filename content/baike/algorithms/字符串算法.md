# 字符串算法


> 📌 **导航**：本文是 **字符串算法** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 字符串算法是处理文本匹配、查找、比较等问题的算法族，核心目标是在长度 n 的文本中高效查找长度 m 的模式，避免暴力匹配的重复比较。

**通俗类比：** 在一本书里找某个词——暴力法从头逐字比对、错位后重来；聪明的算法（如 KMP）会利用「已匹配上的部分」信息跳过不可能匹配的位置，不回头重看。

> 多义说明：本文覆盖单模式匹配（KMP、Rabin-Karp）、多模式匹配（AC 自动机）与后缀结构（后缀数组）；前缀树见 [[前缀树]]。

## 原理与机制

### KMP（Knuth-Morris-Pratt）

预处理模式串的 **next / 失败函数**（最长相等真前后缀长度），匹配失败时按 next 回退**模式串**指针而**不回退文本**指针，整体 O(n+m)。

```python
def build_next(pattern):
    """next[i] = pattern[:i+1] 的最长相等真前后缀长度"""
    next_arr = [0] * len(pattern)
    j = 0
    for i in range(1, len(pattern)):
        while j > 0 and pattern[i] != pattern[j]:
            j = next_arr[j - 1]
        if pattern[i] == pattern[j]:
            j += 1
        next_arr[i] = j
    return next_arr

def kmp_search(text, pattern):
    next_arr = build_next(pattern)
    j, results = 0, []
    for i in range(len(text)):
        while j > 0 and text[i] != pattern[j]:
            j = next_arr[j - 1]
        if text[i] == pattern[j]:
            j += 1
        if j == len(pattern):
            results.append(i - j + 1)   # 命中起始位置
            j = next_arr[j - 1]         # 允许重叠，继续找下一个
    return results
```

### Rabin-Karp（滚动哈希）

用**滚动哈希**在 O(1) 内滑动更新窗口哈希值，期望 O(n+m)；哈希相等再逐字符校验以防碰撞。适合**多模式匹配**与二维匹配。

```python
def rabin_karp(text, pattern):
    n, m = len(text), len(pattern)
    base, mod = 256, 10**9 + 7
    pat_hash = 0
    for c in pattern:
        pat_hash = (pat_hash * base + ord(c)) % mod
    txt_hash, power = 0, pow(base, m - 1, mod)
    for i in range(n):
        txt_hash = (txt_hash * base + ord(text[i])) % mod
        if i >= m:
            txt_hash = (txt_hash - ord(text[i - m]) * power) % mod
        if i >= m - 1 and txt_hash == pat_hash:
            if text[i - m + 1:i + 1] == pattern:   # 防哈希碰撞，逐字符校验
                return i - m + 1
    return -1
```

### AC 自动机（Aho-Corasick）

在 **Trie** 上构建**失败指针**（类似 KMP 的 next），一次扫描文本即可匹配**所有模式**，O(n + m + z)（z 为命中数）。用于敏感词过滤、病毒特征扫描、搜索关键词高亮。

### 后缀数组（Suffix Array）

文本所有后缀按字典序排序后的**起始下标数组**，配合 LCP（最长公共前缀）数组可高效解决最长重复子串、最长公共子串等；构建 O(n log n)（倍增）或 O(n)（SA-IS）。

```
文本: banana
后缀: banana(0) anana(1) nana(2) ana(3) na(4) a(5)
排序: a(5) ana(3) anana(1) banana(0) na(4) nana(2)
SA  : [5, 3, 1, 0, 4, 2]
```

## 应用场景

- 文本编辑器查找、grep / 搜索引擎、敏感词过滤、DNA 序列比对、抄袭检测、数据压缩（LZ 系的串匹配）。

## 算法对比

| 算法 | 时间复杂度 | 预处理 | 适用场景 |
|------|-----------|--------|----------|
| 暴力匹配 | O(n·m) | 无 | 短模式、简单场景 |
| KMP | O(n+m) | O(m) | 单模式匹配 |
| Rabin-Karp | O(n+m) 期望 | O(m) | 多模式 / 滚动 / 二维匹配 |
| AC 自动机 | O(n+m+z) | O(m) | 多关键词同时匹配 |
| 后缀数组 | O(n log n) 构建 | O(n log n) | 复杂子串查询 |

## 优点与局限

- 优点：把匹配从暴力 O(n·m) 降到线性/近线性，支撑海量文本处理。
- 局限：KMP 的 next 数组理解与实现易错；Rabin-Karp 有哈希碰撞与取模开销；后缀数组 / AC 自动机实现较复杂、常数较大。

## 常见误区

- 「KMP 一定比暴力快很多」：最坏 O(n+m) vs O(n·m)，但实际文本中暴力法常因早停并不慢；KMP 的价值在**最坏情况保证**。
- Rabin-Karp 哈希相等就断定匹配：必须**逐字符校验**，否则哈希碰撞会误报。
- 混淆「子串」与「子序列」：子串连续、子序列可不连续（对应不同算法，如 LCS 用 DP，见 [[动态规划]]）。
