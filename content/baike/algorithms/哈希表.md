# 哈希表


> 📌 **导航**：本文是 **哈希表** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 哈希表(Hash Table,又称散列表)是一种通过哈希函数把键映射到存储桶位置、以支持快速按键存取的数据结构,平均情况下查找、插入、删除的时间复杂度为 O(1)。

**通俗类比：** 像衣帽间凭号取衣——你把外套交给前台,对方按规则给你一个号牌(哈希),取衣时报号即可直接定位,不必一件件翻找;好的规则能让不同外套尽量分到不同位置。

> 多义说明:冲突处理主要有链地址法(separate chaining)与开放寻址(open addressing);本文综合讨论。哈希表是 dict / map / unordered_map 等的底层实现。

## 原理与机制

- **哈希函数:** 把任意键映射为桶索引(数组下标);好的哈希函数应分布均匀、计算快速。
- **冲突处理:**
  - 链地址法:每个桶挂一个链表(或红黑树)存放映射到同桶的元素。
  - 开放寻址:冲突时按探测序列(线性探测、二次探测、双重哈希)寻找下一个空位。
- **负载因子(load factor):** = 元素数 / 桶数;超过阈值时扩容(rehash,通常容量翻倍并重新散列)。
- **复杂度:** 平均 O(1);最坏(所有键冲突)O(n)。

## 关键组成

| 组成 | 作用 |
|------|------|
| 桶数组(bucket array) | 存放元素的底层数组 |
| 哈希函数 | 键 → 桶索引 |
| 冲突处理 | 链地址法 / 开放寻址 |
| 负载因子与扩容 | 控制冲突率、触发 rehash |
| hash / equals | 键需正确实现二者 |

## 应用场景

- 字典/映射与集合(Python dict、Java HashMap、JS Map)
- 去重、计数、缓存
- 数据库哈希索引、内存路由表
- 编译期符号表

## 优点与局限

- 优点:平均 O(1) 存取、实现灵活、广泛用于键值存储。
- 局限:最坏 O(n)(哈希碰撞攻击或糟糕哈希函数);默认无序(需额外结构保序);扩容 rehash 有开销;指针/内存开销与缓存不友好。

## 常见误区

- 哈希表平均 O(1),但最坏 O(n)。
- 哈希表默认不保证遍历顺序(需 LinkedHashMap 等保序结构)。
- 好的哈希函数与合适的负载因子对性能至关重要。
- HashMap 的键必须正确实现 hash 与 equals,否则查找失败。
