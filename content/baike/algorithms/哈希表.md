# 哈希表


> 📌 **导航**：本文是 **哈希表** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 哈希表（Hash Table，又称散列表）是一种通过哈希函数把键映射到存储桶位置、以支持快速按键存取的数据结构，平均情况下查找、插入、删除的时间复杂度为 O(1)。

**通俗类比：** 像衣帽间凭号取衣——你把外套交给前台，对方按规则给你一个号牌（哈希），取衣时报号即可直接定位，不必一件件翻找；好的规则能让不同外套尽量分到不同位置。

> 多义说明：冲突处理主要有链地址法（separate chaining）与开放寻址（open addressing）；本文综合讨论。哈希表是 dict / map / unordered_map 等的底层实现。

## 为什么需要它

数组按下标访问是 O(1)，但只能按"整数下标"；要按任意键（字符串、对象）快速查找，就得把键变成下标。哈希表用哈希函数把键映到桶下标，绕过了比较与遍历，平均 O(1) 完成增删查，比有序的 [[二叉搜索树]]/[[二分查找]] 的 O(log n) 更快，代价是牺牲顺序与最坏保证。

## 核心机制

- **哈希函数：** 把任意键映射为桶索引（数组下标）；好的哈希函数应分布均匀、计算快速。
- **冲突处理：** 链地址法（每桶挂链表，Java 链表过长转红黑树）；开放寻址（冲突按线性/二次探测或双重哈希找下一空位）。
- **负载因子：** = 元素数 / 桶数；超阈值时扩容 rehash（常容量翻倍并重新散列），以控制冲突率。
- **复杂度：** 平均 O(1)；最坏（所有键撞同一桶）O(n)。

| 组成 | 作用 |
|------|------|
| 桶数组（bucket array） | 存放元素的底层数组 |
| 哈希函数 | 键 → 桶索引 |
| 冲突处理 | 链地址法 / 开放寻址 |
| 负载因子与扩容 | 控制冲突率、触发 rehash |
| hash / equals | 键需正确实现二者 |

## 具体示例

存 "name"→"张三"：算 hash("name")%容量 得桶下标，直接写入。若另一个键也映到同一桶，链地址法就在该桶挂一条 (key,value) 链表，查找时定位到桶再沿链表用 equals 比对。当元素数/桶数 超过负载因子（如 0.75），就把桶数组翻倍、对所有元素重新散列，让冲突率降回去。

## 何时用 / 何时不用

- **用：** 按键快速存取/去重/计数、缓存、数据库哈希索引、符号表——只要不需要顺序、追求平均 O(1)。
- **不用：** 需要按键有序遍历或范围查询（用 [[二叉搜索树]]/跳表）；对抗性输入可能被哈希碰撞攻击时；内存极敏感且缓存友好优先时。

## 优劣与代价

✅ 平均 O(1) 存取、用途广泛、实现键值映射最直接。
⚠️ 最坏 O(n)（碰撞攻击或糟糕哈希函数）；默认无序。
⚠️ 扩容 rehash 有开销，指针/内存开销大、缓存不友好。

## 与相关概念的区别

- **vs [[二分查找]]/BST：** 哈希平均 O(1) 但无序、最坏 O(n)；BST/二分保有序、稳定 O(log n) 支持范围。
- **链地址法 vs 开放寻址：** 前者冲突挂链表、可存超桶数元素、指针开销大；后者数据紧凑但高负载时探测变慢、删除需墓碑。
- **vs [[前缀树]]：** 哈希只整键命中、不支持前缀枚举；Trie 支持前缀匹配。

## 常见误区

- 哈希表的查找永远是 O(1)，不会退化。
- 哈希表默认就能按插入顺序或键顺序遍历。
- 自定义对象作 HashMap 的键时，只要 equals 正确就行，hashCode 随便写。

## 面试速答

> 🎯 哈希表=哈希函数把键映到桶下标、平均 O(1) 增删查；冲突用链地址法（挂链表/转红黑树）或开放寻址（线性/二次/双重探测），负载因子过高就扩容 rehash 控冲突。最坏 O(n)，默认无序、要顺序用 BST，缓存不友好但键值存取最快；作键的对象必须同时正确实现 hashCode 与 equals。
