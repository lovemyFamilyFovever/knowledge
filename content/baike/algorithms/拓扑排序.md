# 拓扑排序


> 📌 **导航**：本文是 **拓扑排序** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 拓扑排序（Topological Sort）是对有向无环图（DAG）的顶点排出一个线性序列，使得对图中每条有向边 (u → v)，u 都排在 v 之前；它反映了在"先决约束"下的一种合法执行顺序。

**通俗类比：** 像安排课程或穿衣顺序——"穿袜子"必须在"穿鞋"之前、"数据结构"必须在"操作系统"之前；拓扑排序就是把这些先后约束排成一条可行的时间线。

> 多义说明：拓扑序仅对有向无环图（DAG）存在；若图中有环则无法拓扑排序（可借此检测环）。同一 DAG 的拓扑序通常不唯一。

## 为什么需要它

任务调度、编译依赖、构建系统本质上是一堆"谁必须在谁之前"的约束，建模成 DAG 后要得到一个可执行顺序。拓扑排序正是把偏序关系线性化的工具：O(V+E) 排一次即得合法执行序，还能顺带发现"排不完 = 有环 = 依赖自相矛盾"，是调度与依赖解析的核心。

## 核心机制

- **Kahn 算法（基于入度）：** 反复取出入度为 0 的顶点输出，删除其出边（邻居入度减 1），直到无顶点；若输出顶点数 < 总数，说明存在环。
- **DFS 算法：** 对 DFS 的完成顺序（后序）取逆序即拓扑序；DFS 中遇"后向边"说明有环。
- **复杂度：** 两种方法均 O(V + E)。

| 组成 | 说明 |
|------|------|
| 有向无环图（DAG） | 拓扑排序的前提 |
| 入度（in-degree） | Kahn 算法的核心计数 |
| 队列 / 栈 | 存放当前入度为 0 的顶点 |
| DFS 后序逆序 | 另一种求拓扑序的方式 |
| 环检测 | 无法排完即存在环 |

## 具体示例

构建任务 A→C、B→C、C→D：初始入度 A=0、B=0、C=2、D=1。Kahn 先把 A、B 入队输出，删边后 C 入度归 0 入队输出，最后 D——得如 A B C D。若加一条 D→A 形成环，则始终没有入度为 0 的点可取，已输出数 < 4，据此判定图有环（依赖死锁）。

## 何时用 / 何时不用

- **用：** 有依赖先后的执行排序——任务/作业调度、编译与构建系统（Make）、课程先修、数据流/DAG 计算（如 Spark）、公式求值顺序。
- **不用：** 图有环时无解（须先破环或报"存在环"）；无向图无所谓先后；需要唯一确定顺序时要再加优先级约束。

## 优劣与代价

✅ 线性时间 O(V+E)、直观表达依赖顺序、可顺带检测环。
⚠️ 仅适用于 DAG，有环无解。
⚠️ 拓扑序不唯一；图结构动态变化后需重算。

## 与相关概念的区别

- **vs 普通排序：** 普通排序按可比较的键值排；拓扑排序按偏序/依赖边排，且只对 DAG 存在。
- **Kahn vs DFS：** Kahn 用入度 + 队列、天然好判环；DFS 用后序逆序、靠后向边判环。
- **vs [[图算法大全]] 其他：** 拓扑排序专门处理有向无环的先后关系，不同于最短路径/MST。

## 常见误区

- 任何有向图都能做拓扑排序，有没有环无所谓。
- 拓扑排序的输出结果一定是唯一的。
- 拓扑排序适合给无向图的顶点排出先后顺序。

## 面试速答

> 🎯 拓扑排序=给 DAG 顶点排出线性序，使每条边 u→v 中 u 在 v 前，反映依赖先后；两法均 O(V+E)：Kahn（入度为 0 出队、删边，排不完即有环）、DFS（后序逆序、后向边判环）。前提必须是 DAG、结果通常不唯一，用于任务调度、构建依赖、课程先修。判环与拓扑是一枚硬币两面：能排完 ⇔ 无环。
