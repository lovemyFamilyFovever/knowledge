# 空间复杂度

> 📌 **导航**：本文是 **空间复杂度** 词条，属于 algorithms 术语集。相关枢纽：[[复杂度分析]]、[[时间复杂度]]、[[基础数据结构]]、[[算法思想]]、[[主定理]]。

## 定义

**一句话定义：** 空间复杂度衡量算法运行期间**额外**占用的内存随输入规模 n 的增长率，不含输入本身与代码；原地算法为 O(1)，递归还要把调用栈深度计入 S(n)。

**通俗类比：** 做菜要占多少备用碟子：食材本身（输入）不算，你临时切配、腌渍另占的碟子才算——碟子越多，灶台越挤。

## 为什么需要它

内存是比时间更硬的红线：慢一点还能等，撑爆了直接 OOM 或疯狂换页，性能断崖式下跌。嵌入式、移动端、大规模流式处理里，一个 O(n) 的临时数组就可能让整个方案不可行。另外空间与时间常可互换——缓存、哈希表、DP 表都是拿空间买时间，因此必须把两者放在同一杆秤上权衡（见 [[时空权衡]]）。

## 计算逻辑

- **只数额外空间**：输入数组本身不计；新建等长数组、哈希表、邻接矩阵是 O(n)、O(n²)。
- **递归栈要算进去**：递归深度 × 每帧占用即栈空间，链式递归 O(n)、平衡递归 O(log n)。
- **区分辅助空间与总空间**：面试说"原地"通常指辅助空间 O(1)，但递归版快排并非真 O(1)。
- **注意隐式分配**：Python 切片与推导式、`sorted()`、字符串拼接都会另开新对象。

| 阶 | 典型形态 | 例子 |
|---|---|---|
| O(1) | 少量变量、原地交换 | 双指针反转数组 |
| O(log n) | 递归栈深度 | [[二分查找]] 递归版 |
| O(n) | 等长辅助数组、哈希表 | 前缀和、去重计数 |
| O(n²) | 二维表 | 邻接矩阵、DP 表 |

## 具体示例

反转数组的两种写法，时间同为 O(n)，空间差一个量级：

```python
def reverse_inplace(a):              # O(1) 额外空间
    i, j = 0, len(a) - 1
    while i < j:
        a[i], a[j] = a[j], a[i]
        i += 1; j -= 1

def reverse_copy(a):                 # O(n) 额外空间
    return a[::-1]
```

前缀和则是反向例子：多花 O(n) 空间，把区间求和从每次 O(n) 降到 O(1)。

## 何时用与何时不用

- **用**：内存受限环境、超大规模数据、流式与端侧场景；评审时质疑"这份 O(n) 副本是否必要"；判断能否原地化 DP 表。
- **不用**：数据量本就很小且已能放入内存时，为省几个指针而牺牲可读性是错配；缓存友好带来的实测收益往往大于渐近空间的差别。

## 优劣与代价

✅ 与时间复杂度同为机器无关的量纲，能提前预判内存可行性。
✅ 明确空间代价后，"要不要建表缓存"这类决策可以量化。
⚠️ 只算额外空间，容易漏掉递归栈、临时对象与语言运行时开销。
⚠️ 过度追求原地会显著增加代码复杂度，甚至反而变慢。

## 与相关概念的区别

- **空间复杂度 vs [[时间复杂度]]**：一个数内存、一个数操作次数，二者常此消彼长。
- **原地 vs O(1) 空间**：原地指不新建与规模成正比的容器，但递归栈仍可能吃掉 O(n)。
- **辅助空间 vs 总空间**：前者不含输入，后者含；报告结论时要说明用的是哪个口径。
- **空间换时间 vs 输入复用**：前者新建结构加速查询，后者通过改写输入省内存但常破坏原始数据。

## 常见误区

- 原地算法的空间复杂度就一定是 O(1)。
- 递归只是多几行代码，不额外占内存。
- 空间复杂度比时间复杂度低，所以这个实现一定更快。

## 面试速答

> 🎯 空间算的是额外内存随 n 的增长率：新建等长容器 O(n)、二维表 O(n²)，递归栈深度必须计入，所以递归版快排不是 O(1)；它与时间常可互换，取舍看内存红线。
