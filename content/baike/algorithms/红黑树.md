# 红黑树


> 📌 **导航**：本文是 **红黑树** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 红黑树（Red-Black Tree）是一种自平衡二叉搜索树，它给每个节点附加红/黑颜色并遵循五条约束，通过变色与旋转在插入/删除后维持"近似平衡"，保证树高为 O(log n)，从而查找、插入、删除的最坏复杂度均为 O(log n)。

**通俗类比：** 像一支队伍要求"从任何一人往下走到其下属的路上，穿黑制服的人数大致相当"——靠这条颜色规则，队伍不会一边倒地越拉越长，队首到任何队员的距离都不至于失控。

> 多义说明：红黑树是自平衡 BST 的一种；与 AVL 树（严格平衡）相比更"宽松"，插入/删除时的旋转更少。本文讨论红黑树。

## 为什么需要它

普通 [[二叉搜索树]] 在有序输入下退化成链表，操作跌到 O(n)，而许多容器要频繁增删又要保持有序。AVL 严格平衡查询最快但增删旋转多。红黑树用较弱的着色约束把"最长路径 ≤ 2×最短"守住，既保证最坏 O(log n)，又让插入至多 2 次旋转、删除至多 3 次——在写频繁、要求最坏有界的通用容器与内核结构里是更好的折中。

## 核心机制

- **五条性质：** ①节点非红即黑；②根为黑；③所有叶（NIL 空节点）为黑；④红节点的子必为黑（无连续红）；⑤任一节点到其所有叶子路径含相同数目黑节点（黑高相同）。
- **平衡保证：** 由性质 ④⑤ 推出最长路径 ≤ 2×最短路径，树高 ≤ 2·log₂(n+1)。
- **调整：** 插入时新节点染红，再按"叔节点颜色"分情况变色/旋转；删除时处理"双重黑"情形。旋转次数有常数上界。

| 组成 | 说明 |
|------|------|
| 节点颜色（红/黑） | 承载平衡约束 |
| 五条红黑性质 | 保证近似平衡 |
| 旋转（左旋/右旋） | 局部重构以恢复性质 |
| 变色 | 调整颜色以满足性质 |
| 黑高 / NIL 叶 | 度量与哨兵节点 |

## 具体示例

Java TreeMap 按 key 有序地存键值：put 先按 BST 规则插入并染红，再"修复"——若父节点也是红（破坏性质④），据叔节点颜色选择重新着色或旋转来消解连续红，旋转至多 2 次即恢复五条性质。正因这套修复比 AVL 频繁但每次旋转少，红黑树在插入删除密集的容器里更受欢迎。

## 何时用 / 何时不用

- **用：** 需有序 + 频繁增删 + 最坏 O(log n) 的通用容器与系统结构——Java TreeMap、C++ map/set、Linux CFS 调度/epoll/内存管理、Nginx 定时器。
- **不用：** 读极多、追求最快查询且写很少（用 [[AVL 树]]）；磁盘/块存储索引（用多路 [[B+树]]）；只要点查无序（用 [[哈希表]]）。

## 优劣与代价

✅ 最坏 O(log n)，插入/删除旋转次数有常数上界，综合性能稳定。
⚠️ 近似平衡，查询略逊于 AVL。
⚠️ 实现复杂、颜色与旋转易错；指针结构缓存不友好。

## 与相关概念的区别

- **vs [[AVL 树]]：** AVL 严格平衡（|BF|≤1）、查询更快但旋转多；红黑树近似平衡、增删旋转少，写多更优。
- **vs B+树：** 红黑树二叉、面向内存；B+树多路、面向磁盘块（见 [[B+树]]）。
- **本质：** 红黑树可看作"二叉化的 2-3-4 树"，颜色编码多叉节点，源于 Bayer 的对称二叉 B 树。

## 常见误区

- 红黑树和 AVL 一样是严格平衡的，查询一定不比 AVL 慢。
- 红黑树要求"黑节点的子节点必须是红节点"。
- 红黑树和 B+树是同一种结构，只是名字不同。

## 面试速答

> 🎯 红黑树=给 BST 节点染红/黑并守五条性质（根黑、无连续红、到各叶黑高相同），由此最长路径≤2×最短、树高≤2log₂(n+1)，查/增/删最坏 O(log n)。相比严格平衡的 AVL 查询略慢，但插入至多 2 次旋转、删除至多 3 次，写频繁更稳，故 TreeMap；读多写少选 AVL，磁盘索引用 B+ 树。
