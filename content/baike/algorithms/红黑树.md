# 红黑树

## 定义

**一句话定义：** 红黑树(Red-Black Tree)是一种自平衡二叉搜索树,它给每个节点附加红/黑颜色并遵循五条约束,通过变色与旋转在插入/删除后维持"近似平衡",保证树高为 O(log n),从而查找、插入、删除的最坏复杂度均为 O(log n)。

**通俗类比：** 像一支队伍要求"从任何一人到其下属的路上,穿黑制服的人数大致相当"——靠这条颜色规则,队伍不会一边倒地越拉越长,从而保证从队首到任何队员的距离都不至于失控。

> 多义说明:红黑树是自平衡 BST 的一种;与 AVL 树(严格平衡)相比更"宽松",插入/删除时的旋转更少。本文讨论红黑树。

## 原理与机制

- **五条性质:**
  1. 每个节点非红即黑;
  2. 根节点为黑;
  3. 所有叶(NIL 空节点)为黑;
  4. 红节点的子节点必为黑(不存在连续红节点);
  5. 任一节点到其所有叶子的路径包含相同数目的黑节点(黑高相同)。
- **平衡保证:** 由性质 4、5 可推出最长路径 ≤ 2×最短路径,树高 ≤ 2·log₂(n+1)。
- **调整:** 插入时新节点染红,再按"叔节点颜色"分情况变色/旋转;删除时处理"双重黑"情形。

## 关键组成

| 组成 | 说明 |
|------|------|
| 节点颜色(红/黑) | 承载平衡约束 |
| 五条红黑性质 | 保证近似平衡 |
| 旋转(左旋/右旋) | 局部重构以恢复性质 |
| 变色 | 调整颜色以满足性质 |
| 黑高 / NIL 叶 | 度量与哨兵节点 |

## 应用场景

- Java TreeMap、C++ std::map / std::set
- Linux 内核(CFS 调度、epoll、内存区域管理)
- Nginx 定时器、各类需要有序且频繁增删的容器

## 优点与局限

- 优点:最坏 O(log n);插入/删除的旋转次数有常数上界(插入至多 2 次旋转),综合性能稳定。
- 局限:平衡是"近似",查询略逊于 AVL;实现复杂,颜色与旋转逻辑易错;指针结构对缓存不友好。

## 常见误区

- 红黑树不是"严格平衡"(那是 AVL),它以略差的查询换取更少的旋转。
- 红黑树 ≠ B+树:后者是多路、面向磁盘块的结构。
- 性质 4 是"红节点的子为黑",不是"黑节点的子必为红"。
