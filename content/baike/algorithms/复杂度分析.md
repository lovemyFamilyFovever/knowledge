# 复杂度分析

> 复杂度分析是衡量算法效率的标尺，帮助我们不运行代码就能判断算法在数据量增大时的表现。

---

## 时间复杂度（Big O）

### 一句话定义
描述算法执行时间随输入规模增长的**增长速率**，忽略常数和低阶项。

### 通俗类比
两个人跑步：一个跑得越来越快，另一个跑得越来越慢，Big O 告诉你差距会有多大。

### 具体示例
```python
# O(1) - 常数时间
def get_first(arr):
    return arr[0]

# O(log n) - 对数时间
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: left = mid + 1
        else: right = mid - 1

# O(n) - 线性时间
def linear_search(arr, target):
    for i, val in enumerate(arr):
        if val == target: return i

# O(n log n) - 线性对数时间
# 归并排序、快速排序

# O(n²) - 平方时间
def bubble_sort(arr):
    for i in range(len(arr)):
        for j in range(len(arr) - 1 - i):
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]

# O(2ⁿ) - 指数时间
def fibonacci(n):
    if n <= 1: return n
    return fibonacci(n-1) + fibonacci(n-2)
```

### Big O 表示法规则
1. 忽略常数：`3n² + 5n + 10` → `O(n²)`
2. 保留最高阶：`n² + n log n` → `O(n²)`
3. 没有加法，只有乘法：`O(n) + O(m)` → `O(n+m)`，但 `O(n) × O(m)` → `O(nm)`

## 空间复杂度

### 一句话定义
描述算法运行时额外使用的内存空间随输入规模增长的情况。

### 通俗类比
做菜时需要多少调料碟：调料碟越多，你需要的桌面空间越大。

### 具体示例
```python
# O(1) 空间 - 原地操作
def reverse_array(arr):
    left, right = 0, len(arr) - 1
    while left < right:
        arr[left], arr[right] = arr[right], arr[left]
        left += 1; right -= 1

# O(n) 空间 - 额外数组
def create_prefix_sum(arr):
    prefix = [0] * (len(arr) + 1)  # 额外 O(n) 空间
    for i in range(len(arr)):
        prefix[i+1] = prefix[i] + arr[i]
    return prefix

# O(log n) 空间 - 递归栈
def quick_sort(arr):
    if len(arr) <= 1: return arr
    pivot = arr[len(arr)//2]
    left = [x for x in arr if x < pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + [pivot] + quick_sort(right)
    # 递归深度 O(log n)，每层复制 O(n)，但栈空间是 O(log n)
```

### 常见空间复杂度
| 复杂度 | 说明 | 示例 |
|--------|------|------|
| O(1) | 固定额外空间 | 双指针、交换变量 |
| O(n) | 线性额外空间 | 新建等长数组、哈希表 |
| O(n²) | 二维数组 | 邻接矩阵 |
| O(log n) | 递归栈深度 | 二分查找递归 |

## 最好/最坏/平均时间复杂度

### 一句话定义
同一算法在不同输入下的表现可能不同，三种复杂度分别描述最好、最差和平均情况。

### 通俗类比
你去食堂排队：最好情况一到就打到饭（O(1)），最坏情况排了所有人（O(n)），平均排一半（O(n/2)）。

### 具体示例
```python
def linear_search_optimized(arr, target):
    """最好 O(1)，最坏 O(n)，平均 O(n/2)"""
    for i, val in enumerate(arr):
        if val == target:
            return i
    return -1

# 插入排序
# 最好：已有序 → O(n)，只需比较不需移动
# 最坏：逆序 → O(n²)，每轮都要移动到最后
# 平均：随机 → O(n²/4)
```

### 三种复杂度对比
| 算法 | 最好 | 最坏 | 平均 |
|------|------|------|------|
| 线性查找 | O(1) | O(n) | O(n/2) |
| 二分查找 | O(1) | O(log n) | O(log n) |
| 插入排序 | O(n) | O(n²) | O(n²) |
| 快速排序 | O(n log n) | O(n²) | O(n log n) |

## 均摊分析（Amortized Analysis）

### 一句话定义
考虑一系列操作的**平均代价**，某些单次操作虽然代价高，但被多次低代价操作均摊后整体仍高效。

### 通俗类比
健身房年卡：平时不怎么去（均摊每次很便宜），偶尔去一次（单次实际花费很高），但整体还是划算的。

### 具体示例
```python
class DynamicArray:
    def __init__(self):
        self.capacity = 1
        self.size = 0
        self.data = [None] * self.capacity

    def append(self, val):
        if self.size == self.capacity:
            self._resize()  # 扩容：O(n)，但很少发生
        self.data[self.size] = val
        self.size += 1  # 均摊 O(1)

    def _resize(self):
        new_data = [None] * (self.capacity * 2)
        for i in range(self.size):
            new_data[i] = self.data[i]
        self.data = new_data
        self.capacity *= 2
```

### 为什么需要它
单次操作最坏 O(n)，但 n 次操作总代价 O(n)，均摊每次 O(1)。动态数组、栈的 push/pop 都适用。

## 递归复杂度（主定理 / Master Theorem）

### 一句话定义
主定理是求解形如 `T(n) = aT(n/b) + O(n^d)` 递推关系的公式，快速得出递归算法的时间复杂度。

### 通俗类比
一棵树的总叶节点数：你有 a 个分支，每层缩小 b 倍，深度 d 层，总工作量取决于这些参数的关系。

### 主定理公式
```
T(n) = aT(n/b) + O(n^d)

其中：
- a = 子问题数量
- b = 每个子问题缩小的倍数
- d = 合并步骤的指数

三种情况：
① 若 d < log_b(a) → O(n^(log_b(a)))
② 若 d = log_b(a) → O(n^d × log n)
③ 若 d > log_b(a) → O(n^d)
```

### 具体示例
```python
# 归并排序：T(n) = 2T(n/2) + O(n)
# a=2, b=2, d=1 → d = log_2(2) = 1 → 情况② → O(n log n)

# 二分查找：T(n) = T(n/2) + O(1)
# a=1, b=2, d=0 → d = log_2(1) = 0 → 情况② → O(log n)

# Karatsuba 乘法：T(n) = 3T(n/2) + O(n)
# a=3, b=2, d=1 → d < log_2(3) ≈ 1.58 → 情况① → O(n^1.58)
```

### 为什么需要它
不用画递归树就能快速求出归并排序、快速排序、FFT 等分治算法的复杂度。

## NP 完全问题（NP-Complete）

### 一句话定义
目前没有已知多项式时间算法能解决的问题，但验证一个解是否正确可以在多项式时间内完成。

### 通俗类比
解一个魔方可能很难（指数时间），但别人给你一个已解开的魔方，你验证它是否正确很容易（多项式时间）。

### 常见 NP 完全问题
| 问题 | 描述 |
|------|------|
| 旅行商问题（TSP） | 访问所有城市一次并返回，求最短路径 |
| 0-1 背包 | 选物品使价值最大且不超过容量 |
| 图着色 | 用最少颜色给图着色使相邻节点不同色 |
| 哈密顿回路 | 图中是否存在经过每个节点恰好一次的环 |
| 子集和 | 是否存在子集的和等于目标值 |
| SAT 问题 | 布尔公式是否可满足 |

### 为什么需要它
NP 完全问题理论上很难，但实践中可以用**近似算法**、**启发式**或**特殊情况下高效解**来应对。

## P 问题 vs NP 问题

### 一句话定义
- **P 问题**：能在多项式时间内**求解**的问题
- **NP 问题**：能在多项式时间内**验证**一个解是否正确的问题

### 通俗类比
- P：你知道怎么快速解出一道数学题
- NP：有人给你答案，你能快速判断对不对，但自己解可能很慢

### 两者关系
```
P ⊆ NP（能求解的必然能验证）
NP ⊇ P

P = NP ?  ← 千禧年七大数学难题之一，悬赏 100 万美元
```

### 直观理解
| 类型 | 求解难度 | 验证难度 | 例子 |
|------|----------|----------|------|
| P | 多项式 | 多项式 | 排序、最短路径 |
| NP | 指数？ | 多项式 | 数独、TSP |
| NP-Complete | 指数 | 多项式 | 所有 NP 问题可归约到它 |

## 空间换时间

### 一句话定义
用额外的存储空间来加速计算，是算法优化的常用策略。

### 通俗类比
提前把常用数据记在小本子上（缓存），查的时候直接翻本子，不用每次都去翻大字典。

### 具体示例
```python
# 暴力法：O(n²)
def two_sum_brute(arr, target):
    for i in range(len(arr)):
        for j in range(i+1, len(arr)):
            if arr[i] + arr[j] == target:
                return [i, j]

# 哈希表空间换时间：O(n)
def two_sum_hash(arr, target):
    seen = {}
    for i, val in enumerate(arr):
        complement = target - val
        if complement in seen:
            return [seen[complement], i]
        seen[val] = i
```

### 典型应用
| 应用 | 空间 | 时间收益 |
|------|------|----------|
| 哈希表缓存 | O(n) | 查找从 O(n) 到 O(1) |
| 前缀和数组 | O(n) | 区间和从 O(n) 到 O(1) |
| 动态规划表 | O(n²) 或 O(n) | 从指数到多项式 |
| 布隆过滤器 | O(k) | 判重从 O(n) 到 O(k) |

## 时间换空间

### 一句话定义
减少内存使用，通过重复计算来节省空间，适用于内存受限场景。

### 通俗类比
不记笔记，每次用到数据都重新查一遍，虽然费时间但不占桌面空间。

### 具体示例
```python
# 空间换时间：O(n) 空间
def prefix_sum(arr):
    prefix = [0] * (len(arr) + 1)
    for i in range(len(arr)):
        prefix[i+1] = prefix[i] + arr[i]
    return prefix

# 时间换空间：O(1) 空间，每次重新计算
def range_sum(arr, left, right):
    total = 0
    for i in range(left, right + 1):
        total += arr[i]
    return total

# DP 空间优化：滚动数组
# 原始：dp[n][m] → 优化：dp[2][m] 或 dp[m]
def fibonacci_optimized(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a  # O(1) 空间替代 O(n) 的数组
```

### 为什么需要它
嵌入式系统、大规模数据处理、流式计算等内存敏感场景。

## 复杂度对比表

### 增长速率对比
假设 n = 1,000,000（一百万）：

| 复杂度 | n=10⁶ 时操作次数 | 直观感受 |
|--------|-------------------|----------|
| O(1) | 1 | 瞬间完成 |
| O(log n) | 20 | 瞬间完成 |
| O(n) | 10⁶ | 1 秒 |
| O(n log n) | 2 × 10⁷ | 20 秒 |
| O(n²) | 10¹² | 约 11.5 天 |
| O(2ⁿ) | 10³⁰¹⁰²⁹ | 宇宙爆炸也完不成 |
| O(n!) | 10⁵⁵⁶⁵⁷⁰⁹ | 不可想象 |

### 复杂度决策树
```
需要解决问题？
├─ 数据已排序？
│  ├─ 是 → 二分查找 O(log n)
│  └─ 否 → 线性查找 O(n)
├─ 需要排序？
│  ├─ 数据量小 → 插入排序 O(n²)
│  ├─ 数据量大 → 快速排序 O(n log n)
│  └─ 需要稳定 → 归并排序 O(n log n)
├─ 最优解问题？
│  ├─ 重叠子问题 → 动态规划
│  ├─ 局部最优=全局最优 → 贪心
│  └─ 需要穷举 → 回溯/DFS
└─ 图问题？
   ├─ 最短路径 → Dijkstra
   ├─ 连通性 → 并查集
   └─ 依赖排序 → 拓扑排序
```

### 如何选择算法
| 数据规模 | 推荐策略 |
|----------|----------|
| n < 50 | 任何算法都行，O(n²) 也可以 |
| n < 10,000 | O(n²) 可接受，O(n log n) 更好 |
| n < 1,000,000 | 必须 O(n log n) 或更好 |
| n > 10⁶ | O(n) 或 O(n log n)，空间换时间 |
| n > 10⁹ | 近似算法、分布式计算 |

## 复杂度分析实战模板

### 分析步骤
1. **识别循环**：单层循环 → O(n)，嵌套循环 → O(n²)
2. **识别递归**：画递归树或用主定理
3. **识别分治**：每次问题减半 → O(n log n)
4. **识别搜索**：二分 → O(log n)，遍历 → O(n)
5. **合并分析**：取最高阶，忽略常数

### 常见陷阱
```python
# 陷阱 1：看似 O(n)，实则 O(n²)
def mystery(arr):
    for i in range(len(arr)):
        arr.remove(arr[0])  # remove 是 O(n)！

# 陷阱 2：看似 O(1)，实则 O(n)
def pop_all(lst):
    while lst:
        lst.pop()  # 虽然每次 O(1)，但循环 n 次

# 陷阱 3：看似 O(log n)，实则 O(n)
def bad_binary(arr, target):
    return target in arr  # in 操作对列表是 O(n)
```
