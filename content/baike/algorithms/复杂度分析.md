# 复杂度分析

> 复杂度分析是衡量算法效率的标尺，帮助我们不运行代码就能判断算法在数据量增大时的表现。
>
> 📌 **导航**：本文是 **复杂度分析** 枢纽页。各分项已拆为独立词条，本页保留速查阶梯表、选型决策树与实战模板；NP 完全与 P vs NP 属计算复杂性理论，深入见 [[P 与 NP]] 与 [[计算理论]]。

## 定义

**一句话定义：** 复杂度分析是用渐近记号（大 O / Θ / Ω）刻画算法**资源消耗随输入规模的增长率**的方法，忽略常数与低阶项，从而在机器与语言之外比较方案优劣、预判可行性。

**通俗类比：** 像比较两座山的陡峭程度而不是海拔：知道山有多陡，就能推断往上爬时体力消耗会不会失控，而不必先真的爬一次。

本页是**枢纽页**：原汇编的 11 个并列主题已按独立性拆成词条，这里只留"分析怎么一步步做、各阶在真实规模下意味着什么、遇到什么问题去查哪一条"的地图。

## 为什么需要它

实测运行时间依赖硬件、编译器、缓存和数据分布，换台机器结论就可能翻转，无法作为跨环境的判据。增长率则只依赖算法本身：确认 n 会到 10⁶ 以上时，O(n²) 的 10¹² 次操作与 O(n log n) 的 2×10⁷ 次之间是十余天与数十秒的差别，这个量级差任何工程优化都补不回来。复杂度分析因此是**唯一能在写代码之前否决方案的工具**——先看阶，再看常数，最后才谈调优。

## 核心机制

### 分析四步

按代码形态逐层归并：**识别循环**（单层 O(n)，嵌套相乘）→ **识别递归**（画递归树或用 [[主定理]]）→ **识别分治**（规模减半加线性合并即 O(n log n)）→ **合并取最高阶**（串行相加、丢常数）。关键是别漏掉被隐藏的循环：`in`、`remove`、切片、`sum()` 本身都可能是 O(n)；也别忘了把**递归栈与临时容器**计入空间（见 [[空间复杂度]]）。

### 增长阶梯

n = 10⁶ 时的量级直觉（O 只表阶，常数与局部性不在此列）：

| 阶 | 操作数量级 | 体感 | 典型来源 |
|---|---|---|---|
| O(1) / O(log n) | ≤ 20 | 瞬间 | 哈希查表、[[二分查找]] |
| O(n) | 10⁶ | 亚秒 | 单次遍历、双指针 |
| O(n log n) | 2×10⁷ | 数秒 | 归并/快排、建堆 |
| O(n²) | 10¹² | 十余天 | 朴素嵌套、区间枚举 |
| O(2ⁿ) / O(n!) | 不可计 | 不可行 | 子集/排列暴力（见 [[回溯算法]]） |

规模决定可接受的阶：n≤50 随意；n≤10⁴ 容忍 O(n²)；n≥10⁶ 必须 O(n) 或 O(n log n)；更大则考虑近似、启发式或分布式。

### 三种情形与摊薄

同一算法在不同输入下表现不同：**最坏/平均/最好**要分开说（快排平均 O(n log n)、最坏 O(n²)；插入排序最好可达 O(n)）。而当"个别操作很贵但很少发生"时，用 [[均摊分析]] 对操作序列总代价记账，可得动态数组 `append` 均摊 O(1)——注意它既非概率平均，也不保证无延迟毛刺。

## 具体示例

分析最容易被三类"看起来很慢/很快"的写法骗到：

```python
for x in a: a.remove(x)      # 看似 O(n)，remove 每次 O(n) → O(n²)
while lst: lst.pop()         # 单次 O(1)，循环 n 次 → 总 O(n)
return target in sorted_arr   # 想用"二分"，实际 in 是线性 O(n)
```

正确做法：倒序或另建集合删；把循环计入总量；显式写 [[二分查找]]。反向的例子是 [[时空权衡]]：两数之和用哈希表以 O(n) 空间把 O(n²) 降到 O(n)，DP 滚动数组则以近乎不变的时间把 O(n²) 空间压到 O(n)。

## 何时用与何时不用

- **用**：预判大规模数据下的可行性；评审时质疑复杂度阶与隐藏循环；据规模反推可接受的阶；解释批量优于逐条、索引优于扫描。
- **优先算最坏界**：面对外部输入或安全相关路径，平均界可能骗人。
- **不用**：n 恒定很小或瓶颈在 I/O、网络时，渐近分析给不出有用结论；同等阶的实现之间要比的恰是常数、缓存局部性与分支预测，此时应实测而非继续推公式。

## 优劣与代价

✅ 机器无关、可比、可在编码前否决方案，是算法分析的统一语言。
✅ 把"要不要建索引、要不要缓存"变成可量化的取舍。
⚠️ 只描述渐近趋势，丢掉的常数在小 n 上可能反转结论。
⚠️ 平均情况常难算，最坏界又可能过度悲观；实时系统还需单独看尾延迟。

## 与相关概念的区别

- **大 O vs Θ vs Ω**：上界、紧确界、下界；日常"复杂度"通常指 O。
- **复杂度分析 vs 性能剖析**：前者是纸面模型、给阶；后者是实测、给常数与热点，两者互为验证。
- **均摊 vs 平均复杂度**：均摊对操作序列求和均分、与概率无关；平均对输入分布取期望。
- **复杂度 vs [[排序与搜索]]/[[算法思想]]**：本页是度量方法，那些是被度量的具体算法族。

## 常见误区

- O(2n) 比 O(n) 慢一倍，所以要去掉循环里的常数。
- 均摊 O(1) 就意味着每次操作都是常数时间、不会有延迟尖刺。
- 平均复杂度低的算法，可以放心用在任意输入上。

## 面试速答

> 🎯 复杂度分析用大 O 刻画资源随规模的增长率：数循环、解递推（主定理）、按操作序列做均摊记账，时间与空间两条都要算；再据 n 的量级判定可接受的阶，并显式做时空权衡。
> 🔍 追问：均摊分析和平均复杂度差在哪？
> 🔍 追问：为什么 n≤50 时 O(n²) 也可以接受？
