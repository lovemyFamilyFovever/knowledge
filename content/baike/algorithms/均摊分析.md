# 均摊分析

> 📌 **导航**：本文是 **均摊分析** 词条，属于 algorithms 术语集。相关枢纽：[[复杂度分析]]、[[时间复杂度]]、[[空间复杂度]]、[[主定理]]、[[高级数据结构]]。

## 定义

**一句话定义：** 均摊分析把**一整串操作**的总代价除以操作次数，得到每次操作的平均成本，用来刻画"个别操作很贵、但很少发生"的数据结构——它是对最坏情况的诚实记账，不是概率意义上的期望。

**通俗类比：** 健身房年卡：单次真去锻炼很贵，但摊到一整年每天都很便宜——前提是你别把它当成天天都去的成本。

## 为什么需要它

只看单次最坏会误判：动态数组 `append` 偶尔触发 O(n) 扩容，若据此说它是 O(n) 操作，就等于否定了几乎所有实用结构；反过来只看"通常 O(1)"又会漏掉那一下的尖刺。均摊分析给出第三种答案：**连续 m 次操作总代价 O(m)，所以每次均摊 O(1)**，同时保留"单次仍可能 O(n)"的事实，让你既能选结构，也能预判延迟毛刺。

## 计算逻辑

三种标准证法，结论等价、适用场景不同：

- **聚合法**：直接对 n 次操作求总代价再除以 n，适合规律清晰的场景（如翻倍扩容：第 i 次复制代价至多 i，总和 O(n)）。
- **会计法**：给每次"便宜"操作多收几个虚拟硬币存进 bank，等昂贵操作到来时用它付账，要求余额始终非负。
- **势能法**：定义结构状态势能 Φ，第 i 次均摊代价 = 实际代价 + ΔΦ，选好 Φ 即可证界（动态数组可取 Φ = 2·size − capacity）。

| 结构 | 单次最坏 | 均摊 |
|---|---|---|
| 动态数组 append（翻倍） | O(n) | O(1) |
| 栈 push/pop | O(n)（含扩容） | O(1) |
| 并查集 union/find | 最坏 O(n) | O(α(n)) |
| 计数器（二进制递增） | O(n) | O(1) |

## 具体示例

翻倍扩容的动态数组是标准案例：只有 size 追平 capacity 时才复制。

```python
def append(self, x):
    if self.size == self.capacity:
        self._resize(self.capacity * 2)   # 偶尔 O(n)
    self.data[self.size] = x
    self.size += 1                        # 多数 O(1)
```

n 次 append 的复制总量是 1+2+4+…+n < 2n，加 n 次赋值故总代价 O(n)，均摊 O(1)；若改成**每次 +1 扩容**，复制量变成 Θ(n²)，均摊退化。

## 何时用与何时不用

- **用**：评估带自动扩容、惰性重建、延迟删除的结构（动态数组、哈希表、跳表、斐波那契堆、缓冲写入）；解释"为什么批量插入比逐条插入快"。
- **不用**：实时系统看的是**单次最坏延迟**，均摊 O(1) 救不了那一次 O(n) 卡顿，须改用平滑重建等最坏界方案；操作之间不构成长序列时也谈不上均摊。

## 优劣与代价

✅ 揭示了操作序列层面的真实吞吐，避免用最坏单次界否定实用结构。
✅ 势能法是严格可证明的工具，能推广到高级数据结构的设计分析。
⚠️ 只对连续操作序列成立，中途大量删除或复用模式改变可能破坏前提。
⚠️ 掩盖延迟尖刺，面向实时性与尾延迟的场景会误导决策。

## 与相关概念的区别

- **均摊 vs 平均复杂度**：平均是对**输入分布**取期望、依赖概率假设；均摊是对**一次完整操作序列**求和均分，与概率无关，最坏输入下依然成立。
- **均摊 vs 最坏单次**：前者保证序列总成本，后者保证每次都不超，两者是吞吐与延迟的区别。
- **均摊分析 vs [[主定理]]**：主定理解递归式的规模递推，均摊分析处理同规模下的一系列操作。

## 常见误区

- 均摊 O(1) 就意味着每次操作都是常数时间、不会有延迟毛刺。
- 均摊复杂度和平均复杂度是一回事，都是求平均。
- 动态数组既然均摊 O(1)，扩容策略怎么设计都不影响性能。

## 面试速答

> 🎯 均摊分析算的是 n 次操作的总代价除以 n，与概率无关、不同于平均复杂度；动态数组翻倍扩容靠它证得 O(1)，代价是个别操作仍可能 O(n)，实时尾延迟场景不适用。
