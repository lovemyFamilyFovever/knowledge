# 前缀树


> 📌 **导航**：本文是 **前缀树** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 前缀树（Trie，又称字典树/单词查找树）是一种多叉树结构，用于高效存储与检索字符串集合：从根到某节点的路径拼出一个前缀，公共前缀共享同一路径，常用于前缀匹配、自动补全与词频统计。

**通俗类比：** 像字典按字母逐级索引——查 "apple" 时先翻到 a，再 ap、再 app……相同开头的词共用前面的翻页路径，不必每个词都从头找起。

> 多义说明：Trie 读作 "try"；有压缩前缀树（Radix / Patricia tree）、后缀树等变体。本文讨论基本 Trie。

## 为什么需要它

在大量字符串里做前缀匹配或补全，若用哈希表只能整词命中、无法按前缀枚举；用排序 + 二分能找边界但每次比较涉及字符串。Trie 把公共前缀合并到共享路径，使查找代价只与串长 L 有关而与集合规模无关，并天然支持"以某前缀开头的所有词"的枚举——这是自动补全、路由最长前缀匹配、词频统计的关键。

## 核心机制

- **结构：** 每个节点代表一个字符、根为空；从根到"词尾标记（isEnd）"节点的路径构成一个字符串；节点存子节点映射（定长数组或哈希），可选存计数/关联值。
- **操作：** 插入/查找/删除都沿字符逐层下降，时间 O(L)（L 为串长），与集合规模 n 无关。
- **空间：** 朴素 Trie 每节点存整个字母表、稀疏时浪费大，故有压缩变体（Radix tree 合并单链节点）。

| 组成 | 说明 |
|------|------|
| 根节点 | 空，所有串的起点 |
| 字符边 | 父到子对应一个字符 |
| 子节点映射 | 数组（定长字母表）或哈希 |
| 词尾标记 isEnd | 标识某路径是完整字符串 |
| 计数 / 值 | 可选，存词频或关联数据 |

## 具体示例

插入 "app" 与 "apple"：a→p→p 三个节点共享（到第二个 p 标 isEnd 表示 "app" 是完整词），再往下 l→e 才到 "apple" 的词尾。查前缀 "app" 沿路径下降到位后，从该节点 DFS 就能枚举出 "app""apple" 等所有以 app 开头的词——自动补全即在此实现。词频可在每个 isEnd 节点计数。

## 何时用 / 何时不用

- **用：** 搜索自动补全/输入联想、拼写检查与词典、IP 路由最长前缀匹配、词频统计、前缀检索、T9 输入法。
- **不用：** 只需整词精确查找（[[哈希表]] 更简单 O(1)）；字母表巨大且数据稀疏（朴素 Trie 内存膨胀，改用 Radix tree 或哈希）；无按前缀枚举需求时。

## 优劣与代价

✅ 前缀查询 O(L)、天然支持前缀枚举与自动补全、可按字典序遍历。
⚠️ 空间开销大，尤其数据稀疏或字符集大时。
⚠️ 朴素实现内存浪费，常需压缩变体或用哈希存子节点。

## 与相关概念的区别

- **vs 哈希表：** 哈希整词 O(1) 但不支持前缀枚举；Trie 支持前缀匹配/补全、代价 O(L)。
- **vs [[二叉搜索树]]：** BST 二叉、按键比较；Trie 多叉、按字符分层，与集合规模无关地定位。
- **Radix/Patricia tree：** Trie 的压缩版，合并只有一个子节点的路径省空间（见 [[字符串算法]]）。

## 常见误区

- Trie 的查找复杂度取决于集合里的字符串条数 n。
- 前缀树就是二叉搜索树，只是每个节点存一个字符。
- 朴素 Trie 的空间开销和二叉搜索树一样小。

## 面试速答

> 🎯 前缀树 Trie=多叉、按字符分层的字符串集合结构：公共前缀共享路径、节点带 isEnd/计数，插入查找删除都是 O(L)（只与串长有关、与词条数无关），天然支持前缀枚举/自动补全/最长前缀匹配/词频。代价是空间大（大字符集尤甚），用 Radix/Patricia 压缩单链省内存。整词精确查更适合哈希表。
