# 前缀树

## 定义

**一句话定义：** 前缀树(Trie,又称字典树/单词查找树)是一种多叉树结构,用于高效存储与检索字符串集合:从根到某节点的路径拼出一个前缀,公共前缀共享同一路径,常用于前缀匹配、自动补全与词频统计。

**通俗类比：** 像字典按字母逐级索引——查 "apple" 时先翻到 a,再 ap,再 app……相同开头的词共用前面的翻页路径,不必每个词都从头找起。

> 多义说明:Trie 读作 "try";有压缩前缀树(Radix / Patricia tree)、后缀树等变体。本文讨论基本 Trie。

## 原理与机制

- **结构:** 每个节点代表一个字符,根为空;从根到"词尾标记"节点的路径构成一个字符串;节点通常存子节点映射(数组或哈希)、是否为词尾(isEnd),可选存计数或关联值。
- **操作:** 插入 / 查找 / 删除都沿字符逐层下降,时间复杂度 O(L)(L 为字符串长度),与集合规模无关。
- **空间:** 朴素 Trie 每个节点存整个字母表,空间开销大,故有压缩变体(Radix tree 合并单链节点)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 根节点 | 空,所有串的起点 |
| 字符边 | 父到子对应一个字符 |
| 子节点映射 | 数组(定长字母表)或哈希 |
| 词尾标记 isEnd | 标识某路径是完整字符串 |
| 计数 / 值 | 可选,存词频或关联数据 |

## 应用场景

- 搜索自动补全、输入联想
- 拼写检查、词典
- IP 路由的最长前缀匹配
- 词频统计、T9 输入法、前缀匹配检索

## 优点与局限

- 优点:前缀查询极快 O(L)、天然支持前缀枚举与自动补全、可按字典序遍历。
- 局限:空间开销大(尤其稀疏时);朴素实现内存浪费;字符集大时节点膨胀(需压缩或用哈希存子节点)。

## 常见误区

- Trie 的查询复杂度取决于串长 L,而非词条数 n。
- Trie ≠ 二叉搜索树:它是多叉、按字符分层。
- "空间换时间"是其主要代价;Radix/Patricia tree 通过合并单链节点节省空间。
