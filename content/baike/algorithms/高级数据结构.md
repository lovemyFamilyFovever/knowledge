# 高级数据结构

> 本文详解工程中常用的高级结构。其中红黑树、B+ 树、Trie 已有专门词条，此处只给要点并双链；**跳表**与**布隆过滤器**在此展开。基础线性结构见 [[基础数据结构]]。

---

## 红黑树（Red-Black Tree）

**一句话定义：** 一种自平衡二叉搜索树，通过红黑着色规则保证最长路径不超过最短路径的 2 倍，从而增删查均 O(log n)。

> 📎 详见 [[红黑树]]（五条性质、旋转与变色、与 AVL 的取舍）。典型应用：Java TreeMap/TreeSet、C++ std::map、Linux CFS 调度器、Nginx 定时器。

## B+ 树

**一句话定义：** 多路平衡搜索树，非叶子只存索引、数据全在叶子且叶子间用链表相连，磁盘友好、范围查询高效。

> 📎 详见 [[B+树]]（与 B 树的区别、扇出与树高、为何适合数据库索引）。MySQL InnoDB、PostgreSQL 索引均基于 B+ 树；一棵 3 层 B+ 树可支撑千万级行。

## 跳表（Skip List）

**一句话定义：** 在有序链表上叠加多级「快车道」索引，用空间换时间，把查找从 O(n) 降到**平均 O(log n)** 的随机化数据结构。

```
Level 3:  1 ---------------------------------> 9
Level 2:  1 -----------> 5 -----------------> 9
Level 1:  1 ---> 3 ---> 5 ---> 7 ---> 9
（查找 7：先在高层大步逼近，再逐层下降精确定位）
```

- 平均 O(log n) 查找/插入/删除，最坏 O(n)；每层以约 1/2（或 1/4）概率晋升。
- **实现比红黑树简单**，且天然支持范围查询（底层是有序链表）。
- **Redis 的 ZSet（有序集合）** 底层即跳表（+ 哈希表）。

## 布隆过滤器（Bloom Filter）

**一句话定义：** 一种空间效率极高的**概率型**集合结构，用位数组 + 多个哈希函数判断元素「**一定不存在**」或「**可能存在**」。

```python
class BloomFilter:
    def __init__(self, size, hash_count):
        self.size = size
        self.hash_count = hash_count
        self.bit_array = [0] * size

    def add(self, item):
        for i in range(self.hash_count):
            idx = hash(f"{item}:{i}") % self.size
            self.bit_array[idx] = 1

    def might_contain(self, item):
        for i in range(self.hash_count):
            idx = hash(f"{item}:{i}") % self.size
            if self.bit_array[idx] == 0:
                return False   # 有一位为 0 → 一定不存在
        return True            # 全为 1 → 可能存在（有误判率）
```

- **特性**：有**假阳性**（误判「存在」），但**无假阴性**（判「不存在」一定准）；标准布隆过滤器**不支持删除**（需 Counting Bloom Filter）。
- **误判率**随位数组大小、哈希个数与已存元素数变化，可按目标误判率反推容量。
- **应用**：缓存穿透防护（见 [[分布式缓存]]）、爬虫 URL 去重、垃圾邮件/IP 黑名单、数据库「避免无谓回表」。

## Trie（前缀树）

**一句话定义：** 处理字符串前缀的树形结构，相同前缀共享路径，前缀匹配 O(m)（m 为串长，与词典规模无关）。

> 📎 详见 [[前缀树]]。应用：自动补全、拼写检查、IP 路由最长前缀匹配、敏感词（配合 AC 自动机，见 [[字符串算法]]）。

## 各数据结构对比

| 结构 | 查找 | 插入 | 删除 | 有序 | 典型应用 |
|------|------|------|------|------|----------|
| 红黑树 | O(log n) | O(log n) | O(log n) | 是 | 内存有序 Map |
| B+ 树 | O(log n) | O(log n) | O(log n) | 是 | 磁盘/数据库索引 |
| 跳表 | O(log n) 均摊 | O(log n) 均摊 | O(log n) 均摊 | 是 | Redis ZSet |
| 哈希表 | O(1) 均摊 | O(1) 均摊 | O(1) 均摊 | 否 | 快速查找 |
| 布隆过滤器 | O(k) | O(k) | 不支持 | 否 | 存在性预判 |

## 常见误区

- 「跳表最坏也是 O(log n)」：跳表是**随机化**结构，O(log n) 是期望/平均，最坏 O(n)（概率极低）。
- 「布隆过滤器说存在就一定存在」：恰恰相反——它只保证「说不存在一定对」，「说存在」可能误判。
- 「布隆过滤器能随便删元素」：标准版置位不可逆，删除会误伤共享位；需用计数布隆过滤器。
