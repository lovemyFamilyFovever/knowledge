# 高级数据结构


> 📌 **导航**：本文是 **高级数据结构** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 高级数据结构指跳表、布隆过滤器、红黑树、B+ 树、Trie 等在基础结构之上、针对有序/概率/磁盘/前缀/平衡等特定需求优化的工程化结构，各自在查询、增删、有序性与空间间做出不同权衡。

**通俗类比：** 像为特殊任务改造的工具——快车道（跳表）让有序链表查找飞快，门禁名单（布隆过滤器）用极小内存预判"在不在"，仓库货架目录（B+ 树）专为磁盘存取设计。

> 说明：本文详解跳表与布隆过滤器；红黑树、B+ 树、Trie 已有专门词条，只给要点并双链。基础线性结构见 [[基础数据结构]]。

## 为什么需要它

基础结构在特定场景有短板：有序链表查找 O(n)、[[哈希表]] 无序且不支持范围、普通 BST 会退化、内存型平衡树对磁盘不友好、精确集合存储占空间。高级结构正是针对这些短板优化——用随机化（跳表）、概率位图（布隆）、多路磁盘布局（B+ 树）、着色自平衡（红黑树）换取各自场景下更优的复杂度或空间。

## 核心机制

### 跳表（Skip List）

在有序链表上叠加多级"快车道"索引，查找从高层大步逼近、逐层下降定位，把查找/插入/删除降到平均 O(log n)（随机化，最坏 O(n) 概率极低），每节点以约 1/2 概率晋升；实现比平衡树简单、底层有序链表天然支持范围查询。Redis 的 ZSet 底层即跳表 + 哈希表。

```
Level 3:  1 ---------------------------------> 9
Level 2:  1 -----------> 5 -----------------> 9
Level 1:  1 ---> 3 ---> 5 ---> 7 ---> 9
```

### 布隆过滤器（Bloom Filter）

位数组 + k 个哈希的概率型结构：add 把 k 个位置 1，查询看这 k 位是否全 1。有假阳性（说"可能存在"未必在），但无假阴性（有一位 0 则"一定不存在"）；标准版不支持删除（置位不可逆，删会误伤共享位，需计数布隆过滤器）。

```python
def add(item):
    for i in range(k): bits[h(item, i) % m] = 1          # k 个哈希各置位
def might_contain(item):
    return all(bits[h(item, i) % m] for i in range(k))   # 一位为0→必不存在；全1→可能存在
```

### 其余（详见专门词条）

- **红黑树：** 着色自平衡 BST，近似平衡、增删查最坏 O(log n)，用于内存有序容器（[[红黑树]]）。
- **B+ 树：** 多路平衡、数据全在叶子且叶子成链表、磁盘友好、范围查询强，数据库索引基石（[[B+树]]）。
- **Trie：** 前缀共享路径，前缀匹配 O(m)（[[前缀树]]）。

| 结构 | 查找 | 插入 | 删除 | 有序 | 典型应用 |
|------|------|------|------|------|----------|
| 红黑树 | O(log n) | O(log n) | O(log n) | 是 | 内存有序 Map |
| B+ 树 | O(log n) | O(log n) | O(log n) | 是 | 磁盘/数据库索引 |
| 跳表 | O(log n) 均摊 | O(log n) 均摊 | O(log n) 均摊 | 是 | Redis ZSet |
| 哈希表 | O(1) 均摊 | O(1) 均摊 | O(1) 均摊 | 否 | 快速查找 |
| 布隆过滤器 | O(k) | O(k) | 不支持 | 否 | 存在性预判 |

## 具体示例

缓存穿透防护：请求海量不存在的 key 会击穿缓存直打数据库。先用布隆过滤器装载"存在的 key"，不在的（判"一定不存在"）直接拒掉，命中的再查缓存——用极小内存挡住绝大多数无效回源。Redis 排行榜用跳表维护 ZSet：既能 O(log n) 按分数增删查，又因底层有序可快速取 Top-K 与排名区间。

## 何时用 / 何时不用

- **用：** 要有序 + 简单实现选跳表；要极省内存的存在性预判、可容忍假阳性选布隆过滤器；内存有序容器用红黑树；磁盘索引用 B+ 树；字符串前缀用 Trie。
- **不用：** 需精确集合与删除时别用布隆；不需顺序时哈希更快；纯静态数据用数组 + 二分即可。

## 优劣与代价

✅ 各针对一类短板优化：跳表简洁且支持范围、布隆极省空间、B+ 树磁盘高效、红黑树通用有序。
⚠️ 布隆有假阳性、标准版不能删；跳表复杂度是期望非最坏保证。
⚠️ 高级结构增加实现与调参成本（位数组大小、哈希数、跳表概率）。

## 与相关概念的区别

- **跳表 vs [[红黑树]]：** 都是有序 O(log n)；跳表随机化、实现简单、易并发，红黑树确定性平衡。
- **布隆 vs 精确集合/哈希表：** 布隆概率型、省空间但有假阳性、不支持精确成员与删除。
- **B+ 树 vs 红黑树：** B+ 多路、面向磁盘块；红黑二叉、面向内存。

## 常见误区

- 布隆过滤器说某元素"可能存在"，它就一定在集合里。
- 标准布隆过滤器可以方便地删除某个元素。
- 跳表的查找最坏情况也是 O(log n)，绝对稳定。

## 面试速答

> 🎯 高级结构按需求补基础结构短板：跳表=有序链表+多级快车道，期望 O(log n)、实现比平衡树简单、天然支持范围查询（Redis ZSet）；布隆过滤器=位数组+多哈希，空间极省但只有一致误判、无假阴性，适合缓存前置判存在；线段树/树状数组做区间查询，平衡树保有序。
