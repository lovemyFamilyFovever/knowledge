# 二分查找


> 📌 **导航**：本文是 **二分查找** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 二分查找（Binary Search）是一种在**有序**序列中查找目标值的算法：每次将搜索区间对半缩小，通过比较中间元素与目标决定在前半还是后半继续，时间复杂度 O(log n)，远快于逐个查找的 O(n)。

**通俗类比：** 像查字典找单词——不会从第一页翻起，而是翻到中间看：目标词在前半就往前翻一半、在后半就往后翻一半，每次排除一半，很快定位。

> 多义说明：二分查找要求序列**有序**（或单调）；有多种变体（查精确值、查左/右边界、二分答案）。本文讨论基本二分及变体。

## 为什么需要它

线性扫描每次只排除一个元素，最坏 O(n)，在百万级数据上太慢。只要序列有序且能随机访问，就能用"目标与中点的比较"一次砍掉一半候选，把 n 步降到 log₂n 步——20 次比较就能定位上百万元素。它是"用有序性/单调性换对数级复杂度"的最典型范式，还能推广到"二分答案"。

## 核心机制

- **基本流程：** 维护区间 [lo, hi]，取 mid；比较 a[mid] 与 target——相等返回，a[mid] < target 则 `lo = mid + 1`，否则 `hi = mid − 1`。
- **边界与不变式：** 区间开闭（`lo <= hi` vs `lo < hi`）与 mid 取整方向要一致，否则死循环或越界。
- **变体：** lower_bound（第一个 ≥ target）、upper_bound（第一个 > target）、二分答案（在单调的答案空间上二分判定）。
- **复杂度：** 时间 O(log n)，迭代实现空间 O(1)。

| 组成 | 说明 |
|------|------|
| 有序前提 | 二分的必要条件 |
| 区间 [lo, hi] | 当前搜索范围 |
| mid 比较 | 决定收缩方向 |
| 边界处理 | 避免 off-by-one |
| lower/upper_bound | 查边界的变体 |

## 具体示例

在升序数组 `[2,5,8,12,16,23,38]` 找 23：lo=0、hi=6、mid=3 得 12<23，收缩到右半 lo=4；mid=5 得 23==23，返回下标 5。每步排除一半，3 次即命中。若用 lower_bound 找"第一个 ≥ 20"，则不等式方向改为"满足条件就记答案并继续向左找更早的"，得到下标 5。

## 何时用 / 何时不用

- **用：** 有序数组/表的精确查找与边界查找、求插入位置、旋转数组等单调可判的变体；"最小化最大值"类可单调判定的题用二分答案。
- **不用：** 数据无序且不排序（用哈希表/线性）；链表等不能随机访问的结构（退化成线性）；需要频繁插入删除的动态集合（用 [[二叉搜索树]]/平衡树）。

## 优劣与代价

✅ O(log n) 极快，迭代空间 O(1)，简单通用、可扩展到二分答案。
⚠️ 前提是有序——无序须先排序（O(n log n)）。
⚠️ 需要随机访问，且边界/off-by-one 极易写错。

## 与相关概念的区别

- **vs 线性查找：** 线性无前提、O(n)；二分要求有序、O(log n)。
- **vs 哈希查找：** 哈希无序、平均 O(1) 点查但不支持范围/前驱后继；二分保留有序性、可查边界。
- **vs [[二叉搜索树]]：** BST 把"折半"结构固化到树上、支持动态增删；对静态数组二分则 O(1) 空间。

## 常见误区

- 二分查找可以直接用在无序数组上，不需要先排序。
- `mid = (lo + hi) / 2` 这种写法在任何语言下都绝对安全、不会出问题。
- 二分的边界处理（lo<=hi、mid±1）无关紧要，怎么写都能跑对。

## 面试速答

> 🎯 二分查找=有序+随机访问下每次比较折半缩小 [lo,hi] 区间，O(log n)、迭代 O(1) 空间；关键是 mid 取整与 `lo<=hi`/`mid±1` 边界不变式统一（`mid` 用 `lo+(hi-lo)/2` 防溢出）。变体 lower/upper_bound 查边界，二分答案在单调判定空间上二分。
