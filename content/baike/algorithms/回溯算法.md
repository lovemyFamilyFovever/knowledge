# 回溯算法

## 定义

**一句话定义：** 回溯算法(Backtracking)是一种逐步构建候选解、并在发现当前候选不可能导出有效解时立即放弃(回退)转而尝试其他路径的系统化搜索方法;它本质上是带剪枝的深度优先搜索,常用于排列、组合、子集与约束满足问题。

**通俗类比：** 像走迷宫——沿一条路往前走,遇到死胡同(违反约束)就退回上一个岔路口,换一条路继续;通过"走不通就回头"系统地遍历所有可能,而不是一条道走到黑。

> 多义说明:回溯 = DFS + 剪枝;区别于纯暴力枚举(回溯会提前剪掉无效分支)与动态规划(回溯不记忆化子问题,通常求所有解或可行解)。本文讨论回溯。

## 原理与机制

- **框架:** 做选择(加入路径)→ 递归探索 → 若不满足约束则剪枝回溯(撤销选择)→ 尝试其他选择。
- **剪枝(pruning):** 提前排除不可能导出解的分支,大幅减少搜索量。
- **解空间树:** 在解空间树上做 DFS,并用路径记录当前候选解。
- **典型问题:** 全排列、组合、子集、N 皇后、数独、图着色、哈密顿路径。

## 关键组成

| 组成 | 说明 |
|------|------|
| 路径 / 选择 | 当前已构建的部分解 |
| 约束检查 | 判断是否可行 |
| 剪枝 | 提前放弃无效分支 |
| 递归与撤销 | 回溯的核心动作 |
| 解空间树 | DFS 遍历的对象 |

## 应用场景

- 排列、组合、子集枚举
- N 皇后、数独
- 约束满足问题(CSP)
- 图的哈密顿路径、图着色

## 优点与局限

- 优点:能系统地求出所有解或可行解;框架通用;剪枝可显著加速。
- 局限:最坏为指数级复杂度;剪枝设计影响很大;不适合超大规模问题;需正确保存/恢复状态(撤销选择)。

## 常见误区

- 回溯 ≠ 暴力枚举:回溯会剪掉无效分支。
- 回溯基于 DFS(而非 BFS)。
- 必须正确"撤销选择"(状态恢复),否则会污染后续分支。
- 回溯不记忆子问题(区别于动态规划)。
