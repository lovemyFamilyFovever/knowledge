# 回溯算法


> 📌 **导航**：本文是 **回溯算法** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 回溯算法（Backtracking）是一种逐步构建候选解、并在发现当前候选不可能导出有效解时立即放弃（回退）转而尝试其他路径的系统化搜索方法；它本质上是带剪枝的深度优先搜索，常用于排列、组合、子集与约束满足问题。

**通俗类比：** 像走迷宫——沿一条路往前走，遇到死胡同（违反约束）就退回上一个岔路口换一条路继续；通过"走不通就回头"系统地遍历所有可能，而不是一条道走到黑。

> 多义说明：回溯 = DFS + 剪枝；区别于纯暴力枚举（回溯会提前剪掉无效分支）与动态规划（回溯不记忆化子问题，通常求所有解或可行解）。本文讨论回溯。

## 为什么需要它

排列、N 皇后、数独这类"在指数级解空间里找所有/任一可行解"的问题，无法用贪心或 DP 直接给出最优结构。回溯沿解空间树做深度优先搜索，一边构造部分解一边用约束判断可行性，一旦当前前缀不可能扩展成合法解就立即回退——用剪枝把无效子树整片砍掉，远快于盲目枚举。

## 核心机制

- **框架：** 做选择（加入路径）→ 递归探索 → 不满足约束则剪枝回溯（撤销选择）→ 尝试其他选择。
- **剪枝（pruning）：** 提前排除不可能导出解的分支，大幅减少搜索量。
- **解空间树：** 在解空间树上做 DFS，用"路径"记录当前候选解，到达可行/完整解时收集。
- **典型问题：** 全排列、组合、子集、N 皇后、数独、图着色、哈密顿路径。

| 组成 | 说明 |
|------|------|
| 路径 / 选择 | 当前已构建的部分解 |
| 约束检查 | 判断是否可行 |
| 剪枝 | 提前放弃无效分支 |
| 递归与撤销 | 回溯的核心动作 |
| 解空间树 | DFS 遍历的对象 |

## 具体示例

全排列 [1,2,3]：第一层选 1，进入下一层在剩余 {2,3} 里选 2，再选 3 得到 [1,2,3]；收集后撤销 3、撤销 2、回到选 1 的层换 3……每次"选择→递归→撤销选择"恢复现场，确保兄弟分支从干净状态出发。N 皇后则在放置时检查列与两对角线冲突，冲突即剪掉整棵子树。

## 何时用 / 何时不用

- **用：** 需要枚举所有解或任一可行解的组合搜索问题——排列/组合/子集、N 皇后、数独、CSP、图路径着色等。
- **不用：** 只求最优且子问题具最优子结构 + 重叠时（[[动态规划]] 更高效）；有清晰贪心选择性质时（[[贪心算法]]）；解空间过大且无有效剪枝时不可行。

## 优劣与代价

✅ 能系统求出所有解或可行解，框架通用，剪枝可显著加速。
⚠️ 最坏是指数级复杂度，剪枝设计好坏影响巨大。
⚠️ 不适合超大规模问题；须正确保存/恢复状态（撤销选择）。

## 与相关概念的区别

- **vs 暴力枚举：** 回溯用约束剪掉无效分支，枚举把整棵子树走完。
- **vs [[动态规划]]：** 回溯不记忆子问题、常求所有解；DP 存子问题解求最优。
- **vs BFS：** 回溯是 DFS（沿一条路走到底再回头），非逐层扩展。

## 常见误区

- 回溯就是毫无优化地把所有可能组合枚举一遍。
- 回溯应当用广度优先（BFS）逐层扩展解空间树。
- 递归探索后是否撤销选择无所谓，留着全局状态也没事。

## 面试速答

> 🎯 回溯=带剪枝的 DFS：在解空间树上「做选择→递归→撤销选择」构造候选解，当前前缀违反约束或无法扩展成解就立即回退，用于全排列/组合/子集/N 皇后/数独等求所有或任一可行解。关键是必须正确撤销恢复现场，区别于不剪枝的暴力枚举与记忆子问题的 DP，代价是最坏指数级、依赖剪枝质量。
