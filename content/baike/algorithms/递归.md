# 递归


> 📌 **导航**：本文是 **递归** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 递归（Recursion）是一种把问题转化为"规模更小的同类子问题"来求解的方法——函数在其定义中调用自身，不断缩小规模直到抵达可直接求解的基本情况（base case），再逐层返回并合并结果。

**通俗类比：** 像排队问"我第几位"——不从头数，而是问前面一位"你第几?"，他再问他的前一位……直到问到排头（base case），答案再一层层传回来。

> 多义说明：递归是一种编程/算法思想；有直接递归、间接递归、尾递归（tail recursion）。本文讨论递归思想与实现。

## 为什么需要它

许多问题（树、分治、回溯）本身就是自相似的：整体解可由"一个更小的同类子解"推出。递归让你直接按这种数学定义写代码——一个 base case + 一个递归关系即描述清楚，比手动维护栈的迭代实现更简洁、更不易错，是表达 [[分治算法]]、[[回溯算法]]、记忆化 DP 与树/图遍历的自然工具。

## 核心机制

- **两要素：** 递归关系（把规模 n 归约到更小子问题）+ 基本情况（base case，终止条件），缺一不可，否则无限递归爆栈。
- **执行过程：** 每次调用压入调用栈（栈帧保存参数/局部变量/返回地址），抵达 base case 后逐层返回、回溯合并。
- **尾递归：** 递归调用是函数最后一步，理论上可被"尾调用消除"优化为循环，但并非所有语言/编译器都支持（如 Python 默认不优化）。
- **重复计算：** 朴素递归可能指数级重算同一子问题（如斐波那契），需记忆化或自底向上迭代。

| 组成 | 说明 |
|------|------|
| base case | 递归终止条件 |
| 递归关系 | 归约到更小子问题 |
| 调用栈 / 栈帧 | 保存每层调用状态 |
| 递归深度 | 影响栈开销 |
| 尾递归 | 可优化为循环的形式 |

## 具体示例

求阶乘 fact(n)：base case `n<=1 返回 1`，递归关系 `n * fact(n-1)`，规模每层减 1 直到 base case 再逐层返回相乘。树的中序遍历天生递归：`inorder(左) → 访问根 → inorder(右)`。而朴素 `fib(n)=fib(n-1)+fib(n-2)` 会指数级重算，加一张 memo 表（记忆化）或改成迭代累加即降到 O(n)。

## 何时用 / 何时不用

- **用：** 问题具递归结构——树/图遍历、分治、回溯、记忆化 DP、汉诺塔、阶乘/斐波那契等，递归最直观。
- **不用/注意：** 深度极大时栈溢出（改迭代或显式栈）；子问题大量重叠又无记忆化时低效；对性能/内存极敏感、或语言无尾调用优化时优先考虑迭代。

## 优劣与代价

✅ 代码简洁、贴合问题的递归定义、易表达分治与回溯。
⚠️ 调用栈开销大，深度大易栈溢出；朴素递归可能指数级重复计算。
⚠️ 通常比迭代更慢/耗内存，尾递归优化并不普遍。

## 与相关概念的区别

- **递归 vs 迭代：** 递归靠函数调用栈隐式记录状态、迭代靠显式循环/栈；二者可互转，递归更易读但多栈开销。
- **递归 vs [[动态规划]]：** 记忆化递归是自顶向下的 DP 实现，DP 是自底向上的填表，本质同一类"存子问题解"。
- **尾递归 vs 一般递归：** 尾递归（递归在最后一步）可被优化成循环，一般递归不可。

## 常见误区

- 只要写了递归函数就一定能正常终止，不需要显式的 base case。
- 递归一定比循环更快、更好，任何问题都该优先用递归。
- 任何语言都会自动把尾递归优化成循环，因此不必担心栈溢出。

## 面试速答

> 🎯 递归=把问题化为规模更小的同类子问题、函数调用自身，需两要素：base case（终止）+ 递归关系（归约），靠调用栈记录每层状态、逐层返回合并。适合树/图遍历、分治、回溯、记忆化 DP；代价是栈开销与溢出风险、朴素递归可能指数级重算。尾递归并非所有语言都优化（Python 默认不）。
