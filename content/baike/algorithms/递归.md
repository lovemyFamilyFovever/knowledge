# 递归


> 📌 **导航**：本文是 **递归** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** 递归(Recursion)是一种把问题转化为"规模更小的同类子问题"来求解的方法——函数在其定义中调用自身,不断缩小规模直到抵达可直接求解的基本情况(base case),再逐层返回并合并结果。

**通俗类比：** 像排队问"我第几位"——你不从头数,而是问前面一位"你第几?",他再问他的前一位……直到问到排头(base case),答案再一层层传回来。

> 多义说明:递归是一种编程/算法思想;有直接递归、间接递归、尾递归(tail recursion)。本文讨论递归思想与实现。

## 原理与机制

- **两要素:** 递归关系(把规模 n 归约到更小的子问题)+ 基本情况(base case,终止条件);二者缺一不可,否则无限递归导致栈溢出。
- **执行过程:** 每次调用压入调用栈(栈帧),抵达 base case 后逐层返回(递归下降 + 回溯/合并)。
- **常见载体:** 分治、回溯、动态规划(记忆化递归)常用递归实现;树与图的遍历天然适合递归。
- **尾递归:** 递归调用是函数的最后一步,理论上可优化为循环(尾调用消除),但并非所有语言/编译器都支持。

## 关键组成

| 组成 | 说明 |
|------|------|
| base case | 递归终止条件 |
| 递归关系 | 归约到更小子问题 |
| 调用栈 / 栈帧 | 保存每层调用状态 |
| 递归深度 | 影响栈开销 |
| 尾递归 | 可优化为循环的形式 |

## 应用场景

- 树 / 图遍历
- 分治(归并排序、快速排序)
- 回溯(N 皇后、子集)
- 动态规划(记忆化递归)、汉诺塔、阶乘/斐波那契

## 优点与局限

- 优点:代码简洁、贴合问题的递归结构、易于表达分治与回溯。
- 局限:调用栈开销大(深度大易栈溢出);朴素递归可能重复计算(如斐波那契,需记忆化);通常比迭代更慢/耗内存;尾递归优化并不普遍。

## 常见误区

- 缺少 base case 或递归不收敛会导致栈溢出。
- 朴素递归可能指数级重复计算(应记忆化或改迭代)。
- 递归不一定优于迭代(存在栈开销)。
- 并非所有语言都做尾调用优化(如 Python 默认不优化)。
