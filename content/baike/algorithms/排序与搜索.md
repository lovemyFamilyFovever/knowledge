# 排序与搜索

> 排序是将数据按特定顺序排列的过程，搜索是在数据中找到目标的过程。不同的算法适用于不同的数据规模和场景。
>
> 📌 **导航**：本文是 **排序与搜索** 枢纽页。排序与查找族已拆为 [[排序算法]]、[[查找算法]] 独立词条；图的遍历与最短路（DFS/BFS/A*/Dijkstra/Floyd）沿用 [[图算法大全]]、[[最短路径算法]]，复杂度理论见 [[复杂度分析]]。

## 定义

**一句话定义：** 排序与搜索是一对互补的基本操作——排序把数据**预先组织成有序**，搜索在这个前提上做折半、树查或哈希定位；二者合起来回答"这批数据被反复查时，值不值得先整理"。

**通俗类比：** 图书馆的两种工作：编目上架（排序）按索书号排好，读者来查（搜索）才能直奔某一排；先不编目，每次查找就都得从头排到尾。

本页是**枢纽页**：原汇编 16 个并列主题中，排序族与查找族各收敛成独立词条，图搜索部分本就已有多条专文，此处只留选型路线与复杂度总账。

## 为什么需要它

这两类操作是绝大多数系统的底座：主键定位、去重判存、区间扫描、Top-K、按时间线归并、路由与导航，全落在"先组织、再查询"这条链上。更重要的是它们是理解**预处理与查询的分工**的最小例子——比较排序有 Ω(n log n) 下界，查找也受"无序则必须线性"的限制，想突破就必须先付出组织数据的代价，或者改变对键的假设（值域小、分布均匀）。把这条取舍讲清，数据库索引、缓存、布隆过滤器就不再是孤立技巧。

## 核心机制

### 两大问题、一族解法

排序按原理分**比较类**（冒泡、选择、插入、归并、快排、堆排）与**非比较类**（计数、桶、基数），后者靠键的取值分布突破 n log n；查找按**数据前提**分线性、二分、插值、树、哈希五档，越快意味着事先做的组织越多。两者共享同一组评估维度：时间阶、额外空间、稳定性或有序性、以及"最坏情况是否有保证"。

### 选型三问

第一问**数据长什么样**：规模、是否近乎有序、键是否整数小值域、分布是否均匀、重复多不多。第二问**访问模式是什么**：只查一次还是反复查、要不要范围与前驱后继、写入是否频繁。第三问**哪条是硬约束**：内存红线要求原地、尾延迟要求最坏界、多关键字合并要求稳定。三问答完，选择基本唯一。

### 复杂度总账

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
|---|---|---|---|---|
| 插入 | O(n²) | O(n²) | O(1) | 稳定 |
| 归并 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 快排 | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 堆排 | O(n log n) | O(n log n) | O(1) | 不稳定 |
| 计数 | O(n+k) | O(n+k) | O(k) | 稳定 |

## 具体示例

同一条查找，容器选择决定了它是线性还是常数，这是最常见的性能陷阱：

```python
for x in sorted_arr:        # 已排序却不利用有序性：O(n)
    if x == target: break
i = bisect_left(sorted_arr, target)   # 折半：O(log n)
```

批量场景同理：对 n 个查询，"排序一次 + 逐个二分"是 O(n log n)，"逐个线性扫"是 O(n·m)；查询越多，预处理越划算。

## 何时用与何时不用

- **用排序**：下游要二分、去重、区间合并、Top-K、有序输出或外存归并时。
- **用查找**：数据被反复访问就先组织——静态有序用二分、点查用哈希、要范围与有序遍历用平衡树、海量判存用布隆过滤器前置。
- **不用**：只需判存在且仅查一两次，别为二分而整体排序；只要第 K 小或前 K 大，用堆或快速选择而非全排序；值域远大于 n 时别上计数排序。

## 优劣与代价

✅ 一次组织换来后续全部查询降到对数或常数级，是索引与缓存体系的共同原理。
✅ 评估维度统一（阶、空间、稳定性、最坏界），选型可推理而非凭经验。
⚠️ 预处理不是免费的：写入频繁时代价高，静态结构还会过期。
⚠️ 平均界会骗人——快排最坏退化、哈希碰撞攻击、插值在偏斜分布上失效，都要看最坏情况。

## 与相关概念的区别

- **排序 vs 查找**：前者是预处理、后者是消费；"先排后查"就是把一次成本摊给多次查询。
- **稳定 vs 原地**：两条独立的轴，归并稳定不原地、堆排原地不稳定，别混为一谈。
- **比较类 vs 非比较类排序**：前者只依赖两两比较、受下界约束；后者利用键分布可达线性。
- **本页 vs [[算法思想]]**：思想页讲分治/贪心/DP 等范式，本页讲两类具体操作及其选型。

## 常见误区

- 快速排序平均最快，所以任何数据、任何场景都该首选它。
- 哈希查找平均 O(1)，所以有了哈希表就不再需要平衡树。
- 二分查找一定比线性查找快，所以任何时候都应该用它。

## 面试速答
