# KMP 算法


> 📌 **导航**：本文是 **KMP 算法** 词条，属于 algorithms 术语集。相关枢纽：[[AVL 树]]、[[KMP 算法]]、[[二分查找]]、[[二叉搜索树]]、[[位运算]]。

## 定义

**一句话定义：** KMP 算法（Knuth-Morris-Pratt）是一种高效的字符串匹配算法，它通过预处理模式串得到"部分匹配表"（next / failure 数组），在主串失配时利用已匹配的信息跳过不必要的比较、让主串指针不回溯，从而在 O(n + m) 时间内完成匹配。

**通俗类比：** 像在长句里找某个词——朴素方法每次失配都要把"读取位置"退回词头重来；KMP 则记住"这个词自身前后有哪些重复片段"，失配时直接把模式串滑动到该在的位置，主句的读取位置从不后退，省掉大量重复比对。

> 多义说明：KMP 是单模式串匹配算法；区别于朴素匹配（O(n·m)）、Rabin-Karp（基于哈希）与多模式匹配的 AC 自动机。本文讨论 KMP。

## 为什么需要它

朴素匹配最坏是 O(n·m)：每次失配就把主串指针回退、模式串重头比，做了大量重复比较。当文本很长、模式有自相似结构（如 `AAAAAB`）时退化严重。KMP 观察到"已经匹配上的前缀"本身携带信息，据此让主串指针永不回溯、模式串指针智能回跳，把总时间压到线性 O(n + m)，且适合只读一遍/流式场景。

## 核心机制

- **核心思想：** 主串指针 i 不回溯；模式串指针 j 失配时依据 next 数组跳到 `next[j]`。
- **next / 失配数组：** `next[j]` = 模式串前 j 个字符中"最长相等前后缀"的长度；预处理耗时 O(m)。
- **匹配过程：** i 从头扫描主串、j 跟随；失配则反复 `j = next[j]`（直到 j 归零或匹配成功）；当 j 达到 m 即命中一次。
- **复杂度：** 预处理 O(m) + 匹配 O(n) = O(n + m)；空间 O(m)。

| 组成 | 说明 |
|------|------|
| 主串 / 模式串 | 被搜索文本与待匹配模式 |
| next（失配）数组 | 最长相等前后缀长度 |
| 主串指针不回溯 | KMP 的关键特性 |
| O(n + m) | 线性时间复杂度 |

## 具体示例

在文本 `ABABDABABCD` 找模式 `ABABC`。预处理 `ABABC` 的 next 得各位置最长相等前后缀长度（如 `ABAB` 前缀 `AB` = 后缀 `AB`，next=2）。当匹配到第 5 个字符 `C` 处失配（文本是 D），朴素法会整体右移重来；KMP 令 j 回跳到 next[4]=2，模式串 `AB` 对齐到已匹配的后缀 `AB` 下继续比，主串指针不动。因主串指针从不后退，整体只扫一遍即 O(n + m)。

## 何时用 / 何时不用

- **用：** 长文本中单模式匹配、要求线性最坏保证；主串只能读一遍的流式/只读场景；DNA 比对、编辑器查找、入侵检测特征匹配。
- **不用：** 需要同时匹配大量模式串（用 AC 自动机 / [[前缀树]] 扩展）；模式极短、字母表极小时朴素法常数更低；追求实用平均最快可考虑 Boyer-Moore。

## 优劣与代价

✅ 线性时间 O(n + m)、主串不回溯（适合流式）、最坏情况有保证。
⚠️ next 数组构建较难理解与实现、边界/版本易错。
⚠️ 短模式或小字母表下优势不明显，常数因子有时高于朴素或 Boyer-Moore。

## 与相关概念的区别

- **vs 朴素匹配：** 朴素失配回退主串、最坏 O(n·m)；KMP 主串不回溯、O(n + m)。
- **vs Rabin-Karp：** RK 用滚动哈希、适合多模式但可能哈希冲突需验证；KMP 确定性地用前后缀信息。
- **vs AC 自动机：** KMP 单模式；AC 用失败指针在多模式（基于 [[前缀树]]）上同时匹配。

## 常见误区

- KMP 在主串失配时会像朴素算法那样把主串指针退回词头重新比较。
- next 数组只有一种统一定义，实现时无需关心边界与版本差异。
- KMP 天生适合一次性匹配多个不同的模式串。

## 面试速答

> 🎯 KMP=单模式串线性匹配 O(n+m)：先对模式串预处理 next/failure 数组（每位存最长相等前后缀长度，O(m)）；匹配时主串指针 i 永不回溯、失配则模式串指针 j=next[j] 回跳，复用已匹配前缀跳过重复比较。优于朴素 O(n·m)，适合流式；多模式要用 AC 自动机。
