# 时空权衡

> 📌 **导航**：本文是 **时空权衡** 词条，属于 algorithms 术语集。相关枢纽：[[复杂度分析]]、[[时间复杂度]]、[[空间复杂度]]、[[基础数据结构]]、[[动态规划]]。

## 定义

**一句话定义：** 时空权衡是在算法设计中对**时间复杂度**与**空间复杂度**的有意交换：缓存、索引、查表把计算换成存储以提速，原地化、重算、滚动数组则压缩存储、用重复计算省内存——二者通常不可兼得，取哪一头取决于哪个资源更稀缺。

**通俗类比：** 搬家时的断舍离：全部带走最省事但房子要更大，只带常用的则每次要回头再取——空间和时间这杆秤，你总得压一头。

## 为什么需要它

同一问题往往有两条极端的实现：不建表每次重算，或者建满表一步查完。不做取舍就会踩在昂贵的资源上：内存耗尽会触发换页乃至 OOM，比慢一点严重得多；而盲目建表则可能在内存本就紧张的端侧把可行方案变成不可行。把权衡显式化，才能按**瓶颈资源**（内存红线、延迟目标、访问频次）而不是按直觉来决定该花哪一边。

## 核心机制

- **空间换时间**：用额外存储预先算好或索引好，把重复计算变成一次查表——缓存与记忆化、[[哈希表]] 索引、[[动态规划]] 表、前缀和、布隆过滤器判重、预排序。
- **时间换空间**：不存中间结果、需要时重算，或直接改写输入——DP 滚动数组把 O(n²) 压到 O(n)、原地排序、外部多轮扫描代替内存排序、位图代替布尔数组。
- **判断该压哪头**：先看谁是硬约束（内存有上限还是延迟有上限），再看数据被**复用几次**——只查一次就别建表，被高频访问才值得预计算。

| 手法 | 空间代价 | 时间收益 | 典型场景 |
|---|---|---|---|
| 哈希索引 | O(n) | 查找 O(n) → O(1) | 两数之和、去重 |
| 前缀和 | O(n) | 区间和 O(n) → O(1) | 频繁区间查询 |
| 记忆化 | O(状态数) | 指数 → 多项式 | 递归重叠子问题 |
| 滚动数组 | 省 O(n) 档 | 几乎不变 | DP 只依赖前一层 |

## 具体示例

两数之和换成哈希索引是空间换时间；DP 斐波那契收成两个变量是时间换空间：

```python
seen = {}                      # O(n) 空间，换掉外层循环
for i, x in enumerate(nums):
    if target - x in seen: return [seen[target - x], i]
    seen[x] = i

a, b = 0, 1
for _ in range(n):             # O(1) 空间，保留 O(n) 时间
    a, b = b, a + b
```

## 何时用与何时不用

- **用**：同一份数据被反复查询（建索引划算）；内存宽裕但延迟敏感（做缓存、预计算）；内存受限而访问一次性（滚动、原地、重算）。
- **不用**：数据量小到两种写法都无感时，别为省一个数组牺牲可读性；缓存命中率低或访问局部性差时，建表反而同时亏掉空间与时间；有严格尾延迟要求时，延迟扩容类手法要额外评估毛刺。

## 优劣与代价

✅ 让实现能匹配真实瓶颈资源，多数量级跃升（暴力→查表、指数→DP）正是靠这一交换取得。
✅ 两个方向都很朴素：预计算与重算，几乎每个数据结构都建立在此之上。
⚠️ 缓存带来失效、并发与一致性成本，"快"的代价常常转移到了工程复杂度上。
⚠️ 大 O 看不见常数与局部性，实测时常出现同阶实现之间数倍差距。

## 与相关概念的区别

- **空间换时间 vs 单纯优化**：前者改变算法的成本结构（阶或重复次数），后者只降常数。
- **时空权衡 vs [[均摊分析]]**：权衡决定"要不要存"，均摊分析解释"存的代价如何摊到每次操作"。
- **权衡 vs [[时间复杂度]]/[[空间复杂度]] 分析**：先量出两阶，才能谈取舍；权衡是决策层，复杂度分析是度量层。
- **预计算 vs 惰性求值**：前者提前占空间换响应速度，后者推迟到使用时才付代价。

## 常见误区

- 空间换时间总是更优，内存反正比 CPU 便宜。
- 加了缓存就一定更快，命中率无关紧要。
- 只要把辅助空间压到 O(1)，算法性能就一定提升。

## 面试速答

> 🎯 时空权衡就是在两个瓶颈资源之间有意交换：查表、索引、记忆化、前缀和用空间换时间；原地化、滚动数组、重算用时间换空间，选择看哪个是硬约束、数据被复用几次。
