# 端到端加密

## 定义

**一句话定义：** 端到端加密(End-to-End Encryption, E2EE)是一种通信安全机制:数据在发送方加密、只有预期的接收方能解密,传输途中的中间节点(服务器、运营商、中继)即使截获也无法读取明文,从而保护通信内容的机密性。

**通俗类比：** 像寄一个只有收件人有钥匙的保险箱——邮局、快递、中转站(中间服务器)全程只搬运这个锁着的箱子,谁都打不开;只有收件人用他的钥匙(私钥)才能打开看内容。

> 多义说明:E2EE 区别于"传输加密"(如 TLS 只保护客户端到服务器一段,服务器端可见明文);E2EE 是"端到端"全程加密。本文讨论 E2EE。

## 原理与机制

- **密钥:** 通信双方各持私钥,用非对称加密协商/交换对称密钥(如 Signal 协议的 X3DH + 双棘轮 Double Ratchet)。
- **加密:** 消息用对称密钥加密,只有持有对应密钥的端能解密;服务器只存储/转发密文。
- **前向保密(forward secrecy):** 每次会话/消息使用派生的临时密钥,即使长期私钥泄露也无法解密历史消息。
- **身份验证:** 需验证对方公钥指纹/安全码,以防中间人攻击。

## 关键组成

| 组成 | 说明 |
|------|------|
| 端侧密钥对 | 仅通信双方持有 |
| 密钥协商 | X3DH / ECDH |
| 对称加密 | 加密实际消息内容 |
| 前向保密 | 双棘轮等临时密钥 |
| 身份验证 | 安全码/指纹核对 |

## 应用场景

- 即时通讯(Signal、WhatsApp)
- 加密邮件(PGP)
- 视频会议
- 云存储的零知识加密、隐私通信

## 优点与局限

- 优点:中间方无法窥探内容、强隐私与前向保密、抗服务器被攻破。
- 局限:密钥管理复杂(丢失即无法恢复);服务端无法提供内容相关功能(搜索/合规审查);元数据(谁在何时通信)通常不加密;身份验证依赖用户;与执法/合规存在张力。

## 常见误区

- E2EE ≠ TLS/HTTPS:TLS 只加密到服务器(服务器可见明文),E2EE 连服务器也不可见。
- E2EE 通常不保护元数据。
- 前向保密是重要属性(长期密钥泄露不解历史消息)。
- 端到端的前提是正确验证对方身份,否则仍可能被中间人攻击。
