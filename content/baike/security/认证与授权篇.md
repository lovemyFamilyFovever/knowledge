# 认证与授权篇


> 📌 **导航**：本文是 **认证与授权篇** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 认证与授权篇是"身份与权限"总览的索引枢纽：原稿 OAuth 2.0、JWT、Session、Cookie、SSO、RBAC、ABAC、API Key、Basic Auth、Bearer Token、OIDC、MFA 十二节已按概念归口——令牌与授权框架归 [[OAuth 与 JWT]]，有状态会话归 [[Cookie与Session]]，授权模型归 [[访问控制]]，HTTP 层携带凭证的 API Key/Basic/Bearer 归 [[API Key 与 Basic 与 Bearer 认证方式]]，单点登录与多因素各立专条；本页只回答"这个名词归哪一条、认证与授权怎么分"。

**通俗类比：** 像机场出行的流程总图：先确认你是谁(值机核验=认证)，再决定你能进哪、坐哪、能带什么(登机口与舱位=授权)；本篇是这张分流图，每一站的详细规则写在各自词条里，本页只做接线、不复述任何一站的操作。

## 为什么需要它

一期把十二个能独立命名的认证名词挤进一篇、还垫了 244 行代码与十余段配置，属"全都提、全查不到"的原料形态；而 security/network/web-backend 三个子域随各分片推进，已把这些概念逐条立成成熟专条。归口收敛后查任一名词只需一跳：本枢纽负责的是认证(你是谁)与授权(你能做什么)两层的分界、有状态与无状态的选择、单系统与多系统的取舍——这张"跨子域接线图"恰是单条专条写不下、散篇汇编又找不齐的。原稿的示例代码一律收敛，不在此复述。

## 核心机制

先按下表定位归口，再进对应词条看机制：

| 主题 | 归口 | 它回答什么 |
|------|------|------------|
| OAuth 2.0 授权 / JWT 令牌 | [[OAuth 与 JWT]] | 第三方授权流程、令牌格式与验签 |
| Session / Cookie 会话 | [[Cookie与Session]] | 有状态会话怎么维持、怎么失效 |
| API Key / Basic / Bearer 携带凭证 | [[API Key 与 Basic 与 Bearer 认证方式]] | 凭证以什么格式附到请求上 |
| SSO / OIDC 单点登录 | [[SSO 与 OIDC 单点登录]] | 一次登录跨多系统、身份认证层 |
| RBAC / ABAC 授权模型 | [[访问控制]] | 认证之后谁能对什么做什么 |
| MFA 多因素 | [[MFA 多因素认证]] | 这一次登录要用几类因子证明 |
| 整体选型与加固 | [[认证与安全实践]] | 一条链路怎么串起来 |

1. **认证与授权是两层，选型先分层**：回答"你是谁"(认证)的凭证与回答"你能做什么"(授权)的策略不能混谈——OAuth 2.0 本质是授权框架、身份认证要靠其上的 OIDC(见 [[SSO 与 OIDC 单点登录]])，RBAC/ABAC 只管认证之后的授权(见 [[访问控制]])；把"登录成功"当成"已持最小权限"是绝大多数越权的起点。
2. **有无状态是 Session 与 JWT 的分水岭**：Session 把状态留服务端、能即时踢人但要共享存储，JWT 把状态写进签名令牌、免存储却难主动注销(见 [[OAuth 与 JWT]]·[[Cookie与Session]])；凭证怎么带上又是另一维度——Cookie 自动携带、Bearer 手动附头、API Key 静态串(见 [[API Key 与 Basic 与 Bearer 认证方式]])。
3. **多系统就得多一跳信任**：一次登录跨多个互信应用是 SSO 的目标，CAS 靠一次性票据、OIDC 在 OAuth 上签 id_token 来证身份(见 [[SSO 与 OIDC 单点登录]])；单系统内不需要这层中心化复杂度，别为了"看起来企业级"提前上。
4. **认证强度与授权粒度各有一条纵深**：密码之外再叠一类因子(MFA，见 [[MFA 多因素认证]])、口令存储用慢哈希加盐(见 [[加盐哈希与口令存储]])；授权侧 RBAC 够用就别陷入 ABAC 的策略爆炸，全站 HTTPS 保证凭证不在传输层裸奔(见 [[HTTPS 与 TLS]]·[[认证与安全实践]])。

## 具体示例

给一个对外应用做登录与鉴权，本图三块会一次走齐：自家页面登录后服务端建会话、`Set-Cookie` 下发 Session ID(有状态、可即时踢人，见 [[Cookie与Session]])；App 与多服务无状态鉴权则登录换一枚 JWT、以 `Authorization: Bearer` 携带(见 [[OAuth 与 JWT]]·[[API Key 与 Basic 与 Bearer 认证方式]])；接第三方"用微信/GitHub 登录"走 OAuth 2.0 授权码、要身份再叠 OIDC(见 [[SSO 与 OIDC 单点登录]])；高价值账户在密码外再要一枚 TOTP 第二因子(见 [[MFA 多因素认证]])；登录之后"谁能改哪条数据"交给 RBAC/ABAC(见 [[访问控制]])。名词各就各位，工程师要记的只有"这类问题去哪一页"。

## 何时用与何时不用

- **用**：刚接触身份安全、或被问"这个名词归哪类"时，先回本页看表再进专条；给别人讲认证与授权全貌，以"认证层 / 授权层 + 有状态 / 无状态 + 单系统 / 多系统"为大纲。
- **不用**：别在本页找任一协议的报文格式或某框架的行级配置——那是各归口专条的事；枢纽给的是指针与分界，深度论证与实现一律跳转归口词条。

## 与相关概念的区别

- **vs [[认证与安全实践]]**：那条是 Web 后端视角的实践总纲(选 Session 还是 JWT、输入侧加固清单)；本篇是跨子域的术语归口图，认证机制只是其中一路。
- **vs [[OAuth 与 JWT]]**：那条专讲授权框架与令牌格式一对；本篇把 OAuth/JWT 接进"整条认证授权链路"，并指向其余各节归口。
- **vs [[访问控制]]**：访问控制是"授权"这一层的模型总览(DAC/MAC/RBAC/ABAC)；本篇把"认证"与"授权"两层一起索引，授权只占其中一格。

## 常见误区

- 认为用户登录成功，就已经只持有他应有的最小权限。
- 把 OAuth 2.0 当成身份认证协议，以为走通第三方登录就完成了认证。
- 觉得 JWT 和 Session 只是名字不同、失效与注销能力完全一样。

## 面试速答

> 🎯 认证与授权分两层：认证管你是谁、授权管你能做什么；OAuth 只授权、身份靠 OIDC，MFA 强登录，RBAC/ABAC 管授权；Session 可即时踢、JWT 难注销，凭证靠 Cookie/Bearer/API Key 携带，多系统才上 SSO。
