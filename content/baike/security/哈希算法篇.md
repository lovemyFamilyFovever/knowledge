# 哈希算法篇

哈希算法是安全领域的基石，它能把任意长度的数据"压缩"成固定长度的指纹。无论是密码存储、数据完整性校验还是分布式系统，都离不开哈希。本篇将带你理解常见的哈希算法及其应用场景。

---

## MD5（Message Digest 5）

**一句话定义（大白话）**
MD5 是一种把任意长度的数据变成 128 位（32 个十六进制字符）固定长度"指纹"的算法。

**通俗类比（生活场景）**
就像给每本书生成一个独特的"书号"，不管你有多少页，最终只得到一串简短的编号。通过这个编号就能快速判断两本书是否相同。

**具体示例（代码、命令或操作场景）**
```bash
# Linux/Mac 命令行计算 MD5
echo -n "hello" | md5sum
# 输出: 5d41402abc4b2a76b9719d911017c592

# Python 计算 MD5
import hashlib
h = hashlib.md5(b"hello")
print(h.hexdigest())  # 5d41402abc4b2a76b9719d911017c592
```

**为什么需要它（解决什么问题）**
快速校验文件是否被篡改，比如下载文件后对比 MD5 值。但请注意：**MD5 已不安全**，容易被碰撞攻击，不应用于密码存储或安全场景。

**与相关术语的对比和区分**
- MD5 产生 128 位摘要，SHA-1 产生 160 位，SHA-256 产生 256 位
- MD5 速度最快但安全性最低，SHA-256 安全性高但计算稍慢
- 现代系统推荐用 SHA-256 或更高级的哈希算法替代 MD5

---

## SHA-1（Secure Hash Algorithm 1）

**一句话定义（大白话）**
SHA-1 是 MD5 的"升级版"，输出 160 位（40 个十六进制字符）的哈希值，安全性比 MD5 高。

**通俗类比（生活场景）**
像是升级版的防伪标签，比 MD5 更难伪造，但现在已经有了更新的版本。

**具体示例（代码、命令或操作场景）**
```bash
# 命令行计算 SHA-1
echo -n "hello" | sha1sum
# 输出: aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d

# Python 计算 SHA-1
import hashlib
h = hashlib.sha1(b"hello")
print(h.hexdigest())  # aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d
```

**为什么需要它（解决什么问题）**
SHA-1 曾广泛用于数字证书和版本控制（如 Git commit ID）。但 2017 年 Google 实现了碰撞攻击，现在 SHA-1 也被认为不安全。

**与相关术语的对比和区分**
- SHA-1 比 MD5 安全，但比 SHA-256 弱
- Git 仍使用 SHA-1 作为对象标识符（有特例）
- 新项目应选择 SHA-256 或更高级别

---

## SHA-256

**一句话定义（大白话）**
SHA-256 是 SHA-2 家族的一员，输出 256 位（64 个十六进制字符）的哈希值，是目前最主流的安全哈希算法。

**通俗类比（生活场景）**
相当于银行级的防伪技术，想要伪造一个与原文件哈希相同的假文件，计算量大到几乎不可能。

**具体示例（代码、命令或操作场景）**
```bash
# 命令行计算 SHA-256
echo -n "hello" | sha256sum
# 输出: 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

# Python
import hashlib
h = hashlib.sha256(b"hello")
print(h.hexdigest())

# 比特币挖矿就是不断找nonce使得区块哈希的SHA-256结果小于目标值
```

**为什么需要它（解决什么问题）**
比特币的工作量证明（PoW）、TLS 证书签名、文件完整性校验、密码存储等安全场景都依赖 SHA-256。

**与相关术语的对比和区分**
- SHA-256 安全性远高于 MD5 和 SHA-1
- SHA-512 输出更长但计算更慢，适合对安全性要求极高的场景
- 性能：MD5 > SHA-1 > SHA-256 > SHA-512

---

## SHA-512

**一句话定义（大白话）**
SHA-512 是 SHA-2 家族中输出最长的算法，产生 512 位（128 个十六进制字符）的哈希值。

**通俗类比（生活场景）**
像是超长的指纹，理论上比 SHA-256 更难碰撞，适用于高安全要求的军用或金融系统。

**具体示例（代码、命令或操作场景）**
```bash
echo -n "hello" | sha512sum
# 输出一个 128 位的十六进制字符串

# Python
import hashlib
h = hashlib.sha512(b"hello")
print(h.hexdigest())
```

**为什么需要它（解决什么问题）**
当需要更高安全级别时，SHA-512 提供比 SHA-256 更长的摘要，碰撞概率更低。

**与相关术语的对比和区分**
- SHA-512 比 SHA-256 更安全但更慢
- 实际项目中 SHA-256 已经足够安全，SHA-512 多用于特殊场景
- 两者都属于 SHA-2 家族，安全性远超 MD5 和 SHA-1

---

## HMAC（Hash-based Message Authentication Code）

**一句话定义（大白话）**
HMAC 是"带密钥的哈希"，既能验证数据完整性，又能验证发送者身份。

**通俗类比（生活场景）**
普通哈希像公开的防伪标签，谁都能算；HMAC 像是只有你和银行知道密码的防伪标签，别人算不出来。

**具体示例（代码、命令或操作场景）**
```python
import hmac
import hashlib

# HMAC-SHA256
key = b"my-secret-key"
message = b"hello"
hmac_result = hmac.new(key, message, hashlib.sha256).hexdigest()
print(hmac_result)  # 类似: 1c8a5b6d...（带密钥的哈希值）

# 验证
hmac.new(key, message, hashlib.sha256).hexdigest() == hmac_result  # True
```

**为什么需要它（解决什么问题）**
API 请求签名、JWT 签名、消息完整性验证。防止攻击者篡改数据后重新计算哈希。

**与相关术语的对比和区分**
- 普通哈希：任何人都能计算，只能验证完整性
- HMAC：需要密钥才能计算，同时验证完整性和身份
- HMAC 不是加密算法，不提供保密性

## 哈希表原理

**一句话定义（大白话）**
哈希表是一种数据结构，通过哈希函数把键（key）映射到数组下标，实现 O(1) 平均时间复杂度的查找。

**通俗类比（生活场景）**
像酒店的房间号系统：房卡号（key）通过某种规则直接对应到房间（value），不需要挨个查找。

**具体示例（代码、命令或操作场景）**
```python
# Python 字典就是哈希表的实现
student_scores = {}
student_scores["张三"] = 95
student_scores["李四"] = 87

# 查找 O(1)
print(student_scores["张三"])  # 95

# 哈希冲突示例：两个 key 可能映射到同一位置
# 解决方法：链地址法、开放寻址法等
```

**为什么需要它（解决什么问题）**
快速查找、去重、缓存等场景。没有哈希表，很多操作会退化为 O(n)。

**与相关术语的对比和区分**
- 哈希表：用于快速查找的数据结构
- 布隆过滤器：用于快速判断元素是否存在的概率数据结构
- 一致性哈希：用于分布式系统的数据分片策略

---

## 布隆过滤器（Bloom Filter）

**一句话定义（大白话）**
布隆过滤器是一种概率数据结构，用于快速判断一个元素是否"可能存在"或"一定不存在"。

**通俗类比（生活场景）**
像一个有多个印章的检查站：你说"我叫张三"，检查员在你的名字上盖了几个章。下次你再来，看看这些章是否都对。但可能存在别人名字也盖了同样的章（假阳性）。

**具体示例（代码、命令或操作场景）**
```python
# Python 使用 pybloom-live
from pybloom_live import BloomFilter

bf = BloomFilter(capacity=1000, error_rate=0.001)
bf.add("user_12345")
bf.add("user_67890")

print("user_12345" in bf)  # True（一定存在）
print("user_99999" in bf)  # False（一定不存在）
# 假阳性：某个不存在的元素可能被误判为存在
```

**为什么需要它（解决什么问题）**
Redis 防缓存穿透、爬虫URL去重、垃圾邮件过滤。避免对不存在的数据进行昂贵的查询。

**与相关术语的对比和区分**
- 哈希表：精确查找，空间较大
- 布隆过滤器：概率判断，空间极小，有假阳性
- 一致性哈希：用于数据分片，不是判断存在性

---

## 一致性哈希（Consistent Hashing）

**一句话定义（大白话）**
一致性哈希是一种将数据均匀分布到多个节点的算法，当节点增减时只影响少量数据迁移。

**通俗类比（生活场景）**
像转盘抽奖：把转盘分成多个区域，每个区域对应一个服务器。用户根据名字"转"到对应区域。增加或减少服务器时，只需要重新分配相邻区域的数据。

**具体示例（代码、命令或操作场景）**
```
传统哈希：hash(key) % N（N=节点数）
问题：增加节点后，几乎所有数据都要重新映射！

一致性哈希：
节点和数据都映射到环上
数据顺时针找到最近的节点
增加节点只影响相邻节点的数据
```

```python
# 简化的一致性哈希实现思路
import hashlib

class ConsistentHash:
    def __init__(self, nodes, replicas=100):
        self.replicas = replicas
        self.ring = {}
        for node in nodes:
            for i in range(replicas):
                key = self._hash(f"{node}:{i}")
                self.ring[key] = node

    def _hash(self, key):
        return int(hashlib.md5(key.encode()).hexdigest(), 16)

    def get_node(self, data_key):
        h = self._hash(data_key)
        for key in sorted(self.ring.keys()):
            if h <= key:
                return self.ring[key]
        return self.ring[list(self.ring.keys())[0]]
```

**为什么需要它（解决什么问题）**
分布式缓存（Memcached、Redis Cluster）、负载均衡、分布式存储。解决传统哈希在节点变动时大量数据迁移的问题。

**与相关术语的对比和区分**
- 一致性哈希 vs 普通哈希：节点变动时影响范围不同
- 一致性哈希 vs 哈希表：前者用于分布式系统，后者用于本地数据结构
- 虚拟节点：解决数据倾斜问题

## 校验和（Checksum）

**一句话定义（大白话）**
校验和是一种简单的错误检测码，通过对数据进行简单运算得到一个值，用于判断传输过程中是否出错。

**通俗类比（生活场景）**
像快递包裹上的"重量核对"：发货时称重记录，收货时再称一次，重量不对就说明可能丢了东西。

**具体示例（代码、命令或操作场景）**
```bash
# 计算文件校验和
sha256sum myfile.tar.gz
# 输出: 3a7bd3e2...  myfile.tar.gz

# 下载后验证
sha256sum -c checksum.txt
# myfile.tar.gz: OK

# 网络传输中的校验和（TCP/IP首部）
# 发送方计算校验和，接收方验证，不匹配则丢弃重传
```

**为什么需要它（解决什么问题）**
文件下载完整性验证、网络传输错误检测、软件包签名验证。

**与相关术语的对比和区分**
- 校验和：简单快速，用于错误检测（非安全）
- 哈希算法：更复杂，用于安全场景
- 数字签名：包含密钥，可验证来源和完整性

## 加盐哈希（Salted Hash）

**一句话定义（大白话）**
加盐哈希就是在计算哈希之前，给原始数据（如密码）加上一个随机字符串（盐），让相同的密码产生不同的哈希值。

**通俗类比（生活场景）**
像给每碗汤加不同的调料：即使两碗汤底料相同，加了不同调料后味道就不同了。这样即使别人看到你的"汤方"（哈希值），也猜不出原始配方。

**具体示例（代码、命令或操作场景）**
```python
import hashlib
import os

# 不加盐：相同密码产生相同哈希（危险！）
password = "123456"
hashlib.sha256(password.encode()).hexdigest()
# 每次都是同一个值，容易被彩虹表攻击

# 加盐：每次产生不同哈希
salt = os.urandom(16)  # 生成16字节随机盐
salted_hash = hashlib.pbkdf2_hmac(
    'sha256',
    password.encode(),
    salt,
    100000  # 迭代次数
)
print(f"盐: {salt.hex()}")
print(f"哈希: {salted_hash.hex()}")
# 存储时同时保存盐和哈希值
```

**为什么需要它（解决什么问题）**
防止彩虹表攻击。即使两个用户密码相同，加盐后哈希值也不同，攻击者无法批量破解。

**与相关术语的对比和区分**
- 盐（Salt）：随机字符串，加在密码前/后
- 彩虹表：预计算的哈希查找表，加盐使其失效
- 加盐哈希 vs 直接哈希：前者安全性远高于后者
- 推荐使用 PBKDF2、bcrypt、Argon2 等专业密码哈希算法
