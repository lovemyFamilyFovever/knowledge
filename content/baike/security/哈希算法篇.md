# 哈希算法篇


> 📌 **导航**：本文是 **哈希算法篇** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 哈希算法篇是"哈希一体两用"的索引枢纽：作安全原语，它用 MD5/SHA 家族给出抗碰撞的定长摘要，再经 HMAC、加盐慢哈希延伸到身份与口令存储；作索引工具，它把摘要当均匀分布的下标，撑起 [[哈希表]]、[[布隆过滤器]]、[[一致性哈希]] 三类工程结构——本页只回答"哪类问题去哪个子词条"。

**通俗类比：** 像"指纹技术总目录"：刑侦比对指纹(抗碰撞摘要)、火漆钢印(带密钥的 HMAC)、门禁印章板(布隆过滤器)、酒店房卡号对应房间(哈希表)、宴席排桌图挪桌最少(一致性哈希)各立一格；查目录即可对号入座，本页不重述每件工具的原理。

## 为什么需要它

"哈希"一词同时出现在两类性质相反的问题里：对抗性的(攻击者会不会伪造同摘要内容、会不会拖库批量破解口令)与非对抗性的(亿级 key 查一个键、节点增减求最少迁移、存在性预判省内存)。混用会两头出错——拿 MD5 做签名摘要、给口令直存快哈希是前者，用 SHA-512 抗碰撞强度去算布隆位图下标则白付算力。选型第一问永远是"这里有没有对手"，枢纽把这条分界一次画清，细节全部下沉子词条。

## 核心机制

先按下表按问题定位归口，再进对应词条看机制：

| 要解决的问题 | 归口子词条 | 一句话取舍 |
|--------------|------------|------------|
| 消息指纹要抗伪造碰撞 | [[密码学哈希函数（MD5 · SHA-1 · SHA-256 · SHA-512）]] | MD5/SHA-1 退役，默认 SHA-256 |
| 不光没改、还要证明是谁发的 | [[HMAC 与校验和]] | 裸哈希只管完整性，带密钥才管身份 |
| 口令落库，防彩虹表与 GPU 穷举 | [[加盐哈希与口令存储]] | 慢哈希+每人独立盐，快哈希禁用 |
| 海量集合秒答"肯定没来过" | [[布隆过滤器]] | 判无绝对可信，判有有假阳性 |
| 键值按下标直达、O(1) 查找 | [[哈希表]] | 冲突处理与扩容在专条 |
| 节点增减只动最少数据 | [[一致性哈希]] | 环形取值+虚拟节点防倾斜 |

1. **哈希算法选型第一问是"还抗不抗碰撞"**：MD5(2004 起可构造碰撞)与 SHA-1(2017 SHAttered)已从安全原语降级为普通查重函数，签名、证书、任何有对手的路径一律 SHA-256 起步，四成员强度谱系与长度扩展陷阱见 [[密码学哈希函数（MD5 · SHA-1 · SHA-256 · SHA-512）]]。
2. **"存了哈希"不等于"安全"，完整性与身份是两件事**：裸摘要谁都能重算，改内容顺手换摘要即告过关——身份要带密钥的 [[HMAC 与校验和]] 或 [[数字签名]]；口令这类低熵输入更反直觉，须刻意变慢并加盐，配方见 [[加盐哈希与口令存储]]。
3. **同一枚摘要的两副面孔：安全原语与索引工具**：作原语要求"找不到碰撞"，作索引只要求"分布均匀、算得快"——[[哈希表]] 拿它取桶下标、[[布隆过滤器]] 拿它定位 k 个位、[[一致性哈希]] 拿它定环上位置，三处用非加密哈希就够，不必为强度买单。
4. **表格负责"有什么、去哪格"，本页不重复承载机制细节**：算法族谱、HMAC 构造、布隆参数、口令配方各归上列四条新建子词条；盐/彩虹表/密钥的概念地图在仍待拆分收敛的 [[密码学基础篇]]，操作层"到底配什么参数"见 [[密码学实用指南]]。

## 具体示例

一次 HTTPS 访问同时走过三格：证书链验证用 SHA-256 摘要做签名前置(见 [[HTTPS 与 TLS]]、[[公钥基础设施]])，握手完整性由 HMAC 家族构造保证，应用侧会话令牌用 HS256(即 HMAC-SHA256，见 [[OAuth 与 JWT]])；而网关缓存前置布隆过滤器挡"随机不存在的 key"打穿回源，分片层用一致性哈希决定每个 key 落哪台 Redis——同一个哈希函数，按对手在不在场，戴着完全不同两顶帽子。

## 何时用与何时不用

- **对表进子词条**：对抗性摘要→SHA-2 族；带密钥认证→HMAC；口令→加盐慢哈希；存在性预筛→布隆；本地键值→哈希表；分片少迁移→一致性哈希。
- **别做的**：口令禁用快哈希裸存或"MD5 加盐两遍"；签名与证书场景别恋战 MD5/SHA-1；别把 CRC/校验和当防篡改；别把"用了哈希"本身当成安全结论——三条判断线各见对应子词条。

## 优劣与代价

✅ 定长摘要计算极快、无密钥依赖，是完整性、索引、寻址三种角色的公共底座，两侧延伸各有专条承接。
✅ 与既有 done 专条(哈希表/一致性哈希/签名/TLS)双向衔接、不重复承载，安全侧新产物只立了缺口的四格。
⚠️ 哈希不提供保密与身份：不可逆不代表安全，选错档位(快哈希存口令、裸摘要证身份)比不用更容易酿事故。
⚠️ 家族内部代际断层明显：旧存量(MD5 签名、SHA-1 对象 ID)迁移是长尾工程，"还能跑"与"还安全"须分开清账。

## 常见误区

- 哈希就是加密的一种，拿到哈希值再配一把密钥总能还原原文。
- 给数据算过 SHA-256 就等于给数据上了锁，和加密一样安全。
- 哈希表、布隆过滤器、一致性哈希属于密码学应用，选型时必须按 MD5 还是 SHA-256 的安全性来挑。

## 面试速答

> 🎯 哈希一体两用：安全侧按"抗碰撞+带不带密钥"选型——摘要默认 SHA-256(MD5/SHA-1 退役)、身份上 HMAC、口令用加盐慢哈希；索引侧只取分布均匀——哈希表、布隆过滤器、一致性哈希各管查找、预筛、分片。
