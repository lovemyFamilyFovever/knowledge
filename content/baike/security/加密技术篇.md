# 加密技术篇

加密是将明文转换为密文的过程，只有拥有密钥的人才能还原。本篇将带你理解对称加密、非对称加密、混合加密等核心概念，以及 AES、RSA 等主流算法。

---

## 对称加密（Symmetric Encryption）

**一句话定义（大白话）**
加密和解密使用同一把密钥，就像用同一把钥匙锁门和开门。

**通俗类比（生活场景）**
你和室友共用一把钥匙：你锁上门，室友用同一把钥匙打开。双方必须都持有这把钥匙。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.fernet import Fernet

# 生成密钥
key = Fernet.generate_key()
f = Fernet(key)

# 加密
message = b"Hello, World!"
encrypted = f.encrypt(message)
print(encrypted)  # 类似: b'gAAAAABk...'

# 解密
decrypted = f.decrypt(encrypted)
print(decrypted.decode())  # Hello, World!
```

**为什么需要它（解决什么问题）**
快速加密大量数据。对称加密速度比非对称加密快 100-1000 倍，适合文件加密、数据库加密等场景。

**与相关术语的对比和区分**
- 对称加密：同一密钥，速度快，密钥分发困难
- 非对称加密：公钥加密私钥解密，速度慢，解决密钥分发问题
- 混合加密：结合两者优势，实际应用最广

## 非对称加密（Asymmetric Encryption）

**一句话定义（大白话）**
使用一对密钥：公钥加密的数据只有对应的私钥能解密，私钥签名的数据公钥可以验证。

**通俗类比（生活场景）**
像信箱投递口：任何人都能通过投递口（公钥）往里投信，但只有你有钥匙（私钥）能打开信箱取信。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes

# 生成密钥对
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

# 公钥加密
message = b"Secret message"
encrypted = public_key.encrypt(
    message,
    padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()), algorithm=hashes.SHA256(), label=None)
)

# 私钥解密
decrypted = private_key.decrypt(encrypted, padding.OAEP(...))
print(decrypted.decode())  # Secret message
```

**为什么需要它（解决什么问题）**
解决密钥分发难题。HTTPS、SSH、数字签名都依赖非对称加密。

**与相关术语的对比和区分**
- 非对称加密：安全但慢，用于密钥交换和签名
- 对称加密：快但密钥分发难，用于数据加密
- 实际使用通常是混合加密：非对称加密传递对称密钥

## AES（Advanced Encryption Standard）

**一句话定义（大白话）**
AES 是目前最流行的对称加密标准，支持 128/192/256 位密钥，被全球政府和企业广泛采用。

**通俗类比（生活场景）**
像银行保险箱的锁：安全级别高，开锁速度快，全球通用标准。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend
import os

# AES-256 加密
key = os.urandom(32)  # 256位密钥
iv = os.urandom(16)   # 初始化向量

cipher = Cipher(algorithms.AES(key), modes.CBC(iv), backend=default_backend())
encryptor = cipher.encryptor()

plaintext = b"Hello, AES-256!"
# 需要填充到16字节的倍数
padded = plaintext + b"\x00" * (16 - len(plaintext) % 16)
ciphertext = encryptor.update(padded) + encryptor.finalize()

# 解密
decryptor = Cipher(algorithms.AES(key), modes.CBC(iv), backend=default_backend()).decryptor()
decrypted = decryptor.update(ciphertext) + decryptor.finalize()
print(decrypted.rstrip(b"\x00").decode())  # Hello, AES-256!
```

**为什么需要它（解决什么问题）**
替代已不安全的 DES/3DES。AES 是当今最安全、最高效的对称加密算法，被 SSL/TLS、WPA2、磁盘加密等采用。

**与相关术语的对比和区分**
- AES vs DES：AES 安全性更高（128位密钥 vs 56位）
- AES vs 3DES：AES 更快更安全
- AES-256 vs AES-128：前者更安全但稍慢

## DES（Data Encryption Standard）

**一句话定义（大白话）**
DES 是上世纪 70 年代的加密标准，使用 56 位密钥，现在已被认为不安全。

**通俗类比（生活场景）**
像老式门锁：当年很先进，但现在的万能钥匙（计算机）几小时就能打开。

**具体示例（代码、命令或操作场景）**
```python
# DES 已不安全，仅供参考
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
import os

key = os.urandom(8)  # 56位密钥（实际存储8字节）
iv = os.urandom(8)

cipher = Cipher(algorithms.DES(key), modes.CBC(iv))
# ...加密解密流程类似AES
```

**为什么需要它（解决什么问题）**
理解加密发展历史。DES 被破解后催生了 3DES 和 AES。

**与相关术语的对比和区分**
- DES：56位密钥，已被暴力破解
- 3DES：用三次DES增强安全性，但仍不够快
- AES：替代 DES 的现代标准，更安全更快

## 3DES（Triple DES）

**一句话定义（大白话）**
3DES 是对 DES 的增强，用三个不同的 56 位密钥对数据进行三次加密，实际密钥强度为 112 或 168 位。

**通俗类比（生活场景）**
像上了三道锁的保险箱：虽然每道锁（DES）都不够安全，但三道一起用就难破解多了。

**具体示例（代码、命令或操作场景）**
```python
# 3DES 示例（仅供参考，新项目不要用）
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
import os

key = os.urandom(24)  # 三组56位密钥（168位）
iv = os.urandom(8)

cipher = Cipher(algorithms.TripleDES(key), modes.CBC(iv))
# ...加密解密流程
```

**为什么需要它（解决什么问题）**
过渡期方案：DES 不够安全但又要兼容旧系统时使用。现已被 AES 替代。

**与相关术语的对比和区分**
- 3DES vs DES：安全性提升，但速度慢了三倍
- 3DES vs AES：AES 更快更安全，是首选
- 3DES 仍在一些遗留系统（如支付终端）中使用

## RSA

**一句话定义（大白话）**
RSA 是最著名的非对称加密算法，基于大数分解的数学难题，支持密钥长度 1024-4096 位。

**通俗类比（生活场景）**
像一个单向门：进去容易（用公钥加密）出来难（需要私钥解密），除非你知道秘密出口（私钥）。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization

# 生成 RSA 密钥对
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

# 加密
message = b"RSA encryption test"
encrypted = public_key.encrypt(
    message,
    padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()), algorithm=hashes.SHA256(), label=None)
)

# 解密
decrypted = private_key.decrypt(encrypted, padding.OAEP(...))

# 导出公钥
pem = public_key.public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo
)
print(pem.decode())
```

**为什么需要它（解决什么问题）**
密钥交换、数字签名、SSL/TLS 握手。RSA 是互联网安全的基石之一。

**与相关术语的对比和区分**
- RSA vs ECC：RSA 密钥更长（2048位 vs 256位），计算更慢
- RSA vs ElGamal：RSA 更常用，ElGamal 支持同态加密
- RSA 密钥长度：2048位目前安全，推荐 3072 或 4096 位

## ECC（Elliptic Curve Cryptography）

**一句话定义（大白话）**
ECC 是基于椭圆曲线数学的非对称加密，用更短的密钥实现与 RSA 相同的安全级别。

**通俗类比（生活场景）**
像小型电动车 vs 大型卡车：同样能载人（安全级别相同），但 ECC 更轻便（密钥短、计算快）。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.hazmat.primitives import hashes

# 生成 ECC 密钥对
private_key = ec.generate_private_key(ec.SECP256R1())  # 256位
public_key = private_key.public_key()

# 签名
message = b"ECC signature test"
signature = private_key.sign(message, ec.ECDSA(hashes.SHA256()))

# 验证
try:
    public_key.verify(signature, message, ec.ECDSA(hashes.SHA256()))
    print("签名有效！")
except:
    print("签名无效！")
```

**为什么需要它（解决什么问题）**
移动设备、物联网等资源受限环境。比特币、以太坊等加密货币也使用 ECC。

**与相关术语的对比和区分**
- ECC 256位 ≈ RSA 3072位 的安全强度
- ECC 计算更快、密钥更短、带宽更省
- 移动端和区块链首选 ECC

## ElGamal

**一句话定义（大白话）**
ElGamal 是一种基于离散对数问题的非对称加密算法，支持同态加密特性。

**通俗类比（生活场景）**
像可以"部分解密"的信封：即使只解密一部分，也能验证内容是否正确。

**具体示例（代码、命令或操作场景）**
```python
# ElGamal 加密（简化示例）
# 实际使用较少，更多用于学术和特殊场景
from cryptography.hazmat.primitives.asymmetric import elgamal
from cryptography.hazmat.primitives import hashes

# 生成密钥
private_key = elgamal.generate_private_key(key_size=2048)
public_key = private_key.public_key()

# 加密
ciphertext = public_key.encrypt(b"ElGamal test")

# 解密
plaintext = private_key.decrypt(ciphertext)
```

**为什么需要它（解决什么问题）**
同态加密：在密文上直接计算，解密后得到正确结果。适用于隐私保护计算。

**与相关术语的对比和区分**
- ElGamal vs RSA：ElGamal 支持同态加密，RSA 不支持
- ElGamal vs ECC：ECC 更高效，是现代首选
- ElGamal 密文长度是明文的两倍

## 国密 SM2/SM3/SM4

**一句话定义（大白话）**
国密是中国国家密码管理局制定的密码算法标准：SM2 是非对称加密，SM3 是哈希算法，SM4 是对称加密。

**通俗类比（生活场景）**
像中国版的"RSA+SHA256+AES"，是国产化替代方案。

**具体示例（代码、命令或操作场景）**
```python
# 需要安装 gmssl 库
from gmssl import sm2, sm3, sm4

# SM4 对称加密
key = bytes.fromhex('0123456789abcdeffedcba9876543210')
iv = bytes.fromhex('00000000000000000000000000000000')
crypt = sm4.CryptSM4()
crypt.set_key(key, sm4.SM4_ENCRYPT)
encrypted = crypt.crypt_ecb(b'Hello SM4!')

# SM3 哈希
from gmssl.sm3 import sm3_hash
hash_value = sm3_hash.sm3_hash([i for i in b'Hello SM3!'])
```

**为什么需要它（解决什么问题）**
国产化替代、合规要求（金融、政府系统）、自主可控。

**与相关术语的对比和区分**
- SM2 vs RSA：SM2 基于椭圆曲线，更短密钥更高安全
- SM3 vs SHA-256：输出长度相同，安全强度相当
- SM4 vs AES：SM4 密钥128位，安全性与 AES-128 相当

## 密钥交换（Key Exchange）

**一句话定义（大白话）**
密钥交换是让双方在不安全的通道上协商出一个共享密钥的过程。

**通俗类比（生活场景）**
像两个人想约好用同一把锁，但不想让别人知道密码。他们通过一系列公开的"暗号"交流，最终得出相同的密钥。

**具体示例（代码、命令或操作场景）**
```python
# Diffie-Hellman 密钥交换
from cryptography.hazmat.primitives.asymmetric import dh
from cryptography.hazmat.primitives import hashes

# 生成参数
parameters = dh.generate_parameters(generator=2, key_size=2048)

# Alice 和 Bob 各自生成密钥对
alice_private = parameters.generate_private_key()
alice_public = alice_private.public_key()

bob_private = parameters.generate_private_key()
bob_public = bob_private.public_key()

# 各自用对方公钥和自己私钥计算共享密钥
alice_shared = alice_private.exchange(bob_public)
bob_shared = bob_private.exchange(alice_public)

print(alice_shared == bob_shared)  # True！共享密钥相同
```

**为什么需要它（解决什么问题）**
在不安全的网络上安全地建立加密通信。HTTPS、SSH 都使用密钥交换。

**与相关术语的对比和区分**
- DH 密钥交换：不直接加密，只生成共享密钥
- RSA 密钥交换：用公钥加密对称密钥传过去
- ECDHE：基于椭圆曲线的临时密钥交换，更安全

## 混合加密（Hybrid Encryption）

**一句话定义（大白话）**
混合加密结合了非对称加密和对称加密的优点：用非对称加密传递对称密钥，再用对称密钥加密实际数据。

**通俗类比（生活场景）**
像快递包裹：用非对称加密（特殊锁）安全地把对称密钥（普通钥匙）寄过去，然后双方用这把普通钥匙快速通信。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.fernet import Fernet
import os

# 1. 生成非对称密钥对
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

# 2. 生成对称密钥（AES）
symmetric_key = Fernet.generate_key()
f = Fernet(symmetric_key)

# 3. 用非对称密钥加密对称密钥
encrypted_key = public_key.encrypt(
    symmetric_key,
    padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()), algorithm=hashes.SHA256(), label=None)
)

# 4. 用对称密钥加密数据
message = b"Hybrid encryption is the best of both worlds!"
encrypted_data = f.encrypt(message)

# 5. 解密：先用私钥解密对称密钥，再解密数据
decrypted_key = private_key.decrypt(encrypted_key, padding.OAEP(...))
f2 = Fernet(decrypted_key)
decrypted_data = f2.decrypt(encrypted_data)
print(decrypted_data.decode())
```

**为什么需要它（解决什么问题）**
HTTPS、PGP 加密邮件、安全通信。非对称加密解决密钥分发，对称加密保证效率。

**与相关术语的对比和区分**
- 混合加密 = 非对称加密（密钥交换）+ 对称加密（数据加密）
- 这是实际应用中最常见的加密方式
- TLS 1.3 默认使用 ECDHE + AES-256-GCM 混合加密

## 数字信封（Digital Envelope）

**一句话定义（大白话）**
数字信封是一种将对称密钥用接收方公钥加密后发送的技术，只有接收方能解开信封取出密钥。

**通俗类比（生活场景）**
像一个上了锁的保险箱：把对称密钥放进保险箱，用接收方的公钥锁上，只有接收方的私钥能打开。

**具体示例（代码、命令或操作场景）**
```python
# 数字信封的简化流程
# 1. 发送方生成随机对称密钥
# 2. 用对称密钥加密消息
# 3. 用接收方公钥加密对称密钥
# 4. 将加密后的密钥和消息一起发送

# 接收方：
# 1. 用私钥解密得到对称密钥
# 2. 用对称密钥解密消息

# 实际应用：S/MIME 邮件加密、PGP
```

**为什么需要它（解决什么问题）**
安全传递加密数据。结合了对称加密的效率和非对称加密的安全性。

**与相关术语的对比和区分**
- 数字信封 vs 数字签名：信封保证保密性，签名保证完整性和身份认证
- 数字信封 vs 混合加密：本质是同一概念的不同表述
- 数字信封是混合加密的一种具体实现形式
