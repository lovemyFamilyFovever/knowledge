# 中间人攻击


> 📌 **导航**：本文是 **中间人攻击** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 中间人攻击(Man-in-the-Middle Attack, MITM)是攻击者秘密介入通信双方之间,分别与他们建立连接并转发(可窃听或篡改)消息,使双方误以为在直接、私密地通信,从而窃取或操纵数据的一类攻击。

**通俗类比：** 像你和朋友隔空传纸条,中间偷偷站了个人——他先收到你的纸条、看完(甚至改了)再转给朋友,朋友的回信也经他手;你俩都以为在直接对话,其实全程被这个"中间人"看着、甚至改着。

## 为什么需要它

通信两端彼此看不见,只能凭"收到的东西"推断对面是谁、链路是否干净。MITM 攻击的正是这个推断:不必破解任何密码学,只要站到中间,就能让双方各自维持一条"看起来完全正常"的连接。隐蔽性极高——双方都只跟一个"应答正常的一端"说话;门槛也低,一台笔记本加开源工具就够在公共 Wi-Fi 里落地。

## 核心机制

1. **介入信道:** 让自己成为流量的必经之路——ARP 欺骗把自己插进局域网、伪造同名 Wi-Fi 热点("邪恶双胞胎")、DNS 劫持把域名指到自己这里、BGP 劫持改路由。
2. **双向中继:** 与两侧各建一条连接,原样转发或篡改后再转发,并对两侧各自维持正常表象;身份冒充让双方误认对方。
3. **降级:** SSL 剥离(sslstrip)引导用户走 http 链接,压根不给建立 TLS 的机会。

本质是同时破坏"信道可信"与"对方身份可信"——加密本身并不天然提供后者。

## 具体示例

你在咖啡馆连上名为 Free WiFi 的热点,它其实由攻击者架起,他把网关指向自己的机器并打开转发。你访问一个只有 http 的登录页,账号密码被他直接读走;你访问 https 站点时,若他用一张你的设备恰好信任的 CA 签出的伪造证书,而客户端又没做证书固定,他就能同时终结两侧 TLS、明文看完再重新加密转发——你看到的仍是一把正常的锁。

## 何时用与何时不用

- **该做:** TLS/HTTPS 并严格校验证书(见 [[HTTPS 与 TLS]]、[[公钥基础设施]])、HSTS 禁掉明文回落、关键域名做证书固定(pinning)、端到端加密、DNSSEC、局域网静态 ARP 绑定、远程办公走 VPN。
- **别指望:** "看到小锁就安全"(证书链与吊销状态必须真校验);指望用户点掉告警的习惯能被纠正;以为端到端加密自带身份可信——密钥指纹/安全码仍需人工核对。

## 优劣与代价

✅ 对攻击者:成本低、能窃听也能篡改、难以察觉,是性价比极高的机会型手段。
✅ 对防守方:HTTPS + HSTS + pinning 一旦铺开,可覆盖绝大多数 opportunistic 攻击。
⚠️ 防御强依赖配置正确,留一处降级路径或忽略一次告警就前功尽弃。
⚠️ 局域网层的 ARP/DNS 防护要额外基础设施配合;CA 若被误签,除 pinning 外几乎没有第二重保险。

## 与相关概念的区别

- **vs 窃听(sniffing):** 纯嗅探只读不改也不介入会话;MITM 必须居于链路中间,因此具备篡改能力。
- **vs [[SQL注入与XSS]]:** 注入打的是应用对输入的信任,MITM 打的是双方对信道与身份的信任;一个在应用内部,一个在传输链路上。
- **vs 会话劫持:** 会话劫持是拿到有效会话凭据后直接冒充,不必留在链路中;MITM 要持续居中转发。

## 常见误区

- 网站用了 HTTPS,就不可能被中间人攻击。
- 中间人攻击只能发生在同一个局域网内。
- 中间人一定会篡改内容,只偷看不算攻击。

## 面试速答

> 🎯 它不破解密码,只站到中间分别建连再转发;防线是加密加身份验证:TLS 严格校验、HSTS、证书固定、端到端加密。
