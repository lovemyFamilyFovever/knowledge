# 中间人攻击


> 📌 **导航**：本文是 **中间人攻击** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 中间人攻击(Man-in-the-Middle Attack, MITM)是攻击者秘密介入通信双方之间,分别与他们建立连接并转发(可窃听或篡改)消息,使双方误以为在直接、私密地通信,从而窃取或操纵数据的一类攻击。

**通俗类比：** 像你和朋友隔空传纸条,中间偷偷站了个人——他先收到你的纸条、看完(甚至改了)再转给朋友,朋友的回信也经他手;你俩都以为在直接对话,其实全程被这个"中间人"看着、甚至改着。

> 多义说明:MITM 是一类攻击;具体手段有 ARP 欺骗、DNS 劫持、Wi-Fi 钓鱼热点、SSL 剥离、BGP 劫持等。本文讨论原理与防护。

## 原理与机制

- **两步:**
  1. 截获/介入信道:如 ARP 欺骗把自己插入局域网、伪造 Wi-Fi 热点、DNS 劫持。
  2. 中继与篡改:分别与双方通信,转发或修改内容。
- **常见形式:** ARP 欺骗(局域网)、DNS 劫持/欺骗、恶意热点("邪恶双胞胎")、SSL 剥离(把 HTTPS 降级为 HTTP)、会话劫持。
- **本质:** 破坏"信道可信"与"对方身份可信"。

## 关键组成

| 环节 | 手段 |
|------|------|
| 信道截获 | ARP 欺骗 / DNS 劫持 / 钓鱼热点 |
| 双向中继 | 分别与双方建立连接 |
| 窃听 / 篡改 | 读取或修改转发内容 |
| 身份冒充 | 让双方误认对方 |
| SSL 剥离 | 把加密连接降级为明文 |

## 应用场景

（此处指防护手段）TLS/HTTPS + 严格的证书校验(见 [[HTTPS 与 TLS]]、[[公钥基础设施]])、证书固定(pinning)、HSTS、端到端加密、VPN、DNSSEC、静态 ARP 绑定、防钓鱼意识。

## 优点与局限

- (对攻击者)"优点":可窃听/篡改看似安全的通信,且难被察觉。
- 防御局限:依赖正确配置(证书校验/pinning);存在降级攻击(SSL strip)风险;局域网内的 ARP/DNS 防护需额外措施;用户可能忽视证书告警。

## 常见误区

- 有 HTTPS 不等于免疫:若忽略证书告警、缺少 pinning 或被降级,仍可能中招。
- MITM 不限于局域网(DNS/BGP/热点均可)。
- 中间人可"只看不改"(纯窃听),也可篡改。
- 端到端加密 + 身份验证是关键防线。
