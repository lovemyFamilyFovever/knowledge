# 密钥管理与轮换


> 📌 **导航**：本文是 **密钥管理与轮换** 词条，属于 security 术语集。归口枢纽：[[密码学基础篇]]；密钥对象本身在 [[密钥与密钥对（公钥·私钥）]]，怎么送到对端在 [[密钥交换与混合加密与数字信封]]。

## 定义

**一句话定义：** 密钥管理是密钥从生到死的全生命周期安全纪律——生成用密码学安全随机源、存储进 KMS/HSM 而非代码、分发靠协商协议、使用讲最小权限、到期定期轮换以限制泄露爆炸半径、退役彻底销毁密钥材料；绝大多数翻车事故不是算法数学被攻破，而是一把密钥被随手丢在了配置文件里。

**通俗类比：** 像公司的门禁卡体系：制卡要用正品机（安全随机源）、母卡锁在保险柜（HSM）、发卡走登记渠道（受控分发）、定期换卡密（轮换）、员工离职当天注销（销毁）——任何一环失守，全楼的门锁形同虚设。

## 为什么需要它

密钥是系统里唯一的秘密，一旦泄露，存量密文与签名能力一起沦陷，且往往无人察觉。既然"绝不泄露"无法担保，工程上只能换个假设：**假定它已经泄露**，再用管理手段把损失封顶——轮换把可用窗口压缩到几十天，最小权限把可解密的数据切到单业务，集中托管把滥用留痕变成审计日志。这也是等保、PCI-DSS 等合规框架把密钥管理单列成级的原因：它是密码学落地的组织保障，算法只是零件。

## 核心机制

| 阶段 | 要做的事 | 典型失守形态 |
|------|----------|--------------|
| 生成 | CSPRNG 高熵（如 Python secrets），或经标准 KDF 从口令派生 | 用普通随机数、低熵种子 |
| 存储 | KMS、Vault、HSM；退一步也要环境变量/独立配置 | 硬编码进仓库、散落多处配置 |
| 分发 | DH/ECDHE 协商或公钥加密封（数字信封） | IM/邮件明文传"密钥文件" |
| 使用 | 一钥一用、最小权限、内存态即用即弃 | 全公司共用一把"万能密钥" |
| 轮换 | 到期换钥，旧钥归档仅供解密历史数据 | 直接删旧钥，历史数据一起失联 |
| 销毁 | 安全擦除密钥材料并吊销授权 | 以为删掉文件就算销毁 |

- **轮换的价值在限窗口，不在换本身**：常见周期 90–365 天按敏感度定；新钥立即生效写、旧钥保留可读一段时间再退役，双读双写窗口是轮换真正的工程成本。
- **信封加密把轮换变廉价**：海量数据密钥（DEK）加密业务数据，主密钥（KEK）托管在 KMS；轮换时只滚动 DEK、不动 KEK，云端一条 enable-key-rotation 就能让 KMS 每年自动翻KEK。
- **KMS 与 HSM 守的是不同边界**：KMS 是软件服务，防的是"密钥不落你自己手里"；HSM 是硬件模块，防的是"连服务商运维也摸不到明文密钥"；企业自建 PKI 的根私钥几乎必进 HSM（见 [[公钥基础设施]]）。

## 具体示例

JWT 签发服务把签名私钥整个交进 KMS，应用只调"签发"接口、内存里再无密钥原文；头里带 kid 声明指明用哪把钥匙，公开侧 JWKS 同时列出新旧两把公钥，就得到 90 天轮换的窗口期——换钥当天旧 token 仍可验签，到期自然失效。若某把 kid 疑似泄露，凭它能把受影响时间段精确圈出来，吊销换新即止，不必全网重置。

## 何时用与何时不用

- **用**：凡密钥要长期活着（静态加密、签名、会话令牌），上线前就把生老病死写进设计；生产一律走托管 KMS/Vault，根密钥上 HSM；轮换能自动化就不留人手。
- **不用**：别把"三年没出事"当不用轮换的论据——没发现不等于没泄露；别用团队共享密码来转发达人密钥，那等于把生命周期管理退回口口相传；别拿删除文件当销毁。

## 优劣与代价

✅ 轮换把泄露的爆炸半径限制在窗口内，托管服务把最危险的保管环节外包给硬件、审计与SLA。
✅ 事件响应有据可查：kid/版本化密钥能回答"哪段时间的数据被哪把钥匙保护过"。
⚠️ 轮换不是免费的：旧数据仍可解密要求归档旧钥，双读双写增加状态与测试面。
⚠️ KMS 成为新的可用性单点：它不可用时，所有要解密的业务一起卡住，需评估降级与缓存策略。

## 与相关概念的区别

- **vs [[密钥与密钥对（公钥·私钥）]]**：那条讲密钥是什么、公私钥谁干什么；本条讲怎么管它的一生。
- **vs [[密钥交换与混合加密与数字信封]]**：那条只解"分发"一环——怎么把密钥送到对端；本条管全链。
- **vs [[加盐哈希与口令存储]]**：口令的对象是人、低熵、可重置；密钥的对象是机器、高熵、泄露即换钥吊销，两套工艺不可互抄。
- **vs [[公钥基础设施]]**：证书与公钥的信任、吊销是 PKI 的职责；私钥自身的保管与轮换是本条的职责。

## 常见误区

- 密钥放进环境变量、再给配置文件加上读写权限，就已经算密钥管理了。
- 轮换就是生成新钥替换旧钥，替换完成即可把旧钥立刻删除。
- 私钥泄露是"这把钥匙"的事，影响止于当前服务，历史密文不用担心。

## 面试速答

> 🎯 密钥管理=生/存/分/用/换/销六环节纪律：CSPRNG 生成、KMS/HSM 存储、协商或数字信封分发、一钥一用、90–365 天轮换且旧钥归档可解历史、销毁要擦材料；核心假设是"已泄露"，轮换限爆炸半径。
