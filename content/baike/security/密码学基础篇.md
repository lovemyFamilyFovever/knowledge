# 密码学基础篇

密码学是安全的核心，本篇将带你理解盐、彩虹表、密钥管理、PKI 体系等密码学基础概念，以及如何在实际项目中做好密钥管理。

---

## 盐（Salt）

**一句话定义（大白话）**
盐是一个随机字符串，在密码哈希之前与密码组合，使相同密码产生不同的哈希值。

**通俗类比（生活场景）**
像给每碗汤加不同的调料：即使两碗汤底料相同，加了不同调料后味道就不同了。攻击者即使知道"汤方"（哈希算法），也猜不出原始配方。

**具体示例（代码、命令或操作场景）**
```python
import hashlib
import os
import base64

# 不加盐：相同密码产生相同哈希（危险！）
password = "123456"
hash_lib.sha256(password.encode()).hexdigest()
# 每次都是同一个值，容易被彩虹表攻击

# 加盐哈希
def hash_password(password):
    salt = os.urandom(16)  # 生成16字节随机盐
    # PBKDF2 是推荐的密码哈希算法
    hash_value = hashlib.pbkdf2_hmac(
        'sha256',
        password.encode('utf-8'),
        salt,
        100000  # 迭代次数
    )
    # 存储格式：$算法$迭代次数$盐$哈希
    return f"pbkdf2:sha256:100000${base64.b64encode(salt).decode()}${base64.b64encode(hash_value).decode()}"

# 生成哈希
stored_hash = hash_password("123456")
print(stored_hash)
# 类似: pbkdf2:sha256:100000$abc123...$def456...

# 验证密码
def verify_password(password, stored_hash):
    parts = stored_hash.split('$')
    salt = base64.b64decode(parts[2])
    iterations = int(parts[1].split(':')[2])
    hash_value = hashlib.pbkdf2_hmac('sha256', password.encode('utf-8'), salt, iterations)
    return base64.b64encode(hash_value).decode() == parts[3]

print(verify_password("123456", stored_hash))  # True
print(verify_password("wrong", stored_hash))   # False
```

**为什么需要它（解决什么问题）**
防止彩虹表攻击：即使两个用户密码相同，加盐后存储的哈希值也不同，攻击者无法批量破解。

**与相关术语的对比和区分**
- 盐（Salt）vs 密码 Pepper：盐是随机的且公开存储，Pepper 是秘密的且不存储
- 盐 vs IV（初始化向量）：盐用于哈希，IV 用于加密
- 每个用户应该有独立的盐，不要所有用户共用一个盐

## 彩虹表（Rainbow Table）

**一句话定义（大白话）**
彩虹表是一种预计算的哈希查找表，用于快速破解常见密码的哈希值。

**通俗类比（生活场景）**
像一本答案速查手册：攻击者预先计算了大量常见密码的哈希值，拿到你的哈希后直接查表就能找到原密码。

**具体示例（代码、命令或操作场景）**
```
彩虹表工作原理：

1. 预计算阶段
   选择常见密码组合（如 123456、password、qwerty）
   计算它们的 MD5/SHA-256 哈希值
   存储到查找表中

2. 攻击阶段
   攻击者获取密码哈希
   在彩虹表中查找匹配的哈希
   找到对应的明文密码

示例彩虹表（部分）：
密码         | MD5 哈希
123456       | e10adc3949ba59abbe56e057f20f883e
password     | 5f4dcc3b5aa765d61d8327deb882cf99
qwerty       | d8578edf8458ce06fbc5bb76a58c5ca4

# 如何防御彩虹表
# 1. 使用盐（Salt）- 最有效
# 2. 使用慢哈希算法（bcrypt、Argon2）
# 3. 增加迭代次数

# 安装 passlib（推荐的密码哈希库）
pip install passlib

from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["argon2", "bcrypt"], deprecated="auto")

# 哈希密码
hashed = pwd_context.hash("123456")

# 验证密码
print(pwd_context.verify("123456", hashed))  # True
```

**为什么需要它（解决什么问题）**
彩虹表是攻击者的工具，理解它才能知道为什么要加盐和使用慢哈希算法。

**与相关术语的对比和区分**
- 彩虹表 vs 字典攻击：彩虹表是预计算，字典攻击是实时计算
- 彩虹表 vs 暴力破解：彩虹表更快，但需要预计算
- 加盐哈希完全免疫彩虹表攻击

## 密钥（Key）

**一句话定义（大白话）**
密钥是加密和解密过程中使用的秘密参数，就像保险箱的密码，知道密钥才能解密数据。

**通俗类比（生活场景）**
像你家门的钥匙：没有钥匙就打不开门，钥匙丢了谁都能进门。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.fernet import Fernet
import secrets

# 对称密钥（Fernet 自动生成）
key = Fernet.generate_key()
print(f"密钥: {key.decode()}")
# 类似: gAAAAABk...

# 从密码派生密钥
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC

password = b"my-password"
salt = os.urandom(16)
kdf = PBKDF2HMAC(
    algorithm=hashes.SHA256(),
    length=32,
    salt=salt,
    iterations=100000,
)
key = base64.urlsafe_b64encode(kdf.derive(password))

# 密钥应该安全存储，不要硬编码在代码中
# 使用环境变量或密钥管理服务
import os
key = os.environ.get('ENCRYPTION_KEY')
```

**为什么需要它（解决什么问题）**
加密解密、数字签名、身份认证。密钥是安全体系的核心，密钥泄露等于系统沦陷。

**与相关术语的对比和区分**
- 对称密钥：加密解密用同一把，速度快
- 非对称密钥对：公钥加密私钥解密，解决密钥分发问题
- 密钥 vs 密码：密钥是机器使用的，密码是人使用的

## 密钥对（Key Pair）

**一句话定义（大白话）**
密钥对是由一个公钥和一个私钥组成的配对，用于非对称加密和数字签名。

**通俗类比（生活场景）**
像信箱和钥匙：公钥是信箱的投递口（任何人都能投信），私钥是信箱的钥匙（只有你能取信）。

**具体示例（代码、命令或操作场景）**
```python
from cryptography.hazmat.primitives.asymmetric import rsa
from cryptography.hazmat.primitives import serialization

# 生成密钥对
private_key = rsa.generate_private_key(
    public_exponent=65537,
    key_size=2048
)
public_key = private_key.public_key()

# 导出私钥（需要保护！）
private_pem = private_key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.BestAvailableEncryption(b"password")
)

# 导出公钥（可以公开）
public_pem = public_key.public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo
)

print("私钥（前100字符）:")
print(private_pem.decode()[:100])
print("\n公钥:")
print(public_pem.decode())
```

**为什么需要它（解决什么问题）**
非对称加密和数字签名的基础。公钥可以安全分发，私钥必须保密。

**与相关术语的对比和区分**
- 密钥对 vs 单个密钥：密钥对用于非对称加密，单个密钥用于对称加密
- 公钥 vs 私钥：公钥可公开，私钥必须保密
- RSA 密钥对 vs ECC 密钥对：ECC 密钥更短但安全性相当

## 公钥（Public Key）

**一句话定义（大白话）**
公钥是非对称加密中可以公开分享的密钥，任何人都可以用它加密数据或验证签名。

**通俗类比（生活场景）**
像你的邮箱地址：任何人都可以给你发邮件（加密），但只有你能读（私钥解密）。

**具体示例（代码、命令或操作场景）**
```bash
# 生成 RSA 公钥
openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -pubout -out public.pem

# 查看公钥内容
cat public.pem
# -----BEGIN PUBLIC KEY-----
# MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8A...
# -----END PUBLIC KEY-----

# 用公钥加密文件
openssl rsautl -encrypt -in plaintext.txt -inkey public.pem -pubin -out encrypted.bin

# 分发公钥：可以安全地通过网络传输
scp public.pem user@server:/path/
```

```python
# Python 加载公钥
from cryptography.hazmat.primitives import serialization

with open("public.pem", "rb") as f:
    public_key = serialization.load_pem_public_key(f.read())

# 用公钥加密
encrypted = public_key.encrypt(b"secret message", padding.OAEP(...))
```

**为什么需要它（解决什么问题）**
安全地加密数据给特定接收者、验证数字签名。公钥可以自由分发，不需要安全通道。

**与相关术语的对比和区分**
- 公钥 vs 私钥：公钥可公开，私钥必须保密
- 公钥 vs 对称密钥：公钥用于非对称加密，对称密钥用于对称加密
- 公钥通常通过数字证书分发

## 私钥（Private Key）

**一句话定义（大白话）**
私钥是非对称加密中必须保密的密钥，只有私钥持有者才能解密数据或创建签名。

**通俗类比（生活场景）**
像你家门的钥匙：必须妥善保管，丢了就进不了家，被别人拿到就危险了。

**具体示例（代码、命令或操作场景）**
```bash
# 生成带密码保护的私钥
openssl genrsa -aes256 -out private.pem 2048
# 输入密码保护私钥

# 查看私钥
cat private.pem
# -----BEGIN RSA PRIVATE KEY-----
# Proc-Type: 4,ENCRYPTED
# DEK-Info: AES-256-CBC,...
# ...
# -----END RSA PRIVATE KEY-----

# 用私钥解密
openssl rsautl -decrypt -in encrypted.bin -inkey private.pem -out decrypted.txt

# 用私钥签名
openssl dgst -sha256 -sign private.pem -out signature.bin document.txt
```

```python
# Python 安全地使用私钥
from cryptography.hazmat.primitives import serialization

# 从加密文件加载私钥
with open("private.pem", "rb") as f:
    private_key = serialization.load_pem_private_key(
        f.read(),
        password=b"your-password"
    )

# 私钥应该：
# 1. 存储在安全的地方（硬件安全模块 HSM、密钥管理服务）
# 2. 不要提交到 Git 仓库
# 3. 不要硬编码在代码中
# 4. 定期轮换
```

**为什么需要它（解决什么问题）**
解密数据、创建数字签名、身份认证。私钥是安全体系的根基，泄露私钥等于系统沦陷。

**与相关术语的对比和区分**
- 私钥 vs 公钥：私钥必须保密，公钥可以公开
- 私钥 vs 对称密钥：私钥是非对称加密的一部分，对称密钥是独立的
- 私钥泄露：应立即吊销证书并重新生成密钥对

## 证书链（Certificate Chain）

**一句话定义（大白话）**
证书链是从终端证书到根证书的信任路径，每一级证书由上级证书签发，形成信任链条。

**通俗类比（生活场景）**
像身份证的验证：你出示身份证（终端证书），警察验证公安局长签发（中间CA），公安局长由省厅验证（根CA）。

**具体示例（代码、命令或操作场景）**
```
证书链结构：

根证书（Root CA）- 自签名，预装在操作系统/浏览器中
    ↓ 签发
中间证书（Intermediate CA）- 由根证书签发
    ↓ 签发
终端证书（End Entity）- 服务器/客户端证书

# 查看证书链
openssl s_client -connect example.com:443 -showcerts
# Certificate chain
#  0 s:CN = example.com
#    i:C = US, O = Let's Encrypt, CN = R3
#  1 s:C = US, O = Let's Encrypt, CN = R3
#    i:C = US, O = Internet Security Research Group, CN = ISRG Root X1

# 验证证书链
openssl verify -CAfile root.pem -untrusted intermediate.pem cert.pem
# cert.pem: OK
```

**为什么需要它（解决什么问题）**
建立信任传递：只要信任根证书，就能信任由它签发的所有证书。浏览器内置了可信根证书列表。

**与相关术语的对比和区分**
- 证书链 vs 单个证书：证书链是信任传递机制
- 根证书 vs 中间证书：根证书自签名，中间证书由上级签发
- 证书透明度（CT）：记录所有签发的证书

## PKI（Public Key Infrastructure）

**一句话定义（大白话）**
PKI 是一套基于公钥加密的安全基础设施，包括证书颁发、管理、验证、吊销等完整体系。

**通俗类比（生活场景）**
像整个身份证系统：公安局（CA）负责签发，派出所（RA）负责审核，户籍系统（CRL）负责记录吊销。

**具体示例（代码、命令或操作场景）**
```
PKI 组成部分：

1. CA（Certificate Authority）- 证书颁发机构
   签发和管理数字证书

2. RA（Registration Authority）- 注册机构
   审核证书申请者身份

3. 证书库
   存储已签发的证书

4. CRL（Certificate Revocation List）- 证书吊销列表
   记录已吊销的证书

5. OCSP（Online Certificate Status Protocol）
   在线查询证书状态

# 企业 PKI 部署
# 使用 OpenSSL 创建私有 CA
# 1. 创建 CA 证书
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout ca.key -out ca.crt -subj "/CN=My Private CA"

# 2. 用 CA 签发服务器证书
openssl req -new -newkey rsa:2048 -nodes -keyout server.key -out server.csr
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365
```

**为什么需要它（解决什么问题）**
为组织提供完整的公钥管理方案，建立内部信任体系。适用于企业、政府、金融等场景。

**与相关术语的对比和区分**
- PKI vs 单个证书：PKI 是完整体系，证书只是其中一部分
- PKI vs 信任链：PKI 包含信任链，还有管理、吊销等功能
- PKI vs 密码学：PKI 是密码学的应用，不是密码学本身

## 密钥管理（Key Management）

**一句话定义（大白话）**
密钥管理是密钥从生成到销毁整个生命周期的安全管理过程，包括生成、存储、分发、使用、轮换和销毁。

**通俗类比（生活场景）**
像公司钥匙管理：配钥匙（生成）、锁在保险柜（存储）、发放给员工（分发）、定期换锁（轮换）、离职收回（销毁）。

**具体示例（代码、命令或操作场景）**
```
密钥管理最佳实践：

1. 生成
# 使用密码学安全的随机数生成器
import secrets
key = secrets.token_bytes(32)  # 256位密钥

# 不要使用 random 模块（不安全）
# import random  # 不要用这个！

2. 存储
# 开发环境：环境变量
export ENCRYPTION_KEY="base64encodedkey..."

# 生产环境：密钥管理服务
# - AWS KMS
# - Azure Key Vault
# - HashiCorp Vault
# - 阿里云 KMS

3. 分发
# 使用密钥协商协议（如 Diffie-Hellman）
# 或通过安全通道传输

4. 轮换
# 定期更换密钥
# 自动化轮换脚本
python rotate_keys.py --service myapp --rotate

5. 销毁
# 安全删除密钥材料
# 不要只是删除文件！
```

**为什么需要它（解决什么问题）**
密钥是安全体系的核心，密钥管理不当会导致整个系统被攻破。

**与相关术语的对比和区分**
- 密钥管理 vs 密码管理：密钥管理针对机器密钥，密码管理针对用户密码
- 密钥管理 vs 证书管理：密钥管理更底层，证书管理是 PKI 的一部分
- KMS vs HSM：KMS 是软件服务，HSM 是硬件设备

## 密钥轮换（Key Rotation）

**一句话定义（大白话）**
密钥轮换是定期更换加密密钥的过程，减少密钥泄露带来的风险。

**通俗类比（生活场景）**
像定期更换门锁密码：即使密码泄露了，攻击者也只能用很短时间，下次轮换后就失效了。

**具体示例（代码、命令或操作场景）**
```python
# 自动密钥轮换示例
import datetime
import json
from pathlib import Path

class KeyRotator:
    def __init__(self, key_dir="./keys"):
        self.key_dir = Path(key_dir)
        self.key_dir.mkdir(exist_ok=True)
        self.rotation_interval = datetime.timedelta(days=90)  # 90天轮换

    def get_current_key(self):
        key_file = self.key_dir / "current_key.json"
        if key_file.exists():
            data = json.loads(key_file.read_text())
            created = datetime.datetime.fromisoformat(data["created"])
            if datetime.datetime.now() - created < self.rotation_interval:
                return data["key"]
        # 需要轮换
        return self.rotate_key()

    def rotate_key(self):
        import secrets
        new_key = secrets.token_urlsafe(32)
        key_file = self.key_dir / "current_key.json"

        # 归档旧密钥
        if key_file.exists():
            old_data = json.loads(key_file.read_text())
            archive_file = self.key_dir / f"key_{old_data['created'][:10]}.json"
            archive_file.write_text(key_file.read_text())

        # 写入新密钥
        key_file.write_text(json.dumps({
            "key": new_key,
            "created": datetime.datetime.now().isoformat()
        }))

        return new_key

# 使用
rotator = KeyRotator()
current_key = rotator.get_current_key()
```

```bash
# AWS KMS 密钥轮换
aws kms enable-key-rotation --key-id alias/my-key

# 查看轮换策略
aws kms get-key-rotation-status --key-id alias/my-key
```

**为什么需要它（解决什么问题）**
限制密钥泄露的影响范围。即使密钥被泄露，攻击者只能在轮换间隔内利用。

**与相关术语的对比和区分**
- 密钥轮换 vs 证书续期：密钥轮换更换密钥，证书续期延长有效期
- 自动轮换 vs 手动轮换：自动轮换更可靠，推荐在生产环境使用
- 轮换频率：通常 90-365 天，根据安全要求决定

## 对称密钥 vs 非对称密钥

**一句话定义（大白话）**
对称密钥加密和解密用同一把钥匙，速度快但密钥分发难；非对称密钥用公钥加密私钥解密，速度慢但解决了密钥分发问题。

**通俗类比（生活场景）**
对称密钥像两人共用一把钥匙开门；非对称密钥像信箱：任何人都能投信（公钥加密），只有主人能取信（私钥解密）。

**具体示例（代码、命令或操作场景）**
```
对比表：

特性              | 对称密钥            | 非对称密钥
加密速度          | 快（100-1000倍）    | 慢
密钥长度          | 128-256位           | 2048-4096位(RSA)/256位(ECC)
密钥分发          | 困难（需安全通道）   | 简单（公钥可公开）
典型算法          | AES, DES, 3DES     | RSA, ECC, ElGamal
使用场景          | 数据加密            | 密钥交换、数字签名
密钥数量          | n(n-1)/2个（n人通信）| 每人一对

# 实际应用：混合加密
# 1. 用非对称加密交换对称密钥
# 2. 用对称密钥加密数据
# 这就是 HTTPS 的工作原理！

from cryptography.hazmat.primitives.asymmetric import rsa
from cryptography.fernet import Fernet

# 非对称加密：传递对称密钥
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

symmetric_key = Fernet.generate_key()  # 对称密钥
encrypted_key = public_key.encrypt(symmetric_key, padding.OAEP(...))

# 对称加密：加密数据
f = Fernet(symmetric_key)
encrypted_data = f.encrypt(b"Hello, World!")
```

**为什么需要它（解决什么问题）**
理解两种密钥的优缺点才能正确选择加密方案。实际应用中通常结合使用。

**与相关术语的对比和区分**
- 对称密钥：速度快，密钥分发难
- 非对称密钥：速度慢，密钥分发简单
- 混合加密：结合两者优势，实际应用最广
- ECC vs RSA：ECC 密钥更短但安全性相当，推荐使用 ECC

## 数字证书格式（X.509）

**一句话定义（大白话）**
X.509 是数字证书的国际标准格式，定义了证书的结构和字段。

**通俗类比（生活场景）**
像身份证的统一格式：姓名、性别、出生日期、身份证号等字段都有标准位置和格式。

**具体示例（代码、命令或操作场景）**
```
X.509 证书结构：

Version           - 版本号（通常是 v3）
Serial Number     - 序列号（CA 唯一标识）
Signature Algorithm - 签名算法（如 SHA256withRSA）
Issuer            - 颁发者（CA 信息）
Validity
  - Not Before    - 生效时间
  - Not After     - 过期时间
Subject           - 主题（证书持有者信息）
Subject Public Key Info - 公钥信息
Extensions        - 扩展（v3 新增）
  - Subject Alternative Name (SAN) - 替代名称
  - Key Usage     - 密钥用途
  - Basic Constraints - 是否是 CA 证书
Signature Value   - CA 的数字签名

# 查看证书详细信息
openssl x509 -in cert.pem -text -noout

# X.509 证书格式
# PEM：Base64 编码，文本格式（-----BEGIN CERTIFICATE-----）
# DER：二进制格式
# PKCS#12 (.pfx/.p12)：包含证书和私钥的二进制格式

# 格式转换
# PEM → DER
openssl x509 -in cert.pem -outform DER -out cert.der

# DER → PEM
openssl x509 -in cert.der -inform DER -outform PEM -out cert.pem

# PEM → PKCS#12
openssl pkcs12 -export -in cert.pem -inkey key.pem -out cert.p12
```

**为什么需要它（解决什么问题）**
标准化证书格式，确保不同系统间的互操作性。几乎所有 TLS/SSL 证书都使用 X.509 格式。

**与相关术语的对比和区分**
- X.509 vs PGP：X.509 用于 TLS，PGP 用于邮件加密
- X.509 v1/v2/v3：v3 增加了扩展字段，最常用
- PEM vs DER：PEM 是文本，DER 是二进制
- PKCS#12：包含证书和私钥的打包格式
