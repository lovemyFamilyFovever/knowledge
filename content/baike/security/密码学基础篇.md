# 密码学基础篇


> 📌 **导航**：本文是 **密码学基础篇** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 密码学基础篇是"密码学基础概念"的索引枢纽：原稿盐、彩虹表、密钥、密钥对、公钥、私钥、证书链、PKI、密钥管理、轮换、对称 vs 非对称、X.509 十二节已按概念归口拆分收敛——盐与彩虹表归 [[加盐哈希与口令存储]]，密钥对象归 [[密钥与密钥对（公钥·私钥）]]，生命周期归 [[密钥管理与轮换]]，证书链/PKI/X.509 归 [[公钥基础设施]] 与 [[数字证书]]；本页只回答"哪个概念归哪条、谁是谁的证人"。

**通俗类比：** 像武馆总台的"人物名册"：谁学了哪路剑法、各在哪个房间切磋，翻名册即可对号入座；剑法口诀由各房间的秘本各自承载，这一页不复述任何一招。

## 为什么需要它

一期把十二个可独立命名的概念挤进同一文件、还垫了 367 行代码，属于"全都提、全查不到"的原料形态；而 security 子域随各分片推进已把这些概念逐步立成成熟专条或新建族条。归口收敛后，读者与 Agent 查任何一个基础概念都只需一跳：本枢纽负责的是概念间的接线图——密钥与口令谁配谁管、公钥的信任由谁背书、盐该去哈希还是加密那页找——这种"相邻概念的分界"恰恰是单条专条写不下、散篇汇编又找不齐的。

## 核心机制

先按下表定位归口，再进对应词条看机制：

| 概念族 | 归口 | 它回答什么 |
|--------|------|------------|
| 盐、彩虹表、口令存储 | [[加盐哈希与口令存储]] | 慢哈希+每人独立盐，废掉预计算与撞库 |
| 对称 vs 非对称体制 | [[对称加密与非对称加密]] | 一把快但分发难，两把慢但解分发与签名 |
| 密钥、公钥、私钥本身 | [[密钥与密钥对（公钥·私钥）]] | 派生单向，私钥是信任根 |
| 密钥生/存/分/用/换/销 | [[密钥管理与轮换]] | 假定已泄露，把爆炸半径限进窗口 |
| 证书链、CA、吊销 | [[公钥基础设施]] | 信任从根逐级接力到叶子 |
| X.509 字段与格式编码 | [[数字证书]] | 验证四关；PEM/DER/PKCS#12 互转 |
| 会话密钥怎么协商出来 | [[密钥交换与混合加密与数字信封]] | ECDHE 前向保密，混合加密分工 |
| 签名与不可否认 | [[数字签名]] | 私钥签、公钥验 |
| 按场景选算法配参数 | [[密码学实用指南]] | 参数级操作手册 |

1. **本枢纽只管"归口"，不复述机制**：原稿十二节素材全部被表格接走——盐与彩虹表两节曾按 v1.2 §2 第 4 档先行立条，如今删除改双链、由 [[加盐哈希与口令存储]] 完整承接（去重队列第 14 对已收敛）；证书链/PKI/X.509 自一期专条落成起就该双链，不再是本页的章节。
2. **最容易混的是三对术语，各有一条分界线**："密钥 vs 口令"——机器高熵参数归 [[密钥管理与轮换]]，人肉低熵凭据归 [[加盐哈希与口令存储]]；"盐 vs IV"——盐加在哈希前让同口令出不同摘要、防预计算，IV 是分组加密模式的初值、防相同明文暴露模式，一字之差跨两个领域；"公钥加密 vs 私钥加密"——公钥加密只有私钥能解，私钥签名人人可用公钥验，方向恰好相反（见 [[密钥与密钥对（公钥·私钥）]]、[[数字签名]]）。
3. **概念可以互证，归口只能有一处**：programming-languages 子域的同名概览条目 [[密码学基础]] 是 [[密码学与区块链技术指南]] 的两千尺总览（讲原语怎么组合成 TLS 与区块链），原语深化与操作纪律一律归 security 本表——第 12 对"择一归口"裁决即此，两边重叠处各自只留一句并双链对方。
4. **非对称最怕泄露、信任最需要制度化**：私钥一旦泄露只能吊销换新，止损靠 [[公钥基础设施]] 的 CRL/OCSP 与 [[密钥管理与轮换]] 的窗口控制；公钥天然可匿名发布，"这把公钥是谁的"必须由 CA 背书，否则 [[中间人攻击]] 全程接管——这正是 PKI 存在的理由。

## 具体示例

部署一个 HTTPS 站点会一次踩齐本图七格：生成密钥对（[[密钥与密钥对（公钥·私钥）]]）→ CSR 向 CA 申领 X.509 证书（[[数字证书]]）→ 中间链拼到预装根（[[公钥基础设施]]）→ 握手用 ECDHE 协商会话密钥（[[密钥交换与混合加密与数字信封]]）→ 页面数据交给对称加密（[[对称加密与非对称加密]]）→ 登录口令加盐慢哈希落库（[[加盐哈希与口令存储]]）→ 签名私钥进 KMS 并定期轮换（[[密钥管理与轮换]]）。概念各就各位，工程师要记的只有"这一步去哪一页"。

## 何时用与何时不用

- **用**：刚接触密码学、或排查"这个术语到底归谁"时，先回本页看表再进专条；给别人讲密码学基础，也以本图为大纲。
- **不用**：别在本页找参数级"选哪个算法配多少"，那是 [[密码学实用指南]] 的事；别把表里的"一句话回答"当面试论证——枢纽给的是指针与分界，深度论证一律跳转归口词条。

⚠️ 枢纽不承载细节：只读本页得到的是一跳地图，不是机制证明；考试级论证必须进专条。

## 与相关概念的区别

- **vs [[哈希算法篇]]**：那条索引"哈希一体两用"（安全原语与索引工具）；本页索引密钥、签名、证书、盐的概念族谱。
- **vs [[加密技术篇]]**：那条是算法选型枢纽（AES/RSA/国密各族）；本页是概念归口图。
- **vs [[密码学实用指南]]**：指南按场景给"用哪个、参数怎么配"；本页只答"概念归哪条"。
- **vs [[密码学基础]]**：programming-languages 侧的概览条，深化归口本页体系（第 12 对裁决）。

## 常见误区

- 来这页找"盐与彩虹表"的标题就以为要在这里学防御——防御配方在 [[加盐哈希与口令存储]]，本页只指路。
- 把 [[密码学基础]] 与本页当重复词条要删一个——概览与深化各有所归，删任何一边都会断链。
- 认为"公钥加密=更安全的加密"，于是拿公钥直接加密数据库备份——非对称只做密钥交换与签名，批量数据归对称。
