# 数字签名

## 定义

**一句话定义：** 数字签名(Digital Signature)是一种基于非对称密码学的技术:发送方用自己的私钥对消息(或其哈希)进行签名,接收方用发送方的公钥验证,从而提供数据完整性、身份认证与不可否认性。

**通俗类比：** 像盖私人印章并附防伪——你用只有自己拥有的印章(私钥)在文件上盖章,别人拿公开的印章样本(公钥)就能核验"确实是你盖的、且文件没被改";而且你事后无法抵赖说没盖过。

> 多义说明:数字签名(密码学机制)≠ 电子签名(法律概念,范围更广)≠ 手写签名的扫描图像。本文指密码学数字签名。

## 原理与机制

- **签名流程:** 发送方先计算消息哈希(如 SHA-256),再用**私钥**对哈希签名,签名随消息一起发送。
- **验证流程:** 接收方用**公钥**验证签名得到哈希,并自行计算收到消息的哈希,两者一致则通过。
- **算法基础:** 非对称算法如 RSA、DSA、ECDSA、EdDSA(Ed25519)。
- **身份绑定:** 常配合数字证书与 PKI,把公钥与签名者身份可信地绑定。
- **三大属性:** 完整性(消息被改即失效)、认证(私钥唯一对应签名者)、不可否认(仅签名者持私钥)。

## 关键组成

| 组成 | 作用 |
|------|------|
| 消息哈希 | 定长摘要,签名对象 |
| 私钥 | 仅签名者持有,用于生成签名 |
| 公钥 | 公开,用于验证签名 |
| 数字证书 / PKI | 绑定公钥与身份 |
| 签名算法 | RSA / ECDSA / Ed25519 等 |

## 应用场景

- 软件与固件签名、安全启动
- TLS/HTTPS 中的身份认证
- 电子合同、政务与票据防伪
- 区块链交易签名、代码提交签名(如 `git commit -S`)

## 优点与局限

- 优点:提供完整性、认证与不可否认;无需预先共享密钥;可第三方验证。
- 局限:安全性依赖私钥保密(泄露即失效);公钥真实性需 PKI 保障;计算开销高于对称加密;密钥与证书管理复杂。

## 常见误区

- 数字签名不是"加密消息内容":它签的是哈希,消息本身可能仍是明文(保密需另行加密)。
- "验证通过"的前提是公钥确实属于对方,否则可能被中间人冒充(需证书/PKI)。
- 数字签名 ≠ 手写签名的电子图片,后者不具备密码学保障。
