# 防火墙


> 📌 **导航**：本文是 **防火墙** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 防火墙(Firewall)是位于网络边界、依据预设安全规则对进出的数据包进行检查与过滤(允许或拒绝)的安全设备或软件,用于在可信内网与不可信外网之间建立一道访问控制屏障。

**通俗类比：** 像小区的门卫 + 门禁——按名单(规则)决定谁能进、谁能出、走哪个门(端口),把可疑或不速之客挡在外面,只放行符合规定的通行。

## 为什么需要它

内网里跑着大量从未按"对外服务"设计的主机,任何端口都可能被扫到、被利用。防火墙把"可达性"这件事收成一个集中决策点:默认不互通,只有显式声明过的流量才放行。它是纵深防御最外层的收口——成本低、覆盖广,即便上层全都做对,也需要它先把暴露面削掉一个数量级。

## 核心机制

- **包过滤(packet filtering):** 按 IP、端口、协议等头部信息过滤,无状态、不看连接上下文,快但粗。
- **状态检测(stateful inspection):** 维护连接状态表(如 TCP 握手),只放行属于已建立连接的包,因此能做到"内网可自由出、外部不可随意入"。
- **应用层 / NGFW:** 深入应用协议(如 HTTP)做深度包检测(DPI),常集成 IDS/IPS、URL 过滤与应用识别。
- **规则与策略:** 按源/目的 IP、端口、协议、方向匹配,命中即执行动作;"默认允许"风险高,推荐基线是默认拒绝(deny by default)。
- **部署形态:** 网络边界防火墙、DMZ(隔离对外服务的区域)、主机防火墙(如 iptables / Windows Defender Firewall)。

## 具体示例

一套常见规则集:入站只放行 443 到 DMZ 里的公网 Web 服务器;Web 服务器访问数据库的流量限定"源=Web 网段、目的=DB 端口",其余入站一律丢弃;出站默认拒绝,只允许内网访问 80/443 与更新的 DNS——这样即便有主机已失陷,恶意软件也很难回连控制端;而状态表让回包不必再单独开口。这套收益不来自"看懂了攻击",而来自"本来可走的路径就少"。

## 何时用与何时不用

- **该做:** 企业与家庭网络的边界防护、主机层兜底(iptables/nftables)、DMZ 隔离对外服务、限制出站流量、配合 VPN 收敛接入面。
- **别指望:** 挡住内部人员与已失陷主机之间的横向移动(边界看不见内网里的事);深查已加密流量的内容;替代 IDS/IPS、防病毒与应用安全;扛住[[分布式拒绝服务攻击]]这类容量型打击——它只减少暴露面,不吸收流量。

## 优劣与代价

✅ 集中决策、规则可审计可回溯,是性价比最高的暴露面收敛手段。
✅ 状态检测 + 默认拒绝能把"可被扫到的端口"从几百个压到个位数。
⚠️ 只对穿过边界的流量有效:加密内容看不深,内部威胁管不着。
⚠️ 规则只增不减,几年后没人敢删;一条为排障临时放开的宽规则,常常变成长期后门。

## 与相关概念的区别

- **vs IDS/IPS:** 防火墙按规则决定"该不该通",IDS 只检测告警、IPS 会阻断;后两者关心"通的内容里有没有攻击特征"。
- **vs [[网络地址转换]]:** NAT 的职责是地址与端口转换,隐藏内网只是副作用,它不做安全决策,不能当防火墙用。
- **vs [[零信任安全架构]]:** 防火墙建立在"内网可信、外网不可信"的边界假设上;零信任取消这个假设,改为每次请求都独立授权。

## 常见误区

- 装了防火墙,内网主机之间的攻击也就一并挡住了。
- 路由器开了 NAT,相当于已经有了防火墙。
- 为了方便排查问题,先把出站策略改成默认允许。

## 面试速答

> 🎯 防火墙是边界的显式可达性策略:包过滤看头部、状态检测看连接、NGFW 看应用;默认拒绝才有效,但管不了内网与加密内容。
