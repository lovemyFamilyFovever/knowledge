# 零信任安全架构


> 📌 **导航**：本文是 **零信任安全架构** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 零信任(Zero Trust)是一种安全架构原则:不因请求来自内网或已通过一次认证就给予信任,而是每次访问都基于身份、设备状态与上下文重新做授权决策,并以最小权限和微分段把默认可达性压到零。

**通俗类比：** 像机场:不是"进了航站楼就哪儿都能去",而是值机口、安检口、登机口各查一次证件与登机牌——谁也不会因为拿到过一张门票,就拥有全域通行权。

## 为什么需要它

传统边界的隐含假设是"里面的人可信",而现实把这条假设打穿了:云与移动办公让内网边界模糊,攻击者一旦通过 VPN 或钓鱼进入内部,横向移动几乎不受阻;内部误操作与失陷账号造成的损失常常大于外部突破。零信任的回应是取消位置特权——把信任从"网络位置"移到"这次请求的可验证上下文"上,同时压缩外部突破后的活动范围与内部滥用的空间。

## 核心机制

一句话主张:永不信任,始终验证。

| 传统安全 | 零信任 |
|----------|--------|
| 信任内网 | 所有请求都要验证 |
| 网络边界防护 | 微分段 |
| 一次认证 | 持续验证 |
| VPN 接入 | 随时随地安全接入 |

决策链路依次是:用户 → 身份认证(MFA)→ 设备信任评估 → 策略引擎 → 最小权限访问。三个要点:**身份与设备共同作为前提**,人对了不够,设备是否纳管、补丁是否到位同样参与判定;**策略引擎做动态授权**,按用户身份 + 设备状态 + 上下文(位置、时间、风险信号)算出这一次能访问什么;**微分段限制横向移动**,即便某处失陷可达面也已被切到最小。

## 具体示例

Google 的 BeyondCorp 是最常被引用的一版实践:把内部应用直接暴露在公网、不再依赖 VPN 接入,访问一律经过访问代理;每条请求都重新校验用户身份(强 MFA)、设备状态与上下文,授权按应用粒度给出,而不是"进了内网就能连一切"。效果是员工在任意网络都能安全办公,而设备丢失或人员离职时,只需撤掉那一处应用的授权。另一条交付路线是 SASE(安全访问服务边缘):把 SD-WAN 与 CASB / SWG / FWaaS / ZTNA 等安全能力收敛成云原生统一服务。

## 何时用与何时不用

- **收益最大:** 混合办公与云上资产多、VPN 已成瓶颈或发生过内部横向移动事故、有强合规审计要求、遗留应用能被代理包住。
- **别指望:** 用它替代边界防火墙、WAF 与补丁管理——它是原则与架构,不是某个可开启的开关;也别在资产清单与身份体系还没建好时一步到位(先做身份与设备可见性);更不是"买一套产品就自动生效"。

## 优劣与代价

✅ 取消位置特权后,外部突破不再自动换来内网通行权,横向移动与内部滥用空间同时被压缩。
✅ 访问决策集中到策略引擎,"谁在何时访问了什么"天然形成审计证据。
⚠️ 工程量集中在身份、设备可见性与应用代理化上,遗留系统往往最难纳管。
⚠️ 持续验证会伤体验(频繁 MFA 与挑战),策略写错还会把合法用户挡在门外。

## 与相关概念的区别

- **vs [[访问控制]]:** 访问控制是"决定谁能做什么"的机制本身,零信任是对这套机制的使用约束——不因网络位置豁免、每个请求都重新决策。
- **vs [[防火墙]]:** 防火墙假设内外有别、在边界过滤;零信任取消这个假设,把决策点移到每次请求上。
- **vs [[OAuth 与 JWT]]:** 令牌与协议是零信任用来表达与传递"这次是谁、带着什么凭证"的载体,原则本身不绑定具体格式。

## 常见误区

- 采购一套零信任产品,网络就自动变成零信任了。
- 实施了零信任,就不再需要防火墙和边界防护。
- 用户只要通过了 MFA,他后续的请求都可以放行。
