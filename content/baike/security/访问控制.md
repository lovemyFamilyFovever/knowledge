# 访问控制


> 📌 **导航**：本文是 **访问控制** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 访问控制(Access Control)是限制"谁(主体)能对哪些资源(客体)执行何种操作(权限)"的安全机制;它在身份认证之后决定并强制执行授权策略,保护资源不被未授权访问。

**通俗类比：** 像办公楼的门禁——先刷工牌确认你是谁(认证),再由系统判断这张工牌能进哪些房间、能做什么(授权/访问控制);普通员工进不了机房,财务只能进财务室。

> 多义说明:认证(Authentication,你是谁)与授权(Authorization,你能做什么)不同,访问控制属于授权;常见模型有 DAC、MAC、RBAC、ABAC。本文综述模型。

## 原理与机制

- **三要素:** 主体(subject,用户/进程)、客体(object,资源)、访问权限(读/写/执行)。
- **主要模型:**
  - DAC(自主访问控制):资源属主自行授权(如 Unix 文件权限 rwx)。
  - MAC(强制访问控制):系统按安全标签强制(如军用的机密/绝密级,Bell-LaPadula)。
  - RBAC(基于角色):权限赋予角色,用户被分配角色(企业常用)。
  - ABAC(基于属性):按用户/资源/环境属性动态决策(更细粒度)。
- **实施:** ACL(访问控制列表)、能力(capability)、策略引擎。

## 关键组成

| 组成 | 说明 |
|------|------|
| 主体 / 客体 / 权限 | 访问控制三要素 |
| DAC / MAC / RBAC / ABAC | 主要模型 |
| ACL | 访问控制列表 |
| 最小权限原则 | 只授予必要权限 |
| 策略执行点(PEP/PDP) | 决策与执行 |

## 应用场景

- 操作系统文件权限
- 数据库授权(GRANT)
- 应用 RBAC、云平台 IAM
- 网络 ACL / 防火墙、零信任架构

## 优点与局限

- 优点:保护资源的机密性与完整性、支撑合规、实现可控授权。
- 局限:策略配置复杂易错;粒度与复杂度需权衡;存在权限蔓延/过度授权风险;模型选择需匹配场景。

## 常见误区

- 访问控制 ≠ 认证:认证证明身份,访问控制决定权限。
- RBAC ≠ ABAC:前者基于角色,后者基于属性(更细粒度、动态)。
- 最小权限原则(只给必要权限)是关键。
- 默认应"拒绝"(deny by default)。
