# 网络安全篇


> 📌 **导航**：本文是 **网络安全篇** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 网络安全篇是"网络安全总览"的索引枢纽：原稿 HTTPS、TLS/SSL 握手、数字证书、数字签名、CA 机构、中间人攻击、XSS、CSRF、SQL 注入、DDoS、CC 攻击、WAF、CORS、CSP 十四节已按概念归口——传输信任链归 [[HTTPS 与 TLS]]·[[数字证书]]·[[公钥基础设施]]·[[数字签名]]，Web 攻击面归 [[XSS 与内容安全]]·[[注入类漏洞]]·[[CSRF与SSRF]]·[[中间人攻击]]，可用性与边界归 [[分布式拒绝服务攻击]]·[[防火墙与WAF]]·[[零信任安全架构]]，跨源读取单立 [[跨域资源共享（CORS）]]；本页只回答"哪类威胁去哪个专条"。

**通俗类比：** 像医院分诊台：挂号(威胁现象)先在此按科室分流——感染科(注入/XSS)、心内科(加密信任链)、急诊(DDoS 打瘫)、眼科(跨域 CORS)，各科诊疗方案写在各自手册里，本页只做分流、不复述任何一台手术。

## 为什么需要它

一期把十四个能独立命名的名词挤进一篇、还垫了 334 行代码与 15 段配置，属"全都提、全查不到"的原料形态；而 security/network/devops 三个子域随各分片推进，已把这些概念逐条立成成熟专条。归口收敛后查任一名词只需一跳：本枢纽负责的是三块的分界——传输加密的信任链、Web 攻击面、可用性与边界防护——这种"跨子域接线图"恰是单条专条写不下、散篇汇编又找不齐的。原稿的配置代码一律收敛，不在此复述。

## 核心机制

先按下表定位归口，再进对应词条看机制：

| 主题 | 归口 | 它回答什么 |
|------|------|------------|
| HTTPS 与 TLS/SSL 握手 | [[HTTPS 与 TLS]]、[[网络安全协议]] | 加密层怎么协商、前向保密与 1.3 提速 |
| 数字证书 / CA / PKI / 数字签名 | [[数字证书]]、[[公钥基础设施]]、[[数字签名]] | 公钥归谁、信任链怎么逐级背书 |
| 中间人攻击(MITM) | [[中间人攻击]] | 窃听/篡改原理与 HTTPS/HSTS 反制 |
| XSS 与 CSP | [[XSS 与内容安全]] | 三类脚本注入、输出编码与 CSP 兜底 |
| SQL 注入 | [[SQL注入与XSS]]、[[注入类漏洞]] | 参数化为何根治字符串拼接 |
| CSRF | [[CSRF与SSRF]] | Token + SameSite 防冒充发请求 |
| CORS / 同源策略 | [[跨域资源共享（CORS）]] | 跨源读取怎么受控放行 |
| DDoS 与 CC 攻击 | [[分布式拒绝服务攻击]]、[[DDoS攻击与防护]] | 流量/协议/应用层打点与清洗 |
| 防火墙 / WAF | [[防火墙]]、[[防火墙与WAF]] | 网络层 vs 应用层拦截分工 |

1. **传输加密是一条信任链，不是一句"上了 HTTPS"**：握手协商会话密钥见 [[HTTPS 与 TLS]]，但"这把公钥是谁的"须由 [[数字证书]] 承载、经 [[公钥基础设施]] 的根→中间→叶子逐级接力，签名方向反过来(私钥签、公钥验)见 [[数字签名]]——链上任一环松了，[[中间人攻击]] 就能全程接管；这是前六节本为一体的原因。
2. **Web 攻击面的共性是"输入当代码、请求当身份"**：SQL 注入把输入拼进查询(见 [[SQL注入与XSS]]·[[注入类漏洞]])、XSS 把响应当脚本(见 [[XSS 与内容安全]])、CSRF 借浏览器自动带 Cookie 冒充用户(见 [[CSRF与SSRF]])；根治都在语义层而非边界层，方法族概览与 OWASP Top 10 自查在 [[Web安全攻防]]。
3. **CSP 与 CORS 是一读一载两条线，各归各家**：CSP(约束页面能加载哪些资源、防 XSS 最后一道)已由 [[XSS 与内容安全]] 承载、不在本篇单立；CORS(约束哪个源能读跨源响应)库内原无归口且面试必备，故单立 [[跨域资源共享（CORS）]]——别把两者混成"一个跨域开关"。
4. **可用性与边界是纵深防御的外层**：DDoS 打网络/协议层、CC 是其应用层子型(密集打动态页/DB)，防御靠清洗+CDN+限流(见 [[分布式拒绝服务攻击]]·[[DDoS攻击与防护]]·[[网络协议层攻击与防护]])；WAF 是应用层防火墙、与网络层防火墙分工(见 [[防火墙与WAF]]·[[防火墙]])；更根本的"永不默认信任内网"见 [[零信任安全架构]]。

## 具体示例

部署一个对外 Web 服务会把本图三块一次走齐：全站 HTTPS(握手/证书/CA 信任链，见 [[HTTPS 与 TLS]]·[[数字证书]]·[[公钥基础设施]]) → 前端从另一域调 API 需服务端配 CORS 白名单(见 [[跨域资源共享（CORS）]]) → 登录与改状态接口上 CSRF Token+SameSite(见 [[CSRF与SSRF]]) → 所有外部输入参数化/输出编码并加 CSP 头(见 [[注入类漏洞]]·[[XSS 与内容安全]]) → 边缘挂 WAF、大流量靠 DDoS 清洗(见 [[防火墙与WAF]]·[[DDoS攻击与防护]])。威胁各就各位，工程师要记的只有"这类问题去哪一页"。

## 何时用与何时不用

- **用**：刚接触网络安全、或被问"这个名词归哪"时先回本页看表再进专条；给别人讲网络安全全貌，以本三块(信任链/攻击面/可用性边界)为大纲。
- **不用**：别在本页找任一攻击的 payload 或某配置的行级写法——那是各归口专条的事；枢纽给的是指针与分界，深度论证一律跳转归口词条。

## 与相关概念的区别

- **vs [[Web安全攻防]]**：那条是 L7 攻防方法论单条(骗过哪层信任)；本篇是覆盖加密信任链+可用性+跨域的总览索引，攻防只占其中一格。
- **vs [[密码学基础篇]]**：那篇索引密钥/签名/证书/哈希的概念族谱；本篇把它接进 HTTPS/TLS 场景并延伸到 Web 攻击与 DDoS。
- **vs [[零信任安全架构]]**：零信任是一种架构主张；本篇是术语归口图，只在边界防护一格指向它。

## 常见误区

- 认为网站上了 HTTPS 就同时防住了 SQL 注入、XSS 和 CSRF。
- 装了 WAF 就不必在代码里修注入漏洞，把边界拦截当银弹。
- 觉得配了 CORS 就能挡住别人直接访问我的服务器接口。

## 面试速答

> 🎯 网络安全总览的索引枢纽，四组归口：传输信任链(HTTPS/证书/CA/签名/MITM)、Web 攻击面(XSS/SQLi/CSRF)、跨域(CORS/CSP)、可用性与边界(DDoS/CC/WAF/零信任)；要点是加密只管传输、语义漏洞靠参数化与编码、跨源读取归 CORS。
