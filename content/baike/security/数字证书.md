# 数字证书

## 定义

**一句话定义：** 数字证书(Digital Certificate)是由证书颁发机构(CA)签发的、把一个公钥与其持有者身份绑定在一起的电子凭证;它包含公钥、身份信息、有效期与 CA 的数字签名,用于在开放网络中证明"某公钥确实属于某主体",是 PKI 的核心载体。

**通俗类比：** 像身份证/护照——由权威机构(公安局 / CA)签发,把你的照片(公钥)与身份绑定,并盖上防伪印章(CA 签名);别人凭公信的印章就能确认"这张证件是真的、这个人就是本人",而不必私下认识你。

> 多义说明:数字证书是 PKI 的载体,最常见格式为 X.509;有服务器证书、客户端证书、代码签名证书等。本文以 X.509 服务器证书为主。

## 原理与机制

- **证书内容(X.509):** 版本、序列号、签名算法、颁发者(Issuer)、主体(Subject)、有效期、主体公钥、扩展(如 SAN),以及 CA 的数字签名。
- **信任链:** 终端实体证书 ← 中间 CA ← 根 CA;验证方用上级公钥逐级验签,直至受信任的根。
- **验证:** 校验签名、有效期、吊销状态(CRL / OCSP)、域名匹配(SAN)。
- **签发流程:** 主体生成密钥对 → 提交 CSR(证书签名请求)→ CA 验证身份 → 签发证书。

## 关键组成

| 组成 | 作用 |
|------|------|
| 主体公钥 | 被认证绑定的公钥 |
| 主体 / 颁发者身份 | 证书归属与签发方 |
| 有效期 | 证书有效时间窗 |
| CA 签名 | 防伪与可信来源 |
| 证书链 | 终端 → 中间 → 根 |
| 吊销状态(CRL/OCSP) | 是否已作废 |

## 应用场景

- HTTPS / TLS 的服务器身份认证
- 客户端双向认证(mTLS)
- 代码与文档签名
- 邮件安全(S/MIME)、企业内部认证

## 优点与局限

- 优点:可信地绑定公钥与身份,支撑大规模安全通信,标准化程度高。
- 局限:依赖 CA 可信(被攻破则失效);有效期与续期管理;私钥保管;吊销信息传播有延迟;证书误配是常见故障源。

## 常见误区

- 数字证书 ≠ 公钥本身:证书是"公钥 + 身份 + CA 签名"的凭证。
- 证书不用于加密业务数据:它用于认证与密钥交换,加密靠其中的公钥/TLS 会话密钥。
- 过期或被吊销的证书不可信。
- 自签名证书没有第三方信任链(浏览器会告警)。
