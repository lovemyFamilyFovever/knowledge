# 分布式拒绝服务攻击


> 📌 **导航**：本文是 **分布式拒绝服务攻击** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 分布式拒绝服务攻击(Distributed Denial of Service, DDoS)是攻击者控制大量分布式机器(僵尸网络),同时向目标系统发送海量请求或流量,耗尽其带宽、连接或计算资源,使正常用户无法获得服务。

**通俗类比：** 像有人雇了成千上万人同时涌到一家小店门口堵路(甚至假意下单),真正的顾客挤不进去、店员也忙不过来,店铺瘫痪——攻击者靠"人多"压垮目标,而不是攻破门锁。

## 为什么需要它

可用性是三性里最难守的一个:机密性与完整性可以靠密码学做得很强,"扛住流量"却本质是资源对抗。DDoS 把攻击成本外部化了——用别人的机器(IoT 设备、云主机)和别人的带宽,以极低代价换取目标服务中断;它还常充当烟幕弹,在入侵或勒索的同时吸走值守人员的注意力。

## 核心机制

- **攻击链:** 攻击者 → 控制端(C&C)→ 僵尸网络(botnet,被植入木马的大量主机/IoT 设备)→ 同时打向目标。
- **流量型(带宽耗尽):** UDP Flood、ICMP Flood、反射放大攻击——借 NTP / DNS / memcached 等开放服务把小请求变成大响应回砸目标,顺带伪装源地址。
- **协议型(连接与状态耗尽):** SYN Flood 占满半连接队列、连接数耗尽,目标资源在"还没建立完会话"时就被吃掉。
- **应用型(L7):** HTTP Flood、慢速攻击(Slowloris 长期占住连接)、CC 攻击,请求长得像真人。
- **共同特征:** 源地址可伪造、分布式发起;越靠近上层越像正常流量,识别越难。

## 具体示例

反射放大:攻击者把源 IP 伪造成受害者地址,向开放的 memcached 服务发出很小的请求,服务把远大于请求的响应回砸给受害者——放大可达几个数量级,而且"发起方"根本不是攻击者。L7 一侧:Slowloris 只发送半截 HTTP 头、再周期性地续上一行,每个连接都合法但永不结束,几千个就占满服务器连接池,而总流量看起来毫不起眼。

## 何时用与何时不用

- **该做:** CDN 与 Anycast 摊薄流量、上游流量清洗(scrubbing)、黑洞路由(blackhole)兜底、SYN Cookie、限流与验证码挑战、WAF、弹性扩容,并提前与上游运营商建立联动。
- **别指望:** 只靠加大服务器与带宽配置扛流量型攻击(必须在上游清洗);靠"识别异常流量"抓 L7(酷似真实用户);事后才去找清洗服务商——防护容量要提前备好。

## 优劣与代价

✅ 防线可分层叠加且偏被动:CDN/Anycast 摊薄 + 清洗吸收大流量,日常开销可控。
✅ SYN Cookie、限流这类机制不必先判断"谁是坏人"就能自保,误伤面小。
⚠️ 大带宽型只能靠上游,成本随峰值走;弹性扩容本身可能被对手打成天价账单。
⚠️ L7/CC 与真实流量难以区分,挑战做得太严会挡住真用户;IoT 僵尸网络的规模仍在扩大。

## 与相关概念的区别

- **vs DoS:** DoS 由单点发起,DDoS 借分布式资源,封堵与溯源难度不在一个量级。
- **vs CC 攻击:** CC 是 L7 应用型 DDoS 的一种,打的是应用与后端逻辑,而不是带宽。
- **vs [[Web安全攻防]]:** 那类漏洞靠骗过信任来读数据、改数据;DDoS 不关心数据内容,目标就是把服务打停,因此通常不算入侵。

## 常见误区

- DDoS 的目的是入侵系统或窃取数据。
- 把服务器和带宽升级得足够大,就不怕 DDoS 了。
- DDoS 和 CC 攻击是同一回事。

## 面试速答

> 🎯 DDoS 目标是可用性而非数据:分流量型、协议型、L7 三档;防线靠上游清洗与 CDN 摊薄,再配限流和 SYN Cookie。
