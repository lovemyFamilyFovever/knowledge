# SQL注入与XSS

## 定义

**一句话定义：** SQL 注入与 XSS(跨站脚本)是两种最常见的 Web 应用攻击——SQL 注入把恶意 SQL 拼入输入以操纵后端数据库;XSS 把恶意脚本注入页面、在其他用户浏览器中执行以窃取会话或篡改页面;二者根源都是"未经验证/转义的用户输入被当作代码执行"。

**通俗类比：** SQL 注入像你在"姓名"栏不只写名字,还夹带一句"顺便把保险柜打开"的指令,系统若照单全收就中招;XSS 像在公告板贴了一张"会自己动的告示",谁看公告板谁就被这段脚本执行(如偷走登录状态)。

> 多义说明:二者是不同攻击(注入攻击数据库、XSS 攻击浏览器用户),但都属"注入类"漏洞——代码与数据未分离。本文并列讲解。

## 原理与机制

- **SQL 注入:** 应用把用户输入直接拼接进 SQL(如 `WHERE name='" + input + "'"`),输入含 `' OR '1'='1` 等即改变语义;类型有联合查询注入、报错注入、盲注、时间盲注。
- **XSS:** 分存储型(恶意脚本存入服务端,他人访问时触发)、反射型(脚本在请求参数中被即时反射执行)、DOM 型(前端 DOM 操作不当)。
- **共同根因:** 数据与代码未分离、缺乏输入验证与输出编码。

## 关键组成

| 要素 | 说明 |
|------|------|
| 注入点 | 拼接用户输入的位置 |
| SQL 拼接 vs 参数化 | 漏洞根源与安全写法 |
| XSS 三型 | 存储 / 反射 / DOM |
| 输出编码 | 按上下文(HTML/JS/URL)转义 |
| CSP | 内容安全策略,限制脚本来源 |

## 应用场景

（此处指防护手段）参数化查询/预编译语句(防 SQL 注入)、输入校验、按上下文输出转义/编码、Content Security Policy(CSP)、HttpOnly Cookie、数据库账号最小权限、使用 ORM。

## 优点与局限

- (防护)优点:从根本上分离代码与数据,有效抵御注入类攻击。
- 局限:需全链路一致执行(一处遗漏即成漏洞);旧代码改造成本高;CSP 配置复杂;二阶注入等变体防不胜防。

## 常见误区

- 靠"转义/过滤关键词"不可靠,应使用参数化查询。
- XSS 不只是"弹窗炫技",可窃取会话与凭据。
- 前端校验不能替代后端校验。
- 存储型 XSS 危害最大(影响所有访问者);仅靠 WAF 不够,需代码层修复。
