# 公钥基础设施

## 定义

**一句话定义：** 公钥基础设施(Public Key Infrastructure, PKI)是一套通过数字证书与证书颁发机构(CA)来创建、管理、分发、使用、存储与撤销公钥的体系,用于在开放网络中把公钥与其持有者身份**可信地绑定**,从而支撑加密、签名与认证。

**通俗类比：** 像身份证与公安系统——公安局(CA)给你签发身份证(数字证书),把你的相貌(公钥)与身份绑定;别人凭公信的公安局印章(CA 签名)就能确认"这个公钥确实属于你",即便从不曾私下认识你。

> 多义说明:PKI 是整套**体系/基础设施**,数字证书是其中的载体;本文讨论整体。

## 原理与机制

- **信任链模型:** 依赖方信任根 CA → 根 CA 签发中间 CA → 中间 CA 签发终端实体证书,形成证书链(chain)。
- **数字证书:** 包含公钥、主体身份、有效期、签发者,以及 CA 对以上内容的数字签名(常用 X.509 格式)。
- **验证:** 用上级 CA 的公钥逐级验证证书签名、有效期与吊销状态,直至可信根。
- **吊销:** 通过 CRL(证书吊销列表)或 OCSP(在线证书状态协议)查询证书是否已失效。

## 关键组成

| 组成 | 作用 |
|------|------|
| 证书颁发机构(CA) | 签发并背书证书 |
| 注册机构(RA) | 审核证书申请主体身份 |
| 数字证书(X.509) | 绑定公钥与身份 |
| 证书链 | 从终端实体到可信根 |
| 吊销机制(CRL/OCSP) | 发布/查询失效证书 |

## 应用场景

- HTTPS / TLS 网站身份认证
- 代码与文档签名、安全启动
- 企业内网认证、VPN、S/MIME 邮件安全
- 物联网设备身份与双向认证

## 优点与局限

- 优点:解决公钥分发与身份绑定的信任问题,支撑大规模安全通信,标准化程度高。
- 局限:安全性依赖 CA 可信(CA 被攻破则体系失效);证书管理与续期复杂;吊销信息传播有延迟;对私钥保管要求高。

## 常见误区

- PKI ≠ 单个证书:它是包含 CA、证书、吊销、策略等的整套体系。
- HTTPS 安全依赖 PKI,但 PKI 的用途远不止 Web。
- "有证书"不等于"可信":必须验证证书链与吊销状态。
- CA 是信任根,其私钥与运营安全至关重要。
