# 缓冲区溢出

## 定义

**一句话定义：** 缓冲区溢出(Buffer Overflow)是一类常见软件漏洞:程序向固定大小的缓冲区写入的数据超出其容量,溢出部分覆盖了相邻内存(如返回地址、其他变量),轻则程序崩溃,重则被攻击者利用来执行任意代码。

**通俗类比：** 像往一个固定容量的杯子里倒水,水满了还继续倒,溢出的水流到旁边桌面上,把桌上其他东西(相邻内存,比如"程序下一步该去哪"的返回地址)泡坏或篡改了。

> 多义说明:分栈溢出(stack overflow,覆盖返回地址)与堆溢出(heap overflow);常见于不做边界检查的语言(C/C++)。本文讨论原理与防护。

## 原理与机制

- **成因:** 使用不检查边界的函数(如 C 的 `strcpy` / `sprintf` / `gets`)向缓冲区写入超长数据。
- **栈溢出利用:** 覆盖函数返回地址,使其指向攻击者植入的恶意代码(shellcode)或已有代码片段,从而劫持控制流。
- **堆溢出:** 覆盖堆上相邻数据结构,篡改指针或元数据。
- **危害:** 程序崩溃、任意代码执行、提权、信息泄露。

## 关键组成

| 组成 | 说明 |
|------|------|
| 缓冲区 | 固定大小的内存区 |
| 越界写入 | 超出容量的写操作 |
| 返回地址覆盖 | 劫持控制流的关键 |
| shellcode | 攻击者植入的恶意代码 |
| 栈 / 堆溢出 | 两种主要类型 |

## 应用场景

（此处指防护手段）使用安全函数(`strncpy`/`snprintf`)、边界检查、栈保护(canary/栈哨兵)、DEP/NX(数据不可执行)、ASLR(地址空间随机化)、控制流完整性(CFI)、采用内存安全语言(如 Rust)。

## 优点与局限

- (防护)优点:多层防御显著降低被利用的成功率。
- 局限:遗留 C/C++ 代码量庞大;防护并非万能(绕过手法不断演进);有一定性能/兼容开销;需全栈配合。

## 常见误区

- 缓冲区溢出不只导致崩溃,可被利用执行任意代码。
- 不只是栈,堆同样会溢出。
- 现代防护(DEP/ASLR/canary)提高了利用门槛,但未根除问题。
- Java/Python 等高级语言有边界检查,但仍可能存在其他越界问题。
