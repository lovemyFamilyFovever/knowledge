# 缓冲区溢出


> 📌 **导航**：本文是 **缓冲区溢出** 词条，属于 security 术语集。相关枢纽：[[公钥基础设施]]、[[密码学基础篇]]、[[零信任安全架构]]。

## 定义

**一句话定义：** 缓冲区溢出(Buffer Overflow)是一类常见软件漏洞:程序向固定大小的缓冲区写入的数据超出其容量,溢出部分覆盖了相邻内存(如返回地址、其他变量),轻则程序崩溃,重则被攻击者利用来执行任意代码。

**通俗类比：** 像往一个固定容量的杯子里倒水,水满了还继续倒,溢出的水流到旁边桌面上,把桌上其他东西(相邻内存,比如"程序下一步该去哪"的返回地址)泡坏或篡改了。

## 为什么需要它

C/C++ 把内存布局的控制权交给程序员,换取性能与底层能力,代价是"写入越界"没有任何运行时检查会拦下来。而一次越界写远不只是崩溃:返回地址就是躺在栈上的普通数据,能改它就能改程序下一步去哪。这类漏洞三十年来经久不衰,是操作系统与固件里最稳定的远程代码执行来源,也正因为如此,现代缓解机制几乎都围着它演进。

## 核心机制

- **成因:** 使用不检查边界的函数(如 C 的 `strcpy` / `sprintf` / `gets`)向固定大小的缓冲区写入超长数据。
- **栈溢出利用:** 覆盖函数返回地址,使其指向攻击者植入的 shellcode 或程序里已有的代码片段,从而劫持控制流。
- **堆溢出:** 覆盖堆上相邻数据结构,篡改指针或分配器元数据,进一步谋求任意写原语。
- **危害:** 程序崩溃、任意代码执行、提权、信息泄露。

## 具体示例

函数里 `char buf[8]` 配一次 `gets(buf)`:输入 20 个 A,头 8 个落进缓冲区,余下的把保存的帧指针与返回地址一并覆盖成攻击者选定的地址,函数 return 时就跳去执行注入的代码。对应的四道拦截各管一步:canary 在返回地址前放一个随机哨兵值,函数返回前检查它有没有被动过;DEP/NX 把栈标成不可执行,代码落地也跑不起来;ASLR 让地址每次都不一样,预先算好的跳转目标失效;CFI 校验间接跳转是否落在合法目标集合内。

## 何时用与何时不用

- **该做:** 边界检查与安全的字符串/内存函数(`strncpy` / `snprintf`;注意 `strncpy` 不保证以 `\0` 结尾);编译与运行期默认开启栈保护(canary/栈哨兵)、DEP/NX(数据不可执行)、ASLR(地址空间随机化)与控制流完整性(CFI);不可信解析放进沙箱或独立进程并施以最小权限。
- **别指望:** 只靠其中一层(canary 可被信息泄露绕过、ASLR 可被泄露破解);给遗留代码贴补丁而不改越界逻辑;把"换成了安全函数"当免检,长度算错一样越界。

## 优劣与代价

✅ 多层防御彼此独立,叠加后"单点绕过"不再等于"利用成功"。
✅ canary/DEP/ASLR 编译器一键开启,几乎零改造即可覆盖海量遗留代码。
⚠️ 缓解不是根治:利用手法持续演进,一处信息泄露就能把 ASLR 拉平。
⚠️ 存在性能与兼容性开销;遗留 C/C++ 体量庞大,彻底改造要 OS、编译器、应用全栈配合。

## 与相关概念的区别

- **栈溢出 vs 堆溢出:** 前者改写返回地址直接劫持控制流,后者篡改堆元数据或相邻对象,通常先求一个任意写原语。
- **vs 越界读(out-of-bounds read):** 读越界泄露内存内容(如 Heartbleed),写越界才谈得上执行代码;两者同属 CWE-119 家族但目标不同。
- **vs [[SQL注入与XSS]]:** 注入劫持的是解释器对"数据/代码"的区分,缓冲区溢出劫持的是内存布局;一个在应用语义层,一个在机器层。

## 常见误区

- 缓冲区溢出最坏也就是让程序崩一下,重启就好。
- 开了 DEP/ASLR/canary,就不存在缓冲区溢出漏洞了。
- 用 Java/Python 这类有边界检查的语言,就完全不会有越界问题。

## 面试速答

> 🎯 越界写覆盖相邻内存,改掉返回地址就劫持了控制流;canary 防改写、DEP 防执行、ASLR 防定位,叠加但不根治。
