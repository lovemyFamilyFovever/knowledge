# 无障碍访问

## 定义

**一句话定义：** 无障碍访问(Accessibility,常缩写 a11y)指让包括残障人士(视觉、听觉、运动、认知障碍)在内的所有人,都能感知、理解、导航并操作数字产品与物理环境的设计实践与技术。

**通俗类比：** 建筑入口除了台阶还修一条坡道,坐轮椅的人、推婴儿车的人、拉行李箱的人都能进——数字无障碍就是给软件"修坡道",让不同能力的人都能平等使用。

> 命名说明:a11y 是 "a" + 中间 11 个字母 + "y" 的数字缩写(numeronym),与 i18n(国际化)、l10n(本地化)同理。

## 原理与机制

Web 无障碍以 **WCAG(Web Content Accessibility Guidelines)** 为核心,围绕四大原则 **POUR**:

- **Perceivable(可感知):** 信息能被感官接收(如图片提供替代文本 alt、视频配字幕)。
- **Operable(可操作):** 界面可被操作(如纯键盘可达、无焦点陷阱、足够操作时间)。
- **Understandable(可理解):** 内容与操作可预测(清晰语言、一致导航、错误提示)。
- **Robust(健壮):** 兼容各类辅助技术(语义化 HTML、正确的 ARIA 角色与状态)。

辅助技术(屏幕阅读器、放大镜、语音输入、开关扫描)依赖正确的语义与可访问性树(accessibility tree)。

## 关键组成

| 技术手段 | 作用 |
|----------|------|
| 语义化 HTML | 让辅助技术正确理解结构(标题、列表、按钮) |
| ARIA(角色/属性/状态) | 在原生语义不足时补充可访问性信息 |
| 替代文本(alt) | 为图像提供文本等价物 |
| 键盘可达性 | 保证无鼠标也能完成全部操作 |
| 颜色对比度 | 满足最低对比比值,保障低视力可读 |

## 应用场景

- 政府/公共服务与教育网站(常有法规强制要求)
- 电商、金融等面向大众的产品
- 移动 App 与操作系统(旁白、TalkBack)
- 企业内部工具的合规与包容性设计

## 优点与局限

- 优点:扩大用户覆盖、满足法律合规、提升整体可用性与 SEO、体现社会责任。
- 局限:实现与维护有成本;ARIA 误用反而制造障碍;自动化检测只能覆盖部分问题,仍需人工与真实辅助技术测试。

## 常见误区

- 认为"加了 alt 就算无障碍":无障碍是系统工程,涵盖键盘、对比度、焦点、语义等。
- 过度依赖 ARIA:首要原则是"能用原生语义元素就不要用 ARIA"(No ARIA is better than bad ARIA)。
- 只靠自动化工具打分:自动化通常只能发现约一部分问题,需结合人工评估。
