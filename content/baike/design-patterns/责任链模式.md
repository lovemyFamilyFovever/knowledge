# 责任链模式

> 📌 **导航**：本文是 **责任链模式** 词条，属 [[行为型模式（Behavioral Patterns）]] 子词条。

## 定义

**一句话定义：** 责任链模式让多个对象都有机会处理请求，从而解耦请求的发送者与接收者；把这些对象连成一条链，沿链传递请求，直到有对象处理它。

**通俗类比：** 报销审批——组长→部门经理→总监→CFO，金额小的组长批了即可，金额大的一路往上，直到有人有权处理。

## 为什么需要它

一个请求该由谁处理，常常在发出时并不确定，且处理规则会增删调整。若发送者硬编码"if 类型A 就调 B"，就和每个处理者耦合。责任链把处理者串成链，发送者只管把请求丢进链头，具体谁处理、链的组成都可动态调整。

## 核心机制

- **Handler**：声明 `handle`，并持有下一个处理者引用。
- **ConcreteHandler**：能处理则处理，否则 `pass_to_next` 转发给后继。
- **Client**：组装链并发起请求。
- 变体：有的链"一个处理即终止"，有的链"每个节点都过一遍再往下"（如中间件）。

## 具体示例

每个处理者判断能否处理，否则转发后继，支持链式组装：

```python
class Handler:
    def set_next(self, h): self._next = h; return h
    def handle(self, amt):
        if amt <= self.limit: return f"{self.name} 审批 {amt}"
        return self._next.handle(amt) if self._next else "无人处理"
chain = Leader().set_next(Manager()).set_next(CFO())
chain.handle(5000)
```

## 何时用与何时不用

- **用**：Web 中间件（Express/Koa/Gin 的 `next()`）、Servlet Filter、审批流、异常/事件处理链、日志分级。
- **不用**：处理者固定、逻辑简单时直连即可；链过长会影响性能与可观测性。

## 优劣与代价

✅ 发送者与接收者解耦、链可动态增删重排、每个处理者职责单一、符合开闭。
⚠️ 请求可能传到链尾仍未被处理（需兜底）；链过长影响性能与调试。

## 与相关概念的区别

- **责任链 vs 中介者**（[[中介者模式]]）：责任链是请求沿链**顺序传递**直到被处理；中介者是中心节点**协调**多个同僚。
- **责任链 vs 命令模式**（[[命令模式]]）：命令封装"做什么"，责任链决定"谁来处理"。

## 常见误区

- 责任链一定保证每个请求最终都被某个节点处理。
- 责任链和中间件没有任何关系，是两码事。
- 链上每个节点都必须自己处理请求，不能选择转发给下一个。

## 面试速答

> 🎯 责任链 = 把可处理请求的对象串成链，请求沿链传递直到被某节点处理（或到链尾兜底），解耦发送者与接收者、链可动态增删。典型：Web 中间件 next()、审批流、异常处理链。注意"可能无人处理"要有默认处理者。
