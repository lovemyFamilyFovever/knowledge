# 组合模式

> 📌 **导航**：本文是 **组合模式** 词条，属 [[结构型模式（Structural Patterns）]] 子词条。

## 定义

**一句话定义：** 组合模式把对象组合成树形结构来表示"部分—整体"的层次，使客户端对单个对象（叶子）和组合对象（容器）的使用保持一致。

**通俗类比：** 公司组织架构——CEO 下辖部门、部门下辖员工。下发通知时，既可发给整个部门（容器，递归往下传），也可发给单个员工（叶子），调用方式完全一样。

## 为什么需要它

处理树状数据（文件系统、UI 组件树、菜单、组织架构）时，"单个元素"和"一组元素"往往要做同样的操作。若客户端要区分叶子和容器、分别写分支，代码就冗长难扩展。组合模式让二者共享同一抽象接口，客户端用统一方式递归处理，新增节点符合开闭。

## 核心机制

- **Component（抽象构件）**：声明叶子与容器的公共接口。
- **Leaf（叶子）**：无子节点，直接实现业务方法。
- **Composite（容器）**：持有子构件集合，实现 add/remove，并把操作递归委派给子节点。
- 两种风格：**透明式**把 add/remove 放到 Component（叶子需空实现或抛异常）；**安全式**只放在 Composite（客户端需区分类型）。二者在"接口统一"与"类型安全"间取舍。

## 具体示例

Employee（叶子）与 Department（容器）同属 Component，`show` 递归委派，客户端无需区分：

```python
class Employee(Component):            # Leaf
    def show(self, indent=0): print("  "*indent + f"员工: {self.name}")

class Department(Component):          # Composite
    def __init__(self, name): self.children = []
    def add(self, c): self.children.append(c)
    def show(self, indent=0):
        print("  "*indent + f"部门: {self.name}")
        for c in self.children: c.show(indent+1)   # 递归
```

## 何时用与何时不用

- **用**：对象天然呈"部分—整体"树形层次，且希望客户端忽略叶子与容器的差异统一处理。
- **不用**：层次不明显或各构件差异很大时，强行统一接口会牵强、反而更难懂。

## 优劣与代价

✅ 统一叶子与容器的调用、天然递归、新增节点符合开闭。
✅ 客户端用多态遍历任意深度的组合结构。
⚠️ 设计偏抽象；叶子与容器差异大时公共接口会显得别扭。
⚠️ 透明式牺牲类型安全、安全式牺牲调用统一，需权衡。

## 与相关概念的区别

- **组合 vs 装饰器**（[[装饰器模式]]）：组合是"一对多的部分—整体树"、结构递归；装饰器是"一对一层层包裹"、动态加职责。
- **组合 vs 享元**（[[享元模式]]）：组合关注整体/部分的层次一致处理；享元关注共享细粒度对象省内存，常与组合共用叶子。
- 组合常与**迭代器**（[[行为型模式（Behavioral Patterns）]]）配合遍历对象结构。

## 常见误区

- 组合模式就是在一个类里放一个 List 集合。
- 透明式和安全式没有区别，随便选一种即可。
- 用了组合模式后客户端就不用再关心容器与叶子的差异，因此永远不需要类型判断。

## 面试速答

> 🎯 组合 = 用树形结构表达"部分—整体"，让叶子与容器共享同一 Component 接口，客户端以一致方式递归处理。透明式统一接口、安全式类型安全，二者取舍。适合文件树/UI 组件/组织架构。
