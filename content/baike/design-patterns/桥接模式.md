# 桥接模式

> 📌 **导航**：本文是 **桥接模式** 词条，属 [[结构型模式（Structural Patterns）]] 子词条。

## 定义

**一句话定义：** 桥接模式把抽象部分与其实现部分分离，使两者可以独立变化，用组合（一座"桥"）替代继承把两个层次连接起来。

**通俗类比：** 遥控器与电视是两个独立变化的维度——万能遥控可配小米电视、小米遥控也可配三星电视，二者靠"红外/蓝牙"这座桥连接，各自升级互不影响，不必为每种组合造一个型号。

## 为什么需要它

当一个类同时在两个（或多个）维度上扩展，用继承会造成"类爆炸"：M 种形状 × N 种颜色 = M×N 个子类。桥接把两个维度拆成两条独立的类层次，抽象持有一个指向实现的引用，用 M+N 个类替代 M×N，且能在运行时切换实现。

## 核心机制

- **Abstraction（抽象）**：高层接口，持有对 Implementor 的引用。
- **RefinedAbstraction（扩充抽象）**：扩展抽象的行为。
- **Implementor（实现接口）**：定义底层实现抽象。
- **ConcreteImplementor（具体实现）**：实现 Implementor。
抽象与实现各自独立扩展，靠"抽象持有实现引用"这座桥在运行期组合。

## 具体示例

形状（抽象）与颜色（实现）两条层次分离，一个 Shape 持有一个 Color，自由组合：

```python
class Color:                    # Implementor
    def fill(self): ...
class Red(Color):
    def fill(self): return "红色"
class Shape:                    # Abstraction：持实现的引用＝桥
    def __init__(self, color): self.color = color
    def draw(self): return f"画一个{self.color.fill()}的图形"
```

## 何时用与何时不用

- **用**：一个类存在多个独立变化的维度且都要扩展（形状×颜色、平台×功能、消息类型×发送方式）；不想用继承导致类爆炸；需要在运行时切换实现。
- **不用**：只有一个维度、或抽象与实现本就一一对应时，桥接属于过度设计；它要求你在设计期就正确识别出"两个正交维度"。

## 优劣与代价

✅ 抽象与实现解耦、各自独立扩展；用 M+N 类替代 M×N。
✅ 实现细节对客户隐藏，可在运行时替换实现。
⚠️ 需要事前识别出独立维度，对单一维度的简单类是过度设计。
⚠️ 增加一层抽象，理解成本上升。

## 与相关概念的区别

- **桥接 vs 适配器**（[[适配器模式]]）：桥接是**设计期**主动分离两个维度以备各自演化；适配器是**事后**弥补已存在的不兼容接口。
- **桥接 vs 策略模式**（[[行为型模式（Behavioral Patterns）]]）：结构相似（都靠组合委托），但桥接针对"抽象与实现"两层次独立变化，策略针对"可互换的算法"。

## 常见误区

- 桥接模式适合任何继承层级过深的类，用它准没错。
- 桥接和适配器都是转换接口，可以互相替代。
- 用了桥接就一定能在编译期消除所有耦合。

## 面试速答

> 🎯 桥接 = 把"抽象"与"实现"两个独立变化的维度分离，用抽象持有实现引用的组合代替多层继承，把 M×N 个类降为 M+N，并可运行时换实现。与适配器区别：桥接在设计期解耦、适配器在事后弥补。
