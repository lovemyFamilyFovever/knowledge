# 代理模式

> 📌 **导航**：本文是 **代理模式** 词条，属 [[结构型模式（Structural Patterns）]] 子词条。

## 定义

**一句话定义：** 代理模式为目标对象提供一个替身（代理），由代理控制对目标的访问，并可在访问前后附加额外处理。

**通俗类比：** 房产中介——房东把房子委托给中介，租客不直接接触房东；中介代为带看、签约、收租，还能在其中核验资质、记录流水。

## 为什么需要它

有时不能（或不该）让客户端直接操作真实对象：大对象想用到时才加载、敏感操作要先鉴权、跨进程调用要屏蔽网络细节、方法调用要织入日志/事务。代理在客户端与真实对象之间插一层，把"是否/何时/以何权限访问、前后做什么"的控制集中，而不污染业务类本身。

## 核心机制

- **Subject**：声明真实对象与代理的共同接口（二者可互换）。
- **RealSubject**：被代理的真实对象。
- **Proxy**：持有对 RealSubject 的引用，实现 Subject，在转调前后加入控制逻辑。
按用途分：远程代理（RPC 存根）、虚拟代理（延迟加载）、保护代理（权限）、缓存代理、日志 / AOP 代理、智能引用。按实现分见下方对比。

## 具体示例

虚拟代理把"昂贵的真实对象"推迟到首次真正使用才创建：

```python
class ProxyImage(Image):                 # 与 RealImage 实现同一 Subject
    def __init__(self, fn): self.fn, self._real = fn, None
    def display(self):
        if self._real is None:           # 延迟：首次调用才加载
            self._real = RealImage(self.fn)
        self._real.display()
```

## 何时用与何时不用

- **用**：需要延迟加载大对象、访问前鉴权、结果缓存、跨进程 RPC 存根、或为方法织入日志/事务等横切逻辑（Spring AOP）。
- **不用**：客户端可直接、廉价地使用真实对象且无访问控制诉求时，多加一层代理只增开销。

## 优劣与代价

✅ 不改真实对象即可控制访问、增强功能，解耦调用方与真实对象。
✅ 支持延迟加载与横切关注点集中。
⚠️ 类数量增多、多一层转发可能变慢。
⚠️ 动态代理有运行时开销与调试难度。

## 与相关概念的区别

- **代理 vs 装饰器**（[[装饰器模式]]）：结构几乎相同，意图相反——代理**控制对目标的访问**，装饰器**增强功能且不改接口**。
- **代理 vs 适配器**（[[适配器模式]]）：代理一般保持被代理对象的接口（可替换），适配器则改变接口。

| 实现 | 方式 | 是否需要接口 | 局限 |
|---|---|---|---|
| 静态代理 | 手写代理类 | 需要共同接口 | 每种代理手写、冗长 |
| JDK 动态代理 | 反射 `java.lang.reflect.Proxy` | 必须有接口 | 无接口时不可用 |
| CGLIB 代理 | 生成目标子类 | 不需要接口 | 不能代理 final 类/方法 |

## 常见误区

- 代理和装饰器结构几乎一样，所以它俩的意图也一样。
- JDK 动态代理能代理任意类，完全不需要接口。
- CGLIB 通过生成子类实现，因此 final 类、final 方法也能被代理。
