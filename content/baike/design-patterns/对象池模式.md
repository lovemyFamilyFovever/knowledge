# 对象池模式

> 📌 **导航**：本文是 **对象池模式** 词条，属 [[创建型模式（Creational Patterns）]] 子词条。**注意：对象池不属于 GoF 23 种模式**，是工程实践中补充的创建型模式（确切出处建议人工核验）。

## 定义

**一句话定义：** 对象池模式预先创建一批可复用对象放入"池"中循环借用与归还，用复用代替反复的创建 / 销毁，以降低昂贵对象带来的开销。

**通俗类比：** 共享单车——不必每次出行都买一辆新车，用完还到指定点位、下一个人接着骑；只有车全被借走时运营方才补新车。对象池就是这批可循环借还的车。

## 为什么需要它

数据库连接、TCP 连接、线程、文件句柄这类对象创建 / 销毁成本高，且下游往往有连接数上限。高频申请时若每次都新建再销毁，既慢又可能把后端压垮。池把这些昂贵对象提前备好、受控数量地借还，复用摊薄创建成本、同时用上限保护下游。

## 核心机制

- **Pool**：维护空闲对象集合，提供 `acquire()` / `release()`，负责初始化、上限、回收与失效处理。
- **PooledObject**：被池化的资源，归还时通常要重置状态。
- **Client**：借用 → 使用 → 归还，且不得继续使用已归还对象的引用。
- 生产级池还要处理池耗尽策略（阻塞 / 超时 / 抛错）、借出前探活、空闲回收与最大生命周期、并发安全——手写易错，通常直接用成熟实现（HikariCP、Apache Commons Pool）。

## 具体示例

借还务必成对、归还放进 `finally`，避免异常路径泄漏：

```python
pool = ObjectPool(creator=make_conn, max_size=5)
conn = pool.acquire()          # 借（池空时可阻塞/超时）
try:
    ...                         # 用
finally:
    pool.release(conn)         # 还（归还前应重置状态）
```

## 何时用与何时不用

- **用**：创建 / 销毁昂贵、需受控上限保护后端、且对象可安全复用的重量级资源（连接、线程、缓冲区）。
- **不用**：轻量、短命的小对象——在带高效 GC 的语言里，池化的簿记开销与内存常驻往往比直接 new 更慢，属反模式。

## 优劣与代价

✅ 显著降低昂贵对象的创建 / 销毁开销，提升吞吐、减小延迟抖动。
✅ 用池上限约束并发用量，保护下游资源。
⚠️ 借还配对、状态重置、失效检测、并发控制都要正确实现，否则泄漏或脏数据。
⚠️ 对轻量对象得不偿失；池大小需调优（过小阻塞、过大浪费）。

## 与相关概念的区别

| 对比项 | 对象池 | 单例 | 缓存 |
|---|---|---|---|
| 对象数量 | 多个（有上限） | 恰好一个 | 一组键值 |
| 用法 | 借出—独占—归还 | 全局共享同一实例 | 只读共享、命中即复用 |
| 关注点 | 复用昂贵对象、控上限 | 唯一性与访问点 | 加速重复查询 |

## 常见误区

- 用了对象池就一定能提升性能。
- 归还对象时不必重置状态，下个使用者会自己清理。
- 借出用完后，即使已归还也可以继续持有该对象的引用。

## 面试速答

> 🎯 对象池 = 预建一批可复用对象、借出—使用—归还循环复用，摊薄昂贵对象的创建/销毁开销并用上限保护后端（典型：连接池/线程池）。对轻量对象在 GC 语言里常是反模式，优先用 HikariCP 等成熟实现。
