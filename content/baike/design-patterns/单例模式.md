# 单例模式

> 📌 **导航**：本文是 **单例模式** 词条，属 [[创建型模式（Creational Patterns）]] 子词条。

## 定义

**一句话定义：** 单例模式保证一个类在其生命周期内只有一个实例，并由该类自身提供一个访问这个唯一实例的全局入口。

**通俗类比：** 像一家公司的公章——全公司只有一枚，任何部门盖章都到同一处领用，"唯一性"由制度强制，而不是靠大家自觉不刻第二枚。

## 为什么需要它

有些资源全局只需、也只能有一份：数据库连接池、线程池、配置管理器、日志器。若允许 new 出多份，会重复占用句柄、各自维护不一致的状态。单例把"保证唯一 + 提供统一访问点"的责任收进类内部，让全系统从同一个实例读写。

## 核心机制

骨架是三件套：私有构造函数（阻止外部 new）、指向自身唯一实例的静态引用、一个公共静态 `getInstance()` 作为全局访问点。关键约束是唯一性必须由类自身强制，而非依赖调用方自律。常见落地写法：

- 饿汉式：类加载即创建，简单但无法懒加载。
- 双重检查锁（DCL）：懒加载 + 加锁，`instance` 必须 `volatile`。
- 静态内部类 Holder：靠 JVM 类初始化保证线程安全，懒加载且无锁。
- 枚举：天然唯一，能防反射与序列化破坏，代价是不能懒加载、不能继承。

## 具体示例

静态内部类（Holder）是纯 Java 下推荐写法之一——首次调用 `getInstance` 才触发 `Holder` 加载，类初始化由 JVM（JLS 12.4.2）保证线程安全：

```java
public class Singleton {
    private Singleton() {}
    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() { return Holder.INSTANCE; }
}
```

## 何时用与何时不用

- **用**：需要全局唯一实例的资源管理器（连接池、线程池、配置中心、日志器）与硬件 / 系统访问点。
- **不用**：绝大多数普通业务对象不要单例；优先考虑依赖注入（DI）把共享实例传进去，比隐式全局访问更易测试、耦合更清晰。单例应"克制使用"。

## 优劣与代价

✅ 严格控制实例数、节省频繁创建开销，提供统一访问点。
✅ 可懒加载、可经接口做单态替换。
⚠️ 引入全局隐式状态，造成不透明耦合，违反依赖倒置、难以 mock 与单测。
⚠️ 易演变成"什么都往里塞"的上帝对象；线程安全、销毁时机、反射 / 序列化破坏都得自己扛。

## 与相关概念的区别

- **单例 vs 全局变量**：单例由类保证恰好一个、可懒加载、可多态替换；全局变量启动即在、硬编码依赖。
- **单例 vs 静态类**：静态类根本不可实例化、无多态；单例是"恰好一个实例"的对象。
- **手写单例 vs DI 容器托管**：Spring 默认单例作用域由容器负责创建与生命周期，比手写单例更可控、更易注入与测试。

## 常见误区

- 双重检查锁单例不加 volatile 也是线程安全的。
- 把构造函数私有化就万事大吉，反射和序列化都造不出第二个实例。
- 任何需要全局共享的东西都应该写成单例。

## 面试速答

> 🎯 单例 = 一个类全局只有一个实例、由类自身暴露访问点：私有构造防 new、静态引用存实例、getInstance 取用；推荐静态内部类 Holder 或枚举，兼顾懒加载、线程安全与防反射/序列化。
