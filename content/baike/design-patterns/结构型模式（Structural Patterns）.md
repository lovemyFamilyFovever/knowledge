# 结构型模式（Structural Patterns）

> 📌 **导航**：本页是 **结构型模式** 枢纽，索引其 8 个子词条；各模式的定义、代码与误区已拆出，本页只讲"有哪些、怎么选"。

## 定义

**一句话定义：** 结构型模式关注如何把类与对象组合成更大的结构，用继承（类结构型）或组合（对象结构型）在不变动已有类的前提下，获得新的协作能力或更清晰的接口。

**通俗类比：** 像乐高积木的连接规范——单块积木（类）不动，靠不同的拼法把小结构接成大结构，从而搭出原本没有的功能。

## 为什么需要它

写需求时很难预知所有"把已有部件接起来"的方式。结构型模式提供一套经检验的组合手法：接口对不上就适配、维度会各自膨胀就桥接、要动态加料就装饰、子系统太复杂就加外观……它们让你在**不修改既有类**的前提下改变"结构关系"，是重构与集成时的常用工具箱。

## 核心机制

GoF 的结构型模式共 7 种（下表前 7 行）；本页另收常被并列讨论的 MVC / MVVM（属界面架构模式）。按手段可分**类结构型**（靠继承编译期组合，如类适配器）与**对象结构型**（靠组合/委托运行期装配，更灵活、主流）。

| 子词条 | 解决什么 | 何时选它 |
|---|---|---|
| [[适配器模式]] | 把不兼容接口转成客户端期望的接口 | 整合遗留 / 第三方、事后弥补接口 |
| [[桥接模式]] | 抽象与实现两维度独立变化 | 多维度扩展、避免类爆炸、运行时换实现 |
| [[组合模式]] | 以树表达"部分—整体"、叶子与容器一致处理 | 文件树 / UI 组件树 / 组织架构 |
| [[装饰器模式]] | 不改接口地动态叠加职责 | 运行期可组合地增强功能（Java I/O） |
| [[外观模式]] | 给一组子系统统一高层入口 | 简化复杂子系统、解耦客户端 |
| [[享元模式]] | 共享细粒度对象的内在状态省内存 | 海量相似对象（字形、粒子） |
| [[代理模式]] | 控制对目标的访问并附加处理 | 延迟加载 / 鉴权 / 缓存 / RPC / AOP |
| [[MVC 与 MVVM]] | 界面分层、UI 与业务解耦 | Web / 移动 / 桌面应用架构 |

> 另有**过滤器 / Criteria 模式**（按条件组合筛选对象），但它**非 GoF 模式**，且本质是策略 / 规格模式的一种特化——多数场景直接用语言内建的 `filter` / Stream / LINQ 即可，不单列词条。

## 具体示例

按"想改变的是结构关系的哪一面"来选：接口对不上 → [[适配器模式]]；形状×颜色这类多独立维度 → [[桥接模式]]；要递归处理整体与部分 → [[组合模式]]；给对象一层层加功能 → [[装饰器模式]]；给复杂子系统一个简单门面 → [[外观模式]]；海量相似对象要省内存 → [[享元模式]]；想控制或延迟对某对象的访问 → [[代理模式]]；组织 UI 与业务 → [[MVC 与 MVVM]]。各模式的具体结构见对应子词条，本页不重复。

## 何时用与何时不用

- **用**：需要"不改动已有类"就改变结构关系——兼容接口、解耦维度、动态加职责、封装子系统、共享对象、控制访问。
- **不用**：结构本来简单清晰时别硬套；过度组合会让调用链层层包裹、可读性与调试性下降。

## 优劣与代价

✅ 在不改既有代码的前提下扩展能力、提升复用与解耦，符合开闭。
✅ 每种手法针对一类"组合"痛点，选型清晰。
⚠️ 引入额外层次与间接性，用多了调用链变绕。
⚠️ 装饰器/代理/适配器本质都是"包一层"，滥用会让系统难以理解。

## 与相关概念的区别

- **结构型 vs 创建型**（[[创建型模式（Creational Patterns）]]）：创建型管"对象怎么造出来"，结构型管"造好的类与对象怎么组合成更大结构"。
- **结构型 vs 行为型**（[[行为型模式（Behavioral Patterns）]]）：行为型管"对象之间的职责与通信"，与"静态结构组合"正交。
- 结构型内部：适配器/桥接偏"接口与维度解耦"，组合/装饰器/代理偏"包装与递归结构"，外观/享元偏"简化入口与共享"。

## 常见误区

- MVC 和 MVVM 属于 GoF 的 23 种结构型设计模式。
- 代理和装饰器结构差不多，可以随便互换使用。
- 结构型模式与行为型模式的区别只是名字不同。

## 面试速答

> 🎯 结构型模式管"类与对象怎么组合成更大结构"：GoF 七种——适配(转接口)/桥接(分离抽象与实现)/组合(部分—整体树)/装饰(不改接口加职责)/外观(统一入口)/享元(共享省内存)/代理(控制访问)，外加 MVC/MVVM 架构模式。选谁看要改变结构关系的哪一面。
