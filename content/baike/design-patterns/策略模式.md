# 策略模式

> 📌 **导航**：本文是 **策略模式** 词条，属 [[行为型模式（Behavioral Patterns）]] 子词条。

## 定义

**一句话定义：** 策略模式定义一族算法，把它们各自封装成可互相替换的策略类，使算法的变化独立于使用它的客户端。

**通俗类比：** 导航去同一目的地，可选"最快路线""最短路线""不走高速"——算法不同、目标一致，可随时切换，而"发起导航"这件事本身不变。

## 为什么需要它

同一功能有多种实现（排序、压缩、计费、风控），若用一堆 `if-else`/`switch` 按类型分支，每次加一种就得改这段判断、且所有分支堆在一起难测。策略把每种算法封成独立对象，运行时由上下文持有并调用，新增算法只是"加一个策略"，符合开闭，也拆掉了庞杂条件分支。

## 核心机制

- **Strategy**：声明所有算法的公共接口。
- **ConcreteStrategy**：各自实现一种算法。
- **Context**：持有一个 Strategy 引用，把计算委托给它，并可在运行期 `set_strategy` 替换。
- 在支持一等函数的语言里，一个函数/闭包即可充当策略，无需专门建类。

## 具体示例

上下文持策略引用、可运行时替换；真实场景中各策略应有各自实现与复杂度：

```python
class Sorter:                          # Context
    def __init__(self, strategy): self._s = strategy
    def set_strategy(self, s): self._s = s   # 运行时换算法
    def do_sort(self, data): return self._s(data)

sorter = Sorter(sorted)                # 策略就是一个函数
sorter.set_strategy(lambda d: sorted(d, reverse=True))
```

## 何时用与何时不用

- **用**：同一功能多种算法且需在运行时按条件选择/切换；想用组合替代大量条件分支；各算法彼此独立、可单独测试。
- **不用**：只有一两种固定算法、或分支极少时，`if-else` 更直白，别为模式而模式造一堆策略类。

## 优劣与代价

✅ 算法与调用方解耦、可运行时切换、消除条件分支、符合开闭。
✅ 每种算法可独立演进与单测。
⚠️ 策略多时类/对象数量增加，客户端仍需了解各策略差异才能选对。
⚠️ 对极简场景属过度设计。

## 与相关概念的区别

- **策略 vs 状态**（[[状态模式]]）：结构相似、意图不同——策略由**客户端主动选**、各策略互不相关；状态由**对象内部自动切换**、状态间有转换关系。
- **策略 vs 模板方法**（[[模板方法模式]]）：策略用**组合**替换整个算法、可运行期换；模板方法用**继承**复用流程骨架、编译期定死。

## 常见误区

- 策略模式必须定义接口和一堆类，用函数传递算法不算策略模式。
- 用了策略模式后，客户端就完全不必知道有哪些策略可选。
- 策略和状态结构差不多，所以它俩是一回事。
