# 行为型模式（Behavioral Patterns）

> 📌 **导航**：本页是 **行为型模式** 枢纽。高频 7 种已各立子词条；低频 4 种（迭代器 / 备忘录 / 访问者 / 解释器）在本页内联速查。

## 定义

**一句话定义：** 行为型模式关注对象之间的职责分配与通信方式，描述一组对象如何协作完成单个对象无法独立完成的任务，并管理算法、状态与请求的流转。

**通俗类比：** 创建型管"怎么造"、结构型管"怎么拼"，行为型管"拼好之后大家怎么分工协作、消息怎么传"——像一支球队里球员的跑位与传球规则。

## 为什么需要它

复杂业务里，"谁负责什么、谁通知谁、状态怎么流转"若散落成一堆互相调用的 if-else，会耦合紧、难扩展。行为型模式把这些"协作与职责"的模式固化成经检验的手法：换算法用策略、一对多通知用观察者、状态驱动用状态、请求封装用命令……让协作关系显式、可替换。

## 核心机制

GoF 行为型共 11 种。高频 7 种独立成词条：

| 子词条 | 一句话职责 | 典型场景 |
|---|---|---|
| [[策略模式]] | 一族可互换算法 | 计费 / 排序 / 风控规则切换 |
| [[观察者模式]] | 一对多状态通知 | 事件、领域事件、GUI |
| [[命令模式]] | 请求封装为对象 | 撤销/重做、任务队列 |
| [[状态模式]] | 行为随内部状态改变 | 订单 / 审批状态机 |
| [[模板方法模式]] | 骨架固定、步骤子类填 | 框架生命周期、ETL |
| [[责任链模式]] | 请求沿链传递直到被处理 | 中间件、审批流、异常链 |
| [[中介者模式]] | 中心协调多对象交互 | 聊天室、表单联动、编排 |

另 4 种低频，速查如下（细节可后续再立条）：**迭代器**——顺序访问聚合而不暴露内部结构（`for`/生成器即其体现，语言多已内建）；**备忘录**——不破坏封装地保存/恢复对象状态快照（撤销、存档）；**访问者**——不改元素类即新增操作，靠双分派，适合"结构稳定、操作多变"（编译器 AST）；**解释器**——为简单文法建表达式树并求值，复杂语言宜改用 ANTLR 等解析器生成工具。

## 具体示例

按"要解决哪类协作"选：运行时换算法 → [[策略模式]]；一处变化要通知多方 → [[观察者模式]]；要能撤销/排队一个操作 → [[命令模式]]；对象行为随状态跳变 → [[状态模式]]；流程固定只个别步骤变 → [[模板方法模式]]；多个处理者依次接手 → [[责任链模式]]；多对象互相缠绕 → [[中介者模式]]。各模式结构见对应子词条。

## 何时用与何时不用

- **用**：算法需可替换、对象需松耦合通信、状态/请求/遍历需被显式封装时。
- **不用**：逻辑简单、直白调用更易读时别硬套；行为型彼此（策略/状态、命令/策略）结构相近，选错会徒增层次。

## 优劣与代价

✅ 解耦协作双方、把易变的算法/状态/通信显式化、符合开闭、可测性好。
✅ 许多模式（观察者、策略）是事件驱动与可配置设计的地基。
⚠️ 引入额外对象与间接层，滥用会让控制流分散、难追踪。
⚠️ 相似结构（策略/状态）需靠"意图"而非"形状"区分。

## 与相关概念的区别

- **行为型 vs 创建型**（[[创建型模式（Creational Patterns）]]）：创建型管对象如何产生，行为型管对象间如何协作。
- **行为型 vs 结构型**（[[结构型模式（Structural Patterns）]]）：结构型管静态组合，行为型管动态职责与通信。

## 常见误区

- 策略模式和状态模式结构相同，所以是同一个模式。
- 命令模式和策略模式都是"封装一个行为"，没有本质区别。
- 设计模式里用了行为型，代码就一定更清晰。
