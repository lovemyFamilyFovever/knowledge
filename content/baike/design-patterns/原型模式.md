# 原型模式

> 📌 **导航**：本文是 **原型模式** 词条，属 [[创建型模式（Creational Patterns）]] 子词条。

## 定义

**一句话定义：** 原型模式用一个已有对象作为"原型"，通过复制（克隆）它来创建新对象，而不是用 new 从头构造；其核心难点是分清浅拷贝与深拷贝。

**通俗类比：** 老师发一张试卷的复印件——内容与原件一致，但两者相互独立，你在复印件上涂改不影响原件。原型模式就是"照现成样板复印一份"，省去重新排版印刷的成本。

## 为什么需要它

当构造一个对象很贵（要查数据库、发网络请求、做大量计算），或需要一份"和当前状态完全相同"的副本（快照、撤销/回滚），从头 new 一遍既慢又要重复装配。用克隆直接从现成对象复制，能绕过昂贵初始化、快速得到独立副本，还能在运行期动态确定要造的类型。

## 核心机制

Prototype 声明一个克隆接口（Java 的 `clone()`、Python 的 `__copy__/__deepcopy__`），ConcretePrototype 实现它返回自身副本，Client 调用克隆获取新对象。关键在两类复制：

- **浅拷贝**：只复制顶层对象，内部引用字段仍指向同一个对象（共享）。
- **深拷贝**：递归复制整张对象图，每层都新建副本、彼此独立；含循环引用时须借"已拷贝对象"缓存（如 Python `deepcopy` 的 `memo`）避免无限递归。

## 具体示例

对内含引用对象的 `Person`（带 `Address`）：

```python
p2 = copy.copy(p1)       # 浅拷贝：p2.addr is p1.addr → True（内部共享）
p3 = copy.deepcopy(p1)   # 深拷贝：p3.addr is p1.addr → False（完全独立）
```

## 何时用与何时不用

- **用**：对象创建成本高、需要与当前状态相同的独立副本、运行时动态确定要创建的类型。
- **不用**：对象图复杂（大量循环引用）导致深拷贝脆弱时；Java 中 `clone()` 约定繁琐，优先考虑拷贝构造函数 / 拷贝工厂。

## 优劣与代价

✅ 绕过昂贵的构造 / 初始化，运行期可动态增删原型、比静态工厂灵活。
✅ 深拷贝能快速得到相互独立的对象副本。
⚠️ 深拷贝实现复杂，循环引用、克隆正确性都要小心。
⚠️ 侵入性强（几乎每个类都要考虑克隆），且克隆可能绕过构造函数的校验 / 初始化，导致状态不一致。

## 与相关概念的区别

| 类型 | 复制范围 | 引用字段处理 |
|---|---|---|
| 浅拷贝 | 只复制顶层对象 | 复制引用，指向同一内部对象 |
| 深拷贝 | 递归复制整个对象图 | 每层都新建副本，完全独立 |

- **原型 vs 工厂方法**：工厂通过"约定接口 new 出对象"创建，原型通过"复制现成实例"创建，可规避复杂的工厂层次。

## 常见误区

- 复制对象默认就是深拷贝，内部引用的对象也各自独立。
- Java 的 Cloneable 接口自带 clone() 方法，可以直接调用。
- 做深拷贝时不用管循环引用，一路递归复制即可。

## 面试速答
