# 中介者模式

> 📌 **导航**：本文是 **中介者模式** 词条，属 [[行为型模式（Behavioral Patterns）]] 子词条。

## 定义

**一句话定义：** 中介者模式用一个中介对象封装一组对象之间的交互，使各对象不必显式相互引用，从而松耦合、并可独立改变它们的协作方式。

**通俗类比：** 机场塔台——飞机之间不直接喊话，都通过塔台协调起降；塔台掌握全局统一调度，避免两两通信的混乱。

## 为什么需要它

当多个对象彼此直接引用、交互交织成"网状"，改一处可能牵动一大片，且交互逻辑散落各处难维护。中介者把"谁和谁、怎么交互"收敛到一个中心协调者，同僚只认中介者，把多对多降为一对多（星型拓扑），交互规则集中、可复用。

## 核心机制

- **Mediator**：声明同僚通信的方法；ConcreteMediator 持有各同僚引用并协调。
- **Colleague**：只与中介者通信，而非彼此直接引用。
- N 个对象两两交互最多 N×(N−1)/2 条连接，引入中介者后降为 N 条。

## 具体示例

聊天室作中介者，用户（同僚）只向房间收发、不直接持有彼此引用：

```python
class ChatRoom:                        # Mediator
    def __init__(self): self._users = {}
    def register(self, u): self._users[u.name] = u
    def send(self, msg, frm):
        for n, u in self._users.items():
            if n != frm.name: u.receive(msg, frm.name)   # 由中介广播

class User:                            # Colleague
    def __init__(self, name, room): self.name, self.room = name, room; room.register(self)
```

## 何时用与何时不用

- **用**：多对象形成网状引用、交互逻辑分散难维护时，用中心协调者收敛（聊天室、表单控件联动、微服务编排）。
- **不用**：交互本就简单或一对一；强行引入中介者会让它膨胀成"上帝对象"，反而更难维护。

## 优劣与代价

✅ 把多对多降为一对多、同僚间解耦、交互逻辑集中可复用、可独立改变协作方式。
⚠️ 中介者易膨胀成难以维护的上帝对象，塞太多逻辑会适得其反。

## 与相关概念的区别

- **中介者 vs 观察者**（[[观察者模式]]）：中介者协调多个同僚的**多向**交互（有中心节点）；观察者是一对多的**单向**通知。
- **中介者 vs 外观**（[[外观模式]]）：外观是"客户端→子系统"的单向简化入口；中介者处理的是同僚之间的双向交互。

## 常见误区

- 中介者模式和观察者模式都是"中间层"，可以互相替代。
- 有了中介者，同僚对象之间就应该完全禁止任何直接引用。
- 中介者应该承担尽可能多的业务逻辑，越全越好。

## 面试速答

> 🎯 中介者 = 用一个中心对象封装一组对象的交互，同僚只认中介、不互相直接引用，把多对多降为一对多（星型），交互逻辑集中。适合聊天室/表单联动/编排。警惕中介者膨胀成上帝对象。与观察者区别：中介者协调多向、观察者单向广播。
