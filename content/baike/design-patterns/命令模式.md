# 命令模式

> 📌 **导航**：本文是 **命令模式** 词条，属 [[行为型模式（Behavioral Patterns）]] 子词条。

## 定义

**一句话定义：** 命令模式把一个请求封装成对象，从而可用不同的请求对客户参数化，并支持请求排队、记录日志与可撤销操作。

**通俗类比：** 餐厅点菜单——写在纸上的是"命令对象"，服务员只按单执行、不关心谁点的何时点的；单子还能攒着、可撤销、可重下。

## 为什么需要它

若调用方直接调接收者的方法，两者就硬耦合，也难实现"撤销/重做、排队、事务、日志"。把请求变成对象后，命令可被存储、传递、组合、延迟执行，调用者（Invoker）只管触发，不知具体业务；接收者（Receiver）只管干活，不知谁触发——请求的发起与执行解耦。

## 核心机制

- **Command**：声明 `execute`（及可选 `undo`）。
- **ConcreteCommand**：绑定一个 Receiver 与动作。
- **Receiver**：真正执行业务的对象。
- **Invoker**：持有命令并触发 `execute`，可排队、记录历史。
- 用历史栈记录已执行命令即可实现撤销/重做。

## 具体示例

Invoker 执行命令并记入历史栈，undo 时逆序回退：

```python
class Invoker:
    def __init__(self): self._hist = []
    def run(self, cmd):
        cmd.execute(); self._hist.append(cmd)     # 记录以便撤销
    def undo(self):
        if self._hist: self._hist.pop().undo()

class Insert:                                     # ConcreteCommand
    def __init__(self, ed, s): self.ed, self.s = ed, s
    def execute(self): self.ed.text += self.s
    def undo(self): self.ed.text = self.ed.text[:-len(self.s)]
```

## 何时用与何时不用

- **用**：撤销/重做（编辑器、绘图）、命令队列与任务调度、宏命令、事务回滚、操作审计日志。
- **不用**：请求简单、无排队/撤销需求时，直接调用更轻量，别为每个操作都建命令类。

## 优劣与代价

✅ 调用者与接收者解耦；命令可组合/排队/持久化；易实现撤销重做；新增命令符合开闭。
⚠️ 命令类数量可能急剧增多；完整 undo/redo（复杂状态）实现成本高。

## 与相关概念的区别

- **命令 vs 策略**（[[策略模式]]）：策略封装"算法"以替换；命令封装"一次请求"以解耦发起与执行、支持排队撤销。
- **命令 vs 备忘录**（[[行为型模式（Behavioral Patterns）]]）：命令的 undo 记的是"逆操作"；备忘录存的是"状态快照"，二者都能做撤销、机制不同，可结合。

## 常见误区

- 命令模式就是把方法名存成字符串然后用反射调用。
- 实现了命令模式就不可能再做撤销功能。
- 命令模式里 Invoker 必须知道 Receiver 的具体业务细节。

## 面试速答

> 🎯 命令 = 把一次请求封装成对象（含 execute/undo），Invoker 触发、Receiver 执行，二者解耦；由此可排队、记日志、组合宏、实现撤销/重做。与策略区别在封装的是"请求"而非"算法"。
