# 模板方法模式

> 📌 **导航**：本文是 **模板方法模式** 词条，属 [[行为型模式（Behavioral Patterns）]] 子词条。

## 定义

**一句话定义：** 模板方法模式在父类中定义一个算法的骨架，而将其中某些步骤延迟到子类实现，使子类不改变算法结构即可重定义特定步骤。

**通俗类比：** 泡茶与泡咖啡流程都是"烧水→冲泡→倒杯→加料"，前后步骤一样，只有"冲泡"和"加料"因饮品而异——骨架固定、可变步骤交给子类。

## 为什么需要它

多个流程骨架相同、只有个别步骤不同（数据导出、报表生成、ETL、框架生命周期回调），把不变步骤抽到父类复用、变化步骤留钩子给子类，就消除重复、统一控制流程，体现"好莱坞原则：别调用我们，我们会调用你"。

## 核心机制

- **AbstractClass**：定义模板方法（算法骨架，常 `final` 防覆写）、若干抽象步骤（子类必须实现）与钩子方法（有默认实现、子类可选覆写）。
- **ConcreteClass**：实现抽象步骤、按需覆写钩子。
- 骨架由父类的模板方法按序调用，子类只填空。

## 具体示例

`prepare()` 是模板方法，固定流程；`brew`/`add_condiments` 为抽象步骤，`customer_wants_condiments` 为钩子：

```python
class Beverage(ABC):
    def prepare(self):                 # 模板方法：流程骨架
        self.boil_water(); self.brew(); self.pour()
        if self.want_condiments(): self.add_condiments()   # 钩子控制
    def boil_water(self): print("烧水")
    def pour(self): print("倒杯")
    def want_condiments(self): return True                 # 钩子默认实现
    @abstractmethod
    def brew(self): ...
    @abstractmethod
    def add_condiments(self): ...
```

## 何时用与何时不用

- **用**：多个子类共享流程、只在个别步骤上不同；框架想固定算法骨架、把扩展点交给使用者。
- **不用**：需要运行期灵活切换步骤时，继承式模板方法不灵活，改用策略组合（见 [[策略模式]]）。

## 优劣与代价

✅ 复用不变代码、把变化点集中到子类、由父类统一控制流程。
⚠️ 基于继承，灵活性不如组合（Java 单继承限制）。
⚠️ 子类实现会影响父类流程结果，反向控制增加理解成本；步骤过多难维护。

## 与相关概念的区别

- **模板方法 vs 策略**（[[策略模式]]）：模板方法用**继承**复用算法的一部分步骤、编译期定；策略用**组合**替换整个算法、可运行期切换。
- 常配 **钩子方法** 让子类在不改骨架的前提下微调流程。

## 常见误区

- 模板方法模式和策略模式没有区别，都是替换算法。
- 模板方法里的抽象步骤可以省略钩子方法，二者是一回事。
- 一旦定义模板方法，子类就再也不能影响流程的任何环节。

## 面试速答

> 🎯 模板方法 = 父类定义算法骨架、把可变步骤延迟到子类实现，靠继承复用不变部分、用钩子让子类微调流程（好莱坞原则）。与策略的区别：模板用继承、编译期、复用部分步骤；策略用组合、运行期、替换整个算法。
