# 前端路由

> 📌 **导航**：本文是 **前端路由** 词条，属于 frontend-concepts 术语集。相关枢纽：[[前端框架核心概念]]、[[前端工程化核心概念]]。

## 定义

**一句话定义：** 前端路由在单页应用里接管 URL 与视图的映射——拦截导航、按路径渲染对应组件并接入浏览器历史栈，做到切页不向服务器重新请求整份 HTML。

**通俗类比：** 像单页 PPT：翻页（换 URL）时换的是内容而不是重新打开文件（刷新），前进/后退键仍有效，因为每一页都被记进了历史。

## 为什么需要它

SPA 只加载一次文档，之后全在客户端切换视图；若不管 URL，用户就没法收藏某页、刷新回到首页、浏览器前进后退失效。前端路由用 URL 作为"当前视图"的可分享、可回退的地址，把单页体验接回浏览器的导航模型。

## 核心机制

- **两条实现路线差在"改 URL 会不会惊动服务器"**：Hash 路由只改 location.hash（`#/about`）、触发 hashchange，服务器看到的永远是根路径故零配置，但地址栏带 `#`；History 路由用 pushState 换成干净的 `/about`，代价是刷新时服务器必须对该路径回吐同一份 index.html，否则 404，部署要配 fallback（见 [[前端工程化核心概念]]）。
- **路由表 + 匹配 + 守卫是三件套**：声明 path 到组件的映射、按动态段（`/user/:id`）解析出参数、在导航前后插入鉴权与滚动等守卫；React Router 的 Routes/Route 与 Vue Router 的 routes 数组是同一结构的不同皮肤。
- **懒加载把路由切成拆包的天然边界**：一个路由块对应一个可异步加载的 chunk，配合 [[前端构建优化策略]] 的 code splitting，首屏只下载当前路由的代码，跳页时再按需取。

## 具体示例

```javascript
// History 路由核心：改地址但不向服务器要文档
history.pushState(null, "", "/about");
window.addEventListener("popstate", render); // 前进/后退都回到这里重渲染
// 前提：服务器须把 /about 也返回同一份 index.html，否则刷新即 404
```

## 何时用与何时不用

- **用**：任何多视图 SPA 都需要路由承载可寻址的页面；能接受服务器配 fallback 就优先 History，纯静态托管 / 老环境兜底才用 Hash。
- **不用**：多页站点（MPM / 每页独立 HTML）本就走服务器导航，硬套 SPA 路由是给自己加历史栈管理成本；单页无子视图也无需引入。

## 优劣与代价

✅ URL 可分享、可前进后退，切页不重刷整份文档，体验连续。
✅ History 模式地址干净、利于 SEO 与用户信任。
⚠️ History 依赖服务器 fallback 配置，漏配就是子路由刷新 404 的经典线上事故。
⚠️ SPA 首屏要等 JS 起来才可交互，对首屏敏感的场景要配合 SSR（枢纽 [[前端框架核心概念]] 的渲染策略一行）。

## 与相关概念的区别

- **vs [[组件化与微前端]]**：微前端主应用也按路由激活子应用（activeRule），但那是应用级编排；本条解的是单个 SPA 内 URL 到组件的寻址。
- **vs [[前端框架核心概念]]**：那条把路由列为跨框架共性机制之一，本条是它的具体实现与两条路线取舍。

## 常见误区

- History 路由上线没配服务器 fallback，本地一切正常、一刷新子路由就 404。
- 以为 SPA 换页会自动重新加载数据，其实组件切换不发文档请求，数据要自己在守卫里取。
- 把数组下标 / 随机串当路由 key 或参数标识，收藏与回退时定位不到同一视图。

## 面试速答

> 🎯 前端路由在 SPA 里把 URL 映射到组件并接入历史栈：Hash 改 location.hash、零服务器配置但带 #；History 用 pushState 换干净地址、刷新需服务器回吐 index.html 否则 404。核心是"改地址但不重新请求整份文档"。
