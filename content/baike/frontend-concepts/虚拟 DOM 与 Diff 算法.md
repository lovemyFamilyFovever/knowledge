# 虚拟 DOM 与 Diff 算法

> 📌 **导航**：本文是 **虚拟 DOM 与 Diff 算法** 词条，属于 frontend-concepts 术语集。相关枢纽：[[前端框架核心概念]]、[[React深入]]、[[Vue3核心]]。

## 定义

**一句话定义：** 虚拟 DOM 是用普通 JS 对象描述 UI 树的一层中间表示；Diff 算法比较新旧两棵树，把"整棵重建"降级为"只改变化处"的最小 DOM 操作集合。

**通俗类比：** 像装修前后对比图纸——不是拆了重盖，而是拿新旧两张图逐处比对，只动真正变了的地方（换个灯泡不会重砌墙）。

## 为什么需要它

直接操作 DOM 慢在每次读写都可能触发布局与重绘。虚拟 DOM 把更新搬到内存里先算一遍，批量得出最小补丁再一次性提交，用一次廉价的 JS 树比对换掉一串昂贵的 DOM 操作——代价是多了一层抽象与 diff 自身的计算。

## 核心机制

- **树比对本是难题，工程上用启发式压到线性**：严格的最优 tree-edit-distance 约 O(n³)，无法逐帧执行；虚拟 DOM diff 靠三条约定降到近似 O(n)——同层比较（不跨层搬移）、类型不同整棵替换、同类型只比属性差异。
- **key 是列表 diff 唯一的身份凭据**：没有 key 时按下标对齐，删中间一项会让后面全部被误判为"内容变了"而重写；给稳定且唯一的 key，算法才认得出这是"移动"而非"删除 + 新增"，把数组下标当 key 正是最常见的反例。
- **框架实现各有专条，本条只讲通用机制**：React 的 Fiber 把递归 diff 改造成可中断的链表遍历、分 Render / Commit 两段（见 [[React深入]]），Vue 用编译期 PatchFlag 标动态节点、把 diff 缩到"会变的那几个"（见 [[Vue3核心]]）——两者都是对线性 diff 的工程加强，不是另一套理论。

## 具体示例

```javascript
// 虚拟 DOM 就是一个普通对象
const vdom = {
  type: "div", props: { className: "box" },
  children: [{ type: "h1", props: {}, children: ["标题"] }],
};
// 同层 diff 的三条启发式（伪代码）
function diff(a, b) {
  if (a.type !== b.type) return { op: "REPLACE", node: b }; // 类型不同→整棵换
  return { op: "UPDATE", props: patchProps(a.props, b.props) }; // 同类型→只补差异
}
```

## 何时用与何时不用

- **适用**：状态频繁变化、UI 是状态的纯函数、结构复杂的界面——虚拟 DOM 的批量最小更新在这里收益最大。
- **收益低**：一次性静态内容、需要逐帧精确操作个别节点（如手写动画 transform）、极简单页面——直接写 DOM 或用 [[CSS渲染性能]] 的合成层手段反而更省。

## 优劣与代价

✅ 把"该改哪"从开发者手工追踪变成算法负责，且跨端可移植（同一 vnode 可渲染到浏览器 / 小程序 / Native）。
✅ 更新性能可预测，避免"想到哪改到哪"的散落 DOM 操作。
⚠️ 一层抽象有固定成本：首屏与极简场景下，diff + patch 可能慢于直接构建 DOM。
⚠️ "更快"是相对的——它赢在减少 DOM 操作次数，不是让每次操作本身变快。

## 与相关概念的区别

- **vs [[React深入]] 的 Fiber**：Fiber 讲的是"怎么把 diff 拆成可暂停的单元"，是虚拟 DOM diff 的一种可中断实现；本条讲的是 diff 算法本身与 key 语义。
- **vs [[Vue3核心]] 的 PatchFlag**：Vue 把一部分 diff 成本前移到编译期（静态分析）以"少比较"，React 是"重跑再比较"，两条路解决同一个"如何知道要改哪"的问题。

## 常见误区

- 以为用了虚拟 DOM 就一定比手写 DOM 快，简单场景它其实是净开销。
- 用数组下标当 key，一旦列表有增删排序就触发大面积错误重渲染。
- 把虚拟 DOM 等同于 React，其实 Vue、小程序等也用同一套 vnode + diff 思想。

## 面试速答

> 🎯 虚拟 DOM 用 JS 对象描述 UI；Diff 靠"同层比较、类型不同整换、key 定身份"三条启发式把 tree diff 从 O(n³) 压到近似 O(n)，只提交变化的最小补丁；Fiber、PatchFlag 是其可中断与编译期的工程优化。
