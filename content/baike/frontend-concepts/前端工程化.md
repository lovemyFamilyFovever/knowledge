# 前端工程化


> 📌 **导航**：本文是 **前端工程化** 词条，属于 frontend-concepts 术语集。相关枢纽：[[HTML & CSS 核心概念]]、[[JavaScript 基础核心概念]]、[[React深入]]、[[Vue3核心]]、[[前端工程化核心概念]]。

## 定义

**一句话定义：** 前端工程化用系统化的工具链和规范（构建/模块化/代码管理/自动化）将前端开发从手工编码提升为可协作、可复用、可持续交付的工程实践。

**通俗类比：** 像手工作坊到工厂流水线——个体手工能做出产品，但无法规模化、质量不稳定；工程化定义工序、模具和质检让产出可预期。

## 为什么需要它

现代前端项目动辄数百依赖、多端交付（Web/小程序/SSR），纯手工无法管理模块依赖、环境差异和团队协作一致性。工程化降低"改一处崩全站"的风险，让新成员按流程就能快速产出。

## 核心机制

**构建工具链**：Webpack（功能全面的打包器，适合复杂项目）、Vite（基于 ESM 的极快开发体验 + Rollup 构建）、esbuild（Go 实现的极速编译器，常作为底层）、Turbopack（Rust，Next.js 默认）。

**Monorepo**：单仓库管理多包（pnpm workspace / Turborepo / Nx），统一依赖版本、共享代码即时引用、原子提交跨包变更。

**微前端**：将大应用按业务拆为独立部署子应用——qiankun（JS 沙箱+CSS 隔离）、Module Federation（运行时模块共享）、Web Components（原生自定义元素）。

## 具体示例

电商团队 Monorepo：packages/shared 放通用 UI 组件和工具函数；packages/web 是 C 站、packages/admin 是管理后台——Turborepo 按依赖图增量构建，shared 改动时只重新构建受影响的 web/admin。

## 何时用与何时不用

- **用**：团队 > 3 人、项目多包/多端、需要 CI/CD 自动化交付。
- **不用**：单页面静态站（一个 HTML + CDN 即可）、一次性活动页。

## 优劣与代价

✅ 构建工具让代码拆分、Tree-shaking、压缩自动化。
✅ Monorepo 避免"代码复制散弹式维护"。
⚠️ 配置复杂度：Webpack loader/plugin 体系学习成本高。
⚠️ 微前端引入样式隔离、通信、性能等额外问题。

## 与相关概念的区别

- **vs 前端框架**：框架解决"怎么写 UI 组件"，工程化解决"怎么组织、构建和交付整个项目"；二者正交互补。
- **vs CI/CD**：CI/CD 是工程化流程的部署环节，工程化还包含开发态的规范、工具链和架构决策。

## 常见误区

- 工程化就是配 Webpack 打包。
- 用了 Monorepo 就是微前端。
- 工程化越复杂越专业。

## 面试速答

> 🎯 前端工程化 = 构建工具（Vite/Webpack）+ 模块化 + 代码规范 + 自动化交付；Monorepo 解组织问题、微前端解部署独立性，工程化本身是"让协作可规模化"的元能力。
