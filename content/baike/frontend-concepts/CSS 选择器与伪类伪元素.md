# CSS 选择器与伪类伪元素

> 📌 **导航**：本文是 **CSS 选择器与伪类伪元素** 词条，属于 frontend-concepts 术语集。相关枢纽：[[HTML & CSS 核心概念]]、[[前端框架核心概念]]。

## 定义

**一句话定义：** 选择器负责命中元素；多条规则作用于同一元素时，浏览器按（ID 数, 类数, 标签数）三元组比特异性（Specificity）、同分再看源码顺序来裁决生效者；伪类匹配元素的特殊状态与结构位置，伪元素创建不存在于 DOM 中的虚拟盒。

**通俗类比：** 像公司里的汇报关系——标签选择器是公司公告，类选择器是直属经理，ID 是 CEO 点名，!important 则可以直接拍板；伪类是给元素贴"正被悬停"的标签，伪元素是给它"画"一顶身份证照片上没有的帽子。

## 为什么需要它

不懂优先级与源码顺序，就躲不开"为什么我的样式没生效"的灵魂拷问，也无法精准控制哪条规则落地；不懂伪，就会为了首字母下沉、斑马条纹往 HTML 里塞一堆空标签。

## 核心机制

- **三元组逐级比较**：`p` 是 (0,0,1)，`.intro` 是 (0,1,0)，`#main` 是 (1,0,0)，`div.intro` 是 (0,1,1)，`#main .intro` 是 (1,1,0)；属性选择器 `[style]` 与类同档，`p:not(.intro)` 把伪类计进类位。从左往右比，谁先分出大小谁赢；`!important` 是规则外的最高档（慎用）；同特异性时后写的覆盖先写的。
- **伪类选状态与位置（单冒号）**：`a:hover` 悬停、`a:visited` 已访问、`input:focus` 获焦、`li:first-child` 第一个子元素、`li:nth-child(odd)` 奇数行——只选已有元素，不加节点。
- **伪元素造虚拟盒（双冒号）**：`p::first-letter` 首字母、`p::before` 与 `p::after` 配 `content` 在内容前后插入、`::selection` 管选中文本。规范建议伪元素用双冒号（历史单冒号写法浏览器仍兼容），生成的盒参与布局与层叠。

## 具体示例

斑马条纹一行搞定：`li:nth-child(odd) { background: #f5f5f5 }`；卡片角标用 `::before { content: "📌 " }` 加装饰，HTML 保持整洁。当自己的 `.intro` 覆盖不掉第三方库的 `.card .intro`，正确做法是提高类组合或缩窄作用域，而不是堆 `!important`。

## 何时用与何时不用

- **用**：需要命中交互状态、结构位置或纯装饰内容时用伪；样式冲突排查先算三元组、再核源码顺序。
- **不用**：ID 选择器不必禁但应克制——特异性太高会把后续覆盖逼进更特异的死循环；有信息量的正文别塞进 `content`（读屏工具读不到），那该回到 [[HTML 语义化]]。

## 优劣与代价

✅ 状态与结构性选择零 JS、零多余标签，HTML 保持整洁。
✅ 特异性可计算，冲突可推演而不是靠试错。
⚠️ 选择器链越长特异性越高，后期只能更特异性地压回去，形成恶性循环。
⚠️ !important 一旦开始就只能用另一个 important 终结，层叠体系随之失效。

## 与相关概念的区别

- **vs 优先级与特异性**：两者本质相同，特异性是优先级的数值化表达；优先级还额外受源码顺序影响。
- **vs [[CSS 盒模型与 BFC 与层叠上下文]]**：特异性裁决"谁的样式赢了"，层叠上下文裁决"谁盖住谁"，是两类互不相干的冲突。
- **vs [[CSS 变量与动画]]**：选择器决定规则命中谁，变量决定命中之后用什么值渲染。

## 常见误区

- 样式没生效就先叠 !important，不先比特异性与源码顺序。
- 把伪类与伪元素当成单双冒号的新旧写法之争，以为职责相同。

## 面试速答

> 🎯 优先级=（ID,类,标签）三元组从左往右比，同分看源码顺序，!important 是规则外最高档；伪类单冒号选已有元素的状态与位置，伪元素双冒号造虚拟盒参与布局，两者都计入特异性。
