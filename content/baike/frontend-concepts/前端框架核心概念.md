## React

### JSX

**一句话定义**：在 JavaScript 中编写类似 HTML 的语法，最终被编译为函数调用。

**通俗类比**：像在 JavaScript 里"画"界面，写 `<div>` 其实是在调用 `createElement`。

**具体示例**：
```jsx
// JSX 编写
const element = (
  <div className="container">
    <h1>标题</h1>
    <p>{user.name}</p>
    {isLoggedIn && <span>欢迎回来</span>}
  </div>
);

// 编译后（Babel 转换）
const element = React.createElement(
  "div",
  { className: "container" },
  React.createElement("h1", null, "标题"),
  React.createElement("p", null, user.name),
  isLoggedIn && React.createElement("span", null, "欢迎回来")
);
```

**为什么需要它**：比 `createElement` 调用更直观，同时保留 JavaScript 的全部表达能力。

### Hooks

**一句话定义**：让函数组件拥有状态、副作用等原本只有 Class 组件才有的能力。

**通俗类比**：函数组件像"实习生"，Hooks 是给实习生配备的"工具包"——有了 useState 就能管理数据，有了 useEffect 就能处理异步。

**具体示例**：
```jsx
import { useState, useEffect, useContext, useReducer, useMemo, useCallback } from "react";

// useState —— 状态管理
function Counter() {
  const [count, setCount] = useState(0); // [当前值, 更新函数]
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

// useEffect —— 副作用处理（替代 componentDidMount 等）
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetch(`/api/user/${userId}`)
      .then(r => r.json())
      .then(setUser);

    return () => { /* 清理函数（组件卸载时调用） */ };
  }, [userId]); // 依赖数组：userId 变化时重新执行

  return user ? <div>{user.name}</div> : <div>加载中...</div>;
}

// useContext —— 跨组件共享数据
const ThemeContext = React.createContext("light");
function ThemedButton() {
  const theme = useContext(ThemeContext);
  return <button className={`btn-${theme}`}>按钮</button>;
}

// useReducer —— 复杂状态逻辑
function todoReducer(state, action) {
  switch (action.type) {
    case "add": return [...state, { text: action.text, done: false }];
    case "toggle": return state.map((t, i) =>
      i === action.index ? { ...t, done: !t.done } : t
    );
    default: return state;
  }
}

// useMemo —— 缓存计算结果
const expensiveResult = useMemo(() => heavyCalculation(data), [data]);

// useCallback —— 缓存函数引用
const handleClick = useCallback(() => {
  doSomething(id);
}, [id]);

// 自定义 Hooks
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initialValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}
```

**为什么需要它**：Hooks 让逻辑复用更简单（自定义 Hook），组件更简洁（告别 Class 的 this 绑定），心智模型更统一。

**与相关术语的对比和区分**：useState（简单状态）vs useReducer（复杂状态/多个相关状态）。useEffect 不能直接用 async 函数，需要在内部手动调用。

## Vue

### 响应式原理

**一句话定义**：数据变化时，视图自动更新——Vue 通过 Proxy（Vue 3）拦截数据的读写操作来实现。

**通俗类比**：像手机推送通知——你订阅了（读取数据）某个消息源（数据对象），消息一更新（数据变化），你立刻收到推送（视图更新）。

**具体示例**：
```javascript
// Vue 3 响应式（Proxy 实现）
import { reactive } from "vue";

const state = reactive({ count: 0, name: "Alice" });

// 拦截读取
// 依赖收集：记录哪些组件使用了 state.count

// 拦截修改
state.count++; // 触发更新 → 相关组件自动重新渲染
```

**为什么需要它**：开发者只需关注数据逻辑，不用手动操作 DOM 更新视图。

---

### Composition API

**一句话定义**：Vue 3 提供的函数式 API，让逻辑关注点组织更灵活（替代 Options API）。

**通俗类比**：Options API 像按"类型"归档（所有方法放一起、所有数据放一起）；Composition API 像按"功能"归档（登录相关放一起、支付相关放一起）。

**具体示例**：
```vue
<script setup>
import { ref, reactive, watch, computed, onMounted, onUnmounted } from "vue";

// ref —— 基本类型响应式
const count = ref(0);
console.log(count.value); // 读取
count.value++;            // 修改

// reactive —— 对象响应式
const state = reactive({ name: "Alice", items: [] });

// computed —— 计算属性（缓存）
const doubleCount = computed(() => count.value * 2);

// watch —— 监听变化
watch(count, (newVal, oldVal) => {
  console.log(`从 ${oldVal} 变为 ${newVal}`);
});

watch(() => state.name, (newName) => {
  console.log(`名字变为: ${newName}`);
});

// 生命周期
onMounted(() => {
  console.log("组件挂载完成");
  window.addEventListener("resize", handleResize);
});

onUnmounted(() => {
  window.removeEventListener("resize", handleResize);
});

// 组合式函数（自定义 Hook）
function useMousePosition() {
  const x = ref(0);
  const y = ref(0);

  function update(e) { x.value = e.clientX; y.value = e.clientY; }

  onMounted(() => window.addEventListener("mousemove", update));
  onUnmounted(() => window.removeEventListener("mousemove", update));

  return { x, y };
}

const { x, y } = useMousePosition();
</script>

<template>
  <button @click="count++">{{ count }}</button>
  <p>{{ state.name }} - 双击: {{ doubleCount }}</p>
</template>
```

**为什么需要它**：逻辑复用更灵活、TypeScript 支持更好、代码组织更自由。

**与相关术语的对比和区分**：Composition API（函数式、灵活）vs Options API（声明式、直观）。Options API 适合简单组件，Composition API 适合复杂逻辑。

## Angular

### 依赖注入（DI）

**一句话定义**：框架自动创建和注入所需的服务实例，组件不需要自己创建依赖。

**通俗类比**：像餐厅点菜——你不需要自己去厨房做饭（创建服务），服务员（DI 系统）会把菜（服务实例）端给你。

**具体示例**：
```typescript
// 定义服务
@Injectable({ providedIn: 'root' })
export class UserService {
  getUser(id: string): Observable<User> {
    return this.http.get(`/api/users/${id}`);
  }
}

// 在组件中注入
@Component({
  selector: 'app-user',
  template: `<div>{{ user?.name }}</div>`
})
export class UserComponent implements OnInit {
  user: User | null = null;

  constructor(private userService: UserService) {} // DI 注入

  ngOnInit() {
    this.userService.getUser('123').subscribe(user => {
      this.user = user;
    });
  }
}
```

**为什么需要它**：解耦组件和服务，方便测试（可以替换 mock 服务），统一管理依赖生命周期。

---

### RxJS

**一句话定义**：用可观察序列处理异步操作和事件流的库。

**通俗类比**：像处理快递包裹流——你可以过滤（filter）、合并（mergeMap）、限流（debounceTime）、批量处理（buffer）一系列事件。

**具体示例**：
```typescript
import { fromEvent, debounceTime, map, switchMap } from 'rxjs';

// 搜索框防抖
const searchInput = document.querySelector('#search');
fromEvent(searchInput, 'input').pipe(
  debounceTime(300),        // 300ms 内只取最后一次
  map(e => e.target.value), // 提取输入值
  switchMap(term =>         // 取消上一次请求，只保留最新
    this.http.get(`/api/search?q=${term}`)
  )
).subscribe(results => {
  this.displayResults(results);
});
```

**为什么需要它**：Angular 内部大量使用 RxJS（HTTP、表单、路由等），处理复杂异步流比 Promise 更强大。

---

### Zone.js

**一句话定义**：Angular 的变更检测机制——自动追踪异步操作并触发视图更新。

**通俗类比**：像一个"间谍"，监视所有异步操作（setTimeout、Promise、事件等），操作完成后立刻通知 Angular 检查界面是否需要更新。

**具体示例**：
```typescript
// Zone.js 的工作原理（伪代码）
// 1. 拦截所有异步 API
const originalSetTimeout = window.setTimeout;
window.setTimeout = function (fn, delay) {
  return originalSetTimeout(function () {
    fn();
    NgZone.detectChanges(); // 异步完成后触发变更检测
  }, delay);
};

// 2. 所以 Angular 组件不需要手动通知视图更新
@Component({
  template: `<button (click)="update()">{{ message }}</button>`
})
export class MyComponent {
  message = "Hello";

  update() {
    // Zone.js 会自动检测到这个异步操作后的状态变化
    setTimeout(() => {
      this.message = "Updated"; // 视图自动更新
    }, 1000);
  }
}
```

**为什么需要它**：开发者不用手动调用 `.detectChanges()`，Zone.js 自动处理所有异步后的视图同步。

## 虚拟 DOM 与 Diff 算法

**一句话定义**：用 JS 对象模拟真实 DOM 树，比较新旧两棵虚拟树的差异，只更新变化的部分。

**通俗类比**：像装修前后对比照片——不是拆掉重来，而是对比新旧图纸，只改变动的部分（比如换了个灯泡，只换灯泡不换整个房间）。

**具体示例**：
```javascript
// 虚拟 DOM 本质是普通对象
const vdom = {
  type: "div",
  props: { className: "container" },
  children: [
    { type: "h1", props: {}, children: ["标题"] },
    { type: "p", props: {}, children: ["内容"] }
  ]
};

// React Diff 算法简化流程
// 1. 比较元素类型：类型不同 → 整个子树替换
// 2. 同类型元素：只更新变化的属性
// 3. 列表对比：用 key 标识元素，最小化移动操作

// 伪代码
function diff(oldVdom, newVdom) {
  if (oldVdom.type !== newVdom.type) {
    return { type: "REPLACE", newVdom };
  }
  if (typeof oldVdom.children === "string" &&
      oldVdom.children !== newVdom.children) {
    return { type: "TEXT", text: newVdom.children };
  }
  // ... 递归比较子节点
}
```

**为什么需要它**：直接操作 DOM 性能开销大，虚拟 DOM 批量计算差异后一次性更新，大幅减少 DOM 操作次数。

**与相关术语的对比和区分**：虚拟 DOM 是"方案"，Diff 算法是"实现"。React 的 Fiber 架构是对虚拟 DOM 的进一步优化（可中断渲染）。

## 组件化开发

**一句话定义**：将界面拆分为独立、可复用的组件，每个组件封装自己的结构、样式和逻辑。

**通俗类比**：像搭积木——每块积木（组件）有自己的形状和颜色，按不同组合拼出不同的建筑（页面）。

**具体示例**：
```jsx
// React 组件化
function Button({ variant = "primary", children, onClick }) {
  return (
    <button className={`btn btn-${variant}`} onClick={onClick}>
      {children}
    </button>
  );
}

function Card({ title, children, footer }) {
  return (
    <div className="card">
      <div className="card-header"><h3>{title}</h3></div>
      <div className="card-body">{children}</div>
      {footer && <div className="card-footer">{footer}</div>}
    </div>
  );
}

// 使用
<Card title="用户信息">
  <p>姓名：Alice</p>
  <Button variant="danger" onClick={handleDelete}>删除</Button>
</Card>

// Vue 组件化
// UserCard.vue
<template>
  <div class="user-card">
    <h3>{{ name }}</h3>
    <slot></slot>
  </div>
</template>

<script setup>
defineProps(["name"]);
</script>
```

**为什么需要它**：提高代码复用性、降低维护成本、便于团队分工、支持独立测试。

**与相关术语的对比和区分**：组件化 vs 模块化。组件化是 UI 层面的拆分（视图+逻辑+样式）；模块化是 JS 代码层面的拆分（功能函数/类）。

---

## 状态管理

**一句话定义**：集中管理应用中的共享数据，解决多组件间的数据传递和同步问题。

**通俗类比**：像公司的共享文件夹——所有部门（组件）都从同一个地方读写数据，避免信息不一致。

**具体示例**：
```javascript
// ===== Redux (React) =====
// actions
const addTodo = (text) => ({ type: "ADD_TODO", text });

// reducer
function todoReducer(state = [], action) {
  switch (action.type) {
    case "ADD_TODO":
      return [...state, { id: Date.now(), text, done: false }];
    case "TOGGLE_TODO":
      return state.map(todo =>
        todo.id === action.id ? { ...todo, done: !todo.done } : todo
      );
    default:
      return state;
  }
}

// store
import { createStore } from "redux";
const store = createStore(todoReducer);

// React-Redux
function TodoList() {
  const todos = useSelector(state => state);
  const dispatch = useDispatch();
  return (
    <ul>
      {todos.map(t => (
        <li key={t.id} onClick={() => dispatch({ type: "TOGGLE_TODO", id: t.id })}>
          {t.text}
        </li>
      ))}
    </ul>
  );
}

// ===== Pinia (Vue 3, 推荐) =====
import { defineStore } from "pinia";

export const useTodoStore = defineStore("todos", {
  state: () => ({ todos: [] }),
  getters: {
    doneTodos: (state) => state.todos.filter(t => t.done),
  },
  actions: {
    addTodo(text) {
      this.todos.push({ id: Date.now(), text, done: false });
    },
    toggleTodo(id) {
      const todo = this.todos.find(t => t.id === id);
      if (todo) todo.done = !todo.done;
    },
  },
});

// 使用
const store = useTodoStore();
store.addTodo("学习 Pinia");
console.log(store.doneTodos);
```

**为什么需要它**：多组件共享数据时，prop 逐层传递（prop drilling）太繁琐，全局状态管理让数据流清晰可控。

**与相关术语的对比和区分**：Redux（严格单向数据流、函数式）vs Pinia（更轻量、支持组合式 API）vs MobX（响应式、更灵活）。小项目用 Context/Pinia，大项目用 Redux。

## 前端路由

**一句话定义**：在不刷新页面的情况下，根据 URL 切换显示不同的页面内容。

**通俗类比**：像单页 PPT——翻页（切换 URL）时内容变了，但不用重新打开文件（刷新页面）。

**具体示例**：
```javascript
// ===== Hash 路由 =====
// URL 格式：example.com/#/about
window.addEventListener("hashchange", () => {
  const hash = location.hash.slice(1) || "/";
  renderPage(hash);
});

// ===== History 路由 =====
// URL 格式：example.com/about
const router = {
  routes: {
    "/": () => renderHome(),
    "/about": () => renderAbout(),
    "/user/:id": (params) => renderUser(params.id),
  },
  navigate(path) {
    history.pushState(null, "", path);
    this.handleRoute();
  },
  handleRoute() {
    const path = location.pathname;
    // 匹配路由并渲染
  },
};

// React Router
import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">首页</Link>
        <Link to="/about">关于</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/user/:id" element={<User />} />
      </Routes>
    </BrowserRouter>
  );
}
```

**为什么需要它**：SPA 不刷新页面，需要路由来管理 URL 与页面内容的映射，支持浏览器前进/后退。

**与相关术语的对比和区分**：Hash 路由（有 `#`，兼容性好，不需要服务器配置）vs History 路由（URL 干净，需要服务器配合返回 index.html）。

## 服务端渲染（SSR）

**一句话定义**：在服务器上将组件渲染成 HTML 字符串，直接返回给浏览器，用户能更快看到内容。

**通俗类比**：餐厅端菜 vs 自助——SSR 是服务员直接把做好的菜端给你（服务器渲染好），CSR 是给你食材自己做（浏览器渲染）。

**具体示例**：
```javascript
// Next.js (React SSR)
// pages/index.js
export async function getServerSideProps() {
  const res = await fetch("https://api.example.com/data");
  const data = await res.json();

  return { props: { data } }; // 传递给组件的 props
}

function HomePage({ data }) {
  return (
    <div>
      <h1>{data.title}</h1>
      <p>{data.content}</p>
    </div>
  );
}

export default HomePage;

// Nuxt.js (Vue SSR)
// pages/index.vue
<script setup>
const { data } = await useFetch("https://api.example.com/data");
</script>

<template>
  <div>
    <h1>{{ data.title }}</h1>
    <p>{{ data.content }}</p>
  </div>
</template>
```

**为什么需要它**：改善首屏加载速度、提升 SEO（搜索引擎能直接抓取完整 HTML）、改善弱网环境体验。

**与相关术语的对比和区分**：SSR（每次请求都渲染，适合动态内容）vs SSG（构建时渲染，适合静态内容）vs CSR（客户端渲染，最简单但 SEO 差）。

---

## 静态站点生成（SSG）

**一句话定义**：构建时将页面预渲染成静态 HTML 文件，部署后直接返回文件，无需服务器计算。

**通俗类比**：像预制菜——所有菜提前做好装盘（构建时生成 HTML），客人来了直接上菜（返回文件），比现做（SSR）更快。

**具体示例**：
```javascript
// Next.js SSG
export async function getStaticProps() {
  const posts = await fetchPosts();
  return {
    props: { posts },
    revalidate: 60, // ISR：60秒后重新生成（可选）
  };
}

export async function getStaticPaths() {
  const posts = await fetchAllPosts();
  const paths = posts.map(post => ({
    params: { id: post.id.toString() },
  }));
  return { paths, fallback: false };
}

function BlogPost({ post }) {
  return <article><h1>{post.title}</h1></article>;
}

// VitePress / Docusaurus 等文档工具也是 SSG
```

**为什么需要它**：加载速度极快（纯静态文件）、可部署到 CDN、成本低（不需要服务器）。

**与相关术语的对比和区分**：SSG（构建时渲染，适合内容不频繁变化的页面）vs SSR（运行时渲染，适合动态内容）vs ISR（增量静态再生，兼顾两者优点）。

## 微前端

**一句话定义**：将大型前端应用拆分为多个独立开发、独立部署的小型应用，运行时组合成一个整体。

**通俗类比**：像购物中心——每个店铺（微应用）独立运营，但共享停车场、安保等基础设施（主应用提供的公共能力）。

**具体示例**：
```javascript
// ===== qiankun (基于 single-spa) =====
// 主应用注册子应用
import { registerMicroApps, start } from "qiankun";

registerMicroApps([
  {
    name: "vueApp",
    entry: "//localhost:8081",
    container: "#subapp-container",
    activeRule: "/vue",
    props: { token: "xxx" },
  },
  {
    name: "reactApp",
    entry: "//localhost:8082",
    container: "#subapp-container",
    activeRule: "/react",
  },
]);

start();

// ===== Module Federation (Webpack 5) =====
// webpack.config.js
new ModuleFederationPlugin({
  name: "host",
  remotes: {
    app2: "app2@http://localhost:3001/remoteEntry.js",
  },
  shared: { react: { singleton: true }, "react-dom": { singleton: true } },
});

// 主应用使用远程组件
const RemoteApp = React.lazy(() => import("app2/App"));
```

**为什么需要它**：解决大型项目（多团队协作）的技术栈统一、独立部署、增量升级等痛点。

**与相关术语的对比和区分**：qiankun（应用级隔离，基于路由切换）vs Module Federation（模块级共享，更灵活）。iframe 是最简单的微前端方案，但体验差（不共享状态、样式隔离、通信复杂）。
