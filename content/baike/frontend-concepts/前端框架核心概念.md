# 前端框架核心概念


> 📌 **导航**：本文是 **前端框架核心概念** 词条，属于 frontend-concepts 术语集。相关枢纽：[[HTML & CSS 核心概念]]、[[JavaScript 基础核心概念]]、[[React深入]]、[[Vue3核心]]、[[前端工程化核心概念]]。

---

## 定义

**一句话定义：** 前端框架核心概念是跨 React / Vue / Angular 的共性机制总纲——组件化拆分、虚拟 DOM 与 Diff 更新、声明式状态管理、前端路由、多种渲染策略；各框架把同一批机制做成不同 API，选型差异集中在"数据变了视图怎么知道该更新哪几处"。本页只做能力对比与归口索引，机制细节由各子词条与 [[React深入]]、[[Vue3核心]] 承载。

**通俗类比：** 三家电厂（React/Vue/Angular）发的都是"视图随状态自动更新"这一种电，差别在发电机组的接法；本页是并网调度台，只标"哪种故障去哪个车间"，不进车间修机器。

## 为什么需要它

原汇编 12 节把每个框架与每个机制平铺成一节，一个"状态变了视图为什么不更新"的问题要在 React Hooks、Vue 响应式、Angular Zone.js 三节各找一遍答案，而同一句"虚拟 DOM 减少 DOM 操作"在多处各写一遍。拆成四个共性机制子词条后，本页只留框架能力对比表与归口判据：一个机制只有一个权威词条，React / Vue 本体直接双链其 done 专条，不重复承载。

## 核心机制

同一件事，三家框架的落地方式对照如下；表格负责"有什么"，下面四条只讲"为什么这样归口"：

| 维度 | React | Vue 3 | Angular |
|---|---|---|---|
| 视图更新 | 重跑 render + Fiber 可中断 diff（[[React深入]]） | Proxy 精确依赖追踪 + PatchFlag（[[Vue3核心]]） | Zone.js 拦截异步后触发全树变更检测 |
| 逻辑复用 | Hooks（useState / useEffect / 自定义 Hook） | Composition API（ref / computed / watch） | Service + 依赖注入（@Injectable） |
| 共享状态 | Context / Redux / Zustand（[[前端状态管理]]） | Pinia / Vuex（[[前端状态管理]]） | Service + RxJS BehaviorSubject |
| 异步与模板 | JSX + Promise / Suspense | 单文件模板 + async setup | 装饰器模板 + RxJS 流（switchMap / debounceTime） |

1. **视图更新的共性是"减少真实 DOM 操作"，差异只在"怎么算出该改哪几处"**：无论虚拟 DOM diff 还是 Proxy 精准订阅，目标都是把一次状态变更摊成最小 DOM patch；通用算法与 key 的取舍见 [[虚拟 DOM 与 Diff 算法]]，两家框架的实现分别归 [[React深入]] 与 [[Vue3核心]]，本页不重复展开。
2. **组件化是 UI 的拆分，微前端是应用的拆分**：同一套"独立 + 可组合"思想在两个尺度上成立，从函数组件到 qiankun / Module Federation 的谱系见 [[组件化与微前端]]；框架选型解决不了跨团队协作的部署边界问题，那是后者的战场。
3. **状态管理解的是"共享数据怎么流"，不是"数据放哪"**：prop drilling、单向数据流、响应式 store 是同一问题的三种答案，跨框架选型判据统一收在 [[前端状态管理]]；React 的 useState/useReducer 与 Vue 的 reactive 是框架自带的局部状态原语，不等同于全局 store。
4. **路由与渲染策略是框架之外的两层决策**：SPA 用 URL 切内容归 [[前端路由]]；而"HTML 何时产生"是 CSR / SSR / SSG / ISR 的独立取舍——SSR 每次请求现渲、SSG 构建时预生成、ISR 折中增量再生，与选哪个框架正交，本页只留这一行判据，深入实现待各框架服务端方案各自收敛。

## 具体示例

典型问法"React 和 Vue 到底差在哪"：React 把一切交给"重跑 render + diff"，心智是"状态变了整棵子树重新算"；Vue 用 Proxy 在读取时收集依赖，状态变了只通知订阅它的节点；Angular 用 Zone.js 在所有异步之后统一跑一遍变更检测。三者共同目标都是最小化 DOM 操作，差别在"如何知道要改哪"——被动重算、精准订阅、还是全量检查。再往下就落到各子词条的机制里。

## 何时用与何时不用

- **用**：跨框架比较、面试"React vs Vue vs Angular"、判断一个 bug 属于哪个机制层（更新？状态？路由？渲染时机？）——先在本表定位归口再进子词条。
- **不用**：当某一框架的教程用——本页没有任何可运行的组件代码，跳一层才看得到配置与 API；也别把能力对比当成互斥菜单，真实项目常常混用（Angular 里也虚拟 DOM，React 里也精准订阅 memo / Selector）。

## 优劣与代价

✅ 一个机制一个权威词条，版本行为变了只改一处，枢纽页与子词条不会互相打脸。
✅ "维度 × 框架"的对比把复习从背 API 名变成对信号，能迁移到 Svelte / Solid 这类新框架。
⚠️ 框架能力表有半衰期（Angular 已引入 Signals、React 有 Compiler 自动 memo），本页判据比 API 名单耐久，但结论仍建议对照官方文档复核。
⚠️ Angular 在本库无独立专条，其 DI / RxJS / Zone.js 只在对比表与"视图更新"行承载，深度细节按 §5 不据推测补写。

## 与相关概念的区别

- **vs [[React深入]] / [[Vue3核心]]**：那两条是单框架的内部机制（Fiber、PatchFlag），本页是跨框架能力对照与共性机制归口；问"React 怎么实现"看那条，问"三家怎么选"看本页。
- **vs [[前端工程化核心概念]]**：那条解"代码怎么变成产物"（构建、转译、类型），本页解"界面随状态怎么更新"（组件、diff、状态、路由）；tree-shaking 属那边，虚拟 DOM 属这边。
- **vs [[HTML & CSS 核心概念]] / [[JavaScript 基础核心概念]]**：那两条是语言与样式底座，本页是建立在 JS 之上的框架层抽象。

## 常见误区

- 以为虚拟 DOM 一定比直接操作 DOM 快，忽略它在简单场景反而是额外开销。
- 把框架自带的局部状态（useState / ref）当成全局状态管理，用 props 一层层穿透共享数据。
- 认为 SSR 一定比 CSR 快，混淆"首屏可见（HTML 先到）"与"可交互（JS 水合后）"两件事。

## 面试速答

> 🎯 前端框架的共性机制是"视图随状态自动更新"：组件化拆分、虚拟 DOM 或精准订阅算最小改动、集中式状态管理、前端路由切页、CSR/SSR/SSG 选渲染时机；React 重算+diff、Vue Proxy 订阅、Angular Zone.js 全树检测。
