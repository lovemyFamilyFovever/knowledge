# 浏览器单线程与多线程模型

> 📌 **导航**：本文是 **JS 单线程与浏览器多线程的分工模型** 词条。宏任务/微任务/Promise/async 的**用法**见 [[JavaScript 异步编程（事件循环·Promise·async·await·Generator）]]，本文讲的是它背后的**引擎与浏览器架构**；应用案例见 [[Object.defineProperty 与 Vue 响应式]] 的异步批更新一节。

## 定义

**一句话定义：** JavaScript 是单线程的——你的代码永远只有一个调用栈；但**浏览器是多线程进程**。异步的本质不是 JS 会分身，而是"主线程把等待外包给浏览器其他线程，回调排队等主线程空闲"。由此引出核心辨析：**并发（concurrence，排队处理）≠ 并行（parallel，真同时）**。

**通俗类比：** 烤肉店只有你一个老板兼厨师（单线程）。客人点羊排要烤 20 分钟，你不会站在炉前死等，而是放进烤炉定好计时器（**外包给 Web API/浏览器线程**），立刻喊"下一位"；计时器响了，烤好的羊排放到取餐台（**回调进任务队列**），但你必须等手头这单完全做完才能去管它（**事件循环**）。

## 为什么偏偏是单线程

JS 诞生第一职责是操作 DOM。若两个线程一个改节点、一个删节点，浏览器将无法保证渲染一致性、加锁又太重——**单线程是引擎主动的设计选择，异步是单线程的生存之道**。"JS 同时做很多事"是切换极快 + 任务外包造成的错觉。

## 分工：setTimeout 到底在谁手里跑

`setTimeout` 的计时**不是 JS 主线程干的**。浏览器内核里有专门的线程：

| 浏览器侧线程 | 外包的任务 | 完成后 |
|------|------|------|
| 定时器线程 | setTimeout / setInterval 计时 | 回调推入宏任务队列 |
| 网络线程 | AJAX / fetch | 响应到达后回调入队 |
| 事件处理线程 | click / input 等监听 | 事件回调入队 |

主线程只负责**执行回调**。而且任务一旦丢出去就失去控制权——不能暂停它、不能调它的优先级。

`setInterval` 倒计时"一直在刷"却不阻塞，同理：JS 只做轻量的改数值/改 DOM，真正的重绘由浏览器渲染管线按约 60fps 节奏统一执行；动画更讲究的写法是 `requestAnimationFrame`，把回调对齐每一帧。

## 并发 vs 并行：与 C# / Java 的分水岭

- **JS 模式（并发/时间分片）**：所有配好的菜最终都由你一个人摆盘——同一瞬间永远只有一件事在执行。
- **C#/Java/Go/C++ 模式（并行/空间分核）**：行政总厨指挥多个主厨，多核 CPU 上两把火真的同一秒一起烧，每个线程一个独立调用栈。

三件 C# 做得到、JS 主线程**绝对做不到**的事：

1. **纯计算并行**：JS 里写 1 加到 100 亿的循环，整个页面卡死（唯一的厨子被困住）；C# 丢给后台线程，UI 照常丝滑，还能四线程并行压四张图。
2. **线程生杀大权**：`thread.Start()/Suspend()/Priority` 精细调度；JS 的定时器丢出去就只能等。
3. **锁（lock）**：真并行会抢共享资源，C# 必须 `lock` 防竞态。**JS 完全不需要 lock——所有代码在同一线程上排队执行，天然不存在两个操作同时改一个变量**。这是单线程模型最大的心智红利。

> ⚠️ JS 想要真并行计算并非绝路：**Web Worker** 另开线程跑重计算，代价是不共享内存、只能消息通信——但它是"另雇一个人"，不是"把自己劈成两半"。

## 回扣 Vue：这个模型如何撑起批更新

连续三次 `data.name = ...`：三次 setter → 三次 `dep.notify()` → `queueWatcher` 去重后队列里只有一个 Watcher，首次入队时 `Promise.resolve().then(flush)` 排进微任务；同步代码跑完、栈清空，事件循环进入微任务阶段 flush 一次——**视图只更新一次**。没有"单线程 + 任务队列"这套调度，就没有响应式框架的批处理。（源码细节见 [[Object.defineProperty 与 Vue 响应式]]。）

## 面试视角

> 🔍 **追问：单线程和异步矛盾吗？** 不矛盾，异步恰是单线程的生存策略：等待类工作外包给浏览器线程，主线程永不空等阻塞；回调统一经任务队列排队回来。

> 🔍 **追问：为什么 Promise.then 比 setTimeout(fn, 0) 先执行？** 微任务队列在当前宏任务结束、渲染前被完全清空；setTimeout 的回调属于宏任务，要等下一个事件循环周期。

> 🎯 关键要点："JS 单线程为什么异步请求不卡页面"这道题的满分答法是三件套——**外包（浏览器多线程）+ 排队（任务队列）+ 调度（事件循环）**；再补一句并发 vs 并行的本质区别（时间分片 vs 空间分核），就和背题的区分开了。
