# JavaScript 现代语法糖（解构·展开·可选链·空值合并）

> 📌 **导航**：本文是 **JavaScript 现代语法糖（解构·展开·可选链·空值合并）** 词条，属于 frontend-concepts 术语集。相关枢纽：[[JavaScript 基础核心概念]]、[[Vue3核心]]。

## 定义

**一句话定义：** 四个解决同一类问题的语法——解构按结构从数组/对象里取值赋给变量，展开（`...`）把一个集合摊平成元素或把剩余收集起来，可选链 `?.` 让中途遇到 null/undefined 直接返回 undefined，空值合并 `??` 只在 null/undefined 时取默认值。

**通俗类比：** 拆快递不必一件件翻内包装（解构）；把巧克力倒出来或捡回盒子（展开与收集）；问路时任意一环查不到就答"不知道"（可选链）；只在"真的没人"时才启用备选（`??`，0 与空串都算有人）。

## 为什么需要它

业务代码里大量篇幅花在"从复杂结构取字段"和"防 undefined 抛错"上：`a && a.b && a.b.c` 与 `options.x || default` 既啰嗦又会误伤合法假值。这四样把取值与判空写成声明式，减少临时变量与防御性分支。

## 核心机制

- **解构**：数组按位置 `const [a, b, ...rest] = arr`（可用 `[, second]` 跳位），对象按属性名并可重命名与给默认值 `const { name: userName, city = "未知" } = obj`，支持嵌套与函数参数解构。它是赋值模式，不是第三种声明方式；默认值只在属性缺失（undefined）时生效。
- **展开与剩余**：同一个 `...` 两个方向——在调用/字面量位置展开（`[...arr1, 4]`、`{ ...config, ...override }` 后者覆盖前者），在声明左侧或形参位置收集（`sum(...numbers)`）。展开是浅拷贝，嵌套对象仍共享引用。
- **可选链**：`user?.address?.street`、方法调用 `user.greet?.()`、下标 `list?.[0]`；任一环节为 null/undefined 就短路返回 undefined，且整个后续链条一起短路，不会去调用不存在的方法。
- **空值合并**：`count ?? 10` 只在左侧为 null/undefined 时取右值，`0`、`""`、`false`、`NaN` 都被保留——这正是它与 `||` 的全部差别；`??` 不能与 `||`/`&&` 无括号混写。两者常搭配：`user?.address?.city ?? "未知城市"`。

## 具体示例

```javascript
const [a, b, ...rest] = [1, 2, 3, 4];      // rest = [3, 4]
const { name, role = "user" } = { name: "Alice" };
const merged = { ...{ theme: "dark", lang: "zh" }, ...{ lang: "en" } };
const copy = [...[1, 2, 3]];                 // 浅拷贝

const user = { name: "Alice", address: { street: "Main St" } };
user?.phone?.mobile;                          // undefined，不抛错
const city = user?.address?.city ?? "未知城市"; // "未知城市"
const count = 0;
count || 10;                                  // 10（0 被当假值）
count ?? 10;                                  // 0
```

## 何时用与何时不用

- **用**：函数入参形状稳定时用参数解构代替一串 `options.x`；不可变更新用 `{ ...state, patch }`；读外部/接口数据用 `?.` 加 `??` 兜底；只要 falsy 就走默认时用 `||`（如空串也当没填）。
- **不用**：别对深层可变对象用展开当深拷贝（改嵌套会串味）；别在解构函数参数时不给形参默认值又允许调用方不传（`f()` 直接抛错）；别把 `?.` 用在赋值左侧。

## 优劣与代价

✅ 取值与判空从过程式防御变成一行声明，可读性与重构安全性同时上升。
✅ `??` 把"缺值"与"假值"分开，修掉 `||` 吞 0 与空串这一类长期 bug。
⚠️ 解构嵌套写深后 diff 与跳转都变难，多层 `?.` 也可能把本该抛错的数据结构问题静默成 undefined。
⚠️ 展开是浅拷贝且逐层复制，大对象高频展开有性能与别名两份代价。

## 与相关概念的区别

- **vs [[JavaScript 作用域与 this]]**：解构与展开管"值怎么进出结构"，var/let/const 管"绑定怎么建立"；`const {a} = obj` 是两者叠用。
- **vs TypeScript 的解构与工具类型**：类型侧只改编译期形状（见 [[TypeScript深入]]），运行时语义完全由本条决定。
- **vs 对象的 `Object.assign`**：assign 就地改第一个参数且链式返回，展开产出新对象——不可变更新用后者。

## 常见误区

- 以为 `{ ...obj }` 得到的是深拷贝，改嵌套属性不会影响原对象。
- 以为 `??` 和 `||` 等价，只是新一点的写法。
- 以为 `a?.b.c` 会替整条链每一环判空，b 为空时也不会抛错。

## 面试速答

> 🎯 解构按结构取值（可重命名/默认值/嵌套/参数），`...` 双向：展开或收集且只浅拷贝；`?.` 遇 null/undefined 短路返回 undefined，`??` 只把 null/undefined 当缺值，`0`/`""` 保留——这是它与 `||` 的分界。
