# 前端工程化核心概念


> 📌 **导航**：本文是 **前端工程化核心概念** 词条，属于 frontend-concepts 术语集。相关枢纽：[[HTML & CSS 核心概念]]、[[JavaScript 基础核心概念]]、[[React深入]]、[[Vue3核心]]、[[前端工程化核心概念]]。

---

## 定义

**一句话定义：** 前端工程化按"要解决的问题"分成五族工具链——构建打包、语法转换与规范检查、样式组织、构建期优化、离线交付；类型系统与依赖管理另各有既有专条。本页是按问题归口的枢纽页，只负责"遇到这个症状该看哪一条"，机制与配置细节由各子词条承载。

**通俗类比：** 像工厂的工序看板：锻造（构建）、质检（规范）、配件标准（类型）、仓储（包管理）、物流（交付）各有车间，本页只标"这道工序归哪个车间"，不放进车间里看机器。

## 为什么需要它

原汇编 12 节把每个工具平铺成一节，一次"新项目怎么建"的决策要在 Webpack、Vite、构建优化三节里自己拼，而同一句话（如"lock 文件保一致"）在包管理与 Monorepo 两节各写一遍。拆成五个族子词条后，本页只留选型表与判据：一个工具只有一个权威词条，包管理、类型、仓库组织这些库内已有专条的概念直接双链，不重复承载。

## 核心机制

结构、转换、样式、交付四条轴各有归口；下表负责"有什么"，下面五条只讲"为什么这样归口"：

| 现象 / 面试问法 | 归口 | 关键抓手 | 详见 |
|---|---|---|---|
| 大项目起个 dev 要等几十秒 | 构建工具 | Vite 开发态不打包，走原生 ESM | [[JavaScript 构建工具（Webpack 与 Vite）]] |
| 老浏览器不认 `?.` 与 async | 语法转换 | Babel preset-env 按 targets 降级 | [[代码规范与转换工具链（Babel · ESLint · PostCSS）]] |
| 同一文件两种写法，review 全在吵格式 | 规范检查 | ESLint 管对错、Prettier 管好看不 | [[代码规范与转换工具链（Babel · ESLint · PostCSS）]] |
| CSS 要补前缀、想用未来语法 | CSS 转换 | PostCSS 插件链（autoprefixer 等） | [[代码规范与转换工具链（Babel · ESLint · PostCSS）]] |
| 两个组件的 `.title` 互相覆盖 | 样式组织 | CSS Modules 编译期哈希类名 | [[CSS 预处理与模块化（Sass·Less·CSS Modules）]] |
| 主题色改一次要全文替换 | 样式组织 | Sass 变量 / mixin / 嵌套 | [[CSS 预处理与模块化（Sass·Less·CSS Modules）]] |
| 重构改字段名不敢动 | 类型系统 | TS 编译期类型检查与推断 | [[TypeScript深入]] |
| 同事装出来的依赖版本不一样 | 包管理 | lock 文件锁精确版本 | [[包管理器与构建工具]] |
| 多个相关项目要共享组件库 | 仓库组织 | pnpm workspace 与 Monorepo | [[前端工程化]] |
| 首屏 bundle 过大 | 构建优化 | tree shaking + code splitting | [[前端构建优化策略]] |
| 断网也能打开、能加桌面 | 离线交付 | manifest + Service Worker | [[PWA 渐进式 Web 应用]] |

1. **开发态与产物态是两套机制，别用一个工具的名字解释另一个**：冷启动慢属于开发态（依赖图要先构建），产物过大属于构建期（未用代码与拆包粒度），把两件事混称"打包慢"就会开错药方——两段分别归 [[JavaScript 构建工具（Webpack 与 Vite）]] 与 [[前端构建优化策略]]。
2. **转换、检查、类型是三件正交的事**：Babel 与 PostCSS 只翻译语法、不判断对错，ESLint 只读源码、不产出新语法，类型检查发生在 TypeScript 自己的编译过程里；混称"编译器"是面试最常见的失焦，前两者见 [[代码规范与转换工具链（Babel · ESLint · PostCSS）]]，类型层直接归既有专条 [[TypeScript深入]]，本页不再展开。
3. **包管理解"依赖从哪来"，Monorepo 解"代码放哪个仓库"**：`npm`/`yarn`/`pnpm` 的差异（扁平 `node_modules` 与硬链接、严格隔离）与 lock 文件语义在 [[包管理器与构建工具]]，多包仓库的组织收益与成本、workspace 与 Turborepo/Nx 的取舍在 [[前端工程化]]；同一个 `pnpm-workspace.yaml` 写两遍只会漂移，故本页只留一行判据。
4. **CSS 侧的三个问题互不替代**：值复用与嵌套是预处理，作用域隔离是 CSS Modules，前缀与兼容是 PostCSS；写主题切换时还要再多分一层——编译期变量与运行时可改的 CSS 变量不是一件事，前者见 [[CSS 预处理与模块化（Sass·Less·CSS Modules）]]，后者见 [[CSS 变量与动画]]。
5. **构建优化到产物离开构建机为止，再往后是另外两条线**：字节数与块数在构建期定生死，见 [[前端构建优化策略]]；到达浏览器后的优先级与渲染代价在 [[资源加载优化]] 与 [[Web性能优化]]；产物上线之后的自动化环节在 [[构建流水线与 CI-CD 工具]]，把三段混成一锅就会在错误的一侧调参数。

## 具体示例

一次典型选型：新项目要开发快 → Vite；用户里还有旧浏览器 → preset-env 的 `targets` 加 autoprefixer；组件多、样式怕撞 → CSS Modules；要跨包复用组件库 → pnpm workspace 引 `workspace:*`；首屏偏慢 → 先跑 bundle 分析定位体积，再决定拆包粒度与依赖替换；最后才谈离线与桌面入口（manifest + Service Worker）。每一跳都只查一个词条。

## 何时用与何时不用

- **用**：遇到任何工程化报错或选型问法，先在上面的表里按"现象"定位归口，再进子词条看机制；面试体系化复习也从本页出发串五族。
- **不用**：当教程用——本页一律没有 loader 规则、插件名单这类可运行细节，跳一层才能看到配置代码；也别把它当互斥菜单，真实项目常同时踩三条线（转译 + 类型 + 拆包最常见）。

## 优劣与代价

✅ 一个工具一个权威词条，版本行为变了只改一处，枢纽页与子词条不会互相打脸。
✅ "现象 → 归口"的映射把复习从背工具名变成对信号，能迁移到新出现的构建器。
⚠️ 工程化知识的半衰期很短（ESLint 的配置格式、Vite 的版本都在动），本页判据比命令耐久，但结论仍建议对照官方文档复核。
⚠️ 语言层与工具层的边界固定在本族与 [[JavaScript 基础核心概念]]、[[HTML & CSS 核心概念]] 之间，跨层问题（如 `import()` 动态导入既属模块语法又属拆包手段）需要两边都读。

## 与相关概念的区别

- **vs [[前端工程化]]**：那条讲理念与组织形态（构建链、Monorepo、微前端），本页是工具概念的归口索引；选工具看本页，定组织看那条。
- **vs [[JavaScript 基础核心概念]]**：语言本身怎么运行在那边，工具链怎么消费它在本页（tree shaking 的能力来自 ESM 的静态结构，实现来自构建工具）。
- **vs [[包管理器与构建工具]]**：那条是跨语言的通用视角（含 pip / cargo / Maven），本族只看前端这一套。

## 常见误区

- 把工程化等同于"会配 Webpack"，于是解释不了为什么换 Vite 后配置几乎消失。
- 把 Babel、ESLint、TypeScript 统称"编译器"，说不清各自在哪个阶段做什么。
- 以为用了构建工具就自动获得 tree-shaking，忽略它依赖 ES Modules 的可静态分析结构。

## 面试速答

> 🎯 工程化按问题分五族：构建（Webpack/Vite）、转换与规范（Babel/ESLint/PostCSS）、样式组织（Sass/CSS Modules）、构建优化、PWA 离线交付；类型与包管理走既有专条。先按现象定归口再谈配置。
