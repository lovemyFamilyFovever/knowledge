## Webpack

**一句话定义**：将前端资源（JS、CSS、图片等）打包成浏览器能高效加载的 bundle 文件。

**通俗类比**：像快递打包站——把散落各处的商品（各种文件）分拣、合并、压缩，装进合适的包裹（bundle）里发出去。

**具体示例**：
```javascript
// webpack.config.js
const path = require("path");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  entry: "./src/index.js",                    // 入口
  output: {
    path: path.resolve(__dirname, "dist"),    // 输出目录
    filename: "[name].[contenthash].js",      // 输出文件名（带哈希）
    clean: true,                              // 清理旧文件
  },
  module: {
    rules: [
      {
        test: /\.jsx?$/,
        exclude: /node_modules/,
        use: "babel-loader",                  // JS/JSX 转译
      },
      {
        test: /\.css$/,
        use: ["style-loader", "css-loader"], // CSS 处理链
      },
      {
        test: /\.(png|jpg|gif)$/,
        type: "asset/resource",               // 图片资源
      },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({ template: "./public/index.html" }),
  ],
  optimization: {
    splitChunks: {                            // 代码分割
      chunks: "all",
    },
  },
};
```

**核心概念**：
```javascript
// entry —— 打包起点
entry: {
  main: "./src/index.js",
  vendor: "./src/vendor.js",
},

// loader —— 处理非 JS 文件
// file-loader → asset/resource（Webpack 5）
// babel-loader → 转译 JS
// css-loader → 解析 CSS

// plugin —— 扩展构建能力
// HtmlWebpackPlugin → 自动生成 HTML
// MiniCssExtractPlugin → 提取 CSS 到独立文件
// DefinePlugin → 定义全局常量

// code splitting —— 代码分割
// 动态 import()
const LazyComponent = React.lazy(() => import("./HeavyComponent"));

// tree shaking —— 移除未使用的代码（ES Modules 静态分析）
import { specificFunction } from "./utils"; // 只打包用到的函数
```

**为什么需要它**：模块化开发、代码压缩、资源优化、兼容性处理（polyfill）、开发体验（HMR）。

**与相关术语的对比和区分**：Webpack（配置灵活、功能全面、但配置复杂）vs Vite（开箱即用、极快的开发启动、基于 ESM）。

## Vite

**一句话定义**：基于原生 ES Modules 的极速前端构建工具，开发时无需打包。

**通俗类比**：Webpack 像把所有食材提前做好再上菜（打包后才能运行）；Vite 像按需现做（浏览器请求哪个模块就加载哪个），开餐速度极快。

**具体示例**：
```javascript
// vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import path from "path";

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "src"),
    },
  },
  server: {
    port: 3000,
    open: true,
    proxy: {
      "/api": {
        target: "http://localhost:8080",
        changeOrigin: true,
      },
    },
  },
  build: {
    outDir: "dist",
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ["react", "react-dom"],
        },
      },
    },
  },
});

// 开发时：浏览器直接通过 ESM 加载模块
// <script type="module" src="/src/main.jsx"></script>
// 浏览器请求 main.jsx → Vite 实时转换返回
// main.jsx 中 import App → 浏览器继续请求 App.jsx
// 无需打包，按需加载，启动速度接近零

// 生产构建：用 Rollup 打包
// npx vite build
```

**为什么需要它**：Webpack 冷启动慢（大项目可能几十秒），Vite 利用浏览器原生 ESM，开发时几乎零等待。

**与相关术语的对比和区分**：Vite 开发用 ESM（无需打包），生产用 Rollup（优化打包）。Webpack 始终打包。Vite 兼容性要求较高（不支持低版本浏览器的开发模式）。

## Babel

**一句话定义**：JavaScript 编译器，将新语法转换为兼容旧环境的代码。

**通俗类比**：像翻译官——把"新潮语言"（ES6+）翻译成"所有人都能听懂的话"（ES5），确保老浏览器也能运行。

**具体示例**：
```javascript
// babel.config.json
{
  "presets": [
    ["@babel/preset-env", {
      "targets": "> 0.25%, not dead",
      "useBuiltIns": "usage", // 按需引入 polyfill
      "corejs": 3
    }],
    "@babel/preset-react",
    "@babel/preset-typescript"
  ],
  "plugins": [
    "@babel/plugin-proposal-optional-chaining",
    ["@babel/plugin-proposal-decorators", { "legacy": true }]
  ]
}

// 输入（ES6+）
const fn = async () => {
  const result = await fetch("/api");
  const [a, ...rest] = [1, 2, 3];
  return result.json();
};

// Babel 输出（ES5）
var fn = regeneratorRuntime.mark(function _callee() {
  var result, ref, a, rest;
  return regeneratorRuntime.wrap(function _callee$(_context) {
    while (1) switch (_context.prev = _context.next) {
      case 0:
        _context.next = 2;
        return fetch("/api");
      case 2:
        result = _context.sent;
        ref = [1, 2, 3];
        a = ref[0];
        rest = ref.slice(1);
        _context.next = 7;
        return result.json();
      case 7:
        return _context.abrupt("return", _context.sent);
    }
  }, _callee);
});
```

**为什么需要它**：JavaScript 标准每年更新，但浏览器支持不一致，Babel 让开发者能放心使用最新语法。

**与相关术语的对比和区分**：Babel（JS 转译）vs TypeScript（TS→JS 编译）vs PostCSS（CSS 转译）。三者常配合使用。

## ESLint

**一句话定义**：JavaScript/TypeScript 代码静态检查工具，找出潜在错误并强制代码规范。

**通俗类比**：像代码的"语法老师"——你写的代码哪里有错、哪里不规范，它会标出来并告诉你怎么改。

**具体示例**：
```javascript
// .eslintrc.js
module.exports = {
  root: true,
  env: { browser: true, es2021: true, node: true },
  extends: [
    "eslint:recommended",           // 推荐规则
    "plugin:react/recommended",     // React 规则
    "plugin:react-hooks/recommended",
    "plugin:@typescript-eslint/recommended",
    "prettier",                     // 关闭与 Prettier 冲突的规则
  ],
  parser: "@typescript-eslint/parser",
  plugins: ["react", "react-hooks", "@typescript-eslint"],
  rules: {
    "no-unused-vars": "warn",
    "no-console": "warn",
    "react/prop-types": "off",
    "react-hooks/rules-of-hooks": "error",
    "react-hooks/exhaustive-deps": "warn",
    "@typescript-eslint/explicit-function-return-type": "off",
  },
  // 或使用 flat config（ESLint 9+）
  // eslint.config.js
};

// 常用命令
// npx eslint src/           # 检查
// npx eslint src/ --fix     # 自动修复
```

**为什么需要它**：统一团队代码风格，提前发现潜在 bug，减少 code review 的沟通成本。

**与相关术语的对比和区分**：ESLint（逻辑/质量规则）vs Prettier（代码格式化）。ESLint 检查"写得对不对"，Prettier 检查"写得好看不"。两者互补，常配合使用。

## TypeScript

**一句话定义**：JavaScript 的超集，添加了静态类型系统，编译后生成纯 JavaScript。

**通俗类比**：像给 JS 代码上了"保险"——定义好类型后，编译器能在运行前就发现类型错误，避免低级 bug。

**具体示例**：
```typescript
// 基础类型
let name: string = "Alice";
let age: number = 25;
let isStudent: boolean = false;
let items: string[] = ["a", "b"];
let tuple: [string, number] = ["age", 25];

// 接口 —— 定义对象结构
interface User {
  id: number;
  name: string;
  email?: string;        // 可选属性
  readonly role: string; // 只读属性
}

// 泛型 —— 类型参数化
function identity<T>(arg: T): T {
  return arg;
}
identity<string>("hello");  // 显式指定
identity(123);              // 自动推断为 number

// 类型守卫 —— 缩小类型范围
function process(value: string | number) {
  if (typeof value === "string") {
    return value.toUpperCase(); // TS 知道这里是 string
  }
  return value.toFixed(2);     // TS 知道这里是 number
}

// 类型推断
const x = 10; // TS 自动推断为 number
const arr = [1, 2, 3]; // 推断为 number[]

// 声明文件 —— 为 JS 库提供类型
// types/global.d.ts
declare global {
  interface Window {
    __INITIAL_DATA__: Record<string, unknown>;
  }
}

// 条件类型
type IsString<T> = T extends string ? "yes" : "no";
type A = IsString<string>;  // "yes"
type B = IsString<number>;  // "no"
```

**为什么需要它**：大型项目中，类型系统能捕获大量运行时才暴露的 bug，重构更安全，IDE 智能提示更精准。

**与相关术语的对比和区分**：TypeScript（静态类型、编译时检查）vs JavaScript（动态类型、运行时才发现）。TS 最终编译为 JS，浏览器只认 JS。

## npm / yarn / pnpm

**一句话定义**：JavaScript 包管理工具，负责安装、管理项目依赖和脚本执行。

**通俗类比**：像应用商店——npm/yarn/pnpm 是商店，package.json 是购物清单，node_modules 是购物车，lock 文件是"已购买确认单"。

**具体示例**：
```json
// package.json
{
  "name": "my-app",
  "version": "1.0.0",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "lint": "eslint src/",
    "test": "vitest"
  },
  "dependencies": {
    "react": "^18.2.0",
    "react-dom": "^18.2.0"
  },
  "devDependencies": {
    "vite": "^5.0.0",
    "@vitejs/plugin-react": "^4.0.0",
    "typescript": "^5.3.0"
  }
}

// 命令对比
// npm install react          → npm install react
// yarn add react             → yarn add react
// pnpm add react             → pnpm add react

// lock 文件作用：锁定精确版本
// package-lock.json (npm)
// yarn.lock (yarn)
// pnpm-lock.yaml (pnpm)

// pnpm 工作区
// pnpm-workspace.yaml
packages:
  - "packages/*"
  - "apps/*"
```

**为什么需要它**：自动管理依赖关系和版本，lock 文件确保团队成员安装相同的依赖版本。

**与相关术语的对比和区分**：npm（官方默认、node_modules 扁平结构）→ yarn（Facebook 推出、并行安装更快）→ pnpm（硬链接/符号链接、省磁盘、严格依赖隔离）。

## Monorepo

**一句话定义**：将多个项目放在同一个仓库中管理，共享依赖和工具链。

**通俗类比**：像一个大院子里住着多户人家——共享花园（公共依赖）、保安（统一构建）、停车场（工作区管理）。

**具体示例**：
```yaml
# pnpm-workspace.yaml
packages:
  - "packages/*"
  - "apps/*"
```

```json
// 根目录 package.json
{
  "scripts": {
    "dev": "pnpm -r run dev",
    "build": "pnpm -r run build",
    "lint": "pnpm -r run lint"
  }
}
```

```
monorepo/
├── package.json
├── pnpm-workspace.yaml
├── apps/
│   ├── web/          # 主应用
│   │   ├── package.json
│   │   └── src/
│   └── admin/        # 后台管理
│       ├── package.json
│       └── src/
└── packages/
    ├── ui/           # 共享 UI 组件库
    │   ├── package.json
    │   └── src/
    ├── utils/        # 共享工具函数
    │   ├── package.json
    │   └── src/
    └── tsconfig/     # 共享 TypeScript 配置
```

```javascript
// apps/web/package.json
{
  "dependencies": {
    "@myorg/ui": "workspace:*",    // 引用内部包
    "@myorg/utils": "workspace:*"
  }
}

// 使用
import { Button } from "@myorg/ui";
import { formatDate } from "@myorg/utils";
```

**为什么需要它**：多个相关项目共享代码、统一构建、原子化提交（一个 PR 同时改多个包）。

**与相关术语的对比和区分**：Monorepo（一个仓库多项目）vs Multirepo（每个项目独立仓库）。工具：pnpm workspace（轻量）vs Lerna（成熟）vs Turbolorepo（高性能）。

## PostCSS

**一句话定义**：CSS 的 Babel——用插件转换 CSS 语法，添加未来特性或兼容性处理。

**通俗类比**：像 CSS 的预处理器中间层——Sass/Less 写的是"方言"，PostCSS 帮你翻译成"标准普通话"，同时还能自动加上"各地口音"（浏览器前缀）。

**具体示例**：
```javascript
// postcss.config.js
module.exports = {
  plugins: [
    require("autoprefixer"),      // 自动添加浏览器前缀
    require("postcss-preset-env"), // 使用未来 CSS 特性
    require("cssnano"),            // 压缩 CSS
  ],
};

/* 输入 */
.card {
  display: grid;
  transition: transform 0.3s;
  color: hsl(210 100% 50%);
}

/* 输出（添加前缀 + 兼容处理） */
.card {
  display: -ms-grid;
  display: grid;
  -webkit-transition: -webkit-transform 0.3s;
  transition: transform 0.3s;
  color: rgb(0, 102, 255);
}
```

**为什么需要它**：处理 CSS 兼容性、使用实验性 CSS 特性、压缩优化 CSS 文件。

**与相关术语的对比和区分**：PostCSS（CSS 转译工具，插件化）vs Sass/Less（CSS 预处理器，增加变量/嵌套/mixin）。PostCSS 是 Sass/Less 的补充，不是替代品。

---

## Sass / Less

**一句话定义**：CSS 预处理器，给 CSS 添加变量、嵌套、函数等编程能力。

**通俗类比**：CSS 是记流水账（写很多重复代码），Sass/Less 是写程序（用变量和函数减少重复）。

**具体示例**：
```scss
// Sass (SCSS 语法)
$primary: #1890ff;
$spacing-md: 16px;
$breakpoint-tablet: 768px;

@mixin flex-center {
  display: flex;
  justify-content: center;
  align-items: center;
}

.card {
  background: white;
  border-radius: 8px;
  padding: $spacing-md;

  // 嵌套
  &-header {
    font-size: 18px;
    font-weight: bold;
  }

  &-body {
    @include flex-center;
  }

  // 媒体查询内嵌
  @media (max-width: $breakpoint-tablet) {
    padding: 8px;
  }
}

// 函数
@function spacing($multiplier) {
  @return $spacing-md * $multiplier;
}

.item {
  margin: spacing(2); // 32px
}

// & 编译后
// .card { background: white; border-radius: 8px; padding: 16px; }
// .card-header { font-size: 18px; font-weight: bold; }
// .card-body { display: flex; justify-content: center; align-items: center; }
```

**为什么需要它**：原生 CSS 缺少变量、嵌套等能力，导致大量重复和维护困难。

**与相关术语的对比和区分**：Sass（.scss，功能最全，社区最大）vs Less（.less，语法更接近 CSS）。CSS 原生也在增加类似能力（CSS 变量、嵌套）。新项目可优先考虑原生 CSS + PostCSS。

## CSS Modules

**一句话定义**：CSS 类名自动局部化，避免全局命名冲突。

**通俗类比**：像给 CSS 类名加了"身份证号"——每个类名自动变成唯一的哈希值，不同组件的 `.title` 不会互相冲突。

**具体示例**：
```css
/* Button.module.css */
.primary {
  background: #1890ff;
  color: white;
}

.danger {
  background: #ff4d4f;
  color: white;
}
```

```jsx
// Button.jsx
import styles from "./Button.module.css";

function Button({ variant, children }) {
  return (
    <button className={styles[variant]}>
      {children}
    </button>
  );
}

// 渲染结果：
// <button class="Button_primary__a1b2c">...</button>
// 类名被自动哈希化，不会冲突
```

**为什么需要它**：SPA 中所有组件的 CSS 共享全局作用域，类名冲突是常见痛点。CSS Modules 让每个组件的样式独立。

**与相关术语的对比和区分**：CSS Modules（编译时类名哈希化）vs BEM（命名约定）vs CSS-in-JS（在 JS 中写样式）。CSS Modules 是最轻量的方案。

## PWA（渐进式 Web 应用）

**一句话定义**：让网页拥有原生应用的体验——离线可用、可添加到桌面、推送通知。

**通俗类比**：像给网站穿上"原生 App 的外衣"——用浏览器访问，但体验接近原生应用。

**具体示例**：
```javascript
// manifest.json —— 应用配置
{
  "name": "My PWA App",
  "short_name": "MyApp",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#1890ff",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}

// service-worker.js —— 离线缓存
const CACHE_NAME = "v1";
const ASSETS = ["/", "/index.html", "/style.css", "/app.js"];

self.addEventListener("install", (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then(cache => cache.addAll(ASSETS))
  );
});

self.addEventListener("fetch", (event) => {
  event.respondWith(
    caches.match(event.request).then(response => {
      return response || fetch(event.request); // 有缓存用缓存，没有走网络
    })
  );
});

// 注册 Service Worker
if ("serviceWorker" in navigator) {
  navigator.serviceWorker.register("/service-worker.js");
}
```

**为什么需要它**：离线可用、加载更快（缓存策略）、可添加到主屏幕、推送通知——让 Web 应用更接近原生体验。

**与相关术语的对比和区分**：PWA 是"渐进增强"策略（有 Service Worker 就增强，没有也能用）；Service Worker 是 PWA 的核心实现技术。

## 构建优化策略

**一句话定义**：通过各种手段减小打包体积、加快构建速度、提升运行时性能。

**通俗类比**：像搬家优化——先扔掉不要的东西（tree shaking），把东西分类打包（code splitting），选最快的搬家路线（构建加速）。

**具体示例**：
```javascript
// 1. Tree Shaking —— 移除未使用代码
// 确保使用 ES Modules（import/export）
import { specific } from "lodash-es"; // ✅ 可 tree shake
import _ from "lodash";               // ❌ 整个库引入

// package.json 配置副作用标记
{ "sideEffects": false }

// 2. Code Splitting —— 代码分割
// 路由级别分割（React）
const Home = React.lazy(() => import("./pages/Home"));
const About = React.lazy(() => import("./pages/About"));

// Webpack 配置
optimization: {
  splitChunks: {
    chunks: "all",
    cacheGroups: {
      vendor: {
        test: /[\\/]node_modules[\\/]/,
        name: "vendors",
        chunks: "all",
      },
    },
  },
},

// 3. 图片优化
// 使用 WebP 格式
// 图片懒加载
<img loading="lazy" src="photo.jpg" />

// 4. 构建速度优化
// Webpack
cache: { type: "filesystem" }, // 文件系统缓存
resolve: {
  extensions: [".js", ".jsx", ".ts", ".tsx"],
},

// 5. gzip/brotli 压缩
// Nginx 配置
// gzip on;
// brotli on;

// 6. CDN 加速
// 将静态资源部署到 CDN
// package.json
{ "homepage": "https://cdn.example.com" }

// 7. Bundle 分析
// npx webpack-bundle-analyzer stats.json
```

**为什么需要它**：用户感知的加载速度直接影响体验和转化率，构建优化是性能优化的第一道防线。

**与相关术语的对比和区分**：构建时优化（tree shaking、code splitting、压缩）vs 运行时优化（懒加载、缓存策略、CDN）。两者互补，缺一不可。
