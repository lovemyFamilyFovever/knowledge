# 文本预处理与中文分词


> 📌 **导航**：本文是 **文本预处理与中文分词** 词条，属 machine-learning 术语集。相关枢纽：[[自然语言处理NLP完全指南]]、[[词向量]]、[[命名实体识别与序列标注]]。

## 定义

**一句话定义：** 文本预处理是把原始文本清洗、切分、归一为可建模 token 序列的第一步，其中中文分词（Word Segmentation）负责在无空格的连续汉字流中标注词语边界，是中文 NLP 区别于英文的核心前置环节。

**通俗类比：** 英文天生带空格"词与词已用逗号隔开"，中文则像一整串没断句的拼音连写——分词就是先给它"断词"，后面词性、实体、向量才有得算。

## 为什么需要它

几乎所有下游任务（词向量、序列标注、分类）都以"词"为单位，中文没有天然分隔符，切错词会连锁污染整条管线——"研究生命的起源"切作"研究 / 生命"还是"研究生 / 命"直接决定语义。分词质量是中文 NLP 的地基。

## 核心机制

- **基于词典的匹配法**：最大匹配——正向（FMM）从左往右取最长词、逆向（BMM）从右往左、双向匹配再按经验择一；快但依赖词典、歧义与未登录词处理弱。
- **基于统计的分词**：把分词看成序列标注，用 HMM / 最大熵 / CRF 依字频共现学"字是否成词边界"，比纯词典更鲁棒。
- **深度学习分词**：BiLSTM / BiLSTM-CRF 端到端标注 BMES 边界标签，精度最高、能吃上下文歧义。
- **词性标注（POS）**：给每个词打名词 / 动词 / 形容词等标签，中文体系有 CTB、PKU、ICTCLAS；方法同样从规则、HMM 最大熵演进到 BiLSTM / Transformer。
- **其余预处理**：清洗去噪、去停用词、大小写与繁简归一、英文词形还原（lemmatization）与截词（stemming）。

| 分词方法族 | 代表 | 优点 | 短板 |
|-----------|------|------|------|
| 词典最大匹配 | FMM / BMM / 双向 | 快、可解释 | 歧义、未登录词 |
| 统计模型 | HMM / CRF | 抗歧义 | 需标注语料 |
| 深度模型 | BiLSTM-CRF | 精度高 | 算力与数据量大 |

## 具体示例

用 jieba：`jieba.lcut("自然语言处理是人工智能领域的重要方向")` 得 `['自然语言','处理','是','人工智能','领域','的','重要','方向']`；`cut_all=True` 为全模式、`lcut_for_search` 为搜索引擎模式，`jieba.add_word(...)` 可加自定义词典纠正领域专名——三种模式对应"精确 / 穷举 / 召回"不同取舍。

## 何时用 / 何时不用

- **用**：任何中文文本进入模型前；词云、检索、意图识别等以词为单位的应用。
- **不用**：字符级 / 子词模型（如 BPE、[[词向量]] 的 char n-gram 或现代 LLM 的 subword tokenizer）本就绕开词级分词，不必强行先切词。

## 优劣与代价

✅ 为下游任务提供干净、语义正确的词单元，直接影响整体上限。
⚠️ 分词错误会向上传播，且领域 / 新词是长期痛点。
⚠️ 词典法快但脆，深度法准但重，工程上常"词典兜底 + 模型精调"。

## 与相关概念的区别

- **vs 英文分词**：英文靠空格天然成词，中文必须先分词。
- **vs 词形还原 / 截词**：那是英文把复数、时态归一到词根；中文是"切边界"，两者问题不同。
- **vs 子词 / BPE**：现代大模型用 subword 直接喂字符级序列，弱化了对精确词级分词的依赖（见 [[大语言模型架构演进]]）。

## 常见误区

- 中文和英文一样，用空格就能直接切出正确的词，无需专门分词。
- 正向最大匹配、逆向最大匹配在任何句子上结果必然一致，随便选哪个都行。
- 用了 BERT 等大模型后，中文文本必须先人工分好词才能输入模型。

## 面试速答

> 🎯 文本预处理把原始文本清洗、切分、归一为可建模 token；中文分词是无空格汉字流里断词边界的地基任务，方法从词典最大匹配（FMM/BMM），到 HMM/CRF 统计，再到 BiLSTM-CRF 端到端；词性标注同属序列标注。工程常用 jieba 精确/全/搜索三模式加自定义词典。
> 🔍 追问：为什么逆向最大匹配常优于正向？（中文修饰语多在左、右侧组合更易暴露边界，减少误切成倾向）
> 🔍 追问：分词对下游影响有多大？（词单元错了，词向量、NER、分类全部连锁失真，属上游决定性环节）
