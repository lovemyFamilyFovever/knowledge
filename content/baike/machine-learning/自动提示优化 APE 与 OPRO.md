# 自动提示优化 APE 与 OPRO


> 📌 **导航**：本篇是提示方法的"自动优化"专条；人工技巧见 [[Prompt Engineering 高级技巧]]，方法论地图见 [[Prompt Engineering高级指南]]。

## 定义

**一句话定义：** 自动提示优化是用语言模型自身或搜索来生成并迭代提示词的方法，代表有 APE（把提示当作可搜索的指令、由 LLM 生成候选再按评测选优）与 OPRO（把历史提示及得分作为上下文、让 LLM 扮演优化器迭代产出更优提示），把提示工程从手工试错变为可搜索、可量化的过程。

**通俗类比：** 不再手写提示反复试，而是让 AI 当"提示设计师"——先出一批候选、用测试集打分、把高分的留下并变异再生成，像遗传算法，只是变异算子换成了 LLM。

## 为什么需要它

手写提示费工、依赖个人经验、难随任务迁移。自动优化把"哪句提示更好"交给可复现的评估驱动搜索，能稳定挖出人被忽略的措辞，尤其适合大批量、多任务的场景。

## 核心机制

- **APE（Automatic Prompt Engineer）**：给若干输入-输出示例 → LLM 生成一批候选指令 → 在验证集上用目标模型评测打分 → 保留高分者并做"变异 / 编辑"迭代，把提示视为可搜索的"程序"。
- **OPRO（Optimization by PROmpting）**：维护"提示-得分"历史，每轮把表现最好的若干条塞进元提示，让 LLM 据此生成下一批更优提示——LLM 自身充当优化器，形似爬山 / 进化搜索。
- **共同要件**：必须有可靠的评估集与打分函数（否则会优化到错误目标）；生成 + 评测多次调用，成本需控制；容易过拟合小验证集，应留独立测试集。
- **定位**：这是"优化提示的提示"（元层面），产出物是更稳的提示模板，可再接入 [[Prompt 工程与 Agent 详解]] 的模板化与版本管理。

## 具体示例

为"从会议纪要抽取行动项"任务：APE 生成 10 条候选指令，在 50 条标注样例上跑分、保留高分并变异，几轮后自动产出一条 F1 高于人工的提示；OPRO 则以"当前最佳提示 + 其得分"为上下文，继续微调措辞逼近更高分。

## 何时用 / 何时不用

- **用**：有清晰评估指标与一定标注、任务多变、愿意投入搜索成本时。
- **不用**：没有可靠评测（优化无方向）、一次性小任务手写即可、Token 预算紧张时。

## 优劣与代价

✅ 系统化、可复现，常能超过手工基线，跨任务可迁移。
⚠️ 强依赖高质量评估集，计算成本高（多次生成与评测）。
⚠️ 易过拟合小验证集，且最优提示往往"知其效不知其理"，可解释性差。

## 与相关概念的区别

- **vs [[Prompt Engineering 高级技巧]]**：那是人工技巧（CoT / ToT / 自洽），本篇是自动搜索提示的措辞与组合。
- **vs 超参数搜索**：搜索对象是自然语言提示而非数值参数，靠 LLM 生成候选。

## 常见误区

- 自动提示优化不需要评估集，能凭空判断哪条提示最好。
- OPRO 通过反向传播更新大模型权重来"学会"更好的提示。
- 自动提示优化能完全取代人工提示工程，无需再懂 CoT / 结构化输出原理。

## 面试速答

> 🎯 自动提示优化用 LLM 生成并迭代提示，把提示工程变成可搜索、可量化：APE 生成候选→验证集评测→保留高分并变异；OPRO 把历史提示与得分塞进元提示让 LLM 当优化器。要件是可靠评估集、控制多次调用成本、防过拟合小验证集。它产出更稳的提示模板，与人工 CoT / ToT 互补。
> 🔍 追问：为什么自动优化必须有独立测试集？（优化过程会拟合验证集，独立集才能证明泛化）
> 🔍 追问：APE 与 OPRO 的差别？（APE 偏"生成-评测-变异"的搜索，OPRO 让 LLM 读历史得分做梯度式改写）
