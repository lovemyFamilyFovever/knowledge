# Modular RAG 与 Agentic RAG


> 📌 **导航**：本篇是 RAG 架构范式的进阶专条；基础与质量评估见 [[RAG 检索增强生成]]，检索零件见 [[RAG 与检索技术详解]]。

## 定义

**一句话定义：** Modular RAG 把检索增强系统拆成可编排、可替换、可单独评估的模块按需组装；Agentic RAG 更进一步，由 Agent 自主决定何时检索、检索什么、是否多跳与交叉验证，把 RAG 从固定管道升级为智能体驱动的流程。

**通俗类比：** Naive RAG 是一条传送带（查→拼→答），Modular 是模块化工作台（零件可换可拼），Agentic 则是给工作台配一位会思考的工程师——自己决定查不查、查几次、要不要换策略。

## 为什么需要它

线性 RAG 在多跳、异构源、需自适应的场景下检索质量差、无法按需调整。模块化提升灵活性与可评估性，Agent 化赋予"按需检索、自我纠偏"的能力，是 RAG 应对复杂问答的演进方向。

## 核心机制

- **谱系定位**：Naive RAG（检索即答）→ Advanced RAG（查询改写、重排）→ Modular RAG（流程拆成可换模块 + 编排）→ Agentic RAG（模型自主规划检索动作）；前两者的概念与质量评估见 [[RAG 检索增强生成]]。
- **Modular**：以查询变换、检索、重排、路由、记忆、生成等模块组合成流水线 / 图，模块可替换、可单独评估——例如把向量检索热插成 BM25 + 向量的混合检索。
- **Agentic**：由 Agent 决定是否 / 何时 / 从哪检索、多轮迭代、对检索结果做相关性自评并决定是否重查，跨库 / API / 图谱聚合；其控制流即 [[Agent 架构模式详解]] 的规划—行动—观察循环。
- **零件复用**：BM25、向量检索、Cross-Encoder 重排等具体手段见 [[RAG 与检索技术详解]]，Agentic 只是调度它们的大脑。

## 具体示例

问"A 公司创始人母校近三年的融资"：Agentic RAG 先查公司→取创始人→再查其人物页→取母校→再检索该校近三年融资，逐跳按上一步结果决定是否继续；Modular RAG 则把"改写 / 混合检索 / 重排 / 生成"按场景拼成固定但可调的流水线。

## 何时用 / 何时不用

- **用**：多跳、异构源、需要自适应检索策略的复杂问答。
- **不用**：单轮事实问答——Naive / Advanced 足够，上 Agentic 反增延迟、成本与不确定性。

## 优劣与代价

✅ 模块化带来灵活、可组合与可单独评估；Agentic 能自适应多跳与自我纠偏。
⚠️ 复杂度、延迟与调用成本显著上升，编排与评估更难。
⚠️ 简单任务用它是过度工程，得不偿失。

## 与相关概念的区别

- **vs [[AI Agent 概述与核心架构]]**：Agent 是通用框架，本篇是"把 Agent 用于检索决策"的 RAG 特例。

## 常见误区

- Agentic RAG 与 Naive RAG 一样，检索是固定的一次性动作、不经模型自主判断。
- Modular RAG 的模块固定不可替换，只是给 Naive RAG 换个名字。
- 上了 Agentic RAG，任何问答都会比简单 RAG 更准更快。

## 面试速答

> 🎯 RAG 从线性走向可编排与自主：Modular RAG 把查询变换、检索、重排、生成拆成可替换、可单独评估的模块按需组装；Agentic RAG 让模型自主决定何时检索、检索什么、要不要多跳与交叉验证，适合多跳 / 异构源的复杂问答。代价是复杂度、延迟与成本上升，简单任务仍用 Naive / Advanced 更划算。
> 🔍 追问：Agentic RAG 相比 Advanced RAG 多了什么？（把"要不要查、查几次、换不换策略"交给模型自主规划，而非固定流程）
> 🔍 追问：Modular RAG 的"模块可评估"为何重要？（能单独度量每个模块的质量与替换收益，指导针对性优化）
