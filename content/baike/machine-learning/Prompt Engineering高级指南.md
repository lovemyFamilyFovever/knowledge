# Prompt Engineering高级指南


> 📌 **导航**：本文是 **Prompt Engineering高级指南** 词条（提示方法枢纽）。入口：[[Prompt Engineering 高级技巧]]、[[Prompt 工程与 Agent 详解]]、[[自动提示优化 APE 与 OPRO]]、[[Agent 安全与对齐]]。

## 定义

**一句话定义：** 本篇是高级提示方法的枢纽索引——把提示结构、样本策略、推理框架、ReAct、结构化输出、注入防御与自动优化各归其位：已有专条者双链，独有的"自动提示优化"独立成篇，并串成"设计→样例→推理→行动→输出→防御→优化→治理"的方法论地图。

**通俗类比：** 一张"提示工程工具箱地图"——常用扳手（CoT / few-shot）各指其专条，新工具（自动提示优化）单列，组装与保养（模板、版本管理）在本页说清。

## 为什么需要它

高级提示技巧名目繁多、彼此引用，新手易把 CoT、ToT、自洽、ReAct 混成一团。一个按"用在哪一步"排序的枢纽，能让人按问题找方法，并直达每个方法的深入词条。

## 核心机制

按处理环节归位，已归口者一律双链不重复：

- **提示结构与样本策略**：角色 / 任务 / 上下文 / 输出格式 / 约束的要素化组织（RCIEF），以及零样本 / 少样本 / 多样本的示例数量取舍，见 [[Prompt 工程与 Agent 详解]] 与 [[Prompt Engineering 高级技巧]]。
- **推理框架**：思维链 CoT、自洽性多路投票、思维树 ToT 的多分支搜索，归 [[Prompt Engineering 高级技巧]]；把推理延伸到"带工具的自主行动"即 ReAct，见 [[Agent 架构模式详解]]、[[Function Calling 与 Tool Use]]。
- **结构化输出**：用 JSON Schema / 强制格式让机器可解析，机制见 [[Function Calling 与 Tool Use]]。
- **注入与安全**：把不可信输入当数据而非指令、最小权限与输出校验，见 [[Agent 安全与对齐]]。
- **自动优化与治理**：让 LLM 自动搜索更优提示的 APE / OPRO 单列为 [[自动提示优化 APE 与 OPRO]]；工程侧则把提示当代码管理——用 Jinja2 类模板化变量、以 Git 做版本与回滚、配评估集与线上监控，效果下降即触发再优化。

## 具体示例

提示效果不稳时的排查顺序：先用结构四要素与 few-shot 稳定格式 → 复杂推理加 CoT / 自洽 → 需外部信息走 ReAct / 工具 → 要程序解析用 JSON 模式 → 上线前做注入防御 → 批量迁移多任务时用自动优化调出更强模板并纳入版本管理。

## 何时用 / 何时不用

- **用**：作为"按问题类型选提示方法"的导航页。
- **不用**：把本篇当全部内容——每种方法的原理与坑都在对应专条，本篇只索引。

## 优劣与代价

✅ 一页串清提示方法全谱及其工程治理闭环，指路明确。
⚠️ 多数方法已有专条，本篇不重复展开；原文含大量示例提示与"50 模板"清单，此处不复制。
⚠️ 提示方法随模型能力演化而贬值快，需以评估集驱动、持续迭代。

## 与相关概念的区别

- **vs [[Prompt Engineering 高级技巧]]**：那是具体技巧（CoT / ToT / 自洽）的深条，本篇是含样本 / 输出 / 防御 / 自动优化 / 治理的方法论地图。
- **vs [[Prompt 工程与 Agent 详解]]**：那是"提示 ↔ Agent"应用层枢纽，本篇更聚焦提示方法学本身。

## 常见误区

- 提示词越长、示例越多，效果就一定越好，与成本和过拟合无关。
- 自动提示优化会完全取代人工提示工程，无需再懂 CoT / 结构化输出原理。
- 把提示写进代码里硬编码，就是合格的提示治理。

## 面试速答

> 🎯 高级提示方法按环节各有专条：结构四要素、样本、推理（CoT/自洽/ToT）、ReAct 与工具、结构化输出、注入防御、自动优化（APE/OPRO）、模板版本治理。原则：先 few-shot 稳格式，再按需上推理 / 工具 / 防御，批量用自动优化产出更强模板并版本化；各法都有成本与过拟合权衡，需评估集驱动。
> 🔍 追问：什么时候值得上自动提示优化而非手写？（任务多、有可靠评估集、愿投入搜索成本时）
> 🔍 追问：提示为何要做版本管理？（提示是易漂移的资产，版本化才能回滚、审计与 A/B 对比）
