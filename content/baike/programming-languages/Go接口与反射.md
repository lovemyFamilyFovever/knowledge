# Go接口与反射

> 📌 **导航**：本文是 **Go 接口与反射** 词条，属 [[Go语言系统编程指南]] 子词条。接口基础见 [[Go语言核心]]。

## 定义

**一句话定义：** Go 接口是"方法集即契约"的隐式实现（无需 implements），由此获得鸭子类型与解耦；reflect 包则在运行期检视并操作任意值的类型与数据，强大但需慎用。

**通俗类比：** 接口像"会叫、会下蛋的就是鸭子"——Go 不看你自称什么，只看你有没有那些方法；reflect 像运行时"照镜子"，能看穿一个值到底是什么类型、有哪些字段。

## 为什么需要它

隐式接口让"使用者定义契约、实现者无需感知"，天然解耦、便于组合与 mock 测试；泛型之前的通用容器/算法靠 `interface{}` + 类型断言实现。而序列化、ORM、通用遍历等"必须处理任意类型"的场景，非 reflect 不可。

## 核心机制

- **隐式实现**：类型只要实现接口的全部方法即自动满足该接口，无显式声明。
- **空接口 `any`/`interface{}`**：可持任意值，但取用需类型断言 `x.(T)` 或 `type switch`；接口值内部是"类型 + 数据"两字。
- **reflect**：`reflect.TypeOf`/`ValueOf` 得 Type/Value，查 Kind、字段、方法；三条定律（反射自值→可操作须是可变指针、可互相转换）；代价是性能与编译期类型安全缺失。
- 优先用接口/类型断言表达多态，reflect 是"最后手段"。

## 具体示例

type switch 从 `any` 取回具体类型，比 reflect 更直白高效：

```go
switch v := x.(type) {
case int:    fmt.Println("int", v)
case string: fmt.Println("str", v)
default:     fmt.Printf("未知 %T\n", v)   // %T 即类型，轻量反射式调试
}
```

## 何时用与何时不用

- **用**：定义可插拔抽象、测试替身用接口；写 marshal/深拷贝/通用遍历等元编程用 reflect。
- **不用**：能用接口/类型断言解决就别上 reflect；reflect 路径性能敏感处要缓存 Type/字段。

## 优劣与代价

✅ 隐式接口带来松耦合与可组合的多态，天然利于测试与复用。
✅ reflect 让运行期类型操作成为可能。
⚠️ 隐式实现"看不出谁实现了谁"、易接口爆炸；`any` 滥用丢类型安全。
⚠️ reflect 慢、易错、非编译期检查，重构不友好。

## 与相关概念的区别

- **隐式接口 vs 名义接口**（Java `implements`）：Go 看方法集、不认声明。
- **接口 vs 泛型**（见 [[泛型]]）：泛型在类型参数上做编译期多态，接口做运行期多态，互补。
- **type switch/断言 vs reflect**：前者是语言层、可控快；后者是运行期内省、灵活但重。

## 常见误区

- Go 里实现一个接口必须显式写 implements 关键字。
- reflect 灵活方便，应当作为通用多态的首选方案。
- 空接口 `interface{}` 没有任何运行期代价。

## 面试速答

> 🎯 Go 接口是隐式实现(方法集满足即实现、无 implements)→鸭子类型、松耦合；空接口 any 需类型断言/type switch 取用。reflect 运行期内省 Type/Value 处理任意类型(序列化/ORM)，但慢、非编译期安全，是最后手段——能靠接口/泛型多态解决就别用它。
