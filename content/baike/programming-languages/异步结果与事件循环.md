# 异步结果与事件循环

> 📌 **导航**：本文是 **异步结果与事件循环** 词条，属 [[并发编程（Concurrent Programming）概念]] 子词条。协程见 [[协程]]，线程执行资源见 [[线程池]]。

## 定义

**一句话定义：** Future/Promise 是"尚未完成的异步结果"的一等对象（可等待、可组合、可挂回调），事件循环是单线程协作式调度器——不断取出就绪的异步任务/回调执行，让一条线程并发推进海量待决 I/O。

**通俗类比：** Future 像网购的快递单号（货还没到，但它承诺"在路上"、可跟踪）；事件循环像餐厅前台经理——不断看"哪位点单、哪道菜好了、哪桌空出"，按就绪顺序派活，自己不做菜只做调度。

## 为什么需要它

回调嵌套（"回调地狱"）难读难维护；用 Future/Promise 把"未来的值"变成可 `then/await` 组合的对象。而若为每个并发 I/O 各起一线程，几十上百连接就把线程耗尽；事件循环用单线程 + 就绪队列 + 非阻塞 IO 复用，把"等待"变成"不占线程的挂起"，是 asyncio/Node.js 高并发的引擎。

## 核心机制

- **Future vs Promise**：Future 通常代表"只读的异步结果句柄"（谁来 fulfill 与谁等待分离）；Promise 是"可被 resolve/reject 的占位"；两者常指同一物、术语因语言而异。
- **组合与链式**：`then/thenApply`、`Promise.all/gather`、`CompletableFuture.thenApply(x->..)` 做扇入扇出与转换，`await` 是其语法糖（见 [[Rust 并发与异步]]）。
- **事件循环**：注册/监听 I/O 与定时器 → 就绪后调度对应协程/回调继续 → 让出控制权时切走；Python `asyncio.run`/`get_event_loop`、`create_task`、`call_later`、`run_in_executor`(把阻塞代码丢线程池，见 [[线程池]])；Node 的 libuv 事件循环同理。
- **协作式**：任务必须 `await`/主动让出，任何一处阻塞调用会卡住整个循环（红线）。

## 具体示例

事件循环并发调度、gather 汇聚 Future：

```python
async def task(n): await asyncio.sleep(n); return n
async def main():
    results = await asyncio.gather(task(2), task(1))  # 并发，总耗时≈2s
    print(results)  # [2, 1]
asyncio.run(main())
```

## 何时用与何时不用

- **用**：I/O 密集、大量并发待决（网络/磁盘）且能坚持非阻塞——事件循环 + async/await 最省资源；需把异步结果当作值传递/组合时用 Future/Promise。
- **不用**：CPU 密集（单线程循环帮不上，交 [[线程池]]/进程池多核并行）；混入不可控的阻塞库会拖垮循环，此时退回多线程更稳。

## 优劣与代价

✅ 单线程扛海量 I/O、上下文切换与内存开销小；Promise/Future 组合消灭回调地狱。
✅ `async/await` 让异步代码读起来像同步，心智负担下降。
⚠️ 一处阻塞调用即毒化整条事件循环；错误在异步链中易被吞。
⚠️ 与同步库/生态阻抗不匹配（"红色函数 vs 蓝色函数"），调试栈跨 `await` 边界不直观。

## 与相关概念的区别

- **事件循环 vs 线程池**：前者单/少线程协作式、擅长 I/O；后者多线程抢占式、可吃多核、擅长 CPU/阻塞。
- **Future vs Promise**：术语侧重不同——Future 强调"结果的只读句柄"，Promise 强调"可完成该结果的写入端"，实践中常混用。
- **async/await vs 回调**：前者是可组合语法糖，后者是底层风格。

## 常见误区

- 事件循环能加速 CPU 密集型计算。
- 在 async 函数里调用普通阻塞 `time.sleep`/同步 IO 没问题，反正都在"异步"里。
- `await` 之后的代码是另一条线程并行执行的。

## 面试速答

> 🎯 Future/Promise=把"未完成的异步结果"变一等对象，可 await/then 组合、消灭回调地狱；事件循环=单线程协作式调度器，就绪才跑、await 让出，用极少线程扛海量 I/O。红线：循环里禁阻塞调用（阻塞交线程池）。CPU 密集别指望它、多核并行靠线程/进程池。
