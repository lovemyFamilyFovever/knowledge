# 类型系统

> 📌 **导航**：本文是 **类型系统** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 类型系统（Type System）是编程语言中一套规则，用于定义如何为值、变量与表达式赋予类型，以及不同类型之间允许哪些运算与转换，从而在编译期或运行期阻止某一类错误（例如对字符串做算术）。

**通俗类比：** 像表格的填写规则——"年龄"栏只能填数字、"姓名"栏只能填文字；类型系统给程序里每个数据贴上"能做什么、不能做什么"的标签，提前拦住张冠李戴的操作。

## 为什么需要它

很多 bug 源于"拿错类型的值做操作"：把字符串当数字相加、把空对象调方法。类型系统在写代码时就给每个值划定"能参与哪些运算"，把这类错误尽量前移到编译期消灭；同时类型还是给编译器的优化线索、给 IDE 的补全依据、给协作读者的活文档。

## 核心机制

- **静态 vs 动态**：静态类型在编译期确定（Java、C、Rust、TypeScript）；动态类型在运行期携带并检查（Python、JavaScript）。
- **强 vs 弱**：指是否严格限制隐式类型转换；强类型更少做危险的自动转换。
- **类型检查**：编译器 / 解释器依类型规则验证运算合法性，违反即报错。
- **类型推断**：静态语言中自动推导未显式标注的类型（var / let）。
- **名义 vs 结构**：按"名字"还是按"形状"判定类型是否相容。

## 具体示例

同一句"给整型变量赋字符串"，静态语言在编译期拦下，动态语言要到运行执行到那行才报错——这正是静态/动态维度的差别：

```
int n = "hello";     // Java/TS：编译期即报错
n = len(42)          # Python：能编译，运行到这行才 TypeError
```

## 何时用与何时不用

- **用静态类型**：大型代码库、长期维护、团队协作、要重构与工具化支持。
- **用动态类型**：快速原型、脚本、胶水代码，追求灵活与少写样板。
- 不是二选一：TypeScript 给 JS 加静态层、运行期仍是动态的 JS。

## 优劣与代价

✅ 提前发现一类错误、便于优化与工具化、增强可维护性与可读性。
✅ 类型即文档，IDE 补全 / 安全重构靠它。
⚠️ 静态类型增加书写与灵活性成本；动态类型把错误推迟到运行期。
⚠️ 越强的类型系统（如泛型约束、依赖类型）学习与调试门槛越高。

## 与相关概念的区别

- **静态/动态 vs 强/弱**：两组正交维度——静态说的是"何时检查"，强/弱说的是"隐式转换松不松"，不能划等号。
- **名义 vs 结构类型**：名义看"是不是同一个名字/继承关系"，结构看"字段形状是否匹配"（TypeScript 偏结构）。
- **类型检查 vs 正确性**：类型只保证"操作合法"，不保证业务逻辑对。

## 常见误区

- 静态类型就是强类型，动态类型就是弱类型。
- TypeScript 的类型在运行时也会做检查、拦截错误。
- 类型系统能保证程序的业务逻辑正确。

## 面试速答

> 🎯 类型系统 = 给值 / 表达式赋类型、规定哪些运算合法的规则，在编译期或运行期拦截一类错误；沿正交维度分：静态/动态（何时检查）、强/弱（隐式转换）、名义/结构、显式/推断。
