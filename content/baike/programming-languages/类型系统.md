# 类型系统

## 定义

**一句话定义：** 类型系统(Type System)是编程语言中一套规则,用于定义如何为值、变量与表达式赋予"类型",以及不同类型之间允许哪些运算与转换,从而在编译期或运行期阻止某一类错误(例如对字符串做算术)。

**通俗类比：** 像表格的填写规则——"年龄"栏只能填数字、"姓名"栏只能填文字;类型系统给程序里每个数据贴上"能做什么、不能做什么"的标签,提前拦住张冠李戴的操作。

> 多义说明:类型系统有多个**正交**维度:静态 vs 动态、强 vs 弱、显式标注 vs 类型推断、名义(nominal)vs 结构(structural)类型;本文综合讨论,不特指某一种。

## 原理与机制

- **静态 vs 动态:** 静态类型在编译期确定(Java、C、Rust、TypeScript);动态类型在运行期携带并检查(Python、JavaScript)。
- **强 vs 弱:** 指是否严格限制隐式类型转换;强类型语言更少做危险的隐式转换。
- **类型检查:** 编译器/解释器依据类型规则验证运算合法性;违反则报错(编译期或运行期)。
- **类型推断:** 在静态语言中自动推导未显式标注的类型(如 `var`/`let`)。
- **作用:** 提供类型安全、为优化提供信息、充当文档、支撑 IDE 补全与重构。

## 关键组成

| 要素 | 说明 |
|------|------|
| 类型 | 值的集合与其允许的操作 |
| 类型规则 | 运算/赋值的合法性判定 |
| 类型检查器 | 执行检查的编译期/运行期组件 |
| 类型推断 | 自动推导类型 |
| 类型转换 | 隐式(coercion)/显式(cast) |
| 泛型/参数化类型 | 类型层面的抽象与复用 |

## 应用场景

- 编程语言设计与编译器实现
- 编译优化(依据类型生成高效代码)
- 静态检查、IDE 智能提示与安全重构
- 在运行前捕获类型相关缺陷

## 优点与局限

- 优点:提前发现一类错误、便于优化与工具化、增强大型代码库的可维护性与可读性。
- 局限:静态类型增加书写与灵活性成本;动态类型把错误推迟到运行期;复杂类型系统(如依赖类型)学习与调试门槛高。

## 常见误区

- 静态 ≠ 强类型、动态 ≠ 弱类型:这是两个独立维度(如 Python 是动态但强类型)。
- 类型系统只能防"某类"错误,不能保证业务逻辑正确。
- TypeScript 的类型在编译为 JavaScript 后被擦除,运行期不再做类型检查。
