# TypeScript深入

> 📌 **导航**：本文是 **TypeScript深入** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** TypeScript 是 JavaScript 的超集，在保留其运行语义的同时加上静态类型系统，靠结构类型、泛型、条件与映射类型、工具类型提供强类型表达能力。

**通俗类比：** 像给 JavaScript 请了一位"编译期语文老师"：作文（代码）照旧用 JS 写、最终也交 JS，但老师在交卷前先把主谓宾（类型）检查一遍，把笔误（类型错误）挡在运行之前。

## 为什么需要它

纯 JavaScript 的动态类型在小脚本里灵活，但在大项目里代价明显：拼错属性名要到运行时才炸、重构只能全局搜替换、接口全靠文档口口相传。TypeScript 在不改变 JS 运行模型的前提下补上静态类型与推断，把整类错误提前到编译期，并给 IDE 补全、跳转、安全重构提供依据。

## 核心能力

- **结构类型**：按"形状是否匹配"判定兼容，而非 Java 的名义（按名字/继承）。
- **类型推断**：多数变量不必显式标注，编译器自动推导。
- **泛型 / 联合 / 交叉 / 字面量类型**：组合出精确的类型表达。
- **条件类型与映射类型**：类型层面的 if / for，是工具类型的基础。

| 工具类型 | 作用 |
|------|------|
| Partial<T> | 所有属性变可选 |
| Pick<T,K> | 选取部分属性 |
| Omit<T,K> | 排除部分属性 |
| Record<K,V> | 键值对类型 |

## 具体示例

泛型让函数在保持类型安全的同时复用；`identity<T>` 返回什么类型就由入参决定：

```typescript
function identity<T>(arg: T): T { return arg; }
```

条件类型 + 映射类型能"计算"出新类型，下面 Partial<T> 就是把 T 的每个属性都变成可选：

```typescript
type IsString<T> = T extends string ? "yes" : "no";
type Partial<T> = { [P in keyof T]?: T[P] };
```

## 何时用与何时不用

- **用**：中大型前端 / Node 工程、团队协作、长期维护、需要可靠重构与接口契约。
- **不用**：一次性脚本、十几行的玩具 demo——加编译步骤与类型样板的收益不抵成本。

## 优劣与代价

✅ 编译期捕获类型错误、IDE 体验强、可渐进采用（能混用 .js、可用 any 逃生）。
✅ 最终擦除成 JS，无缝融入整个 JS 生态。
⚠️ "类型体操"过深时可读性下降，复杂推断偶有反直觉。
⚠️ 多一道编译步骤；类型只在编译期有效，运行时仍需另行校验。

## 与相关概念的区别

- **结构类型 vs 名义类型**：TS 看形状是否兼容，Java/C# 看名字与继承链。
- **类型擦除 vs 运行时类型**：TS 编译后类型消失，运行时不再检查——需要运行时校验要靠 zod / class-validator 等。
- **any vs unknown**：any 放弃检查（向后不兼容一切）；unknown 是"类型安全的 top"，必须先收窄才能用。

## 常见误区

- TypeScript 的类型信息在运行时会保留并参与校验。
- 给参数标了类型，运行时就会自动拒绝传错类型的实参。
- any 和 unknown 是一回事，都是"任意类型"。
