# 垃圾回收

## 定义

**一句话定义：** 垃圾回收(Garbage Collection, GC)是一种自动内存管理机制,由运行时系统周期性地识别并释放程序不再可能引用的对象所占内存,免除程序员手动 free/delete,降低内存泄漏与悬垂指针风险。

**通俗类比：** 像办公室的保洁——你不必自己扔垃圾,保洁(GC)定期巡查,把"没人再认领"的东西(不可达对象)清走腾出空间;代价是打扫时可能短暂打断你(停顿)。

> 多义说明:GC 指**自动内存回收**;区别于手动内存管理(C/C++ 的 malloc/free)与 RAII/引用计数等确定性释放方式。

## 原理与机制

判定"垃圾"的两条主线:

- **引用计数(Reference Counting):** 每个对象记录被引用次数,归零即回收;实现简单、回收及时,但难以处理**循环引用**(需弱引用等补充)。
- **可达性分析(Reachability):** 从一组 **GC Roots**(栈上引用、静态变量、寄存器等)出发遍历,不可达的对象即为垃圾。

常见回收算法:标记–清除(mark-sweep)、标记–整理(mark-compact)、复制/半空间(semispace copying)、**分代收集**(基于"弱代假说":多数对象很快就死)、以及增量式/并发 GC(降低停顿)。

## 关键组成

| 部件 | 作用 |
|------|------|
| GC Roots | 可达性分析起点 |
| 分配器 | 在堆上为新对象分配空间 |
| 回收算法 | 标记/清除/整理/复制 |
| 分代策略 | 新生代/老年代差异化回收 |
| 停顿(STW) | 回收时暂停应用线程的时间 |

## 应用场景

- Java/JVM、C#/.NET、Go、Kotlin 等托管语言的堆内存管理
- Python(引用计数 + 分代 GC)、JavaScript 引擎(V8 等)
- 长时间运行服务的内存自动治理

## 优点与局限

- 优点:自动化、显著减少内存泄漏与悬垂指针、提升开发效率与内存安全。
- 局限:GC 停顿影响实时性;额外 CPU 与内存开销;回收时机不确定;在极致性能或资源受限场景不如手动管理可控。

## 常见误区

- 有 GC ≠ 永不内存泄漏:逻辑泄漏、意外长期持有引用(如静态集合)仍会耗尽内存。
- GC ≠ 回收所有资源:文件句柄、网络连接、锁等仍需显式释放(try-with-resources/using/defer)。
- 引用计数与可达性分析是两类不同机制,不要混为一谈。
