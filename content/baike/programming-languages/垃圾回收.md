# 垃圾回收

> 📌 **导航**：本文是 **垃圾回收** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 垃圾回收（Garbage Collection, GC）是一种自动内存管理机制，由运行时系统周期性地识别并释放程序不再可能引用的对象所占内存，免除程序员手动 free/delete，降低内存泄漏与悬垂指针风险。

**通俗类比：** 像办公室的保洁——你不必自己扔垃圾，保洁定期巡查，把"没人再认领"的东西（不可达对象）清走腾出空间；代价是打扫时可能短暂打断你（停顿）。

## 为什么需要它

手动 free 一旦出错就是崩溃或安全漏洞，而且"这个对象还有没有人用"在复杂程序里极难人工判断。GC 把"判断可达性 + 回收"这件事交给运行时：程序员只管创建对象，运行时负责在没人能再访问它时把内存收回，从而大幅降低内存错误、提升开发效率。

## 核心机制

判定"垃圾"的两条主线：

- **引用计数（Reference Counting）**：每个对象记录被引用次数，归零即回收；实现简单、回收及时，但难处理循环引用（需弱引用等补充）。
- **可达性分析（Reachability）**：从一组 GC Roots（栈上引用、静态变量、寄存器等）出发遍历，不可达的对象即为垃圾。

常见回收算法：标记–清除、标记–整理、复制 / 半空间、分代收集（基于"弱代假说"：多数对象很快就死），以及增量式 / 并发 GC（降低 STW 停顿）。

## 具体示例

两个对象互相引用、外部再无指针指向它们——这正是引用计数失效、可达性分析才能回收的经典循环：

```
a.next = b;  b.next = a;   // 相互引用
root = null;               // 外部已无人指向 a/b
// 引用计数：a/b 计数永不为 0 → 泄漏；可达性分析：二者不可达 → 可回收
```

## 何时用与何时不用

- **用**：Java / C# / Go / Python / JS 等托管语言的堆内存管理、长时间运行的服务。
- **不用（换手动 / RAII / 所有权）**：实时系统、极致低延迟或资源受限场景——GC 停顿不可精确控制时是硬伤。

## 优劣与代价

✅ 自动化、显著减少内存泄漏与悬垂指针、提升开发效率与内存安全。
✅ 分代 + 并发让吞吐和延迟都能调优。
⚠️ GC 停顿影响实时性，额外占 CPU 与内存。
⚠️ 回收时机不确定，非内存资源仍需自己管。

## 与相关概念的区别

- **引用计数 vs 可达性分析**：前者每对象记引用数、回收及时但漏循环；后者从根遍历、能处理循环但有扫描开销。
- **GC vs 手动 / RAII**：GC 回收时机不定、运行期判定；RAII 在作用域退出确定性释放。
- **内存 vs 其他资源**：GC 管的是堆内存，文件句柄 / 连接 / 锁不属于它。

## 常见误区

- 有 GC 就永远不会内存泄漏。
- GC 会自动释放文件句柄、网络连接、锁等所有资源。
- 引用计数能正确处理循环引用。

## 面试速答

> 🎯 GC = 运行时自动回收"不再可达"的对象内存。判定靠引用计数（简单但漏循环引用）或可达性分析（从 GC Roots 遍历）；算法有标记-清除/整理、复制、分代，并用增量/并发降低 STW 停顿。
