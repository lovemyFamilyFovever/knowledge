# 函数式错误处理与不可变数据结构

> 📌 **导航**：本文是 **函数式错误处理与不可变数据结构** 词条，属 [[函数式编程完全指南]] 子词条。Monad 结构见 [[Functor 与 Monad]]。

## 定义

**一句话定义：** 函数式错误处理把"失败"当作一个普通值（Option/Either/Result）随类型流动、用 map/flatMap 链式传播而非抛异常；不可变数据结构则通过持久化数据结构（结构共享）让"改即产新值"在大集合上也高效。

**通俗类比：** 错误不用"扔出窗口让人接"（异常），而是"随包裹一起标注状态往下传"（Either）；改大文件不重印整本，而是新旧两版共享没变的那几页（结构共享）。

## 为什么需要它

异常式错误破坏引用透明、控制流隐蔽、跨边界难处理；把错误编进类型后，调用方被迫正视失败、链路可组合。纯函数要求不可变，但"改即全量拷贝"在大结构上太贵——持久化数据结构用共享旧版本节点，把更新降到对数级、且天然安全（旧值不变，可并发读/回滚）。

## 核心机制

- **错误即值**：`Option/Maybe` 表"可能没有"、`Either<E,A>/Result` 表"要么错误要么成功"；链式 `map/flatMap` + 语言糖（Rust `?`、TS 可选链、Haskell do/for-comprehension）传播，`left`/`Err` 一路短路。
- **持久化数据结构**：写时复制 + 结构共享（如HAMT/平衡树）实现 `List/Map/Set` 的"不可变但更新高效"，旧版本仍可安全读；Immutable.js / immer / Clojure persistent vectors 为代表。
- 好处：可缓存、可快照/时间旅行、无线性并发写冲突。

## 具体示例

用 Either 链式传播错误，任一环 left 即短路：

```javascript
readConfig(path)
  .flatMap(parseJson)      // 任一失败→左值，后续不再执行
  .map(setPort)
  .getOrElse(defaultConfig);
```

## 何时用与何时不用

- **用**：把可恢复失败编进类型（Either/Result）、需要大量派生/并发读或快照时上持久化数据结构。
- **不用**：一次性脚本可继续用 try/catch；小结构频繁整体替换时 Immutable.js 未必比手写拷贝划算，注意误用"深冻结"开销。

## 优劣与代价

✅ 错误显式在类型里、可组合、引用透明保持；结构共享让不可变更新近似原地性能。
✅ 天然利于并发读、缓存与历史快照。
⚠️ Either/Result 样板与嵌套链有时冗长；语言无内建时靠库。
⚠️ 持久化结构有额外内存/调试成本，深对象"结构性共享"收益才明显。

## 与相关概念的区别

- **Either vs 异常**：异常隐式跳出栈、破坏透明；Either 是普通值、控制流显式。
- **持久化数据结构 vs 深拷贝**：前者更新只复制路径、共享其余；后者全量复制，O(n)。
- **不可变数据结构 vs 只读视图**：前者根本无原地改、可安全共享；后者只是访问约束。

## 常见误区

- 用 Either/Result 就等于把程序改成了 Haskell。
- 持久化数据结构每次修改都全量深拷贝，比可变更慢。
- 抛出异常再在顶层 catch，比返回 Result 更"函数式"。

## 面试速答

> 🎯 函数式错误处理=把失败当值：Option(可能空)/Either·Result(错误|成功)，用 map/flatMap(+? /可选链)链式传播、左值短路，替代抛异常以保引用透明。持久化数据结构靠写时复制+结构共享，让"改即新值"近 O(log n)、旧版可安全读/快照。
