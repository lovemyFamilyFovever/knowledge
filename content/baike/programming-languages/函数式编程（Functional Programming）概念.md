# 函数式编程（Functional Programming）概念

> 📌 **导航**：本页是 **函数式编程（FP）概念** 枢纽，索引其子词条；各概念的机制、代码与误区已拆出（多数复用既有 FP 专条），本页只做概念地图与归属。

## 定义

**一句话定义：** 函数式编程是以"纯函数 + 不可变数据 + 函数作为一等公民 + 组合"为核心的编程范式，用"描述要算什么"取代"命令怎么改状态"；本枢纽把 14 个 FP 术语归位到各自的专条。

**通俗类比：** 像用乐高搭东西：每块小积木是纯函数，接口标准（输入输出）就能任意拼；不拆改已有积木（不可变），只叠出新的成品。

## 为什么需要它

FP 术语零散：纯函数、副作用、不可变、高阶、柯里化、组合、闭包、Functor/Monad/Applicative、惰性、声明式……若各写一段易重复、彼此失联。把它们收敛成一张"术语→专条"地图，读者按概念直达深入页，也避免多篇汇编重复承载（本页即由原 14 概念汇编收敛而来）。

一句话主线：**纯函数**是地基，**高阶 + 组合**是把小函数拼成大逻辑的手段，**Functor→Applicative→Monad** 是给"带上下文的值"（可失败/多值/副作用）建模的抽象阶梯。

## 具体示例

典型 FP 风格片段——纯函数 + 高阶 + 组合表达数据流：

```python
# 纯、无副作用；map/filter 是高阶函数；compose 串管道
to_even_sq = lambda xs: list(map(lambda x: x*x, filter(lambda x: x % 2 == 0, xs)))
to_even_sq([1, 2, 3, 4])  # [4, 16]
```

## 何时用与何时不用

- **用**：数据变换/业务规则/并发逻辑尽量函数化——需要可测、可并行、可组合时；I/O 边界把副作用隔离到最外层。
- **不用**：不必处处 FP；强状态机、与命令式/OOP 框架深度绑定的场景，混用更实际。范式选型见 [[面向对象编程（OOP）概念]]。

## 优劣与代价

✅ 可预测、易测试、易并行；引用透明使缓存/惰性/推理自然成立。
✅ 组合与抽象（Monad）把错误、空值、副作用统一建模。
⚠️ 全不可变有拷贝成本、Monad/类型类对新人陡峭、调试惰性/异步链更绕。
⚠️ 语言不原语支持 FP 时，样板（如 JS 手写 curry）会抵消优雅。

## 与相关概念的区别

- **函数式 vs 面向对象**（[[面向对象编程（OOP）概念]]）：前者"数据 + 无状态函数变换"，后者"对象封装状态 + 消息"。
- **Functor vs Applicative vs Monad**：抽象能力递增（map → 容器函数应用 → bind 展平），见 [[Functor 与 Monad]]。
- **声明式 vs 命令式**：风格层，函数式是其中一种声明式（见 [[声明式风格与惰性求值]]）。

## 常见误区

- 函数式编程要求彻底消灭一切副作用。
- 用了 map/filter/箭头函数就算函数式，无需关心纯与不可变。
- Monad 只是语法糖，和 map 没有本质区别。

## 面试速答

> 🎯 FP=纯函数+不可变+函数一等公民+组合的范式。主线：纯函数为基，高阶函数与组合拼逻辑，Functor→Applicative→Monad 给带上下文的值建模，声明式风格 + 惰性求值提简洁度。副作用非消灭而是隔离到边界。
