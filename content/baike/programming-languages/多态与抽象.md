# 多态与抽象

> 📌 **导航**：本文是 **多态与抽象** 词条，属 [[面向对象编程（OOP）概念]] 子词条。继承基础见 [[封装与继承]]。

## 定义

**一句话定义：** 抽象用"接口/抽象类"描述"能做什么"而隐藏"怎么做"；多态让同一调用在不同类型上表现不同行为——靠重写实现运行期分派、靠重载与泛型实现编译期分派。

**通俗类比：** "形状都能 draw()" 是抽象契约；给圆和方分别实现——同一句 `shape.draw()` 因实际类型画出不同图形，这就是多态；接口像统一的电源插口，具体电器各显其能。

## 为什么需要它

面向抽象而非具体编程，才能替换实现、扩展类型而不改调用方（配合 [[设计原则]]）。多态用统一接口消除 `if type==` 分支、支撑 [[策略模式]] 等；抽象给出稳定契约，隔离变化点。

## 核心机制

- **抽象类**：可含状态与部分实现、常有抽象方法，"是什么"的骨架。
- **接口**：纯能力契约（Java 前无实现、现可 default），"能做什么"，可多实现→规避多继承。
- **重写 override**：子类替换父类方法，运行期按对象实际类型分派（vtable/消息派发）。
- **重载 overload**：同名不同参数，编译期按签名选择——与重写不同。
- 参数多态=泛型（见 [[泛型]]）；子类型多态=继承/接口替换（受 [[封装与继承|LSP]] 约束）。

## 具体示例

同一接口、不同实现，调用方不关心具体类型：

```python
class Shape:                # 抽象/接口：契约
    def area(self): raise NotImplementedError
class Rect(Shape):
    def __init__(self,w,h): self.w,self.h=w,h
    def area(self): return self.w*self.h
for s in shapes: print(s.area())   # 多态：按实际类型分派
```

## 何时用与何时不用

- **用**：有多种可替换实现、需面向抽象协作、想消除类型分支时用接口/抽象类 + 多态。
- **不用**：单一实现、稳定无扩展点时直接具体类型即可，别为"将来可能"过度抽象；轻量子类型行为差异用数据/枚举或函数更简。

## 优劣与代价

✅ 面向抽象、易替换易扩展、支撑开闭与测试 mock。
✅ 多态消除类型分支、代码更内聚。
⚠️ 抽象层增多间接性与理解成本；过度抽象 YAGNI。
⚠️ 运行期分派有性能与调试（跳进去难找实现）代价。

## 与相关概念的区别

- **重写 vs 重载**：重写=父子同签名、运行期分派；重载=同类不同参数、编译期。
- **抽象类 vs 接口**：前者带状态/部分实现（is-a 骨架），后者纯能力契约（can-do、可多实现）。
- **子类型多态 vs 参数多态**：前者继承替换，后者泛型（[[泛型]]）。

## 常见误区

- 接口和抽象类完全等价，随便选。
- 重载就是多态的唯一形式（运行期多态来自重写/实现）。
- 抽象越多越解耦、越面向对象。

## 面试速答

> 🎯 抽象=用接口(能力契约,可多实现)/抽象类(is-a骨架,含状态) 描述做什么、隐藏怎么做；多态让同一调用按实际类型不同——重写(override,运行期)与重载(overload,编译期)不同，参数多态即泛型。面向抽象支撑开闭与替换，别过度抽象。
