# 并发编程（Concurrent Programming）概念

> 📌 **导航**：本页是 **并发编程（CP）概念** 枢纽，索引其子词条；各术语的机制、代码与误区已拆出（多数复用既有并发专条），本页只做概念地图与归属。

## 定义

**一句话定义：** 并发编程研究"多个执行流如何在时间上交叠推进并正确协调"——涵盖执行实体（进程/线程/协程）、共享内存协调（锁/原子/CAS）、消息传递（Channel/Actor）、执行资源（线程池）与异步编排（Future/事件循环）；本枢纽把 14 个并发术语归位到各自专条。

**通俗类比：** 像一间多人协作的厨房：谁在做菜（执行流）、两人抢一口锅怎么不打架（锁/原子）、不共享锅而靠传菜口传菜（消息传递）、厨师与灶台数量怎么配（线程池）、以及"先下单后取菜"的接单调度（事件循环）。

主线：**共享内存**（锁/原子协调同一份数据）与**消息传递**（传所有权/消息、少共享）是两条协调路线；**线程池**与**事件循环**是两种执行/调度模型，按 I/O 密集 vs CPU 密集选。

## 具体示例

一条并发抓取心智：判 I/O 密集 → 用 [[线程池]] 限并发或 [[异步结果与事件循环]] 单线程扛海量连接；共享计数器才上 [[同步原语与无锁并发]] 的锁/原子；跨任务通信优先 [[消息传递并发：CSP 与 Actor]] 的 channel，避免锁与 [[死锁]]。

## 何时用与何时不用

- **用**：需重叠等待（I/O）、利用多核、保持响应性时引入并发；协调优先消息、其次不可变、最后才共享可变 + 锁。
- **不用**：任务本就串行且量小，别为并发增加调度与调试复杂度；能一进程一任务解决的不硬上多线程。

## 优劣与代价

✅ 并发提升吞吐与响应、用满多核；正确的抽象（消息/不可变/池）把复杂度关进笼子。
✅ 术语分门别类后，问题可快速定位到"协调 or 调度 or 资源"哪一层。
⚠️ 竞态/死锁/内存序等隐蔽 bug 调试成本高，抽象（如 Monad 式 Future）对新人陡峭。
⚠️ 过度并发反被上下文切换与协调开销拖垮，"并发 ≠ 越快"。

## 与相关概念的区别

- **并发 vs 并行**：并发是"多任务交叠推进"（可单线程轮转）、并行是"同时执行"（需多核）——见 [[并发与并行及线程模型]]。
- **共享内存 vs 消息传递**：前者靠锁/原子协调、后者传所有权少共享（[[消息传递并发：CSP 与 Actor]]）。
- **事件循环 vs 线程池**：协作单线程 vs 抢占多线程（见 [[异步结果与事件循环]]、[[线程池]]）。

## 常见误区

- 并发程序一定比串行快。
- 只要加了锁，多线程访问同一数据就绝对正确。
- 协程比线程好，可以无节制地创建几十万个而不影响性能。

## 面试速答

> 🎯 并发=多执行流交叠推进 + 正确协调。四块：执行实体(进程/线程/协程)、协调(共享内存:锁/原子/CAS vs 消息传递:Channel/Actor)、资源(线程池)、异步编排(Future/事件循环)。按 I/O 密集选事件循环/协程、CPU 密集选多核/线程池；协调优先消息与不可变。
