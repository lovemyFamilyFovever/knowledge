# Rust编程基础

> 📌 **导航**：本文是 **Rust编程基础** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** Rust 是一门以所有权系统为核心的系统编程语言，在不用垃圾回收的前提下，靠编译期借用检查同时保证内存安全与并发安全。

**通俗类比：** 像一套严格的"物品归属规则"——每件东西同一时刻只有一个主人，转交（move）后原主人就不能再用，借用（&）要看清归还期限；规则在编译时就查，跑起来不用请"保洁"（GC）来擦屁股。

## 为什么需要它

C/C++ 快，但悬垂指针、use-after-free、数据竞争这类 bug 靠人自觉、常常逃逸到线上；带 GC 的语言安全，却有停顿、运行时开销，也不适合系统 / 嵌入式。Rust 的目标是鱼与熊掌兼得：把内存与并发安全前移到编译期，用所有权 + 借用检查在零运行时开销下消灭整类 bug。

## 核心能力

| 机制 | 作用 |
|------|------|
| 所有权 | 每个值有唯一所有者，离开作用域自动释放（RAII），赋值即 move |
| 借用与生命周期 | 用 &T / &mut T 借用，编译器检查引用不悬垂 |
| 无 GC | 内存由所有权规则在编译期确定，无运行时回收停顿 |
| 并发安全 | Send / Sync trait 在编译期阻止数据竞争 |
| Option / Result | 用类型系统替代 NULL 与异常表达"缺失/失败" |

## 具体示例

赋值与传参会"移动"所有权，原变量随即失效；要共享就用借用、要独立副本就显式 clone：

```rust
let s1 = String::from("hello");
let s2 = s1;          // 所有权 move 到 s2，此后 s1 不可再用
let s3 = s2.clone();  // 显式深拷贝，s2、s3 各自独立
```

借用则用 `&`：返回引用的函数需写生命周期标注（如 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`），声明"返回的引用活得和输入一样久"，编译器据此拒绝悬垂。多线程共享可变状态靠 `Arc<Mutex<T>>`，把数据安全锁在编译期保证之内。

## 何时用与何时不用

- **用**：操作系统、嵌入式、WebAssembly、网络服务、对性能与内存安全都苛刻且能接受陡峭学习曲线的系统级项目。
- **不用**：需要极快出原型、团队不愿吃借用检查 / 生命周期的心智成本、纯业务 CRUD（Go / Python 更省事的场景）。

## 优劣与代价

✅ 编译期内存与并发安全，无 GC 停顿，零成本抽象、性能比肩 C/C++。
✅ 强类型 + Cargo + 友好编译器诊断，工程体验好。
⚠️ 学习曲线陡（所有权 / 生命周期），编译期与借用检查器"较真"。
⚠️ 编译较慢，部分生态仍比成熟语言年轻。

## 与相关概念的区别

- **Rust vs C++**：C++ 靠 RAII + 手动管理，安全靠自觉；Rust 把规则交给编译器强制。
- **Rust vs Go**：Go 用 GC + goroutine 换取简单，Rust 用所有权换无 GC 的确定性性能。
- **借用 vs 移动 / 克隆**：借用是"临时看不夺所有权"，移动转移唯一所有权，克隆造独立副本。
- **Option / Result vs NULL / 异常**：用类型显式表达缺失与失败，强迫调用方处理。

## 常见误区

- Rust 和 Go / Java 一样靠垃圾回收管理内存。
- let s2 = s1; 之后 s1 还能照常继续使用。
- Rust 里内存绝对不可能不安全，因为根本没有 unsafe。
