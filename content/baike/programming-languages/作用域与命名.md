# 作用域与命名

> 📌 **导航**：本文是 **作用域与命名** 词条，属 [[编程语言通用概念]] 子词条。闭包机制见 [[闭包]]。

## 定义

**一句话定义：** 作用域规定一个名字在代码的哪些位置可见、其绑定何时产生与销毁；命名规范是团队为标识符约定的一致风格，用来降低歧义、提升可读性。

**通俗类比：** 作用域像"名字的有效期与可见范围"——局部变量只在这间屋（块/函数）里作数；命名规范像公司统一的工牌格式，一看就懂谁是谁。

## 为什么需要它

没有作用域，所有名字全局互撞、同名歧义、生命周期失控。词法作用域让名字按"定义处"解析，界定可见性与生命周期，支撑封装与闭包；一致的命名则让代码"读起来像散文"，减少沟通成本与误读。

## 核心机制

- **作用域种类**：全局 / 函数 / 块（`let`/`const` 在块）作用域；嵌套时内层可遮蔽（shadow）外层同名。
- **词法 vs 动态作用域**：主流语言词法（按书写位置解析），闭包即捕获词法环境（见 [[闭包]]）；动态作用域按调用链查名（少用）。
- **生命周期与提升**：绑定的存活期；部分语言（JS `var`、函数声明）有提升行为。
- **命名规范**：约定式如 camelCase/snake_case/CONSTANT_CASE、类型帕斯卡命名；语义清晰、避免缩写歧义、布尔用 is/has 前缀等，按语言惯例统一。

## 具体示例

块级作用域与遮蔽：

```javascript
let x = 1;
{ let x = 2; console.log(x); }  // 块内 x=2（遮蔽外层）
console.log(x);                  // 外层仍 1，块结束内部绑定销毁
```

## 何时用与何时不用

- **用**：把名字限制在尽量小的作用域、尽早释放；命名遵团队/语言惯例、表意清晰。
- **不用**：别滥用全局；别靠遮蔽制造可读性灾难；别为"短"牺牲可理解的名字。

## 优劣与代价

✅ 作用域带来封装、避免命名冲突、界定生命周期与 GC 友好。
✅ 统一命名提升可发现性与可读性。
⚠️ 遮蔽/提升/变量名混淆引入隐蔽 bug。
⚠️ 命名规范过严或团队不一致反生摩擦。

## 与相关概念的区别

- **作用域 vs 生命周期**：可见范围 vs 绑定存活期，常相关但不等同。
- **词法 vs 动态作用域**：名字按"写在哪"还是"从哪调用"解析。
- 与 [[控制流与函数]]：函数调用通常引入新作用域帧。

## 常见误区

- 块里声明的变量出了块仍可访问（视语言而定，如 JS `var` 会函数级泄漏）。
- 变量遮蔽（shadowing）总是好的、能让代码更简洁。
- 命名规范纯属个人偏好，无所谓统一。

## 面试速答

> 🎯 作用域=名字的可见范围与生命周期：全局/函数/块作用域，嵌套可遮蔽；词法作用域按书写位置解析、是闭包(见 [[闭包]])的基础，区别于按调用链的动态作用域。命名规范(camelCase/snake_case/CONSTANT、表意清晰、布尔 is/has)统一风格、降歧义。尽量小作用域、少全局、少遮蔽。
