# 栈与队列

> 📌 **导航**：本文是 **栈与队列** 词条，属 [[编程概念音频课-数据结构]] 子词条。底层载体见 [[数组与链表]]。

## 定义

**一句话定义：** 栈是后进先出（LIFO）的受限序列——只在栈顶 push/pop；队列是先进先出（FIFO）——一端入队、另一端出队。两者都可用数组或链表实现，只是限制了存取的位置。

**通俗类比：** 栈像一摞盘子，只能从顶上放/取；队列像食堂排队，先来的先打饭。约束了"在哪进出"，换来特定的顺序语义。

## 为什么需要它

很多算法只关心"最近的先处理"（递归、撤销、括号匹配、DFS）或"先来先服务"（任务队列、BFS、缓冲）。用栈/队列把访问顺序显式化，既符合问题语义，又能保证这些操作 O(1) 高效，避免随意访问带来的错误。

## 核心机制

- **栈**：`push`/`pop`/`peek`，LIFO；用于函数调用栈、表达式求值、括号/回文检测、DFS、撤销重做、单调栈。
- **队列**：`enqueue`/`dequeue`，FIFO；用于 BFS、生产者-消费者缓冲、任务调度、层序。
- **变体**：双端队列 deque（两端进出）、循环队列（数组复用空间避免搬移）、优先级队列（按 key 出队，见 [[堆与优先队列]]）、阻塞队列（并发）。
- 实现：数组定长需搬移/环形；链表天然适合头尾操作（见 [[数组与链表]]）。

## 具体示例

用数组实现的循环队列避免出队搬移：

```text
front, rear 环形推进：
入队  queue[rear] = x;  rear = (rear+1) % cap
出队  v = queue[front]; front = (front+1) % cap   // 均 O(1)，无需搬元素
```

## 何时用与何时不用

- **用栈**：需要"最近优先/嵌套配对/回溯"；用队列：需要"公平 FIFO/缓冲解耦/层序"。
- **不用**：要两端都频繁进出用 deque、按优先级出队用堆而非普通队列；只是随机读写序列直接用数组。

## 优劣与代价

✅ 语义清晰、进出 O(1)，是表达式解析/BFS/DFS/调度等的基础构件。
✅ 循环队列/链表实现规避数组搬移。
⚠️ 定长数组栈/队列需处理满/扩容；FIFO 数组队列若不用环形会 O(n) 搬移。
⚠️ 栈过深递归可能栈溢出（可转显式栈迭代）。

## 与相关概念的区别

- **栈 vs 队列**：LIFO vs FIFO，决定"谁先被处理"。
- **队列 vs 双端队列 vs 优先队列**：两端可操作 vs 按优先级出队（堆实现，见 [[堆与优先队列]]）。
- 均建于 [[数组与链表]] 之上。

## 常见误区

- 栈和队列只是数组换了个名字，没有额外约束。
- 用数组做队列，出队时不移动元素也能保持 O(1)。
- 优先队列一定用堆实现（也可有序数组等，堆只是常见高效选择）。

## 面试速答

> 🎯 栈 LIFO(递归/表达式/括号/DFS/撤销)、队列 FIFO(BFS/缓冲/调度/生产者消费者)；变体 deque(两端)、循环队列(数组复用免搬移)、优先队列(按 key，堆实现，见 [[堆与优先队列]])。用约束进出位置换顺序语义，进出 O(1)，数组或链表实现。
