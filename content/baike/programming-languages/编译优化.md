# 编译优化

## 定义

**一句话定义：** 编译优化(Compiler Optimization)是编译器在把源代码(或中间表示)翻译成目标代码的过程中,在不改变程序可观测语义的前提下,自动改写代码以生成更高效(更快、更小、更省资源)目标程序的一系列变换技术。

**通俗类比：** 像一个聪明的编辑——在保证原意不变的前提下,把啰嗦的句子精简、把重复的话合并、把顺序调整得更顺,让最终稿子(机器码)读起来(执行起来)更省力高效。

> 多义说明:优化可在不同层次(源码级、IR 级、目标码级)与作用域(局部/全局/过程间)进行;常见级别 -O0 / -O1 / -O2 / -O3 / -Os。本文综述。

## 原理与机制

- **局部优化(基本块内):** 常量折叠、公共子表达式消除、复写传播、强度削减。
- **全局优化(过程内跨基本块):** 基于数据流分析(到达定值、活跃变量),如循环不变量外提、循环展开。
- **过程间优化(IPO):** 函数内联(inlining)、跨函数常量传播。
- **其他:** 死代码消除、寄存器分配、指令调度、向量化(SIMD)。
- **约束:** 必须保持语义(可观测行为)不变;并在优化效果与编译时间/代码体积间权衡。

## 关键组成

| 组成 | 说明 |
|------|------|
| 优化级别 | -O0 ~ -O3 / -Os |
| 数据流分析 | 全局优化的基础 |
| 常量折叠 / 传播 | 编译期算出常量 |
| 循环优化 | 不变量外提、展开 |
| 内联 | 消除调用开销 |
| 死代码消除 / 寄存器分配 | 精简与资源分配 |

## 应用场景

- 所有编译型语言(C / C++ / Rust / Go 等)
- 性能关键的系统软件
- JIT 运行时优化
- 嵌入式(以 -Os 优化代码体积)

## 优点与局限

- 优点:自动生成更高效代码、无需手改源码、充分利用硬件特性。
- 局限:激进优化增加编译时间;可能使调试困难(代码与源不对应);优化基于假设(如严格别名);对依赖未定义行为的代码可能产生意外结果。

## 常见误区

- 优化不能改变程序的可观测语义(否则是错误)。
- 更高级别(-O3)不一定更好(可能增大体积,或触发与未定义行为相关的意外)。
- 优化会让调试与栈跟踪更难。
- 依赖未定义行为的代码在优化后可能"变脸",这不是编译器的错。
