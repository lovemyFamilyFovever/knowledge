# 编译优化

> 📌 **导航**：本文是 **编译优化** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 编译优化（Compiler Optimization）是编译器在把源代码或中间表示翻译成目标代码的过程中，在不改变程序可观测语义的前提下，自动改写代码以生成更高效（更快、更小、更省资源）目标程序的一系列变换技术。

**通俗类比：** 像一个聪明的编辑——在保证原意不变的前提下，把啰嗦的句子精简、把重复的话合并、把顺序调整得更顺，让最终稿子（机器码）执行起来更省力高效。

## 为什么需要它

手写汇编榨性能成本高、易错、还不可移植。编译优化把这活儿交给机器：在 IR 上反复应用一批"保持语义的等价变换"，自动做出常量折叠、消除冗余、循环改造、内联等人类懒得手工做的改进，让开发者用可读的高级语言也能得到接近手工调优的目标码。

## 核心机制

- **局部优化（基本块内）**：常量折叠、公共子表达式消除、复写传播、强度削减。
- **全局优化（过程内跨基本块）**：基于数据流分析（到达定值、活跃变量），如循环不变量外提、循环展开。
- **过程间优化（IPO）**：函数内联、跨函数常量传播。
- **其他**：死代码消除、寄存器分配、指令调度、向量化（SIMD）。
- **约束**：必须保持可观测语义不变，并在优化效果与编译时间 / 代码体积间权衡；常见级别 -O0 / -O1 / -O2 / -O3 / -Os。

## 具体示例

常量折叠把编译期就能算出的表达式直接替换成结果，省掉运行时计算：

```
x = 3 * 4 + 5      →      x = 17
```

## 何时用与何时不用

- **用**：所有编译型语言的性能敏感代码（C / C++ / Rust / Go）、JIT 运行时优化、嵌入式用 -Os 压体积。
- **不用（降低级别）**：正在调试、需要代码与源严格对应、栈跟踪清晰的阶段——用 -O0；上线前的性能构建再开高级别。

## 优劣与代价

✅ 自动生成更高效代码，无需手改源码，充分利用硬件特性。
✅ 高级别优化对热点循环、内联收益显著。
⚠️ 激进优化增加编译时间、可能膨胀代码体积。
⚠️ 代码与源行不再一一对应，调试与栈跟踪更难；优化基于假设（如严格别名），对依赖未定义行为的代码可能产生意外结果。

## 与相关概念的区别

- **保持语义 vs 改变语义**：合法优化只能改变"怎么算"，不能改变可观测行为；改了行为就是 bug。
- **优化级别权衡**：-O3 追求速度可能增大体积与编译时间，-Os 反过来优先体积，没有"越高越好"。
- **优化 vs 算法选择**：编译器做的是局部等价变换，换更优算法/数据结构是程序员层面的"优化"，二者层次不同。

## 常见误区

- 优化级别越高程序一定越快，-O3 永远优于 -O2。
- 为了让优化生效可以依赖未定义行为，编译器会按我想要的方式处理。
- 内联、指令重排等激进优化不会给调试带来任何影响。
