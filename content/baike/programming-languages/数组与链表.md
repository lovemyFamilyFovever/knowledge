# 数组与链表

> 📌 **导航**：本文是 **数组与链表** 词条，属 [[编程概念音频课-数据结构]] 子词条。复杂度见 [[复杂度分析]]。

## 定义

**一句话定义：** 数组在内存里连续存放、按下标 O(1) 随机访问，但中间增删要搬移；链表用"节点 + 指针"串联，随机访问只能顺走 O(n)，胜在已定位处插入/删除 O(1)。

**通俗类比：** 数组像一排编号储物柜——第 3 号一步走到，但中间塞一个就得整体挪；链表像"手拉手"的队伍——谁想插队，改一下前后牵的手即可，但要找第 5 个人得从头数过去。

## 为什么需要它

序列容器是几乎所有上层结构的底座，而"随机访问 vs 频繁增删、内存连续 vs 动态分散"是根本取舍。理解两者差异，才能为场景选对容器，也才看得懂栈/队列/哈希桶等的实现。

## 核心机制

- **数组**：连续内存、定长或动态扩容（翻倍均摊 O(1) 追加）、缓存友好（局部性好）。下标访问 O(1)、中间插入/删除 O(n)、支持二维/切片。
- **链表**： singly（next）/ doubly（prev+next，可双向）。定位后插入/删除 O(1)，随机访问/按值查 O(n)，无扩容拷贝但每节点额外指针、缓存不友好。
- 二者是 [[栈与队列]]、[[哈希表]] 等结构的底层承载。

## 具体示例

同一个"删除当前位置"的取舍：

```text
数组: 删中间元素 → 其后整体前移        O(n)
链表: 已持有节点 → 改前后指针即删除    O(1)
反向：按序号取第 k 个——数组 O(1)、链表 O(k)
```

## 何时用与何时不用

- **用数组**：读多、按下标随机访问、元素数稳定或只尾部增删、要缓存友好/向量化。
- **用链表**：已知位置频繁插入/删除（如 LRU 的双向链表）、元素数量波动大且不愿整体拷贝。
- 现实里多数"动态数组"（Python list、Java ArrayList）用数组，链表更多作特定结构的骨架。

## 优劣与代价

✅ 数组：随机访问快、内存紧凑、局部性好；链表：定位后增删 O(1)、无整块拷贝。
⚠️ 数组中间增删 O(n)、定长需扩容搬移；链表访问 O(n)、指针额外内存、缓存差、不能随机访问。
⚠️ 链表单线程下并发/回滚等需另设机制。

## 与相关概念的区别

- **数组 vs 链表**：连续+随机访问 vs 分散+顺序遍历；增删位置成本互补（见 [[复杂度分析]]）。
- **静态数组 vs 动态数组**：后者按需扩容、追加均摊 O(1)。
- 上层：栈/队列可两者实现（[[栈与队列]]）。

## 常见误区

- 链表一定比数组快，因为插入删除是 O(1)。
- 数组插入到中间也只是改个数，不影响后面的元素。
- Python 的 list 是链表。

## 面试速答

> 🎯 数组=连续内存、下标 O(1) 随机访问、缓存友好，但中间插删 O(n)、动态数组尾部追加均摊 O(1)；链表=节点+指针、定位后插删 O(1)，随机访问 O(n)、指针开销、缓存差。取舍在"随机访问 vs 频繁增删、连续 vs 动态"；栈/队列/哈希桶常建于其上（见 [[栈与队列]]、[[哈希表]]）。
