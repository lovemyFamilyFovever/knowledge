# 离散数学与组合

> 📌 **导航**：本文是 **离散数学与组合** 词条，属 [[程序员的数学基础]] 子词条。图的具体算法见 [[图算法大全]]。

## 定义

**一句话定义：** 离散数学是研究"可数、分离"结构的数学——集合论给数据结构与关系奠基、逻辑给程序与证明立规则、组合数学负责计数与可能性、图论刻画实体间的连接。

**通俗类比：** 它是编程的"数学语法"：集合是分类装东西的框、逻辑是 if 的严格版、组合是"有多少种摆法"、图是点与线画出的关系网。

## 为什么需要它

连续数学（微积分）之外，计算机处理的多是离散对象：类型/集合、布尔判定、算法复杂度计数、网络/依赖/调度建模成图。离散数学给这些提供精确语言与工具，是算法分析、数据库关系、形式验证、密码学的底座。

## 核心机制

- **集合论**：∈/∪/∩/补、笛卡尔积、关系与函数、基数（可数/不可数）——数据分类与关系模型的根。
- **数理逻辑**：命题/谓词逻辑、¬∧∨→、量词 ∀∃，是布尔代数、查询条件与程序正确性推理的形式语言。
- **组合数学**：排列/组合、二项式、加法/乘法原理、鸽巢、容斥——用于计数与概率、算法复杂度分析。
- **图论**：图 G=(V,E)、度/路径/连通/树/二部/有向、欧拉·哈密顿——算法实现详见 [[图算法大全]]。

## 具体示例

计数与逻辑无处不在：

```text
子集数:  n 元集合有 2^n 个子集；选 k 个有 C(n,k)=n!/(k!(n-k)!)
谓词逻辑: ∀x (Student(x) → Person(x))  —— 推理与查询条件的形式基础
```

## 何时用与何时不用

- **用**：算法复杂度与计数分析、数据库/类型/关系建模、布尔表达式化简、把网络/依赖建成图、形式化验证与密码学基础。
- **不用**：图像/信号/数值仿真等连续问题更多要用微积分/线性代数（见 [[线性代数]]），别硬套离散框架。

## 优劣与代价

✅ 给"可数结构 + 精确推理"统一语言，是算法/DB/形式方法的根基。
✅ 组合与图论直接支撑复杂度分析与建模。
⚠️ 组合爆炸使精确计数/推理在实际中难（近似、上限、NP 难）。
⚠️ 形式化门槛高，工程里常被"够用即可"替代。

## 与相关概念的区别

- **离散 vs 连续数学**：前者处理可数/结构（本词条），后者微积分/实数（数值计算）。
- **图论（数学）vs 图算法（实现）**：本词条讲结构与性质，具体遍历/最短路算法见 [[图算法大全]]。
- 与 复杂度分析：组合计数常用于复杂度推导。

## 常见误区

- 图论就是画图画得好看，和算法实现无关。
- 集合与列表是一回事，可以互相替代理解。
- 离散数学偏理论，对写工程代码没有实际用处。

## 面试速答

> 🎯 离散数学=可数结构的数学：集合论(∈/∪/∩/笛卡尔积/关系函数/基数)、逻辑(命题/谓词/量词/布尔)、组合(排列组合/二项式/容斥/鸽巢，支撑计数与复杂度)、图论(G=(V,E)/连通/树，算法见 [[图算法大全]])。是算法分析、数据库、类型、密码学、形式验证的语言底座。
