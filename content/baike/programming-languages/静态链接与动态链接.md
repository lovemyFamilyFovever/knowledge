# 静态链接与动态链接

## 定义

**一句话定义：** 静态链接与动态链接是程序构建时把目标文件与库代码组合成可执行文件的两种方式——静态链接在编译期把库代码直接复制进可执行文件;动态链接则在运行时由加载器/动态链接器把共享库装载并绑定到程序。

**通俗类比：** 静态链接像把参考书中需要的页全部复印进你自己的手册(自带、独立、但厚);动态链接像在手册里写"详见图书馆某书第几页"(引用共享的书,手册薄,但用时得去图书馆取)。

> 多义说明:静态库(如 `.a` / `.lib`)与动态/共享库(如 `.so` / `.dll` / `.dylib`);链接分别发生在编译期与运行期。本文对比二者。

## 原理与机制

- **静态链接:** 链接器把用到的库目标代码复制进最终可执行文件;产物自包含、体积大;运行时不依赖外部库文件。
- **动态链接:** 可执行文件只记录对共享库的引用;加载时由动态链接器(如 `ld.so`)解析符号、加载 `.so`/`.dll`;多个进程可共享同一份库的内存映像。
- **符号解析与重定位:** 两种链接都需解析符号引用、重定位地址;动态链接把部分工作推迟到运行时(甚至惰性绑定 lazy binding)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 静态库(.a/.lib) | 编译期并入可执行文件 |
| 共享库(.so/.dll/.dylib) | 运行时加载、可共享 |
| 链接器 | 静态链接阶段工作 |
| 动态链接器/加载器 | 运行时解析与绑定 |
| 符号解析与重定位 | 两种链接都涉及 |

## 应用场景

- 发布独立可执行文件(静态链接)
- 系统共享库、节省内存与磁盘(动态链接)
- 插件机制、库的热更新(动态)

## 优点与局限

- 静态:优点=自包含、部署简单、启动快、无运行时依赖;局限=体积大、多程序重复占用磁盘/内存、库更新需重新编译。
- 动态:优点=体积小、多程序共享库省内存、库可独立升级;局限=运行时依赖(缺库或版本不符则失败,如 "DLL hell")、加载/绑定有开销、部署需附带库。

## 常见误区

- 静态链接产物大但独立;动态链接产物小但依赖外部库文件。
- 动态库省内存,是因为多进程共享同一份物理页。
- 动态链接的版本不匹配是常见部署问题。
- 二者可在同一程序中混合使用。
