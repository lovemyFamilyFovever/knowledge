# 静态链接与动态链接

> 📌 **导航**：本文是 **静态链接与动态链接** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 静态链接与动态链接是程序构建时把目标文件与库代码组合成可执行文件的两种方式——静态链接在编译期把库代码直接复制进可执行文件；动态链接则在运行时由加载器 / 动态链接器把共享库装载并绑定到程序。

**通俗类比：** 静态链接像把参考书需要的页全部复印进你自己的手册（自带、独立、但厚）；动态链接像在手册里写"详见图书馆某书第几页"（引用共享的书，手册薄，但用时得去图书馆取）。

## 为什么需要它

库代码什么时候并入程序、以什么形态存在，决定了"能不能独立跑、占多少磁盘内存、库升级要不要重编"。静态链接换来"一个文件走天下"的自包含；动态链接换来"多个程序共享同一份库、库可独立升级"的经济性。理解二者才能解释为什么会有 DLL hell、为什么 Go 能发单文件、插件为什么用 .so。

## 核心机制

- **静态链接**：链接器把用到的库目标代码复制进最终可执行文件；产物自包含、体积大；运行时不依赖外部库文件。
- **动态链接**：可执行文件只记录对共享库的引用；加载时由动态链接器（如 ld.so）解析符号、加载 .so/.dll；多个进程可共享同一份库的内存映像。
- **符号解析与重定位**：两者都要解析符号、重定位地址；动态链接把部分工作推迟到运行时（甚至惰性绑定 lazy binding）。

## 具体示例

同一个依赖，静态方式把库并进可执行文件、动态方式只在运行时找它：

```
gcc app.o ./libfoo.a     # 静态：把 foo 代码并进 app，产物自包含
gcc app.o -L. -lfoo      # 动态：运行时需能加载 libfoo.so
```

## 何时用与何时不用

- **用静态**：要发独立单文件、目标机器环境不可控、追求启动快与零外部依赖（命令行工具、嵌入式）。
- **用动态**：多程序共用大库以省磁盘/内存、需要库独立升级或插件热加载（系统库、插件机制）。

## 优劣与代价

✅ 静态：自包含、部署简单、启动快、无运行时依赖。
⚠️ 静态：体积大、多程序重复占用、库更新需重新编译。
✅ 动态：体积小、多进程共享库省内存、库可独立升级。
⚠️ 动态：运行时依赖，缺库或版本不符即失败（DLL hell），加载/绑定有开销。

## 与相关概念的区别

| 维度 | 静态链接 | 动态链接 |
|---|---|---|
| 库并入时机 | 编译期 | 运行期加载 |
| 产物体积 | 大 | 小 |
| 外部依赖 | 无 | 需对应 .so/.dll |
| 多程序共享 | 各带一份 | 共享同一份内存映像 |
| 库升级 | 需重编 | 可替换库文件 |

- **静态库（.a/.lib）vs 共享库（.so/.dll/.dylib）**：前者编译期并入、后者运行时加载。
- 同一程序可混合两者（部分库静态、部分动态）。

## 常见误区

- 静态链接的程序运行时仍需外部静态库才能跑。
- 静态链接产物更小、动态链接产物更大。
- 动态库既然能共享，就永远不会有版本冲突。

## 面试速答

> 🎯 静态链接在编译期把库代码复制进可执行文件（自包含、体积大、无运行时依赖）；动态链接只记引用，运行时由加载器装载共享库（体积小、多进程共享、但有版本依赖如 DLL hell）。
