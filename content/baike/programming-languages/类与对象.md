# 类与对象

> 📌 **导航**：本文是 **类与对象** 词条，属 [[面向对象编程（OOP）概念]] 子词条。

## 定义

**一句话定义：** 类是"数据与操作它的函数的蓝图"，对象是"类的一个实例（带自身状态）"；构造函数在创建时初始化、析构/Finalizer 在销毁时清理，访问修饰符划定成员的可见范围。

**通俗类比：** 类是"月饼模具"，对象是用模具压出的每一块饼（形状相同、馅料各异）；构造是"成型工序"、析构是"吃完收拾"，访问修饰符决定哪些馅对外可见。

## 为什么需要它

把"状态 + 行为"封装成一个单元，程序从"一堆函数操作全局数据"进化到"对象间发消息协作"。类给复用与类型抽象的模板，对象承载各自状态；构造/析构管生命周期、访问控制管封装边界，是 OOP 的地基。

## 核心机制

- **类与实例**：类定义字段与方法；实例化得到各自持有状态的对象。
- **构造/析构**：构造负责初始化（可重载、支持默认/带参），析构负责释放资源；生命周期与 GC/RAII 相关。
- **成员分类**：实例成员 vs 类(静态)成员；`this/self` 引用当前对象。
- **访问修饰符**：public/protected/private（+ 包内/内部等，依语言）——决定封装边界；尽量最小可见。

## 具体示例

一个类的最小骨架（构造 + 私有字段 + 方法）：

```python
class Account:
    def __init__(self, owner, balance=0):   # 构造，初始化实例状态
        self.owner = owner
        self.__balance = balance             # 双下划线=名称改写，近似私有
    def deposit(self, amt): self.__balance += amt
```

## 何时用与何时不用

- **用**：有明确"实体 + 状态 + 行为"的建模；用私有封装不变量、构造统一初始化。
- **不用**：纯数据或无状态操作可用函数/记录；别为"像 OOP"把简单流程包成一堆类。

## 优劣与代价

✅ 状态与行为内聚、可复用（模板→多实例）、生命周期清晰。
✅ 访问控制支撑封装、降低耦合。
⚠️ 过度类化导致"类爆炸"与层层间接。
⚠️ 静态成员/全局单例状态易成隐式耦合（见 [[单例模式]]）。

## 与相关概念的区别

- **类 vs 对象**：类型定义 vs 具体实例（含独立状态）。
- **构造 vs 普通方法**：构造在实例化时自动调用、通常无返回类型。
- **实例成员 vs 静态成员**：随对象 vs 随类共享。
- 与 [[封装与继承]]：可见性在此、继承机制在其。

## 常见误区

- 静态成员每个对象各有一份。
- 加了 private 关键字，字段在语言里就绝对读不到（多数只是访问控制，反射可破）。
- 构造函数必须显式写（多数语言有默认构造）。

## 面试速答

> 🎯 类=数据+行为的蓝图、对象=带自身状态的实例；构造初始化、析构清理资源(配 GC/RAII)，可重载；实例成员随对象、静态成员随类共享；访问修饰符(public/protected/private)划封装边界、取最小可见。是 OOP 把状态与行为内聚的地基。
