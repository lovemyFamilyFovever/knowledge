# TypeScript高级编程指南

> 📌 **导航**：本页是 **TypeScript 高级编程** 枢纽。类型基础/泛型/工具类型概览见 [[TypeScript深入]]；高级主题已拆子词条。

## 定义

**一句话定义：** TypeScript 高级编程，是超越日常标注的能力——用类型体操做类型级计算、用模块与声明文件对接外部代码、用装饰器与编译器 API 做元编程与工具链，从而写库、做框架与 IDE 级工程化。

**通俗类比：** [[TypeScript深入]] 教你"怎么给代码加类型"，本页是"怎么让类型本身去算、去描述外部世界、被工具读取"——从用 TS 到造 TS 生态。

## 为什么需要它

写通用库、框架、代码生成/lint 工具时，光会标类型不够：要精确推导返回类型、给无类型 JS 补声明、按运行环境组织模块、用装饰器织横切、用编译器 API 读 AST。这些是把 TS 用到极致的工具箱。

## 具体示例

一条写库的链路：用 [[TypeScript 高级类型与类型体操]] 精确推导 API 返回类型 → 用 [[TypeScript 模块与声明文件]] 定义打包格式与 `.d.ts` 对外发布 → 框架场景用装饰器、工具链用编译器 API（[[TypeScript 装饰器与编译器API]]）。基础语法层见 [[TypeScript深入]]。

## 何时用与何时不用

- **用**：开发对外发布的库/框架/CLI/代码生成工具；跨模块环境或对接无类型 JS 时。
- **不用**：普通业务应用优先可读直白，别堆类型体操；基础类型够用就留在 [[TypeScript深入]] 层。

## 优劣与代价

✅ 把 TS 从"加类型"升到"类型级编程 + 生态互操作 + 工具链"。
✅ 精确推导与强声明提升库的类型安全与 DX。
⚠️ 高级特性可读性/维护成本上升、编译变重、易炫技。
⚠️ 模块规范与装饰器双标准带来迁移与互操作坑。

## 与相关概念的区别

- **类型体操 vs 类型标注**：前者在类型层"算"新类型，后者描述值；基础见 [[TypeScript深入]]。
- **编译器 API（编译期）vs 装饰器反射（运行期元数据）**：作用阶段不同，别混为一谈。
- **模块（组织运行代码）vs 声明文件（只描述类型）**。

## 常见误区

- 类型体操越花哨越好，能写多复杂写多复杂。
- `.d.ts` 和 `.ts` 没区别，都可以含实现。
- 实验性装饰器和标准装饰器是一回事。

## 面试速答
