# Rust Trait与泛型

> 📌 **导航**：本文是 **Rust Trait 与泛型** 词条，属 [[Rust系统编程入门到精通]] 子词条。所有权/借用见 [[Rust编程基础]]。

## 定义

**一句话定义：** Rust 用 Trait 定义共享行为契约、用泛型写与类型无关的代码并在编译期单态化，用 Trait 对象做运行期动态分发——三者共同支撑它的抽象与复用。

**通俗类比：** Trait 像"能充电的设备"这一能力标签，泛型让充电器适配任意符合标签的机型；编译期泛型=为每种机型专门造一台（单态化），Trait 对象=统一插口运行时认机型（动态分发）。

## 为什么需要它

既要零成本抽象又要复用，泛型让你写一份逻辑服务多类型、并在编译期展开成专用代码（无运行期开销）；Trait 提供"哪些类型能互换"的契约，是重写、约束与多态的载体；需要异构集合/运行时决定类型时用 Trait 对象。

## 核心机制

- **Trait**：声明方法签名（可带默认实现），`impl Trait for Type` 实现；`+` 组合约束、可带关联类型。
- **泛型与单态化**：`fn f<T: Bound>(x: T)`，编译器为每个具体 T 生成专用代码，运行期零开销，代价是代码膨胀与编译时间。
- **Trait 对象动态分发**：`dyn Trait`（胖指针：数据指针 + vtable）走运行时查表，用于异构集合/递归类型；与泛型的静态分发相对。
- **选择**：能用泛型（静态、单态化）优先；需运行期多态或类型擦除时用 `dyn`。

## 具体示例

静态分发（泛型）与动态分发（`dyn`）之别：

```rust
fn print_item<T: Display>(x: &T) { println!("{x}"); }   // 单态化，零开销
let items: Vec<Box<dyn Display>> = vec![Box::new(1), Box::new("s")]; // 异构，动态分发
for it in &items { println!("{it}"); }
```

## 何时用与何时不用

- **用**：跨类型复用逻辑→泛型；约定能力/做接口→Trait；异构集合或需要对象安全时→`dyn Trait`。
- **不用**：滥用 trait object 平白引入 vtable 开销与间接；泛型过度约束会放大编译期与体积。

## 优劣与代价

✅ 泛型单态化=零成本抽象、类型安全、无装箱。
✅ Trait 让复用与多态清晰、可组合约束。
⚠️ 泛型过度用致代码膨胀/编译慢、错误信息冗长。
⚠️ `dyn` 有运行期分发开销且受对象安全限制。

## 与相关概念的区别

- **泛型（静态分发）vs Trait 对象（动态分发）**：前者编译期定、可内联、单态化；后者运行时查 vtable、支持异构。
- **Trait vs 结构体方法**：Trait 是跨类型的共享契约，可被泛型约束、被多类型实现。
- 与 Go 隐式接口（[[Go接口与反射]]）：Rust 需显式 `impl Trait for`，类型关系更明确。

## 常见误区

- `dyn Trait` 和泛型完全等价，随便选。
- Trait 只能声明方法、不能有默认实现或关联类型。
- 泛型运行时要装箱、有性能损失。

## 面试速答

> 🎯 Rust 抽象三件套：Trait(能力契约，可默认实现/关联类型)、泛型(与类型无关、编译期单态化=零成本但会膨胀)、`dyn Trait`(胖指针+vtable 运行期动态分发，支持异构)。选静态还是动态看是否需要运行期多态/类型擦除。
