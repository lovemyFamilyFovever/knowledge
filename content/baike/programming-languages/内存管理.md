# 内存管理

## 定义

**一句话定义：** 内存管理(Memory Management)是程序运行时对内存资源的分配、使用与回收的管理机制,包括栈与堆的组织、对象的分配与释放,以及防止内存泄漏与悬垂指针;可由程序员手动管理(C/C++),或由运行时自动管理(GC 语言)。

**通俗类比：** 像管理一间仓库的货架——东西(对象)放哪、怎么找空位(分配)、用完怎么腾出来(回收)、别把过道堵死(泄漏)、别指着已清走的货位(悬垂指针);有的仓库靠管理员自动整理(GC),有的靠你自己借还(手动)。

> 多义说明:本文从编程语言/运行时视角讨论内存管理(栈/堆、分配/回收);操作系统层面的虚拟内存与分页见 [[虚拟内存]],二者相关但层次不同。

## 原理与机制

- **栈(stack):** 由编译器/运行时自动管理,函数调用压栈、返回弹栈;存局部变量,速度快,生命周期随作用域。
- **堆(heap):** 动态分配,生命周期由程序控制;需显式 `free`(C/C++)或由 GC(Java/Go/Python 等)回收。
- **手动管理:** `malloc/free`、`new/delete`;易出现内存泄漏(忘记释放)、悬垂指针(释放后仍用)、双重释放、越界。
- **自动/其他:** 垃圾回收(见 [[垃圾回收]])、RAII(C++/Rust,作用域结束自动释放)、所有权模型(Rust,编译期保证内存安全且无 GC)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 栈 | 自动管理、随作用域 |
| 堆 | 动态分配、需管理 |
| 分配器(allocator) | 负责分配/回收 |
| 手动 free / GC | 两种回收方式 |
| RAII / 所有权 | 确定性释放 / 编译期安全 |
| 常见错误 | 泄漏 / 悬垂 / 越界 |

## 应用场景

- 所有程序的运行时内存使用
- 系统/嵌入式编程(手动管理)
- 托管语言(GC)
- Rust 所有权模型、性能与内存优化

## 优点与局限

- 手动:优点=精细控制、无 GC 开销、行为可预测;局限=易错(泄漏/悬垂/双重释放)、心智负担重。
- 自动(GC):优点=安全省心、减少泄漏;局限=GC 停顿与开销、控制粒度低、回收时机不确定。

## 常见误区

- 内存管理 ≠ 只有 GC:还有手动管理、RAII、所有权模型。
- 栈内存自动回收(随作用域),需要管理的主要是堆内存。
- 内存泄漏(该释放没释放)≠ 内存溢出(OOM,分配超过可用)。
- "有 GC 就没有内存问题"是错的(逻辑泄漏、意外持有引用仍会发生)。
- Rust 用所有权在编译期保证内存安全,无需 GC。
