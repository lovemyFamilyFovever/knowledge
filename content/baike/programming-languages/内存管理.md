# 内存管理

> 📌 **导航**：本文是 **内存管理** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 内存管理（Memory Management）是程序运行时对内存资源的分配、使用与回收的管理机制，包括栈与堆的组织、对象的分配与释放，以及防止内存泄漏与悬垂指针；可由程序员手动管理（C/C++），或由运行时自动管理（GC 语言）。

**通俗类比：** 像管理一间仓库的货架——东西放哪、怎么找空位（分配）、用完怎么腾出来（回收）、别把过道堵死（泄漏）、别指着已清走的货位（悬垂指针）；有的仓库靠管理员自动整理（GC），有的靠你自己借还（手动）。

## 为什么需要它

每个对象都要"生"和"死"：谁来分配、谁记得释放、什么时候能安全回收。管不好就会出现内存泄漏（越跑越吃内存）、悬垂指针（访问已释放内存导致崩溃或安全漏洞）、双重释放。内存管理的目标，就是在性能、安全与心智负担之间选择一套合适的策略。

## 核心机制

- **栈**：由编译器 / 运行时自动管理，函数调用压栈、返回弹栈；存局部变量，速度快，生命周期随作用域。
- **堆**：动态分配，生命周期由程序控制；需显式 free（C/C++）或由 GC（Java / Go / Python）回收。
- **手动管理**：malloc/free、new/delete；易出现泄漏、悬垂、双重释放、越界。
- **确定性 / 编译期方案**：RAII（C++/Rust，作用域结束自动释放）、所有权模型（Rust 编译期保证内存安全且无 GC）。

## 具体示例

手动管理最典型的泄漏：分配后把指针覆盖，原内存再无引用却也再也释放不了——

```c
char *p = malloc(128);
p = NULL;        /* 原 128 字节再无引用 → 内存泄漏 */
```

## 何时用与何时不用

- **手动 / RAII / 所有权**：系统、嵌入式、对延迟和确定性要求高的场景。
- **GC**：业务应用、快速开发，换取"不必手写 free"的安全与省心。
- **权衡点**：需要可控的停顿和极致的资源利用时慎用 GC；追求开发效率、内存占用不极端时慎用手动。

## 优劣与代价

✅ 手动：精细控制、无 GC 开销、行为可预测。
⚠️ 手动：易错（泄漏 / 悬垂 / 双重释放）、心智负担重。
✅ GC：安全省心、显著减少泄漏。
⚠️ GC：有停顿与开销、回收时机不确定、控制粒度低。

## 与相关概念的区别

- **栈 vs 堆**：栈自动、随作用域、分配极快；堆动态、生命周期需管理、灵活但有开销。
- **内存泄漏 vs 内存溢出**：泄漏是"该释放没释放"、逐渐累积；OOM 是"单次分配超过可用"，二者不同。
- **GC vs RAII vs 所有权**：GC 运行期自动回收（时机不定）、RAII 作用域退出确定性释放、Rust 所有权在编译期就杜绝大部分问题且无 GC。

## 常见误区

- 用了带 GC 的语言就彻底不会有内存问题了。
- 内存泄漏和内存溢出（OOM）是一回事。
- 栈上的对象也需要程序员手动 free。
