# Rust 智能指针

> 📌 **导航**：本文是 **Rust 智能指针** 词条，属 [[Rust系统编程入门到精通]] 子词条。所有权/借用基础见 [[Rust编程基础]]。

## 定义

**一句话定义：** 智能指针是带元数据与析构逻辑、管理堆/共享/可变性的指针类型——`Box` 堆分配、`Rc` 引用计数共享、`Arc` 原子引用计数跨线程共享、`RefCell` 运行期借用（内部可变性）。

**通俗类比：** 普通引用是"借书看一眼就还"，智能指针像"带归还提醒和计数器的书卡"——谁最后拿着、引用还剩几个、何时自动销毁，都由它管。

## 为什么需要它

纯所有权只能单属、编译期借用检查，够不到某些模式：需要把大数据放堆上/移交所有权(Box)、需要多所有者共享(Rc/Arc)、需要在只读接口下做局部可变(RefCell)、需要递归类型自引用。智能指针补足这些，同时保留自动释放。

## 核心机制

- **`Box<T>`**：值放堆、栈上存指针；用于递归类型、大值转移、trait object（`Box<dyn Trait>`）。离开作用域自动 drop。
- **`Rc<T>`**：非原子引用计数，单线程多所有者共享；计数归零才释放。不能跨线程（否则用 `Arc`）。
- **`Arc<T>`**：原子引用计数，跨线程安全共享。
- **`RefCell<T>`**：内部可变性——把借用检查从编译期挪到运行期（`borrow`/`borrow_mut` 计数，违反则 panic）；常与 `Rc` 组 `Rc<RefCell<T>>` 得"多所有者且可变"。
- **`Deref`/`Drop`/`Weak`**：像引用一样解引用、离开作用域执行清理、`Weak` 打断循环引用防泄漏。

## 具体示例

共享且可变的常见组合 `Rc<RefCell<T>>`：

```rust
let a = Rc::new(RefCell::new(0));
let b = Rc::clone(&a);
*a.borrow_mut() += 1;              // 运行期可变
println!("{}", *b.borrow());       // 1；Rc 计数归零才释放
```

## 何时用与何时不用

- **用**：递归/大值→Box；多属主共享→Rc（单线程）/Arc（跨线程）；只读接口内需局部改→RefCell；断环→Weak。
- **不用**：能用普通引用/所有权表达就别上 `Rc<RefCell<_>>`；单线程共享别误用 `Arc`（原子开销），跨线程别用 `Rc`（不 Send）。

## 优劣与代价

✅ 在保留自动内存管理的同时补齐共享/可变/堆分配场景。
✅ Drop 保证资源成对释放，无手动 free。
⚠️ RefCell 把借用违规推迟到运行期 panic；Rc/Arc 有计数开销、循环引用会泄漏（需 Weak）。
⚠️ `Rc<RefCell<T>>` 滥用会把编译期安全换成运行期小心。

## 与相关概念的区别

- **`Box` vs `&`**：Box 拥有堆值、可转移/做 trait object；& 只是借用不拥有。
- **`Rc` vs `Arc`**：计数是否原子；能否跨线程。
- **`RefCell` vs 普通可变**：编译期借用检查 vs 运行期借用检查（内部可变性）。
- 与 Go/Java GC（[[内存管理]]）：Rust 无 GC，靠所有权+引用计数+Drop 决定生命周期。

## 常见误区

- `Rc<T>` 可以安全地在多线程间共享。
- `RefCell<T>` 只是语法糖，不会在运行期 panic。
- `Rc` 循环引用不会导致内存泄漏。

## 面试速答

> 🎯 智能指针补所有权够不到的场景：Box(堆/递归/trait object)、Rc(单线程多所有者)、Arc(原子计数可跨线程)、RefCell(运行期借用的内部可变，常配 Rc)，配 Deref/Drop/Weak(断环)。无 GC、靠计数+Drop 释放，代价是计数开销与运行期借用 panic。
