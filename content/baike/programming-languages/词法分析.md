# 词法分析

> 📌 **导航**：本文是 **词法分析** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 词法分析（Lexical Analysis，又称扫描 scanning）是编译的第一阶段，它把源代码的字符流按语言的词法规则切分为一个个有意义的最小单元——词法单元（token），如关键字、标识符、常量、运算符，再交给后续的语法分析。

**通俗类比：** 像读一句话先把它切成一个个单词——"我 / 爱 / 编程"；词法分析就是把连续的字符流切成关键字、标识符、运算符、常量、分隔符这些"单词"。

## 为什么需要它

后续的语法分析、语义分析若直接面对原始字符流，要一边识别单词一边解析结构，职责混杂、效率低。词法分析先把"字符"升格为"token"这一离散、带类型与位置的符号流，让语法层只关心结构、报错时也能给出精确行列，把编译前端拆成职责清晰的两个阶段。

## 核心流程

- **规则**：词法规则通常用正则表达式描述，其识别程序由有限状态自动机（DFA/NFA）实现（见 [[有限状态机]]）。
- **扫描**：词法分析器（scanner / lexer）逐字符扫描，按最长匹配等原则识别 token，记录类型、值、位置（行列，用于报错）。
- **附带处理**：跳过空白与注释、识别字面量，某些语言还做宏展开、字符串相邻拼接。
- **工具**：Lex / Flex 可由正则规则自动生成词法分析器。

## 具体示例

源代码 `int x = 5;` 经扫描后，空白被丢弃，其余字符被归并成如下 token 流交给语法分析：

| 片段 | token 类型 | 值 |
|---|---|---|
| int | 关键字 | int |
| x | 标识符 | x |
| = | 运算符 | = |
| 5 | 整型常量 | 5 |
| ; | 分隔符 | ; |

## 何时用与何时不用

- **用**：编译器 / 解释器前端、IDE 语法高亮、代码格式化的第一步、DSL 解析、Lint 工具。
- **不用（单独拿出来）**：结构级判断（表达式优先级、括号配对、语句嵌套）不属于词法层，应交给语法分析。

## 优劣与代价

✅ 把字符流抽象为 token，简化后续分析；正则 + 自动机理论成熟、运行高效。
✅ 与语法分析解耦，报错可定位到行列。
⚠️ 只能识别正则语言，无法处理需要上下文或栈的结构。
⚠️ 词法与语法的边界因语言而异（如 C 的"最长匹配"歧义、缩进语言把结构放进词法）。

## 与相关概念的区别

- **词法分析 vs 语法分析**：词法把字符切成 token（"有哪些单词"），语法把 token 组织成语法结构（"句子结构对不对"）；括号配对、优先级属于语法层。
- **正则语言 vs 上下文无关语言**：词法规则用正则、由有限状态机识别；文法用上下文无关文法、由带栈的下推自动机识别。
- **token vs 记号字面量**：token 是"类型"（整型常量），lexeme 是"这段原文"（`5`）。

## 常见误区

- 词法分析能判断括号是否配对、语句结构是否合法。
- 词法规则一般用上下文无关文法描述、由下推自动机识别。
- token 只有关键字和标识符两类。

## 面试速答

> 🎯 词法分析（扫描）是编译第一阶段：把字符流按词法规则切成 token（类型 + 值 + 位置），规则用正则、识别靠有限状态机，不负责结构合法性。
