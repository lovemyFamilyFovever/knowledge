# 词法分析

## 定义

**一句话定义：** 词法分析(Lexical Analysis,又称扫描 scanning)是编译的第一阶段,它把源代码的字符流按语言的词法规则切分为一个个有意义的最小单元——词法单元(token),如关键字、标识符、常量、运算符,再交给后续的语法分析。

**通俗类比：** 像读一句话先把它切成一个个单词——"我 / 爱 / 编程";词法分析就是把连续的字符流 `int x = 5;` 切成 int(关键字)、x(标识符)、=(运算符)、5(常量)、;(分隔符)这些"单词"。

> 多义说明:词法分析产出 **token 流**;它与语法分析(把 token 组织成结构)是相邻但不同的阶段。本文讲词法分析。

## 原理与机制

- **规则:** 词法规则通常用正则表达式描述,其识别程序由有限状态自动机(DFA/NFA)实现(见 [[有限状态机]])。
- **扫描:** 词法分析器(scanner / lexer)逐字符扫描,按最长匹配等规则识别 token,并记录类型、值、位置(行列,用于报错)。
- **附带处理:** 跳过空白与注释、识别字面量,可能做宏展开、字符串拼接等。
- **工具:** Lex / Flex 等可由正则规则自动生成词法分析器。

## 关键组成

| 组成 | 说明 |
|------|------|
| 字符流输入 | 原始源代码 |
| token | 类型 + 值 + 位置 |
| 正则规则 | 描述各类 token 的模式 |
| 有限状态自动机 | 识别 token 的机制 |
| 符号表交互 | 登记标识符等信息 |

## 应用场景

- 编译器 / 解释器前端
- IDE 语法高亮
- 代码格式化的第一步
- DSL 解析、Lint 工具

## 优点与局限

- 优点:把字符流抽象为 token、简化后续分析;正则 + 自动机理论成熟、高效。
- 局限:只能处理正则语言(无法识别需要上下文的结构,如括号配对——那是语法分析的职责);与语法分析的边界划分因语言而异。

## 常见误区

- 词法分析 ≠ 语法分析:前者切 token,后者建结构。
- 词法层无法判断括号是否匹配(需要语法分析 + 栈)。
- token 不只关键字,还有标识符、常量、运算符、分隔符。
- 词法规则用正则表达式描述,对应有限状态机。
