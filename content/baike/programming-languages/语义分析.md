# 语义分析

> 📌 **导航**：本文是 **语义分析** 词条，属 [[编译原理与解释器实现]] 子词条。前后阶段见 [[语法分析]]、[[中间表示]]。

## 定义

**一句话定义：** 语义分析在通过语法的 AST 上检查"含义是否合法"——建符号表解析变量/函数作用域、做类型检查与推导、标注类型信息，把"结构正确但语义错误"（未定义、类型不符）在编译期拦下。

**通俗类比：** 语法分析确认"句子成分齐全"，语义分析确认"这句话讲不讲得通"——有没有引用不存在的词、动词和宾语搭不搭。

## 为什么需要它

语法合法 ≠ 有意义：`x = y + 1` 语法没问题，但 y 未声明、或 int+string 类型不匹配。若无语义层，这些要么运行期才炸、要么悄悄出错。语义分析把作用域与类型规则集中、提前报错，并为后续 [[中间表示]]/优化提供类型注解。

## 核心机制

- **符号表**：登记标识符→类型/作用域/存储；进入新作用域压栈、退出弹栈，支持嵌套遮蔽。
- **名字解析**：把 AST 里的名字绑定到声明（词法作用域链查找，见 [[闭包]]机制）。
- **类型检查/推导**：自底向上综合、必要时向下推断；检查赋值/调用/运算的类型相容。
- 在 AST 上"装饰"类型与作用域信息，产物交下游。

## 具体示例

类型检查伪流程：

```text
check(  x = e ):
  ty = typeOf(e)          # 递归求表达式类型
  if not assignable(int, ty): error("类型不匹配")
  symtab[x] = int         # 符号表登记/校验已声明
```

## 何时用与何时不用

- **用**：静态语言编译前端必做；动态语言可延后到运行期做（鸭子类型）。
- **不用**：解释型脚本常把类型检查推到运行期，不必编译期全量检查。

## 优劣与代价

✅ 编译期捕获未定义/类型错误，早且准，信息交优化器。
✅ 符号表+类型标注是后续阶段的公共底座。
⚠️ 复杂类型系统（泛型/推导）实现难、报错易晦涩。
⚠️ 过度严格会误拒合法惯用法。

## 与相关概念的区别

- **语法 vs 语义分析**：前者验结构合法（[[语法分析]]、[[抽象语法树]]），后者验含义合法。
- **类型检查 vs 类型推断**：检查是"给定类型验证"，推断是"由表达式求类型"；常配合。
- 输出为 [[中间表示]] 与 [[编译优化]] 供料。

## 常见误区

- 过了语法检查就能安全编译运行。
- 符号表只在词法分析阶段有用。
- 静态语言一定不做类型推断（很多都做局部/全局推断）。

## 面试速答

> 🎯 语义分析在合法 AST 上验含义：符号表(标识符→类型/作用域，进出作用域压弹栈、支持遮蔽)、名字解析(按词法作用域绑定声明)、类型检查(验证相容)/推导(求表达式类型)，编译期拦下未定义/类型错并给 AST 装饰类型信息供 [[中间表示]]/[[编译优化]] 用。语法对≠语义对。
