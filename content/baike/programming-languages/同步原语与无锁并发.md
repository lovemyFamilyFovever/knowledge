# 同步原语与无锁并发

> 📌 **导航**：本文是 **同步原语与无锁并发** 词条，属 [[并发编程模式与实践]] 子词条。

## 定义

**一句话定义：** 同步原语（互斥锁、读写锁、信号量、条件变量）用"加锁/等待通知"协调对共享状态的访问、防止数据竞争；无锁并发则用原子 CAS 与内存序在不用阻塞锁的情况下实现安全的高并发数据结构。

**通俗类比：** 锁像"厕所门锁——一人进其他人等"；读写锁像"女厕可多人进、清洁时需独占"；无锁像"自助改价签：改前先核对没人动过（CAS），动过就重试"，谁都不用排队等门。

## 为什么需要它

多线程共享可变状态必然有竞态。锁给出互斥与可见性的"最省心"手段；但高争用下锁成为吞吐瓶颈、还有死锁/优先级反转。无锁用硬件原子指令降低协调开销，提升可扩展性——代价是算法与内存模型更难写对。

## 核心机制

- **Mutex**：互斥进入临界区；`tryLock` 非阻塞；配 RAII/defer 保证释放。死锁四条件（互斥/持有并等待/不可剥夺/循环等待）→ 靠固定加锁顺序等破坏。
- **RWLock**：多读单写，读多写少更优（否则写者可能饿）。
- **信号量**：计数许可控并发度；**条件变量**：`wait`/`notify` 配合锁等待某条件（须 `while` 防虚假唤醒）。
- **原子与 CAS**：`compare_and_swap(old,new)` 硬件原子；原子变量保证单操作不可分割、无锁计数器/CSP 底层。
- **内存序（memory order）**：relaxed/acquire/release/seq_cst 约束读写重排与可见性；relaxed 只保证原子性、release/acquire 建立跨线程可见边。
- **无锁队列/并发哈希表**（ConcurrentHashMap 分段/CAS）：以 CAS 重试实现无阻塞。

## 具体示例

CAS 乐观自增——冲突则重读重试，无需锁：

```text
loop:
  v = atomic_load(x)
  if CAS(x, expect=v, want=v+1) ok: break   // 成功即 +1；否则重试
```

## 何时用与何时不用

- **用**：一般共享状态用锁（简单稳妥）；读远多于写用 RWLock；限并发用信号量；极热/高争用的计数与队列考虑无锁结构。
- **不用**：无锁结构别乱用——内存序易错、ABA 问题、可维护性差，多数场景锁或不可变/消息传递更稳；避免多锁嵌套致死锁。

## 优劣与代价

✅ 锁/条件变量直观、正确性易保证；原子/CAS 在高争用下提升吞吐、避免阻塞。
✅ 读写锁/信号量针对场景优化并发度。
⚠️ 锁有死锁、 convoy、上下文切换开销；无锁有内存序/ABA/复杂度陷阱。
⚠️ "无锁 ≠ 更快"，写多或低争用时未必划算。

## 与相关概念的区别

- **悲观锁 vs 无锁 CAS**：前者阻塞等待、后者乐观重试。
- **Mutex vs 信号量**：互斥（一次一个）vs 计数许可（可 n 个）。
- **原子操作 vs 加锁**：原子只保证单变量不可分割；锁保护一段临界区/多变量不变式。
- 语言级实现另见 [[Rust 并发与异步]]、[[Go并发与内存模型]]。

## 常见误区

- 无锁数据结构一定比加锁快。
- 只要用了原子变量，就不会有数据竞争。
- 条件变量用 `if` 判条件即可，不必 `while` 循环。

## 面试速答

> 🎯 同步原语：Mutex(互斥，防死锁看四必要+固定顺序)、读写锁(多读单写)、信号量(计数限并发)、条件变量(配锁、while 防虚假唤醒)。无锁：原子+CAS(乐观重试)、内存序(acquire/release 控可见)、无锁队列/CHM。锁直观、无锁高吞吐但易错(ABA/内存序)。
