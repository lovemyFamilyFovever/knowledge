# 抽象语法树


> 📌 **导航**：本文是 **抽象语法树** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 抽象语法树(Abstract Syntax Tree, AST)是源代码语法结构的一种树状中间表示,树的每个节点代表代码中的一种构造(如表达式、语句、声明),它省略了对语义无关的细节(如括号、分号),便于后续分析与转换。

**通俗类比：** 像把一句话拆解成主谓宾的"句子结构树"——去掉标点等表面符号,只保留"谁—做什么—对谁"的结构骨架,方便机器理解句子的真正构造。

> 多义说明:AST(抽象语法树)区别于 CST/具体语法树(Concrete Syntax Tree,保留所有语法细节),也区别于语法分析之前的 token 流。本文指 AST。

## 原理与机制

- **编译前端流程:** 源代码 → 词法分析(token 流)→ 语法分析(按文法构建 AST)→ 语义分析(类型检查、符号解析,常在 AST 上"装饰"信息)。
- **构建方式:** 语法分析器(递归下降、LL、LR 等)依据文法规则把 token 组织成树结构。
- **使用方式:** 遍历(visitor 模式)AST 完成类型检查、代码生成、优化、格式化、静态分析与转译。

## 关键组成

| 组成 | 说明 |
|------|------|
| 节点(node) | 一种语法构造(表达式/语句/声明) |
| 子节点 | 构成该构造的成分 |
| 属性 | 位置、类型、符号等附加信息 |
| 遍历器(visitor) | 按序访问并处理节点 |

## 应用场景

- 编译器与解释器的前端
- 代码格式化(Prettier)、静态检查(ESLint)
- 转译(Babel、TypeScript → JavaScript)
- IDE 重构、代码生成与元编程、模板引擎

## 优点与局限

- 优点:结构清晰、与源文本解耦、便于分析与变换,是编译与工具链的核心中间表示。
- 局限:构建依赖正确的文法与语法分析;大文件的 AST 内存开销大;不同语言/工具的 AST 结构不统一。

## 常见误区

- AST ≠ token 流:token 是叶子级词法单元,AST 是结构化树。
- AST ≠ CST:AST 省略括号、分号等非语义细节。
- AST ≠ 字节码/IR:AST 更贴近源语言语法,IR/字节码更贴近执行。
