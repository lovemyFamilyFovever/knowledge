# 即时编译


> 📌 **导航**：本文是 **即时编译** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 即时编译(Just-In-Time Compilation, JIT)是一种在程序运行时把中间代码(如字节码)动态编译为本地机器码的技术,兼具解释器的跨平台灵活性与编译执行的高性能,广泛用于 Java(JVM)、.NET(CLR)、JavaScript(V8)等运行时。

**通俗类比：** 像同声传译——不是提前把整本书译好(静态编译),也不是逐字慢读(纯解释),而是在演讲进行中把常讲、重要的段落实时"翻译并记住"(把热点代码编译成机器码),后面再遇到就飞快地直接用。

> 多义说明:JIT 介于"提前编译(AOT)"与"解释执行"之间;有分层/分级 JIT(tiered)。本文讨论运行时 JIT。

## 原理与机制

- 先解释执行字节码,同时监控"热点"(hot spot,频繁执行的代码)。
- 对热点代码触发 JIT,编译为本地机器码并缓存,后续直接执行机器码。
- **运行时优化:** 基于实际执行信息做推测优化(内联、去虚拟化、基于 profile 的分支优化);若假设失效则去优化(deoptimization)回退到解释执行。
- **分级编译:** 如 JVM 的 C1(快速)+ C2(深度优化)结合,兼顾启动与峰值性能。

## 关键组成

| 组成 | 说明 |
|------|------|
| 字节码 / IR | JIT 的输入 |
| 热点探测 | 识别频繁执行的代码 |
| JIT 编译器 | 生成机器码 |
| 机器码缓存 | 复用已编译代码 |
| 运行时 profile | 支撑推测优化 |
| 去优化(deopt) | 假设失效时回退 |

## 应用场景

- JVM(Java / Kotlin / Scala)
- .NET CLR(C#)
- JavaScript 引擎(V8 / SpiderMonkey)
- Python(PyPy)、数据库查询执行

## 优点与局限

- 优点:运行时按实际情况优化,性能接近甚至超过静态编译;字节码跨平台。
- 局限:启动有"预热"开销(先解释后编译);运行时占用 CPU/内存做编译;可能出现去优化抖动;实现复杂。

## 常见误区

- JIT ≠ 解释器:JIT 编译为机器码执行,解释器逐条执行字节码。
- JIT ≠ AOT:AOT 在运行前编译。
- JIT 有预热期,短命程序可能不划算(故有 AOT / GraalVM native-image)。
- JIT 的推测优化可能因假设失效而去优化回退。
