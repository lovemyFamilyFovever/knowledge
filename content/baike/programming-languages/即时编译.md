# 即时编译

> 📌 **导航**：本文是 **即时编译** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 即时编译（Just-In-Time Compilation, JIT）是一种在程序运行时把中间代码（如字节码）动态编译为本地机器码的技术，兼具解释器的跨平台灵活性与编译执行的高性能，广泛用于 Java（JVM）、.NET（CLR）、JavaScript（V8）等运行时。

**通俗类比：** 像同声传译——不是提前把整本书译好（AOT），也不是逐字慢读（纯解释），而是在演讲进行中把常讲、重要的段落实时"翻译并记住"（把热点代码编成机器码），后面再遇到就飞快地直接用。

## 为什么需要它

纯解释逐条执行字节码，跨平台但慢；纯 AOT 提前编成机器码，快却拿不到运行时信息、也丢了"一份字节码到处跑"的灵活。JIT 取中间路线：平时用解释保证启动与兼容，等程序"热"起来后再针对**真实执行到的路径**编译并深度优化，从而在不牺牲跨平台的前提下逼近甚至超过静态编译的性能。

## 核心机制

- **边跑边测**：先解释执行字节码，同时监控"热点"（hot spot，频繁执行的代码）。
- **热点编译**：对热点触发 JIT，编译为本地机器码并缓存，后续直接执行机器码。
- **推测优化**：基于实际 profile 做内联、去虚拟化、分支优化；一旦假设失效，通过去优化（deoptimization）回退到解释执行。
- **分级编译**：如 JVM 的 C1（快速）+ C2（深度优化）结合，兼顾启动与峰值。

## 具体示例

伪代码概括其"解释—探测—编译"循环：计数器越过阈值才付编译成本，把开销花在真正值得的热点上。

```
run(method):
  if compiled(method): return exec_machine_code(method)
  interpret(method); counter[method] += 1
  if counter[method] > HOT: jit_compile_and_cache(method)
```

## 何时用与何时不用

- **用**：长时间运行的服务（JVM、.NET、浏览器 JS 引擎）、需要跨平台分发字节码、代码热路径占比明显。
- **不用（改用 AOT）**：追求极短启动 / 小内存的场景——Serverless 冷启动、嵌入式、GraalVM native-image 等，预热期反而是负担。

## 优劣与代价

✅ 按运行时实际情况优化，峰值性能接近甚至超过静态编译。
✅ 保留字节码的跨平台分发能力。
⚠️ 启动有"预热"开销；编译占用运行时 CPU / 内存。
⚠️ 推测失效会引起去优化抖动，实现复杂。

## 与相关概念的区别

- **JIT vs 解释器**：解释器逐条执行字节码；JIT 把热点字节码编成本地机器码后直接执行。
- **JIT vs AOT**：AOT 在运行前编好机器码（启动快、无 profile）；JIT 在运行时编（有预热、但能用真实 profile）。
- **JIT 与 IR**：JIT 的输入就是一种 IR / 字节码，它把 IR 进一步 lowering 成本地码（见 [[中间表示]]）。

## 常见误区

- JIT 就是解释器，只是解释得比较快。
- JIT 程序没有启动开销，开箱即达峰值性能。
- JIT 的推测优化一旦做出就永不回退。

## 面试速答

> 🎯 JIT = 运行时把字节码 / IR 动态编成本地机器码：先解释、探测热点再编译缓存，据 profile 做推测优化（内联 / 去虚拟化），假设失效则 deopt 回退，兼顾跨平台与峰值性能。
