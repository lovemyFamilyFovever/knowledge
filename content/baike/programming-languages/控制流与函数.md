# 控制流与函数

> 📌 **导航**：本文是 **控制流与函数** 词条，属 [[编程语言通用概念]] 子词条。作用域见 [[作用域与命名]]。

## 定义

**一句话定义：** 控制流决定语句的执行顺序（条件分支、循环、跳转），函数把一段计算封装成"带参数与返回值的可复用单元"，递归则是函数调用自身来分解问题。

**通俗类比：** 控制流是行程的"分岔与绕圈"（若…则、反复做）；函数像一台"投料→出品"的机器，同样原料得同样产物；递归是"把大问题丢给一台同款小机器递归解决"。

## 为什么需要它

顺序执行不足以表达真实逻辑，需分支与循环；函数消除重复、封装细节、界定输入输出、便于测试与复用；递归以自相似结构优雅处理树/分治/回溯，替代冗长的手动栈。

## 核心机制

- **条件**：if/else、switch、三元表达式。
- **循环**：for / while / do-while、`break`/`continue`；无限循环与循环不变式需谨慎。
- **函数**：参数与返回值、纯 vs 有副作用、默认/可变参数、一等公民（可传可返）见 [[闭包]]。
- **递归**：必须有基准情形与"向基准收敛"的递归步；否则栈溢出；尾递归可优化为循环。
- 结构化编程三基本构造：顺序、选择、迭代。

## 具体示例

递归求阶乘——基准情形 + 递归步是必备两件套：

```python
def fact(n):
    if n <= 1: return 1        # 基准情形，缺则无限递归
    return n * fact(n - 1)     # 向基准收敛
```

## 何时用与何时不用

- **用**：分支表达决策、循环做重复、函数做抽象复用、递归处理树形/分治/回溯。
- **不用**：递归过深或热路径怕栈开销时改迭代/显式栈；无早退的深嵌套 if 宜用卫语句/多态改写。

## 优劣与代价

✅ 控制流 + 函数是过程式抽象的骨架，可读、可复用、可测。
✅ 递归让自相似问题代码简洁、贴近定义。
⚠️ 递归有栈深/栈溢出成本，可能重复计算（可记忆化，见 [[闭包]]）。
⚠️ 复杂嵌套分支/循环易失控，难测难改。

## 与相关概念的区别

- **循环 vs 递归**：同为重复，一个靠迭代计数、一个靠自调用+栈；可互相转换。
- **函数 vs 过程/方法**：是否返回值、是否绑定对象的差别（语言相关）。
- 与 [[变量与数据类型]]：控制流作用于数据、函数界定作用域。

## 常见误区

- 递归一定比循环优雅又高效。
- switch 比一长串 if-else 永远更快。
- 函数有了返回值才算函数（有些语言函数可有副作用无返回）。
