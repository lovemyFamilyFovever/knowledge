# 协程

> 📌 **导航**：本文是 **协程** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 协程（Coroutine）是一种可以主动暂停（挂起）并在之后恢复执行的程序组件，它由用户态调度、以协作方式在多个执行流之间切换，从而用同步的写法实现并发，常用于高效处理 I/O 密集型任务。

**通俗类比：** 像一个人同时看几本书——读到要等外卖（阻塞 I/O）时他不干等，先放下这本去看另一本，外卖到了再回来接着读；一个人（单线程）靠"主动切换"推进多件事。

## 为什么需要它

用线程扛高并发 I/O，成本在创建、上下文切换和内核调度，万级连接就吃不下；用回调写异步又陷入"回调地狱"、控制流被打碎。协程把切换点收敛到用户态、由事件循环调度，开销极低可轻松开十万个；同时用 await 把异步逻辑写回线性同步的样子，兼得高并发与可读性。

## 核心机制

- **挂起与恢复**：协程在 await / yield 处主动让出控制权并保存自身状态，稍后从中断处恢复，而不是被抢占。
- **用户态调度**：由事件循环 / 运行时调度（asyncio、Kotlin 协程、Go runtime），避免内核态切换开销。
- **协作式**：切换点显式可预测（不像线程被 OS 抢占）；单线程内同一时刻只有一个协程在跑，同步因此更简单。
- **有栈 vs 无栈**：有栈协程自带独立调用栈（可在任意调用深度挂起，如 goroutine、Lua）；无栈协程由编译器转成状态机（C++20、Python async、Rust async）。

## 具体示例

await 就是协程的挂起点：遇到 I/O 时把控制权交回事件循环，让别的协程继续跑，I/O 就绪后再恢复到这里。

```python
async def fetch(url):
    data = await io.read(url)      # 挂起点：让出控制权
    return process(data)
# fetch 挂起期间，事件循环去推进其他就绪的协程
```

## 何时用与何时不用

- **用**：高并发 I/O（网络服务器、爬虫、代理）、异步编程 async/await、游戏脚本与协作式任务。
- **不用**：CPU 密集型计算——协程在单线程里不会自动并行，应改用多线程 / 多进程；或对延迟要求苛刻到不能容忍任何一次协作让出被阻塞的场合。

## 优劣与代价

✅ 轻量：创建 / 切换成本远低于线程，单机可支撑海量并发。
✅ 用同步写法表达异步，避免回调地狱。
⚠️ CPU 密集任务无法靠协程并行，需配合多线程 / 多进程。
⚠️ 协作式下一个协程长时间阻塞会拖累整条线程；调试依赖语言与生态支持。

## 与相关概念的区别

- **协程 vs 线程**：协程由用户态调度、更轻、切换点在 await；线程由内核调度、更重、可能被抢占。
- **并发 vs 并行**：单线程事件循环内多协程是"并发"（交替推进），要"并行"用多核得多 worker / 多线程。
- **有栈 vs 无栈协程**：有栈可深层调用处挂起、内存按栈增长；无栈编译成状态机、更省内存但受挂起点限制。

## 常见误区

- 协程就是更轻的线程，能自动利用多核。
- 在 async 函数里直接调用同步阻塞 I/O 也没关系。
- 用了协程，CPU 密集型任务也能自动加速。

## 面试速答

> 🎯 协程 = 用户态调度的轻量执行单元，在 await/yield 处主动挂起、之后恢复，用同步写法实现并发；单线程内同一时刻只跑一个协程，擅长 I/O 密集，不自动多核并行。
