# 线程池

> 📌 **导航**：本文是 **线程池** 词条，属 [[并发编程（Concurrent Programming）概念]] 子词条。线程/进程模型见 [[并发与并行及线程模型]]。

## 定义

**一句话定义：** 线程池是预先创建并复用一组线程、用任务队列 + 有限工作线程来执行提交的任务的并发执行框架——避免每任务都创建/销毁线程的开销，并把并发度限制在可控上限内。

**通俗类比：** 像餐厅固定几名服务员轮流接桌，而不是每来一客就现招一名服务员再辞退——人（线程）复用，队列（待接的桌）排队分配。

## 为什么需要它

创建/销毁 OS 线程昂贵（内核态栈分配、调度），且线程数无上限会耗尽内存、加剧上下文切换、压垮下游。线程池把"线程生命周期"与"任务"解耦：固定一批常驻 worker，任务进队列排队取，从而复用线程、控制并发度、削峰填谷、防止过载。

## 核心机制

- **核心组件**：有限 worker 集合 + 有界/无界任务队列 + 提交接口（`submit`/`execute`/`map`）。
- **容量参数**：最大线程数、核心线程数、队列容量、拒绝策略（队列满且线程满时如何处置新任务：丢弃/抛异常/调用者跑）。
- **大小选型经验**：I/O 密集可 `线程数 > CPU 核`（多在等待）；CPU 密集约 `核数 + 1`，再多只会增切换。
- **各语言落地**：Python `ThreadPoolExecutor`/`ProcessPoolExecutor`；Java `Executors.newFixedThreadPool`/`ThreadPoolExecutor`（可调参），JDK21 虚拟线程另计；Go 无常驻池，惯用"worker pool + channel"模式手写。
- **与协程区别**：线程池是抢占式内核线程复用；海量并发 I/O 常改用协程/事件循环更省（见 [[异步结果与事件循环]]、[[协程]]）。

## 具体示例

```python
from concurrent.futures import ThreadPoolExecutor
def task(n): return n * n
with ThreadPoolExecutor(max_workers=4) as ex:
    futures = [ex.submit(task, i) for i in range(10)]  # 复用4线程跑10任务
    results = [f.result() for f in futures]
```

## 何时用与何时不用

- **用**：大量短任务、需限制并发度保护资源/下游、混合 CPU/阻塞 I/O 的批处理——固定大小池 + 有界队列是稳妥默认。
- **不用**：任务极少或一次性不必建池；纯高并发 I/O（数十万连接）用线程池会线程爆炸，改协程/事件循环；CPU 密集且无 GIL 争用可考虑进程池绕开解释器锁。

## 优劣与代价

✅ 复用线程省去创建销毁开销、并发度可控、队列缓冲抗突发、任务生命周期统一管理。
✅ 屏蔽底层调度，`submit/结果` 抽象跨语言一致。
⚠️ 大小难调：太小吞吐受限、太大失去限流意义并增内存/切换。
⚠️ 有界队列满会触发拒绝、无界队列可能 OOM；池内任务互相阻塞易死锁（如任务 A 占线程又等 B 的结果）。

## 与相关概念的区别

- **线程池 vs 每任务一线程**：前者复用限流、后者无控易爆。
- **线程池 vs 协程池/事件循环**：内核抢占多线程 vs 用户态协作单/少线程。
- **固定池 vs 弹性池**：大小写死 vs 按需伸缩（后者实现与调参更复杂）。

## 常见误区

- 线程池越大并发越高、性能越好。
- 池里的任务等待另一个池任务的结果完全安全，不会死锁。
- 有了线程池就不需要限制队列长度，队列多大都行。

## 面试速答

> 🎯 线程池=常驻有限 worker + 任务队列，复用线程、限并发、防过载。关键调参：最大/核心线程数、队列容量、拒绝策略；大小选型 CPU 密集≈核数+1、I/O 密集可更大。海量 I/O 别堆线程、改协程/事件循环；有界队列防 OOM、注意池内互相等待死锁。
