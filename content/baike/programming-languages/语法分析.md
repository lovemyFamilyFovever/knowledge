# 语法分析

> 📌 **导航**：本文是 **语法分析** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 语法分析（Syntax Analysis，又称解析 parsing）是编译的第二阶段，它接收词法分析产出的 token 流，依据语言的上下文无关文法（CFG）检查其结构是否合法，并构建出反映程序层次结构的语法树（如抽象语法树 AST）。

**通俗类比：** 像语文老师分析句子成分——把"我吃苹果"按语法规则解析成"主语（我）+ 谓语（吃）+ 宾语（苹果）"的结构树，并判断这句话合不合语法，不合就报错。

## 为什么需要它

词法分析只保证"每个单词合法"，但"单词合法"不等于"句子成文"。语法分析负责把离散的 token 流按文法组织成有层次的结构，既校验程序在形式上是否合法，又产出 AST 供后续语义分析和代码生成消费——没有这一步，编译器无法表达优先级、嵌套与作用域所依赖的结构。

## 核心流程

- **输入输出**：输入 token 流，依据文法规则推导；输出语法树 / AST（见 [[抽象语法树]]）。
- **自顶向下**：递归下降、LL(1) 分析——从开始符向下推导，预测下一个产生式。
- **自底向上**：LR、LALR、SLR——移进 / 归约，从 token 逐步归约到开始符（Yacc / Bison 可生成）。
- **错误处理**：检测到不符合文法时报告语法错误，并尝试恢复（如恐慌模式 panic-mode）。

## 具体示例

表达式 `3 + 4 * 5` 经语法分析后，按乘法优先级高于加法建成如下 AST——这正是词法层的线性 token 流无法表达、而结构层必须给出的信息：

```
3 + 4 * 5   →   (+ 3 (* 4 5))
```

## 何时用与何时不用

- **用**：编译器 / 解释器构建 AST、IDE 解析与诊断、数据格式解析（JSON / XML / SQL）、DSL 与配置语言、代码工具链。
- **不用（单独）**：只关心"有没有拼错的单词"时用词法即可；含义层面的类型检查、作用域解析属于语义分析，不在语法层。

## 优劣与代价

✅ 严格校验程序结构，产出结构化 AST 供后续分析与代码生成。
✅ 解析算法与工具（ANTLR、Bison）成熟。
⚠️ 文法设计直接影响可解析性，二义文法需要消歧。
⚠️ LR 分析器手工实现复杂，常依赖生成器；错误信息友好度高度依赖实现。

## 与相关概念的区别

- **语法分析 vs 语义分析**：语法查"结构合不合法"，语义查"含义对不对"（类型匹配、作用域、初始化）。
- **语法正确 vs 程序正确**：语法通过只说明句子成文，不代表逻辑正确或类型安全。
- **LL vs LR**：LL 自顶向下预测推导，LR 自底向上移进-归约；LR 识别能力更强、手写更难。
- **AST vs token 流**：解析输出是带层次/优先级的树，而非线性序列。

## 常见误区

- 语法分析会检查变量类型是否匹配、作用域是否正确。
- 只要语法分析通过，程序就能正确运行。
- 语法分析的产物是线性的 token 序列。

## 面试速答

> 🎯 语法分析（解析）是编译第二阶段：吃 token 流，按上下文无关文法判断结构合法性并构建 AST；分自顶向下（LL / 递归下降）与自底向上（LR / LALR）。
