# 语法分析


> 📌 **导航**：本文是 **语法分析** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 语法分析(Syntax Analysis,又称解析 parsing)是编译的第二阶段,它接收词法分析产出的 token 流,依据语言的上下文无关文法(CFG)检查其结构是否合法,并构建出反映程序层次结构的语法树(如抽象语法树 AST)。

**通俗类比：** 像语文老师分析句子成分——把"我吃苹果"按语法规则解析成"主语(我)+ 谓语(吃)+ 宾语(苹果)"的结构树,并判断这句话合不合语法;不合语法就报错。

> 多义说明:语法分析基于**上下文无关文法**;分为自顶向下(LL / 递归下降)与自底向上(LR / LALR)两大类。本文综述。

## 原理与机制

- **输入输出:** 输入 token 流,依据文法规则推导;输出语法树 / AST(见 [[抽象语法树]])。
- **自顶向下:** 递归下降、LL(1) 分析——从开始符向下推导,预测下一个产生式。
- **自底向上:** LR、LALR、SLR——移进 / 归约,从 token 逐步归约到开始符(Yacc / Bison 可生成)。
- **错误处理:** 检测到不符合文法时报告语法错误,并尝试恢复(如恐慌模式)。

## 关键组成

| 组成 | 说明 |
|------|------|
| token 流输入 | 来自词法分析 |
| 上下文无关文法 | 语法规则 |
| 解析算法 | LL / LR / 递归下降 |
| 语法树 / AST | 结构化输出 |
| 错误恢复 | 报错并继续分析 |

## 应用场景

- 编译器 / 解释器构建 AST
- IDE 解析与诊断
- 数据格式解析(JSON / XML / SQL)
- DSL 与配置语言、代码工具链

## 优点与局限

- 优点:严格校验程序结构、产出结构化 AST 供后续语义分析与代码生成;算法与工具成熟。
- 局限:文法设计影响可解析性(二义文法需消歧);LR 分析器手工实现复杂(常用生成器);错误信息的友好度依赖实现。

## 常见误区

- 语法分析 ≠ 语义分析:前者查结构,后者查类型/作用域等含义。
- 语法正确 ≠ 程序正确(语义与逻辑另论)。
- LL 与 LR 是不同方向的分析策略,各有适用文法。
- 解析结果是树(AST),不是线性的 token 序列。
