# 中间表示

## 定义

**一句话定义：** 中间表示(Intermediate Representation, IR)是编译器在把源代码翻译成目标代码过程中使用的一种内部数据结构,它介于源语言与目标机器码之间,便于进行分析、优化与代码生成,并解耦前端语言与后端架构。

**通俗类比：** 像跨国会议的"通用中间语"——不管与会者说什么语言(不同源语言),都先翻译成一种通用中间语(IR),在其上做记录与润色(优化),最后再翻成每位听众的母语(不同目标平台),省去"每种语言两两互译"的麻烦。

> 多义说明:IR 有多种层次与形式(高层 HIR、低层 LIR;三地址码、SSA、栈式、图式,如 LLVM IR)。本文综述。

## 原理与机制

- **位置:** 前端(词法/语法/语义分析)→ 生成 IR → 中端(在 IR 上做与机器无关的优化)→ 后端(IR → 目标机器码)。
- **常见形式:** 三地址码/四元式、静态单赋值(SSA,每个变量只赋值一次,便于数据流分析)、栈式(如 JVM 字节码)、LLVM IR。
- **作用:** 支撑优化(常量折叠、死代码消除、循环优化、内联等),并解耦 M 种语言 × N 种架构(只需 M + N 而非 M × N 个编译器)。

## 关键组成

| 组成 | 说明 |
|------|------|
| IR 层次 | 高层 HIR / 低层 LIR |
| IR 形式 | 三地址码 / SSA / 字节码 |
| 优化 pass | 在 IR 上做的各类变换 |
| 前后端接口 | 解耦语言与架构 |

## 应用场景

- 编译器(GCC / LLVM)
- Java 字节码与 JVM、.NET IL
- LLVM IR 生态、跨语言/跨平台工具链
- JIT 即时编译

## 优点与局限

- 优点:便于优化、解耦前端语言与后端架构(可复用)、支持多趟分析。
- 局限:IR 设计影响优化能力与编译速度;不同 IR 各有取舍;抽象层次选择复杂;可能损失部分源语言信息。

## 常见误区

- IR ≠ AST:AST 贴近源语言语法,IR 更贴近执行、便于优化(如 SSA)。
- IR ≠ 最终机器码:还需后端生成目标代码。
- SSA 是 IR 的一种性质/形式,并非唯一。
- 字节码(如 JVM bytecode)是一种 IR。
