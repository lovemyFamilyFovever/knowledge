# 中间表示

> 📌 **导航**：本文是 **中间表示** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 中间表示（Intermediate Representation, IR）是编译器在把源代码翻译成目标代码过程中使用的一种内部数据结构，它介于源语言与目标机器码之间，便于进行分析、优化与代码生成，并解耦前端语言与后端架构。

**通俗类比：** 像跨国会议的"通用中间语"——不管与会者说什么语言，都先译成一种中间语，在其上做记录与润色（优化），最后再翻成每位听众的母语（不同目标平台），省去"每种语言两两互译"的麻烦。

## 为什么需要它

若每种源语言都要为每种 CPU 各写一个直通编译器，就要维护 M × N 个。引入一层 IR 后，前端只需把语言翻译成 IR、后端只需把 IR 翻译成目标码，编译器数量降到 M + N；同时"优化"集中在 IR 这一稳定层做一次，就能被所有语言、所有平台共享。IR 是把编译过程"分段解耦"的枢纽。

## 核心机制

- **位置**：前端（词法 / 语法 / 语义分析）→ 生成 IR → 中端（在 IR 上做与机器无关的优化）→ 后端（IR → 目标机器码）。
- **常见形式**：三地址码 / 四元式、静态单赋值（SSA，每个变量只赋值一次，便于数据流分析）、栈式（如 JVM 字节码）、LLVM IR。
- **作用**：支撑常量折叠、死代码消除、循环优化、内联等 pass，并解耦语言与架构。IR 有高低层次之分（HIR 贴近源、LIR 贴近机器）。

## 具体示例

表达式 `a = b + c + d` 降为三地址码后，每步最多一个运算、结果落到临时变量，这种扁平形式正是数据流分析与优化的理想输入：

```
t1 = b + c
t2 = t1 + d
a  = t2
```

## 何时用与何时不用

- **用**：多语言 / 多平台的编译器（GCC / LLVM）、JVM 字节码与 .NET IL、JIT 即时编译、跨语言工具链。
- **不用（不必显式引入）**：单语言、单目标、不做优化的极简编译器，可以直接 AST → 目标码，省一层 IR。

## 优劣与代价

✅ 便于机器无关优化、解耦前后端、支持多趟分析与复用。
✅ 让 M 语言 × N 架构只需 M + N 份实现。
⚠️ IR 的设计直接影响优化能力与编译速度，抽象层次选择复杂。
⚠️ 翻译到 IR 可能丢失部分源语言信息，需额外携带调试元数据。

## 与相关概念的区别

- **IR vs AST**：AST 贴近源语言语法、结构嵌套；IR 更贴近执行、形式扁平（如三地址码 / SSA），是优化的主战场。
- **IR vs 机器码**：IR 是平台无关或半相关的中间物，仍需后端生成最终目标码。
- **SSA vs 其他 IR**：SSA 是 IR 的一种"每变量只赋值一次"的性质 / 形式，并非唯一；栈式字节码同样是一种 IR。

## 常见误区

- IR 就是 AST，两者可以互换。
- IR 就是最终交付的机器码，编到 IR 就算完成。
- 只有 SSA 才算 IR，栈式字节码不算。
