# 编程概念音频课-设计模式

（开场轻松音乐，渐弱）

嘿，朋友们！欢迎回到“代码聊天室”。我是你们的老朋友，今天咱们不聊框架不卷源码，就来聊点编程里特别酷的“套路”——设计模式。别一听名字就犯怵，这玩意儿其实就是前辈程序员总结出来的“最佳实践”，就像你打游戏时的连招技巧，用好了能让你代码写得又快又稳。

咱们今天就用大白话，加上生活里的例子，把八种常用的设计模式给盘明白。保证你听完后，能拍着大腿说：“哦！原来我天天都在用啊！”

### 1. 单例模式：一个公司只能有一个CEO

想象一下，如果你在一个大公司，每个人都能自己印名片说自己是CEO，那不就乱套了吗？公司必须只能有且只有一个CEO，这就是**单例模式（Singleton Pattern）**。

**它解决啥问题？** 当你需要确保一个类只有一个实例，并且这个实例要能被全局访问时，就用它。比如数据库连接池、配置管理器、日志记录器这些，总不能每个地方都创建一个新的吧？多浪费资源啊！

**代码来一个（Java版本，简单粗暴）：**
```java
public class CEO {
    // 唯一的那个实例，先占个坑，但先不new
    private static CEO uniqueInstance;

    // 构造函数私有化，new不了，就创建不了新对象
    private CEO() {
        System.out.println("一个新的CEO诞生了！");
    }

    // 全局唯一的访问入口
    public static synchronized CEO getInstance() {
        if (uniqueInstance == null) {
            uniqueInstance = new CEO();
        }
        return uniqueInstance;
    }

    public void makeBigDecision() {
        System.out.println("CEO正在做重大决定...");
    }
}

// 其他地方想用CEO，只能这样：
// CEO ceo = CEO.getInstance();
// ceo.makeBigDecision();
```
**synchronized** 关键字是为了防止多线程下创建多个实例。在真实的“懒汉式”单例里，还有更高效的写法（双重检查锁），但这个足够理解核心思想了。

**实际用在哪？**
- **Spring框架的Bean作用域**：默认情况下，Spring容器中的Bean就是单例的。
- **Windows的任务管理器**：你打开多少次，都只能弹出同一个窗口。
- **打印机的后台处理程序**：整个系统里只有一个负责管理打印队列。

### 2. 工厂模式：后厨来料加工

你去餐厅吃饭，不会直接去后厨自己炒菜，对吧？你只需要告诉服务员“来份宫保鸡丁”，后厨（工厂）就会帮你做出来。你不需要知道厨师是谁，用的什么锅，这就是**工厂模式（Factory Pattern）** 的精髓。

**它解决啥问题？** 当你想要创建对象，但不想让使用者知道具体的创建细节，或者想把创建对象的逻辑集中管理时，就用它。特别适合对象类型可能变化的情况。

**代码来一个（模拟一个披萨店）：**
```java
// 先定义一个披萨接口
interface Pizza {
    void prepare();
    void bake();
}

// 具体的披萨们
class CheesePizza implements Pizza {
    public void prepare() { System.out.println("准备芝士披萨的原料..."); }
    public void bake() { System.out.println("烤制芝士披萨..."); }
}

class VeggiePizza implements Pizza {
    public void prepare() { System.out.println("准备蔬菜披萨的原料..."); }
    public void bake() { System.out.println("烤制蔬菜披萨..."); }
}

// 披萨工厂（后厨）
class PizzaFactory {
    // 工厂方法：根据类型生产披萨
    public static Pizza createPizza(String type) {
        Pizza pizza = null;
        if ("cheese".equals(type)) {
            pizza = new CheesePizza();
        } else if ("veggie".equals(type)) {
            pizza = new VeggiePizza();
        }
        // 可以轻松扩展新口味，比如再加个 if
        return pizza;
    }
}

// 顾客（使用者）的代码就非常简单：
// Pizza myPizza = PizzaFactory.createPizza("cheese");
// myPizza.prepare();
// myPizza.bake();
```

**实际用在哪？**
- **JDBC的DriverManager**：`DriverManager.getConnection(url)`，你不用关心底层用的是MySQL驱动还是Oracle驱动。
- **Spring的BeanFactory/ApplicationContext**：这就是最典型的大工厂，帮你创建和管理所有对象（Bean）。
- **日志框架**：比如`LoggerFactory.getLogger(Class)`，你不用关心返回的是Log4j的Logger还是其他的。

### 3. 观察者模式：微信群聊@所有人

你在公司微信群，老板在群里发了个通知：“明天团建！”。这个消息会自动推送给群里的每一个人。你不需要一遍遍去问老板“有新通知吗？”，老板也不需要挨个私聊。这就是**观察者模式（Observer Pattern）**，也叫发布-订阅模式。

**它解决啥问题？** 当一个对象的状态改变时，需要自动通知其他一系列对象，并且这些对象可能随时变化（有人退群有人加群），就需要这个模式。它能解耦发布者和订阅者。

**代码来一个（用Java内置的`Observable`类演示，虽然过时了但说明问题）：**
```java
import java.util.Observable;
import java.util.Observer;

// 老板（被观察者/主题）
class Boss extends Observable {
    private String message;

    public void setMessage(String msg) {
        this.message = msg;
        // 状态改变了，标记变化并通知所有人
        setChanged();
        notifyObservers(msg); // 推送消息
    }
}

// 员工（观察者）
class Employee implements Observer {
    private String name;
    public Employee(String name) { this.name = name; }

    @Override
    public void update(Observable o, Object arg) {
        System.out.println(name + " 收到新通知: " + arg);
    }
}

// 使用：
Boss boss = new Boss();
Employee emp1 = new Employee("张三");
Employee emp2 = new Employee("李四");

// 关注（订阅）
boss.addObserver(emp1);
boss.addObserver(emp2);

// 发布通知
boss.setMessage("明天上午9点，公司楼下集合团建！");
// 输出：
// 李四 收到新通知: 明天上午9点，公司楼下集合团建！
// 张三 收到新通知: 明天上午9点，公司楼下集合团建！
```
现代开发中，我们常用自定义的观察者接口，或者事件总线（EventBus）、消息队列（如Kafka、RabbitMQ）来实现更强大的解耦。

**实际用在哪？**
- **GUI事件监听**：按钮的`addActionListener`，你点一下，所有监听了这个事件的处理器都会被调用。
- **Spring的事件机制**：通过`ApplicationEventPublisher`发布事件，监听`@EventListener`来处理。
- **前端状态管理**：比如Vue的响应式系统、React的状态提升，背后思想都有观察者模式的影子。
- **消息队列**：就是工业级的观察者模式，生产者发布消息，多个消费者订阅消费。

### 4. 策略模式：导航软件的多种路线选择

打开高德地图，输入目的地，它会给你推荐“时间优先”、“费用少”、“不走高速”等多种路线策略。你根据自己的需求（开车、坐公交、骑车）选择一种，算法（策略）就切换了，但导航的核心功能不变。这就是**策略模式（Strategy Pattern）**。

**它解决啥问题？** 当你有很多相关的算法或行为，它们只是在具体实现上不同时，可以把它们封装成独立的策略类，让它们可以互相替换，避免使用大量if-else或switch。

**代码来一个（旅行方式策略）：**
```java
// 策略接口：旅行方式
interface TravelStrategy {
    void travel(String destination);
}

// 具体策略们
class AirplaneStrategy implements TravelStrategy {
    public void travel(String destination) {
        System.out.println("乘坐飞机前往 " + destination);
    }
}

class TrainStrategy implements TravelStrategy {
    public void travel(String destination) {
        System.out.println("乘坐火车前往 " + destination);
    }
}

class BicycleStrategy implements TravelStrategy {
    public void travel(String destination) {
        System.out.println("骑自行车前往 " + destination + "，锻炼身体！");
    }
}

// 上下文（Context），持有一个策略的引用
class TravelContext {
    private TravelStrategy strategy;

    // 可以设置或更换策略
    public void setStrategy(TravelStrategy strategy) {
        this.strategy = strategy;
    }

    // 执行策略
    public void goOnTrip(String destination) {
        if (strategy == null) {
            throw new RuntimeException("请先选择一种出行方式！");
        }
        strategy.travel(destination);
    }
}

// 使用：
TravelContext context = new TravelContext();
context.setStrategy(new AirplaneStrategy());
context.goOnTrip("三亚"); // 输出：乘坐飞机前往 三亚

// 想换个方式？轻松换！
context.setStrategy(new BicycleStrategy());
context.goOnTrip("楼下便利店"); // 输出：骑自行车前往 楼下便利店，锻炼身体！
```

**实际用在哪？**
- **支付方式选择**：支付宝、微信、银联，都是不同的支付策略。
- **文件压缩算法**：ZIP、RAR、7z，你可以选择不同的压缩策略。
- **排序算法**：`Collections.sort(list, comparator)`，那个`Comparator`就是策略。
- **权限校验**：不同的角色（管理员、普通用户）有不同的权限策略。

### 5. 装饰器模式：给手机戴壳、贴膜

你新买了一部裸机手机。为了防摔，你给它戴了个保护壳；为了防刮，你贴了张钢化膜。手机的核心功能没变，但通过一层层“装饰”，它变得更强大了。这就是**装饰器模式（Decorator Pattern）**。

**它解决啥问题？** 当你想动态地给一个对象添加一些额外的职责，又不想通过生成子类来扩展时（继承不够灵活），就用装饰器。它比继承更灵活，可以“嵌套”多层装饰。

**代码来一个（给咖啡加配料）：**
```java
// 基础组件接口
interface Beverage {
    String getDescription();
    double cost();
}

// 具体的组件：基础咖啡
class SimpleCoffee implements Beverage {
    public String getDescription() { return "一杯简单的咖啡"; }
    public double cost() { return 10.0; }
}

// 抽象装饰器（很重要！它也实现组件接口，并持有组件的引用）
abstract class BeverageDecorator implements Beverage {
    protected Beverage beverage; // 被装饰者
    public BeverageDecorator(Beverage beverage) {
        this.beverage = beverage;
    }
}

// 具体的装饰器们
class MilkDecorator extends BeverageDecorator {
    public MilkDecorator(Beverage beverage) { super(beverage); }
    public String getDescription() {
        return beverage.getDescription() + " + 牛奶";
    }
    public double cost() {
        return beverage.cost() + 2.0;
    }
}

class MochaDecorator extends BeverageDecorator {
    public MochaDecorator(Beverage beverage) { super(beverage); }
    public String getDescription() {
        return beverage.getDescription() + " + 摩卡";
    }
    public double cost() {
        return beverage.cost() + 3.0;
    }
}

// 使用：可以像套娃一样一层层装饰
Beverage myCoffee = new SimpleCoffee();
System.out.println(myCoffee.getDescription() + " 价格: " + myCoffee.cost());
// 输出：一杯简单的咖啡 价格: 10.0

myCoffee = new MilkDecorator(myCoffee); // 加奶
System.out.println(myCoffee.getDescription() + " 价格: " + myCoffee.cost());
// 输出：一杯简单的咖啡 + 牛奶 价格: 12.0

myCoffee = new MochaDecorator(myCoffee); // 再加摩卡
System.out.println(myCoffee.getDescription() + " 价格: " + myCoffee.cost());
// 输出：一杯简单的咖啡 + 牛奶 + 摩卡 价格: 15.0
```

**实际用在哪？**
- **Java I/O流**：这就是装饰器模式的经典应用！`new BufferedReader(new InputStreamReader(new FileInputStream("file.txt")))`，一层套一层，添加缓冲、转换等功能。
- **Servlet API**：`HttpServletRequestWrapper`就是一个装饰器，可以用来修改或增强请求对象。
- **中间件**：比如在Express.js（Node.js框架）中，你可以一层层添加日志、认证、压缩等中间件。

### 6. 适配器模式：充电头转换器

你从美国带回来一个电器，插头是两扁一圆的，咱们国内的插座是两孔或三孔扁的。直接插不进去怎么办？用个**转换器（Adapter）** 呗！它把国外插头的标准“适配”成了国内插座能接受的标准。这就是**适配器模式（Adapter Pattern）**。

**它解决啥问题？** 当你有一个类，它的接口和你当前系统需要的接口不匹配时，你就需要一个适配器来转换接口，让它们能协同工作。俗称“包装”一下。

**代码来一个（对象适配器，更常用）：**
```java
// 系统现在需要的是“三孔插座”接口
interface ThreePinSocket {
    void supplyWithThreePins();
}

// 我们手头有的是“两孔插头”类
class TwoPinPlug {
    public void connectWithTwoPins() {
        System.out.println("两孔插头连接成功");
    }
}

// 适配器：把两孔插头包装成三孔插座的样子
class PlugAdapter implements ThreePinSocket {
    private TwoPinPlug twoPinPlug; // 适配器持有被适配者的引用

    public PlugAdapter(TwoPinPlug plug) {
        this.twoPinPlug = plug;
    }

    // 实现三孔插座的接口，内部调用两孔插头的功能
    public void supplyWithThreePins() {
        System.out.println("转换器工作：");
        twoPinPlug.connectWithTwoPins(); // 委托给被适配者
        System.out.println("已成功适配为三孔供电！");
    }
}

// 使用：
TwoPinPlug myPlug = new TwoPinPlug();
// 我的系统需要三孔插座
ThreePinSocket socket = new PlugAdapter(myPlug);
socket.supplyWithThreePins(); // 通过适配器，两孔插头也能用了！
```

**实际用在哪？**
- **旧系统整合**：新系统需要调用老系统的接口，但接口不匹配，写个适配器包装一下。
- **第三方库集成**：用的库提供的类和你项目定义的接口不一样，用适配器统一接口。
- **数据格式转换**：比如你拿到的是XML格式的数据，但系统需要JSON，这个转换逻辑可以放在适配器里。

### 7. 代理模式：明星和他的经纪人

一个大明星，不可能自己去处理所有粉丝的来信、接听所有商务电话。他需要一个**经纪人（Proxy）**。经纪人代表明星，在访问真正对象（明星）之前或之后，做一些控制或额外处理，比如筛选邀请、安排日程。这就是**代理模式（Proxy Pattern）**。

**它解决啥问题？** 当你想对一个对象的访问进行控制（比如延迟加载、权限检查、日志记录），或者访问的对象在远程服务器上（远程代理）时，就用代理。代理和真实对象实现相同的接口，调用者感觉不到区别。

**代码来一个（静态代理，简单版）：**
```java
// 接口：明星业务
interface Star {
    void sing();
    void signContract();
}

// 真实明星
class RealStar implements Star {
    public void sing() {
        System.out.println("明星正在深情演唱...");
    }
    public void signContract() {
        System.out.println("明星正在签署高额合同...");
    }
}

// 经纪人（代理）
class StarAgent implements Star {
    private RealStar realStar; // 持有真实明星的引用

    public StarAgent(RealStar star) {
        this.realStar = star;
    }

    public void sing() {
        System.out.println("经纪人：档期已确认，安保已就位。");
        realStar.sing(); // 调用真实明星的方法
        System.out.println("经纪人：演出费已结算。");
    }

    public void signContract() {
        System.out.println("经纪人：正在审查合同条款...");
        // 可以在这里加权限控制，比如只有大单才让明星签
        realStar.signContract();
        System.out.println("经纪人：合同已归档。");
    }
}

// 粉丝（调用者）只需要和经纪人打交道：
Star star = new StarAgent(new RealStar());
star.sing(); // 经纪人会处理好前后事宜
```

**实际用在哪？**
- **Spring AOP**：这就是最强大的动态代理应用！@Transactional（事务管理）、@Cacheable（缓存）、日志记录，这些功能都是通过代理在方法执行前后插入逻辑实现的。
- **远程过程调用（RPC）**：客户端调用的其实是一个本地代理，它负责把方法调用序列化，通过网络发给真正的服务器。
- **延迟加载**：比如Hibernate中，对象关联的集合属性，在你第一次访问时才去数据库查询，这就是代理对象的功劳。

### 8. 模板方法模式：老食谱与新厨师

你家传了一本《红烧肉秘籍》，上面写着：
1. **第一步：准备材料**（五花肉、冰糖…）
2. **第二步：焯水去腥**（水开后下肉，煮3分钟）
3. **第三步：炒糖色**（具体怎么炒，火候大小）
4. **第四步：炖煮**（小火慢炖1小时）
5. **第五步：收汁装盘**

这个流程（步骤）是固定不变的，但第三步“炒糖色”的具体操作可能每个厨师有自己独门的小技巧。这个固定的流程框架，就是**模板方法模式（Template Method Pattern）**。

**它解决啥问题？** 当你有一个算法（流程）的骨架已经确定，但某些步骤的具体实现可能变化时，可以把不变的部分（骨架）放在父类，变化的部分（具体步骤）留给子类去实现。完美体现了“对扩展开放，对修改关闭”的原则。

**代码来一个：**
```java
abstract class AbstractCook {
    // 这个模板方法定义了算法骨架，通常设为final，防止子类重写流程
    public final void cookBraisedPork() {
        prepareMaterials(); // 步骤1
        blanch(); // 步骤2
        colorWithSugar(); // 步骤3：这是抽象的，子类必须实现
        simmer(); // 步骤4
        thickenAndPlate(); // 步骤5
    }

    // 具体步骤，已经实现好，子类共用
    private void prepareMaterials() {
        System.out.println("准备五花肉、冰糖、八角...");
    }
    private void blanch() {
        System.out开水，下肉焯3分钟，洗净备用。");
    }
    private void simmer() {
        System.out.println("加水没过肉，小火慢炖1小时。");
    }
    private void thickenAndPlate() {
        System.out.println("大火收汁，装盘。");
    }

    // 抽象方法：炒糖色，必须由子类实现
    protected abstract void colorWithSugar();
}

// 具体子类A：传统炒法
class TraditionalChef extends AbstractCook {
    @Override
    protected void colorWithSugar() {
        System.out.println("用油小火慢慢融化冰糖，炒出琥珀色。");
    }
}

// 具体子类B：创新炒法
class ModernChef extends AbstractCook {
    @Override
    protected void colorWithSugar() {
        System.out.println("先用少许油炒香香料，再下糖快速翻炒。");
    }
}

// 使用：
AbstractChef chef1 = new TraditionalChef();
chef1.cookBraisedPork(); // 整个流程自动走完，第三步用的是传统方法

AbstractChef chef2 = new ModernChef();
chef2.cookBraisedPork(); // 整个流程一样，但第三步用的是现代方法
```

**实际用在哪？**
- **JUnit测试**：`setUp()`、`testXXX()`、`tearDown()`，测试的骨架流程是固定的。
- **Servlet的生命周期**：`init()`, `service()`, `destroy()`，你只需要重写`doGet()`/`doPost()`。
- **Spring的JdbcTemplate**：定义了数据库操作的模板流程（获取连接、创建语句、执行、处理结果集、关闭连接），你只需要提供SQL和结果映射。
- **Android的AsyncTask**：`onPreExecute()`, `doInBackground()`, `onPostExecute()`，执行顺序是固定的。

### 结尾总结
