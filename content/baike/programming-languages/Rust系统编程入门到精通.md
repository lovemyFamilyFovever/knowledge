# Rust系统编程入门到精通

> 📌 **导航**：本页是 **Rust 系统编程** 枢纽。所有权/借用/生命周期/unsafe 基础见 [[Rust编程基础]]；Trait泛型、错误处理、智能指针、并发异步已拆子词条。

## 定义

**一句话定义：** Rust 系统编程，是在"所有权 + 零成本抽象 + 无 GC"的地基上，用 Trait/泛型做抽象、用 Result/智能指针/并发异步写出不牺牲性能的系统级安全代码。

**通俗类比：** 所有权是"每样东西只有一个主人"的地基（见 [[Rust编程基础]]），本页是地基之上的四根承重柱：抽象(Trait/泛型)、失败(Result)、堆与共享(智能指针)、并行(async/线程)。

## 为什么需要它

C/C++ 的性能配不上内存安全，Go 的安全配不上零成本抽象。Rust 想两者兼得，代价是把这些能力拆成一整套显式机制——掌握 Trait、Result、智能指针、Send/Sync 与 async，才能写出既快又正确的系统代码。

## 何时用与何时不用

- **用**：需要 C 级性能又要有内存/并发安全保证的系统、CLI、Web 后端、嵌入式等。
- **不用**：极致追求开发速度、无性能刚需的脚本（Go/Python 更省）；团队尚未跨过借用/生命周期学习曲线时评估成本。

## 优劣与代价

✅ 编译期消灭整类内存/并发 bug，运行期几乎零额外开销。
✅ 抽象与并发的能力齐整、可组合。
⚠️ 借用检查器、trait bound、async 签名学习曲线陡，编译报错信息量大。
⚠️ 过度用 `Rc<RefCell>`、`unwrap`、`clone` 会退回运行期小心与开销。

## 与相关概念的区别

- **所有权（[[Rust编程基础]]）vs 智能指针共享**：所有权是默认单属；需要多所有者/内部可变时借 Rc/Arc/RefCell 补足。
- **泛型/静态分发（[[Rust Trait与泛型]]）vs Trait 对象/动态分发**：零成本单态化 vs 运行期 vtable。
- 与 Go 隐式接口/错误值：Rust 更显式、编译期把关更强。

## 常见误区

- Rust 既然内存安全，就再也不用关心并发死锁与逻辑错误。
- 只要用 Arc 就自动线程安全、无需 Send/Sync 与锁。
- 泛型有运行期开销、所以性能不如 C。

## 面试速答

> 🎯 Rust 系统编程=所有权地基([[Rust编程基础]])之上四柱：Trait与泛型(零成本抽象/单态化/dyn)、Result+`?` 显式错误、Box/Rc/Arc/RefCell 智能指针、线程+async/Tokio 并发(Send/Sync 编译期灭数据竞争)。既要 C 级性能又要内存/并发安全。
