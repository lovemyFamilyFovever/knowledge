# 函数式并发与多语言实践

> 📌 **导航**：本文是 **函数式并发与多语言实践** 词条，属 [[函数式编程完全指南]] 子词条。通用并发概念见 [[并发编程模式与实践]]。

## 定义

**一句话定义：** 函数式并发用"无共享可变状态"的思路降低并发难度——软件事务内存（STM）以可组合事务替代锁、Actor 模型以消息传递隔离状态；各语言的 FP 风格落地在 RxJS 流、Haskell 惰性/类型类、Rust 迭代器与所有权并行等。

**通俗类比：** 与其多人抢改一块白板（加锁易错），不如各拿一份只读副本 + 走"提交事务"（STM）或"各房间只靠传话"（Actor）。

## 为什么需要它

共享可变 + 锁导致死锁、竞态、难组合。函数式强调不可变与消息传递，天然减少锁；STM 让并发更新以事务自动重试、组合；Actor 把状态封进单线程进程、靠邮箱消息交互，避免共享。各语言的 FP 特性则把这些落到实用代码。

## 核心机制

- **STM**：把读写放进事务、提交时冲突则回滚重试（Clojure `alter/commit`、Scala STM、Haskell `STM`），可组合、无锁编程。
- **Actor 模型**：私有状态 + 邮箱消息 + `!`发送（Akka/Erlang），无共享、位置透明，适合分布式有状态并发。
- **JS/TS**：RxJS 以 Observable + 操作符做异步数据流（map/merge/switchMap）；原生 `map/filter/reduce`、可选链、`immer`。
- **Haskell**：惰性求值、类型类、Monad/do-notation；**Rust**：迭代器 `map/filter/collect` 零成本、`Rayon` 数据并行、所有权保证"无畏并发"。

## 具体示例

Rust 用迭代器 + 所有权做无锁并行 map，Rayon 自动分片：

```rust
use rayon::prelude::*;
let sum: i64 = data.par_iter().map(|x| x * x).sum(); // 并行、无数据竞争
```

## 何时用与何时不用

- **用**：高并发共享状态→优先考虑 Actor/STM 或不可变消息；流式异步→RxJS；CPU 数据并行→Rust/Rayon 或 map-reduce 式纯函数。
- **不用**：低并发/单线程别上 Actor/STM 徒增心智；RxJS 过深操作符链可读性反降。

## 优劣与代价

✅ 不可变 + 消息/事务从根上减少锁、竞态与死锁，组合性好。
✅ STM/Actor 给出并发编程的高层模型；各语言 FP 工具贴近实用。
⚠️ STM 有重试/开销、并非万能；Actor 调试跨进程消息链难。
⚠️ RxJS/Haskell 抽象陡峭、上手成本高。

## 与相关概念的区别

- **STM vs 锁**：锁需手动正确加解锁、易死锁；STM 事务自动冲突回滚、可组合。
- **Actor vs 共享状态线程**：Actor 无共享、靠消息；共享状态靠锁/原子。
- 与 Rust 所有权并发（[[Rust 并发与异步]]）：后者靠类型系统在编译期灭数据竞争，是"函数式并发"的另一实现路径。

## 常见误区

- 函数式并发就是禁止一切线程。
- 用了 STM/Actor 就永远不会出并发 bug。
- RxJS 只是把回调换了个写法，没有组合与背压价值。

## 面试速答

> 🎯 函数式并发=少共享可变、多不可变+消息：STM(可组合事务、冲突自动重试，免手动锁)与 Actor(私有状态+邮箱消息) 两大模型；落地 Rust(所有权+Rayon)、Haskell(惰性/Monad)、JS/TS(RxJS)。收益是降死锁/竞态，代价是抽象与调试成本。
