# Python 元类编程

> 📌 **导航**：本文是 **Python 元类编程** 词条，属 [[Python高级编程完全指南]] 子词条。

## 定义

**一句话定义：** 元类是"创建类的类"——Python 默认元类是 `type`，自定义元类可在类被创建的瞬间拦截并改写其行为（自动注册、强制接口、注入属性）；轻量场景可用 `__init_subclass__` 替代。

**通俗类比：** 如果说类是"造对象的模具"，元类就是"造模具的机器"——在你按下 `class` 的那一刻，它决定这个模具最终长什么样。

## 为什么需要它

有时要在"类被定义时"而非"实例化时"做统一动作：给所有子类自动登记到注册表、校验必须实现某些方法、注入公共属性、实现 ORM 元数据。元类把这类"造类级"的横切逻辑集中到一处。

## 核心机制

- **type 三参**：`type(name, bases, namespace)` 既是所有类的默认元类，也可直接动态造类；`class C(B, metaclass=M)` 时，创建过程交给 M。
- **自定义元类**：继承 `type`、覆写 `__new__`（改类本身，如注入方法）或 `__init__`（类创建后配置），在类诞生时介入。
- **`__init_subclass__`**：定义在父类里的钩子，每当有子类即自动调用——许多"想上元类"的需求用它即可，更轻更清晰。
- 顺序：`type.__call__ → metaclass.__new__ → __init__`；实例化 `cls.__call__ → __new__ → __init__` 是另一条链，别混淆。

## 具体示例

用元类把所有子类自动登记进注册表：

```python
class RegistryMeta(type):
    registry = {}
    def __new__(mcs, name, bases, ns):
        cls = super().__new__(mcs, name, bases, ns)
        if bases: RegistryMeta.registry[name] = cls
        return cls
class Plugin(metaclass=RegistryMeta): ...   # 所有子类自动被登记
```

## 何时用与何时不用

- **用**：框架级"造类时统一处理"（注册/校验/ORM 元数据），且 `__init_subclass__`、类装饰器都难以优雅表达时。
- **不用**：普通业务代码几乎用不到——"能用类/装饰器/`__init_subclass__` 就别上元类"是 Python 社区常识；元类继承关系隐晦、调试难。

## 优劣与代价

✅ 在类创建点集中施加规则，支撑插件式/声明式框架。
✅ `__init_subclass__`/类装饰器提供了更轻的替代。
⚠️ 元类是"黑魔法"，可读性差、继承冲突时难排错。
⚠️ 过度使用让类体系难以理解，违背"明确优于隐晦"。

## 与相关概念的区别

- **元类 vs 类装饰器**：都能改类；装饰器在类定义后原地改、更直观；元类介入创建过程、能力更强也更重。
- **元类 vs `__init_subclass__`**：后者是内建钩子，覆盖多数"子类登记/校验"需求，优先用它。
- **元类 `__new__/__init__` vs 实例的 `__new__/__init__`**：前者作用于"类"，后者作用于"对象"。

## 常见误区

- 元类是 Python 高级特性，应当鼓励多用。
- `__init_subclass__` 和元类功能完全相同、没有取舍。
- 元类的 `__init__` 是在创建每个实例时调用的。

## 面试速答

> 🎯 元类是"创建类的类"，默认是 `type`；`class C(metaclass=M)` 让 M 在类诞生时经 `__new__/__init__` 介入（自动注册/强制接口/注入）。多数需求可用更轻的 `__init_subclass__` 或类装饰器；元类强但隐晦，属"非必要不用"的框架级手段。
