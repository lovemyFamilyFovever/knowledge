# Python 高级装饰器

> 📌 **导航**：本文是 **Python 高级装饰器** 词条，属 [[Python高级编程完全指南]] 子词条。装饰器基础见 [[Python高级特性]]，GoF 结构型"装饰器模式"见 [[装饰器模式]]。

## 定义

**一句话定义：** Python 装饰器是"接收一个函数、返回一个新函数"的高阶函数语法糖；高级用法包括带参数的装饰器（装饰器工厂）、用类实现并可持状态的类装饰器，并靠 `functools.wraps` 保留被装饰函数的元信息。

**通俗类比：** 装饰器像"给礼物重新包一层"——`@deco` 就是把函数塞进包装器、换回一个带附加行为的新函数；带参装饰器则是"先选好包装纸，再包这一件"。

## 为什么需要它

横切关注点（计时、日志、鉴权、重试、缓存）若写进每个函数会到处重复。装饰器把这些抽成一个可复用的"外层包裹"，`@` 一处声明即生效，既解耦又不改原函数体——Python 里最地道的 AOP 式手法。

## 核心机制

- **基本式**：`@deco` 等价于 `f = deco(f)`，在定义时即完成包装。
- **带参数（工厂）**：再套一层——`@retry(times=3)` 先由外层收到参数、返回真正的装饰器，形成"工厂→装饰器→包装函数"三层。
- **类装饰器**：用 `__call__` 让实例可调用；`__init__` 天然存放参数与状态，适合需维护内部状态的装饰器。
- **`functools.wraps`**：把原函数的 `__name__/__doc__/__module__` 等复制过去，否则内省/文档/help 会丢失。

## 具体示例

带参数装饰器 = 三层嵌套，外层收配置、中层才是装饰器：

```python
def retry(times):                 # 装饰器工厂
    def deco(fn):                 # 真正的装饰器
        @functools.wraps(fn)
        def wrapper(*a, **k):
            for _ in range(times):
                try: return fn(*a, **k)
                except Exception: pass
        return wrapper
    return deco
```

## 何时用与何时不用

- **用**：横切复用逻辑、路由/权限注册式框架（Flask `@app.route`）、性能/日志切面。
- **不用**：逻辑简单一次性时别硬造装饰器；装饰器叠太多层会难调试、执行顺序需心里有数。

## 优劣与代价

✅ 抽取横切关注点、声明式复用、不改原函数体。
✅ 类装饰器可优雅承载状态与参数。
⚠️ 忘写 `@wraps` 会丢函数元信息、破坏装饰器栈的内省。
⚠️ 多层装饰器使调用链与执行顺序变复杂、难排错。

## 与相关概念的区别

- **`@deco` vs 直接 `f=deco(f)`**：语法糖完全等价，只是更易读。
- **装饰器 vs GoF 装饰器模式**（[[装饰器模式]]）：Python `@` 是语言级函数包装语法；GoF 强调"装饰器与被装饰对象实现同一接口、层层可替换"，神似而形不同。
- **函数装饰器 vs 类装饰器**：前者轻、闭包持状态；后者用 `__call__`、状态更显式。

## 常见误区

- `@deco` 会在每次调用函数时才执行一次包装。
- 忘了 `@wraps` 也无所谓，不影响 help 和函数名。
- 带参数的装饰器和普通装饰器结构完全一样。

## 面试速答

> 🎯 装饰器=`@deco` 即 `f=deco(f)`、定义时套一层高阶函数。带参装饰器再套一层成"工厂→装饰器→wrapper"三层；类装饰器用 `__call__`+`__init__` 存状态；`wraps` 保留元信息。GoF 装饰器模式是同接口层层包裹，与此不同。
