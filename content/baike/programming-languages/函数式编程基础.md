# 函数式编程基础（纯函数·不可变·高阶·柯里化）

> 📌 **导航**：本文是 **函数式编程基础** 词条，属 [[函数式编程完全指南]] 子词条。闭包语言机制另见 [[闭包]]。

## 定义

**一句话定义：** 函数式编程以"求值即计算数学函数"为核心：纯函数（同入同出、无副作用）+ 引用透明、不可变数据、高阶函数与闭包，并用柯里化/函数组合把逻辑拼成可复用的小件。

**通俗类比：** 像搭乐高而非用瑞士军刀改东西——每块（纯函数）只进不出、改完不碰原件（不可变），高阶函数与组合让你把小块拼成大功能。

## 为什么需要它

命令式改状态、共享可变数据会带来隐藏耦合与并发 bug。纯函数把"输入→输出"变确定、可缓存、可并行、好测；不可变消除"谁改了它"的心智负担；高阶函数与组合复用行为、减少重复样板。

## 核心机制

- **纯函数 & 引用透明**：结果只由参数决定、不改外部状态；故同一表达式可替换为其值（可记忆化、可并行、易测）。
- **不可变性**：数据一旦生成不改，"修改"=产生新值（常配合 [[函数式错误处理与不可变数据结构]] 的持久化数据结构做结构共享）。
- **高阶函数**：接收/返回函数（map/filter/reduce）把"做什么"参数化。
- **闭包**：函数捕获定义环境中的自由变量（见 [[闭包]]）。
- **柯里化 & 组合**：`f(a,b)→f(a)(b)` 便于部分应用与复用；`compose(f,g)=f∘g` 把小函数串成流水线。

## 具体示例

纯函数 + map/compose 把处理写成可组合的数据流：

```javascript
const add = a => b => a + b;            // 柯里化：纯、可部分应用
const double = x => x * 2;
const incThenDouble = x => double(x + 1); // 组合（引用透明，可缓存）
[1, 2, 3].map(incThenDouble);            // [4, 6, 8]，无副作用
```

## 何时用与何时不用

- **用**：业务逻辑/数据变换尽量写成纯函数链，便于测试与并行；共享数据默认不可变。
- **不用**：I/O、DOM、数据库等边界处仍需副作用——隔离到最外层，别强求处处纯；性能热路径过度拷贝不可变结构需权衡。

## 优劣与代价

✅ 可预测、易测、易并行、组合复用强，减少一类状态 bug。
✅ 引用透明使缓存/惰性/记忆化自然成立。
⚠️ 全不可变在大数据/频繁更新下增加拷贝成本（靠持久化数据结构缓解）。
⚠️ 柯里化/组合过度使用降低可读性、对新人不友好。

## 与相关概念的区别

- **纯函数 vs 无返回值函数**：纯≠"只读"，而是"同入同出 + 无副作用"。
- **不可变 vs 只读引用**：只读防改、不可变是根本无原地修改。
- **柯里化 vs 偏函数应用**：柯里化逐级返回一元函数、偏应用固定部分参数。
- 与 GoF 无关，是编程范式（[[MVC 与 MVVM]] 是架构、范式不同）。

## 常见误区

- 只要函数没有参数就算纯函数。
- 不可变数据永远比可变数据快。
- 函数式编程要求完全消灭一切副作用。
