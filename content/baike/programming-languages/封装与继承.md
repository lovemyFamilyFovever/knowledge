# 封装与继承

> 📌 **导航**：本文是 **封装与继承** 词条，属 [[面向对象编程（OOP）概念]] 子词条。多态见 [[多态与抽象]]。

## 定义

**一句话定义：** 封装把内部状态藏起、只暴露受控接口；继承让子类复用并扩展父类的字段与行为——但强耦合易失控，"组合优于继承"是普遍经验，里氏替换则约束继承何时才正确。

**通俗类比：** 封装像汽车方向盘——你操作接口、不必懂引擎内部；继承像"电动车是一种车"，复用车的共性再加电池；但若为省事乱继承，子类一改父类全崩，常不如"把引擎拼装进来"（组合）。

## 为什么需要它

封装隐藏实现、维持不变量、降低调用方与内部改动的耦合，是模块化的支柱。继承提供代码复用与"是一个（is-a）"的类型层次，配合多态支撑面向抽象编程；但不当继承脆弱，故需组合替代与 LSP 约束。

## 核心机制

- **封装**：私有字段 + 受控方法（getter/setter、不变式校验）；对外契约稳定、内部可换。
- **继承**：子类 extends 父类，复用字段/方法、可覆写；单继承 vs 多继承（菱形问题）由语言取舍；`super` 调父类。
- **组合 vs 继承**：组合(has-a)通过持有成员并委托，耦合更松、更灵活可换；仅当确实是 is-a 且行为契约稳定才继承。
- **里氏替换（LSP）**：子类型必须能替换父类型而不破坏程序性质（不加强前置、不削弱后置、保持不变式）——是判断"该不该继承"的准绳。

## 具体示例

用组合替换脆弱继承：

```python
class Duck:      def fly(self): ...          # 若用继承做"会飞的鸟"会很脆
class Drone:     def fly(self): ...
class Vehicle:
    def __init__(self, flyable): self._fly = flyable.fly   # 组合+委托
# Vehicle(Duck()) / Vehicle(Drone()) 皆可，不必为"会飞"造类层次
```

## 何时用与何时不用

- **用继承**：真正的 is-a、契约稳定、需要多态基类时。
- **用组合/委托**：为复用实现、或仅"部分行为相同"——多数场景优于继承；封装一律推荐（最小可见）。
- 别用继承做代码拷贝式复用，别违反 LSP（如 Square 继承 Rectangle 破坏 setWidth/setHeight 契约）。

## 优劣与代价

✅ 封装降耦、护不变量、允许内部演化；继承减少重复、支撑多态层次。
⚠️ 深继承=脆弱基类问题：父类改、子孙崩；组合更松但需委托样板。
⚠️ 多继承带来菱形与复杂度；违反 LSP 的继承让多态埋雷。

## 与相关概念的区别

- **封装 vs 抽象**：封装藏"实现/状态"，抽象定"该暴露什么接口"（见 [[多态与抽象]]）。
- **继承 vs 组合**：is-a vs has-a；组合优先。
- **LSP** 是继承正确性准则，也是 SOLID 的 L。

## 常见误区

- 为了复用几个方法就该用继承。
- 私有字段等于绝对安全、外部绝无可能读到。
- 只要编译通过，子类型就一定符合里氏替换。

## 面试速答

> 🎯 封装=藏状态、暴露受控接口、护不变式、降耦；继承=is-a 复用与扩展父类，但有脆弱基类/菱形问题，故"组合优于继承"——只在稳定 is-a 时用继承。里氏替换(LSP)是判据：子类可无缝替换父类型(不加强前置、不削弱后置、保不变式)，Square 继承 Rectangle 即典型违反。
