# 泛型

> 📌 **导航**：本文是 **泛型** 词条，属于 programming-languages 术语集。相关枢纽：[[Go语言核心]]、[[Python高级编程完全指南]]、[[Rust系统编程入门到精通]]、[[Rust编程基础]]、[[TypeScript深入]]。

## 定义

**一句话定义：** 泛型（Generics）是一种让类、接口或方法在定义时使用类型参数、在实例化或调用时再指定具体类型的编程特性，从而实现"一份代码适用于多种类型"的类型安全复用（参数化多态）。

**通俗类比：** 像一个通用收纳盒的模具——模具不规定装什么，你可以指定做成"装鞋的盒"或"装书的盒"，既复用了同一套设计，又保证"鞋盒只装鞋"的类型安全。

## 为什么需要它

没有泛型，要么为每种元素类型各写一遍 List，要么用 Object 集合然后到处强制类型转换、把类型错误从编译期拖到运行期。泛型让你只写一份逻辑、在使用处才绑定具体类型，既复用了代码，又把类型检查留在编译期——这是"参数化多态"的价值。

## 核心机制

- **类型参数**：用占位符（T、K、V）声明，使用时替换为具体类型。
- **实现策略**：类型擦除（Java，编译后擦除泛型信息，运行时退化为原始类型）；单态化 / 具化（C++/Rust，为每个具体类型生成专门代码，快但体积增大）；运行时具化（C#，运行时保留泛型信息）。
- **约束（bounds）**：限定类型参数需满足的条件（实现某接口 / 继承某类）。
- **型变（variance）**：协变 / 逆变 / 不变（Java 通配符 ? extends / ? super，Kotlin in / out）。

## 具体示例

同一份 ArrayList 实现，靠类型参数安全地服务不同元素类型：

```
List<String>  names = new ArrayList<>();   // T = String
List<Integer> ids   = new ArrayList<>();   // T = Integer
// 无需为每种元素重写容器，也不必到处强转
```

## 何时用与何时不用

- **用**：集合与通用容器（List<T>、Map<K,V>）、通用算法与数据结构复用、类型安全的 API 设计。
- **慎用**：为了"通用"把类型参数叠得过多、约束和型变规则复杂到读不动；简单一次性场景用具体类型更清晰。

## 优劣与代价

✅ 类型安全的复用、编译期检查、减少强制转换、提升可维护性。
✅ 一份实现覆盖多种类型。
⚠️ 各语言实现差异大：擦除有运行时限制，单态化导致代码膨胀。
⚠️ 约束与型变规则增加理解成本。

## 与相关概念的区别

- **泛型 vs 动态类型 / Object**：泛型仍有静态类型检查，在编译期就拒绝放错类型；用 Object + 强转把错误推迟到运行期。
- **类型擦除 vs 单态化**：Java 擦除后运行时不区分 List<String> 与 List<Integer>；C++/Rust 单态化为每个类型各生成一份代码。
- **泛型 vs 接口多态**：接口多态是"同一接口不同实现"，泛型是"同一份代码模板套不同（含非公共父类的）类型"。

## 常见误区

- Java 泛型在运行时仍保留具体类型信息，可以 new T[] 或按 T 分支。
- 泛型就是"任意类型 / Object"，反正都要强转。
- 协变 / 逆变是语言默认且安全的，无需显式声明。
