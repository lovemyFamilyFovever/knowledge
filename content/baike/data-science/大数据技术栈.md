# 大数据技术栈


> 📌 **导航**：本文是 **大数据技术栈** 词条，属于 data-science 术语集。相关枢纽：[[A B测试与实验设计]]、[[ETL]]、[[MLOps实践]]、[[RNN LSTM GRU]]、[[卷积神经网络(CNN)]]。

## 定义

**一句话定义：** 大数据技术栈是围绕海量（TB/PB 级）数据的 4V 特征，用分布式存储与计算来采集、保存、处理和分析数据的一整套工程工具的总称。

**通俗类比：** 传统数据库像一个小仓库，大数据技术栈是一套超级物流系统——能处理每天数百万包裹的入库、分拣、运输和查询。

## 为什么需要它

单机在存储容量、计算能力、I/O 和吞吐上都有硬上限，当数据到 TB/PB、还要近实时处理并容纳结构化/半结构化/非结构化混合时，纵向加机器既贵又封顶。大数据栈用"分而治之 + 横向扩展"，把数据切成块、把计算摊到成百上千台普通节点，用冗余换容错、用规模换吞吐。

## 核心机制

大数据的动机由 4V 刻画：

| 特征 | 英文 | 说明 |
|------|------|------|
| 大量 | Volume | TB/PB 级数据 |
| 高速 | Velocity | 实时或近实时处理 |
| 多样 | Variety | 结构化/半结构化/非结构化 |
| 价值 | Value | 从数据中挖掘价值 |

整套栈按职责分层，每层有代表工具：

| 组件 | 工具 | 功能 |
|------|------|------|
| 分布式存储 | HDFS、S3 | 海量文件存储 |
| 计算引擎 | Spark、MapReduce | 分布式计算 |
| 流处理 | Kafka、Flink | 实时数据流 |
| 数据仓库 | Hive、ClickHouse | OLAP 分析 |
| 调度 | Airflow、DolphinScheduler | 任务编排 |
| 查询引擎 | Presto、Trino | 交互式查询 |

Hadoop 是奠基性的一体化生态（HDFS 存储 + MapReduce 计算 + YARN 资源管理，外围 Hive/HBase/ZooKeeper/Sqoop）：

```
Hadoop
├── HDFS（分布式文件系统）
├── MapReduce（分布式计算框架）
├── YARN（资源管理）
└── 生态：Hive / HBase / ZooKeeper / Sqoop
```

Spark 以内存计算 + DAG 执行引擎优化迭代式计算，常见操作如下按部门聚合求平均薪资并排序：

```python
df = spark.read.parquet("hdfs://data/users/")
result = df.groupBy("department").agg(avg("salary").alias("avg_salary")) \
           .orderBy("avg_salary", ascending=False)
```

Spark 相比 MapReduce 通常快 10–100 倍，主要因中间结果留在内存、避免多轮落盘，而非代码更精简。

## 具体示例

一条用户行为日志的旅程：埋点先到 Kafka 缓冲，Flink 做实时清洗聚合写回消息/看板；原始日志按天落到 HDFS/S3 数据湖；夜间 Spark 批处理做画像与特征；结果进 Hive/数仓建模；分析师用 Presto 交互查询；整条链路由 Airflow 定时编排与失败重试。

## 何时用 / 何时不用

- **用：** 数据规模超出单机、需横向扩展与容错、多源多格式、要同时支持离线批处理与实时流处理。
- **不用：** 数据量小、单机 PostgreSQL/MySQL 就能扛时——上 Hadoop/Spark 属过度工程，徒增运维；纯低延迟点查/OLTP 用关系库或 Redis。

## 优劣与代价

✅ 水平可扩展、天然容错（副本）、生态齐全、批流一体可分层选型。
⚠️ 部署与运维复杂、成本高，分布式调试与数据一致性更难。
⚠️ 小数据场景收益抵不上复杂度；组件选型多、学习曲线陡。

## 与相关概念的区别

- **vs 传统数据库：** 传统 DB 走单机强 ACID；大数据栈以分布式换吞吐与扩展，常牺牲强一致换可用性（见 [[ETL]]、[[数据仓库]]、[[数据湖]]）。
- **数据仓库 vs 数据湖：**

| 特性 | 数据仓库 | 数据湖 |
|------|----------|--------|
| 数据格式 | 结构化 | 任意格式 |
| Schema | 写入前定义（Schema-on-Write） | 读取时定义（Schema-on-Read） |
| 成本 | 较高 | 较低（对象存储） |
| 适用 | BI 分析 | 机器学习 + 分析 |
| 代表 | Snowflake、Redshift | Delta Lake、Iceberg |

## 常见误区

- 只要数据量一大，就必须立刻上 Hadoop/Spark 这套大数据栈。
- 数据仓库和数据湖是一回事，只是叫法不同。
- Spark 比 MapReduce 快，是因为它的代码写得更精简。

## 面试速答

> 🎯 大数据栈=为 4V 数据做的分布式分层：存储（HDFS/S3）→批计算（Spark）→流（Kafka/Flink）→数仓（Hive/ClickHouse）→交互查询（Trino）→调度（Airflow），靠横向扩展+副本换吞吐与容错。数据量小则属过度工程，湖仓之别在格式/Schema/成本。
