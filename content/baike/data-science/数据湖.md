# 数据湖

## 定义

**一句话定义：** 数据湖(Data Lake)是一种以原始格式集中存储海量结构化、半结构化与非结构化数据的存储库/系统;数据写入时不强制预设结构(schema-on-write),而是在分析时再按需赋予结构(schema-on-read),为大数据分析与机器学习提供统一的数据底座。

**通俗类比：** 数据仓库像整理好的图书馆(书按类目上架编目,入库即规范);数据湖像一个天然"蓄水湖"——各路水源(各种原始数据)先原样汇入,等要用时再按需取水处理(读取时才定义结构)。

> 多义说明:数据湖 vs 数据仓库(见 [[数据仓库]])——湖存原始各类数据、schema-on-read;仓库存结构化已建模数据、schema-on-write。近年有"湖仓一体(Lakehouse)"融合二者。本文讨论数据湖。

## 原理与机制

- **存储:** 通常建在廉价可扩展的分布式存储上(如 HDFS、对象存储 S3/OSS),存放原始数据(日志、图片、视频、JSON、表等)。
- **schema-on-read:** 写入不强制模式,读取/分析时再解析结构(灵活,但需治理)。
- **处理:** 配合批处理(MapReduce / Spark)、流处理、SQL 引擎(Presto/Trino)与机器学习。
- **治理挑战:** 缺乏治理易沦为"数据沼泽"(data swamp,数据堆积却难用),需元数据管理、数据目录、质量与权限治理。

## 关键组成

| 组成 | 说明 |
|------|------|
| 原始多类型数据 | 结构化/半结构化/非结构化 |
| 分布式 / 对象存储 | HDFS / S3 / OSS |
| schema-on-read | 读取时才定义结构 |
| 元数据 / 数据目录 | 治理与发现 |
| 处理引擎 | Spark / Trino 等 |

## 应用场景

- 大数据分析与数据科学
- 机器学习训练数据
- 日志、物联网、点击流汇聚
- 企业统一数据底座、湖仓一体

## 优点与局限

- 优点:存原始数据不丢信息、schema 灵活、支持多类型与大规模、成本较低(对象存储)。
- 局限:缺乏治理易成数据沼泽;schema-on-read 把复杂度后移;数据质量与一致性难保证;查询性能通常不如数据仓库(需额外优化)。

## 常见误区

- 数据湖 ≠ 数据仓库:湖存原始/schema-on-read,仓库存结构化/schema-on-write。
- 数据湖不是"随便堆数据",缺乏治理会沦为数据沼泽。
- 数据湖 ≠ 一定用 Hadoop(现代多基于对象存储)。
- 湖仓一体(Lakehouse)意在融合湖的灵活与仓的管理能力。
