# 数据仓库

## 定义

**一句话定义：** 数据仓库(Data Warehouse)是面向主题的、集成的、相对稳定的、反映历史变化的数据集合,它把来自多个业务系统的数据经清洗、整合后集中存储,专门用于支持分析、报表与决策(OLAP),而非日常事务处理(OLTP)。

**通俗类比：** 像公司的"档案馆 + 分析中心"——把各部门日常产生的零散记录(业务库)定期整理、统一口径后归档进来,专门供管理层做趋势分析与决策,而不是用来处理今天的日常业务。

> 多义说明:数据仓库(DW)面向分析(OLAP),区别于业务数据库(OLTP);相关概念有数据湖(data lake,存原始数据)、数据集市(data mart,部门级)、湖仓一体(lakehouse)。本文讨论数据仓库。

## 原理与机制

- **特征(Inmon/Kimball):** 面向主题、集成、非易失、随时间变化。
- **建模:** 星型模型(事实表 + 维度表)、雪花模型(维度进一步规范化);Kimball 维度建模 vs Inmon 企业级范式建模。
- **ETL / ELT:** 从源系统抽取(Extract)、清洗转换(Transform)、加载(Load)到仓库。
- **OLAP:** 支持多维分析(切片、钻取、旋转)与聚合查询。

## 关键组成

| 组成 | 说明 |
|------|------|
| 面向主题的集成数据 | 跨源统一口径 |
| 事实表 / 维度表 | 星型 / 雪花模型 |
| ETL / ELT | 抽取-转换-加载 |
| OLAP 查询 | 多维分析 |
| 数据集市 | 部门级子集 |

## 应用场景

- BI 报表与仪表盘
- 经营分析与决策支持
- 历史趋势分析、多维 OLAP
- 数据中台

## 优点与局限

- 优点:统一口径、面向分析优化、支持历史与多维查询、与业务库解耦。
- 局限:建设成本高(ETL 复杂);数据有延迟(非实时,除非实时数仓);schema 变更成本高;与数据湖的定位需权衡。

## 常见误区

- 数据仓库 ≠ 业务数据库:DW 面向分析(OLAP),业务库面向事务(OLTP)。
- 数据仓库 ≠ 数据湖:仓库存结构化/已建模数据,湖存原始各类数据。
- 星型模型是"反范式"的(为查询性能故意冗余)。
- 数据仓库通常有延迟,实时数仓是另一套架构。
