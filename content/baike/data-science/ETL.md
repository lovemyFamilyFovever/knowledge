# ETL


> 📌 **导航**：本文是 **ETL** 词条，属于 data-science 术语集。相关枢纽：[[A B测试与实验设计]]、[[ETL]]、[[MLOps实践]]、[[RNN LSTM GRU]]、[[卷积神经网络(CNN)]]。

## 定义

**一句话定义：** ETL（Extract-Transform-Load，抽取-转换-加载）是数据集成的核心流程：从各数据源抽取（Extract）原始数据，按业务规则清洗、转换（Transform）为统一格式与口径，再加载（Load）到目标存储（如数据仓库），为分析与报表提供高质量数据。

**通俗类比：** 像把各地采购来的食材做成一桌菜——先从各处取来原料（抽取），再清洗、切配、调味（转换），最后装盘上桌（加载到数仓供分析）；中间的清洗加工决定了成菜质量。

> 多义说明：ETL 与 ELT（先加载后转换，借助目标端算力，常见于云数仓/数据湖）顺序不同。本文讨论 ETL 并对比 ELT。

## 为什么需要它

企业的"事实"散落在业务库、日志、第三方 API、Excel 等各种异构源里，口径不一、脏数据多。直接拿这些去做报表会得出互相矛盾的数。ETL 把"取来→洗干净→统一口径→装进数仓"固化成可调度、可校验、可追血缘的管道，让下游分析建立在一致、可信的数据之上。

## 核心机制

- **Extract（抽取）：** 从业务库、日志、API、文件等抽取数据（全量或增量）。
- **Transform（转换）：** 清洗（去重/补缺/纠错）、转换（统一格式/单位/编码）、聚合、关联、脱敏、业务规则计算。
- **Load（加载）：** 写入数据仓库/数据集市（全量/增量/拉链表）。
- **调度与监控：** 定时或事件触发，失败重试、数据质量校验、血缘追踪。

| 阶段 | 说明 |
|------|------|
| 抽取 | 全量 / 增量 |
| 清洗与转换 | 统一口径、保证质量 |
| 加载 | 全量 / 增量 / 拉链 |
| 调度编排 | 定时 / 事件触发 |
| 数据质量与血缘 | 校验与追踪 |

## 具体示例

每天凌晨从订单库增量抽取昨日订单、从埋点日志抽行为：去重、补全缺失字段、把金额统一到"分"、把不同系统的用户 ID 关联对齐，再按天分区加载进数仓的事实表；加载后跑数据质量规则（主键唯一、非空、金额≥0）校验，失败告警重试，并记录该表由哪些源加工而来（血缘）。

## 何时用 / 何时不用

- **用：** 数据仓库建设、BI 报表数据准备、数据中台/跨系统集成、历史数据迁移等需统一口径与质量保证的场景。
- **不用/慎用：** 强实时分析（批 ETL 有延迟，应走流式如 Flink 或 ELT）；源端算力/云数仓足够时，可先加载后转换（ELT）省去转换集群。

## 优劣与代价

✅ 统一数据口径、提升数据质量、支撑分析与决策。
⚠️ 开发与维护成本高，转换逻辑复杂。
⚠️ 批处理有延迟，实时需流式 ETL；上游 schema 变更会击穿管道，需监控与再平衡。

## 与相关概念的区别

- **ETL vs ELT：** ETL 在入仓前用独立引擎转换、适合敏感/受限目标；ELT 先原样加载再由云数仓/大数据引擎就地转换，弹性更强、更贴近现代数据栈。
- **ETL vs 数据复制/CDC：** 复制只搬变更行保持原样，ETL 强调口径转换与质量加工。
- **vs 实时流处理：** 流式（Flink）做低延迟增量，传统 ETL 是批量 T+1。

## 常见误区

- ETL 和 ELT 没有区别，只是叫法不同。
- ETL 的核心工作就是把数据从一个地方搬到另一个地方。
- 传统批处理 ETL 直接就能满足实时分析需求。

## 面试速答

> 🎯 ETL=从异构源抽取(全量/增量)→按业务规则清洗转换统一口径→加载入仓，配调度、质量校验与血缘；价值是把脏乱数据变可信一致的数据底座。与 ELT 的区别是先转换后加载还是先加载后在目标端转换；强实时场景改用流式而非批 ETL。
