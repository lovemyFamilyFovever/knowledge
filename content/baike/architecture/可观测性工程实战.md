# 可观测性工程实战

# 可观测性工程实战指南

## 1. 可观测性三支柱

### 1.1 核心概念与演进

可观测性(Observability)源于控制理论，指通过系统的外部输出推断其内部状态的能力。在分布式系统时代，它已经从单纯的“监控”发展为涵盖**日志(Logs)、指标(Metrics)、链路追踪(Traces)**的三位一体体系。

**传统监控 vs. 可观测性**：
- **传统监控**：预定义已知故障模式，关注系统是否正常运行
- **可观测性**：探索未知故障模式，关注系统内部发生了什么
- **关键区别**：监控回答“哪里出了问题”，可观测性帮助回答“为什么会出问题”

### 1.2 三大支柱深度解析

**日志(Logs)**：
- **本质**：离散的、带时间戳的事件记录
- **优势**：包含详细上下文信息，适合调试和审计
- **挑战**：数据量巨大，需要结构化和采样策略

**指标(Metrics)**：
- **本质**：聚合的数值型时间序列数据
- **优势**：存储效率高，查询速度快，适合告警和趋势分析
- **挑战**：维度爆炸，基数控制

**链路追踪(Traces)**：
- **本质**：请求在分布式系统中的完整调用路径
- **优势**：直观展示请求流，快速定位性能瓶颈
- **挑战**：需要应用埋点，对系统侵入性较高

```python
# 概念示例：如何通过三支柱协同诊断问题
def handle_request(request_id):
    # 链路追踪：记录请求的起始点
    with tracer.start_as_current_span("handle_request") as span:
        span.set_attribute("request.id", request_id)
        
        # 指标：记录请求计数和耗时
        REQUEST_COUNT.labels(endpoint="/api/orders").inc()
        start_time = time.time()
        
        try:
            # 日志：记录详细处理过程
            logger.info(f"Processing order", 
                       extra={"request_id": request_id, "action": "start"})
            
            # 业务逻辑
            result = process_order(request_id)
            
            # 指标：记录成功状态
            REQUEST_LATENCY.labels(
                endpoint="/api/orders", 
                status="success"
            ).observe(time.time() - start_time)
            
            logger.info(f"Order processed successfully",
                       extra={"request_id": request_id, "result": result})
            
        except Exception as e:
            # 链路追踪：记录错误信息
            span.set_status(Status(StatusCode.ERROR))
            span.record_exception(e)
            
            # 指标：记录错误状态
            REQUEST_LATENCY.labels(
                endpoint="/api/orders",
                status="error"
            ).observe(time.time() - start_time)
            ERROR_COUNT.labels(error_type=type(e).__name__).inc()
            
            # 日志：记录错误详情
            logger.error(f"Order processing failed",
                        extra={"request_id": request_id, 
                               "error": str(e),
                               "stack_trace": traceback.format_exc()})
            raise
```

### 1.3 三支柱的协同效应

**故障排查场景**：
1. **告警触发**（指标）：P99延迟突然升高
2. **根因定位**（链路追踪）：发现某个微服务响应缓慢
3. **详情查看**（日志）：发现数据库连接池耗尽的错误日志
4. **解决方案**：调整连接池配置并监控相关指标

**数据关联**：通过`trace_id`、`request_id`等标识符将三个支柱的数据串联起来，实现从宏观到微观的完整视图。

```python
# Python日志配置示例
import logging
import json
import sys

class StructuredLogger:
    def __init__(self, service_name, environment):
        self.logger = logging.getLogger(service_name)
        self.service_name = service_name
        self.environment = environment
        
        # 设置日志级别
        log_level = self._get_log_level(environment)
        self.logger.setLevel(log_level)
        
        # 创建JSON格式的处理器
        handler = logging.StreamHandler(sys.stdout)
        formatter = logging.Formatter(
            '%(message)s'  # 消息本身就是JSON
        )
        handler.setFormatter(formatter)
        self.logger.addHandler(handler)
    
    def _get_log_level(self, environment):
        levels = {
            'production': logging.WARNING,
            'staging': logging.INFO,
            'development': logging.DEBUG
        }
        return levels.get(environment, logging.INFO)
    
    def log(self, level, message, **kwargs):
        """结构化日志记录方法"""
        log_entry = {
            'timestamp': datetime.utcnow().isoformat() + 'Z',
            'level': logging.getLevelName(level),
            'service': self.service_name,
            'environment': self.environment,
            'message': message,
            **kwargs
        }
        
        self.logger.log(level, json.dumps(log_entry))
    
    def error_with_context(self, message, error, context=None):
        """带上下文的错误日志"""
        self.log(
            logging.ERROR,
            message,
            error_type=type(error).__name__,
            error_message=str(error),
            stack_trace=traceback.format_exc(),
            **(context or {})
        )

# 使用示例
logger = StructuredLogger("order-service", "production")

logger.log(logging.INFO, "Order processed",
           order_id="ORD-001",
           user_id="user123",
           amount=99.99)

try:
    # 业务逻辑
    pass
except DatabaseError as e:
    logger.error_with_context("Database operation failed", e,
                             query="SELECT * FROM orders",
                             duration_ms=1250)
```

**日志级别使用指南**：

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| **FATAL** | 系统无法继续运行 | 数据库连接池完全耗尽，服务无法启动 |
| **ERROR** | 操作失败但服务仍可运行 | 支付网关调用失败，使用备用方案 |
| **WARN** | 潜在问题，需关注 | 响应时间超过阈值，资源使用率高 |
| **INFO** | 重要业务事件 | 用户登录成功，订单创建完成 |
| **DEBUG** | 开发调试信息 | 函数调用参数，SQL查询语句 |
| **TRACE** | 极其详细的调试信息 | 每一步处理流程，循环内部状态 |

### 2.3 日志采样与降噪策略

**动态采样算法**：
```python
class AdaptiveSampler:
    """自适应日志采样器"""
    
    def __init__(self, base_rate=0.1, error_rate=1.0):
        self.base_rate = base_rate  # 基础采样率
        self.error_rate = error_rate  # 错误日志采样率
        self.counters = {}
        self.window_size = 60  # 统计窗口（秒）
        
    def should_sample(self, log_entry):
        """决定是否采样该日志"""
        log_hash = self._hash_log_pattern(log_entry)
        
        # 错误日志始终采样
        if log_entry.get('level') == 'ERROR':
            return True
        
        # 检查是否为重复日志
        if self._is_repetitive(log_hash):
            return random.random() < self.base_rate * 0.1
        
        # 正常采样
        return random.random() < self.base_rate
    
    def _hash_log_pattern(self, log_entry):
        """计算日志模式哈希"""
        # 移除易变的字段（如时间戳、ID等）
        pattern = {k: v for k, v in log_entry.items() 
                  if k not in ['timestamp', 'trace_id', 'span_id']}
        return hashlib.md5(json.dumps(pattern, sort_keys=True).encode()).hexdigest()
    
    def _is_repetitive(self, log_hash):
        """检查是否为重复日志"""
        current_time = time.time()
        if log_hash not in self.counters:
            self.counters[log_hash] = {'count': 1, 'window_start': current_time}
            return False
        
        counter = self.counters[log_hash]
        if current_time - counter['window_start'] > self.window_size:
            counter['count'] = 1
            counter['window_start'] = current_time
            return False
        
        counter['count'] += 1
        return counter['count'] > 10  # 超过10次/分钟视为重复
```

**自定义指标实现**：

```python
# Python Flask应用的Prometheus指标集成
from prometheus_client import Counter, Histogram, Gauge, Summary, generate_latest
from prometheus_client import CollectorRegistry, multiprocess, Info
from flask import Flask, Response, request
import time
import psutil

app = Flask(__name__)

# 创建指标
REQUEST_COUNT = Counter(
    'http_requests_total',
    'Total HTTP requests',
    ['method', 'endpoint', 'status']
)

REQUEST_LATENCY = Histogram(
    'http_request_duration_seconds',
    'HTTP request latency in seconds',
    ['method', 'endpoint'],
    buckets=(0.01, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0)
)

IN_PROGRESS = Gauge(
    'http_requests_in_progress',
    'Number of HTTP requests in progress'
)

DB_QUERY_LATENCY = Summary(
    'db_query_duration_seconds',
    'Database query latency in seconds',
    ['query_type', 'table']
)

SYSTEM_MEMORY = Gauge(
    'system_memory_usage_bytes',
    'System memory usage in bytes',
    ['type']
)

# 中间件：自动收集请求指标
@app.before_request
def before_request():
    request.start_time = time.time()
    IN_PROGRESS.inc()

@app.after_request
def after_request(response):
    # 记录请求延迟
    latency = time.time() - request.start_time
    REQUEST_LATENCY.labels(
        method=request.method,
        endpoint=request.path
    ).observe(latency)
    
    # 记录请求计数
    REQUEST_COUNT.labels(
        method=request.method,
        endpoint=request.path,
        status=response.status_code
    ).inc()
    
    # 递减进行中请求计数
    IN_PROGRESS.dec()
    
    return response

# 系统指标收集器
def collect_system_metrics():
    """定期收集系统指标"""
    while True:
        memory = psutil.virtual_memory()
        SYSTEM_MEMORY.labels(type='used').set(memory.used)
        SYSTEM_MEMORY.labels(type='available').set(memory.available)
        SYSTEM_MEMORY.labels(type='percent').set(memory.percent)
        
        cpu_percent = psutil.cpu_percent(interval=1)
        SYSTEM_CPU.labels(type='percent').set(cpu_percent)
        
        time.sleep(15)

# 指标端点
@app.route('/metrics')
def metrics():
    return Response(generate_latest(), mimetype='text/plain')

# 业务指标装饰器
def track_db_query(query_type, table):
    def decorator(func):
        def wrapper(*args, **kwargs):
            start_time = time.time()
            result = func(*args, **kwargs)
            duration = time.time() - start_time
            
            DB_QUERY_LATENCY.labels(
                query_type=query_type,
                table=table
            ).observe(duration)
            
            return result
        return wrapper
    return decorator

# 使用示例
@app.route('/api/orders')
@track_db_query('SELECT', 'orders')
def get_orders():
    # 业务逻辑
    orders = db.query("SELECT * FROM orders")
    return jsonify(orders)

# 启动系统指标收集线程
import threading
metrics_thread = threading.Thread(target=collect_system_metrics, daemon=True)
metrics_thread.start()
```

## 5. OpenTelemetry标准详解

### 5.1 OpenTelemetry架构

**核心组件**：
1. **API**：定义遥测数据的概念和接口
2. **SDK**：API的具体实现，包含采样、处理、导出
3. **Collector**：供应商无关的代理，接收、处理和导出遥测数据
4. **Instrumentation Libraries**：自动/手动插桩库

**三大信号类型**：
- **Traces**：分布式追踪
- **Metrics**：指标
- **Logs**：日志

### 5.3 Context Propagation详解

```python
# W3C Trace Context传播示例
from opentelemetry import propagate
from opentelemetry.propagators import textmap
from opentelemetry.trace.propagation.tracecontext import TraceContextTextMapPropagator

# 设置传播器
propagate.set_global_textmap(TraceContextTextMapPropagator())

# 在HTTP客户端中注入Context
def make_request_with_context(url, data):
    headers = {}
    # 将当前Context注入到HTTP头
    propagate.inject(headers)
    
    response = requests.post(url, json=data, headers=headers)
    return response

# 在HTTP服务端提取Context
@app.before_request
def extract_context():
    # 从HTTP头中提取Context
    ctx = propagate.extract(carrier=dict(request.headers))
    
    # 将提取的Context设置为当前上下文
    from opentelemetry.context import attach
    attach(ctx)
```
