# 数据分片与热点处理

> 📌 **导航**：本文是 **数据分片与热点处理** 词条，属于 architecture 术语集。相关枢纽：[[系统设计]]、[[读写分离]]、[[缓存策略]]、[[限流]]、[[分布式 ID]]。

## 定义

**一句话定义：** 数据分片是把大数据集切散到多个存储节点以突破单机容量与吞吐上限的手法（水平按行切、垂直按列切）；热点处理则针对"极少数 key 吃掉大部分流量"的分布不均问题，用本地缓存、探测、二次拆分与只读副本把这股压力摊开。

**通俗类比：** 分影像图书馆设分馆藏书，单馆放不下就按区号分；热点像春运售票，光多加窗口不够，还得把热门车次的请求分片、并在入口先放本地缓存的余票信息。

## 为什么需要它

单机数据库的存储与连接数有硬上限，数据量与并发涨到一定规模只能水平拆。但拆完只是解决了"放得下"，没解决"分不均"：按用户 ID 取模能让行数均匀，却挡不住某个明星、某个爆款商品的瞬时集中访问——少数 key 可能占掉一半流量，把单个分片打到极限，其余分片闲着。所以两者必须一起设计：**分片决定数据放在哪，热点处理决定请求怎么不打爆那一片**，配套还要有 [[分布式 ID]] 生成与跨片查询的代价预算。

## 核心机制

- **水平分片**按行切（`user_id % 4`），解容量与并发；分片键要选**查询最常带的条件**，否则大量查询要扫全片（scatter-gather）。
- **垂直分片**按列/按业务拆库（订单基本信息、明细、物流各一库），解表过宽与冷热混杂，代价是跨库 join 与事务变复杂。
- **扩容与再平衡**：取模分片加机器要迁移近乎全部数据，实务上用一致性哈希或成倍扩容（4→8 只迁一半）来收敛搬迁量。
- **热点治理四招**：① 多级缓存（本地 Caffeine 挡在最前，再到 Redis，最后落库）；② 热点探测（实时统计 key 频次，自动降级进本地缓存）；③ 热点拆分（把 `user_1001` 拆成 `user_1001_0..7`，读时聚合、写时随机路由）；④ 读写分离把读压散到只读副本。

| 手段 | 解决什么 | 主要代价 |
|---|---|---|
| 水平分片 | 单机容量与并发上限 | 跨片查询、分布式事务、扩容迁移 |
| 垂直分片 | 表过宽、冷热混杂 | 跨库 join、服务边界耦合 |
| 本地缓存挡热点 | 单 key 读压 | 与远端缓存的一致性、内存占用 |
| 热点 key 拆分 | 单分片被打满 | 读写路径复杂、聚合成本 |

## 具体示例

热点读的典型链路，逐层兜住同一把钥匙：

```text
请求 -> 本地缓存(Caffeine, 1s TTL) -> Redis -> 只读副本 -> 主库
             ^                              |
             +---- 热点探测: 频次超阈值 -> 动态提升到本地缓存
```

写侧则把热点 key 拆成 N 份（`item_8848_0..7`）随机落库以摊开行锁与 IO，读时聚合 N 份结果——**拆分是把一次冲突换成 N 次无冲突，代价由读聚合承担**。

## 何时用与何时不用

- **用**：单表数据量或写入吞吐逼近单机上限、连接数打满、存储成本失衡 → 分片；监控发现少数 key 贡献大头流量、单分片 CPU/连接/带宽显著高于同群 → 热点处理。
- **先试更便宜的**：读写比高而容量未爆，先 [[读写分离]] + [[缓存策略]]；索引与 SQL 优化常能顶住很久再动分片。
- **不用**：数据量小却分片，是把一次运维成本换成永久的跨片查询与事务复杂度；热点未出现就预置拆分逻辑，属于为不存在的问题付费。

## 优劣与代价

✅ 突破单机存储与吞吐上限，让容量随节点数近似线性扩展。
✅ 多级缓存加热点拆分能把突发流量的破坏力限制在单点之外。
⚠️ 跨分片聚合、分布式事务与扩容迁移是长期成本，分片键一旦选错很难改。
⚠️ 本地缓存与热点探测引入不一致窗口，需按业务容忍度设定 TTL 与降级策略。

## 与相关概念的区别

- **分片 vs [[读写分离]]**：分片解决"一台机器存不下、写不动"，读写分离解决"读压过大与主库被拖慢"；两者常叠加使用。
- **水平 vs 垂直分片**：按行切解决数据量，按列切解决表宽度与冷热混杂。
- **热点处理 vs 一般缓存**：缓存优化整体平均性能，热点处理专治分布不均的极端值。
- **分片键 vs [[分布式 ID]]**：ID 决定记录能否均匀散布，业务查询条件决定读起来要不要扫全片，两者常要折中。

## 常见误区

- 只要按主键取模分片，就天然能保证读写压力均匀。
- 分片数量越多系统越好，扩节点永远是正收益。
- 出现热点流量时，把缓存过期时间调长就足以解决问题。

## 面试速答

> 🎯 分片按行（水平）或按列（垂直）切开突破单机上限，分片键要贴最常查的条件否则退化为扫全片；热点用多级缓存、频次探测、热点 key 拆分与只读副本摊开，代价是跨片查询、分布式事务与一致性窗口。
