# 微服务架构


> 📌 **导航**：本文是 **微服务架构** 词条，属于 architecture 术语集。相关枢纽：[[SaaS产品技术架构]]、[[事件驱动架构]]、[[云原生与多云架构实战指南]]、[[分布式系统设计完全指南]]、[[微服务架构]]。

## 核心原则

- 单一职责：每个服务只负责一个业务领域
- 独立部署：服务可独立发布
- 去中心化治理：各服务可选不同技术栈
- 容错设计：单个服务故障不应级联

## 服务拆分

| 维度 | 说明 |
|------|------|
| 按业务域 | 用户服务、订单服务、支付服务 |
| 按变更频率 | 稳定的核心服务 vs 频繁迭代的前台服务 |
| 按团队 | 一个团队负责一组服务 |

## 服务发现

| 方案 | 原理 | 代表 |
|------|------|------|
| 客户端发现 | 客户端查注册中心 | Eureka |
| 服务端发现 | 负载均衡器查注册中心 | Consul + Nginx |
| DNS发现 | DNS轮询 | K8s Service |

## API网关

```
客户端 -> API网关(认证/限流/路由/聚合) -> 微服务集群
```

功能：认证鉴权、限流熔断、请求路由、协议转换、日志监控。

## 熔断器模式

```
关闭 -> (失败率超阈值) -> 打开 -> (超时后) -> 半开 -> (成功) -> 关闭
                          -> (失败) -> 打开
```

代表：Hystrix(已停维护)、Resilience4j、Sentinel。

## Saga事务

```
T1(下单) -> T2(扣库存) -> T3(扣款)
  成功        成功         失败!
  <- C1(取消订单) <- C2(恢复库存)  补偿操作
```

两种实现：
- 编排(Orchestration)：中央协调器
- 协同(Choreography)：事件驱动，无中心
