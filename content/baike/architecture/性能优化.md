# 性能优化

## 1. 缓存（本地缓存/分布式缓存）

**一句话定义：** 将频繁访问的数据存储在高速存储介质中，减少重复计算或查询。

**通俗类比：** 像你把常用工具放在办公桌上，而不是每次都去仓库取。

**具体示例：**
```java
// 本地缓存 - Caffeine
Cache<String, User> cache = Caffeine.newBuilder()
    .maximumSize(1000)
    .expireAfterWrite(Duration.ofMinutes(5))
    .build();

// 分布式缓存 - Redis
redisTemplate.opsForValue().set("user:1001", user, 5, TimeUnit.MINUTES);
```

**为什么需要它：** 减少数据库压力，提升响应速度，典型场景可将响应时间从毫秒级降到微秒级。

**本地缓存 vs 分布式缓存：** 本地缓存速度快但容量有限且不跨实例，分布式缓存可跨实例共享但有网络开销。

---

## 2. CDN（内容分发网络）

**一句话定义：** 在全球部署边缘节点，将内容缓存到离用户最近的节点加速访问。

**通俗类比：** 像连锁超市，每个社区都有分店，你不用跑总部买东西。

**具体示例：**
```
用户(北京) --> CDN节点(北京) --命中--> 直接返回
                          --未命中--> 回源服务器(上海)
```

**为什么需要它：** 减少网络延迟，降低源站压力，提升全球用户的访问体验。

**与缓存对比：** CDN是地理位置分散的缓存，专注于静态内容分发；普通缓存是应用层的加速手段。

---

## 3. 负载均衡（轮询/加权/最少连接/IP Hash）

**一句话定义：** 将用户请求分发到多台服务器，避免单台服务器过载。

**通俗类比：** 像银行叫号系统，把客户分配到不同的柜台办理业务。

**具体示例：**
```nginx
# Nginx 负载均衡配置
upstream backend {
    # 轮询（默认）
    server 192.168.1.1 weight=3;  # 加权轮询
    server 192.168.1.2 weight=1;
    server 192.168.1.3 backup;    # 备用服务器
    # ip_hash;  # IP哈希，同一IP固定到同一服务器
}
```

**为什么需要它：** 提高系统可用性和并发处理能力，避免单点故障。

**四种策略对比：** 轮询适合服务器性能相同场景，加权适合性能不同，最少连接适合长连接场景，IP Hash适合会话保持。

---

## 4. 连接池

**一句话定义：** 预先创建一批可复用的连接对象，避免频繁创建销毁的开销。

**通俗类比：** 像公司班车，固定几辆车来回接送，而不是每次出行都租车。

**具体示例：**
```java
// 数据库连接池配置
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/mydb");
config.setMaximumPoolSize(20);
config.setMinimumIdle(5);
config.setConnectionTimeout(30000);
```

**为什么需要它：** 数据库连接创建代价高昂，连接池可复用连接，显著提升性能。

**与线程池对比：** 连接池管理数据库/网络连接，线程池管理执行任务的线程，两者常配合使用。

---

## 5. 异步处理

**一句话定义：** 将耗时操作放到后台执行，主流程不等待结果继续运行。

**通俗类比：** 像餐厅点餐，下单后去等位，厨师做好会叫号，你不用一直站在窗口等。

**具体示例：**
```java
// Spring 异步处理
@Async
public CompletableFuture<Order> createOrder(OrderDTO dto) {
    // 耗时的订单处理逻辑
    return CompletableFuture.completedFuture(order);
}
// 调用方不阻塞，立即返回
```

**为什么需要它：** 提升用户体验和系统吞吐量，避免长等待阻塞主线程。

**与同步对比：** 同步是顺序执行等待结果，异步是发出任务后继续其他工作，通过回调或通知获取结果。

---

## 6. 限流（令牌桶/漏桶/滑动窗口）

**一句话定义：** 控制单位时间内的请求处理数量，防止系统被突发流量压垮。

**通俗类比：** 像高速公路收费站，同时只能通过有限数量的车辆，多余的要排队。

**具体示例：**
```java
// 令牌桶算法示例
RateLimiter rateLimiter = RateLimiter.create(100); // 每秒100个请求
if (rateLimiter.tryAcquire()) {
    // 处理请求
} else {
    // 返回限流响应
}
```

**为什么需要它：** 保护系统稳定性，防止雪崩效应，保证服务质量。

**三种算法对比：** 令牌桶允许突发流量，漏桶严格匀速处理，滑动窗口统计精确但实现复杂。

---

## 7. 熔断器模式（Circuit Breaker）

**一句话定义：** 当下游服务故障时自动断开连接，避免级联失败，定期尝试恢复。

**通俗类比：** 像家里的保险丝，电流过大时自动断开，保护电器不被烧毁。

**具体示例：**
```java
// Resilience4j 熔断器
CircuitBreakerConfig config = CircuitBreakerConfig.custom()
    .failureRateThreshold(50)      // 失败率超过50%触发熔断
    .waitDurationInOpenState(Duration.ofSeconds(10))
    .build();

CircuitBreaker breaker = CircuitBreaker.of("userService", config);
```

**为什么需要它：** 防止一个服务故障拖垮整个系统，提供快速失败和自动恢复机制。

**与限流对比：** 限流控制正常请求的速率，熔断是当下游已经故障时的保护措施。

---

## 8. 降级策略

**一句话定义：** 系统压力过大时，主动关闭非核心功能，保证核心服务可用。

**通俗类比：** 像商场停电时，只保留应急照明和收银，关闭空调、装饰灯等。

**具体示例：**
```java
// 降级示例
try {
    return callExternalService(); // 调用外部服务
} catch (Exception e) {
    return getDefaultValue();     // 降级：返回默认值或缓存数据
}
```

**为什么需要它：** 在资源有限时优先保障核心业务，避免系统全面崩溃。

**与熔断对比：** 熔断是自动检测故障断开连接，降级是主动选择牺牲部分功能。

---

## 9. 预加载

**一句话定义：** 在用户需要之前提前加载可能用到的数据或资源。

**通俗类比：** 像你出门前把钥匙、手机、钱包提前放好，不用临时找。

**具体示例：**
```html
<!-- 预加载关键资源 -->
<link rel="preload" href="hero-image.jpg" as="image">
<link rel="preload" href="main.css" as="style">
```

**为什么需要它：** 减少用户等待时间，提升首次访问体验。

**与懒加载对比：** 预加载提前加载可能需要的资源，懒加载延迟加载暂时不用的资源。

---

## 10. 懒加载

**一句话定义：** 只在真正需要时才加载资源，避免一次性加载所有内容。

**通俗类比：** 像图书馆按需借书，不用把所有书都搬回家。

**具体示例：**
```javascript
// 图片懒加载
<img data-src="product.jpg" class="lazyload" />

// Vue 路由懒加载
const routes = [
  { path: '/dashboard', component: () => import('./Dashboard.vue') }
];
```

**为什么需要它：** 减少初始加载体积，提升页面加载速度，节省带宽。

**与预加载对比：** 懒加载延迟到使用时加载，预加载提前加载，适用场景相反。

---

## 11. 数据库连接池

**一句话定义：** 管理数据库连接的生命周期，实现连接的复用和控制。

**通俗类比：** 像酒店前台管理房间钥匙，入住时分配，退房后回收再分配给下一位客人。

**具体示例：**
```yaml
# HikariCP 配置
spring:
  datasource:
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      idle-timeout: 300000
      max-lifetime: 1800000
```

**为什么需要它：** 数据库连接创建销毁代价高，连接池通过复用降低开销。

**与普通连接池对比：** 这是连接池的一种特化，专门管理数据库连接，需考虑事务、超时等数据库特性。

---

## 12. 线程池

**一句话定义：** 预先创建一组线程来执行任务，避免频繁创建销毁线程的开销。

**通俗类比：** 像工厂的工人团队，固定编制，有活就干，没活就休息。

**具体示例：**
```java
// 线程池配置
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    5,                      // 核心线程数
    10,                     // 最大线程数
    60L, TimeUnit.SECONDS,  // 空闲线程存活时间
    new LinkedBlockingQueue<>(100)  // 任务队列
);
```

**为什么需要它：** 线程创建开销大，线程池通过复用线程提高性能和资源利用率。

**与连接池对比：** 线程池管理CPU执行资源，连接池管理IO连接资源，两者常配合使用。
