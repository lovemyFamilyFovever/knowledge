## 1. 数据仓库架构

### 1.1 Kimball vs Inmon 方法论

**Kimball 方法（自底向上）**：
- **核心思想**：从业务部门需求出发，构建面向主题的数据集市，再逐步整合为企业数据仓库
- **优势**：交付周期短、投资回报快、业务导向明确
- **劣势**：需要精心设计总线架构以保证一致性

```sql
-- Kimball维度建模示例：零售业订单事实表
CREATE TABLE fact_sales (
    order_key       BIGINT PRIMARY KEY,
    date_key        INT REFERENCES dim_date(date_key),
    product_key     INT REFERENCES dim_product(product_key),
    customer_key    INT REFERENCES dim_customer(customer_key),
    store_key       INT REFERENCES dim_store(store_key),
    order_id        VARCHAR(50),
    quantity        INT,
    unit_price      DECIMAL(10,2),
    discount_amount DECIMAL(10,2),
    total_amount    DECIMAL(10,2),
    etl_load_date   TIMESTAMP
);
```

**Inmon 方法（自顶向下）**：
- **核心思想**：先构建企业级规范化数据仓库（3NF），再从中央仓库衍生出部门数据集市
- **优势**：数据高度整合、避免冗余、长期维护成本低
- **劣势**：前期投入大、建设周期长

```sql
-- Inmon规范化模型示例
CREATE TABLE orders (
    order_id        BIGINT PRIMARY KEY,
    customer_id     BIGINT REFERENCES customers(customer_id),
    order_date      DATE,
    ship_date       DATE,
    order_status    VARCHAR(20)
);

CREATE TABLE order_items (
    item_id         BIGINT PRIMARY KEY,
    order_id        BIGINT REFERENCES orders(order_id),
    product_id      BIGINT REFERENCES products(product_id),
    quantity        SMALLINT,
    unit_price      DECIMAL(10,2)
);
```

### 1.2 维度建模详解

维度建模是Kimball方法论的核心，包含四个关键步骤：

**步骤1：选择业务过程**
```sql
-- 电商核心业务过程识别
1. 订单创建
2. 订单支付
3. 订单发货
4. 用户注册
5. 商品浏览
```

**步骤2：声明粒度**
```sql
-- 订单事实表的粒度选择
原子粒度：每行代表一个订单中的单个商品项
推荐粒度：订单商品项级别（最细粒度）

-- 粒度决定语句示例
"本事实表中的每一行代表一个客户在特定日期通过特定渠道购买的单个商品"
```

**步骤3：识别维度**
```sql
-- 电商常见维度
1. 时间维度：date_key, year, quarter, month, week, day
2. 商品维度：product_key, product_name, category, brand, supplier
3. 客户维度：customer_key, customer_name, gender, age_group, city
4. 渠道维度：channel_key, channel_name (Web/Mobile/App/Offline)
5. 促销维度：promotion_key, promotion_name, discount_type
```

**步骤4：确定事实**
```sql
-- 事实类型分类
1. 可加事实：quantity, revenue, cost（可跨所有维度累加）
2. 半可加事实：account_balance（只能在部分维度累加）
3. 不可加事实：temperature, ratio（通常作为计算得出的衍生事实）
```

### 1.3 星型模型 vs 雪花模型

**星型模型（Star Schema）**：
```sql
-- 典型的星型结构
维度表直接关联事实表，没有中间层
维度表可能是反规范化的（包含冗余数据）

-- 客户维度表（星型）
CREATE TABLE dim_customer (
    customer_key     INT PRIMARY KEY,
    customer_id      VARCHAR(20),
    customer_name    VARCHAR(100),
    gender           VARCHAR(10),
    birth_date       DATE,
    city             VARCHAR(50),
    state            VARCHAR(50),
    country          VARCHAR(50),
    registration_date DATE
);
```

**雪花模型（Snowflake Schema）**：
```sql
-- 维度表进一步规范化
维度表被拆分为多个相关表

-- 雪花化客户维度
CREATE TABLE dim_customer (
    customer_key     INT PRIMARY KEY,
    customer_id      VARCHAR(20),
    customer_name    VARCHAR(100),
    location_key     INT REFERENCES dim_location(location_key),
    registration_date DATE
);

CREATE TABLE dim_location (
    location_key     INT PRIMARY KEY,
    city             VARCHAR(50),
    state_key        INT REFERENCES dim_state(state_key)
);

CREATE TABLE dim_state (
    state_key        INT PRIMARY KEY,
    state_name       VARCHAR(50),
    country_key      INT REFERENCES dim_country(country_key)
);
```

**选型建议**：
- 星型模型：查询性能好，更易理解，适合OLAP
- 雪花模型：节省存储，更新维护更简单，适合OLTP
- 现代数据仓库：通常推荐星型模型，利用列式存储优化

## 2. ETL vs ELT

### 2.1 传统ETL流程

```python
# 传统ETL流程示例（使用Python + Pandas）
import pandas as pd
from sqlalchemy import create_engine

def extract():
    """从源系统抽取数据"""
    source_conn = create_engine('postgresql://user:pass@source-db/orders')
    query = """
        SELECT order_id, customer_id, order_date, total_amount
        FROM orders 
        WHERE order_date >= '2023-01-01'
    """
    return pd.read_sql(query, source_conn)

def transform(df):
    """数据清洗和转换"""
    # 1. 处理缺失值
    df = df.dropna(subset=['customer_id'])
    
    # 2. 数据类型转换
    df['order_date'] = pd.to_datetime(df['order_date'])
    
    # 3. 衍生字段计算
    df['year'] = df['order_date'].dt.year
    df['month'] = df['order_date'].dt.month
    
    # 4. 数据标准化
    df['total_amount'] = df['total_amount'].abs()
    
    # 5. 业务规则应用
    df['is_large_order'] = df['total_amount'] > 1000
    
    return df

def load(df, target_table):
    """加载到数据仓库"""
    target_conn = create_engine('postgresql://user:pass@dw-server/datawarehouse')
    
    # 使用pandas的to_sql加载
    df.to_sql(
        name=target_table,
        con=target_conn,
        if_exists='append',  # 追加模式
        index=False,
        method='multi'  # 批量插入提高性能
    )

# 执行ETL
raw_data = extract()
transformed_data = transform(raw_data)
load(transformed_data, 'fact_orders')
```

### 2.3 ETL vs ELT 对比分析

| **维度** | **ETL** | **ELT** |
|---------|---------|---------|
| **数据处理位置** | 专用ETL服务器 | 数据仓库内部 |
| **可扩展性** | 受限于ETL服务器 | 利用数据仓库计算能力 |
| **数据量支持** | 中小规模数据 | 大规模数据（PB级） |
| **转换灵活性** | 复杂转换易实现 | 依赖SQL能力 |
| **实时性** | 批处理为主 | 支持准实时更新 |
| **工具生态** | Informatica, Talend, SSIS | dbt, Dataform, SQL |
| **适用架构** | 传统数据仓库 | 云数据仓库、数据湖 |

## 4. 流处理技术

### 4.1 Apache Flink 核心概念

```java
// Flink流处理示例（Java）
public class StreamingJob {
    public static void main(String[] args) throws Exception {
        // 1. 创建流执行环境
        StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
        env.setParallelism(4);
        
        // 2. 创建Kafka数据源
        KafkaSource<String> source = KafkaSource.<String>builder()
            .setBootstrapServers("kafka-broker:9092")
            .setTopics("user-events")
            .setGroupId("flink-consumer")
            .setValueOnlyDeserializer(new SimpleStringSchema())
            .build();
        
        DataStream<String> eventStream = env.fromSource(
            source, 
            WatermarkStrategy.noWatermarks(), 
            "Kafka Source"
        );
        
        // 3. 处理流数据
        DataStream<UserEvent> processedStream = eventStream
            .map(new EventParser())  // 解析事件
            .filter(event -> event.getUserId() != null)  // 过滤无效事件
            .keyBy(UserEvent::getUserId)  // 按用户ID分区
            .window(TumblingProcessingTimeWindows.of(Time.minutes(5)))  // 5分钟滚动窗口
            .aggregate(new UserSessionAggregator());  // 会话聚合
        
        // 4. 输出结果
        processedStream.addSink(new RedisSink<>(redisConfig, new UserEventRedisMapper()));
        
        // 5. 启动作业
        env.execute("User Session Analysis");
    }
}

// 自定义聚合函数
public class UserSessionAggregator implements AggregateFunction<UserEvent, UserSession, UserSession> {
    @Override
    public UserSession createAccumulator() {
        return new UserSession();
    }

    @Override
    public UserSession add(UserEvent event, UserSession session) {
        session.setUserId(event.getUserId());
        session.setEventCount(session.getEventCount() + 1);
        session.setLastEventTime(event.getTimestamp());
        // ... 更新会话状态
        return session;
    }

    @Override
    public UserSession getResult(UserSession session) {
        return session;
    }

    @Override
    public UserSession merge(UserSession a, UserSession b) {
        // 合并两个会话
        a.setEventCount(a.getEventCount() + b.getEventCount());
        // ... 其他合并逻辑
        return a;
    }
}
```

### 4.2 Kafka Streams 应用

```java
// Kafka Streams示例：实时异常检测
public class AnomalyDetectionApp {
    public static void main(String[] args) {
        Properties config = new Properties();
        config.put(StreamsConfig.APPLICATION_ID_CONFIG, "anomaly-detection");
        config.put(StreamsConfig.BOOTSTRAP_SERVERS_CONFIG, "kafka:9092");
        
        StreamsBuilder builder = new StreamsBuilder();
        
        // 1. 从Kafka主题读取原始事件
        KStream<String, MetricEvent> metricsStream = builder.stream(
            "system-metrics",
            Consumed.with(Serdes.String(), new MetricEventSerde())
        );
        
        // 2. 计算滚动统计（5分钟窗口）
        KTable<Windowed<String>, MetricStats> statsTable = metricsStream
            .groupByKey()
            .windowedBy(TimeWindows.ofSizeWithNoGrace(Duration.ofMinutes(5)))
            .aggregate(
                MetricStats::new,
                (key, event, stats) -> stats.update(event),
                Materialized.<String, MetricStats, WindowStore<Bytes, byte[]>>as("stats-store")
                    .withValueSerde(new MetricStatsSerde())
            );
        
        // 3. 检测异常值
        KStream<String, AnomalyAlert> alertsStream = statsTable
            .toStream()
            .filter((windowedKey, stats) -> stats.isAnomalous())
            .mapValues((windowedKey, stats) -> new AnomalyAlert(
                windowedKey.key(),
                stats.getMetricName(),
                stats.getAvgValue(),
                stats.getStdDev()
            ));
        
        // 4. 发送告警到Kafka
        alertsStream.to(
            "anomaly-alerts",
            Produced.with(Serdes.String(), new AnomalyAlertSerde())
        );
        
        // 5. 启动流处理应用
        KafkaStreams streams = new KafkaStreams(builder.build(), config);
        streams.start();
        
        // 添加关闭钩子
        Runtime.getRuntime().addShutdownHook(new Thread(streams::close));
    }
}
```

### 4.3 Spark Structured Streaming

```python
# Spark Structured Streaming示例
from pyspark.sql import SparkSession
from pyspark.sql.functions import *
from pyspark.sql.types import *

# 初始化SparkSession
spark = SparkSession.builder \
    .appName("StructuredStreamingExample") \
    .config("spark.sql.streaming.checkpointLocation", "/checkpoint") \
    .getOrCreate()

# 定义Schema
schema = StructType([
    StructField("timestamp", TimestampType()),
    StructField("user_id", StringType()),
    StructField("action", StringType()),
    StructField("product_id", StringType()),
    StructField("amount", DoubleType())
])

# 从Kafka读取流数据
kafka_df = spark \
    .readStream \
    .format("kafka") \
    .option("kafka.bootstrap.servers", "kafka:9092") \
    .option("subscribe", "user-clicks") \
    .load()

# 解析JSON数据
parsed_df = kafka_df \
    .selectExpr("CAST(value AS STRING)") \
    .select(from_json(col("value"), schema).alias("data")) \
    .select("data.*")

# 窗口聚合：每5分钟统计用户行为
windowed_agg = parsed_df \
    .withWatermark("timestamp", "10 minutes") \
    .groupBy(
        window("timestamp", "5 minutes"),
        "user_id"
    ) \
    .agg(
        count("action").alias("event_count"),
        sum("amount").alias("total_amount"),
        countDistinct("product_id").alias("unique_products")
    )

# 输出到控制台（调试）
query = windowed_agg \
    .writeStream \
    .outputMode("update") \
    .format("console") \
    .option("truncate", "false") \
    .start()

# 输出到HDFS（生产）
hdfs_query = windowed_agg \
    .writeStream \
    .outputMode("append") \
    .format("parquet") \
    .option("path", "/data/processed/user_sessions") \
    .option("checkpointLocation", "/checkpoint/sessions") \
    .trigger(processingTime="1 minute") \
    .start()

# 等待终止
spark.streams.awaitAnyTermination()
```

## 5. 批处理技术

### 5.1 Apache Spark 优化实践

```python
# Spark优化示例：电商数据分析
from pyspark.sql import SparkSession
from pyspark.sql.functions import *
from pyspark.sql.types import *

# 配置优化
spark = SparkSession.builder \
    .appName("EcommerceAnalysis") \
    .config("spark.sql.adaptive.enabled", "true") \
    .config("spark.sql.adaptive.coalescePartitions.enabled", "true") \
    .config("spark.sql.shuffle.partitions", "200") \
    .config("spark.sql.files.maxPartitionBytes", "134217728") \
    .config("spark.serializer", "org.apache.spark.serializer.KryoSerializer") \
    .getOrCreate()

# 1. 数据读取优化
orders_df = spark.read \
    .format("parquet") \
    .option("mergeSchema", "true") \
    .load("/data/warehouse/orders") \
    .repartition(100, "order_date")  # 按日期重分区

customers_df = spark.read \
    .format("delta") \
    .load("/data/warehouse/customers")

# 2. 广播小表优化（Broadcast Join）
# 假设products表较小
products_df = spark.read.format("parquet").load("/data/warehouse/products")
enriched_orders = orders_df \
    .join(broadcast(products_df), "product_id")  # 广播连接

# 3. 缓存常用数据集
customer_segments_df = customers_df \
    .filter(col("customer_status") == "active") \
    .select("customer_id", "customer_segment", "region") \
    .cache()  # 缓存到内存

# 4. 复杂分析查询
result_df = enriched_orders \
    .join(customer_segments_df, "customer_id") \
    .groupBy(
        "order_year",
        "order_month",
        "customer_segment",
        "region"
    ) \
    .agg(
        countDistinct("order_id").alias("order_count"),
        sum("total_amount").alias("total_revenue"),
        avg("total_amount").alias("avg_order_value"),
        countDistinct("customer_id").alias("customer_count")
    ) \
    .withColumn("revenue_per_customer", 
                col("total_revenue") / col("customer_count")) \
    .orderBy("order_year", "order_month", desc("total_revenue"))

# 5. 输出优化（分区写入）
result_df \
    .repartition("order_year", "order_month") \
    .write \
    .partitionBy("order_year", "order_month") \
    .format("parquet") \
    .mode("overwrite") \
    .option("compression", "snappy") \
    .save("/data/analytics/monthly_report")
```

-- hive.properties
connector.name=hive-hadoop2
hive.metastore.uri=thrift://hive-metastore:9083

connection-user=admin
connection-password=password

-- kafka.properties
connector.name=kafka
kafka.nodes=kafka:9092

-- 2. 跨数据源联合查询
WITH customer_orders AS (
    -- 来自Hive数据仓库
    SELECT 
        customer_id,
        COUNT(*) as order_count,
        SUM(total_amount) as total_spend
    FROM hive.ecommerce.orders
    WHERE order_date >= DATE '2023-01-01'
    GROUP BY customer_id
),
customer_details AS (
    -- 来自MySQL业务数据库
    SELECT 
        customer_id,
        customer_name,
        email,
        signup_date
    FROM mysql.ecommerce.customers
    WHERE signup_date >= DATE '2020-01-01'
),
real_time_events AS (
    -- 来自Kafka实时流
    SELECT 
        user_id as customer_id,
        COUNT(*) as recent_events
    FROM kafka.ecommerce.user_events
    WHERE event_time > CURRENT_TIMESTAMP - INTERVAL '1' HOUR
    GROUP BY user_id
)
-- 联合查询
SELECT 
    cd.customer_name,
    cd.email,
    co.order_count,
    co.total_spend,
    COALESCE(re.recent_events, 0) as recent_activity,
    CASE 
        WHEN co.total_spend > 1000 THEN 'Premium'
        WHEN co.total_spend > 500 THEN 'Regular'
        ELSE 'Casual'
    END as customer_tier
FROM customer_details cd
LEFT JOIN customer_orders co ON cd.customer_id = co.customer_id
LEFT JOIN real_time_events re ON cd.customer_id = re.customer_id
WHERE co.order_count > 0
ORDER BY co.total_spend DESC
LIMIT 100;

-- 3. 性能优化技巧
-- 使用近似计算
SELECT 
    APPROX_DISTINCT(customer_id) as unique_customers,
    APPROX_PERCENTILE(total_amount, 0.95) as p95_order_value
FROM hive.ecommerce.orders;

-- 使用物化视图加速查询
CREATE MATERIALIZED VIEW monthly_summary AS
SELECT 
    DATE_TRUNC('month', order_date) as month,
    product_category,
    SUM(total_amount) as revenue,
    COUNT(*) as order_count
FROM hive.ecommerce.orders
GROUP BY 1, 2;
