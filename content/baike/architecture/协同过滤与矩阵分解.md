# 协同过滤与矩阵分解

> 📌 **导航**：本文是 **协同过滤与矩阵分解** 词条，属于 architecture 术语集。相关枢纽：[[推荐系统设计与实现]]、[[推荐系统]]、[[K近邻算法]]、[[机器学习基础]]。

## 定义

**一句话定义：** 协同过滤不读物品内容、只用行为共现——UserCF 推"和你相似的用户喜欢的"，ItemCF 推"和你喜欢的物品被同一批人一起消费过的"；矩阵分解把稀疏的用户-物品评分矩阵写成两张低维隐因子表的乘积 R ≈ U × Vᵀ，用内积补全没观测到的格子，是今天一切 embedding 召回的算法原型。

**通俗类比：** 老店员记不清每本书写了什么，但记得"买 A 的人也常买 B"，于是靠顾客重合度荐书。

## 为什么需要它

内容理解昂贵且滞后：视频、商品、音乐的多媒体特征提取本身就是一个大工程。行为共现提供了一条捷径——只要有点击与购买日志，不需要"读懂"任何物品就能给出"看了这个的人还看了"。而共现矩阵极度稀疏（Netflix 数据集 99.8% 为空），逐格存相似度既存不下也算不完，于是需要矩阵分解把稀疏行压成几十维稠密向量：相似度变成两个向量的内积，可离线预算、可进向量库做近邻检索（工程侧见 [[多路召回与双塔模型]]）。

## 核心机制

**UserCF 四步**：构建用户-物品评分矩阵 → 算用户两两相似度 → 取最相似的 K 个用户 → 把相似用户喜欢而目标用户未接触的物品推给他。相似度用余弦或皮尔逊：皮尔逊先按各自均值中心化，能吸收"有人习惯打高分、有人习惯打低分"的评分尺度差异，代价是共现物品太少时不稳。

**ItemCF 三步**：算物品之间的相似度 → 按用户历史行为取最相似物品 → 对候选评分预测。工业上 ItemCF 常优于 UserCF，因为物品之间的相似度相对稳定，而用户兴趣随时间漂移、活跃用户还会把不相干的人连成一片。原稿的电影案例就是共现直觉：A 与 B 共有《肖申克的救赎》、A 与 C 共有《阿甘正传》，于是 B 喜欢的《泰坦尼克号》被推给 A。

**相似度式子与 IUF 修正**：ItemCF 的经典式是 sim(i,j) = |同时喜欢 i 和 j 的人数| / √(|喜欢 i 的人| × |喜欢 j 的人|)，分子是共现计数、分母是流行度归一。IUF（Inverse User Frequency）再把活跃用户的共现贡献压低：分子改为对共同用户求 Σ user_activity(u)，用户越活跃该值越小，从而抑制"什么都看"的人把热门物品连成万能相似。

**矩阵分解的四个变体**：SGD 逐格拟合观测评分，误差 error = rating − pred，同时更新用户/物品偏置与隐因子，并带 L2 正则（原稿取 n_factors=50、lr=0.01、reg=0.02、20 epoch，按 RMSE 观察收敛）。

| 变体 | 处理稀疏 | 加了什么 |
|---|---|---|
| SVD | 不适用（要求完整矩阵） | 标准奇异值分解 |
| FunkSVD | 是，只对有评分的位置算损失 | 跳过空格子 |
| BiasSVD | 是 | 用户偏置 + 物品偏置 + 全局偏置 |
| SVD++ | 是 | 把隐式反馈（点击/浏览）并入隐因子 |

## 具体示例

预测一个格子只要三步：pred = 全局均值 + 用户偏置 + 物品偏置 + P[u] · Q[i]ᵀ。给同一用户出 Top-N 时不必逐格算：把他的隐因子向量与整张物品隐因子矩阵做一次矩阵乘（再加上偏置项），按分数取前 N 并排除已交互物品——这一步在真实系统里就是向量近邻检索，物品隐因子表可直接喂进 FAISS 一类的向量索引（[[向量数据库技术]]）。

## 何时用与何时不用

- **用**：有可观的行为日志、物品内容难解析或同质（短视频、电商 SKU）、需要"意外发现"式的探索性推荐。
- **不用**：冷启动期与长尾新物品（零共现即零分数）；兴趣漂移极快、需要按内容语义解释推荐时；稀疏到共同邻居常为空（改上矩阵分解或内容特征）。
- **别忘**：共现相似会被热门偏置带偏，流行度归一与活跃度惩罚不是可选装饰；行为数据口径一变，隐因子表即作废。

## 优劣与代价

✅ 零内容理解成本，有日志即可上线，是最快的推荐冷方案。
✅ 隐因子向量体积小、可离线预算，天然对接向量检索与线上低延迟服务。
⚠️ 冷启动与稀疏是硬伤：新物品、新用户、极稀疏类别都算不出相似。
⚠️ 可解释性只到"买过 X 的人也买 Y"，说不清语义原因；隐因子缺人类可读语义，兴趣漂移只能靠周期性重训追。

## 与相关概念的区别

- **vs [[基于内容推荐与混合策略]]**：那侧比较物品的内容特征，这侧比较用户的行为重合；两者对冷启动的短板正好互补。
- **vs [[K近邻算法]]**：协同过滤本质是在共现空间里做 KNN 检索，这里 K 指邻居数而非分类的 K。
- **vs 深度学习排序模型**（[[深度推荐模型]]）：矩阵分解只做隐因子内积，不建模特征交叉与行为序列，通常落在召回或粗排层。

## 常见误区

- 协同过滤要先能理解物品的内容特征，才能算出物品之间的相似度。
- ItemCF 与 UserCF 只是算法实现细节不同，效果与稳定性没有实际差别。
- 矩阵分解必须用标准 SVD 对整个评分矩阵做分解，稀疏矩阵没法处理。

## 面试速答

> 🎯 协同过滤=只用行为共现做推荐：UserCF 找相似用户、ItemCF 找相似物品（工业更稳，因为物品相似更稳定），经典式是共现人数除以两者用户数开方；IUF 降权活跃用户；矩阵分解 R≈U×Vᵀ 把稀疏共现压成隐因子内积，四变体 SVD/FunkSVD/BiasSVD/SVD++；短板是冷启动与稀疏。
