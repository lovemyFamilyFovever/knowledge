# 命令行效率工具

> 📌 **导航**：本文是 **命令行效率工具** 词条，属 [[开发者效率工具大全]] 子词条。

## 定义

**一句话定义：** 命令行效率工具指一批以 Rust 等重写、比传统 Unix 工具更快更好用的替代品——fzf 模糊查找、ripgrep 代码搜索、fd 文件查找、bat 带高亮的 cat、jq 处理 JSON。

**通俗类比：** 像把老式算盘换成计算器：干的是同一件事（找、搜、看、算），但默认更快、更省心、还尊重你项目里的 `.gitignore`。

## 为什么需要它

`find`/`grep`/`cat` 功能强但慢、参数反直觉、还会一头扎进 `node_modules` 和二进制文件。新一代工具针对开发者日常重写了默认行为：并行搜索、智能忽略、彩色输出、模糊匹配，把"在终端里检索、查看、加工数据"的体验拉满。

## 核心能力

| 工具 | 替代 | 强项 |
|---|---|---|
| fzf | 手动翻找 | 任意列表的实时模糊过滤，可绑 Ctrl-R/Ctrl-T |
| ripgrep (rg) | grep | 极快、默认递归+忽略 .gitignore/二进制、类型过滤 |
| fd | find | 语法直观、默认忽略无关文件、可 `-x` 执行 |
| bat | cat | 语法高亮、行号、Git 改动标记、自动分页 |
| jq | （无） | 命令行解析/查询/改写 JSON |

共同点：默认尊重 `.gitignore`、对开发者常用场景开箱友好，可与管道自由组合。

## 具体示例

真正提升效率的是把它们串进管道：

```bash
rg -t js "TODO"                 # 只搜 js 文件里的 TODO
fd -e tmp . | xargs rm          # fd 找临时文件批量删除
vim $(fzf)                      # fzf 模糊选一个文件再打开
echo '{"age":30}' | jq '.age = 31'   # jq 就地改写 JSON
```

## 何时用与何时不用

- **用**：本地代码检索、按类型/名称批量找文件、查看带高亮的文件、在 shell 里处理 API 返回的 JSON。
- **不用（谨慎）**：脚本要跨机器通用、目标环境未必装了这些新工具时，回退到标准 `find`/`grep`/`sed` 更可移植。

## 优劣与代价

✅ 更快（并行）、更省心（默认忽略噪声）、更直观的参数。
✅ fzf 的交互模糊查找极大提升人机协作检索效率。
⚠️ 属额外依赖，非默认安装；自动化脚本引入会降低可移植性。
⚠️ 高级用法仍需查文档（如 fzf 脚本、rg 配置）。

## 与相关概念的区别

- **ripgrep vs grep**：grep 是逐行匹配的基础工具；rg 默认递归、跳过 .gitignore/隐藏/二进制、多线程，快且开箱友好。
- **fd vs find**：find 靠 `-name/-type` 等谓词组合、语法繁复；fd 用直观参数并默认过滤无关文件。
- **jq vs sed/awk**：sed/awk 面向文本流；jq 理解 JSON 结构，能按键路径精确取值/过滤/改写。

## 常见误区

- ripgrep 只是 grep 的别名，行为完全相同。
- fzf 只能用来在文件列表里挑选。
- 命令行里解析 JSON 只能靠 sed/awk 硬抠。

## 面试速答

> 🎯 新一代命令行工具普遍用 Rust 重写、默认忽略 .gitignore、并行且彩色：fzf(任意列表模糊过滤)、ripgrep(极快代码搜索)、fd(直观文件查找)、bat(带高亮分页的 cat)、jq(命令行处理 JSON)。可管道组合；写可移植脚本时仍回退 find/grep。
