# 结对编程

## 定义

**一句话定义：** 结对编程(Pair Programming)是一种敏捷开发实践:两名开发者共用一台电脑协作编程,一人担任"驾驶员"(Driver)负责敲代码,另一人担任"领航员"(Navigator)实时审查、思考设计与把控方向,并定期互换角色。

**通俗类比：** 像开车时的"司机 + 副驾领航"——司机专注操控方向盘(写代码),副驾盯着路线、提醒路况与方向(审查与设计),两人随时沟通、必要时换手;比一个人闷头开更安全、更少走错路。

> 多义说明:结对编程是极限编程(XP)的核心实践之一;有面对面结对与远程结对;变体如 mob programming(多人)。本文讨论双人结对。

## 原理与机制

- **角色:** Driver(写代码、关注实现细节)、Navigator(审查、设计、把控全局、发现问题);定期轮换(如每 15–30 分钟)。
- **协作:** 持续对话、即时评审、共同思考;知识实时共享。
- **形式:** 现场结对、远程结对(屏幕共享)、乒乓结对(结合 TDD,一人写测试、另一人实现)。

## 关键组成

| 组成 | 说明 |
|------|------|
| Driver / Navigator | 两个协作角色 |
| 角色轮换 | 定期互换,避免疲劳 |
| 持续沟通 | 实时对话与评审 |
| 远程 / 现场 | 协作形式 |

## 应用场景

- 敏捷 / XP 团队
- 关键或复杂模块开发
- 新人培养与知识传递
- 高质量要求的场景、远程协作

## 优点与局限

- 优点:代码质量高(实时评审)、知识共享与传承、减少 bug、集思广益、提升专注。
- 局限:人力成本翻倍(两人一台机);需良好沟通与默契;性格/节奏不合会低效;并非所有任务都适合。

## 常见误区

- 结对 ≠ 一人写、一人干看:Navigator 要主动审查与思考。
- 结对不等于效率减半:质量与知识共享的收益需一并计入。
- 需定期轮换角色,避免疲劳与单方主导。
- 不是所有任务都适合结对(简单或探索性任务可能单人更高效)。
