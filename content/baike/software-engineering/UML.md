# UML

## 定义

**一句话定义：** UML(Unified Modeling Language,统一建模语言)是一种通用的、可视化的建模语言,用一组标准的图形化记号来描述软件系统的结构与行为,帮助在编码前及开发过程中沟通设计、记录架构与分析系统。

**通俗类比：** 像建筑的图纸与示意图——施工(编码)前先用统一图例画出平面结构、水电走向、施工流程,让设计师/工人/业主看同一套图就能理解,而不必等房子盖好才知道长啥样。

> 多义说明:UML 是**建模语言**(不是方法学或开发流程,也不限定开发模型);由 OMG 维护,有多个版本(如 UML 2.x)。本文讨论 UML 概念与常用图。

## 原理与机制

- **两大类图:**
  - 结构图(静态):类图、对象图、组件图、部署图、包图、组合结构图——描述系统的静态结构。
  - 行为图(动态):用例图、活动图、状态机图,以及交互图(时序图、通信图)——描述系统的动态行为。
- **常用图:** 类图(结构与关系:关联/聚合/组合/继承)、时序图(对象间消息时序)、用例图(角色与功能)、状态图(状态迁移)、活动图(流程)。
- **用途:** 需求分析、设计沟通、文档化、正向/逆向工程。

## 关键组成

| 组成 | 说明 |
|------|------|
| 结构图 | 类图 / 组件图 / 部署图 |
| 行为图 | 用例 / 活动 / 状态 / 时序 |
| 关系 | 关联 / 聚合 / 组合 / 泛化 |
| 建模元素 | 类、对象、接口、消息等 |

## 应用场景

- 面向对象分析与设计
- 系统架构文档
- 需求沟通、设计评审
- 教学、逆向工程

## 优点与局限

- 优点:标准化可视化、促进沟通与文档化、覆盖结构与行为、工具支持广泛。
- 局限:图多易过度建模(重文档轻代码);有学习成本;易与实现脱节(模型不更新);敏捷中常被轻量化使用。

## 常见误区

- UML 是建模语言,不是方法学或开发流程(不规定"怎么开发")。
- UML ≠ 只画类图(它有十余种图)。
- 模型应与代码保持同步,否则失效。
- 敏捷下 UML 常"够用即可",不追求画全。
