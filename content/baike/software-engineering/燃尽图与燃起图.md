# 燃尽图与燃起图

> 📌 **导航**：本文是 **燃尽图与燃起图** 词条，属 [[05-项目管理]] 子词条。迭代节奏见 [[迭代与回顾]]。

## 定义

**一句话定义：** 燃尽图（Burndown）画"剩余工作量随时间下降"、燃起图（Burnup）画"已完成工作量随时间上升并叠加总范围线"，两者都是把 Sprint/发布进度可视化的敏捷度量图，用来预测能否按时完成、并暴露范围蔓延。

**通俗类比：** 燃尽图像沙漏里剩下的沙、燃起图像逐渐填满的进度条；燃起图额外画出"总量本身还在变"，能看出需求越加越多。

## 为什么需要它

光看"还剩几个任务"不直观，也难判断趋势与能否收尾。把工作量随时间画成曲线，团队和干系人一眼看到进度超前/落后、估算偏差与范围变化，从而及早调整范围或资源，而非到截止日才发现开天窗。

## 核心机制

- **燃尽图**：X 轴=剩余天数，Y 轴=剩余故事点/工时；一条"理想线"匀速下降到 0，实际点在其下=超前、其上=落后。
- **燃起图**：Y 轴=已完成量，常画"总范围线"与"已完成线"两条；两线间距=剩余工作，总范围线抬升=范围蔓延。
- **数据口径**：以故事点或剩余工时为单位，每日更新；Sprint 燃尽看迭代、Release 燃尽/燃起看多迭代（见 [[迭代与回顾]]）。
- **速度（Velocity）**：常与燃尽配合——历史每迭代完成点数，用来估算能否装下计划的量。

## 具体示例

燃尽图（剩余点数 vs 天）：理想线 20→0 匀速，实际前期慢、后期追上：

```
剩余
20|\●
15| \ ●        实际在理想线上方 = 落后
10|  \  ●●
 5|   \     ●●
 0|____\________●__> 天
     理想线 \
```

## 何时用与何时不用

- **用**：Sprint/发布需要每日可见的进度趋势、要向干系人沟通"能否按期"、要暴露范围蔓延时（燃起图尤其）。
- **不用**：别把它当考核工具逼团队"把线画漂亮"而虚报完成；探索型/无明确待办列表的工作硬套燃尽意义不大；用 [[看板方法]] 关注流动与在制品时，燃尽非必需。

## 优劣与代价

✅ 一眼看趋势与风险，促进透明与早期纠偏；燃起图显式暴露范围变化。
✅ 与故事点/速度结合，让"还能不能再加需求"有数据支撑。
⚠️ 依赖诚实、稳定的估算，垃圾进垃圾出；可能诱导 gaming（拖后集中勾选）。
⚠️ 只度量"量"不度量"价值/质量"，需与缺陷率、评审等指标一起看（见 [[OKR与KPI]]）。

## 与相关概念的区别

- **燃尽 vs 燃起**：剩余下降 vs 完成上升（燃起另画总范围、更能显示蔓延）。
- **燃尽图 vs 看板**：图表看趋势时间序列 vs 看板看在制品与流转瓶颈。
- **Sprint 燃尽 vs Release 燃尽**：单迭代收尾预测 vs 跨迭代发布节奏。

## 常见误区

- 燃尽图实际线在理想线上方，说明进度超前。
- 为了让燃尽图好看，可以把未做完的任务先勾掉。
- 燃起图和燃尽图信息完全一样，随便用哪个都行。

## 面试速答

> 🎯 燃尽图=剩余工作量随时间下降(实际在理想线下=超前)；燃起图=已完成随时间上升、叠加总范围线，两线间距是剩余、总范围上抬=范围蔓延。二者把进度可视化助预测与纠偏，但要诚实估算、别拿来逼"画漂亮线"，且不衡量价值/质量。
