# 代码异味

> 📌 **导航**：本文是 **代码异味** 词条，属于 software-engineering 术语集。相关枢纽：[[01-开发流程]]、[[02-版本控制]]、[[03-代码质量]]、[[04-CI CD]]、[[05-项目管理]]。

## 定义

**一句话定义：** 代码异味（Code Smell，亦译"坏味道"，两者同义）指代码表面上一眼可辨、暗示内部可能存在设计问题的征兆，如重复代码、过长函数、过大类；它本身不是缺陷，而是指向 [[重构]] 方向的线索。

**通俗类比：** 像身体的症状：发烧不是病本身，却提示该去查病因。闻到异味不等于这里有 bug，但它值得你停下来看一眼。

## 为什么需要它

设计层面的问题不会以编译错误的形式出现，它们只是让每次改动都更贵一点。等意识到时，改一处要动十处、没人敢碰。代码异味提供了一套**廉价的早期探针**：不需要度量、不需要工具，靠可读经验就能识别，把"结构在腐烂"这件事变成日常可讨论的具体名词，从而让重构有明确的下手对象，而不是凭"感觉这段代码不舒服"。

## 核心机制

Martin Fowler 在《重构》中列出的常见异味：

- **重复代码**：同一段逻辑散在多处，改一处漏一处。
- **过长函数 / 过大类**：一个单元承担太多职责，无法单独理解与测试。
- **发散式变化与霰弹式修改**：一个类因多种原因被改 / 一种原因要改多个类，都是职责没对齐。
- **基本类型偏执与数据泥团**：一组参数总是结伴出现却用裸类型传递，该抽成对象。
- **依恋情结**：方法花在别人数据上的逻辑比自己的多，位置放错了。
- **投机通用性**：为"将来可能用到"预留的抽象，实际只有一处在用。

| 异味 | 一手信号 | 常见解法 |
|---|---|---|
| 重复代码 | 复制粘贴的痕迹 | 提炼函数 / 模板方法 |
| 过长函数 | 需要滚动才看完 | 分解函数、以查询取代临时变量 |
| 过大类 | 字段多到难以尽览 | 抽离类、提炼子类 |
| 数据泥团 | 同几个参数总一起出现 | 引入值对象 |

## 具体示例

两处各自算折扣再各自拼文案，是典型的重复代码；抽出唯一变化点即可：

```python
# 异味：新增一种会员等级要改两个函数
def price_vip(item):  return item.price * 0.8
def desc_vip(item):   return f"{item.name}（{item.price * 0.8:.0f} 元）"

# 重构后：折扣只有一处真相
RATE = {"vip": 0.8, "normal": 1.0}
def price(item, tier="vip"): return item.price * RATE[tier]
```

## 何时用与何时不用

- **用**：改动旧代码前的体检、评审时的共同语言、决定"这块值不值得排重构"的依据。
- **不用**：不要把它当打分表逐条清零——**三行重复好过错误的抽象**，在需求未收敛时强行消除重复会造出更难改的假抽象；也不要拿异味清单指责作者，它描述代码，不描述人。

## 优劣与代价

✅ 门槛低、可讨论、把隐性的设计劣化显性化，直接给出重构靶点。
⚠️ 主观：同一现象不同人判断不同，清单也随语言范式变化（大类在函数式风格里并非异味）。
⚠️ 只给方向不给优先级，需要配合影响面与改动频率才能排序。

## 与相关概念的区别

- **异味 vs 缺陷**：异味是当前可运行、但让未来改动变贵的征兆；缺陷是行为已经错了。
- **异味 vs [[技术债务]]**：异味是"哪里不对劲"的观察，技术债务是"欠了多少、利息几何"的成本账。
- **异味 vs [[圈复杂度]]**：一个靠人读出来，一个由工具算出来；量化指标能设门禁，人工征兆能看见语义。
- **异味 vs lint 告警**：lint 查风格与已知错误模式，多数结构性异味（职责错位、投机抽象）工具看不见。

## 常见误区

- 代码闻起来有异味，说明它现在就有 bug、必须立刻修。
- 异味清单越清零，代码质量就越高，所以应该设定"零异味"目标。

## 面试速答

> 🎯 代码异味 = 暗示深层设计问题的表面征兆（重复代码、过长函数、过大类、霰弹式修改等），出自 Fowler《重构》；它不是 bug，是重构的靶点，解法按异味类型对号入座，但要警惕为清零而过度抽象。
