# 线程


> 📌 **导航**：本文是 **线程** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 线程（Thread）是操作系统能够进行调度的最小执行单元，它存在于进程之内、与同进程的其他线程共享该进程的地址空间和资源，但各自拥有独立的执行栈、程序计数器和寄存器状态。

**通俗类比：** 一个进程像一间工厂厂房（有场地、设备、原料），线程像厂房里的多名工人：共用同一套设备和原料（共享内存）、各自干各自的活（独立执行），彼此配合但也可能抢同一台机器而需协调（同步）。

> 多义说明：本文讨论操作系统的软件线程（执行单元）；区别于 CPU 的硬件线程（如超线程 SMT 的逻辑处理器）。

## 为什么需要它

进程各自独立地址空间，协作要靠 IPC、切换也重。当一个程序内部有多个可并行推进的任务（界面响应 + 后台计算、服务器每请求处理）时，用同进程内的多线程共享数据、轻量切换，比开多进程更高效地利用 CPU 与多核。

## 核心机制

- **资源边界：** 同进程线程共享代码段、数据段、堆和打开的文件；独占各自的栈、寄存器、PC 与线程状态。共享使线程间通信比 IPC 高效，但需要同步以避免数据竞争。
- **调度与层次：** 内核级线程由 OS 调度、用户级线程由运行时库调度（切换快但一个阻塞可能拖累全进程），以及二者混合的多对多模型。
- **并发 vs 并行：** 多线程在多核上可真正并行，在单核上通过时间片轮转并发。
- **关键要素：** 线程 ID、PC、寄存器集合、独立栈、线程状态与优先级、线程本地存储（TLS）。

## 具体示例

Web 服务器线程池：固定 N 个 worker 线程从任务队列取请求处理，共享只读配置省内存、并发吃满多核；但 N 远大于核数时，过多线程只会加剧上下文切换与调度开销、吞吐反降。

## 何时用与何时不用

- **用：** 服务器并发（线程池）、GUI 后台线程保持响应、多核并行计算、异步 I/O 与任务流水线。
- **不用：** 任务彼此要强隔离、怕一个崩溃拖垮全部时用多进程；高并发 I/O 密集型可考虑事件循环 / 协程替代"每请求一线程"。

## 优劣与代价

✅ 比进程轻量（创建 / 切换成本低）、共享内存使通信高效、能充分利用多核。
⚠️ 共享数据带来竞态，需锁 / 信号量同步、易引发死锁与性能下降；调试困难（非确定性）；线程过多使上下文切换与内存占用上升。

## 与相关概念的区别

vs 进程：进程是资源分配单位、地址空间独立，线程是调度执行单位、共享所属进程资源（见 [[进程间通信]]）；vs [[上下文切换]]：线程切换比进程轻，因同进程不需切换页表。

## 常见误区

- 线程就是进程，二者是一回事。
- 多线程一定比单线程更快。
- 线程共享内存就不需要同步。

## 面试速答

> 🎯 线程 = 进程内可被 CPU 调度的最小执行单元，共享代码 / 数据 / 堆 / 文件、独占栈与寄存器，通信高效但需同步；分内核级 / 用户级 / 混合，多核可并行、单核靠时间片并发。
