# 虚拟内存


> 📌 **导航**：本文是 **虚拟内存** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 虚拟内存（Virtual Memory）是操作系统提供的内存管理技术，它为每个进程提供独立、连续的虚拟地址空间，由硬件（MMU）与 OS 协作把虚拟地址映射到物理内存或磁盘，从而实现进程隔离、内存"扩容"与按需调页。

**通俗类比：** 像酒店给每位客人发一本"房间号册"（虚拟地址），客人以为整座酒店都归自己用；前台（OS + MMU）在背后把房间号映射到真实房间（物理内存），暂不使用的先空着、需要时再安排（按需调页）。

> 多义说明：狭义"虚拟内存"常特指用磁盘扩展可用内存（swap / 分页）；广义指整套虚拟地址空间机制。本文取广义。

## 为什么需要它

物理内存有限又不连续，进程若直接管理物理地址既不安全（能读写别人内存），也难以运行超过物理大小的程序。虚拟内存给每进程一个独立连续地址空间，用页表映射到离散物理帧、不常用的页换出到磁盘，实现隔离、保护与"比内存更大"的假象。

## 核心机制

- **分页：** 虚拟地址空间划分为页（page）、物理内存划分为帧（frame），页表建立页→帧映射（常为多级）。
- **地址转换：** MMU 在访问时把虚拟地址翻译成物理地址；TLB（快表）缓存最近映射以加速。
- **缺页中断：** 目标页不在物理内存时触发，OS 从磁盘调入、必要时先置换出一页。
- **页面置换：** LRU / FIFO / Clock 等决定换出哪一页（详见 [[页面置换算法]]）；物理内存不足而频繁换页会导致抖动（thrashing）。

## 具体示例

fork() 后父子进程用写时复制（COW）共享同一批物理页、只读不拷贝；一方写入才触发缺页、复制出私有页——大量"只 fork 不改"的短命令因此省内存又相互隔离，正是虚拟内存机制的用武之地。

## 何时用与何时不用

- **用：** 几乎所有现代 OS 的内存管理与隔离、内存保护（非法访问触发段错误）、mmap 文件映射、fork 的写时复制。
- **慎 / 不用：** 硬实时系统对缺页 / 换页时延敏感，需锁页（mlockall）或关换页；内存本就紧张还大幅超配会抖动作废。

## 优劣与代价

✅ 进程相互隔离与保护、可用地址空间可超过物理内存、程序员面对连续地址编程更简单、支持共享与写时复制。
⚠️ 地址转换有开销（TLB 缓解）；缺页会引发磁盘 I/O 拖慢性能；置换不当导致抖动。

## 与相关概念的区别

vs 单纯 swap：swap 只是虚拟内存的一个组成（换出页的存放区），虚拟内存是含页表 / TLB / 缺页 / 置换的整套机制；vs [[内存与存储系统]]：那是物理内存层级（cache / RAM / 磁盘），虚拟内存是架在其上的地址抽象层。

## 常见误区

- 虚拟内存就是磁盘上的交换空间。
- 虚拟内存设置得越大越好。
- 虚拟地址连续就意味着物理内存也连续。
