# 操作系统核心


> 📌 **导航**：本文是 **操作系统核心** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 操作系统（OS）是管理硬件资源（CPU、内存、设备）、为程序提供运行环境与统一接口的系统软件，其核心职责是进程管理、内存管理、文件系统与 I/O 管理。

**通俗类比：** 操作系统像一家公司的行政总管——把有限的工位、设备与时间（硬件资源）合理分配给各个项目（进程），并制定统一的办事流程（系统调用接口）。

> 多义说明：本文是操作系统核心子系统的枢纽与索引；各主题均有专门词条，此处速览并双链深入，避免重复维护。

## 为什么需要它

程序不能直接抢硬件：CPU、内存、磁盘、设备都要有人统一分配、隔离保护并给出稳定接口。OS 正是这层管理者——调度 CPU、管虚拟内存、抽象文件系统、经系统调用给程序一套与硬件无关的运行环境。

## 核心机制

| 主题 | 一句话要点 | 深入 |
|------|-----------|------|
| 进程 / 线程 / 协程 | 资源分配单位 / CPU 调度单位 / 用户态轻量执行体 | [[线程]]、[[操作系统基础术语]] |
| 进程调度 | FCFS / SJF / RR / CFS 决定谁先上 CPU | [[进程调度]] |
| 进程通信 | 管道 / 消息队列 / 共享内存 / 信号 / 套接字 | [[进程间通信]] |
| 内存管理 | 虚拟地址→页表→物理地址，TLB 加速 | [[虚拟内存]] |
| 文件系统 | ext4 / XFS / NTFS / APFS / Btrfs 等 | [[文件系统]] |
| 中断与系统调用 | 内核响应事件 / 用户态进内核的入口 | [[中断]]、[[系统调用]] |
| 用户态与内核态 | CPU 的特权级别划分 | [[用户态与内核态]] |
| 同步与死锁 | 信号量 / 互斥锁；死锁四条件与预防 | [[信号量与互斥锁]]、[[死锁]] |

内核架构上还分宏内核（如 Linux，驱动与核心服务都在内核态，快但庞大、驱动 bug 可波及全局）与微内核（如 MINIX/QNX，内核只留最小功能、其余移到用户态服务，可靠但频繁 IPC 有开销），现代系统多为混合折中。

## 具体示例

一个程序读文件：CPU 调度轮到它（[[进程调度]]）→ 调 `read` 系统调用陷入内核 → 内核经 [[中断]] / 块设备完成 I/O、查 [[虚拟内存]] 页表定位缓冲区 → 由 [[文件系统]] 把 inode 与数据块映射成文件内容返回——各子系统串成一次调用。

## 何时用与何时不用

- **用：** 作为操作系统整体的入门地图，先掌握四大子系统及其关系，再按双链跳到专门词条。
- **不用：** 查某子系统的细节（调度算法、页表与 TLB、日志文件系统实现）时，到对应专门词条看。

## 优劣与代价

✅ 提供资源管理、隔离保护与统一接口，让多程序安全并发、硬件可复用与抽象。
⚠️ 引入调度 / 上下文切换 / 系统调用等开销；内核态 bug 可能波及全局；抽象层越多性能损耗越大。

## 与相关概念的区别

vs [[操作系统基础术语]]：那篇是横向术语速览，本文是核心子系统枢纽；vs 硬件（[[CPU与处理器架构]]）：OS 是跑在硬件之上的管理软件，硬件提供 CPU / 内存 / 总线，OS 负责调度与抽象。

## 常见误区

- 线程一定比进程快。
- 协程能自动利用多核并行。
- CPU 核心和频率越多，系统就一定越流畅。

## 面试速答
