# 上下文切换


> 📌 **导航**：本文是 **上下文切换** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 上下文切换(Context Switch)是操作系统把 CPU 从一个进程/线程切换到另一个时,保存当前执行上下文(寄存器、程序计数器等)并载入目标上下文的过程;它是多任务并发执行的基础,但本身有开销。

**通俗类比：** 像你同时处理几项工作,每次被打断切换任务时,要先把当前进度记下来(存上下文),再翻出另一项的进度接着做(载入上下文);切换本身要花时间,频繁切换反而降低整体效率。

> 多义说明:有进程上下文切换与线程上下文切换(后者更轻,因共享地址空间);区别于模式切换(用户态 ↔ 内核态)。本文讨论进程/线程上下文切换。

## 原理与机制

- **触发条件:** 中断、系统调用、时间片用完、更高优先级任务就绪、阻塞(等待 I/O)、主动让出。
- **切换过程:** 保存当前 PCB/TCB(程序计数器、寄存器、栈指针、状态等)→ 调度器选择下一个 → 载入其上下文 → 恢复执行。
- **开销:** 直接开销(保存/恢复寄存器、切换页表、刷新 TLB)与间接开销(缓存与 TLB 变冷导致后续变慢)。
- **进程 vs 线程:** 线程切换更轻(同进程线程共享地址空间,无需切换页表)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 上下文(PCB/TCB) | PC、寄存器、栈指针、状态 |
| 触发条件 | 中断/时钟/阻塞/让出 |
| 保存 / 恢复 | 切换的核心动作 |
| TLB 与缓存影响 | 间接开销来源 |
| 进程 vs 线程切换 | 后者更轻量 |

## 应用场景

- 多任务操作系统的并发执行
- 时间片轮转调度
- 中断与系统调用处理
- 高并发服务器

## 优点与局限

- 优点:实现多任务并发、共享 CPU、及时响应事件。
- 局限:有开销,不宜过于频繁;导致 cache/TLB 变冷、降低性能;上下文过多占用内存;是常见的系统性能瓶颈点。

## 常见误区

- 上下文切换 ≠ 模式切换(用户态/内核态)。
- 线程切换比进程切换轻。
- 切换开销主要来自间接部分(缓存/TLB 变冷)。
- 过多线程或过短时间片会因频繁切换而降低吞吐(见 [[进程调度]])。
