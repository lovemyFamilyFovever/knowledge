# 上下文切换


> 📌 **导航**：本文是 **上下文切换** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 上下文切换是操作系统把 CPU 从一个进程 / 线程切换到另一个时，保存当前执行上下文（寄存器、程序计数器等）并载入目标上下文的过程，是多任务并发的基础，但本身有开销。

**通俗类比：** 像同时处理几项工作，每次被打断切换任务时要先把当前进度记下来、再翻出另一项的进度接着做；切换本身要花时间，频繁切换反而降低整体效率。

> 多义说明：有进程上下文切换与线程上下文切换（后者更轻，因同进程线程共享地址空间）；区别于模式切换（用户态 ↔ 内核态）。

## 为什么需要它

单个 CPU 要在多个任务间"同时"推进，靠的就是快速来回切换——每个任务跑一小段时间片就让位。它是多任务、及时响应 I/O 与中断、共享 CPU 的底层机制，代价是每次切换都要花时间。

## 核心机制

- **触发条件：** 中断、系统调用、时间片用完、更高优先级任务就绪、阻塞（等待 I/O）、主动让出。
- **切换过程：** 保存当前 PCB / TCB（程序计数器、寄存器、栈指针、状态）→ 调度器选择下一个 → 载入其上下文 → 恢复执行。
- **开销构成：** 直接开销（保存 / 恢复寄存器、切换页表、刷新 TLB）+ 间接开销（cache / TLB 变冷使后续访存变慢），后者往往占比更大。
- **进程 vs 线程：** 线程切换更轻——同进程内线程共享地址空间，无需切换页表。

## 具体示例

用 `vmstat 1` 看 cs 列：若每秒上下文切换数异常高、吞吐却下降，常是线程过多或时间片过短导致频繁切换；减少线程数、调大时间片后 cs 回落、吞吐回升。

## 何时用与何时不用

- 用：这是 OS 自动完成的基础机制，谈不上主动选用，重点是别制造不必要的频繁切换。
- 少用 / 优化方向：CPU 绑核、控制线程数、用协程 / 事件循环做 I/O 并发、增大时间片，都能显著降低切换开销。

## 优劣与代价

✅ 实现多任务并发、共享 CPU、及时响应外部事件。
⚠️ 有开销、不宜过频；导致 cache / TLB 变冷降性能；过多上下文占用内存；是常见的系统性能瓶颈点。

## 与相关概念的区别

vs 模式切换（[[用户态与内核态]]）：模式切换只是特权级变化、不换任务地址空间，上下文切换换一个任务、可能要换页表；vs [[进程调度]]：调度决定"下一个切给谁"，上下文切换是"怎么切"的动作。

## 常见误区

- 上下文切换就是用户态与内核态之间的模式切换。
- 线程切换和进程切换的开销一样大。
- 上下文切换的开销可以忽略不计。

## 面试速答

> 🎯 上下文切换 = 保存当前 PCB/TCB、载入下一个任务上下文让 CPU 换任务跑；触发有中断 / 时间片 / 阻塞等，开销含直接（寄存器 / 页表 / TLB）与间接（cache 变冷），线程切换比进程轻。
