# 中断


> 📌 **导航**：本文是 **中断** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 中断(Interrupt)是硬件或软件向 CPU 发出的异步信号,提示有事件需要立即处理;CPU 收到后暂停当前执行流、保存现场,转去执行对应的中断处理程序,处理完再恢复原任务,从而实现对外设与异常的及时响应。

**通俗类比：** 像你正专心写字,突然电话铃响(中断)——你放下笔、记住写到哪(保存现场),接电话处理事情(中断处理),完事后再回到刚才的位置继续写(恢复现场)。

> 多义说明:广义上含**中断**(interrupt,异步,来自外部硬件)与**异常/陷阱**(exception/trap,同步,来自当前指令,如缺页、除零、系统调用);二者机制相似。本文统称并加以区分。

## 原理与机制

- **触发来源:** 外设(I/O 完成、定时器、键盘)发出硬件中断;程序执行触发异常(缺页、非法指令)或软中断/陷阱(系统调用)。
- **响应过程:** CPU 按中断号查中断向量表(IDT/IVT),保存当前状态(PC、寄存器),切换到内核态,跳转到中断服务程序(ISR)。
- **处理分层:** 上半部(top half)做快速关键处理;下半部(bottom half,如 Linux 软中断/tasklet/工作队列)延后处理耗时工作。
- **优先级与屏蔽:** 中断有优先级,可被屏蔽(关中断)以避免嵌套混乱。

## 关键组成

| 组成 | 作用 |
|------|------|
| 中断源 | 外设、定时器、异常、软件 |
| 中断号 / 向量 | 标识中断类型 |
| 中断向量表(IDT/IVT) | 中断号到处理程序入口的映射 |
| 中断服务程序(ISR) | 实际处理逻辑 |
| 现场保存 / 恢复 | 保护与还原被中断的上下文 |
| 上半部 / 下半部 | 快速处理与延后处理分离 |

## 应用场景

- 外设 I/O(键盘、网卡、磁盘完成通知)
- 定时器中断驱动调度时钟
- 缺页中断支撑虚拟内存
- 系统调用陷入、实时系统的事件响应

## 优点与局限

- 优点:异步事件可被及时响应;CPU 无需轮询(节省资源);支撑多任务与实时性。
- 局限:中断处理需尽快完成(否则丢中断或增加延迟);频繁中断开销大;编程复杂(现场保存、重入与并发);存在"中断风暴"风险。

## 常见误区

- 中断 ≠ 轮询:中断是事件驱动,轮询是 CPU 主动反复查询。
- 中断不只来自硬件:软件中断、异常、陷阱也走类似机制。
- 中断处理应尽量短,耗时工作交给下半部。
