# 中断


> 📌 **导航**：本文是 **中断** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 中断是硬件或软件向 CPU 发出的异步信号，提示有事件需要立即处理；CPU 收到后暂停当前执行流、保存现场、转去执行对应的中断处理程序，处理完再恢复原任务，从而及时响应外设与异常。

**通俗类比：** 像正专心写字时电话铃响——你放下笔、记住写到哪（保存现场）、接电话处理事情（中断处理），完事再回到刚才的位置继续写（恢复现场）。

> 多义说明：广义含中断（interrupt，异步、来自外部硬件）与异常 / 陷阱（exception/trap，同步、来自当前指令，如缺页、除零、系统调用），二者机制相似。

## 为什么需要它

若靠 CPU 反复轮询外设"好了没"，既浪费算力又延迟高。中断把主动权交给事件源：有事才打断 CPU，让它平时跑别的任务、事件到来时及时响应，是多任务、实时性与虚拟内存缺页处理的底层支撑。

## 核心机制

- **触发来源：** 外设（I/O 完成、定时器、键盘）发出硬件中断；程序执行触发异常（缺页、非法指令）或软中断 / 陷阱（系统调用）。
- **响应过程：** CPU 按中断号查中断向量表（IDT / IVT），保存现场（PC、寄存器），切到内核态，跳转到中断服务程序（ISR）。
- **处理分层：** 上半部（top half）做快速关键处理；下半部（bottom half，如 Linux 软中断 / tasklet / 工作队列）延后处理耗时工作。
- **优先级与屏蔽：** 中断有优先级，可关中断屏蔽以避免嵌套混乱。

## 具体示例

网卡收包触发硬中断，上半部快速应答、标记数据并尽快退出以免丢包，真正的协议栈处理（解析、拷贝）交给下半部 softirq 延后执行；若上半部做重活，高并发收包时就会"中断风暴"、丢包加剧。

## 何时用与何时不用

- **用：** 外设 I/O 完成通知、定时器中断驱动调度时钟、缺页中断支撑虚拟内存、系统调用陷入、实时系统事件响应。
- **不用：** 极高频小包等场景盲目每包一中断开销大，改用 NAPI 轮询 + 中断混合；需关中断的临界区窗口尽量短。

## 优劣与代价

✅ 异步事件可被及时响应、CPU 无需轮询省资源、支撑多任务与实时性。
⚠️ 中断处理需尽快完成否则丢事件 / 增延迟；频繁中断开销大；编程复杂（现场保存、重入、并发）；有"中断风暴"风险。

## 与相关概念的区别

vs 轮询：轮询是 CPU 主动反复查询设备状态（简单但费 CPU），中断是事件到来才被动打断；vs [[系统调用]]：系统调用走 trap / 软中断"主动陷入"内核、是同步的，硬件中断则是异步外部事件。

## 常见误区

- 中断就是靠 CPU 不断轮询外设来实现的。
- 中断只可能来自外部硬件。
- 中断上半部应把耗时的活一次做完再返回。

## 面试速答

> 🎯 中断 = 硬 / 软件向 CPU 发异步信号，CPU 查向量表、存现场、进内核态跑 ISR 再恢复；分上半部（快、短）与下半部（延后处理耗时），实现事件驱动、免轮询，支撑 I/O / 缺页 / 系统调用。
