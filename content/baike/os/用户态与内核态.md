# 用户态与内核态

## 定义

**一句话定义：** 用户态与内核态是 CPU 提供的两种特权级别——内核态(高特权)可执行所有指令、访问所有硬件与内存,用户态(低特权)只能执行非特权指令、访问受限资源;这种隔离是操作系统安全与稳定的基础。

**通俗类比：** 像公司的普通员工与核心管理层——员工(用户态)只能在办公区做常规工作,不能进机房改服务器;需要动用核心资源时,得走审批流程(系统调用)请管理层(内核态)代为操作。

> 多义说明:也称用户模式/内核模式、ring 3 / ring 0(x86)、user / supervisor mode(ARM EL0/EL1);本文讲这一特权级机制。

## 原理与机制

- **硬件支持:** CPU 设特权级(x86 ring 0~3,常用 ring0=内核、ring3=用户;ARM 的 Exception Level)。
- **受限操作:** 特权指令(如 I/O 操作、修改页表、关中断)只能在内核态执行;用户态执行会触发异常。
- **模式切换:** 用户态 → 内核态通过系统调用/中断/异常(trap);内核态 → 用户态通过返回指令(如 iret/sret)。切换需保存/恢复上下文,有开销(可能刷新 TLB/缓存)。
- **地址隔离:** 配合虚拟内存/MMU,内核空间与用户空间地址相互隔离,防止用户程序破坏内核或其他进程。

## 关键组成

| 组成 | 说明 |
|------|------|
| 特权级(ring/EL) | 区分内核态与用户态 |
| 特权指令 | 仅内核态可执行 |
| 陷入(trap)机制 | 触发用户态→内核态切换 |
| 模式切换开销 | 上下文保存/恢复的成本 |
| 地址空间隔离 | 内核与用户内存分离 |

## 应用场景

- 现代操作系统的进程保护与安全
- 系统调用与中断/异常处理
- 设备驱动运行在内核态
- 虚拟化与容器的隔离基础

## 优点与局限

- 优点:隔离与保护(用户程序崩溃不拖垮内核)、安全可控、支撑稳定的多任务。
- 局限:模式切换开销大(频繁 syscall 拖累性能);内核态代码的 bug 危害大;驱动开发难度高。

## 常见误区

- 用户态程序不能直接访问硬件,必须经由内核(系统调用)。
- 模式切换有成本,故有 vDSO、批量 syscall、io_uring 等优化手段。
- 内核态 ≠ "root 权限":前者是 CPU 特权级,后者是用户账户权限概念。
