# 系统调用

## 定义

**一句话定义：** 系统调用(System Call)是操作系统内核向用户程序提供的编程接口,是应用程序请求内核执行特权操作(如读写文件、创建进程、分配内存、网络通信)的唯一合法途径,调用时从用户态陷入(trap)到内核态。

**通俗类比：** 像顾客不能自己进后厨炒菜(直接操作硬件),只能通过服务员(系统调用)下单,由后厨(内核)代为完成再把菜端出来;服务员是顾客与后厨之间唯一的正规通道。

> 多义说明:系统调用 ≠ 普通函数调用(后者全程在用户态);也 ≠ 库函数(库函数可能封装一个或多个系统调用,如 `printf` 最终调用 `write`)。本文指内核接口。

## 原理与机制

- **特权级:** CPU 区分用户态与内核态(如 x86 的 ring 3 / ring 0),应用运行在用户态,不能直接执行特权指令或访问硬件。
- **陷入(trap):** 应用把系统调用号与参数放入约定寄存器,执行陷入指令(x86 的 `int 0x80` / `syscall`,ARM 的 `svc`),触发受控异常并切换到内核态。
- **内核处理:** 内核依据调用号在**系统调用表**中找到对应服务例程,执行完毕后把结果写入寄存器并返回用户态。
- **开销:** 涉及模式切换与上下文保存,比普通函数调用昂贵(故有 vDSO、调用批量化等优化)。

## 关键组成

| 组成 | 作用 |
|------|------|
| 系统调用号 | 标识请求哪个服务 |
| 参数寄存器 | 传递参数与返回值 |
| 陷入指令 | 触发用户态→内核态切换 |
| 系统调用表 | 调用号到处理例程的映射 |
| errno | 返回错误码 |

## 应用场景

- 文件 I/O(open/read/write/close)
- 进程控制(fork/exec/wait/exit)
- 内存管理(mmap/brk)
- 网络通信(socket/send/recv)与设备、IPC

## 优点与局限

- 优点:提供隔离与保护(应用无法直接操作硬件)、统一抽象、安全可控。
- 局限:模式切换开销大,频繁调用拖累性能;接口与操作系统绑定,影响可移植性。

## 常见误区

- 系统调用 ≠ 库函数/标准库:库函数可能纯用户态实现,或在其内部封装 syscall。
- 它不是"调用某个系统程序",而是请求内核服务。
- 现代许多读操作被缓存或 vDSO 优化,并非每次都真正陷入内核。
