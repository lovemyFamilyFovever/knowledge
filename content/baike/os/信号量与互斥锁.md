# 信号量与互斥锁


> 📌 **导航**：本文是 **信号量与互斥锁** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 信号量与互斥锁是并发编程中协调多个线程 / 进程访问共享资源的同步原语——互斥锁保证同一时刻只有一个线程进入临界区，信号量是带计数的"许可池"、允许至多 N 个线程同时访问，兼具同步与互斥能力。

**通俗类比：** 互斥锁像单人卫生间的门锁——里面有人就锁上、别人必须等；信号量像有 N 个隔间的卫生间，门口挂着 N 把钥匙，拿到才能进、用完归还，钥匙被拿完就得等。

> 多义说明：二者相关但不同；信号量分计数信号量与二值信号量（二值近似互斥，但语义与所有权不同）。

## 为什么需要它

并发线程共享数据时，若不协调就会出现数据竞争、读到写了一半的值。互斥锁把临界区串行化保证互斥，信号量还能计数限并发、跨线程发信号做同步（如生产者–消费者），是并发正确性的基础工具。

## 核心机制

- **互斥锁：** `lock()` / `unlock()`，具有"所有权"（谁加锁谁解锁），用于保护临界区。
- **信号量：** 由 Dijkstra 提出；`wait/P`（申请许可、计数减 1、不足则阻塞）与 `signal/V`（释放许可、计数加 1、唤醒等待者）；计数信号量用于控制并发数。
- **底层实现：** 通常结合原子操作（CAS / test-and-set）与阻塞队列；区分忙等待（自旋锁）与阻塞（mutex / semaphore）。
- **用途区分：** 互斥（保护共享数据）与同步（控制执行顺序）。

## 具体示例

生产者–消费者队列：empty 信号量初值 = 容量、full 初值 = 0；生产者 `wait(empty)` 后放入、`signal(full)`，消费者 `wait(full)` 后取出、`signal(empty)`，再加一把互斥锁保护队列本身——信号量管同步、互斥锁管互斥。

## 何时用与何时不用

- **用：** 保护共享数据的临界区（互斥锁）、限制并发度 / 资源池（计数信号量）、跨线程执行顺序同步（生产者–消费者）。
- **不用：** 能无锁（原子变量 / 不可变 / 线程封闭）就别加锁；临界区极短用自旋锁、较长用阻塞锁；跨机器场景要改用 [[分布式锁]]。

## 优劣与代价

✅ 提供可靠的互斥与同步、可控并发度。
⚠️ 使用不当会导致死锁 / 活锁 / 优先级反转；加锁与竞争开销影响性能；所有权与可重入性需谨慎处理。

## 与相关概念的区别

vs [[死锁]]：锁本身不防死锁，多把锁获取顺序不当仍会死锁，需按序申请、破坏死锁四条件；vs 自旋锁：mutex / semaphore 拿不到锁就阻塞让出 CPU，自旋锁忙等占 CPU、只适合极短临界区。

## 常见误区

- 二值信号量和互斥锁完全等价。
- 信号量只能用来做互斥。
- 临界区较长时应优先用自旋锁。

## 面试速答

> 🎯 互斥锁 = 有所有权的 lock/unlock 保临界区；信号量 = Dijkstra 的计数许可池，wait/P 申请、signal/V 释放，可计数限并发也能跨线程同步；都靠原子操作 + 阻塞队列实现，用不好会死锁。
