# 信号量与互斥锁


> 📌 **导航**：本文是 **信号量与互斥锁** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 信号量与互斥锁是并发编程中协调多个线程/进程访问共享资源的同步原语——互斥锁(mutex)保证同一时刻只有一个线程进入临界区;信号量(semaphore)是一个带计数的"许可池",允许至多 N 个线程同时访问,兼具同步与互斥能力。

**通俗类比：** 互斥锁像单人卫生间的门锁——里面有人就锁上,别人必须等;信号量像有 N 个隔间的卫生间,门口挂着 N 把钥匙,拿到钥匙才能进、用完归还,钥匙被拿完就得等。

> 多义说明:二者相关但不同;信号量分计数信号量与二值信号量(二值近似互斥,但语义与所有权不同)。本文辨析二者。

## 原理与机制

- **互斥锁:** `lock()` / `unlock()`;具有"所有权"(谁加锁谁解锁);用于保护临界区。
- **信号量:** 由 Dijkstra 提出;`wait/P`(申请许可,计数减 1,不足则阻塞)与 `signal/V`(释放许可,计数加 1,唤醒等待者);计数信号量用于控制并发数。
- **底层:** 通常结合原子操作(CAS / test-and-set)与阻塞队列实现;区分忙等待(自旋锁 spinlock)与阻塞(mutex/semaphore)。
- **用途:** 互斥(保护共享数据)与同步(控制执行顺序,如生产者–消费者)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 互斥锁 | 有所有权,lock/unlock |
| 信号量 | 计数 + wait/signal |
| 原子操作 | CAS/test-and-set 保证不可分割 |
| 阻塞队列 | 存放等待的线程 |
| 自旋锁 | 忙等待,适合极短临界区 |

## 应用场景

- 线程/进程同步与互斥
- 生产者–消费者模型
- 读写锁、连接池/资源池的并发限流
- 操作系统内核同步、并发数据结构

## 优点与局限

- 优点:提供可靠的互斥与同步、可控制并发度。
- 局限:使用不当会导致死锁/活锁/优先级反转;加锁开销与竞争影响性能;所有权与可重入性需谨慎;分布式场景需改用分布式锁(见 [[分布式锁]])。

## 常见误区

- 互斥锁有所有权(只能由加锁线程解锁),二值信号量无所有权(可由其他线程 signal)——二者并不等价。
- 信号量不只用于互斥,更常用于计数/同步。
- 加锁粒度与范围直接影响性能与正确性。
- 自旋锁适合极短临界区(避免上下文切换),长临界区应用阻塞锁。
