# 文件系统

## 定义

**一句话定义：** 文件系统(File System)是操作系统用于在存储设备上组织、命名、存储与检索文件的机制与数据结构,它把物理磁盘块抽象为"文件与目录"的逻辑视图,并管理空间分配、元数据与访问权限。

**通俗类比：** 像图书馆的管理系统——书(数据)放在书架格子(磁盘块)里,目录卡片(索引/元数据)记录每本书的名字、位置和借阅规则;你按书名(文件名)就能找到,不必关心它在第几排第几层。

> 多义说明:文件系统既指通用**抽象机制**,也指具体**实现**(如 ext4、NTFS、APFS、XFS、ZFS);本文先讲通用机制。

## 原理与机制

- **文件:** 由数据与元数据(名称、大小、权限、时间戳、指向数据块的指针)组成。
- **目录:** 一种特殊文件,维护"文件名 → 文件记录(inode 等)"的映射,构成树状层次结构。
- **空间管理:** 用位图或空闲链表跟踪空闲块;分配策略有连续、链接、索引三种。
- **索引:** 类 Unix 用 inode、NTFS 用 MFT 存元数据与块指针;大文件常用多级索引或 extents。
- **一致性:** 通过日志(journaling)或写时复制(CoW)保证崩溃后结构可恢复。

## 关键组成

| 组成 | 作用 |
|------|------|
| 文件 / 目录 | 逻辑数据单元与层次组织 |
| inode / 元数据 | 记录属性与数据块位置 |
| 数据块 | 磁盘空间分配的基本单位 |
| 空闲空间管理 | 位图/链表跟踪可用块 |
| 日志 / CoW | 崩溃一致性与可靠性 |
| 权限 | 访问控制(读写执行、属主) |

## 应用场景

- 操作系统的持久化存储与文件管理
- 数据库、日志系统的底层存储
- 分布式文件系统(HDFS、Ceph、GlusterFS)
- 备份、快照与版本化存储

## 优点与局限

- 优点:提供统一的文件抽象与层次化组织,管理权限与一致性,屏蔽物理磁盘细节。
- 局限:不同文件系统互不兼容;一致性机制带来写开销;长期使用产生碎片;海量小文件时元数据可能成瓶颈。

## 常见误区

- 文件系统 ≠ 磁盘分区:分区是对磁盘的物理/逻辑划分,文件系统是建立在其上的组织方式。
- "删除"文件通常只是移除元数据/标记块为空闲,数据可能仍可恢复(直到被覆盖)。
- 格式化是重建文件系统结构,不等于物理擦除磁盘每个扇区。
