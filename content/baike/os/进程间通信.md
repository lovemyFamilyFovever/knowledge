# 进程间通信


> 📌 **导航**：本文是 **进程间通信** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 进程间通信(Inter-Process Communication, IPC)是操作系统提供的、让不同进程之间交换数据并同步协作的机制总称;由于进程拥有相互隔离的地址空间,必须借助内核提供的 IPC 手段才能通信。

**通俗类比：** 像住在不同房间、各自上锁的人要协作——他们不能直接翻对方的东西(内存隔离),只能通过公共渠道:递纸条(管道)、公告板(共享内存)、打电话(信号/消息),或请物业转交(内核)。

> 多义说明:IPC 是多种机制的统称(管道、消息队列、共享内存、信号量、信号、Socket 等);本文综述常见机制。

## 原理与机制

- **管道(pipe)/命名管道(FIFO):** 半双工字节流;亲缘进程用匿名管道,无亲缘用命名管道。
- **消息队列:** 内核维护的带格式消息链表,进程按类型收发,有消息边界。
- **共享内存:** 多进程映射同一块物理内存,速度最快(无需内核拷贝),但需配合同步。
- **信号量(semaphore):** 用于同步与互斥,保护共享资源(常与共享内存搭配)。
- **信号(signal):** 异步事件通知(如 SIGINT、SIGKILL)。
- **Socket:** 支持同机(Unix domain socket)与跨主机(TCP/UDP)通信。

## 关键组成

| 机制 | 特点 |
|------|------|
| 管道 / FIFO | 简单字节流,半双工 |
| 消息队列 | 有消息边界、可带类型 |
| 共享内存 | 最快,需自行同步 |
| 信号量 | 同步与互斥 |
| 信号 | 异步通知 |
| Socket | 可跨主机、通用 |

## 应用场景

- 多进程架构与微内核设计
- Shell 管道(`cmd1 | cmd2`)
- 客户端–服务器模型
- 生产者–消费者等协作模式
- 浏览器多进程模型、跨主机服务通信(Socket)

## 优点与局限

- 优点:在进程隔离的前提下实现协作;机制多样,适配不同场景;共享内存高效。
- 局限:编程复杂,需处理同步与竞态;跨主机 IPC(Socket)有网络开销;各机制语义与性能差异大。

## 常见误区

- IPC ≠ 线程间通信:线程共享地址空间,通信更简单;IPC 针对地址空间隔离的进程。
- 共享内存虽最快,但必须自行做同步(信号量等),否则产生竞态。
- 管道是无消息边界的字节流,需要应用层自定义分帧。
