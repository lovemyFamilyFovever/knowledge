# 实时操作系统


> 📌 **导航**：本文是 **实时操作系统** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 实时操作系统(Real-Time Operating System, RTOS)是一类能在确定的时间约束内对外部事件作出响应、保证任务在规定截止期限(deadline)前完成的操作系统;其正确性不仅取决于计算结果,还取决于结果产生的时间。

**通俗类比：** 像汽车安全气囊的控制器——碰撞发生后必须在几毫秒内点火,晚一点人就受伤了;这类"必须按时、否则等于失败"的系统,需要能保证时限的实时操作系统,而不是"尽量快"的普通系统。

> 多义说明:分硬实时(hard,错过截止即失败,如飞控/气囊)与软实时(soft,偶尔超时可容忍,如视频播放);区别于追求平均吞吐的通用分时 OS。本文讨论 RTOS。

## 原理与机制

- **核心目标:** 可预测性/确定性(而非最大吞吐),保证时限。
- **实时调度:** 速率单调调度(RMS,静态优先级)、最早截止期优先(EDF,动态优先级)。
- **机制:** 快速上下文切换、可抢占内核、优先级继承(防优先级反转)、最小中断延迟、同步原语(信号量/事件)。
- **关键指标:** 中断延迟、调度延迟、截止期满足率。

## 关键组成

| 组成 | 说明 |
|------|------|
| 截止期(deadline) | 任务必须完成的时间约束 |
| 可抢占内核 | 保证及时响应 |
| 实时调度(RMS/EDF) | 按优先级/截止期调度 |
| 优先级继承 | 防止优先级反转 |
| 确定性 | 可预测的响应时间 |

## 应用场景

- 嵌入式与物联网
- 工业控制、汽车电子
- 航空航天、医疗设备
- 机器人、音视频处理

## 优点与局限

- 优点:保证时限与可预测性、快速响应、高可靠。
- 局限:追求确定性可能牺牲平均吞吐;开发复杂(需分析最坏情况);硬件资源受限;优先级反转等陷阱需处理。

## 常见误区

- 实时 ≠ 快:实时是"按时/可预测",不是"最快"。
- 硬实时错过截止 = 系统失败。
- RTOS 通常不追求高吞吐,而求确定性。
- 优先级反转需靠优先级继承解决(著名案例:火星探路者号)。
