# 实时操作系统


> 📌 **导航**：本文是 **实时操作系统** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 实时操作系统（RTOS）是能在确定的时间约束内对外部事件作出响应、保证任务在规定截止期限（deadline）前完成的操作系统；其正确性不仅取决于计算结果，还取决于结果产生的时间。

**通俗类比：** 像汽车安全气囊的控制器——碰撞后必须在几毫秒内点火，晚一点人就受伤；这类"必须按时、否则等于失败"的系统需要 RTOS，而不是"尽量快"的普通系统。

> 多义说明：分硬实时（hard，错过截止即失败，如飞控、气囊）与软实时（soft，偶尔超时可容忍，如视频播放）；区别于追求平均吞吐的通用分时 OS。

## 为什么需要它

通用 OS 调度追求平均吞吐与公平，响应时间不可预测（会因 GC、分页、抢占而抖动）。工业控制、飞控、气囊这类场景要求"最晚某时刻一定完成"，只有 RTOS 用可抢占内核和可分析的最坏情况时延来保证时限。

## 核心机制

- **核心目标：** 可预测性 / 确定性（而非最大吞吐），保证时限。
- **实时调度：** 速率单调 RMS（静态优先级，周期越短优先级越高）、最早截止期优先 EDF（动态优先级）；可调度性由 CPU 利用率上界判定。
- **关键机制：** 快速上下文切换、可抢占内核、优先级继承（防优先级反转）、最小中断 / 调度延迟、同步原语（信号量 / 事件）。
- **关键指标：** 中断延迟、调度延迟、截止期满足率。

## 具体示例

1997 火星探路者号：气象仪与通信任务共用总线，高优先级通信任务被低优先级任务持有的资源阻塞、又被中优先级任务抢占，反复触发看门狗重启——典型优先级反转，靠给持锁任务临时提权（优先级继承）解决。

## 何时用与何时不用

- **用：** 有硬 / 软截止期限的嵌入式与工控——飞控、汽车电子、医疗设备、机器人、工业 PLC。
- **不用：** 追求高吞吐与通用生态的服务器 / 桌面用 Linux/Windows 更合适；软实时可用通用 OS 调优（如 PREEMPT_RT）凑合，未必上专用 RTOS。

## 优劣与代价

✅ 保证时限与可预测性、快速响应、高可靠。
⚠️ 追求确定性会牺牲平均吞吐；开发复杂（须分析最坏情况执行时间 WCET）；硬件资源受限；优先级反转等陷阱需专门处理。

## 与相关概念的区别

vs [[进程调度]] 的通用算法（RR / 多级反馈队列）：后者优化平均周转与吞吐，实时调度（RMS / EDF）优化"每个任务按时截止"；vs "高性能"：实时 = 可预测按时，不等于最快。

## 常见误区

- 实时操作系统就是运行速度最快的系统。
- 软实时偶尔错过截止期也会导致系统失败。
- RTOS 追求的是最高的平均吞吐量。

## 面试速答

> 🎯 RTOS = 在截止期限内确定响应、正确性含时间；求确定性而非最大吞吐，用可抢占内核 + 快速切换 + RMS/EDF 调度 + 优先级继承防反转；硬实时错过即失败，软实时容忍偶发超时。
