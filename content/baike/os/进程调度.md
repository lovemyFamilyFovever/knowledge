# 进程调度


> 📌 **导航**：本文是 **进程调度** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 进程调度（Process / CPU Scheduling）是操作系统内核按某种策略从就绪队列中选择一个进程 / 线程分配到 CPU 上执行的机制，目标是在吞吐率、响应时间、周转时间、公平性与实时性之间取得平衡。

**通俗类比：** 像只有一个柜员（CPU）的窗口、面前排着很多客户（就绪进程）：叫号规则（调度算法）决定谁先办、办多久——是让每人快速办一点（轮转），还是优先办急件（优先级），直接影响整体效率与等待感受。

> 多义说明：有长程（作业）、中程（内存挂起）、短程（CPU）调度；本文主要讲短程 CPU 调度，并区分抢占式与非抢占式。

## 为什么需要它

CPU 核数远少于就绪任务数，必须决定"下一个跑谁、跑多久"。好的调度要在公平、吞吐、响应、截止时间间权衡——既要交互式任务响应快，又要后台任务吞吐高，还要兼顾实时期限，不能只追单一指标。

## 核心机制

- **触发时机：** 进程阻塞 / 主动让出、时间片用完、有更高优先级进程就绪、中断或系统调用返回。
- **经典算法：** FCFS（简单但有护航效应）、SJF / SRTF（平均等待最优但需预知时长、可能饿死长作业）、优先级调度（用老化 aging 防饥饿）、时间片轮转 RR、多级反馈队列 MLFQ、CFS（Linux 按虚拟运行时间 vruntime 公平分配）。
- **抢占 vs 非抢占：** 抢占式可在时间片到 / 更高优先级就绪时强行换下当前任务，是交互与实时系统的基础。
- **性能指标：** CPU 利用率、吞吐率、周转时间、等待时间、响应时间。

## 具体示例

Linux CFS 给每个任务记账 vruntime（按权重折算的实际运行时间），红黑树里总挑 vruntime 最小的运行；nice 值高（权重低）的任务 vruntime 涨得慢、自然少占 CPU，多任务按比例公平分摊。

## 何时用与何时不用

- **用：** 通用多任务 OS 的 CPU 分配、实时系统（RMS / EDF）、服务器吞吐与桌面交互优化、容器 cgroup 的 CPU 配额。
- **不用 / 权衡：** 纯批处理只图吞吐可用 FCFS / SJF 思路；强实时别用"平均最优"的通用算法，应换可调度性分析的实时调度。

## 优劣与代价

✅ 让多任务共享 CPU、平衡各类性能目标、支撑交互与实时需求。
⚠️ 各算法皆有取舍（无万能方案）；上下文切换有开销；优先级可能导致饥饿 / 反转；时间片等参数调优复杂。

## 与相关概念的区别

vs [[实时操作系统]]：通用调度优化平均指标（周转 / 吞吐 / 响应），实时调度（RMS / EDF）优化"每任务按时截止"；vs [[上下文切换]]：调度器决定"选谁"，上下文切换是"换过去"的动作，频繁切换正是参数不当的代价。

## 常见误区

- 进程调度的目标就是让周转时间最短。
- 时间片越小越好、响应就快。
- 优先级调度天然公平、不会有任务饿死。

## 面试速答

> 🎯 进程调度 = 从就绪队列按策略选任务上 CPU，多目标权衡（吞吐 / 周转 / 响应 / 公平 / 实时）：FCFS、SJF、优先级、RR、MLFQ、CFS(vruntime)；抢占式支撑交互实时，时间片大小与老化是关键参数。
