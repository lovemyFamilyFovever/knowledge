# 进程调度


> 📌 **导航**：本文是 **进程调度** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 进程调度(Process/CPU Scheduling)是操作系统内核按某种策略,从就绪队列中选择一个进程或线程分配到 CPU 上执行的机制,目标是在吞吐率、响应时间、周转时间、公平性与实时性之间取得平衡。

**通俗类比：** 像只有一个柜员(CPU)的窗口,面前排着很多客户(就绪进程);叫号规则(调度算法)决定谁先办、办多久——是让每人快速办一点(轮转),还是优先办急件(优先级),直接影响整体效率与每个人的等待感受。

> 多义说明:有长程(作业)、中程(内存挂起)、短程(CPU)调度;本文主要讲**短程调度(CPU 调度)**,并区分抢占式与非抢占式。

## 原理与机制

- **触发时机:** 进程阻塞/主动让出、时间片用完、有更高优先级进程就绪、中断或系统调用返回等。
- **经典算法:**
  - FCFS(先来先服务):简单,但长作业拖累短作业(护航效应)。
  - SJF / SRTF(短作业优先):平均等待最优,但需预知运行时间、可能饿死长作业。
  - 优先级调度:可能饥饿,用"老化(aging)"缓解。
  - 轮转 RR(时间片):交互友好,时间片大小是关键。
  - 多级反馈队列 MLFQ:综合兼顾响应与效率。
  - CFS(Linux 完全公平调度):按虚拟运行时间 vruntime 公平分配。
- **性能指标:** CPU 利用率、吞吐率、周转时间、等待时间、响应时间。

## 关键组成

| 组成 | 作用 |
|------|------|
| 就绪队列 | 等待 CPU 的进程集合 |
| 调度算法 | 决定选谁上 CPU |
| 时间片(quantum) | 轮转中每次运行的上限 |
| 优先级与老化 | 区分轻重、防饥饿 |
| 调度器 / 分派器 | 执行上下文切换 |

## 应用场景

- 通用操作系统的多任务处理
- 实时系统(EDF、RMS 等实时调度)
- 服务器吞吐优化、桌面交互响应
- 容器 / cgroup 的 CPU 资源分配

## 优点与局限

- 优点:让多任务共享 CPU,平衡各类性能目标,支撑交互与实时需求。
- 局限:各算法均有取舍(无万能方案);上下文切换有开销;优先级可能导致饥饿或优先级反转;参数(如时间片)调优复杂。

## 常见误区

- 调度是多目标权衡,并非单一"最快"。
- SJF 平均等待最优,但需预知运行时间且会饿死长作业。
- 时间片过大退化为 FCFS,过小则上下文切换开销占比过高。
- 优先级反转需靠优先级继承/优先级天花板解决。
