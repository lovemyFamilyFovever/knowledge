# 进程管理详解


> 📌 **导航**：本文是 **进程管理详解** 枢纽页，属于 os 术语集。进程 / 调度原理见 [[操作系统核心]] 等专条，全量命令见 [[Linux 命令速查手册]]，本文聚焦进程与服务管理的运维纵面。

## 定义

**一句话定义：** 进程管理是 Linux 下对进程与服务进行查看、控制、调度与排障的运维操作集合——ps / top 看进程、kill 发信号、nohup / tmux 管后台、systemd 管服务、cron 跑定时任务、nice 调优先级、/proc 与 journalctl 查状态与日志。

**通俗类比：** 像工厂车间管理：ps 点名、top 盯仪表盘、kill 下达指令、systemd 排班并开机自启、cron 定闹钟、/proc 查每道工序的运行记录。

## 为什么需要它

运维要实时掌握"哪些进程在跑、卡没卡、崩没崩"，并安全地停启服务、跑定时任务、调优先级。Linux 把这些能力交给一组命令 + systemd / cron，是服务器日常管理与故障处置的基本功。

## 核心机制

- **查看进程：** ps 拍静态快照（`ps aux` / `ps -ef` / `--forest`），top / htop 动态实时按 CPU / 内存排序——命令细则见 [[Linux 命令速查手册]]。
- **信号控制：** kill 发信号——SIGTERM(15) 优雅退出、SIGKILL(9) 强制且不可捕获（最后手段）、SIGHUP(1) 重载配置、STOP / CONT 暂停恢复。
- **后台与作业：** nohup / `&` / disown 让进程脱离终端续跑，tmux / screen 提供可重连会话，Ctrl+Z 配合 bg / fg 前后切换。
- **服务与定时：** systemctl 起停 / 重载 / 设开机自启 + 自定义 unit 文件，cron 按"分 时 日 月 周"五段语法跑周期任务。
- **优先级：** nice 值（−20~19）越低优先级越高、renice 改运行中进程，配合 [[进程调度]] 的权重调度。
- **状态与日志：** /proc 虚拟文件系统暴露进程与内核指标，dmesg 看内核环形缓冲、journalctl 统一查 systemd 服务日志。

进程 / 线程 / 僵尸与孤儿的成因等概念原理见 [[操作系统核心]] 与 [[线程]]。

## 具体示例

排查"内存持续涨"：`top` 按 M 排序定位高 RSS 进程 → `ps -o pid,ppid,stat -p <pid>` 看父子与状态、`ps aux | awk '$8~/Z/'` 揪僵尸 → 查 `/proc/<pid>/status` 与 `fd/`；处置优先 `kill -15` 让其优雅退出，无响应才 `-9`。

## 何时用与何时不用

- **用：** 服务器日常运维、服务部署（systemd）、周期任务（cron）、故障排查（ps / top / journalctl）。
- **注意：** kill -9 会跳过清理（刷盘 / 释放锁 / 删临时文件），优先 -15；cron 环境变量极简（PATH 很短），脚本须用绝对路径或显式设 PATH。

## 优劣与代价

✅ 命令 + systemd / cron 组合覆盖"查—控—自启—定时—排障"全流程，无需 GUI。
⚠️ 命令繁多、BSD / SystemV 选项风格不一；systemd unit 与 cron 环境有坑（PATH、时区）；误用 kill -9 可致数据不一致。

## 常见误区

- kill -9 是最干净的停进程方式、应优先使用。
- 僵尸进程可以用 kill 杀掉。
- cron 任务继承交互式 shell 的完整 PATH 环境。
