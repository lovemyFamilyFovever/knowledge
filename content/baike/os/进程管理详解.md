# 进程管理详解

## 概述

**一句话定义：** 本文汇总 Linux 下进程与服务的实战管理命令——进程查看(ps/top)、信号控制(kill)、后台运行(nohup/&)、服务管理(systemd)、定时任务(cron)、优先级(nice)、僵尸/孤儿进程、/proc 与日志(dmesg/journalctl)。

> 多义说明：本文侧重 **Linux 命令与运维实操**；进程/线程/调度的**概念原理**见 [[操作系统核心]]、[[操作系统基础术语]]、[[线程]]、[[进程调度]]、[[进程间通信]]。

## ps — 进程快照

**一句话定义：** `ps` 命令在某一时刻对进程进行"拍照"，显示当前系统中所有进程的静态信息。

**通俗类比：** 就像给教室拍一张照片，能看到此刻谁在座位上、谁在走动、谁在睡觉。

**具体示例：**
```bash
# BSD 风格（常用）
ps aux
#  USER  PID %CPU %MEM  VSZ RSS TTY STAT START TIME COMMAND
#  root    1  0.0  0.1 168M 20M ?   Ss   10:00 0:01 /sbin/init

# System V 风格
ps -ef

# 自定义输出列
ps -eo pid,ppid,user,%cpu,%mem,vsz,rss,stat,start,time,comm --sort=-%mem

# 查找特定进程
ps aux | grep -E "nginx|apache" | grep -v grep

# 查看进程树
ps -ef --forest
pstree
```

## top / htop — 实时监控

**一句话定义：** `top` 和 `htop` 以动态刷新的方式实时显示系统资源使用情况和进程排名。

**通俗类比：** `top` 像看股票行情大屏，数字不断跳动；`htop` 像升级版行情软件，支持鼠标操作、彩色显示。

**具体示例：**
```bash
# top 交互快捷键
top
# P - 按 CPU 排序
# M - 按内存排序
# k - 杀死进程（输入 PID）
# q - 退出

# 只显示特定用户
top -u mysql

# htop（需安装）
sudo apt install htop
htop
htop -p 1234,5678    # 监控指定进程
htop -u www-data     # 只看指定用户
```

## kill — 发送信号

**一句话定义：** `kill` 命令向进程发送信号，可以终止、重启或以其他方式控制进程行为。

**常用信号：**
| 信号 | 编号 | 作用 | 类比 |
|------|------|------|------|
| SIGHUP | 1 | 挂起/重载配置 | 打招呼"嘿，还在吗？" |
| SIGINT | 2 | 中断（Ctrl+C） | 请停下来 |
| SIGKILL | 9 | 强制杀死（不可捕获） | 直接拔电源 |
| SIGTERM | 15 | 优雅终止（默认） | 请收拾好东西离开 |
| SIGUSR1 | 10 | 用户自定义信号 | 自定义指令 |
| SIGSTOP | 19 | 暂停进程 | 按下暂停键 |
| SIGCONT | 18 | 继续运行 | 按下播放键 |

```bash
kill 1234              # 默认发送 SIGTERM
kill -9 1234           # 强制杀死（最后手段）
kill -HUP 1234         # 重载配置（如 nginx）
kill -USR1 1234        # 发送自定义信号
kill -STOP 1234        # 暂停
kill -CONT 1234        # 恢复
killall nginx          # 杀死所有 nginx 进程
pkill -f "python app"  # 按命令名匹配杀进程
```

## nohup 与后台运行

**一句话定义：** 让进程在终端关闭后继续运行，不被 SIGHUP 信号打断。

**通俗类比：** 你在离开办公室时给同事说"这个任务你盯着，我走了也别停"。

```bash
# 方式1：nohup（输出重定向到 nohup.out）
nohup python3 app.py &

# 方式2：直接用 &（终端关闭时进程会收到 SIGHUP）
python3 app.py &

# 方式3：disown（从当前 shell 的作业表中移除）
python3 app.py &
disown %1

# 查看后台任务
jobs -l

# 方式4：screen / tmux（推荐）
screen -S mysession    # 创建会话
# ... 运行命令 ...
# Ctrl+A D 分离会话
screen -ls             # 列出会话
screen -r mysession    # 重新连接
```

## systemd — 服务管理

**一句话定义：** 现代 Linux 的初始化系统和服务管理器，替代了传统的 init 和 SysV 脚本。

**通俗类比：** systemd 是整个系统的"总调度"，负责启动、停止、监控所有服务，就像酒店的前台经理管理所有部门。

```bash
# 基本操作
systemctl start nginx          # 启动服务
systemctl stop nginx           # 停止服务
systemctl restart nginx        # 重启服务
systemctl reload nginx         # 重载配置（不中断服务）
systemctl status nginx         # 查看状态
systemctl enable nginx         # 开机自启
systemctl disable nginx        # 取消开机自启
systemctl is-active nginx      # 是否正在运行
systemctl is-enabled nginx     # 是否开机自启

# 查看所有服务
systemctl list-units --type=service
systemctl list-units --type=service --state=running

# 查看服务日志
journalctl -u nginx -f         # 实时查看
journalctl -u nginx --since today  # 今天的日志
```

### 自定义 Unit 文件

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My Python Application
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/python3 /opt/myapp/app.py
Restart=always
RestartSec=5
Environment=APP_ENV=production
Environment=APP_PORT=8000

[Install]
WantedBy=multi-user.target
```

```bash
# 加载并启用自定义服务
sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp
```

## cron 定时任务

**一句话定义：** cron 是 Linux 的定时任务调度器，按预定时间自动执行脚本或命令。

**通俗类比：** 就像设定闹钟——每天早上8点、每周一、每月1号，到点自动触发。

### crontab 语法

```
┌───────────── 分钟 (0-59)
│ ┌───────────── 小时 (0-23)
│ │ ┌───────────── 日 (1-31)
│ │ │ ┌───────────── 月 (1-12)
│ │ │ │ ┌───────────── 星期几 (0-7, 0和7都是周日)
│ │ │ │ │
* * * * * command_to_execute
```

**特殊字符串：**
| 字符 | 含义 |
|------|------|
| `*` | 任意值 |
| `,` | 列表（如 1,3,5） |
| `-` | 范围（如 1-5） |
| `/` | 步长（如 */5 表示每5） |
| `@reboot` | 开机时执行 |
| `@daily` | 每天执行 |
| `@weekly` | 每周执行 |

```bash
# 编辑当前用户的 crontab
crontab -e

# 查看当前用户的 crontab
crontab -l

# 示例
# 每天凌晨2点备份数据库
0 2 * * * /usr/bin/mysqldump -u root mydb > /backup/db_$(date +\%Y\%m\%d).sql

# 每5分钟检查一次服务
*/5 * * * * /opt/scripts/check_service.sh

# 每周一早上8点发报告
0 8 * * 1 /opt/scripts/weekly_report.sh

# 每月1号清理日志
0 0 1 * * /opt/scripts/clean_logs.sh

# 开机时执行
@reboot /opt/scripts/startup.sh
```

## 前台与后台任务切换

```bash
# 将前台任务放到后台
# 先按 Ctrl+Z 暂停，然后：
bg          # 放到后台继续运行
fg          # 拉回前台
fg %2       # 拉回指定任务（job编号）

# 查看后台任务
jobs -l

# 输出示例：
# [1]+ 12345 Running    python3 app.py &
# [2]- 12346 Stopped    vim file.txt

# 恢复暂停的任务
bg %2       # 在后台继续
fg %2       # 拉回前台
```

## 进程优先级（nice/renice）

**一句话定义：** nice 值决定进程的调度优先级，范围 -20（最高）到 19（最低），值越大越"谦让"。

**通俗类比：** nice 值高的进程就像"谦让的乘客"，让其他进程先用 CPU；nice 值低的像"VIP"，优先获得 CPU。

```bash
# 以指定 nice 值启动程序
nice -n 10 python3 heavy_task.py     # 降低优先级
nice -n -5 ./important_task.sh       # 提高优先级（需 root）

# 修改运行中进程的优先级
renice 15 -p 1234        # 将 PID 1234 的 nice 值改为 15
renice -5 -p 1234        # 提高优先级（需 root）
```

## 僵尸进程与孤儿进程

**僵尸进程（Zombie）：** 子进程已结束，但父进程还没回收它的退出状态，进程描述符仍留在进程表中。

**孤儿进程（Orphan）：** 父进程已结束，子进程还在运行，被 init（PID 1）收养。

```bash
# 查找僵尸进程
ps aux | awk '$8 ~ /Z/ {print}'

# 查找父进程
ps -o pid,ppid,stat,cmd -p <zombie_pid>

# 杀死父进程来清理僵尸
kill -9 <parent_pid>

# 查找孤儿进程（PPID 为 1 的非 init 进程）
ps -eo pid,ppid,stat,cmd | awk '$2 == 1 && $1 != 1'
```

## /proc 文件系统

**一句话定义：** `/proc` 是一个虚拟文件系统，以文件形式暴露内核数据和进程信息。

**通俗类比：** `/proc` 就像系统的"体检报告"，每个进程都有对应的文件夹，里面是它的各项指标。

```bash
# 系统信息
cat /proc/cpuinfo         # CPU 信息
cat /proc/meminfo         # 内存信息
cat /proc/loadavg         # 系统负载
cat /proc/uptime          # 运行时间

# 进程信息
cat /proc/<pid>/status    # 进程状态
cat /proc/<pid>/cmdline   # 启动命令
cat /proc/<pid>/maps      # 内存映射
cat /proc/<pid>/fd/       # 打开的文件描述符
ls -la /proc/<pid>/fd/    # 进程打开的文件
```

## dmesg — 内核日志

**一句话定义：** 显示内核环形缓冲区的内容，包含硬件检测、驱动加载、内核错误等底层信息。

```bash
# 查看全部内核日志
dmesg

# 只看最近的
dmesg | tail -20

# 只看错误和警告
dmesg -l err,warn

# 按时间过滤
dmesg -T | grep "2026"

# 实时跟踪
dmesg -w
```

---

## journalctl — 系统日志

**一句话定义：** systemd 的日志管理工具，统一查看系统和各服务的日志。

```bash
# 查看所有日志
journalctl

# 按服务筛选
journalctl -u nginx
journalctl -u nginx -u php-fpm   # 多个服务

# 按时间筛选
journalctl --since "2026-08-20"
journalctl --since "2026-08-20 10:00" --until "2026-08-20 12:00"
journalctl --since today

# 按优先级
journalctl -p err               # 只看错误
journalctl -p warning           # 只看警告

# 实时跟踪
journalctl -f
journalctl -u nginx -f          # 实时跟踪 nginx 日志

# 清理旧日志
journalctl --vacuum-time=30d    # 保留30天
journalctl --vacuum-size=500M   # 保留500MB
```

## systemctl 与 cron 综合示例

### 示例1：创建一个 Web 应用的 systemd 服务

```bash
# 1. 编写服务文件
sudo tee /etc/systemd/system/webapp.service << 'EOF'
[Unit]
Description=Node.js Web Application
After=network.target

[Service]
Type=simple
User=deploy
Group=deploy
WorkingDirectory=/opt/webapp
ExecStart=/usr/bin/node /opt/webapp/server.js
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
Environment=NODE_ENV=production
Environment=PORT=3000

[Install]
WantedBy=multi-user.target
EOF

# 2. 启用并启动
sudo systemctl daemon-reload
sudo systemctl enable webapp
sudo systemctl start webapp

# 3. 查看状态
sudo systemctl status webapp
sudo journalctl -u webapp -f
```

### 示例2：使用 cron 定期清理日志

```bash
# 编写清理脚本
cat > /opt/scripts/clean_logs.sh << 'EOF'
#!/bin/bash
# 清理30天前的日志
find /var/log/myapp -name "*.log" -mtime +30 -delete
# 清理超过500MB的归档文件
find /var/log/myapp -name "*.gz" -size +500M -delete
echo "$(date): Log cleanup completed" >> /var/log/clean_logs.log
EOF

chmod +x /opt/scripts/clean_logs.sh

# 添加 cron 任务
(crontab -l 2>/dev/null; echo "0 3 * * * /opt/scripts/clean_logs.sh") | crontab -
```

## 常见误区

- `kill -9`（SIGKILL）不可被捕获/忽略，进程来不及清理（刷盘、释放锁、删临时文件）；应优先 `kill -15`（SIGTERM）优雅退出，-9 只作最后手段。
- 僵尸进程无法用 kill 杀死（它已终止，只是父进程未回收其退出状态）；应让父进程 wait，或终止父进程使其被 init 收养后回收。
- cron 环境变量极简（PATH 很短），脚本务必用绝对路径或在 crontab 里显式设置 PATH。
