# 容器运行时


> 📌 **导航**：本文是 **容器运行时** 词条，属于 os 术语集。相关枢纽：[[Shell 脚本详解]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 容器运行时（Container Runtime）是负责实际运行容器的软件，底层依赖 Linux 内核的 **namespace（隔离）** 与 **cgroup（资源限制）**，把打包好的镜像跑成受隔离、受资源约束的普通进程。

**通俗类比：** 若把容器镜像比作「集装箱货物清单」，容器运行时就是港口的吊车与堆场——按清单把货物（进程）安置进一个独立、互不干扰的隔间，并限定它能用多少水电（资源）。

> 多义说明：容器运行时分**高级运行时**（Docker、Podman、containerd，负责镜像管理、构建、与编排对接）与**低级运行时**（runc、crun，真正调用内核创建容器）；容器 ≠ 虚拟机——容器共享宿主内核，VM 各自带完整操作系统。

## 原理与机制

- **两大内核基石**：**Namespace** 提供隔离视图（进程、网络、挂载、用户等各看各的），**cgroup** 提供资源限额（CPU、内存、I/O）。二者结合，使容器成为「被隔离 + 被限量」的进程。
- **OCI 规范**（Open Container Initiative）统一接口，使不同运行时可互换：

```
OCI Runtime Spec      -> 定义容器「如何运行」（config.json + 生命周期）
OCI Image Spec        -> 定义镜像格式（分层、清单）
OCI Distribution Spec -> 定义镜像如何分发（registry 推拉）
```

- **运行时分层**（高级 → 低级 → 内核）：

```
Docker / Podman    (高级运行时：镜像、构建、CLI)
      │
containerd / CRI-O (容器管理：生命周期、对接编排)
      │
runc / crun        (OCI 低级运行时：真正创建容器)
      │
Linux Kernel       (cgroups + namespaces)
```

## 关键组成

### Namespace（隔离）

| Namespace | 隔离内容 | clone 标志 |
|-----------|----------|-----------|
| PID | 进程 ID（容器内自成 PID 1） | CLONE_NEWPID |
| NET | 网络栈（网卡/IP/端口/路由） | CLONE_NEWNET |
| MNT | 挂载点/文件系统视图 | CLONE_NEWNS |
| UTS | 主机名与域名 | CLONE_NEWUTS |
| IPC | 进程间通信（信号量/消息队列） | CLONE_NEWIPC |
| USER | 用户/组 ID 映射 | CLONE_NEWUSER |
| Cgroup | cgroup 根视图 | CLONE_NEWCGROUP |
| TIME | 系统时钟（Linux 5.6+ 新增） | CLONE_NEWTIME |

### cgroup（资源限制，v2 统一层级）

```bash
# 限制 CPU：每 100ms 周期内最多用 50ms → 约 50% 单核
echo "50000 100000" > /sys/fs/cgroup/myapp/cpu.max
# 限制内存上限 512MB
echo "512M" > /sys/fs/cgroup/myapp/memory.max
```

## 应用场景

- Kubernetes/Docker 部署微服务；CI/CD 构建与运行；本地开发环境隔离；多租户资源隔离（配合 gVisor/Kata 等安全容器增强隔离）。

## 优点与局限

- 优点：共享宿主内核，启动快（毫秒/秒级）、开销小、部署密度高、镜像可移植（OCI 标准化）。
- 局限：隔离性弱于虚拟机（共享内核，存在逃逸风险，故有 Kata/gVisor 等「安全容器」）；强依赖 Linux 内核特性（Windows/macOS 上需借 Linux 虚拟机承载）。

## 常见误区

- **容器 ≠ 轻量虚拟机**：容器是**受隔离的进程**、共享宿主内核；VM 通过 Hypervisor 运行完整独立 OS。
- 以为 Docker 直接管理容器：Docker（高级）实际经 containerd → runc（低级）→ 内核，runc 才是真正「运行」容器的一层。
- 以为容器天然安全隔离：默认共享内核，需 USER namespace、只读根、seccomp、安全容器等手段加固。
