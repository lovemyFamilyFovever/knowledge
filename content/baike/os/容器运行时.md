# 容器运行时


> 📌 **导航**：本文是 **容器运行时** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 容器运行时（Container Runtime）是负责实际运行容器的软件，底层依赖 Linux 内核的 namespace（隔离）与 cgroup（资源限制），把打包好的镜像跑成一个受隔离、受资源约束的普通进程。

**通俗类比：** 若把容器镜像比作"集装箱货物清单"，容器运行时就是港口的吊车与堆场——按清单把货物（进程）安置进一个独立、互不干扰的隔间，并限定它能用多少水电（资源）。

> 多义说明：分高级运行时（Docker、Podman、containerd，管镜像 / 构建 / 对接编排）与低级运行时（runc、crun，真正调用内核创建容器）；容器 ≠ 虚拟机——容器共享宿主内核，VM 各带完整操作系统。

## 为什么需要它

要在同一台机器上密集、快速、可移植地跑大量相互隔离的应用，虚拟机的完整客户 OS 太重。容器把"隔离 + 限量"下沉到内核原语（namespace / cgroup），启动毫秒级、开销小、镜像标准化可搬，是云原生交付的基础执行单元。

## 核心机制

- **两大内核基石：** Namespace 提供隔离视图（进程 / 网络 / 挂载 / 用户等各看各的），cgroup 提供资源限额（CPU / 内存 / I/O），二者结合使容器成为"被隔离 + 被限量"的进程。
- **运行时分层（高级 → 低级 → 内核）：** Docker / Podman（镜像、构建、CLI）→ containerd / CRI-O（生命周期、对接编排）→ runc / crun（OCI 低级运行时，真正创建容器）→ Linux 内核（cgroups + namespaces）。
- **OCI 规范统一接口使各运行时可互换：** Runtime Spec 定义"如何运行"、Image Spec 定义镜像分层与清单格式、Distribution Spec 定义 registry 推拉。
- **常见 Namespace 类型：** PID、NET、MNT、UTS、IPC、USER、Cgroup、TIME（Linux 5.6+），各以 `CLONE_NEW*` 标志创建，容器内可自成 PID 1。

## 具体示例

cgroup v2 下限制某容器应用的 CPU 与内存——写这两个文件即可，运行时的资源约束最终落到内核 cgroup 接口上：

```bash
echo "50000 100000" > /sys/fs/cgroup/myapp/cpu.max     # 每 100ms 周期最多用 50ms ≈ 半核
echo "512M"          > /sys/fs/cgroup/myapp/memory.max  # 内存上限 512MB，超则 OOM
```

## 何时用与何时不用

- **用：** Kubernetes / Docker 部署微服务、CI/CD 构建运行、本地开发隔离、多租户资源隔离（配 gVisor / Kata 增强）。
- **不用：** 不可信多租户要强隔离时，共享内核有逃逸风险，改用 VM 或安全容器（Kata / gVisor）；非 Linux 平台需借 Linux 虚拟机承载。

## 优劣与代价

✅ 共享宿主内核，启动快（毫秒 / 秒级）、开销小、部署密度高、镜像可移植（OCI 标准化）。
⚠️ 隔离性弱于虚拟机（共享内核、有逃逸风险，故有安全容器）；强依赖 Linux 内核特性。

## 与相关概念的区别

vs 虚拟机：VM 经 Hypervisor 跑各自完整客户 OS、隔离强但重，容器是共享宿主内核的受隔离进程、轻但隔离弱；vs [[操作系统核心]]：namespace / cgroup 是内核机制，容器运行时是把它们编排起来的用户态软件栈。

## 常见误区

- 容器本质上就是一个轻量级虚拟机。
- Docker 直接调用内核来运行容器。
- 容器天生隔离安全，不需要额外加固。

## 面试速答

> 🎯 容器运行时 = 用内核 namespace 做隔离、cgroup 做限额，把镜像跑成受约束的进程；栈分层 Docker/containerd → runc（低级、真正创建）→ 内核，遵循 OCI 规范可互换；容器 ≠ 虚拟机（共享宿主内核）。
