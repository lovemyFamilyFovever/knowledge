## 一、进程、线程与协程

### 进程（Process）

**一句话定义：** 程序被加载到内存并运行起来的实例，是操作系统**分配资源**的基本单位（拥有独立地址空间、文件描述符等）。

```bash
ps aux          # 查看所有进程
pstree          # 进程树
python3 app.py  # 启动一个进程
```

### 线程（Thread）

**一句话定义：** 进程内部的执行单元，是 **CPU 调度**的基本单位；同进程内多线程共享地址空间与资源。

> 📎 详见 [[线程]]（生命周期、并发模型、与进程的取舍）。

### 协程（Coroutine）

**一句话定义：** 比线程更轻量的**用户态**执行体，可主动挂起/恢复，由程序协作式调度（非内核抢占），切换成本极低。

```python
import asyncio
async def fetch():
    await asyncio.sleep(1)   # 主动让出控制权
    return "数据已获取"
asyncio.run(fetch())
```
> 适合高并发 I/O；单线程内的协程是**并发非并行**，用多核需配合多线程。

### 进程 vs 线程（对比）

| 维度 | 进程 | 线程 |
|------|------|------|
| 地址空间 | 独立 | 共享所属进程 |
| 创建/切换开销 | 大 | 小 |
| 通信 | IPC（管道/消息队列/共享内存，见 [[进程间通信]]） | 共享变量（需同步） |
| 崩溃影响 | 一般不影响其他进程 | 可能拖垮整个进程 |
| 角色 | 资源分配单位 | CPU 调度单位 |

### 上下文切换（Context Switch）

**一句话定义：** CPU 从一个任务切到另一个时，保存当前任务状态、恢复目标任务状态的过程；切换有成本，过于频繁会拖累吞吐。

```bash
vmstat 1        # 输出中的 cs 列即每秒上下文切换次数
```

## 二、内存管理（详见 [[虚拟内存]]）

### 虚拟内存（Virtual Memory）

**一句话定义：** 每个进程看到的独立「假」地址空间，由 OS + MMU 映射到物理内存或磁盘，实现隔离、按需加载与「超过物理内存」的使用。

> 📎 详见 [[虚拟内存]]。

### 页表（Page Table）与 TLB

**一句话定义：** 页表记录虚拟页 → 物理页帧的映射（OS 维护、MMU 使用）；TLB 是页表项的高速缓存，避免每次访存都遍历多级页表。

### 分页 / 分段

- **分页**：内存切成固定大小页（常见 4 KB），消除外部碎片。
- **分段**：按逻辑段（代码段/数据段/栈段）划分，更贴合程序结构。
- 现代系统多用**段页式**结合二者优点。

### 页面置换算法

物理内存不足时，选择淘汰哪一页：

| 算法 | 策略 | 类比 |
|------|------|------|
| LRU（最近最少使用） | 淘汰最久未访问的页 | 清理最久没人借的书 |
| LFU（最不经常使用） | 淘汰访问次数最少的页 | 清理借阅量最低的书 |
| FIFO（先进先出） | 淘汰最早进入的页 | 先到先走（可能出现 Belady 异常） |

### 内存映射（mmap）

**一句话定义：** 把文件或设备映射进进程虚拟地址空间，读写内存即读写文件，省去 read/write 在用户态↔内核态之间的**额外拷贝**，适合大文件 I/O 与共享内存。

## 三、用户态与内核交互

### 用户态与内核态

**一句话定义：** CPU 的两种特权级别——用户态只能执行非特权指令，内核态可执行全部特权指令；特权隔离保障系统稳定与安全。

> 📎 详见 [[用户态与内核态]]。

### 系统调用（System Call）

**一句话定义：** 用户程序请求内核服务的接口，是用户态进入内核态的**受控入口**（如 read/write/fork）。

> 📎 详见 [[系统调用]]；用 `strace ls` 可跟踪一次命令触发的系统调用。

### 中断（Interrupt）

**一句话定义：** 硬件或软件向 CPU 发出的信号，令其暂停当前流程转去处理事件、处理完再返回；避免 CPU 低效轮询设备状态。

> 📎 详见 [[中断]]。

## 四、同步原语与死锁（详见 [[信号量与互斥锁]]、[[死锁]]）

### 互斥锁（Mutex）

**一句话定义：** 保证同一时刻只有一个线程进入临界区，避免数据竞争（race condition）。

> 📎 详见 [[信号量与互斥锁]]。

### 信号量（Semaphore）

**一句话定义：** 用整型计数配合 P(wait)/V(signal) 操作，控制**多个**线程对有限资源的并发访问上限（互斥锁是其取值 0/1 的特例）。

> 📎 详见 [[信号量与互斥锁]]。

### 条件变量（Condition Variable）

**一句话定义：** 允许线程在条件不满足时等待（wait）、由其他线程在条件满足时通知（notify/signal）；须与互斥锁配合，且等待前后用 `while` 复查条件以防**虚假唤醒**。

### 自旋锁（Spinlock）

**一句话定义：** 获取失败时不挂起、而是忙等（自旋）反复重试，适合锁持有时间极短的场景。

| 维度 | 自旋锁 | 互斥锁 |
|------|--------|--------|
| 等待方式 | 忙等（占用 CPU） | 挂起（让出 CPU） |
| 适用 | 临界区极短 | 临界区较长 |
| 开销 | 无线程切换、但空耗 CPU | 有切换开销 |

### 死锁（Deadlock）

**一句话定义：** 多个进程/线程互相持有对方所需资源又互相等待，导致全部无法继续推进。

**四个必要条件**：互斥、占有并等待、不可剥夺、循环等待——破坏其中任一即可预防（如按固定顺序申请资源）。

> 📎 详见 [[死锁]]。
