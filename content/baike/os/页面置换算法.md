# 页面置换算法


> 📌 **导航**：本文是 **页面置换算法** 词条，属于 os 术语集。相关枢纽：[[Shell脚本编程]]、[[操作系统基础术语]]、[[操作系统核心]]、[[进程管理详解]]。

## 定义

**一句话定义：** 页面置换算法（Page Replacement Algorithm）是虚拟内存管理中，当发生缺页中断且物理内存已满时，操作系统用来决定"淘汰哪一页换出到磁盘、腾出帧给新页"的策略，目标是最小化缺页率。

**通俗类比：** 像书桌（内存）只能摊开几本书，要用的新书没地方放时得决定把哪本先放回书架（换出）——放错了下次又要跑去拿（缺页），所以"该放哪本"很有讲究。

> 多义说明：页面置换是虚拟内存 / 分页管理的一部分（见 [[虚拟内存]]）；本文聚焦"选哪一页淘汰"的算法。

## 为什么需要它

进程需要的页总数常超过物理帧数，新页调入时内存已满，就必须选一页换出。选得好，被换出的页短期内不再用、缺页少；选得差，刚换出又要用、频繁缺页甚至抖动。置换策略直接决定虚拟内存的实际性能。

## 核心机制

- **OPT（最优）：** 淘汰未来最久不再使用的页——理论最优但需预知未来、不可实现，仅作性能基准。
- **FIFO（先进先出）：** 淘汰最早进入的页；简单，但可能出现 Belady 异常（帧增多缺页反增）。
- **LRU（最近最少使用）：** 淘汰最久未访问的页、接近 OPT；精确实现开销大（需时间戳 / 栈），实际多用近似。
- **Clock（二次机会）：** LRU 的近似，用访问位环形扫描、开销小，实际系统常用；结合修改位可减少写回。
- **缺页与抖动：** 帧不足 + 糟糕的置换策略 → 频繁缺页甚至抖动（thrashing）。

## 具体示例

对访问序列 `7 0 1 2 0 3 0 4` 在 3 个物理帧下：LRU 用最近使用顺序淘汰、缺页 9 次；而 FIFO 在帧数从 3 增到 4 时缺页有时反而增加——即 Belady 异常。LRU 是栈式算法、不会出现此现象。

## 何时用与何时不用

- **用：** 虚拟内存缺页处理、内存回收、数据库缓冲池管理（类似 LRU / Clock 思想）。
- **不用（选型反面）：** 别在生产环境追求精确 LRU（开销高），用 Clock / 二次机会近似即可；OPT 只用于离线评估算法优劣。

## 优劣与代价

✅ 在有限物理内存下支撑更大的地址空间、提升多道程序度。
⚠️ 好算法（精确 LRU）实现开销大；近似算法次优；FIFO 有 Belady 异常；置换不当会导致抖动。

## 与相关概念的区别

vs [[虚拟内存]]：页面置换只是虚拟内存的一个环节（缺页时选谁换出），虚拟内存是含页表 / TLB / 缺页的整套机制；vs 缓存替换：与 CPU cache / Redis 淘汰思想相通（LRU / LFU），但页面置换要付磁盘 I/O 代价、抖动后果更重。

## 常见误区

- OPT 是最优的，所以实际系统都优先用 OPT。
- 给进程分配的物理帧越多，缺页一定越少。
- LRU 精确实现开销很小、可以到处直接用。

## 面试速答
