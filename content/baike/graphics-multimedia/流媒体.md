# 流媒体


> 📌 **导航**：本文是 **流媒体** 词条，属于 graphics-multimedia 术语集。相关枢纽：[[光栅化]]、[[光线追踪]]、[[全局光照]]、[[图像压缩]]、[[图形渲染管线]]。

## 定义

**一句话定义：** 流媒体(Streaming Media)是将音频、视频等连续媒体以数据流方式"边传输边播放"的技术,用户无需等待整个文件下载完成即可开始观看,传输与播放并行进行。

**通俗类比：** 像用自来水——打开水龙头(点播放)水(数据)就持续流来直接用,不必先蓄满一整缸(下载完整文件)再用;关掉就停,也不在自家存下整缸水。

> 多义说明:流媒体既指传输**技术/方式**,也泛指流媒体**服务/平台**(如视频网站);本文讨论技术层面。

## 原理与机制

- **传输形态:** 渐进式下载(progressive download)与真正的流式传输(streaming);后者支持随机定位与实时直播。
- **主流协议:** RTP/RTCP(实时传输与控制)、RTSP(会话控制),以及基于 HTTP 的 HLS(HTTP Live Streaming)与 MPEG-DASH。
- **自适应码率(ABR):** 把媒体切成小分片并编码成多档清晰度,客户端按实时带宽动态切换,兼顾流畅与画质。
- **缓冲(buffering):** 预存一小段数据以吸收网络抖动,减少卡顿。
- 依赖 [[视频编解码器]] 对媒体压缩(H.264/HEVC/AV1)以降低带宽。

## 关键组成

| 环节 | 作用 |
|------|------|
| 编码器 | 采集并压缩为流式格式 |
| 流媒体服务器 / CDN | 分发数据流、就近服务 |
| 传输协议 | HLS / DASH / RTSP / RTP |
| 客户端播放器 | 解析、缓冲、解码、播放 |
| 缓冲区 | 平滑网络波动 |

## 应用场景

- 视频点播与直播(影视、赛事、带货)
- 音视频通话与在线会议
- 在线音乐、播客
- 云游戏与远程桌面

## 优点与局限

- 优点:即点即播、无需完整下载、节省本地存储、天然支持直播与实时互动。
- 局限:强依赖网络质量;存在端到端延迟(直播尤甚);需要服务器与带宽成本;版权保护(DRM)较复杂。

## 常见误区

- 流媒体 ≠ 下载:流式播放通常不在本地留存完整文件。
- 直播"零延迟"不现实:采集、编码、分发、缓冲都会引入数秒级延迟。
- HLS/DASH 是"基于 HTTP 的分片流",与传统 RTSP/RTP 长连接流在机制上不同。
