# 图形渲染管线

## 定义

**一句话定义：** 图形渲染管线是把三维场景描述(几何、材质、光照、相机)转换为二维屏幕像素的一系列有序处理阶段,是实时图形学(游戏、可视化)的核心流程。

**通俗类比：** 像一条汽车装配流水线——零件(顶点)进入后,依次经过冲压、焊接、喷漆、质检(各处理阶段),每个工位只做一件事并传给下一个,最终下线一辆整车(一帧画面)。多个工位并行工作,整体吞吐很高。

> 多义说明:本文讨论的是**图形渲染管线**(graphics/rendering pipeline),而非 CPU 指令流水线;二者思想相通但对象不同。

## 原理与机制

管线整体分为**可编程阶段**(着色器可改写)与**固定功能阶段**(由 API/硬件定义)。数据以"顶点 → 图元 → 片元 → 像素"的形态逐级流动,并通过大规模并行(SIMD/SIMT)在 GPU 上执行。

典型顺序:应用阶段(CPU 准备数据与绘制命令)→ 几何阶段(顶点处理、裁剪、屏幕映射)→ 光栅化(图元转片元)→ 片元处理(着色、纹理采样)→ 逐片元操作(深度/模板测试、混合)→ 帧缓冲。

## 关键组成

| 阶段 | 位置 | 主要工作 |
|------|------|----------|
| 顶点着色器(Vertex Shader) | 可编程 | 逐顶点变换、光照计算 |
| 图元装配 + 裁剪 | 固定功能 | 组装三角形、裁掉视锥外部分 |
| 光栅化(Rasterization) | 固定功能 | 图元离散为片元(fragment) |
| 片元着色器(Fragment/Pixel Shader) | 可编程 | 逐像素计算颜色、采样纹理 |
| 逐片元操作 | 固定功能 | 深度测试、模板测试、混合(blending) |

## 应用场景

- 游戏引擎与实时三维(Unity/Unreal)
- CAD、建筑可视化、医学影像渲染
- 数据可视化与科学计算可视化
- UI 合成与 GPU 加速绘制

## 优点与局限

- 优点:阶段解耦、高度并行、吞吐高,是实时渲染(每帧毫秒级)的基础。
- 局限:传统前向管线难以高效处理大量动态光源与全局光照;固定功能阶段灵活性受限;片元/顶点着色器负载不均会造成 GPU 瓶颈。

## 常见误区

- 误以为"渲染 = 光栅化":光栅化只是其中一个阶段。
- 误以为管线全在 GPU:应用阶段(剔除、提交 draw call)在 CPU,CPU 瓶颈会导致 GPU 空闲。
- 把延迟渲染(Deferred)当作唯一正确方案:它与前进渲染(Forward)各有取舍(光源数量 vs 带宽/MSAA)。
