# 图形渲染管线


> 📌 **导航**：本文是 **图形渲染管线** 词条，属于 graphics-multimedia 术语集。相关枢纽：[[光栅化]]、[[光线追踪]]、[[全局光照]]、[[图像压缩]]、[[图形渲染管线]]。

## 定义

**一句话定义：** 图形渲染管线是把三维场景描述（几何、材质、光照、相机）转换为二维屏幕像素的一系列有序处理阶段，是实时图形学的核心流程。

**通俗类比：** 像汽车装配流水线——零件（顶点）依次经过冲压、焊接、喷漆、质检（各阶段），每个工位只做一件事并传给下一个，最终下线整车（一帧画面）。

## 为什么需要它

GPU 无法一次性完成"从三角面片到屏幕像素"的全部工作——管线将任务拆为可并行、可流水的多个阶段，使千万像素在 16ms 内完成更新（60FPS），是实时渲染的工程基础。

## 核心机制

数据形态从"顶点→图元→片元→像素"逐级流动：

| 阶段 | 类型 | 职责 |
|------|------|------|
| 应用阶段（CPU） | — | 剔除、提交 draw call |
| 顶点着色器 | 可编程 | 坐标变换（模型→世界→视→裁剪） |
| 图元装配+裁剪 | 固定 | 组装三角形、裁掉视锥外 |
| 光栅化 | 固定 | 图元离散为片元 |
| 片元着色器 | 可编程 | 计算颜色、采样纹理 |
| 逐片元操作 | 固定 | 深度/模板测试、混合 |

可编程阶段由开发者写着色器代码控制，固定阶段由硬件/API 定义。

## 具体示例

渲染 10000 个三角形场景：CPU 做视锥剔除后提交 draw call → GPU 顶点着色器 10000 次并行变换 → 光栅化器生成 ~200 万片元 → 片元着色器并行采样纹理+光照 → 深度测试丢弃 ~40% 被遮挡片元 → 写入帧缓冲。

## 何时用与何时不用

- **用**：所有实时 3D 渲染（游戏/CAD/UI 合成）；现代图形 API（Vulkan/Metal/D3D12）都基于管线模型。
- **不用**：离线光线追踪渲染器（无固定管线，按光线求交+着色循环）。

## 优劣与代价

✅ 阶段解耦+大规模并行实现每帧毫秒级吞吐。
✅ 可编程着色器灵活度极高。
⚠️ CPU draw call 提交常成瓶颈（GPU 等 CPU）。
⚠️ 片元/顶点负载不均导致 GPU 利用率波动。

## 与相关概念的区别

- **vs 光线追踪管线**：传统管线正向投影（顶点→像素），光线追踪反向（像素→场景求交）；前者吞吐高、后者精确处理全局光照。
- **vs 延迟渲染/前向渲染**：都是管线上组织光照计算的方式——前向逐光源画场景（光源多时重复绘制），延迟先 GBuffer 存属性后一次光照。

## 常见误区

- "渲染 = 光栅化"：光栅化只是其中一个阶段。
- 管线全在 GPU：应用阶段在 CPU，CPU 瓶颈会让 GPU 空闲。
- 延迟渲染一定优于前向渲染：各有取舍（带宽、MSAA 兼容、透明处理）。
