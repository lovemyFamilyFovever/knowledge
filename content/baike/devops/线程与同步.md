# 线程与同步

> 📌 **导航**：本文是 **线程与同步** 词条，属 [[操作系统内核原理]] 子词条。进程视角见 [[进程与调度]]。

## 定义

**一句话定义：** 线程是 CPU 调度的更细单位，同一进程内的线程共享地址空间；内核用线程模型管理它们，并用互斥锁、条件变量、原子操作等同步原语保证并发下的正确性。

**通俗类比：** 进程像一家公司（独立账户），线程是公司里共享办公室的员工——协作快，但同一台打印机（共享数据）要排队加锁，否则就乱。

## 为什么需要它

进程间地址隔离，共享数据要走 IPC、切换也重。线程共享地址空间、创建切换更轻，便于把一个任务拆成多路并行。但"共享"即"竞态"：多个线程同时读写同一数据会出错，于是必须引入同步原语来约束临界区。

## 核心机制

- **线程模型**：内核级线程 KLT（Linux `pthread_create` 经 `clone()` 实现，内核直接调度；一线程阻塞时同进程其他线程仍可跑，充分利用多核）；用户级线程 ULT（库内调度、切换极快，但一线程阻塞会卡住整进程，多对一，已少用）；二者折中的混合模型。
- **同步原语**：互斥锁（pthread_mutex 先原子自旋、抢不到才经 futex 睡眠）、读写锁（读多写少）、条件变量（必须配互斥锁、`while` 判条件防虚假唤醒）、自旋锁（持锁极短、忙等不睡眠、用于内核临界区）、原子操作（`cmpxchg` 等，最底层基石）。

## 具体示例

经典生产者-消费者：条件变量必须与互斥锁配合，且用 `while` 而非 `if` 判条件以防虚假唤醒：

```c
pthread_mutex_lock(&m);
while (count == 0)              // 用 while 防虚假唤醒
    pthread_cond_wait(&cv, &m); // 原子地释放锁并挂起
int item = queue[--count];
pthread_mutex_unlock(&m);
```

## 何时用与何时不用

- **用**：多核上并行计算、共享内存的流水线/工作线程池；读多写少用读写锁。
- **不用**：纯 IO 等待用异步/事件循环更省（见 [[协程]]）；临界区很长时别用自旋锁（空转烧 CPU）。

## 优劣与代价

✅ 线程共享地址、创建切换轻，利于多核并行。
✅ 锁/原子/条件变量组合可表达丰富同步协议。
⚠️ 共享带来竞态与死锁风险，锁粒度与顺序易错。
⚠️ 自旋锁/频繁上下文切换会空烧 CPU；纯 IO 场景线程不如异步。

## 与相关概念的区别

- **KLT vs ULT**：KLT 由内核调度、阻塞隔离好；ULT 全在用户态、一线程阻塞即全进程停摆。
- **互斥锁 vs 自旋锁**：前者睡眠让出 CPU，后者忙等——按临界区长短选。
- **线程 vs 进程**：线程共享地址、轻；进程隔离、稳。

## 常见误区

- 多个线程可以同时持有同一把写锁。
- 条件变量可以脱离互斥锁单独使用。
- 自旋锁适合持有时间很长的临界区。

## 面试速答

> 🎯 线程共享进程地址、调度更轻；KLT 由内核调度、一线程阻塞时同进程其他线程可继续。同步靠 mutex(futex：先自旋后睡)、读写锁、条件变量(while 防虚假唤醒、必配 mutex)、自旋锁(短临界不睡眠)、原子操作。按临界区长短与读写比例选锁。
