# 蓝绿部署与灰度发布

## 定义

**一句话定义：** 蓝绿部署与灰度发布是两种降低上线风险的发布策略——蓝绿部署维护两套相同环境(蓝 = 当前、绿 = 新版本),通过一次性切换流量实现发布与快速回滚;灰度发布(金丝雀发布)则先把新版本放给一小部分流量/用户,验证无误后再逐步扩大至全量。

**通俗类比：** 蓝绿像"准备好一间全新装修的店面(绿),择时把顾客一次性引过去,旧店(蓝)留着随时可退回";灰度像"新菜品先给 5% 的客人试吃,反馈好再逐步推给所有人",风险渐进可控。

> 多义说明:二者是不同策略(蓝绿 = 双环境一次切换;灰度/金丝雀 = 按比例渐进),常与滚动更新(rolling update)并列。本文对比蓝绿与灰度。

## 原理与机制

- **蓝绿部署:** 准备两套环境,负载均衡/网关把流量从蓝整体切到绿;回滚即切回蓝。切换瞬间完成,但需双倍资源。
- **灰度 / 金丝雀发布:** 新版本先接小比例流量(如 1% → 5% → 50% → 100%),监控错误率/延迟/业务指标,异常则回滚;可按用户、地域、设备分流。
- **支撑设施:** 负载均衡、流量网关、特性开关(feature flag)、监控与自动回滚、健康检查。

## 关键组成

| 组成 | 作用 |
|------|------|
| 双环境(蓝/绿) | 蓝绿部署的基础 |
| 流量切换 | 一次性或按比例 |
| 灰度比例 | 金丝雀的流量放量节奏 |
| 指标监控 | 错误率/延迟/业务指标 |
| 特性开关 | 与发布解耦的功能控制 |
| 回滚机制 | 快速退回旧版本 |

## 应用场景

- 生产环境的安全发布
- 微服务与云原生部署
- A/B 测试、大流量系统的渐进上线
- 降低发布风险与停机时间

## 优点与局限

- 蓝绿:优点=切换快、回滚简单、零停机;局限=双倍资源成本、需处理数据库/schema 兼容、切换瞬间的会话与缓存一致。
- 灰度:优点=风险渐进、用真实流量验证、可自动回滚;局限=发布周期长、需精细流量控制与监控、多版本共存增复杂度、灰度期问题定位较难。

## 常见误区

- 蓝绿 ≠ 灰度:前者整体一次切换,后者按比例渐进。
- 灰度 ≠ A/B 测试:灰度重"安全发布",A/B 重"效果对比",机制相似但目的不同。
- 蓝绿需处理数据库向后兼容(新旧版本可能共用库)。
- 特性开关与灰度常配合,但不是同一回事。
