# 云服务详解

> 📌 **导航**：本文是 **云服务详解** 词条，属于 devops 术语集。相关枢纽：[[Docker容器化完全指南]]、[[Kubernetes云原生实战指南]]、[[Kubernetes深入]]、[[Web安全攻防实战指南]]、[[云服务详解]]。

## 定义

**一句话定义：** 云服务是通过网络按需把计算、存储、数据库等资源像水电一样提供给用户、按用量付费的 IT 资源交付模式。

**通俗类比：** 过去要自己打井取水（自建机房买服务器），现在接上市政自来水管，用多少付多少，水厂的维护和扩容不归你管。

## 为什么需要它

自建机房要提前采购硬件、预留峰值容量、承担运维和折旧，钱压死在资本支出（CapEx）上，还常常一边闲置一边过载。云服务把它换成运营支出（OpEx）：按需申请、弹性伸缩、全球就近部署，SLA 和高可用由厂商兜底，团队得以把精力从"伺候基础设施"转回业务本身。

## 核心机制

按"厂商帮你管到哪一层"划分服务模型，你管的越少、越省心、也越被绑定：

| 模型 | 你负责 | 厂商负责 | 典型 |
|------|--------|----------|------|
| IaaS | 操作系统、运行时、应用、数据 | 虚拟化、网络、存储、机房 | AWS EC2、阿里云 ECS |
| PaaS | 应用与数据 | 连运行时、中间件一起托管 | Heroku、Google App Engine |
| SaaS | 只用软件 | 全套 | Gmail、Salesforce |
| FaaS | 只写函数 | 连服务器都不见，按调用计费 | AWS Lambda、函数计算 |

再按部署形态分：公有云（多租户共享）、私有云（独享资源）、混合云（两者结合）。

## 具体示例

一段处理 API 请求的无服务器函数，部署后无需准备任何服务器，每次调用按执行时长计费、流量来了自动并发扩容——这正是 FaaS"免运维、按次付费"的典型形态。要声明式地开出一台云服务器，则用 Terraform 描述期望资源，`terraform apply` 让云端收敛到该状态。

## 何时用与何时不用

- **用**：流量波峰波谷明显、要快速上线或全球部署、不想养基础设施团队。
- **不用（或慎选模型）**：超低延迟、强合规数据主权要求把数据锁在本地，或长期稳定高负载——此时按需云服务未必比包年自建划算，需算总账。

## 优劣与代价

✅ 弹性伸缩、起步快、把固定成本变可变成本。
✅ 分层服务大幅降低运维负担。
⚠️ 长期高负载下按需计费可能贵过自建，成本失控是常见坑。
⚠️ 深度依赖厂商专有 API 会带来锁定（vendor lock-in）与迁移成本。

## 与相关概念的区别

- **IaaS vs PaaS vs SaaS**：同一条"托管程度"光谱上的不同档位，区别只在你要自己管到哪一层。
- **Serverless vs 容器**：Serverless 连服务器和伸缩都不暴露给你；容器仍需编排（但比裸机轻）。
- **托管 K8s vs 自建 K8s**：AWS EKS、阿里云 ACK 等帮你运维控制面，节点和数据面编排仍归你。
- **对象存储 vs 块存储 vs 文件存储**：对象适合海量非结构化数据、块适合数据库这类低延迟随机读写、文件适合共享目录。

## 常见误区

- 上云就是买台云服务器，和应用跑在本机没有任何区别。
- Serverless 真的完全没有服务器，也不用关心冷启动和执行超时。
- 云服务一定比自建便宜，用量的钱迟早省回来。
