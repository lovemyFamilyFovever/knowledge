# Linux系统管理高级指南

> 📌 **导航**：本页是 **Linux 系统管理** 枢纽。内核/进程/内存/VFS 机制归 [[操作系统内核原理]]，本文索引运维与工具层主题。

## 定义

**一句话定义：** Linux 系统管理是在内核之上对主机做运维治理的能力面——性能分析下钻、网络配置与防火墙、文件系统选型、进程与内存调优、服务托管与 Shell 自动化等，让机器跑得快、连得通、存得稳。

**通俗类比：** 内核机制是"发动机原理"（归 [[操作系统内核原理]]），系统管理是"驾驶与保养"——看仪表找异响、管油电路、选对轮胎、按需调校。

## 为什么需要它

懂内核原理不等于会运维一台 Linux：出故障要能用工具定位瓶颈，网络要能配防火墙与选路，存储要会选文件系统，服务要能托管与调资源。这些"操作层"技能独立于"机制层"，是把 Linux 用于生产的必备功。

## 核心机制

运维/工具层主题各立子词条；机制层走双链、不在此重复：

进程（状态/信号/nice）、内存（THP/swappiness/OOM）、cgroup v2、`sysctl` 调优、systemd 服务托管等属内核机制的运维旋钮，机制细节以 [[操作系统内核原理]] 为准，本文不重复展开。

## 具体示例

一条典型排障链：`dstat -cdnmsg` 看全局哪个资源饱和 → `perf record -g` 找 CPU 热点或 `strace -c` 看慢系统调用 → 若是 IO/网络再上 `tcpdump`；定完瓶颈才谈调 `sysctl` 或换文件系统（见 [[Linux 文件系统选型]]）。

## 何时用与何时不用

- **用**：主机层调优、排障、网络与存储治理、上线前的性能定位。
- **不用**：容器内不该做的事（跑 systemd/写满 host 网络规则）交给编排层；集群服务网格的流量治理不该在每台主机手堆 iptables。

## 优劣与代价

✅ 把"运维一台 Linux"从零散命令整理成分层的工具与选择。
✅ 机制与操作分层：调 sysctl/cgroup 前先在 [[操作系统内核原理]] 弄清原理。
⚠️ 主机层手工治理难以规模化、跨机一致性差，宜代码化/交给编排。
⚠️ 工具多、参数深，误用（如常驻 strace、错选 CoW 给 DB）有代价。

## 与相关概念的区别

- **运维层 vs 机制层**：本页(工具与操作)与 [[操作系统内核原理]](原理)是同一对象的两个抽象层，互补不重复。
- **主机网络 vs 集群网络**：nftables/bridge 管单机，跨机 overlay/服务发现交给 [[Kubernetes 网络（Service 与 Ingress）]]。

## 常见误区

- 会用 top 重启就等于会 Linux 系统管理，不必懂工具分层与 USE 方法。
- 文件系统只是存数据的，选哪个不影响快照、完整性与性能。
- 内核机制和网络配置是一回事，懂一个就够了。

## 面试速答

> 🎯 Linux 系统管理=内核之上的运维/工具层：性能下钻(dstat/perf/strace/tcpdump + USE)、网络治理(nftables/策略路由/VLAN)、文件系统选型、进程内存调优与服务托管。机制层归 [[操作系统内核原理]]。
