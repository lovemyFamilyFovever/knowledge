# 进程与调度

> 📌 **导航**：本文是 **进程与调度** 词条，属 [[操作系统内核原理]] 子词条。线程视角见 [[线程与同步]]。

## 定义

**一句话定义：** 进程是操作系统资源分配与调度的基本单位；内核用状态机刻画其生命周期、用调度器（Linux 默认 CFS）公平分配 CPU，并用多种 IPC 机制让进程协作。

**通俗类比：** 进程像一家家独立经营的店铺（各有账本=地址空间）；调度器是"给每店分配收银台时间"的排班员；IPC 则是店与店之间传货的通道。

## 为什么需要它

多个程序要在有限的 CPU 上"同时"跑、还要交换数据，内核必须：给每个进程独立的资源边界、决定谁何时上 CPU、并提供跨进程通信手段。这三件事撑起多任务操作系统的基本能力。

## 核心机制

- **进程状态机**（task_struct）：R 运行/就绪、S 可中断睡眠、D 不可中断睡眠（等硬件 IO，kill -9 无效）、T 停止、Z 僵尸（已退出、父未 wait 回收）、X 消亡。
- **CFS 完全公平调度**：不用固定时间片，而是按 `vruntime`（虚拟运行时间，= 实际执行 × NICE_0_WEIGHT/权重）把所有可运行任务挂在**红黑树**上，每次选 vruntime 最小（最左节点）执行。nice 越小权重越高、vruntime 涨得越慢、分到 CPU 越多。
- **IPC**：匿名/命名管道（内核环形缓冲）、消息队列、共享内存（最快，需信号量同步）、信号（异步通知）、套接字（含 Unix Domain）。

## 具体示例

CFS 用红黑树选"最欠跑"的任务，天然公平；nice 通过权重调节 vruntime 增速：

```c
// 选 vruntime 最小者（红黑树最左）执行
left = rb_first_cached(&cfs_rq->tasks_timeline);
// nice 越低权重越高 → Δvruntime 越小 → 越常被选中
curr->vruntime += calc_delta_fair(delta_exec, curr);
```

## 何时用与何时不用

- **理解进程**：调 CPU 亲和/优先级（nice/chrt）、排查 D 状态（IO 卡死）与僵尸（父进程没 wait）、选 IPC 方式时。
- **不用**：同一进程内的并行共享地址空间用线程（[[线程与同步]]），跨机协作用网络套接字。

## 优劣与代价

✅ 状态机 + CFS 让多任务公平可预期，nice/亲和性可调；IPC 覆盖从轻量管道到高吞吐共享内存。
✅ 进程隔离边界清晰，一个崩溃不轻易波及其他。
⚠️ 进程切换与 IPC 拷贝开销高于线程；共享内存需自备同步。
⚠️ CFS 权重/调度域调优有门槛，D 状态与僵尸问题需专门排查。

## 与相关概念的区别

- **进程 vs 线程**：进程是资源隔离单位、各有地址空间；线程共享进程地址空间、切换更轻（见 [[线程与同步]]）。
- **共享内存 vs 管道**：前者最快但需自己同步；后者有内核缓冲、天然同步但需拷贝。
- **D 状态 vs S 状态**：D 不可被信号打断（等硬件 IO），S 可被信号唤醒。

## 常见误区

- 僵尸进程可以用 kill -9 杀掉。
- 共享内存是最慢的 IPC，因为要拷贝数据。
- nice 值越小，进程优先级越低、越难抢到 CPU。

## 面试速答

> 🎯 进程是资源分配与调度基本单位，内核用状态机(R/S/D/T/Z)管生命周期、CFS 用红黑树按 vruntime 最小者优先做公平调度(nice 调权重)；IPC 有管道/消息队列/共享内存/信号/套接字。僵尸需父进程 wait 回收、D 状态 kill -9 无效。
