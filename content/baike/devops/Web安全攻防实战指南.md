# Web安全攻防实战指南

> 📌 **导航**：本页是 **Web 安全攻防** 枢纽。高频攻击类型各立子词条；OWASP 全景、认证与鉴权细节走双链。

## 定义

**一句话定义：** Web 安全攻防是以 OWASP Top 10 为风险地图、按"理解威胁→分析原理→掌握攻击→构建防御"的方式，系统应对注入、XSS、CSRF、SSRF、上传与反序列化等常见 Web 漏洞的工程实践。

**通俗类比：** 像给一栋楼做安防：先列常见入侵方式（OWASP 全景），再对每种给出门锁与监控（原理+防御），而不是出了事才补洞。

## 为什么需要它

Web 应用把输入、认证、文件、内部调用都暴露给不可信的互联网，同类漏洞反复上榜、危害从盗 Cookie 到 RCE、到打内网。有一张权威风险清单 + 每类的成因与纵深防御，才能"设计阶段就防"而非事后救火。

## 具体示例

一条通用纵深：输入按上下文输出编码（防 XSS）、查询一律参数化（防注入）、改状态接口带 CSRF Token + SameSite、任何"按用户 URL 去请求"处做 SSRF 白名单与网络隔离，再叠 WAF/CSP/最小权限做兜底。

## 何时用与何时不用

- **用**：设计期做威胁建模、编码期按上表逐项防御、部署期配 CSP/HSTS/最小权限/及时升级依赖与镜像扫描。
- **不用**：别把"过滤黑名单关键字/前端校验"当主防线；别在生产开着详细报错与调试信息。

## 优劣与代价

✅ 以 OWASP 为共同语言，把零散"安全常识"变成可核查清单。
✅ 每种攻击都有"根因→对应防御"，可评审、可自动化。
⚠️ 攻防持续演进（新算法/新绕过），清单要随版本更新、不能一劳永逸。
⚠️ 过度防御堆叠会伤性能与体验，需按风险定级取舍。

## 与相关概念的区别

- **认证 vs 授权**：认证（你是谁，见 [[OAuth 与 JWT]]）解决身份，授权/访问控制（A01）解决"能否做此操作"，两者都不可缺。
- **安全左移 vs 上线后加固**：A04 设计缺陷靠威胁建模在编码前拦，比事后补丁更省；运行时再配监控告警兜底。

## 常见误区

- 装了 WAF 和 HTTPS，应用本身就没注入/XSS 问题了。
- 安全是上线前扫一次的事，之后不用管依赖和配置。
- 校验了文件扩展名/Content-Type，文件上传就绝对安全。

## 面试速答

> 🎯 以 OWASP Top10 为地图逐项防御：注入→参数化，XSS→输出编码+CSP，CSRF→Token+SameSite，SSRF→URL白名单+网络隔离，上传/反序列化→幻数校验+不反序列化不可信数据，认证/访问控制→逐请求校验+OAuth/JWT，配置/组件/日志→SBOM+扫描+告警。
