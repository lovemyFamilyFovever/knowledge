# 网络协议层攻击与防护

> 📌 **导航**：本文是 **网络协议层攻击与防护** 词条，属 [[网络安全与渗透测试]] 子词条。应用层攻防见 [[Web安全攻防实战指南]]。

## 定义

**一句话定义：** 网络协议层攻击利用 TCP/IP、DNS、ARP 等协议的先天设计缺陷（无状态、缺内建认证）实施拒绝服务与欺骗，防护靠 SYN Cookie、反向路径过滤、DNSSEC、静态 ARP/DAI 等机制在协议边界收敛风险。

**通俗类比：** 协议像约定好的"通用 handshake 手势"——因为大家都照做、不验身份，坏人就能假握手占满接待台（DoS）或冒充熟人递假信（欺骗）。防护就是给接待台限流、给信件验封蜡。

## 为什么需要它

网络层是所有对外的第一面，许多协议为效率与互通设计、默认信任邻居，天然可被伪造、重放或耗尽。应用层 WAF 再强，也挡不住耗尽带宽/半连接的 DDoS 或二层 ARP 欺骗——需在协议与网络边界专门设防。

## 核心机制

- **TCP SYN Flood / 资源耗尽**：只发 SYN 不完成握手，撑爆半连接队列。防御：SYN Cookie（不预占状态）、增大 backlog、调低 `tcp_synack_retries`、防火墙/清洗设备限速。
- **IP 欺骗与反射放大**：伪造源 IP 借第三方反射打目标。防御：`rp_filter` 反向路径过滤、BCP38 入口过滤、不响应可被放大的开放解析器。
- **DNS 劫持**：本地/路由/中间人/权威四个层面篡改解析。防御：DNSSEC 校验签名、DoT/DoH 加密传输、固定可信解析器。
- **ARP 欺骗（中间人）**：ARP 无认证，可伪造网关映射。防御：静态 ARP 绑定、交换机 DAI、802.1X、网络分段。

## 具体示例

主机侧缓解 SYN Flood 与 IP 欺骗的常用加固（防御向）：

```bash
sysctl -w net.ipv4.tcp_syncookies=1        # 开启 SYN Cookie
sysctl -w net.ipv4.conf.all.rp_filter=1    # 反向路径过滤，丢伪造源 IP
sysctl -w net.ipv4.tcp_max_syn_backlog=8192
```

## 何时用与何时不用

- **用**：边界/交换机/解析器加固、抗 DDoS 预案、内网防中间人、DNS 可信化。
- **不用**：别只在应用层做安全而忽略 L3/L4 与二层；公网服务需叠加云侧 DDoS 清洗，非单机 sysctl 能扛尽。

## 优劣与代价

✅ 协议层加固能挡住应用层防御覆盖不到的 L3/L4/二层攻击（DoS、ARP/DNS 欺骗）。
✅ 多为内核/交换机标准能力，成本低、可基线化。
⚠️ 单机 sysctl 扛不住大流量 DDoS，须云侧清洗；策略过严会误杀正常流量。
⚠️ DNSSEC/802.1X 等有部署与运维复杂度。

## 与相关概念的区别

- **网络层 vs 应用层**：本词条管协议/带宽/解析层，注入/XSS/CSRF/SSRF 属应用层（见 [[Web安全攻防实战指南]]）。
- **拒绝服务 vs 欺骗**：前者打可用性（耗尽资源），后者打机密/完整性（伪造身份或映射）。
- **DNSSEC vs DoT/DoH**：前者验"应答没被篡改"，后者保"查询通道不被窃听"，可并用。

## 常见误区

- 部署了 HTTPS 就不怕 DNS 劫持了。
- 有了防火墙就不需要防内网 ARP 欺骗。
- SYN Cookie 会给连接加密、顺便防窃听。

## 面试速答

> 🎯 网络协议层攻击利用协议"无状态、不验身份"缺陷：SYN Flood 耗尽半连接(SYN Cookie/backlog)、IP 欺骗与反射放大(rp_filter/入口过滤)、DNS 劫持(DNSSEC+DoT/DoH)、ARP 欺骗(静态绑定/DAI/802.1X)。属 L3/L4/二层，与 Web 应用层攻防互补。
