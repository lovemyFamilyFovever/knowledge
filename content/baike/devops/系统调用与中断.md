# 系统调用与中断

> 📌 **导航**：本文是 **系统调用与中断** 词条，属 [[操作系统内核原理]] 子词条。

## 定义

**一句话定义：** 系统调用是用户态进程进入内核请求服务的唯一合法入口（切态后查系统调用表执行），中断是硬件事件异步打断 CPU 的机制，二者加上统一的设备驱动模型，构成内核与外界交互的通道。

**通俗类比：** 系统调用像"去柜台办业务"（主动、要排队进后台）；中断像"火警铃响"（被动、所有人停下处理紧急情况）；设备驱动是"每种电器配的转接头"。

## 为什么需要它

用户态无权直接操作硬件或做特权动作，必须经内核受控放行（系统调用）；硬件完成 IO、时钟到点等事件需及时通知 CPU（中断）；成千上万种硬件的差异要抽象成统一注册与匹配框架（设备模型），否则内核无法通用。

## 核心机制

- **系统调用**（x86-64）：C 库把调用号放入 `rax`、参数放其它寄存器 → `syscall` 指令从 Ring3 切到 Ring0 → 按号在 `sys_call_table` 找处理函数（如 `sys_read`）→ 执行 → 结果放 `rax` → `sysret` 返回。
- **中断处理**：硬中断由设备触发，CPU 查 IDT 进入 ISR（运行在**中断上下文、不能睡眠**）；紧急部分在上半部速处理，耗时工作交**下半部**（softirq / tasklet / workqueue）。
- **设备模型**：`device`/`device_driver`/`bus_type` 三类对象，总线 `match()` 匹配后调驱动 `probe()` 初始化；`sysfs` 导出设备树、`uevent`+`udev` 动态建 `/dev` 节点。

## 具体示例

一次 `read()` 陷入内核再返回的路径：

```
用户 read() → libc 置 rax=调用号 → syscall 指令 → 切内核态
→ 查 sys_call_table[rax]=sys_read → 执行 → rax 放返回值 → sysret 返回用户态
```

## 何时用与何时不用

- **用（理解）**：分析 syscall 开销/上下文切换成本、用 strace 看调用、写/排查驱动、理解网络包"硬中断→softirq→协议栈"路径。
- **不用**：上半部里做耗时或可能睡眠的操作（会拖垮中断响应）——应推迟到下半部/工作队列。

## 优劣与代价

✅ 系统调用提供受控特权入口；中断让硬件事件及时被响应；设备模型统一纳管异构硬件。
✅ 上半部/下半部拆分兼顾响应速度与吞吐。
⚠️ 陷入内核与上下文切换有开销（高频 syscall 是性能杀手）。
⚠️ 中断上下文约束严格（不可睡眠），写错易致系统不稳定。

## 与相关概念的区别

- **系统调用 vs 中断 vs 异常**：系统调用是程序主动陷入（软中断/陷入），中断是外设异步事件，异常是执行出错（如缺页、除零）同步触发。
- **上半部 vs 下半部**：上半部快、禁中断、不能睡；下半部可被再中断、可安排耗时活。

## 常见误区

- 中断服务程序（ISR）里可以睡眠等待磁盘 IO 完成。
- 系统调用就是普通函数调用，不涉及特权级切换。
- 设备驱动加载后会一直主动轮询硬件取数据。

## 面试速答

> 🎯 系统调用是用户态进内核的唯一入口（syscall 切态、查系统调用表执行后返回）；中断由设备异步触发进 ISR（不可睡眠），分上半部与下半部（softirq/tasklet/workqueue）；设备经总线匹配驱动 probe 纳管。
