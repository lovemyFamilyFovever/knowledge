# 文件上传与反序列化

> 📌 **导航**：本文是 **文件上传与反序列化** 词条，属 [[Web安全攻防实战指南]] 子词条。

## 定义

**一句话定义：** 文件上传漏洞是服务器未严格校验上传的类型/内容/存储/执行权限而被人塞入 WebShell；反序列化漏洞是把不可信数据反序列化时触发对象魔术方法导致远程代码执行——两者都能直接拿下服务器。

**通俗类比：** 上传漏洞像"快递柜不查内容、把炸弹当衣服收了还允许它自己引爆"；反序列化像"照一张陌生人的表单去组装对象，结果表单里藏着危险指令"。

## 为什么需要它

上传点是"把任意字节写入服务器"的通道，一旦能落一个可被解释器执行的脚本文件、或目录有执行权，就是 WebShell/RCE。反序列化则把"重建对象"变成"执行攻击者选定的代码路径"，Java/PHP 历史上有大量 RCE 案例。

## 核心机制

- **文件上传**：手法有上传 `.php/.jsp/.asp`、Burp 改扩展名/Content-Type 绕过、利用解析漏洞（Nginx `%00` 截断、IIS 短文件名）、图片马 + 文件包含。防御多层：**白名单扩展名 + 校验文件头幻数 + UUID 重命名 + 存到非 Web 目录/对象存储 + 上传目录禁执行 + 图片重编码破坏负载**；前端校验仅为体验、不可信。
- **反序列化**：危险在 `readObject`/`__wakeup`/`__destruct` 等魔术方法里的敏感操作；铁律是**绝不反序列化不可信数据**，改用 JSON、必要时白名单类、及时升级易受攻的库（Jackson/Fastjson/Commons-Collections）。

## 具体示例

MIME 可伪造，要信"文件内容签名"而非声明类型；并把上传目录关执行：

```
JPEG 头 FF D8 FF E0 …     // 校验幻数，不只信 Content-Type
存储：随机文件名 + 非 Web 目录 + 无脚本执行权限
```

## 何时用与何时不用

- **用**：任何接受上传的功能都要"白名单 + 幻数 + 重命名 + 存储隔离 + 去执行权"；任何反序列化入口只处理可信来源或换 JSON。
- **不用**：别把"前端 JS 校验大小/扩展名"或"只查 Content-Type"当安全边界。

## 优劣与代价

✅ 白名单+幻数+重命名+存储隔离+禁执行 组合能挡绝大多数上传 RCE。
✅ 改 JSON、不反序列化不可信数据可根除一类高危 RCE。
⚠️ 多层校验有性能/体验成本，对象存储等引入额外依赖。
⚠️ 遗留协议/库仍带反序列化面，彻底改造有迁移成本。

## 与相关概念的区别

- **扩展名校验 vs 幻数校验**：扩展名/MIME 可伪造；读文件头签名更可靠。
- **序列化格式安全性**：JSON 只承载数据、不重建任意对象，天然避开反序列化 RCE。
- 与 [[注入类漏洞]]：注入是"输入当指令"，上传/反序列化是"数据落地/重建对象"引发的代码执行。

## 常见误区

- 校验了 Content-Type/MIME 类型就能防住文件上传。
- 前端限制了大小和扩展名，上传就安全了。
- 只反序列化自家系统产生的数据就一定安全。

## 面试速答

> 🎯 文件上传防的是"落一个可执行文件/目录有执行权"→白名单扩展名+幻数校验+UUID重命名+存非 Web 目录或对象存储+关执行权，别信前端/MIME。反序列化防的是"重建对象触发魔术方法 RCE"→绝不反序列化不可信数据、改 JSON、白名单类、升级易攻库。
