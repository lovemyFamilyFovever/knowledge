# 容器网络与数据持久化

> 📌 **导航**：本文是 **容器网络与数据持久化** 词条，属 [[Docker容器化完全指南]] 子词条。

## 定义

**一句话定义：** 容器网络决定容器如何获得网络栈、如何相互与对外通信（bridge/host/none/overlay/macvlan），数据持久化决定容器写出的数据在容器销毁后如何留存（volume/bind mount/tmpfs）。

**通俗类比：** 网络像"门牌与通路"——决定这间房能不能上网、能否和邻居串门；数据持久化像"该把东西放进自带保险柜（volume）还是临时桌面（容器层）"，房子拆了保险柜里的东西还在。

## 为什么需要它

容器默认隔离、且"用完即弃"：不配网络，容器间、容器与外界不通；数据写在容器可写层，容器一删就没了（数据库丢数据是灾难）。网络驱动与存储类型正是把"通信"和"留存"这两件容器天生不具备的能力补齐。

## 核心机制

网络驱动：

| 驱动 | 特点 | 典型用途 |
|---|---|---|
| bridge | 默认，NAT 到宿主机，同网络可按名互访 | 单机容器互联 |
| host | 共享宿主机网络栈、无隔离 | 追求性能、简单端口映射 |
| none | 仅回环、无外网 | 强隔离 |
| overlay | 跨主机（Swarm） | 多机容器通信 |
| macvlan | 容器直接拿到二层独立 MAC/IP | 当"物理机"接进局域网 |

数据三态：**volume**（Docker 管理的命名卷，存数据库等持久数据、可备份迁移）、**bind mount**（挂载宿主机指定路径，多用于开发热更新/配置）、**tmpfs**（写内存、不落盘、容器停即失，适合临时/敏感数据）。

## 具体示例

数据备份走一次性容器挂载卷打包，避免污染生产容器：

```bash
# 用命名卷持久化，而非写进容器层
docker run -d -v pgdata:/var/lib/postgresql/data postgres:14
# 备份：起个临时容器把卷 tar 到宿主机
docker run --rm -v pgdata:/source:ro -v $(pwd):/backup alpine \
  tar czf /backup/pgdata.tar.gz -C /source .
```

## 何时用与何时不用

- **网络**：默认自定义 bridge（比默认 bridge 多 DNS 按名解析）；host 换性能但丢隔离；跨机用 overlay；需接入既有局域网用 macvlan。
- **数据**：数据库/有状态服务用 volume；开发期挂载源码用 bind mount；临时/敏感中间态用 tmpfs。别让有状态数据落在容器可写层。

## 优劣与代价

✅ 按名互访、隔离可控、数据与容器生命周期解耦、卷可备份迁移。
⚠️ host 模式失去网络隔离；macvlan 与宿主机间通信受限。
⚠️ bind mount 依赖宿主机路径、可移植性差；tmpfs 不持久、受内存大小限制。

## 与相关概念的区别

- **volume vs bind mount**：卷由 Docker 管理、路径抽象、便于备份与驱动（如 NFS）；bind 直接映射宿主机某路径、强依赖宿主环境。
- **bridge vs overlay**：bridge 单机；overlay 通过 VXLAN 跨主机让容器二层互通。
- **数据持久化 vs 镜像分层**：镜像层是只读交付物；运行时的写入落在容器可写层，易失——持久数据必须外挂 volume。

## 常见误区

- 把数据库文件写在容器默认文件系统里，删容器数据也还在。
- host 网络模式和 bridge 模式隔离性一样，只是写法不同。
- tmpfs 是一种可靠的持久化方案。

## 面试速答

> 🎯 网络驱动：bridge(默认/按名互访)、host(快无隔离)、none、overlay(跨机)、macvlan(独立IP)；持久化：volume(Docker管理可备份)/bind mount(挂宿主路径)/tmpfs(内存易失)。核心：有状态数据别放容器可写层。
