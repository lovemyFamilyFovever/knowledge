# Docker容器化完全指南

> 📌 **导航**：本页是 **Docker 容器化** 枢纽。容器/镜像/Dockerfile 与 Compose 基础已收敛到专条，本页索引 Docker 进阶主题。

## 定义

**一句话定义：** Docker 容器化是把应用连同依赖打包为共享内核、秒级启动的标准容器；本枢纽聚焦构建分发、网络与存储、运行时安全与日志等把容器"用好"的进阶面。

**通俗类比：** 集装箱运输——[[容器与编排技术详解]] 讲"箱子是什么、码头怎么装"，本页讲"怎么把箱子造得小、怎么接线通网、怎么防潮上锁、怎么记日志"。

## 为什么需要它

会用 `docker run` 只是入门；真正上生产会遇到镜像又大全是漏洞、容器间连不通、数据一删就没、容器以 root 裸奔、日志无处可查。这些不是"是什么"而是"怎么用好"的问题，正是本篇进阶子词条要解决的。

## 具体示例

一次把 Web 服务安全容器化的动作串：写多阶段 Dockerfile 出小镜像 → push 到 Harbor 并扫描 → 用 bridge 网络 + 命名卷跑起来 → 加 seccomp/只读/非 root 加固 → stdout 交给日志采集。

## 何时用与何时不用

- **用**：把单个容器交付演进到"可维护、可分发、安全、可观测"的生产形态时。
- **不用**：需要跨主机调度、自愈、伸缩时，Docker 本身不够，应上 [[Kubernetes深入]] 等编排平台。

## 优劣与代价

✅ 环境一致、启动快、镜像可分发可扫描，网络/存储/安全各有成熟机制。
✅ 主题分层，可按需深挖单一面。
⚠️ 共享内核决定隔离弱于虚拟机；镜像与配置若不加治理会积累安全与体积债。
⚠️ 工具链分散（registry/扫描/日志/编排）带来运维整合成本。

## 与相关概念的区别

- **单机容器 vs 集群编排**：Docker（+Compose）管单机的镜像/容器/网络/卷；跨机调度、自愈、服务发现交给 Kubernetes（见 [[Kubernetes云原生实战指南]]）。
- **镜像层(只读交付) vs 容器可写层/卷(运行时数据)**：持久数据要外挂 volume，别依赖易失的可写层（见 [[容器网络与数据持久化]]）。

## 常见误区

- 会敲 docker build/run 就等于掌握了 Docker 容器化，不必管网络、存储与安全。
- 生产把有状态数据写在容器可写层里就够了。
- 上了容器天然就比虚拟机安全。

## 面试速答

> 🎯 Docker 容器化进阶四块：镜像(多阶段/瘦身/Harbor)、网络与存储(bridge/host/overlay + volume/bind/tmpfs)、运行时安全(非root/seccomp/扫描)、日志聚合。基础见 [[容器与编排技术详解]]，跨机编排交给 Kubernetes。
