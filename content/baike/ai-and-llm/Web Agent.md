# Web Agent


> 📌 **导航**：本文是 **Web Agent** 词条，属于 ai-and-llm 术语集。相关枢纽：[[大模型基础术语详解]]、[[Transformer架构深度解析]]、[[RAG 与检索技术详解]]、[[多 Agent 协作系统]]、[[Prompt 工程与 Agent 详解]]。

## 定义

**一句话定义：** Web Agent 是能自主浏览网页、检索信息、填写表单并点击操作的 Agent，像人一样通过浏览器与网站交互来完成在线任务。

**通俗类比：** 一个会自己开浏览器、搜东西、读网页、填表格的"数字网虫实习生"——你交代目标，它就去网页上一步步办妥。

## 为什么需要它

大量在线信息没有 API，只能靠人上网点。Web Agent 走"浏览器"这条人用通道，把跨网站的信息采集、比价、填单等重复操作自动化，省下可观的人工。

## 核心能力

| 能力 | 说明 | 技术 |
|------|------|------|
| 网页浏览 | 打开并导航页面 | 浏览器自动化 |
| 信息提取 | 从页面取结构化数据 | DOM 解析 + LLM |
| 表单填写 | 自动填写与提交 | 元素定位 |
| 搜索执行 | 使用搜索引擎 | API / 自动化 |
| 页面理解 | 理解内容与结构 | 视觉 + 文本理解 |

技术上常基于 Playwright、Selenium 等浏览器自动化：把 DOM / 可访问性树连同截图交给 LLM 理解，再决定点哪、填什么。工作流为：解析目标 → 加载页面 → 理解 DOM 与视觉 → 提取信息或执行操作 → 返回结果，循环推进直到完成。

## 具体示例

"把三家电商的同款耳机价格整理成表"：Agent 逐一搜索、进入商品页、按预定义 schema 抽取价格与型号 → 汇总成表。遇 JS 动态加载要先等渲染完成，遇验证码则需人工兜底。

在线操作也带来一堆现实阻碍：

| 挑战 | 说明 |
|------|------|
| 反爬虫 | 验证码、频率限制 |
| 动态内容 | JavaScript 渲染页面 |
| 页面变化 | 结构更新导致脚本失效 |
| 登录状态 | Cookie / Session 管理 |

## 何时用 / 何时不用

- **用**：目标只有网页界面、没有稳定 API 的在线操作。
- **不用**：有官方 API 时优先用接口（更稳更快）；且必须注意合规、频控与网站 ToS 约束。

## 优劣与代价

✅ 打通无 API 的在线任务，实现跨站自动化。
⚠️ 较脆弱——页面改版即可能失效，且易被反爬 / 验证码拦截。
⚠️ 抓取数据存在法律与 ToS 风险，动态渲染与登录态也增加工程复杂度。

## 与相关概念的区别

- **vs [[Computer Use Agent]]**：Web Agent 在浏览器 DOM 内操作，有结构化信号可依，比纯像素更稳；Computer Use 在像素层操控整台机器，更通用也更脆。
- **vs [[Research Agent]]**：后者聚焦学术文献检索与综述，Web Agent 面向泛互联网操作。

## 常见误区

- Web Agent 只能靠截图看像素操作网页，无法利用网页结构。
- 只要目标网站没改版，Web Agent 的自动操作就永远稳定、不受反爬影响。
- 用 Web Agent 抓取任何网站的数据都不存在合规或 ToS 风险。

## 面试速答

> 🎯 Web Agent 让 AI 走浏览器这条人用通道自主上网办事：基于 Playwright/Selenium 等自动化，把 DOM/可访问性树与截图交给 LLM 理解 → 决定导航、点击、填表 → 抽取结构化数据，循环完成跨站任务。有官方 API 时优先用接口。
> 🔍 追问：Web Agent 相比 Computer Use 更稳在哪？（能读 DOM / 可访问性树等结构化信号，不纯靠像素定位）
> 🔍 追问：动态内容和反爬会带来什么问题？（JS 渲染要等、元素会变，验证码与频控会拦，需等待策略与人工兜底）
