# 长上下文技术


> 📌 **导航**：本文是 **长上下文技术** 词条，属于 ai-and-llm 术语集。相关枢纽：[[大模型基础术语详解]]、[[Transformer架构深度解析]]、[[RAG 与检索技术详解]]、[[多 Agent 协作系统]]、[[Prompt 工程与 Agent 详解]]。

## 概述
长上下文技术让LLM处理更长的输入文本，从最初的4K到现在的百万token级别。

## 核心挑战
```
标准Attention: O(N^2) 复杂度
128K token → 内存和计算需求爆炸
```

## 位置编码外推

| 方法 | 原理 | 外推能力 |
|------|------|---------|
| **绝对位置** | 可学习的位置向量 | 差 |
| **RoPE** | 旋转位置编码 | 中 |
| **ALiBi** | 线性偏置 | 好 |
| **NTK-aware** | 动态NTK缩放 | 好 |

## RoPE 外推
```python
# 旋转位置编码的基本思想
# 每个位置编码是旋转矩阵
# 通过调整旋转频率实现长度外推

# NTK-aware缩放: 修改基频
def ntk_rope(dim, max_seq_len, base=10000):
    # 动态调整base频率
    adjusted_base = base * (max_seq_len / original_max_seq) ** (dim / (dim - 2))
    # 计算旋转角度
    theta = 1.0 / (adjusted_base ** (torch.arange(0, dim, 2) / dim))
    return theta
```

## Ring Attention
将长序列分散到多个GPU上并行计算：
```
GPU0: token[0:32K]    ←→  GPU1: token[32K:64K]
         ↕                         ↕
GPU3: token[96K:128K] ←→  GPU2: token[64K:96K]

通过传递KV块实现跨GPU注意力计算
```

## Infini-Attention
Google提出的无限上下文注意力：
```python
# 核心思想: 压缩历史为固定大小的记忆矩阵
# 1. 将长序列分块
# 2. 对每个块计算标准注意力
# 3. 将历史压缩到记忆矩阵中
# 4. 查询时同时检索记忆和当前块
```

## 长上下文 vs RAG

| 维度 | 长上下文 | RAG |
|------|---------|-----|
| **准确性** | 所有信息可见 | 依赖检索质量 |
| **成本** | 高（大量Token） | 低（只检索相关） |
| **延迟** | 高 | 低 |
| **适用场景** | 需要全部信息 | 只需部分信息 |

## 小结
长上下文技术通过位置编码外推、分布式注意力等方法突破了上下文长度限制。实际应用中，长上下文和RAG应结合使用。
