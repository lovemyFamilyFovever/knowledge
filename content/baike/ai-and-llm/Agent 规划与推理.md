# Agent 规划与推理

> 📌 **导航**：本文是 **Agent 规划与推理** 词条，属于 ai-and-llm 术语集（Agent 方向）。相关枢纽：[[AI Agent 概述与核心架构]]、[[Agent 架构模式详解]]、[[多 Agent 协作系统]]、[[大模型基础术语详解]]、[[RAG 与检索技术详解]]。

## 定义

**一句话定义：** Agent 规划与推理是把复杂目标拆解为可执行子步骤、在多条候选路径中搜索决策、并依反馈修正的思维能力。

**通俗类比：** 像"下棋 + 做项目计划"的合体——先想清有哪些步骤，再评估每种走法的好坏，走错一步就复盘重排。

## 为什么需要它

复杂任务无法一步完成，需要分解与排序；环境又充满不确定性，需要在候选行动里择优、失败后重规划。缺少规划与推理，Agent 只能对单条提示做单步反应，无法应对多步骤、有依赖、需中途纠偏的长程任务。

## 核心机制

任务分解的常见方式：

| 方法 | 说明 | 适用场景 |
|------|------|---------|
| LLM 分解 | 用大模型把任务拆成子步骤 | 通用任务 |
| 目标分解 | 按目标层级逐层拆解 | 复杂目标 |
| 依赖分析 | 识别子任务前后依赖 | 可并行任务 |
| MCTS 搜索 | 蒙特卡洛树搜索最优路径 | 开放探索任务 |

**路径搜索（MCTS）** 把决策建模为在候选行动树上搜索，四步循环：选择（用 UCB 公式在"探索未知"与"利用已知"间权衡）→ 扩展（生成新行动）→ 模拟（评估该行动前景）→ 回传（把结果统计更新到路径上）。它可靠性最高，但算力与延迟成本也最高。

**推理策略谱系**按"Token 换准确率"分档：

| 策略 | 说明 | Token 效率 | 准确率 |
|------|------|----------|--------|
| 直接推理 | 一步到位 | 高 | 低 |
| CoT | 逐步思考 | 中 | 高 |
| 自洽性 | 多次采样投票 | 低 | 很高 |
| MCTS | 树搜索多路径 | 很低 | 最高 |

把这几种能力编排成控制流，就是**规划-执行-反思**闭环：先出计划，逐步执行，对不满意的步骤反思并重排计划，直到收敛。

## 具体示例

"规划一次五天行程"：目标分解出查机票、比价、订酒店、排行程，依赖分析发现日期确定后机酒可并行；执行到订酒店时满房，触发反思→放宽预算重新规划——分解、搜索、反思在一件长任务里协同工作。

## 何时用 / 何时不用

- **用**：任务多步骤、子任务有依赖、需要在中途纠偏或探索多种路径时。
- **不用**：单步事实问答或明确直给的流程，过度规划只会徒增 Token 与延迟。

## 优劣与代价

✅ 让 Agent 具备处理长程复杂任务的能力，配合反思能自我纠错。
⚠️ 初始分解一旦错误会向后级联放大，需重规划机制兜底。
⚠️ MCTS、自洽性等高准确率手段的算力成本随搜索规模急剧上升。

## 与相关概念的区别

- **vs Agent 架构模式**：架构模式（ReAct、Plan-and-Execute 等）是"整体控制流骨架"，本词条聚焦其中"规划与推理"这一能力的具体算法。
- **vs [[Agent 记忆系统]]**：记忆解决"知道哪些信息"，规划推理解决"下一步该做什么"。

## 常见误区

- 推理链越长、采样次数越多，Agent 的答案就一定越准且成本不变。
- MCTS 通过反向传播更新大模型的权重来提升规划能力。
- 任务一旦分解成固定子步骤就无需再调整，反思重规划纯属浪费。

## 面试速答

> 🎯 规划=把目标拆成带依赖的子步骤，推理=在候选路径里择优。方法谱系从直接推理→CoT→自洽性投票→MCTS 树搜索，准确率升、Token 成本也升。生产用"规划-执行-反思"闭环：出错就复盘重排，在质量与成本间取平衡。
> 🔍 追问：CoT 和自洽性有何区别？（CoT 单次逐步推理；自洽性多次采样投票取众数，更准也更贵）
> 🔍 追问：MCTS 如何平衡探索与利用？（用 UCB 公式在未试分支与已知高价值分支之间权衡）
