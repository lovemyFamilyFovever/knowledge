## 1. LLM（大语言模型）

**一句话定义：** 用海量文本训练出来的、能理解和生成人类语言的人工智能模型。

**通俗类比：** 就像一个读过整个互联网所有书籍的超级学霸，你问它什么它都能回答，但它不是真的"理解"，而是在统计规律下给出最可能的答案。

**具体示例：**
```
输入： "中国的首都是"
LLM输出： "北京。中华人民共和国的首都为北京市，位于华北平原北部。"
```

**为什么需要它：** LLM 是整个 AI 应用的基础能力层，所有对话、写作、代码生成等功能都依赖它。

**与相关术语的对比：**
- LLM vs 传统 NLP：传统 NLP 每个任务需要单独训练模型，LLM 一个模型搞定所有任务
- LLM vs 小模型：LLM 参数量通常在 10 亿以上，小模型参数量小但推理更快

## 2. Transformer 架构

**一句话定义：** 一种基于"自注意力机制"的神经网络架构，是目前几乎所有大模型的底层骨架。

**通俗类比：** 就像一本书的目录系统，能快速定位到任意章节之间的关联，而不需要从头读到尾。

**具体示例：**
```
传统 RNN：  读句子 "我爱北京天安门" → 从左到右逐字处理，容易忘记前面的内容
Transformer： 同时看到所有词 → 直接计算任意两个词之间的关系
```

**模型架构图（文本版）：**
```
输入序列
    ↓
[输入 Embedding + 位置编码]
    ↓
┌─────────────────────────┐
│   Transformer Block ×N   │
│  ┌───────────────────┐  │
│  │  Multi-Head Self-  │  │
│  │    Attention        │  │
│  └───────────────────┘  │
│           ↓             │
│  ┌───────────────────┐  │
│  │   Feed Forward     │  │
│  │     Network        │  │
│  └───────────────────┘  │
│           ↓             │
│  [Layer Norm + 残差连接] │
└─────────────────────────┘
    ↓
输出概率分布
```

**为什么需要它：** Transformer 解决了传统模型处理长文本时的"遗忘"问题，并且支持并行计算，训练效率大幅提升。

**与相关术语的对比：**
- Transformer vs RNN/LSTM：RNN 串行处理慢且遗忘严重，Transformer 并行处理且全局关联
- Transformer vs CNN：CNN 擅长局部特征，Transformer 擅长全局依赖

## 3. Self-Attention 机制（自注意力）

**一句话定义：** 让句子中的每个词都能"看到"并"关注"其他所有词，计算它们之间的相关性。

**通俗类比：** 就像开会时每个人都能和其他人直接对话，而不是只能听到旁边人说的话。

**具体示例：**
```
句子： "小猫坐在垫子上，它很舒服"

Self-Attention 计算：
  "它" → 关注 "小猫"（权重 0.8）
  "它" → 关注 "垫子"（权重 0.15）
  "它" → 关注 "舒服"（权重 0.05）

结果：模型理解 "它" 指代 "小猫"
```

**为什么需要它：** 让模型能理解上下文中的指代关系、语义关联等复杂语言现象。

**与相关术语的对比：**
- Self-Attention vs Cross-Attention：Self-Attention 在同一序列内计算，Cross-Attention 在两个不同序列间计算（如翻译任务）

---

## 4. Multi-Head Attention（多头注意力）

**一句话定义：** 同时从多个不同角度去分析词与词之间的关系。

**通俗类比：** 就像派多个侦探同时调查同一个案件，每个侦探关注不同的线索（语法、语义、情感等），最后综合所有线索得出结论。

**具体示例：**
```
句子： "苹果发布了新手机，股价大涨"

Head 1（语法关系）： "苹果" → "发布" → "手机"
Head 2（因果关系）： "发布手机" → "股价大涨"
Head 3（实体关系）： "苹果" → "股价"
Head 4（情感关系）： "大涨" → 正面情感

多头合并后：模型同时掌握了语法、因果、实体、情感四维度信息
```

**为什么需要它：** 单一注意力只能捕捉一种关系，多头机制让模型能并行捕获多种语义关系。

**与相关术语的对比：**
- Multi-Head vs Single-Head：Single-Head 只有一个视角，容易遗漏信息；Multi-Head 多视角更全面

---

## 5. Position Encoding（位置编码）

**一句话定义：** 给输入的每个词加上位置信息，让模型知道词的先后顺序。

**通俗类比：** 就像给排队的人发号码牌，虽然 Transformer 同时看到所有人，但通过号码牌知道谁在前谁在后。

**具体示例：**
```
句子： "我 爱 你" vs "你 爱 我"

无位置编码：两个句子的词向量集合完全相同，无法区分
有位置编码：
  "我" 在位置1 → 向量 + 位置1编码
  "爱" 在位置2 → 向量 + 位置2编码
  "你" 在位置3 → 向量 + 位置3编码

两个句子的编码结果完全不同
```

**为什么需要它：** Transformer 是并行处理的，天然不知道顺序，位置编码补上了这个关键信息。

---

## 6. Token 与分词（BPE/WordPiece）

**一句话定义：** Token 是模型处理文本的最小单位，分词算法决定如何把文本切成 Token。

**通俗类比：** 就像切菜，"中华人民共和国"可以切成"中华/人民/共和国"（大块），也可以切成"中/华/人/民/共/和/国"（小块），BPE/WordPiece 就是决定怎么切的算法。

**具体示例：**
```
原始文本： "ChatGPT is amazing"

按空格切分：  ["ChatGPT", "is", "amazing"]  → 3个Token
按BPE切分：   ["Chat", "G", "PT", " is", " amazing"] → 5个Token
按字符切分：  ["C","h","a","t","G","P","T",...] → 很多Token

中文示例：
"我喜欢编程" → BPE可能切分为 ["我", "喜欢", "编", "程"]
```

**为什么需要它：** 模型不直接处理文字，需要先把文字转成数字，分词是这个转换的第一步。

**与相关术语的对比：**
- BPE vs WordPiece：BPE 按频率合并，WordPiece 按互信息合并，效果类似
- Token vs 字符 vs 词：Token 是介于字符和词之间的粒度

---

## 7. Embedding 向量化

**一句话定义：** 把 Token 转换成一串数字（向量），让模型能进行数学计算。

**通俗类比：** 就像给每个中文词分配一个独特的"身份证号"，意思相近的词"身份证号"也接近。

**具体示例：**
```
Token "国王" → [0.23, -0.15, 0.87, 0.42, ...] （768维向量）
Token "女王" → [0.21, -0.18, 0.85, 0.45, ...] （很接近）
Token "汽车" → [-0.56, 0.73, -0.12, 0.34, ...] （差异很大）

数学关系：国王 - 男人 + 女人 ≈ 女王
```

**为什么需要它：** 数字是模型唯一能理解的格式，Embedding 是文本世界和数学世界之间的桥梁。

---

## 8. GPT 系列

**一句话定义：** OpenAI 开发的一系列基于 Decoder-Only 架构的大语言模型。

**通俗类比：** 就像一个只会"续写"的天才作家，给它开头它就能一直写下去，而且写得很好。

**具体示例：**
```
GPT 版本演进：
GPT-1 (2018)：1.17亿参数，能简单续写
GPT-2 (2019)：15亿参数，能写文章
GPT-3 (2020)：1750亿参数，能做各种任务
GPT-3.5 (2022)：ChatGPT，对话能力爆发
GPT-4 (2023)：多模态，能看图+超强推理
GPT-4o (2024)：更快更便宜，音频视频全支持

核心特点：Decoder-Only + 自回归生成（一个Token一个Token往右生成）
```

**为什么需要它：** GPT 系列证明了"大规模预训练+指令微调"这条路的可行性，是当前 AI 浪潮的起点。

**与相关术语的对比：**
- GPT vs BERT：GPT 擅长生成（从左到右），BERT 擅长理解（双向看全文）
- GPT vs LLaMA：GPT 是闭源的，LLaMA 是 Meta 的开源版本

---

## 9. BERT

**一句话定义：** Google 开发的双向语言理解模型，擅长理解文本含义而不是生成文本。

**通俗类比：** 就像一个阅读理解高手，给它一篇文章和一个问题，它能精准找到答案，但它自己不会写文章。

**具体示例：**
```
BERT 输入： "巴黎是[法国]的首都" → 完形填空，填入 "法国"
BERT 输入： "这部电影很好看" → 情感分类 → 正面

BERT 变体：
  BERT-Base：1.1亿参数，12层
  BERT-Large：3.4亿参数，24层
  RoBERTa：BERT 的改进版，训练更充分
  DeBERTa：增强版，目前 GLUE 排行榜靠前
```

**为什么需要它：** BERT 是"预训练+微调"范式的开创者，证明了一个模型可以通过微调适配各种下游任务。

**与相关术语的对比：**
- BERT vs GPT：BERT 双向看全文（理解型），GPT 单向从左到右（生成型）
- BERT vs T5：BERT 擅长分类/抽取，T5 擅长生成

---

## 10. Encoder-Decoder 架构

**一句话定义：** 由编码器（理解输入）和解码器（生成输出）两部分组成的模型架构。

**通俗类比：** 就像同声传译员：先听懂原文（编码器），再翻译成目标语言（解码器）。

**具体示例：**
```
任务：机器翻译 "Hello, how are you?" → "你好，你怎么样？"

编码器：  "Hello" → [向量1]
         "how"   → [向量2]
         "are"   → [向量3]
         "you"   → [向量4]
         （理解整句话的含义）

解码器：  根据编码器输出，逐词生成 "你" → "好" → "，" → "你" → "怎" → "么" → "样" → "？"
```

**为什么需要它：** 非常适合输入输出长度不同的任务，如翻译、摘要、对话等。

**与相关术语的对比：**
- Encoder-Decoder vs Decoder-Only：前者适合序列到序列任务，后者（GPT）更适合纯生成任务
- Encoder-Decoder vs Encoder-Only：前者能生成，后者只能理解

## 11. Temperature 参数

**一句话定义：** 控制模型输出随机性的"温度旋钮"，温度越高越随机，越低越确定。

**通俗类比：** 就像空调温度：设高了（0.8）回答天马行空有创意，设低了（0.1）回答保守但准确。

**具体示例：**
```
问题： "天空是什么颜色？"

Temperature = 0.1（低）：
  输出： "天空是蓝色的。"（100%确定）

Temperature = 0.7（中）：
  输出： "天空通常是蓝色的，但有时也会呈现橙红色。"

Temperature = 1.5（高）：
  输出： "天空是紫色的鱼缸，里面游满了想法。"（胡说八道）
```

**为什么需要它：** 让用户根据场景调节输出风格——写代码要低温度（准确），写诗要高温度（创意）。

## 12. Top-P 采样

**一句话定义：** 从累积概率达到 P 的最小词集中随机选择下一个词。

**通俗类比：** 就像点餐时只看菜单上概率最高的几个菜，P=0.9 意味着只从累积概率达到 90% 的菜中选。

**具体示例：**
```
模型预测下一个词的概率：
  "北京" = 0.4
  "上海" = 0.25
  "深圳" = 0.15
  "广州" = 0.1
  "杭州" = 0.05
  "其他" = 0.05

Top-P = 0.8 时：
  累积：北京(0.4) → 上海(0.65) → 深圳(0.80)
  候选池：["北京", "上海", "深圳"]
  从中随机选择

Top-P = 1.0 时：
  所有词都有机会被选中
```

**为什么需要它：** 比 Top-K 更灵活，自动调整候选词数量，在质量和多样性之间取得平衡。

**与相关术语的对比：**
- Top-P vs Top-K：Top-K 固定选 K 个，Top-P 根据概率动态调整数量
- Top-P vs Temperature：Temperature 改变概率分布形状，Top-P 截断分布尾部

## 13. 幻觉（Hallucination）

**一句话定义：** 模型一本正经地编造不存在的事实，输出看起来很合理但实际上是假的。

**通俗类比：** 就像一个爱吹牛的朋友，说的头头是道但很多都是瞎编的，你还信以为真。

**具体示例：**
```
用户： "谁发明了 Python？"

幻觉输出： "Python 由 Guido van Rossum 于 1991 年在微软发明。"
实际情况： 确实是 Guido 发明的，但他在 CWI（荷兰）发明的，不是微软

用户： "请引用《红楼梦》第50回的诗句"
幻觉输出： "落花有意随流水，流水无心恋落花。"
实际情况： 这不是《红楼梦》里的，是其他诗句，模型编造了出处
```

**为什么需要它：** 幻觉是当前 LLM 最大的问题之一，理解它有助于我们设计 RAG、事实核查等解决方案。

**与相关术语的对比：**
- 幻觉 vs 事实错误：事实错误是信息不准确，幻觉是模型"创造"了不存在的信息
- 幻觉 vs 拒绝回答：好的模型在不确定时应该说"我不确定"而不是编造

## 14. 上下文窗口（Context Window）

**一句话定义：** 模型一次能处理的最大 Token 数量，决定了模型能"记住"多少内容。

**通俗类比：** 就像人的工作记忆，普通人只能同时记住 7±2 个信息块，上下文窗口就是模型的"工作记忆容量"。

**具体示例：**
```
不同模型的上下文窗口：
GPT-3.5：    4,096 Token（约3000字）
GPT-4：      8,192 / 32,768 Token
GPT-4 Turbo：128,000 Token（约10万字）
Claude 3：   200,000 Token（约15万字）
Gemini 1.5：  1,000,000 Token（约75万字）

实际影响：
  上下文窗口 = 4K：   只能处理一篇短文
  上下文窗口 = 128K： 可以一次性读完一本小说
```

**为什么需要它：** 上下文窗口越大，模型能参考的信息越多，但推理成本也越高。

**与相关术语的对比：**
- 上下文窗口 vs 训练数据：训练数据是模型"学习"的知识，上下文窗口是模型"当前能看见"的内容
- 上下文窗口 vs 记忆：上下文窗口是短期记忆，训练数据是长期记忆
