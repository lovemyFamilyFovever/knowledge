# 微调与训练技术详解

---

## 1. Fine-tuning（微调）

**一句话定义：** 在预训练好的大模型基础上，用特定领域数据继续训练，让模型适配具体任务。

**通俗类比：** 就像一个全科医生去进修了一段时间，变成了心脏科专家——基础医学知识都在，只是专科能力更强了。

**具体示例：**
```
场景： 让通用大模型变成医疗问答专家

预训练模型：GPT-4（什么都知道一点，但医疗不够专业）

微调数据：
  {"问": "感冒了怎么办？", "答": "普通感冒一般7天自愈，注意休息多喝水..."}
  {"问": "血压高吃什么药？", "答": "高血压用药需遵医嘱，常用药物有..."}
  ...（10万条医疗问答）

微调后：模型在医疗问答场景下的回答更专业、更准确
```

**为什么需要它：** 通用模型在特定领域表现不够专业，微调能让它成为领域专家。

**与相关术语的对比：**
- 微调 vs 预训练：预训练从零开始学通用知识，微调在已有知识基础上学专业知识
- 微调 vs Prompt Engineering：Prompt Engineering 不改模型参数，微调会改参数

---

## 2. LoRA（Low-Rank Adaptation）

**一句话定义：** 一种只训练模型中很小一部分参数的高效微调方法，大幅降低显存和计算需求。

**通俗类比：** 就像给一个大厦加装电梯——不需要重建整栋楼（全参数训练），只在关键位置做小改动（低秩矩阵），效果却很好。

**具体示例：**
```
全参数微调 GPT-3（1750亿参数）：
  需要存储：1750亿 × 4字节（FP32）= 700GB 显存
  需要GPU：  16×A100 80GB

LoRA 微调 GPT-3：
  只训练：0.1% 的参数 = 1750万参数
  需要存储：约 8GB 显存
  需要GPU：  1×RTX 3090 24GB

效果：LoRA 微调效果达到全参数微调的 90-95%
```

**LoRA 原理图：**
```
原始权重矩阵 W (d×d)：
┌─────────────┐
│             │
│     W       │ ← 冻结，不训练
│             │
└─────────────┘

LoRA 低秩分解：
┌─────────┐   ┌─────────┐
│         │   │         │
│    A    │ × │    B    │ ← 只训练 A 和 B
│  (d×r)  │   │  (r×d)  │    r << d （通常r=8或16）
│         │   │         │
└─────────┘   └─────────┘

更新后的权重：W' = W + A×B
```

**为什么需要它：** 让普通消费者级 GPU 也能微调大模型，大幅降低微调门槛和成本。

---

## 3. QLoRA

**一句话定义：** 在 LoRA 基础上加入量化技术，用更少的显存微调更大的模型。

**通俗类比：** 如果 LoRA 是"只装修关键房间"，QLoRA 就是"把不重要的房间压缩成折叠房，省出空间来装修"。

**具体示例：**
```
对比：
  全参数微调 7B 模型：  需要 28GB 显存
  LoRA 微调 7B 模型：   需要 16GB 显存
  QLoRA 微调 7B 模型：  需要 6GB 显存  ← 单卡RTX 3060可跑

  全参数微调 65B 模型： 需要 260GB 显存
  QLoRA 微调 65B 模型： 需要 24GB 显存 ← 单卡RTX 3090可跑
```

**为什么需要它：** 进一步降低微调门槛，让消费级显卡也能微调超大模型。

---

## 4. RLHF（基于人类反馈的强化学习）

**一句话定义：** 让人类对模型的多个回答打分，然后用强化学习让模型学会生成人类更喜欢的回答。

**通俗类比：** 就像训练一只导盲犬——每次做对了给零食奖励，做错了不给，慢慢它就知道什么行为是对的。

**具体示例：**
```
Step 1: 收集人类偏好数据
  问题： "如何减肥？"
  回答A： "少吃多运动。"（人类评分：3/5）
  回答B： "建议制定合理的饮食计划，配合每周3-4次有氧运动..."（人类评分：5/5）

Step 2: 训练奖励模型（Reward Model）
  学习人类的打分偏好

Step 3: 用强化学习（PPO算法）优化LLM
  让模型生成高分回答，惩罚低分回答

结果：模型学会了生成详细、有帮助、安全的回答
```

**为什么需要它：** 解决了"模型能力很强但不听话"的问题，让模型的价值观和行为与人类对齐。

**与相关术语的对比：**
- RLHF vs SFT：SFT 教模型"正确的知识"，RLHF 教模型"人类喜欢的表达方式"
- RLHF vs DPO：RLHF 需要训练奖励模型，DPO 简化了这个流程

---

## 5. DPO（Direct Preference Optimization）

**一句话定义：** 一种比 RLHF 更简单的对齐方法，直接用人类偏好数据训练，不需要单独的奖励模型。

**通俗类比：** RLHF 像是先找裁判（奖励模型），再让裁判指导选手；DPO 直接让选手看观众喜好（偏好数据）自己调整。

**具体示例：**
```
RLHF 流程：
  LLM → 生成回答 → 奖励模型打分 → 强化学习更新LLM
  （三步，需要训练两个模型）

DPO 流程：
  LLM → 生成回答 → 直接与人类偏好对比 → 更新LLM
  （两步，只需要一个模型）

DPO 训练数据：
  {"prompt": "写一首诗", "chosen": "优秀诗歌", "rejected": "普通诗歌"}
```

**为什么需要它：** DPO 训练更稳定、更简单，效果与 RLHF 相当，是目前的主流对齐方法之一。

---

## 6. 预训练（Pre-training）

**一句话定义：** 在海量无标注文本上从零开始训练语言模型，让它学会语言的基本规律。

**通俗类比：** 就像婴儿学说话——没有人刻意教，但通过大量听大人说话，慢慢学会了语言的规则。

**具体示例：**
```
预训练任务（以GPT为例）：自回归语言建模

输入： "今天天气真"
目标： "好"

输入： "今天天气真好"
目标： "，"

模型通过数万亿个这样的"下一个词预测"任务，学会了：
  - 语法规则
  - 事实知识
  - 推理能力
  - 世界知识

预训练数据：
  Common Crawl (网页)：约 60%
  书籍：约 15%
  维基百科：约 5%
  代码 (GitHub)：约 10%
  其他：约 10%

训练成本：
  GPT-3 (175B)：约 460万美元
  LLaMA-2 (70B)：约 200万美元
```

**为什么需要它：** 预训练是大模型能力的基础，模型的所有知识都来源于预训练阶段。

---

## 7. SFT（监督微调）

**一句话定义：** 用人工标注的"问答对"数据来微调模型，教它如何正确回答问题。

**通俗类比：** 就像老师给学生批改作业——告诉模型"这个回答是对的，那个回答是错的"。

**具体示例：**
```
SFT 训练数据格式：
{
  "instruction": "翻译成英文",
  "input": "今天天气很好",
  "output": "The weather is nice today."
}

{
  "instruction": "总结以下文章",
  "input": "（一段长文）",
  "output": "（一段摘要）"
}

{
  "instruction": "写一首关于春天的诗",
  "input": "",
  "output": "春风拂面柳丝长，桃花盛开满园香..."
}

训练过程：
  模型看到 instruction + input → 尝试生成 output
  计算生成内容与真实 output 的差距 → 反向传播更新参数
```

**为什么需要它：** 预训练后的模型什么都能说但不知道"怎么说才对"，SFT 教它正确的回答格式和风格。

---

## 8. 指令微调（Instruction Tuning）

**一句话定义：** SFT 的一种特殊形式，专注于训练模型理解和执行各种指令。

**通俗类比：** 就像训练员工听指令——"写邮件"就写邮件，"做PPT"就做PPT，模型要学会听懂各种指令并执行。

**具体示例：**
```
指令微调数据集（Alpaca格式）：

1. 指令： "用一句话概括量子力学"
   输出： "量子力学是描述微观粒子行为的物理学理论。"

2. 指令： "写一封拒绝参加会议的邮件"
   输出： "尊敬的XX，很抱歉无法参加本次会议..."

3. 指令： "把以下列表排序：3,1,4,1,5,9"
   输出： "1, 1, 3, 4, 5, 9"

关键：指令类型要多样化，覆盖翻译、摘要、分类、生成等各种任务
```

**与相关术语的对比：**
- 指令微调 vs 普通SFT：指令微调强调"指令-执行"的格式，SFT 范围更广
- 指令微调 vs 预训练：预训练学知识，指令微调学如何执行任务

---

## 9. 数据标注

**一句话定义：** 给训练数据打上标签或写出正确答案，是微调数据的生产过程。

**通俗类比：** 就像给考试出答案——老师需要先写出每道题的正确答案，学生才能对照学习。

**具体示例：**
```
情感分析标注：
  文本： "这家餐厅的菜太难吃了"
  标签：负面

命名实体标注：
  文本： "张三在北京大学读书"
  标签：[张三/人名] 在 [北京大学/组织] 读书

问答对标注：
  文档： （一段关于公司政策的文字）
  问题： "年假有多少天？"
  答案： "入职满1年享5天年假，满5年享10天。"

标注工具：
  Label Studio（开源）
  Doccano（开源）
  Prodigy（付费，高效）
```

**为什么需要它：** 高质量的标注数据是微调成功的关键，"数据质量决定模型上限"。

---

## 10. 训练数据格式

**一句话定义：** 微调数据需要遵循特定的 JSON/JSONL 格式，才能被训练框架正确读取。

**通俗类比：** 就像寄快递需要标准的快递单格式——收件人、地址、电话缺一不可，模型训练也有固定的"快递单"格式。

**常见格式示例：**
```json
// Alpaca 格式（最常用）
{"instruction": "翻译成英文", "input": "你好", "output": "Hello"}

// ShareGPT 格式（多轮对话）
{"conversations": [
  {"from": "human", "value": "什么是机器学习？"},
  {"from": "gpt", "value": "机器学习是人工智能的一个分支..."},
  {"from": "human", "value": "它和深度学习有什么区别？"},
  {"from": "gpt", "value": "深度学习是机器学习的子集..."}
]}

// OpenAI 格式
{"messages": [
  {"role": "system", "content": "你是一个助手"},
  {"role": "user", "content": "你好"},
  {"role": "assistant", "content": "你好！有什么可以帮助你的？"}
]}
```

**为什么需要它：** 格式不对训练框架无法解析，标准格式确保数据能被正确加载和处理。

## 11. 过拟合与欠拟合

**一句话定义：** 过拟合是模型把训练数据"背下来了"但举一反三能力差；欠拟合是模型连训练数据都没学好。

**通俗类比：**
- 过拟合 = 考试前只背了原题，换了新题就不会了
- 欠拟合 = 连原题都不会做

**具体示例：**
```
训练集准确率：  98%
验证集准确率：  65%
→ 过拟合（训练好但泛化差）

训练集准确率：  55%
验证集准确率：  52%
→ 欠拟合（训练都没学好）

理想情况：
训练集准确率：  92%
验证集准确率：  89%
→ 既学得好又泛化好
```

**解决方法：**
```
过拟合 → 增加数据量、Dropout、Early Stopping、数据增强
欠拟合 → 增加模型容量、增加训练轮数、调整学习率
```

## 12. 学习率（Learning Rate）

**一句话定义：** 控制每次参数更新步幅大小的超参数，太大会"跳过"最优点，太小会收敛太慢。

**通俗类比：** 就像下山时的步伐——步子太大可能跨过最低点，步子太小走半天到不了。

**具体示例：**
```
学习率 = 0.001（太大）：
  Loss: 2.5 → 0.1 → 3.2 → 0.05 → 4.1（震荡，不收敛）

学习率 = 0.00001（太小）：
  Loss: 2.5 → 2.49 → 2.48 → 2.47（收敛太慢）

学习率 = 0.0003（合适）：
  Loss: 2.5 → 1.2 → 0.4 → 0.1 → 0.03（稳定收敛）

常用策略：学习率预热 + 衰减
  前100步：从0逐步增加到0.0003（预热）
  之后：缓慢衰减到0.00001
```

**为什么需要它：** 学习率是训练中最重要的超参数之一，直接影响训练是否收敛和收敛速度。

---

## 13. Epoch/Batch/Step

**一句话定义：** 描述训练过程的三个核心计数单位。

**通俗类比：**
- Epoch = 把所有教材读一遍
- Batch = 每次考试的题目数量
- Step = 做一道题

**具体示例：**
```
训练数据： 10万条样本
Batch Size：32
Epochs：3

计算：
  Steps per Epoch = 100000 / 32 = 3125 步
  Total Steps = 3125 × 3 = 9375 步

训练过程：
  Epoch 1:
    Step 1:    用第1-32条数据训练
    Step 2:    用第33-64条数据训练
    ...
    Step 3125: 用第99969-100000条数据训练
  
  Epoch 2:
    Step 3126: 重新打乱数据，从第1条开始
    ...
  
  Epoch 3: 完成所有训练
```

**为什么需要它：** 理解这三个概念才能正确设置训练参数和监控训练过程。

## 14. 混合精度训练

**一句话定义：** 同时使用 FP16（半精度）和 FP32（全精度）进行训练，加速计算并减少显存占用。

**通俗类比：** 就像用草稿纸做计算——简单计算用草稿纸（FP16）快速完成，关键步骤用正式稿纸（FP32）保证精度。

**具体示例：**
```
纯 FP32 训练：
  模型参数：7B × 4字节 = 28GB
  梯度：28GB
  优化器状态：56GB
  总显存：约 112GB

混合精度训练（FP16+FP32）：
  模型参数（FP16）：7B × 2字节 = 14GB
  梯度（FP16）：14GB
  优化器状态（FP32）：56GB
  Master Weights（FP32）：28GB
  总显存：约 80GB（减少约30%）

速度提升：约 1.5-3 倍（利用 Tensor Core 加速）
```

**为什么需要它：** 在不损失模型效果的前提下，显著减少显存占用和训练时间，是大模型训练的标配。

## PyTorch/HuggingFace 训练代码示例

```python
# 使用 HuggingFace Transformers 微调模型
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments, Trainer
from peft import LoraConfig, get_peft_model
from datasets import load_dataset

# 1. 加载模型和分词器
model_name = "meta-llama/Llama-2-7b-hf"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype="auto", device_map="auto")

# 2. 配置 LoRA
lora_config = LoraConfig(
    r=16,                    # 低秩维度
    lora_alpha=32,           # 缩放系数
    target_modules=["q_proj", "v_proj"],  # 应用 LoRA 的层
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(model, lora_config)

# 3. 加载和处理数据
dataset = load_dataset("json", data_files="train_data.json")
def preprocess(examples):
    return tokenizer(examples["text"], truncation=True, max_length=512)
tokenized_dataset = dataset.map(preprocess, batched=True)

# 4. 设置训练参数
training_args = TrainingArguments(
    output_dir="./output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=8,
    learning_rate=2e-4,
    warmup_steps=100,
    logging_steps=10,
    save_strategy="epoch",
    fp16=True,               # 混合精度训练
)

# 5. 开始训练
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset["train"],
)
trainer.train()
```
