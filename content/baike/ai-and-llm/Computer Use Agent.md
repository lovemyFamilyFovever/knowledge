# Computer Use Agent


> 📌 **导航**：本文是 **Computer Use Agent** 词条，属于 ai-and-llm 术语集。相关枢纽：[[大模型基础术语详解]]、[[Transformer架构深度解析]]、[[RAG 与检索技术详解]]、[[多 Agent 协作系统]]、[[Prompt 工程与 Agent 详解]]。

## 定义

**一句话定义：** Computer Use Agent 是能"看屏幕、动鼠标键盘"操作图形界面的 Agent，把视觉理解与 GUI 自动化结合，替人完成跨软件的桌面任务。

**通俗类比：** 像坐到你电脑前的远程助理——看你的屏幕（截图）、判断该点哪里、再替你点击打字，用的是和人一样的图形界面，而不是后台 API。

## 为什么需要它

大量老旧软件与桌面应用没有 API 或命令行接口，只能靠人点。Computer Use 让 AI 走"和人一样的通道"（看像素、动光标），从而把那些无接口可走的 GUI 应用纳入自动化范围。

## 核心能力

| 能力 | 说明 | 技术 |
|------|------|------|
| 屏幕理解 | 解析截图中的 UI 元素 | 视觉模型 + OCR |
| 元素定位 | 找到可交互元素坐标 | 目标检测 |
| 鼠标操作 | 点击、拖拽、滚动 | 自动化 API |
| 键盘输入 | 打字、快捷键 | 自动化 API |
| 屏幕录制 | 记录操作过程 | 录屏技术 |

**工作流**是"像素进、动作出"的感知—行动闭环：截图 → 视觉模型理解界面 → 决定下一步 → 执行点击 / 输入 → 再截图验证 → 迭代。实现层既可用 Anthropic 的 computer use 工具接口（工具版本标识 `computer_20241022`），也可用 PyAutoGUI 一类库做截图与点击，并配置 FAILSAFE（把鼠标甩到角落即停）等安全阀。

典型落地：GUI 自动化测试、RPA 办公、跨系统数据录入、标准化软件演示。它的通用性也带来稳定与安全上的挑战：

| 挑战 | 说明 |
|------|------|
| 延迟 | 视觉理解需要时间 |
| 准确性 | 坐标定位可能偏移 |
| 安全性 | 操控整机需严格权限 |
| 可复现性 | 界面改版可能导致失败 |

## 具体示例

"在桌面记账软件里逐条录入上月发票"：Agent 截图认出输入框 → 定位坐标 → 填入金额 → 再截图核对 → 下一条。一旦软件改版、按钮位置变化，坐标就可能错位，这正是它脆弱之处。

## 何时用 / 何时不用

- **用**：目标只有 GUI、没有 API，或需要跨多个封闭软件协同操作时。
- **不用**：有稳定 API 或成熟 RPA 脚本可用时，直接调接口更快更可靠；高危写操作环境须谨慎授权。

## 优劣与代价

✅ 打通无接口的软件，覆盖面广，逼近"通用桌面助手"。
⚠️ 视觉理解慢、坐标易偏、界面一改就失效，稳定性弱于 API 方案。
⚠️ 能操控整台机器，安全面极大，必须配套权限控制与人在环兜底。

## 与相关概念的区别

- **vs [[Web Agent]]**：Web Agent 在浏览器 DOM 内操作，有结构化信号可依；Computer Use 在屏幕像素层操作任意 GUI，更通用也更脆弱。
- **vs [[Code Agent]]**：后者在代码与开发工具链内工作，Computer Use 工作在图形界面层。

## 常见误区

- Computer Use Agent 必须依赖目标软件提供 API 才能操作它。
- 因为直接看截图定位，Computer Use 的坐标永远精确、界面改版也不受影响。
- 让 Agent 操控整台电脑没有额外风险，不必做权限控制。

## 面试速答

> 🎯 Computer Use Agent 让 AI 走"和人一样的通道"：截图 → 视觉理解 → 决定动作 → 点击 / 输入 → 再截图验证，专治没有 API 的桌面 / GUI 软件。相比 Web Agent 靠 DOM，它在像素层操作更通用，但延迟高、坐标易偏、界面改版即失效，且操控整机安全面大，需严格权限与人在环。
> 🔍 追问：它和 Web Agent 的关键差别？（Web Agent 用浏览器 DOM 结构，Computer Use 用屏幕像素 + 坐标，更通用更脆弱）
> 🔍 追问：为什么说它是高风险能力？（能读写任意界面、跨系统操作，误操作或被注入的影响面是"整台电脑"）
