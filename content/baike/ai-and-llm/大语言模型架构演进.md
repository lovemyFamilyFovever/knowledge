# 大语言模型架构演进


> 📌 **导航**：本文是 **大语言模型架构演进** 词条，是 LLM 架构谱系的总览枢纽。相关枢纽：[[Transformer架构深度解析]]、[[GPT系列模型演进]]、[[MoE 混合专家模型]]、[[Scaling Law]]。

## 定义

**一句话定义：** 本词条梳理大语言模型的架构演进——以 Transformer 为共同底座，沿规模、对齐、效率、多模态与开源五轴，从 GPT-1 一路走到 DeepSeek 的关键创新谱系。

**通俗类比：** 一条"同一引擎不断改装"的家谱树：每一代在参数规模、训练配方、注意力算子和开放程度上各进一步，看懂它就看懂了现代 LLM 从何而来。

## 为什么需要它

LLM 不是一次发明，而是十余个关键节点的累积。知道"谁在哪一步引入了什么"（BERT 双向、GPT-3 规模涌现、ChatGPT 对齐、GPT-4 多模态、Llama 开源、DeepSeek 细粒度 MoE），选型与学习才不会踩在旧认知上。

## 核心机制

1. **演进主线——一条时间线**：decoder（GPT 系）与 encoder（BERT）先分流，再靠规模涌现（GPT-3）、RLHF 对齐（ChatGPT）、多模态（GPT-4 / Gemini）、开源（Llama）与高效 MoE（DeepSeek V3）层层推进。

| 模型 | 年代 | 参数量 | 关键创新 |
|------|------|--------|---------|
| GPT-1 | 2018 | 117M | Transformer decoder |
| BERT | 2018 | 340M | 双向编码 |
| GPT-2 | 2019 | 1.5B | 零样本学习 |
| GPT-3 | 2020 | 175B | Few-shot learning |
| ChatGPT | 2022 | ~175B | RLHF 对齐 |
| GPT-4 | 2023 | ~1.8T (MoE) | 多模态 |
| Claude 3 | 2024 | 未知 | 长上下文 |
| Gemini | 2024 | 未知 | 原生多模态 |
| Llama 3 | 2024 | 8B-405B | 开源 SOTA |
| DeepSeek V3 | 2025 | 671B (MoE) | MoE 架构 |

2. **关键技术——把 Transformer 精修到高效**：底座仍是"Tokenizer → Embedding → N×(自注意力 + FFN) → 输出"，真正拉开工程差距的是这些算子：

| 技术 | 说明 | 贡献 |
|------|------|------|
| RoPE | 旋转位置编码 | 相对位置、可外推 |
| GQA | 分组查询注意力 | 大幅减少 KV Cache |
| RMSNorm | 均方根归一化 | 更稳定高效 |
| SwiGLU | 门控激活 | 更强表达力 |
| FlashAttention | IO 感知注意力 | 加速训练与推理 |

3. **开源 vs 闭源**：闭源（GPT-4 / Claude）能力顶尖但按 API 计费、数据需上传、更新由厂商控制；开源（Llama / Qwen）可自部署、数据本地、完全可定制、社区驱动快速追赶——选型看隐私、成本与定制需求。

## 具体示例

要做一个私有部署、可微调的中文助手：多从开源（Llama / Qwen 系）起步，用其 decoder-only 架构叠加 RoPE / GQA / RMSNorm / SwiGLU 组合，必要时上 MoE，按 [[Scaling Law]] 定参数与数据配比，再本地微调——这条路径的每一步都来自上面的演进史。

## 何时用 / 何时不用

- **用**：建立 LLM 全局坐标、判断某能力/技术出自哪个阶段、指导选型时。
- **不用**：把它当深读材料——某个模型 / 技术的机制细节请看对应专条。

## 常见误区

- GQA 的作用是显著增加 KV Cache 显存占用以提升精度。
- 现代大模型已纷纷抛弃 Transformer、改用全新的非注意力架构。
- BERT 是 decoder-only 的自回归生成架构。

## 面试速答

> 🎯 大模型架构以 Transformer 为共同底座，沿五轴演进：规模（GPT-1→3 与涌现）、对齐（ChatGPT 的 RLHF）、效率（RoPE、GQA、RMSNorm、FlashAttention）、多模态（GPT-4/Gemini）、开源与 MoE。闭源强但需上传数据，开源可自部署定制。
> 🔍 追问：GQA 相比 MHA 解决什么？（把 KV 头分组共享，大幅省 KV Cache 显存与带宽，几乎不掉质量）
> 🔍 追问：为什么说"从密集走向 MoE"？（用稀疏专家解耦总参数与每 token 计算，改善大容量下的训练 / 推理性价比）
