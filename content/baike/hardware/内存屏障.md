# 内存屏障


> 📌 **导航**：本文是 **内存屏障** 词条，属于 hardware 术语集。相关枢纽：[[CPU 缓存]]、[[CPU与处理器架构]]、[[RAID 磁盘阵列]]、[[主板与总线]]、[[内存与存储系统]]。

## 定义

**一句话定义：** 内存屏障（Memory Barrier / Memory Fence）是一种 CPU 指令或编译器约束，用于禁止其前后的内存操作被重排序，并保证内存写入对其他核心的可见性顺序，从而在多线程 / 多核环境下实现正确的同步语义。

**通俗类比：** 像流水线上的"闸门"——工序本可被调度器提前或延后（重排序）以提效，装上闸门后，闸前的操作必须先全部完成并对他人可见、闸后的才能开始，确保顺序不被打乱。

> 多义说明：有编译器屏障（禁止编译器重排）与 CPU 屏障（禁止处理器重排 / 刷新 store buffer）；按语义分读屏障、写屏障、全屏障。本文讨论其概念。

## 为什么需要它

编译器与 CPU（乱序执行、store buffer、缓存）会为提速而重排内存操作，单线程看不出问题，多线程下却会破坏预期的可见性与顺序——比如经典的双重检查锁若不加屏障，可能读到"引用非空但对象还没构造完"。屏障显式钉住顺序与可见性。

## 核心机制

- **屏障类型：** 写屏障（StoreStore / StoreLoad，保证之前的写先可见）、读屏障（LoadLoad / LoadStore，保证之前的读先完成）、全屏障。
- **效果：** 屏障前的操作先于屏障后的操作完成 / 可见，并强制刷新 store buffer、配合缓存一致性协议维护可见。
- **语言层依赖：** Java 的 volatile / final、C++ 的 atomic 与 memory_order、C11 内存模型，底层都依赖屏障实现顺序保证。

## 具体示例

双重检查锁单例里，"构造对象 + 赋指针"本是两步，CPU / 编译器可能重排成先赋指针、后初始化。给写指针前插 StoreStore 屏障（或在 Java 里把字段声明为 volatile），就能保证别的核看到非空指针时对象一定已构造完成。

## 何时用与何时不用

- **用：** 无锁编程 / 并发数据结构、双重检查锁、原子操作实现、内核同步、高性能并发库。
- **不用：** 常规业务优先用锁或语言提供的原子 / 内存序抽象，别手写屏障；能不加就不加——屏障有性能代价。

## 优劣与代价

✅ 在保证正确性的前提下提供比锁更轻量的顺序控制，支撑无锁编程。
⚠️ 滥用 / 过度屏障会阻止优化、损害性能；不同架构语义不同（x86 强序、ARM/POWER 弱序）；极难正确使用与调试。

## 与相关概念的区别

vs [[信号量与互斥锁]]：锁提供互斥且隐含顺序，内存屏障只管顺序与可见性、不提供互斥；vs [[缓存一致性]]：MESI 保证各核缓存最终一致，屏障额外约束指令流重排与 store buffer 刷出时机，二者配合才得到正确内存序；vs [[超标量与乱序执行]]：乱序正是屏障要"纠正"的重排来源。

## 常见误区

- 内存屏障是一种加锁机制、能实现互斥。
- Java 和 C/C++ 的 volatile 都能保证多线程可见性。
- 内存屏障没有代价、可以无脑到处添加。

## 面试速答

> 🎯 内存屏障 = 禁止屏障前后内存操作重排、保证写入对其他核可见顺序的 CPU/编译器约束；分读 / 写 / 全屏障，因编译器 + CPU 乱序与 store buffer 而必要（双重检查锁、volatile/atomic/memory_order 底层）；只约束顺序不互斥、有性能代价、x86 强序 ARM 弱序。
