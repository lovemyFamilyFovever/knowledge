# 内存屏障


> 📌 **导航**：本文是 **内存屏障** 词条，属于 hardware 术语集。相关枢纽：[[CPU 缓存]]、[[CPU与处理器架构]]、[[RAID 磁盘阵列]]、[[主板与总线]]、[[内存与存储系统]]。

## 定义

**一句话定义：** 内存屏障(Memory Barrier / Memory Fence)是一种 CPU 指令或编译器约束,用于禁止其前后的内存操作被重排序,并保证内存写入对其他核心的可见性顺序,从而在多线程/多核环境下实现正确的同步语义。

**通俗类比：** 像流水线上的"闸门"——正常情况下工序可被调度器提前或延后(重排序)以提效,但装上闸门(屏障)后,闸门前的操作必须先全部完成并对他人可见,闸门后的才能开始,确保顺序不被打乱。

> 多义说明:有编译器屏障(禁止编译器重排)与 CPU 屏障(禁止处理器重排/刷新 store buffer);按语义分读屏障、写屏障、全屏障。本文讨论其概念。

## 原理与机制

- **为何需要:** 编译器与 CPU(乱序执行、store buffer、缓存)会重排内存操作以提效;单线程看不出问题,但多线程下重排会破坏预期的可见性与顺序(如双重检查锁失效)。
- **屏障类型:** 写屏障(StoreStore / StoreLoad,保证之前的写先可见)、读屏障(LoadLoad / LoadStore,保证之前的读先完成)、全屏障。
- **效果:** 屏障前的操作先于屏障后的操作完成/可见;并强制刷新 store buffer、维护缓存一致。
- **语言层面:** Java 的 volatile/final、C++ 的 atomic 与 memory_order、C11 内存模型底层都依赖屏障。

## 关键组成

| 组成 | 说明 |
|------|------|
| 编译器屏障 | 禁止编译器重排 |
| CPU 屏障 | 禁止处理器重排 |
| 读 / 写 / 全屏障 | 不同语义的屏障 |
| store buffer 刷新 | 保证写可见 |
| 内存序(memory order) | 语言层的顺序约束 |

## 应用场景

- 无锁编程、并发数据结构
- 双重检查锁
- 原子操作实现、内核同步
- 高性能并发库

## 优点与局限

- 优点:在保证正确性的前提下提供比锁更轻量的顺序控制,支撑无锁编程。
- 局限:滥用/过度屏障会损害性能(阻止优化);不同架构屏障语义/指令不同(x86 强序、ARM 弱序);极难正确使用与调试。

## 常见误区

- 内存屏障不"加锁":它约束顺序与可见性,不提供互斥。
- x86 是较强内存模型(部分重排少),ARM/POWER 是弱内存模型(需显式屏障)。
- Java 的 volatile 含屏障语义,而 C/C++ 的 volatile 不保证多线程可见性(需用 atomic)。
- 屏障有性能代价,不应无脑添加。
