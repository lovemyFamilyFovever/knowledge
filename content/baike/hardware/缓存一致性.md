# 缓存一致性


> 📌 **导航**：本文是 **缓存一致性** 词条，属于 hardware 术语集。相关枢纽：[[CPU 缓存]]、[[CPU与处理器架构]]、[[RAID 磁盘阵列]]、[[主板与总线]]、[[内存与存储系统]]。

## 定义

**一句话定义：** 缓存一致性（Cache Coherence）是多处理器 / 多核系统中，保证各核心的私有缓存对同一共享内存地址的副本保持一致的机制，使一个核对数据的修改能被其他核正确观察到、避免读到过期数据。

**通俗类比：** 像多个同事各自复印了同一份文件——有人在自己那份上做了修改，必须有一套机制通知其他人"这份改了、你的作废 / 需更新"，否则大家拿着不同版本就会出错。

> 多义说明：缓存一致性（coherence，针对同一地址多副本的一致）≠ 内存一致性模型（consistency，针对不同地址访问的顺序）；也 ≠ 数据库 / 分布式系统中的"缓存一致"。本文讨论多核硬件的 cache coherence。

## 为什么需要它

每个核有私有 L1/L2，同一块内存可能被多核各自缓存一份。若核 A 改了数据而核 B 还拿着旧副本，程序就会读到过期值、逻辑错乱。缓存一致性硬件协议保证"同一地址改后其他副本失效或更新"，是多核正确运行的地基。

## 核心机制

- **问题根源：** 多核各有私有缓存，共享数据可能被多核同时缓存，某核写入后其他核的副本会变陈旧。
- **监听（snooping）协议：** 各缓存监听总线上的读写事件、靠状态转换维护一致，经典为 MESI（Modified / Exclusive / Shared / Invalid）四态。
- **目录（directory）协议：** 用目录记录"哪些缓存持有某数据行"，减少总线广播，更适合大规模系统。
- **写策略：** 写无效（write-invalidate，使其他核副本失效）与写更新（write-update）。

## 具体示例

两个核各把某缓存行置为 Shared；核 A 要写，先广播无效化、把核 B 的同行降为 Invalid、自己转 Modified——核 B 下次读就 miss、重新取最新值，这就是 MESI 保一致。若两个不同变量恰好落在同一 64B 行、被两核频繁互写，会不停互相无效化 → 伪共享，性能骤降。

## 何时用与何时不用

- **用：** 多核 CPU 与 SMP、GPU、多处理器架构；为多线程共享数据提供硬件级一致。
- **注意：** 硬件一致 ≠ 程序正确——跨多语句的原子性与顺序仍须软件锁 / 原子 / [[内存屏障]]；用按缓存行对齐填充来消除伪共享。

## 优劣与代价

✅ 对软件透明地维护多核缓存一致，是多核正确性的硬件基础。
⚠️ 协议有开销（总线流量 / 目录存储）；伪共享导致性能下降；大规模一致性成本高；不替代软件同步。

## 与相关概念的区别

vs 内存一致性模型：coherence 管"同一地址多副本是否一致"，consistency 管"不同地址访问的可见顺序"（后者才需内存屏障约束，见 [[内存屏障]]）；vs [[CPU 缓存]]：那是单核缓存层次与命中率，本文是多核间副本一致。

## 常见误区

- 缓存一致性（coherence）和内存一致性模型（consistency）是一回事。
- 硬件保证了缓存一致，多线程就不需要再加锁同步了。
- 一致性协议能自动避免伪共享带来的性能问题。

## 面试速答

> 🎯 缓存一致性（coherence）= 多核对同一地址的缓存副本保持一致，让一个核的写被其他核正确看到：MESI 四态监听协议（或目录协议）+ 写无效 / 写更新；它管单地址、不等于内存一致性模型（跨地址顺序、需屏障），也不替代软件锁；同缓存行多变量互写会伪共享。
