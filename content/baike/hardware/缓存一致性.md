# 缓存一致性

## 定义

**一句话定义：** 缓存一致性(Cache Coherence)是多处理器/多核系统中,保证各核心的私有缓存对同一共享内存地址的副本保持一致的机制,使一个核对数据的修改能被其他核正确观察到,避免读到过期数据。

**通俗类比：** 像多个同事各自复印了同一份文件(缓存副本)——当有人在自己那份上做了修改,必须有一套机制通知其他人"这份改了,你的作废/需更新",否则大家拿着不同版本就会出错。

> 多义说明:缓存一致性(coherence,针对**同一地址**多副本的一致)≠ 内存一致性模型(consistency,针对**不同地址**访问的顺序);也 ≠ 数据库/分布式系统中的"缓存一致"。本文讨论多核硬件的 cache coherence。

## 原理与机制

- **问题:** 多核各有私有缓存,共享数据可能被多核同时缓存;某核写入后,其他核的副本会变陈旧。
- **监听(snooping)协议:** 各缓存监听总线上的读写事件,通过状态转换维护一致;经典为 MESI(Modified / Exclusive / Shared / Invalid)四态。
- **目录(directory)协议:** 用目录记录"哪些缓存持有某数据行",减少广播,更适合大规模系统。
- **写策略:** 写无效(write-invalidate,使其他核副本失效)与写更新(write-update)。

## 关键组成

| 组成 | 说明 |
|------|------|
| 私有缓存副本 | 各核持有的数据副本 |
| MESI 状态 | Modified/Exclusive/Shared/Invalid |
| 监听 / 目录协议 | 维护副本一致的机制 |
| 写无效 / 写更新 | 处理写操作的策略 |
| 总线 / 互连 | 传递一致性消息 |

## 应用场景

- 多核 CPU 与 SMP 系统
- GPU、多处理器架构
- 为多线程共享数据提供硬件级一致(软件仍需同步,见 [[信号量与互斥锁]])

## 优点与局限

- 优点:对软件透明地维护多核缓存一致,是多核正确性的硬件基础。
- 局限:协议开销(总线流量或目录存储);伪共享(false sharing)导致性能下降;大规模一致性成本高;不替代软件同步(原子性/顺序仍需锁或屏障)。

## 常见误区

- coherence ≠ consistency:前者是单地址多副本一致,后者是跨地址的访问顺序(内存模型)。
- 硬件保证缓存一致,但"多线程数据竞争"仍需软件同步(硬件一致 ≠ 程序正确)。
- 伪共享是一致性协议的副作用(不同变量落在同一缓存行)。
- coherence 不保证跨地址的可见性顺序(需内存屏障)。
