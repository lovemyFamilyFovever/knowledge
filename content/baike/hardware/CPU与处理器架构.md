# CPU与处理器架构


> 📌 **导航**：本文是 **CPU与处理器架构** 词条，属于 hardware 术语集。相关枢纽：[[CPU 缓存]]、[[CPU与处理器架构]]、[[RAID 磁盘阵列]]、[[主板与总线]]、[[内存与存储系统]]。

## 定义

**一句话定义：** CPU（中央处理器）是计算机中执行指令、进行算术逻辑运算并协调各部件工作的核心芯片，其架构决定了取指—执行方式、并行能力与性能特征。

**通俗类比：** 若把计算机比作厨房，CPU 就是主厨——所有菜品（程序指令）都要经他的手（运算）才能完成；核心数是同时掌勺的厨师数，时钟频率是他动作的快慢。

> 多义说明：本文综述 CPU 的整体架构与关键指标；更细的子主题见专门词条——[[指令流水线]]（流水线与冒险）、[[指令集架构]]（CISC/RISC、ISA）、[[CPU 缓存]]（存储层次）、[[分支预测]]（推测执行）、[[冯·诺依曼结构]]（存储程序模型）。

## 原理与机制

- **指令周期**：取指（Fetch）→ 译码（Decode）→ 执行（Execute）→ 访存（Memory）→ 写回（Write Back），每秒循环数十亿次。
- **流水线与超标量**：把指令周期拆成多级流水、多条指令重叠执行；超标量（superscalar）每周期发射多条指令（详见 [[指令流水线]]）。
- **乱序执行 + 推测执行**：在不改变语义的前提下重排指令、预测分支提前执行，以填满流水线（详见 [[分支预测]]）。
- **多核与多线程**：多个物理核心并行；SMT/超线程让一个物理核对外呈现为两个逻辑核，共享执行单元以提高利用率。

## 关键组成

| 部件 | 作用 |
|------|------|
| 控制单元（CU） | 取指、译码、产生控制信号 |
| 算术逻辑单元（ALU） | 整数算术与逻辑运算 |
| 浮点单元（FPU）/ 向量单元 | 浮点与 SIMD 运算 |
| 寄存器 | CPU 内部最快的小容量存储（PC、SP、通用寄存器等） |
| 缓存 L1/L2/L3 | 缓解 CPU 与内存的速度差（详见 [[CPU 缓存]]） |
| 总线接口 | 与内存、芯片组、外设通信 |

### 时钟频率、核心与线程

- **时钟频率**：每秒的时钟周期数，单位 GHz；3.5 GHz ≈ 每秒 35 亿个周期。频率不等于性能，还取决于架构与 IPC（每周期指令数）。
- **核心数**：物理处理单元数量，多核利于可并行任务（编译、渲染）。
- **线程 / 超线程（SMT）**：一个物理核模拟出两个逻辑核，共享执行资源以提升吞吐（并非等于两个真核）。

### 缓存与存储层次

| 层级 | 典型容量 | 相对速度 | 说明 |
|------|----------|----------|------|
| 寄存器 | 几十~几百 B | 最快 | CPU 内部 |
| L1 | 32–64 KB/核 | 极快 | 常分指令缓存 / 数据缓存 |
| L2 | 256 KB–1 MB/核 | 很快 | 多为每核独立 |
| L3 | 4–64 MB | 较快 | 多核共享 |
| 内存(RAM) | 8–128 GB | 慢 | 见 [[内存与存储系统]] |
| 硬盘 | 256 GB+ | 最慢 | 持久存储 |

### 处理器架构（ISA 流派）

- **x86 / x64（CISC）**：复杂指令集，Intel/AMD 主导，用于 PC 与服务器；现代 x86 内部会把复杂指令译码为类 RISC 的**微操作（micro-ops）**再执行。
- **ARM（RISC）**：精简指令集，低功耗，用于手机/平板，并已扩展到笔记本（Apple M 系列）与服务器（如 AWS Graviton）。

## 应用场景

- 通用计算（PC、服务器、嵌入式）；多核用于可并行任务（编译、渲染、科学计算）。
- 选型关注：单核性能（游戏、日常响应）、多核吞吐（内容创作、服务器）、能效比（移动设备）。

## 关键指标与常见误区

| 指标 | 含义 | 常见误区 |
|------|------|----------|
| 频率(GHz) | 每秒周期数 | ≠ 性能，需结合架构与 IPC |
| 核心/线程 | 并行能力 | 逻辑核（超线程）≠ 物理核 |
| 缓存 | 近 CPU 的高速存储 | 越大越好，但成本/面积上升 |
| TDP | 散热设计功耗 | 功耗 ≠ 性能，也非实时功耗 |
| 制程(nm) | 工艺节点 | 「nm」是商业代号，非晶体管真实物理尺寸 |

## 优点与局限

- 优点：擅长复杂逻辑、串行任务与低延迟控制，是通用计算的核心；生态成熟。
- 局限：核心数有限，大规模并行（图形、AI 训练）不如 GPU；受功耗、散热与「内存墙」制约，主频提升趋缓，转向多核与专用加速（如内置 NPU/GPU）。

## 常见误区

- 「频率越高越快」：跨架构不能只看频率，IPC 与缓存同样关键。
- 「核越多越好」：单线程任务用不上多核，还取决于软件能否并行。
- 「nm 越小晶体管就是那个尺寸」：现代节点命名是营销代号，与栅极长度等物理尺寸不直接对应。
