# CPU 缓存


> 📌 **导航**：本文是 **CPU 缓存** 词条，属于 hardware 术语集。相关枢纽：[[CPU 缓存]]、[[CPU与处理器架构]]、[[RAID 磁盘阵列]]、[[主板与总线]]、[[内存与存储系统]]。

## 定义

**一句话定义：** CPU 缓存（Cache）是位于处理器与主存之间的高速、小容量存储器，用于临时保存最近或频繁访问的指令与数据，借助程序访问的局部性原理弥补 CPU 与主存之间的速度鸿沟、降低平均访存时间。

**通俗类比：** 像书桌与书架——正在用的书放在手边书桌（缓存）上拿取飞快，暂时不看的放回远处书架（内存）、要用时再取回；把常用的放手边就不必频繁跑书架。

> 多义说明：缓存常分为指令缓存（L1i）与数据缓存（L1d），并有 L1/L2/L3 多级；本文讨论通用机制。

## 为什么需要它

CPU 比主存快几个数量级，若每次取数都要访主存，CPU 大部分时间在空等——这就是"存储墙"。缓存把热点数据提到贴近 CPU 的高速层，用少量高成本存储换巨大的平均访存提速，缓解冯·诺依曼瓶颈。

## 核心机制

- **局部性原理：** 时间局部性（刚访问的数据很可能再被访问）、空间局部性（邻近地址很可能被访问）。
- **缓存行与映射：** 以固定大小的块（常见 64 字节）在主存与缓存间搬运；映射有直接、组相联、全相联，用标签 / 索引 / 偏移定位归属。
- **命中与缺失：** 命中直接返回；缺失需从下级加载，分强制缺失、容量缺失、冲突缺失。
- **写策略与替换：** 写回（write-back）/ 写通（write-through），替换如 LRU；多核用一致性协议（MESI）保证各核缓存视图一致。

| 组成 | 作用 |
|------|------|
| 缓存行 cache line | 数据搬运的基本单位（常 64B） |
| 标签 / 索引 / 偏移 | 定位数据属于哪个内存块 |
| 多级 L1/L2/L3 | 容量递增、速度递减 |
| 映射与替换 | 决定放置与淘汰（直接 / 组相联 / 全相联、LRU） |
| 写策略 | 写回 / 写通，影响一致性与延迟 |
| 一致性协议 MESI | 多核间保持缓存一致 |

## 具体示例

按行优先遍历二维数组比列优先快很多：缓存按 64 字节行预取，顺序访问命中率高；而两个变量落在同一缓存行、被不同核频繁各写各的，会触发 MESI 反复失效——即伪共享（false sharing），需按缓存行对齐填充来消除。

## 何时用与何时不用

- **用：** 所有现代 CPU 的存储层次；性能优化靠缓存友好的数据布局与访问顺序、多核编程规避伪共享。
- **注意：** 不能把它当黑盒不管——数据布局、访问顺序直接决定命中率与并行性能。

## 优劣与代价

✅ 大幅降低平均访存延迟、提升吞吐、缓解冯·诺依曼瓶颈。
⚠️ 容量有限、缺失代价高；层级越深延迟越高；多核一致性复杂；不当布局或伪共享会显著拖累性能。

## 与相关概念的区别

vs [[内存与存储系统]]：主存（DRAM）比缓存慢、容量大，是缓存的下级；vs [[指令流水线]]：缓存命中与否决定流水线会不会因等内存而 stall；vs 软件缓存：那是应用层用内存 / 磁盘做副本，CPU 缓存由硬件自动维护。

## 常见误区

- CPU 缓存对程序员完全透明，所以性能上不必关心它。
- 缓存越大就一定越快。
- 多核下某个核写入的数据，其他核会立刻自然可见。

## 面试速答

> 🎯 CPU 缓存 = 贴 CPU 的高速小容量层，靠时间 / 空间局部性、以缓存行（~64B）搬运、分 L1/L2/L3 与直接 / 组相联 / 全相联映射、写回或写通 + LRU 替换；缺失分强制 / 容量 / 冲突，多核靠 MESI 保持一致、警惕伪共享。
