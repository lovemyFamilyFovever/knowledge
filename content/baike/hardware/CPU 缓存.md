# CPU 缓存

## 定义

**一句话定义：** CPU 缓存(Cache)是位于处理器与主存之间的高速、小容量存储器,用于临时保存最近或频繁访问的指令与数据,借助程序访问的局部性原理弥补 CPU 与主存之间的速度鸿沟,降低平均访存时间。

**通俗类比：** 像书桌与书架——你正在用的书放在手边书桌(缓存)上,拿取飞快;书桌放不下或暂时不看的放回远处书架(内存),要用时再取回。把常用的放手边,就不必频繁跑书架。

> 多义说明:缓存常分为指令缓存(L1i)与数据缓存(L1d),并有 L1/L2/L3 多级;本文讨论通用机制。

## 原理与机制

- **局部性原理:** 时间局部性(刚访问的数据很可能再被访问)、空间局部性(邻近地址的数据很可能被访问)。
- **缓存行(cache line):** 以固定大小的块(常见 64 字节)为单位在主存与缓存之间搬运。
- **映射方式:** 直接映射、组相联(set-associative)、全相联。
- **命中与缺失:** 命中(hit)直接返回;缺失(miss)需从下级存储加载,分为强制缺失、容量缺失、冲突缺失。
- **写策略与替换:** 写回(write-back)/写通(write-through);替换算法如 LRU。多核下用一致性协议(如 MESI)保证各核缓存一致。

## 关键组成

| 组成 | 作用 |
|------|------|
| 缓存行(cache line) | 数据搬运的基本单位 |
| 标签/索引/偏移 | 定位数据属于哪个内存块 |
| 多级缓存 L1/L2/L3 | 容量递增、速度递减的层次 |
| 映射与替换策略 | 决定放置与淘汰 |
| 写策略 | 写回/写通,影响一致性与时延 |
| 一致性协议(MESI) | 多核间保持缓存一致 |

## 应用场景

- 所有现代 CPU 的存储层次
- 性能优化:缓存友好的数据布局与访问顺序
- 多核并行编程(需规避伪共享 false sharing)
- GPU 与嵌入式处理器的存储管理

## 优点与局限

- 优点:大幅降低平均访存延迟、提升吞吐,缓解冯·诺依曼瓶颈。
- 局限:容量有限;缓存缺失代价高;多核一致性复杂;不当的数据布局或伪共享会显著拖累并行性能。

## 常见误区

- 缓存对程序员是"透明"的,但其性能影响并不透明——数据布局直接决定命中率。
- 缓存并非越大越快:层级越深,访问延迟越高。
- 多核下"一个核写入,别的核立刻可见"并非天然成立,需一致性协议保障。
