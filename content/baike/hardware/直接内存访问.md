# 直接内存访问


> 📌 **导航**：本文是 **直接内存访问** 词条，属于 hardware 术语集。相关枢纽：[[CPU 缓存]]、[[CPU与处理器架构]]、[[RAID 磁盘阵列]]、[[主板与总线]]、[[内存与存储系统]]。

## 定义

**一句话定义：** 直接内存访问（Direct Memory Access，DMA）是一种让外设（如磁盘、网卡）通过专门的 DMA 控制器直接与主存交换数据、而无需 CPU 逐字节搬运的机制，从而在大批量 I/O 时释放 CPU、提升系统整体效率。

**通俗类比：** 像快递直接送进你家仓库（内存），而不是每件都先经你手（CPU）再搬进去——你只需开始时下个单、结束时收一个"送完了"的通知（中断），中间搬运由专门的搬运队（DMA 控制器）完成。

> 多义说明：DMA 指以"数据块"为单位的传输机制；区别于程序查询 I/O 与逐字节的中断驱动 I/O。本文讨论块传输的 DMA。

## 为什么需要它

若每读一个扇区、每收一个网络包都要 CPU 逐字节从设备寄存器拷进内存，CPU 会被 I/O 拖死（程序查询 / 中断驱动 I/O 皆如此）。DMA 把"成块搬运"外包给专用控制器，CPU 只在开始配置、结束收中断时参与，腾出手做计算。

## 核心机制

- **流程：** CPU 配置 DMA 控制器（源 / 目的地址、字节数、方向）→ 控制器接管总线，在设备与内存间逐块搬数据 → 传输完成后向 CPU 发一个中断。
- **CPU 介入点：** 仅在"开始配置"与"结束响应中断"时参与，中间不逐字节搬运。
- **总线使用：** 周期窃取（cycle stealing）——DMA 分时占用总线，可能与 CPU 访存竞争。
- **现代扩展：** 分散-聚集（scatter-gather）DMA；IOMMU 为设备提供地址转换与隔离（虚拟化与安全需要）。

## 具体示例

SSD 读 1 MB：CPU 只需告诉 DMA 控制器"从这地址、读这么多字节到那块内存"，控制器自己搬完发一个中断，期间 CPU 可切去跑别的线程——相比逐 4 KB 中断驱动，中断次数与 CPU 占用大幅下降。Linux 的 sendfile / mmap 零拷贝也建立在 DMA 之上。

## 何时用与何时不用

- **用：** 磁盘 / SSD 读写、网卡收发包、声卡显卡等高速外设数据传输、零拷贝（zero-copy）技术的基础。
- **注意：** 极少量字节传输用 DMA 反而配置开销不划算（PIO / 中断驱动即可）；不安全外设直访内存要靠 IOMMU 拦截。

## 优劣与代价

✅ 大批量 I/O 时大幅降低 CPU 占用、提高吞吐。
⚠️ 需额外硬件（DMA 控制器）；存在总线竞争；编程更复杂；可绕过 CPU 直接读写内存，滥用 / 被攻击有安全风险（需 IOMMU 防护）。

## 与相关概念的区别

vs 中断驱动 I/O：中断驱动仍由 CPU 逐字节搬、频繁触发中断，DMA 按块自动搬、结束才中断一次；vs [[输入输出与外设]] 的 PIO：程序查询 I/O 让 CPU 主动轮询搬运，DMA 把搬运交给控制器——都属 I/O 方式，差别在 CPU 参与程度。

## 常见误区

- 用了 DMA 后 CPU 就完全不参与数据传输了。
- DMA 就是中断驱动 I/O 的另一种叫法。
- DMA 直接访问内存没有安全风险。

## 面试速答

> 🎯 DMA = 外设经 DMA 控制器直接和主存成块交换数据、CPU 只在开始配置、结束收中断时介入（不逐字节搬），靠周期窃取分时用总线，现代有 scatter-gather 与 IOMMU 做地址转换与隔离；是零拷贝基础，但直访内存有安全面（Thunderclap 类攻击）。
