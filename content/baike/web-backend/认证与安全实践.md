# 认证与安全实践

## Web认证方式

**一句话定义：** 认证是确认"你是谁"的过程，授权是确认"你能做什么"的过程。

### 认证方式对比

| 方式 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| Session | 服务端存储状态 | 安全、可控 | 有状态、难扩展 |
| JWT | 客户端携带令牌 | 无状态、易扩展 | 无法主动失效 |
| OAuth 2.0 | 第三方授权 | 标准化 | 实现复杂 |
| API Key | 简单密钥 | 简单易用 | 安全性低 |

### Session认证流程

```
1. 用户登录 → 服务端验证
2. 服务端创建Session → 返回Session ID（Cookie）
3. 后续请求携带Cookie
4. 服务端根据Session ID查找用户信息
```

### JWT认证流程

```
1. 用户登录 → 服务端验证
2. 服务端生成JWT（包含用户信息+签名）→ 返回
3. 客户端存储JWT（localStorage/Cookie）
4. 后续请求在Header携带: Authorization: Bearer <token>
5. 服务端验证JWT签名 → 提取用户信息
```

### JWT结构

```
Header.Payload.Signature
eyJhbG...  ← Base64编码的JSON

Header: {"alg": "HS256", "typ": "JWT"}
Payload: {"sub": "1234", "name": "John", "exp": 1690000000}
Signature: HMAC-SHA256(header + "." + payload, secret)
```

### Web安全最佳实践

**1. SQL注入防护**
```python
# 错误！
query = f"SELECT * FROM users WHERE name='{username}'"

# 正确：参数化查询
cursor.execute("SELECT * FROM users WHERE name=?", (username,))
```

**2. XSS防护**
- 输出转义：`{{ user.name | e }}`
- Content-Security-Policy头
- HttpOnly Cookie

**3. CSRF防护**
- CSRF Token
- SameSite Cookie属性
- 验证Referer头

**4. 密码存储**
```python
# 错误！
hashed = md5(password)

# 正确：使用bcrypt/argon2
from bcrypt import hashpw, gensalt
hashed = hashpw(password.encode(), gensalt())
```

**5. HTTPS**
- 所有生产环境必须使用HTTPS
- 使用HSTS强制HTTPS
- 证书用Let's Encrypt（免费）
