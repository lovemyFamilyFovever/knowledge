# 认证与安全实践


> 📌 **导航**：本文是 **认证与安全实践** 词条，属于 web-backend 术语集。相关枢纽：[[Web框架对比]]、[[缓存策略]]、[[认证与安全实践]]。

## 定义

**一句话定义：** 认证（Authentication）是确认"你是谁"，授权（Authorization）是确认"你能做什么"；Web 安全实践则是在这条身份链路与输入输出边界上堵住最常见的攻击面。

**通俗类比：** 认证像进大楼前刷工牌确认身份，授权像工牌决定了你能进哪几层；HTTPS 是保密通道，而 SQL 注入、XSS 相当于有人往登记簿里填别人的名字。

## 为什么需要它

HTTP 本身无状态，每个请求都得自证身份；一旦身份判断出错或被绕过，后面的所有权限控制一起失效。同时 Web 应用的所有输入都来自不可信的公网，攻击者会主动试探拼接 SQL、回显脚本、跨站请求——安全不是附加功能，而是默认假设。

## 核心机制

| 方式 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| Session | 服务端存状态，Cookie 只带 ID | 可控、能即时踢出 | 有状态，多实例要共享存储 |
| JWT | 客户端携带自签名令牌 | 无状态、易水平扩展 | 签发后难主动失效 |
| OAuth 2.0 | 第三方授权框架（授权码模式常用） | 标准化、可委托与限 Scope | 流程复杂，本身不定义身份 |
| API Key | 简单密钥 | 接入极简 | 粒度粗、泄漏面大、难轮换 |

- **Session 流程**：登录 → 服务端建会话 → Set-Cookie 下发 Session ID → 后续请求带 Cookie，服务端查表还原用户。会话放 Redis 即可多实例共享（见 [[缓存策略]]）。
- **JWT 流程**：登录 → 服务端签出 `Header.Payload.Signature`（三段 Base64URL，签名 HMAC-SHA256 或 RSA）→ 客户端存储并以 `Authorization: Bearer <token>` 携带 → 服务端只验签不查库。Payload 只是编码不是加密，别放敏感数据。
- **失效对策**：短 access TTL + refresh token 轮换，必要时用 Redis 黑名单或 token 版本号把"无状态"换回可控。
- **加固清单**：SQL 注入用参数化查询，不拼字符串；XSS 靠输出转义 + CSP + HttpOnly Cookie；CSRF 靠同步 token、SameSite 属性与校验来源；密码用 bcrypt/argon2 这类加盐慢哈希，不用 MD5/SHA；全站 HTTPS + HSTS，证书可用 Let's Encrypt 免费签发（见 [[SQL注入与XSS]]、[[HTTPS 与 TLS]]）。

## 具体示例

给 App 供 API：登录成功后签 15 分钟 access JWT + 30 天 refresh；Web 端把两者放 HttpOnly + SameSite=Lax 的 Cookie 里，避免脚本读取；后台管理另做角色校验（同一 token，不同 Scope）。用户改密时把 token 版本号 +1，旧令牌立刻失效。密码入库只存 `hashpw(password, gensalt())` 的 bcrypt 结果，永不存明文或可逆密文。

## 何时用与何时不用

- **Session**：单体或集中式服务、需要立即踢人、客户端只有自家网页。
- **JWT**：多服务/多端要免中心化查询验签、移动端长期令牌、微服务间传递身份（见 [[微服务架构]]）。
- **OAuth 2.0**：要接第三方登录或开放平台授权；需要"是谁在调用"而非仅"有权"时叠 OIDC。**API Key** 只适合服务间调用与配额。
- **不用**：把 JWT 当会话替代品去承载细粒度权限——权限变更不会自动反映到已签发的令牌里。

## 优劣与代价

✅ 无状态令牌让水平扩展与跨服务传播变得简单；标准协议省去自造轮子的安全审计成本。
⚠️ 令牌一旦签出就脱离服务端控制，失效、撤销、算法误配（`alg: none`、混淆 HS/RS）都是真实事故来源。
⚠️ 完整链条还要加：速率限制、审计日志、依赖库 CVE 跟进、最小权限。清单很长，任何一环缺失都等于没有。

## 与相关概念的区别

- **认证 vs 授权**：前者回答"你是谁"，后者回答"你能做什么"（RBAC/ABAC 属于后者）；OAuth 2.0 是授权框架，身份认证要靠其上的 OIDC（见 [[OAuth 与 JWT]]）。
- **加密 vs 哈希 vs 签名**：加密可逆保机密、哈希单向比一致性（密码用慢哈希）、签名证明来源与完整性（JWT 的 Signature 属此类）。
- **认证 vs 会话管理**：认证是一次性事件，会话是持续状态；JWT 把会话状态隐式写进令牌，Session 把它显式留在服务端。

## 常见误区

- JWT 可以在服务端随时作废，所以不必设短过期时间。
- 密码只要用 MD5 或 SHA256 哈希过，就不算明文泄露。
- Cookie 设了 HttpOnly，就再也不必管 XSS 了。
