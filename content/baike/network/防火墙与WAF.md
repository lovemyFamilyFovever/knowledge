# 防火墙与WAF

> 📌 **导航**：本文是 **防火墙与WAF** 词条，由 [[网络安全协议]] 拆分而来。

## 定义

**一句话定义：** 防火墙按规则控制进出流量——包过滤看 IP / 端口、状态检测看连接是否"先出后回"、应用层防火墙 WAF 看 HTTP 内容；WAF 专防 SQL 注入 / XSS 等 Web 攻击，IDS / IPS 负责入侵检测 / 阻断。

**通俗类比：** 包过滤像门卫查身份证、状态检测像"只让出过门的人再回来"、WAF 像安检员开包看内容、IDS/IPS 像监控系统发现异常就报警或拦下。

## 为什么需要它

网络威胁分多层：非授权访问、异常连接、恶意 payload 各不相同，单一层拦不住。逐层设防——网络层包过滤、传输层状态检测、应用层 WAF、行为层 IDS/IPS，构成纵深防御。

## 核心机制

- **包过滤（网络层）：** 按源 / 目的 IP、端口、协议放行或丢弃（iptables ACCEPT/DROP）。
- **状态检测（传输层）：** 跟踪连接状态，只放行 ESTABLISHED/RELATED 回包与受控的 NEW。
- **WAF（应用层）：** 深入 HTTP 内容，用规则拦 SQLi / XSS / 危险文件上传，可透明串联、反向代理或云 WAF 部署。
- **IDS vs IPS：** IDS 旁路检测、只告警（不误杀）；IPS 串联、检测即阻断（误报会中断正常流量）。

## 具体示例

对外 Web 的纵深：DNS → 云 WAF / DDoS 清洗 → 防火墙（只放 80/443、SSH 限内网）→ 反向代理；WAF 拦 `id=1' OR '1'='1` 这类注入，IPS 在内部东西向检测异常访问。

## 何时用与何时不用

- **用：** 边界默认拒绝 + 白名单放行；Web 前置 WAF；需审计 / 阻断配 IDS/IPS；生产启用状态检测而非纯包过滤。
- **注意：** WAF 不替代代码层输入校验与参数化查询（那才是根因）；IPS 串联误报会阻断正常流量，宜先 IDS 观察再上 IPS。

## 优劣与代价

✅ 多层纵深防御、规则集中可审计。
⚠️ 纯包过滤不懂状态、易误放 / 误拦；WAF 规则维护成本高、存在绕过；IPS 误报影响可用性。

## 与相关概念的区别

vs [[代理与正向反向代理]]：WAF 常以反向代理形态部署，但职责是"检查内容"；vs [[HTTPS 与 TLS]]：加密由 TLS、内容级防护由 WAF；vs [[DDoS攻击与防护]]：WAF / 防火墙管"恶意内容与访问"，DDoS 防护管"流量洪峰"。

## 常见误区

- 装了防火墙就等于 Web 安全、不必管 SQL 注入。
- IPS 一定比 IDS 好、应直接上 IPS。
- WAF 能替代代码层的输入校验。

## 面试速答

> 🎯 防火墙与 WAF：包过滤(网络层看 IP/端口)→状态检测(传输层只放 ESTABLISHED/RELATED)→WAF(应用层看 HTTP 内容,拦 SQLi/XSS/危险上传)；IDS 旁路告警、IPS 串联阻断(先 IDS 观察再 IPS)；WAF 多以反代/云 WAF 部署，但不替代代码层参数化校验。
