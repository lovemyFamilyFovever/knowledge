# 文件传输协议

> 📌 **导航**：本文是 **文件传输协议** 词条，由 [[应用层协议]] 拆分而来。

## 定义

**一句话定义：** 文件传输协议族解决"把文件从 A 搬到 B"——FTP 用控制连接（21）+ 数据连接（20 / 被动随机端口）、分主动 / 被动模式、明文传输；SFTP / SCP 复用 SSH（22）全程加密，FTPS 在 FTP 上叠 TLS（990）。

**通俗类比：** FTP 像寄明信片（命令和数据都公开），SFTP / SCP 像走加密专线快递；FTP 的主动模式是"快递员上门取件"、被动模式是"你自己去网点"。

## 为什么需要它

早期文件传输要跨防火墙、支持断点续传，FTP 用双通道满足；但它明文传密码，现代安全要求下须改用 SSH 系（SFTP / SCP）或 TLS（FTPS）。

## 核心机制

- **FTP 双通道：** 控制连接 21 走命令，数据连接走内容——主动(PORT)由服务器从 20 连回客户端数据口、被动(PASV)由客户端连服务器新开的端口。
- **主动 vs 被动：** 客户端有防火墙时主动模式连不进来，被动(PASV)对客户端防火墙更友好，是默认选择。
- **安全替代：** SFTP / SCP 复用 SSH 单端口 22、全程加密、防火墙友好；FTPS 用 990。

## 具体示例

公网传文件优先 SFTP / `scp` / `rsync`（走 22、免开双端口）；用 FTP 时选被动模式以穿过客户端 NAT / 防火墙；大文件增量同步用 `rsync` 而非整体重传。

## 何时用与何时不用

- **用：** 脚本化传输用 scp / rsync；交互式浏览远端目录用 sftp；兼容遗留系统才用 FTP。
- **不用：** 别在公网用明文 FTP 传凭据；被动模式的高端口也可能给服务端防火墙添麻烦，能上 SSH 就别上 FTP。

## 优劣与代价

✅ FTP 功能全（目录、断点续传）、被动模式穿墙；SFTP / SCP 加密且防火墙友好。
⚠️ FTP 双通道 + 明文是历史包袱；被动高端口仍需服务端放行；各协议端口 / 加密不一，易配错。

## 与相关概念的区别

vs [[SSH与远程登录]]：SFTP / SCP 是 SSH 的文件传输子系统、复用其加密通道；vs [[HTTPS 与 TLS]]：FTPS 是"在旧协议上叠 TLS"的同一思路。

## 常见误区

- SFTP 是 FTP 的"加速 / 简化版"，与 SSH 无关。
- FTP 主动模式一定比被动模式好用。
- FTP 传输密码有加密、公网可以放心用。

## 面试速答

> 🎯 文件传输协议族：FTP 双通道(控制 21 + 数据 20/被动随机)、主动(PORT 服务器连入) vs 被动(PASV 客户端连出、穿防火墙更友好)、明文；SFTP/SCP 复用 SSH(22) 全程加密单端口，FTPS(990) 叠 TLS；公网默认选 SFTP/scp/rsync。
