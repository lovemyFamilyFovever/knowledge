# 内容分发网络


> 📌 **导航**：本文是 **内容分发网络** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 内容分发网络（Content Delivery Network，CDN）是由分布在各地的边缘服务器组成的网络，它把内容缓存到离用户更近的位置并按需就近提供服务，从而降低访问延迟、减轻源站压力、提升可用性与抗攻击能力。

**通俗类比：** 像连锁便利店——总仓库（源站）不必服务全国每个人，各地便利店（边缘节点）就近备着常用商品（缓存内容），你在家门口就能买到，不必千里迢迢跑总仓。

> 多义说明：CDN 既指基础设施 / 服务，也指其缓存与分发机制；本文综合讨论。

## 为什么需要它

用户地理分散、访问又集中到源站，会有高延迟、带宽瓶颈与单点风险。CDN 把热点内容复制到靠近用户的边缘节点，就近命中直接返回、未命中才回源，既提速又护源站，还能借分布式边缘吸收 DDoS。

## 核心机制

- **缓存与回源：** 边缘节点缓存静态内容；未命中（miss）时向源站回源拉取并缓存。
- **请求调度：** 通过 DNS 解析（CNAME 到 CDN 域名）、Anycast 或 HTTP 重定向，把用户请求导向最优（最近 / 最闲）边缘节点。
- **缓存策略：** 靠 Cache-Control / TTL、缓存键设计决定缓存什么、存多久，用 purge（刷新）/ prefetch（预热）管理内容时效。
- **动态加速：** 对不可缓存内容用路由优化、连接复用、TLS 优化、边缘回源专线等手段加速。

## 具体示例

图片站上 CDN：用户请求 `img.xx.com/a.png` 经 DNS 解析到就近边缘节点，命中直接回图、未命中回源取并缓存，之后同区域用户都命中边缘——源站带宽骤降、用户延迟更低；发布新版后调 purge 刷新缓存，避免用户拿到旧图。

## 何时用与何时不用

- **用：** 网站 / 图片 / 视频 / 静态资源加速、大文件与软件分发、直播与流媒体、DDoS 缓解与流量吸收。
- **不用 / 慎用：** 强动态、每请求个性化且不可缓存的内容收益有限（要靠动态加速而非普通缓存）；源站本已够快的小站，别为缓存一致性徒增复杂度。

## 优劣与代价

✅ 降低延迟、节省源站带宽、提升可用性与抗压能力、就近服务全球用户。
⚠️ 对动态 / 个性化内容加速有限；缓存一致性（过期、刷新）复杂；有成本、可能被厂商锁定；有时会掩盖源站自身问题。

## 与相关概念的区别

vs [[负载均衡]]：负载均衡把请求分发到同一服务的多个后端实例、解决"单实例过载"，CDN 解决"内容离用户太远"，二者常配合（回源后再 LB）；vs [[缓存策略]]：CDN 是地理分布式的边缘缓存，进程内 / Redis 缓存是应用内缓存，层次不同。

## 常见误区

- 加了 CDN 源站就再也不会被打垮。
- CDN 对动态个性化内容和静态资源一样能靠缓存加速。
- CDN 就是负载均衡的另一种叫法。

## 面试速答

> 🎯 CDN = 全球边缘节点缓存内容 + 智能调度（DNS CNAME / Anycast / 重定向）就近服务，靠 Cache-Control/TTL/回源/purge/预热管理缓存，对静态内容大幅降延迟、护源站、抗 DDoS；动态内容需专门的动态加速。
