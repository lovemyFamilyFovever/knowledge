# 组播与广播


> 📌 **导航**：本文是 **组播与广播** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 广播（Broadcast）是把数据发送给网络中所有主机的传输方式，组播（Multicast，多播）是把数据发送给一组特定订阅者（加入某组播组的主机）的传输方式；二者与单播（Unicast，一对一）并列，是"一对多"通信的不同形态。

**通俗类比：** 单播像打电话给某一个人；广播像用大喇叭对全场喊话（所有人都听到）；组播像微信群发——只有加入了这个群（组播组）的人才收到，不在群里的人不受打扰。

> 多义说明：单播 / 组播 / 广播是三种传输方式；组播依赖 IGMP（管理组成员）与组播路由（如 PIM）。本文对比组播与广播。

## 为什么需要它

一份内容要同时发给很多人时，单播要逐份复制、浪费源与带宽；广播虽一次到位却打扰全网、还出不了广播域。组播折中：源只发一份，网络在分叉处复制、只交给订阅了该组的接收者，兼顾效率与隔离。

## 核心机制

- **单播：** 一对一，多个接收者时源需为每人各发一份。
- **广播：** 一对所有，限于同一广播域（二层广播如 ARP；三层广播默认不被路由器转发）。
- **组播：** 一对一组，用 IPv4 D 类地址（224.0.0.0/4）标识组；主机用 IGMP 加入 / 离开组，组播路由（PIM、DVMRP）构建分发树，只在有接收者的分支转发以省带宽。

## 具体示例

IPTV 直播：电视台向一个组播地址发一路流，运营商网络用 PIM 建分发树，只有加入该频道组、且下游有观众的分支才复制转发——一路视频服务成千上万用户而不占万倍带宽；OSPF 等路由协议也用组播向邻居发更新。

## 何时用与何时不用

- **用：** 直播 / IPTV、视频会议、在线游戏状态同步、金融行情分发、服务发现（mDNS / SSDP）、路由协议（OSPF）。
- **不用：** 跨公网、需可靠有序的点到点传输用单播 + TCP；广播慎用于易起广播风暴的大网段。

## 优劣与代价

✅ 组播节省带宽、源不必知道所有接收者；广播简单、无需预知接收者。
⚠️ 组播部署复杂（设备需支持 IGMP/PIM）、多基于 UDP 不可靠、跨公网组播受限；广播有广播风暴风险、仅限广播域、浪费带宽。

## 与相关概念的区别

组播 vs 广播：组播只发给加入组的接收者、其余主机不受影响，广播发给广播域内所有主机；vs 单播：单播点对点、多人要多份，组播一份共享；组播多建立在 [[用户数据报协议]] 上、可靠性需应用层补偿。

## 常见误区

- 组播和广播是一回事。
- 广播可以随意跨路由器扩散到整网 / 互联网。
- 组播传输默认是可靠的。

## 面试速答

> 🎯 单播 / 组播 / 广播是三种传输方式：广播发给广播域内所有主机（路由器默认不转发）、组播用 D 类地址经 IGMP 加入组、PIM 建分发树只在有接收者处复制（省带宽）、单播一对一；组播多基于 UDP 不保证可靠、跨公网受限。
