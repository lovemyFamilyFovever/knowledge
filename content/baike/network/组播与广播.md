# 组播与广播

## 定义

**一句话定义：** 广播(Broadcast)是把数据发送给网络中所有主机的传输方式;组播(Multicast,多播)是把数据发送给一组特定订阅者(加入某组播组的主机)的传输方式;二者与单播(Unicast,一对一)并列,是"一对多"通信的不同形态。

**通俗类比：** 单播像打电话给某一个人;广播像用大喇叭对全场喊话(所有人都听到);组播像微信群发——只有加入了这个群(组播组)的人才收到,不在群里的人不受打扰。

> 多义说明:单播 / 组播 / 广播是三种传输方式;组播依赖 IGMP(管理组成员)与组播路由(如 PIM)。本文对比组播与广播。

## 原理与机制

- **单播:** 一对一;多个接收者时源需为每个接收者各发一份。
- **广播:** 一对所有;局限在同一广播域(二层广播如 ARP;三层广播受限,路由器默认不转发广播)。
- **组播:** 一对一组;使用组播地址(IPv4 的 D 类 224.0.0.0/4);主机用 IGMP 加入/离开组播组;组播路由(PIM、DVMRP)构建分发树,只在有接收者的分支转发,节省带宽。

## 关键组成

| 组成 | 说明 |
|------|------|
| 单播 / 组播 / 广播 | 三种传输方式 |
| 组播地址(D 类) | 标识组播组 |
| IGMP | 管理组成员加入/离开 |
| 组播路由(PIM) | 构建分发树 |

## 应用场景

- 直播 / IPTV、视频会议
- 在线游戏状态同步、金融行情分发
- 服务发现(mDNS / SSDP)
- 路由协议(OSPF 使用组播)

## 优点与局限

- 组播:优点=节省带宽(一份数据多接收者)、源不必知道所有接收者;局限=部署复杂(需设备支持 IGMP/PIM)、多基于 UDP(不可靠,需应用层补偿)、跨公网组播受限。
- 广播:优点=简单、无需知道接收者;局限=广播风暴风险、仅限广播域、浪费带宽(所有主机都收)。

## 常见误区

- 广播默认不能跨路由器(广播域被隔离)。
- 组播 ≠ 广播:组播只发给组成员,更省带宽。
- 组播多基于 UDP(不保证可靠,需应用层处理)。
- 组播需要交换机/路由器支持 IGMP/PIM 才能生效。
