# QUIC

## 定义

**一句话定义：** QUIC 是一种基于 UDP 的现代传输层协议(为 HTTP/3 设计),它在用户态实现了可靠传输、多路复用、内建 TLS 加密与连接迁移,旨在解决 TCP + TLS 的队头阻塞与握手延迟问题。

**通俗类比：** 如果说 TCP 是一条"单车道高速公路"(一处事故就堵死后面所有车,即队头阻塞),QUIC 就像"多车道 + 每辆车独立"——一条流堵了不影响其他流;而且上路前的手续(握手 + 加密)一次办好,更快更顺。

> 多义说明:QUIC 最初由 Google 提出,后由 IETF 标准化(RFC 9000);HTTP/3 = HTTP over QUIC。区别于基于内核、面向字节流的 TCP。本文讨论 IETF QUIC。

## 原理与机制

- **基于 UDP:** 在用户态实现可靠性(重传、拥塞控制),绕开内核 TCP 栈,便于快速演进与部署。
- **无队头阻塞的多路复用:** 多个流(stream)相互独立,单个流丢包不阻塞其他流(解决 TCP 的队头阻塞)。
- **内建加密:** 集成 TLS 1.3,握手与传输加密合一,减少 RTT(支持 1-RTT,甚至 0-RTT)。
- **连接迁移(Connection ID):** 用连接 ID 而非四元组标识连接,切换网络(如 WiFi → 蜂窝)时连接不中断。

## 关键组成

| 组成 | 作用 |
|------|------|
| 基于 UDP | 用户态实现可靠传输 |
| 流(stream)多路复用 | 独立流,避免队头阻塞 |
| 内建 TLS 1.3 | 加密与握手合一 |
| 连接 ID 与迁移 | 网络切换不断连 |
| 用户态拥塞控制 | 可快速迭代算法 |

## 应用场景

- HTTP/3、Web 与视频传输
- 移动端(频繁网络切换)
- 降低建连延迟与队头阻塞的场景

## 优点与局限

- 优点:无队头阻塞、握手快(0/1-RTT)、内建加密、支持连接迁移、用户态易于演进。
- 局限:基于 UDP 可能被网络设备限速或阻断;用户态实现 CPU 开销较高;生态与中间件仍在完善;缺少内核 TCP 的成熟优化。

## 常见误区

- QUIC 不是 TCP 的小改,而是全新的基于 UDP 的传输协议。
- HTTP/3 用 QUIC,HTTP/2 用 TCP(且 HTTP/2 存在 TCP 层队头阻塞)。
- QUIC 内建加密(TLS 1.3),不可关闭。
- 0-RTT 存在重放攻击风险,需谨慎使用。
