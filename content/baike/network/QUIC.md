# QUIC


> 📌 **导航**：本文是 **QUIC** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** QUIC 是一种基于 UDP 的现代传输层协议（为 HTTP/3 设计），它在用户态实现了可靠传输、多路复用、内建 TLS 加密与连接迁移，旨在解决 TCP + TLS 的队头阻塞与握手延迟问题。

**通俗类比：** TCP 像一条"单车道高速"（一处事故就堵死后面所有车，即队头阻塞），QUIC 像"多车道、每辆车独立"——一条流堵了不影响其他流；而且上路前的手续（握手 + 加密）一次办好，更快更顺。

> 多义说明：QUIC 最初由 Google 提出、后由 IETF 标准化（RFC 9000）；HTTP/3 = HTTP over QUIC。区别于基于内核、面向字节流的 TCP。本文讨论 IETF QUIC。

## 为什么需要它

HTTPS 的 TCP 全局有序 + 字节流，使 HTTP/2 的多路复用一旦一个包丢失、所有流都得等重传（传输层队头阻塞）；TCP 握手再叠加 TLS 握手又拖慢建连；移动网络换 IP 会断连。QUIC 把这些痛点在用户态基于 UDP 重写解决。

## 核心机制

- **基于 UDP：** 在用户态实现重传与拥塞控制，绕开内核 TCP 栈，便于快速演进与部署。
- **无队头阻塞的多路复用：** 多个 stream 相互独立，单个流丢包不会阻塞其他流。
- **内建加密：** 集成 TLS 1.3，握手与传输加密合一、减少 RTT（1-RTT 建连、会话恢复可 0-RTT，但 0-RTT 有重放风险）。
- **连接迁移：** 用 Connection ID 而非四元组标识连接，切换网络（WiFi ↔ 蜂窝）时连接不中断。

## 具体示例

手机从 Wi-Fi 切到 4G：TCP 连接因源 IP 变化而断开、需重连重握手；QUIC 用不变的 Connection ID 认连接，切换网络后原会话继续，用户几乎无感——这正是连接迁移的价值。

## 何时用与何时不用

- **用：** HTTP/3、Web 与视频传输、移动端频繁切网、追求低建连延迟并消除传输层队头阻塞的场景。
- **不用：** 对 UDP 可能被网络设备限速 / 阻断、需要内核 TCP 成熟优化或极低 CPU 开销的环境要权衡；0-RTT 涉及重放敏感操作时慎用。

## 优劣与代价

✅ 无队头阻塞、握手快（0 / 1-RTT）、内建加密、支持连接迁移、用户态易于演进。
⚠️ 基于 UDP 可能被中间设备限速 / 阻断；用户态实现 CPU 开销较高；生态与中间件仍在完善、缺少内核 TCP 的成熟优化。

## 与相关概念的区别

vs [[TCP深入]]：TCP 在内核、全局字节流有序，HTTP/2 复用仍受 TCP 队头阻塞；QUIC 在用户态基于 UDP、每流独立、握手加密合一；vs HTTP/3：HTTP/3 就是 HTTP over QUIC（RFC 9114）。

## 常见误区

- QUIC 只是对 TCP 做了一点小改动。
- HTTP/2 和 HTTP/3 在队头阻塞上没有区别。
- QUIC 的加密可以按需关闭。

## 面试速答

> 🎯 QUIC = 基于 UDP、在用户态实现可靠传输 + 无队头阻塞的 stream 多路复用 + 内建 TLS 1.3（1-RTT/0-RTT）+ Connection ID 连接迁移，解决 TCP+TLS 的队头阻塞 / 握手延迟 / 切网断连问题，是 HTTP/3 的底座。
