# 地址解析协议


> 📌 **导航**：本文是 **地址解析协议** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 地址解析协议(Address Resolution Protocol, ARP)用于在局域网中把已知的 IP 地址(网络层)解析为对应的 MAC 地址(数据链路层),以便在以太网等链路上传输数据帧;它是 IP 通信落到底层硬件地址的关键桥梁。

**通俗类比：** 像在公司里知道某人的工号(IP),但要当面找他得先查到工位(MAC)——你喊一嗓子"工号 X 的工位在哪?"(ARP 广播请求),本人应答"在这"(ARP 响应),你就记住位置(缓存)以便直接过去。

> 多义说明:ARP 用于 IPv4(IP → MAC);IPv6 改用 NDP(邻居发现协议);反向解析为 RARP(现已少用)。本文讨论 ARP。

## 原理与机制

- **请求(广播):** 主机 A 要向同网段的 B 发数据,但只知 B 的 IP,于是广播 ARP 请求("谁是 IP_B?请告知你的 MAC")。
- **响应(单播):** B 收到后单播回复自己的 MAC 地址。
- **缓存:** A 把 IP → MAC 映射存入 ARP 缓存(有 TTL),减少重复广播。
- **跨网段:** 当目标不在同一网段时,解析的是默认网关(路由器)的 MAC,由网关继续转发。

## 关键组成

| 组成 | 作用 |
|------|------|
| ARP 请求(广播) | 询问某 IP 对应的 MAC |
| ARP 响应(单播) | 回复 MAC 地址 |
| ARP 缓存表 | 缓存 IP↔MAC 映射 |
| 网关 MAC | 跨网段时解析路由器 MAC |

## 应用场景

- 局域网内的 IP 通信
- 路由器与主机的地址解析
- 网络排障(`arp` 命令查看/管理缓存)

## 优点与局限

- 优点:自动、无需人工配置地完成 IP → MAC 映射,支撑以太网通信。
- 局限:广播带来开销;缓存有时效;协议无认证,易受 ARP 欺骗/投毒(中间人攻击),需静态绑定或动态检测防护。

## 常见误区

- ARP 解析的是"同网段"目标的 MAC;跨网段时解析的是网关的 MAC。
- ARP 无认证机制,因此存在 ARP 欺骗风险。
- IPv6 不使用 ARP,而使用 NDP(邻居发现)。
- ARP 工作在网络层与数据链路层之间(地址映射)。
