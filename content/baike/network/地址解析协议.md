# 地址解析协议


> 📌 **导航**：本文是 **地址解析协议** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 地址解析协议（Address Resolution Protocol，ARP）用于在局域网中把已知的 IP 地址（网络层）解析为对应的 MAC 地址（数据链路层），以便在以太网等链路上传输数据帧；它是 IP 通信落到底层硬件地址的关键桥梁。

**通俗类比：** 像在公司里知道某人的工号（IP），但要当面找他得先查到工位（MAC）——你喊一嗓子"工号 X 的工位在哪?"（ARP 广播请求），本人应答"在这"（ARP 响应），你就记住位置（缓存）以便直接过去。

> 多义说明：ARP 用于 IPv4（IP → MAC）；IPv6 改用 NDP（邻居发现协议）；反向解析为 RARP（现已少用）。本文讨论 ARP。

## 为什么需要它

以太网帧只能凭 MAC 地址投递，而应用层知道的是 IP。同一网段内要把包送到某台主机，就得先把它的 IP 翻译成 MAC。ARP 就是这层"IP → 同网段 MAC"的自动映射，让 IP 通信能落到链路层硬件地址。

## 核心机制

- **请求（广播）：** 主机 A 要向同网段 B 发数据、只知 B 的 IP，于是广播 ARP 请求"谁是 IP_B？请告知你的 MAC"。
- **响应（单播）：** B 收到后单播回复自己的 MAC 地址。
- **缓存：** A 把 IP → MAC 映射存入 ARP 缓存（有 TTL），减少重复广播。
- **跨网段：** 目标不在同网段时，解析的是默认网关（路由器）的 MAC，由网关继续转发。

## 具体示例

本机 `arp -a` 能看缓存的 IP↔MAC 表；给同网段主机发包时若无缓存就广播 ARP 请求、拿到 MAC 后单播发送并缓存；访问外网时 ARP 解析的其实是默认网关的 MAC，帧的下一跳交给路由器转发。

## 何时用与何时不用

- **用：** 局域网内的 IP 通信、路由器与主机的地址解析、网络排障（`arp` 命令查看 / 管理缓存）。
- **不用（别误用）：** 跨网段不要指望 ARP 直接解析远端主机 MAC（只能解析到网关）；IPv6 场景改用 NDP、不用 ARP。

## 优劣与代价

✅ 自动、无需人工配置地完成 IP → MAC 映射，支撑以太网通信。
⚠️ 广播带来开销；缓存有时效；协议无认证、易受 ARP 欺骗 / 投毒（中间人攻击），需静态绑定或动态检测（如 DHCP Snooping + DAI）防护。

## 与相关概念的区别

vs DNS：DNS 把"域名 → IP"（高层名字），ARP 把"IP → MAC"（链路层硬件地址）；vs [[网络地址转换]]：NAT 改写 IP / 端口做地址复用，ARP 只做同网段的 IP↔MAC 映射，层次与目的都不同。

## 常见误区

- ARP 会把任意目的 IP 解析成该目的主机的 MAC。
- IPv6 仍然使用 ARP。
- ARP 有身份认证、不会被欺骗。

## 面试速答

> 🎯 ARP = 把同网段的"已知 IP 解析成 MAC"：广播问"谁是 IP_B"、对端单播答 MAC、结果带 TTL 缓存；跨网段解析的是默认网关 MAC 而非远端；协议无认证故有 ARP 欺骗风险，IPv6 用 NDP 取代 ARP。
