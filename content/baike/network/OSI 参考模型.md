# OSI 参考模型


> 📌 **导航**：本文是 **OSI 参考模型** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** OSI 参考模型（Open Systems Interconnection Reference Model）是 ISO 提出的概念性七层网络架构，自下而上为物理层、数据链路层、网络层、传输层、会话层、表示层、应用层，用于标准化和描述不同系统间通信的功能划分。

**通俗类比：** 像一家公司的组织分层——一线搬运（物理层）、部门内传递（链路层）、跨部门路由（网络层）、端到端送达确认（传输层）……每层只与相邻层打交道、各司其职，你不必知道楼下怎么运作就能用楼上的服务。

> 多义说明：OSI 既指参考模型（七层概念框架，广泛使用），也指当年一套具体的 OSI 协议族（实际未被大规模采用）。本文讨论参考模型。

## 为什么需要它

网络系统由不同厂商、不同技术拼装，需要一套共同"语言"来划分职责、界定接口、定位故障。OSI 用七层抽象把复杂通信拆成各司其职、边界清晰的功能块，让设计、教学与排错都有一个公共坐标系。

## 核心机制

核心思想是分层（layering）与封装（encapsulation）：

- 每层向上层提供服务、对上层屏蔽实现细节，层间通过明确定义的接口交互。
- 数据自上而下逐层封装（加头部 / 尾部），到对端再自下而上逐层解封装。
- 分层带来模块化：某层技术演进（如物理层从以太网到 Wi-Fi）不影响其他层。

| 层 | 名称 | 关注点 | 典型协议 / 单位 |
|----|------|--------|-----------------|
| 7 | 应用层 Application | 面向用户的应用服务 | HTTP、DNS、SMTP |
| 6 | 表示层 Presentation | 数据格式 / 加密 / 压缩 | TLS、编码转换 |
| 5 | 会话层 Session | 建立 / 管理 / 终止会话 | 会话控制 |
| 4 | 传输层 Transport | 端到端可靠传输 | TCP、UDP / 段(segment) |
| 3 | 网络层 Network | 逻辑寻址与路由 | IP / 包(packet) |
| 2 | 数据链路层 Data Link | 相邻节点可靠传输、MAC 寻址 | Ethernet、ARP / 帧(frame) |
| 1 | 物理层 Physical | 比特在介质上的传输 | 电压、光、无线电 / 比特(bit) |

## 具体示例

排查"网页打不开"就用分层思维逐层隔离：物理层看网线 / Wi-Fi 是否通，链路层看能否拿到 IP、能否 ARP，网络层看能否 ping 通网关与外网 IP，传输层看端口是否可达，应用层才看 DNS 解析与 HTTP 响应——把问题锁定到某一层。

## 何时用与何时不用

- **用：** 网络教学与概念框架、协议设计与标准化的沟通语言、故障排查的分层定位。
- **不用：** 把它当成真实部署协议栈——实际互联网用的是更简化的 TCP/IP 四层模型，会话层 / 表示层在现实中界限模糊。

## 优劣与代价

✅ 概念清晰、层次分明，是通用的"讨论语言"，促进互操作与模块化设计。
⚠️ 是理论模型而非实际部署标准；会话 / 表示层界限模糊；部分功能在层间的划分存在争议。

## 与相关概念的区别

vs TCP/IP 模型：OSI 七层是教学参考框架，TCP/IP（链路 / 网络 / 传输 / 应用四层）是互联网实际栈，二者可对照；vs 具体协议：OSI 是"模型"，HTTP / TCP / IP 是落在各层的"协议"。

## 常见误区

- OSI 就是互联网实际使用的协议栈。
- OSI 和 HTTP、TCP 一样是具体的协议。
- 交换机、路由器严格只工作在某一层。

## 面试速答

> 🎯 OSI = ISO 的概念性七层框架（物理 / 链路 / 网络 / 传输 / 会话 / 表示 / 应用），靠分层 + 封装划分职责、定位故障；它是"讨论语言"而非实际栈，真实互联网用更简的 TCP/IP 四层模型。
