# SSH与远程登录

> 📌 **导航**：本文是 **SSH与远程登录** 词条，由 [[应用层协议]] 拆分而来。

## 定义

**一句话定义：** SSH 是加密的远程终端协议（22），用公钥 / 密码认证登录并管理远程主机、还支持端口转发，取代明文的 Telnet（23）；其子系统 scp / sftp / rsync 顺带解决了安全的文件传输。

**通俗类比：** SSH 像加密电话——内容全程加密、还能验证对方身份；Telnet 像明码电报，每个字（含密码）都在网络上裸奔。

## 为什么需要它

远程管理是运维日常，若在明文信道传密码与命令会被窃听、篡改。SSH 提供加密 + 身份认证 + 隧道，既能安全登录、又能复用做端口转发与文件传输。

## 核心机制

- **认证：** 密码，或更安全的密钥——`ssh-keygen` 生成密钥对、`ssh-copy-id` 上传公钥实现免密登录。
- **端口转发：** 本地 `-L`（把远端服务映到本地）、远程 `-R`、动态 `-D`（SOCKS 代理）。
- **子系统：** `scp` / `sftp` / `rsync` 复用同一加密通道传文件。
- **配置：** `~/.ssh/config` 配 Host 别名与 IdentityFile，简化反复连接。

## 具体示例

生产环境禁用密码登录、改密钥 + 改非默认端口 + fail2ban；用 `ssh -L 3306:localhost:3306 user@host` 把远端 MySQL 安全映射到本地调试，胜过明文暴露数据库端口。

## 何时用与何时不用

- **用：** 一切远程 shell、脚本化运维、端口转发与 SFTP / SCP 传输都用 SSH。
- **不用：** Telnet 仅适合隔离网内调试端口连通性（更优用 nc / Test-NetConnection），绝不用来传凭据。

## 优劣与代价

✅ 加密 + 强认证 + 隧道 + 文件传输一体，是远程管理的事实标准。
⚠️ 首次连接需校验主机指纹（防中间人）；私钥须妥善保管；配置与端口转发有学习曲线。

## 与相关概念的区别

vs [[文件传输协议]]：SFTP / SCP 复用 SSH 通道；vs [[HTTPS 与 TLS]]：都用公钥加密思想，SSH 面向终端会话与隧道、TLS 面向应用层传输加密。

## 常见误区

- SSH 和 Telnet 都能远程登录、安全性差不多。
- 用了 SSH 就一定安全，不必校验首次主机指纹。
- 密钥太麻烦，生产还是密码登录更实际。

## 面试速答

> 🎯 SSH(22) = 加密远程终端 + 公钥 / 密码认证 + 端口转发(-L/-R/-D)，子系统 scp/sftp/rsync 走同一加密通道，取代明文 Telnet(23)；生产用密钥登录、校验首次主机指纹防中间人、禁用 Telnet 传凭据。
