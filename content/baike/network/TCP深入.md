# TCP深入


> 📌 **导航**：本文是 **TCP深入** 枢纽页，属于 network 术语集。各机制已拆到专门词条，本页只做全景索引与关系。

## 定义

**一句话定义：** TCP（传输控制协议）是面向连接、可靠有序的传输层协议，靠三次握手建连、序列号 / 确认 / 重传保可靠、滑动窗口控流量、拥塞控制护网络；本页是 TCP 深入主题的枢纽索引，把各机制归口到专门词条。

**通俗类比：** TCP 像寄挂号信——先确认对方在家（握手）、编号寄送（序列号）、丢了补发（重传）、确认收到才结束（挥手）。

## 为什么需要它

TCP 机制多且彼此咬合（握手 / 挥手 / 窗口 / 拥塞 / 状态回收 / 分帧 / 保活 / 报文格式），且多数已拆成专条。需要一张地图把"某个 TCP 问题属于哪块机制、去哪深入"讲清，本页承担这个索引角色。

## 核心机制

- **连接管理：** 三次握手建连、四次挥手释放，因全双工须各方向单独关闭，主动方进入 TIME_WAIT，详见 [[三次握手与四次挥手]]。
- **流量控制：** 接收方用滑动窗口（rwnd）告知"还能收多少"、缓冲区满时零窗口、靠窗口更新报文恢复，详见 [[滑动窗口]]。
- **拥塞控制：** 发送方用拥塞窗口（cwnd）探网络容量，慢启动 / 拥塞避免 / 快重传 / 快恢复，实际发送窗 = min(rwnd, cwnd)，详见 [[拥塞控制]]。
- **TIME_WAIT 与连接回收：** 主动关闭方等 2MSL 保最后 ACK 可达并让旧报文消散，高并发短连接会耗尽端口，详见 [[TIME_WAIT与连接回收]]。
- **粘包 / 拆包：** TCP 字节流无消息边界，须由应用层用定长 / 分隔符 / 长度前缀分帧，详见 [[TCP粘包与拆包]]。
- **对比与保活：** 与 UDP 的可靠 / 不可靠取向对比见 [[用户数据报协议]]；连接存活探测用 TCP Keep-Alive（默认 2 小时），与 HTTP keep-alive 复用是两回事；SYN Flood 打的是握手半连接队列、用 SYN Cookie 无状态缓解。

TCP 报文首部关键字段（服务于上述机制）：

| 字段 | 位数 | 作用 |
|---|---|---|
| 源 / 目的端口 | 16 × 2 | 标识进程端点 |
| 序列号 / 确认号 | 32 × 2 | 保证有序与确认 |
| 数据偏移 / 标志 | 4 / 8 | 首部长度；SYN/ACK/FIN/RST 等 |
| 窗口 | 16 | 流量控制（通告 rwnd） |
| 校验和 / 选项 | 16 / 变长 | 差错检测；MSS、窗口缩放 |

## 具体示例

一次连接的完整生命周期把上述机制串起来：SYN → SYN+ACK → ACK 握手（[[三次握手与四次挥手]]）→ 在 min(rwnd, cwnd) 窗口内传数据、丢包走快重传（[[滑动窗口]] / [[拥塞控制]]）→ 发 FIN 四次挥手、主动方进 TIME_WAIT 等 2MSL（[[TIME_WAIT与连接回收]]）。

## 何时用与何时不用

- **用：** 作为 TCP 全景入口，先判断问题属于连接 / 窗口 / 拥塞 / 状态回收 / 分帧 / 保活哪一块，再跳到对应专条。
- **不用：** 需要某机制的字段级、抓包级细节时——进对应专条，本页只索引。

## 与相关概念的区别

vs [[用户数据报协议]]：那篇讲无连接、有边界、不可靠的 UDP，本文机制都服务于 TCP 的可靠字节流；vs [[QUIC]]：QUIC 在 UDP 上重建握手 / 多路复用 / 拥塞控制，消除了 TCP 层队头阻塞。

## 常见误区

- 把本页当成握手 / 拥塞 / 窗口等机制的完整推导来复习。
- 认为滑动窗口和拥塞控制是一回事（一个防接收方溢出、一个防网络过载）。

## 面试速答

> 🎯 TCP 枢纽：面向连接的可靠字节流——三次握手 / 四次挥手管连接、滑动窗口(rwnd)控流量、拥塞控制(cwnd)护网络、发送窗 = min(rwnd, cwnd)，主动关闭方进 TIME_WAIT 等 2MSL，字节流无边界须应用层分帧；各机制详见对应专条。
