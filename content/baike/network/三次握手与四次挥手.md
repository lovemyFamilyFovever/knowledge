# 三次握手与四次挥手


> 📌 **导航**：本文是 **三次握手与四次挥手** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 三次握手与四次挥手是 TCP 建立与释放连接的机制——建立连接时双方通过三次报文交换同步初始序列号（三次握手），释放连接时因 TCP 是全双工、需各自关闭一个方向，共经历四次报文（四次挥手）。

**通俗类比：** 三次握手像打电话前确认双方都能听能说："喂，听得到吗?""听得到，你能听到我吗?""能"——都确认后才开始通话；四次挥手像挂电话，一方说"我说完了"、对方回"知道了、我还没说完"，等对方也说完再确认"那挂了"。

> 多义说明：属 TCP 连接管理；握手 = 建立（3 次），挥手 = 释放（4 次）。本文分别说明。

## 为什么需要它

TCP 是面向连接、可靠有序传输，通信前必须同步双方初始序列号、确认彼此收发动作可用；又因全双工、两方向数据流独立，关闭时必须各方向单独确认，避免半路丢数据。握手与挥手就是这套建立 / 释放的可靠流程。

## 核心机制

- **三次握手：** ① 客户端发 SYN(seq = x)；② 服务器回 SYN + ACK(seq = y, ack = x+1)；③ 客户端回 ACK(ack = y+1)，双方进入 ESTABLISHED、完成初始序列号 ISN 同步。用三次（而非两次）是为确认双向收发能力、防止已失效的历史连接请求突然到达而错误建连。
- **四次挥手：** ① 主动方发 FIN；② 被动方回 ACK（此时被动方可能仍有数据要发，故 ACK 与 FIN 分开 → 四次）；③ 被动方发 FIN；④ 主动方回 ACK 并进入 TIME_WAIT、等 2MSL 后关闭。
- **TIME_WAIT（2MSL）：** 出现在主动关闭方，确保最后一个 ACK 能到达对端、并让本连接的旧报文在网络中自然消散。
- **半关闭：** 一方发 FIN 后仍可接收对端数据，体现全双工可单方向关闭。

## 具体示例

高并发短连接服务的服务器大量处于 TIME_WAIT：每次主动关闭都占一个四元组 2MSL，可能耗尽端口——用长连接 / 连接池复用 TCP、或调 `tcp_tw_reuse` 缓解。SYN Flood 则打握手第一步的半连接队列，用 SYN Cookie 缓解。

## 何时用与何时不用

- **用：** 所有 TCP 通信的连接建立与释放、Web / API 连接管理、长连接 / 连接池与 TIME_WAIT 调优。
- **不用（别误读）：** 不必每次"新建连接"，复用连接（keep-alive / 连接池）能摊薄握手 RTT；短连接暴增要警惕 TIME_WAIT 耗尽。

## 优劣与代价

✅ 可靠同步序列号、双方确认收发能力、支持有序释放与半关闭。
⚠️ 握手带来 1-RTT 建连延迟；TIME_WAIT 占用资源（大量短连接时可能端口耗尽）；SYN Flood 利用握手（用 SYN Cookie 缓解）。

## 与相关概念的区别

vs [[TCP深入]]：连接管理只是 TCP 的一部分，深入篇还含滑动窗口 / 拥塞控制；握手同步的是双向初始序列号，挥手因全双工才需四次；SYN Flood 针对三次握手的半连接队列、与挥手无关。

## 常见误区

- TCP 建立连接两次握手就够了。
- TIME_WAIT 出现在被动关闭的一方。
- SYN Flood 攻击利用的是四次挥手。

## 面试速答

> 🎯 三次握手 = SYN → SYN+ACK → ACK，同步双向 ISN、确认收发能力、防历史连接；四次挥手 = FIN → ACK → FIN → ACK，因 TCP 全双工需各关一方向，主动关闭方进入 TIME_WAIT 等 2MSL；SYN Flood 打的是握手队列。
