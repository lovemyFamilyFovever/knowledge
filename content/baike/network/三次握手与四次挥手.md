# 三次握手与四次挥手


> 📌 **导航**：本文是 **三次握手与四次挥手** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 三次握手与四次挥手是 TCP 建立与释放连接的机制——建立连接时双方通过三次报文交换同步初始序列号(三次握手);释放连接时因 TCP 是全双工、需各自关闭一个方向,共经历四次报文(四次挥手)。

**通俗类比：** 三次握手像打电话前确认双方都能听能说:"喂,听得到吗?""听得到,你能听到我吗?""能"——双方都确认收发能力后才开始通话;四次挥手像挂电话,一方说"我说完了",对方回"知道了,我还没说完",等对方也说完再确认"那挂了"。

> 多义说明:属 TCP 连接管理;握手 = 建立(3 次),挥手 = 释放(4 次)。本文分别说明。

## 原理与机制

- **三次握手:**
  1. 客户端发送 SYN(seq = x);
  2. 服务器回复 SYN + ACK(seq = y, ack = x + 1);
  3. 客户端回复 ACK(ack = y + 1)。双方进入 ESTABLISHED,完成初始序列号(ISN)同步。
- **为何是三次:** 确认双方收发能力、同步双向初始序列号,并防止已失效的历史连接请求突然到达而错误建连(两次不足以保证)。
- **四次挥手:**
  1. 主动方发送 FIN;
  2. 被动方回 ACK(此时被动方可能仍有数据要发,故 ACK 与 FIN 分开 → 四次);
  3. 被动方发送 FIN;
  4. 主动方回 ACK,并等待 2MSL(TIME_WAIT)后关闭。

## 关键组成

| 组成 | 说明 |
|------|------|
| SYN / ACK / FIN | 建连与断连的标志位 |
| 初始序列号(ISN) | 握手时同步 |
| TIME_WAIT 与 2MSL | 主动关闭方等待,确保末 ACK 到达并让旧报文消散 |
| 半关闭状态 | 一个方向已关、另一方向仍可发 |

## 应用场景

- 所有 TCP 通信的连接建立与释放
- Web / API 的连接管理
- 长连接、连接池与 TIME_WAIT 调优

## 优点与局限

- 优点:可靠同步序列号、双方确认收发能力、有序释放连接。
- 局限:握手带来 RTT 建连延迟;TIME_WAIT 占用资源(大量短连接时可能端口耗尽);SYN Flood 攻击利用握手(用 SYN Cookie 缓解)。

## 常见误区

- 握手是三次而非两次:两次无法防止历史连接、无法确认双向能力。
- 挥手是四次:因 TCP 全双工,被动方的 ACK 与 FIN 通常不能合并。
- TIME_WAIT 出现在**主动关闭方**,等待 2MSL 是为确保最后的 ACK 到达并让旧报文消散。
- SYN Flood 利用的是握手(半连接队列),不是挥手。
