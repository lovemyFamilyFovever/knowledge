# 网络安全协议

## 一句话定义（大白话）

网络安全协议是保护数据在传输过程中不被窃听、篡改、冒充的各种加密和认证技术，是互联网安全的"防护盾"。

---

## 通俗类比

网络安全协议像快递的安全措施——防拆封（加密）、防伪造（认证）、防替换（完整性校验）、有追踪（日志审计）。

## IPSec（传输模式/隧道模式）

### 一句话定义

IPSec是网络层的安全协议套件，为IP通信提供加密、认证和完整性保护，支持传输模式（保护数据）和隧道模式（保护整个IP包）。

### 通俗类比

- **传输模式**：给信件内容加密，信封（IP头）不变
- **隧道模式**：把整个信封装进一个新信封，完全隐藏原始地址

### 具体示例

```
传输模式（Transport Mode）：
┌──────────┬──────────┬─────────────────┐
│ 原IP头   │ IPSec头  │ 加密的原始数据   │
└──────────┴──────────┴─────────────────┘
用途：端到端加密（如两台服务器之间）

隧道模式（Tunnel Mode）：
┌──────────┬──────────┬──────────┬─────────────────┐
│ 新IP头   │ IPSec头  │ 原IP头   │ 加密的原始数据   │
└──────────┴──────────┴──────────┴─────────────────┘
用途：VPN网关之间（如总部到分支机构）

# IPSec组件
AH（认证头）：提供认证和完整性，不加密
ESP（封装安全载荷）：提供认证+加密+完整性
IKE（密钥交换）：协商密钥和安全参数

# Linux查看IPSec状态
ip xfrm state
ip xfrm policy
```

### 为什么需要它

IP层本身不提供安全保护，IPSec为所有IP流量提供透明的安全保障。

### 与相关术语的对比

| 特性 | IPSec | SSL/TLS |
|------|-------|---------|
| 层级 | 网络层 | 传输层 |
| 保护范围 | 所有IP流量 | 特定应用 |
| 配置复杂度 | 高 | 低 |
| 典型应用 | VPN | HTTPS |

## VPN（PPTP/L2TP/IPSec/OpenVPN/WireGuard）

### 一句话定义

VPN是虚拟专用网络，通过加密隧道在公共网络上建立私有安全通道，让你"身在外地，如同在家"。

### 通俗类比

VPN像一条加密隧道——你从隧道这头进去，那头出来时已经在公司内网了，外面的人看不到隧道里走的什么。

### 具体示例

```
VPN协议对比：

PPTP（点对点隧道协议）
- 端口：1723
- 加密：MPPE（较弱）
- 安全性：低（已不推荐）
- 速度：快

L2TP/IPSec
- 端口：500/4500
- 加密：IPSec（强）
- 安全性：高
- 速度：中等

OpenVPN
- 端口：1194（UDP/TCP）
- 加密：OpenSSL（可配置）
- 安全性：高
- 速度：中等

WireGuard
- 端口：51820（UDP）
- 加密：ChaCha20, Curve25519
- 安全性：高
- 速度：快（内核级实现）

# WireGuard配置示例（客户端）
[Interface]
PrivateKey = <客户端私钥>
Address = 10.0.0.2/32
DNS = 8.8.8.8

[Peer]
PublicKey = <服务器公钥>
Endpoint = 203.0.113.1:51820
AllowedIPs = 0.0.0.0/0          # 全局代理
# AllowedIPs = 192.168.1.0/24   # 仅访问内网

# OpenVPN连接
openvpn --config client.ovpn
```

### 为什么需要它

公共网络不安全，VPN保护远程办公、公共Wi-Fi下的数据安全。

### 各VPN协议对比

| 协议 | 加密强度 | 速度 | 易用性 | 推荐场景 |
|------|---------|------|--------|---------|
| PPTP | 低 | 快 | 高 | 不推荐 |
| L2TP/IPSec | 高 | 中 | 中 | 兼容性需求 |
| OpenVPN | 高 | 中 | 中 | 通用 |
| WireGuard | 高 | 快 | 高 | 现代首选 |
| IPSec | 高 | 中 | 低 | 企业级 |

## WAF（Web应用防火墙）

### 一句话定义

WAF是专门保护Web应用的安全设备/软件，过滤恶意HTTP请求，防止SQL注入、XSS等攻击。

### 通俗类比

WAF像小区门口的保安——检查每个进楼的人（HTTP请求），可疑的（恶意攻击）拦在外面，正常的放行。

### 具体示例

```
WAF防护的常见攻击：

1. SQL注入
恶意请求: /user?id=1' OR '1'='1
WAF拦截: 检测到SQL关键词，阻断请求

2. XSS跨站脚本
恶意请求: /search?q=<script>alert(1)</script>
WAF拦截: 检测到script标签，阻断请求

3. 文件上传漏洞
恶意请求: 上传webshell.php
WAF拦截: 检测到危险文件类型，阻断请求

# WAF部署模式
透明模式: 串联在网络中，直接过滤
反向代理模式: WAF作为前端，转发合法请求
云WAF: 通过DNS解析将流量先经过云WAF

# 常见WAF产品
- ModSecurity（开源，Apache模块）
- AWS WAF（云服务）
- Cloudflare WAF（云服务）
- NAXSI（Nginx模块）

# ModSecurity规则示例
SecRule ARGS "@detectSQLi" \
  "id:1001,phase:1,deny,status:403,\
  msg:'SQL Injection Detected'"
```

### 为什么需要它

传统防火墙只在网络层/传输层过滤，WAF在应用层深度检查HTTP内容。

### 与相关术语的对比

| 设备 | 工作层级 | 防护对象 |
|------|---------|---------|
| 包过滤防火墙 | 网络层 | IP/端口 |
| WAF | 应用层 | HTTP请求内容 |
| IDS/IPS | 网络层+应用层 | 入侵检测/防御 |

## DDoS攻击类型与防御

### 一句话定义

DDoS是分布式拒绝服务攻击，大量僵尸设备同时向目标发送请求，耗尽其资源使其无法正常服务。

### 通俗类比

DDoS像10000人同时打电话给一家餐厅，把所有线路占满，真正的客户打不进来。

### 具体示例

```
DDoS攻击类型：

1. 流量型攻击（网络层）
   SYN Flood: 发送大量SYN包
   UDP Flood: 发送大量UDP包
   ICMP Flood: 发送大量ping包
   特点：耗尽带宽

2. 协议型攻击（传输层）
   SYN Flood: 利用TCP三次握手漏洞
   Ping of Death: 超大ICMP包
   特点：耗尽服务器连接资源

3. 应用层攻击（应用层）
   HTTP Flood: 大量HTTP请求
   Slowloris: 慢速连接占满连接池
   CC攻击: 针对动态页面大量请求
   特点：耗尽服务器CPU/内存

# 防御方案
1. 云防护: 阿里云DDoS防护、Cloudflare
2. 限速: iptables限制连接速率
   iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j DROP

3. SYN Cookie:
   sysctl -w net.ipv4.tcp_syncookies=1

4. 流量清洗: 在CDN/云服务处过滤恶意流量

5. CDN分散: 将流量分散到多个节点
```

### 为什么需要它

DDoS攻击成本低（租用僵尸网络）但破坏力大，是Web服务面临的最大威胁之一。

### 各类型DDoS对比

| 攻击类型 | 攻击层级 | 消耗资源 | 防御难度 |
|---------|---------|---------|---------|
| SYN Flood | 传输层 | 连接资源 | 中 |
| UDP Flood | 网络层 | 带宽 | 低 |
| HTTP Flood | 应用层 | CPU/内存 | 高 |
| Slowloris | 应用层 | 连接数 | 高 |

## 防火墙（包过滤/状态检测/应用层）

### 一句话定义

防火墙是网络安全的第一道防线，根据规则控制进出网络的流量，包过滤看地址，状态检测看连接，应用层看内容。

### 通俗类比

- **包过滤**：门卫看身份证（IP/端口），符合就放行
- **状态检测**：门卫记住谁先出门的，只有出去的人才能回来
- **应用层**：安检员打开包检查内容（HTTP请求内容）

### 具体示例

```
1. 包过滤防火墙（网络层）
规则示例：
# 允许HTTP和HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
# 允许SSH（仅特定IP）
iptables -A INPUT -p tcp --dport 22 -s 10.0.0.0/8 -j ACCEPT
# 拒绝所有其他入站
iptables -A INPUT -j DROP

2. 状态检测防火墙（传输层）
# 只允许已建立连接的回包和新连接
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -m state --state NEW -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -j DROP

3. 应用层防火墙（WAF）
# 检查HTTP内容
# 阻止SQL注入
# 阻止XSS攻击
# 限制请求频率
```

### 为什么需要它

网络安全需要多层次防护——网络层阻止非授权访问，传输层检测异常连接，应用层过滤恶意内容。

### 各类型防火墙对比

| 类型 | 工作层级 | 检查内容 | 性能 | 功能 |
|------|---------|---------|------|------|
| 包过滤 | 网络层 | IP/端口 | 高 | 基础访问控制 |
| 状态检测 | 传输层 | 连接状态 | 中 | 连接跟踪 |
| 应用层 | 应用层 | 协议内容 | 低 | 深度检测 |
| 下一代(NGFW) | 多层 | 综合 | 中 | 全面防护 |

## 正向代理与反向代理

### 一句话定义

正向代理帮客户端访问服务器（隐藏客户端），反向代理帮服务器接收请求（隐藏服务器）。

### 通俗类比

- **正向代理**：你让朋友帮你去商店买东西（商店不知道是谁买的）
- **反向代理**：商店前台帮你接待客户（你不知道哪个店员服务）

### 具体示例

```
正向代理（Forward Proxy）：
客户端 → 正向代理 → 服务器
- 客户端知道代理，服务器不知道真实客户端
- 用途：翻墙、匿名访问、缓存加速

# Nginx正向代理配置
server {
    listen 8080;
    location / {
        proxy_pass $scheme://$host$request_uri;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

反向代理（Reverse Proxy）：
客户端 → 反向代理 → 后端服务器群
- 服务器知道代理，客户端不知道真实服务器
- 用途：负载均衡、SSL终结、安全隔离

# Nginx反向代理配置
upstream backend {
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
    server 192.168.1.103:8080;
}

server {
    listen 443 ssl;
    ssl_certificate /etc/nginx/cert.pem;
    ssl_certificate_key /etc/nginx/key.pem;

    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 为什么需要它

正向代理保护客户端隐私，反向代理保护服务器安全并实现负载均衡。

### 与相关术语的对比

| 特性 | 正向代理 | 反向代理 |
|------|---------|---------|
| 位置 | 客户端侧 | 服务器侧 |
| 谁配置 | 客户端 | 服务器 |
| 隐藏对象 | 隐藏客户端 | 隐藏服务器 |
| 用途 | 匿名、翻墙 | 负载均衡、安全 |
| 示例 | VPN、Squid | Nginx、HAProxy |

## NAT（SNAT/DNAT）

### 一句话定义

NAT转换IP地址，SNAT改源地址（内网→外网），DNAT改目标地址（外网→内网端口转发）。

### 通俗类比

- **SNAT**：多人共用一个公司号码打电话（前台把你的分机号改成公司总机号）
- **DNAT**：外面打公司总机，前台转接给你（把总机号改成你的分机号）

### 具体示例

```
SNAT（源地址转换）：
内网设备                      公网
192.168.1.100 ─┐
192.168.1.101 ─┼──→ NAT ──→ 203.0.113.5
192.168.1.102 ─┘

# iptables配置SNAT
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j MASQUERADE

# 或指定公网IP
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 203.0.113.5

DNAT（目标地址转换/端口转发）：
外网用户访问 203.0.113.5:8080 → 转发到 192.168.1.100:80

# iptables配置DNAT（端口转发）
iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.100:80
iptables -A FORWARD -p tcp -d 192.168.1.100 --dport 80 -j ACCEPT

# Windows端口转发（netsh）
netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 connectport=80 connectaddress=192.168.1.100

# 查看端口转发规则
netsh interface portproxy show v4tov4
```

### 为什么需要它

IPv4地址不够用，SNAT让内网共用公网IP，DNAT让外网能访问内网服务。

### SNAT vs DNAT对比

| 特性 | SNAT | DNAT |
|------|------|------|
| 改变的地址 | 源IP | 目标IP |
| 方向 | 内→外 | 外→内 |
| 用途 | 上网共享 | 端口转发 |
| 规则链 | POSTROUTING | PREROUTING |

## 端口转发

### 一句话定义

端口转发是将对一个端口的访问重定向到另一个端口或另一台机器，是DNAT的具体应用。

### 通俗类比

端口转发像电话转接——你打公司前台（公网IP:8080），前台帮你转接到分机（内网IP:80）。

### 具体示例

```bash
# Linux端口转发（iptables）
# 将8080端口转发到内网80端口
iptables -t nat -A PREROUTING -p tcp --dport 8080 -j REDIRECT --to-port 80

# Linux端口转发（socat）
socat TCP-LISTEN:8080,fork TCP:192.168.1.100:80

# Windows端口转发
netsh interface portproxy add v4tov4 listenport=3389 listenaddress=0.0.0.0 connectport=3389 connectaddress=192.168.1.200

# Nginx端口转发（反向代理）
server {
    listen 8080;
    location / {
        proxy_pass http://192.168.1.100:80;
    }
}

# SSH端口转发（动态SOCKS代理）
ssh -D 1080 user@203.0.113.1

# 验证端口转发
telnet 203.0.113.5 8080
curl http://203.0.113.5:8080
```

### 为什么需要它

内网服务需要对外提供访问，但不想暴露整个内网。端口转发是"最小暴露原则"的实践。

### 与相关术语的对比

| 概念 | 说明 |
|------|------|
| 端口转发 | 单端口→单端口重定向 |
| 负载均衡 | 多端口/多服务器分发 |
| NAT | 地址转换（含端口转发） |
| 反向代理 | 应用层的端口转发 |

## SSL/TLS证书管理

### 一句话定义

SSL/TLS证书是数字身份证，验证服务器身份并加密通信，由CA（证书颁发机构）签发。

### 通俗类比

SSL证书像身份证——证明"我确实是这家银行（域名）"，同时给对话加密（只有你和银行能听懂）。

### 具体示例

```
# 证书类型
DV（域名验证）: 只验证域名所有权（免费，如Let's Encrypt）
OV（组织验证）: 验证组织身份（几百元/年）
EV（扩展验证）: 最严格验证（几千元/年，地址栏显示公司名）

# 生成自签名证书（测试用）
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout server.key -out server.crt

# 生成CSR（证书签名请求）
openssl req -new -newkey rsa:2048 -nodes -keyout server.key -out server.csr

# Let's Encrypt免费证书
# 使用certbot自动获取和续期
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d example.com

# 证书自动续期
sudo crontab -e
0 0 1 * * certbot renew --quiet

# Nginx配置SSL
server {
    listen 443 ssl http2;
    server_name example.com;
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
}

# 查看证书信息
openssl x509 -in server.crt -text -noout
openssl s_client -connect example.com:443 -showcerts
```

### 为什么需要它

没有SSL/TLS，HTTP通信是明文的，密码、信用卡号等敏感信息会被窃听和篡改。

### 证书管理要点

| 要点 | 说明 |
|------|------|
| 自动续期 | Let's Encrypt证书90天有效 |
| 证书链 | 中间CA证书+根CA证书 |
| HSTS | 强制使用HTTPS |
| OCSP Stapling | 加速证书验证 |
| 证书固定 | 防止CA被攻破 |

## 蜜罐（Honeypot）

### 一句话定义

蜜罐是故意设置的诱饵系统，引诱攻击者攻击，从而收集攻击信息、拖延攻击时间。

### 通俗类比

蜜罐像假金库——小偷以为是真金库进来偷，结果被监控录像拍下，真金库反而安全。

### 具体示例

```
蜜罐分类：

1. 低交互蜜罐
- 只模拟基础服务（端口监听）
- 收集有限信息
- 部署简单
- 示例：Honeyd, Kippo

2. 高交互蜜罐
- 完整的真实系统
- 可深入分析攻击行为
- 风险较高
- 示例：完整的Linux虚拟机

3. 陷阱系统（Honeytoken）
- 假数据库、假文件
- 触发即告警
- 示例：假信用卡号、假API密钥

# 部署SSH蜜罐示例（Cowrie）
# 安装
pip install cowrie

# 配置监听端口
[ssh]
enabled = true
listen_endpoints = tcp:2222:interface=0.0.0.0

# 查看攻击日志
tail -f var/log/cowrie/cowrie.json

# 看到的攻击行为
- 暴力破解尝试
- 恶意命令执行
- 文件上传尝试
- 漏洞利用尝试

# 蜜罐的价值
1. 延迟攻击：让攻击者浪费时间在假系统上
2. 收集情报：了解攻击者手法和工具
3. 早期预警：发现内网横向移动
4. 取证分析：攻击路径和时间线
```

### 为什么需要它

传统防御是"被动防御"，蜜罐是"主动防御"——引诱攻击者暴露自己。

### 与相关术语的对比

| 概念 | 说明 |
|------|------|
| 蜜罐 | 诱饵系统 |
| 蜜网 | 多个蜜罐组成的网络 |
| 蜜标(Honeytoken) | 假数据（假账号、假文件、假密钥） |
| 沙箱 | 隔离运行可疑程序 |

## 安全架构示例

```
                    ┌─────────────┐
                    │   互联网     │
                    └──────┬──────┘
                           │
                    ┌──────┴──────┐
                    │    WAF      │ ← Web应用防火墙
                    └──────┬──────┘
                           │
                    ┌──────┴──────┐
                    │   防火墙     │ ← 包过滤/状态检测
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
       ┌──────┴──────┐ ┌──┴───┐ ┌─────┴─────┐
       │  反向代理    │ │ 蜜罐  │ │  VPN网关   │
       │  (Nginx)    │ │      │ │ (WireGuard)│
       └──────┬──────┘ └──────┘ └─────┬─────┘
              │                        │
       ┌──────┴──────┐         ┌──────┴──────┐
       │  Web服务器   │         │  内网服务器   │
       │  (应用层)   │         │  (数据库等)  │
       └─────────────┘         └─────────────┘

安全防护层次：
1. 网络层：防火墙、NAT、VPN
2. 传输层：SSL/TLS加密
3. 应用层：WAF、IDS/IPS
4. 数据层：加密存储、访问控制
5. 监控层：蜜罐、日志审计
```
