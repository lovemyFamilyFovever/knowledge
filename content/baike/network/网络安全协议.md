# 网络安全协议


> 📌 **导航**：本文是 **网络安全协议** 枢纽页，属于 network 术语集。各防护机制已归口到族词条或已有专条，本页只做索引与纵深关系。

## 定义

**一句话定义：** 网络安全协议与机制在网络层到应用层为数据提供加密、认证、完整性、访问控制与入侵防护；本页是其枢纽索引——把 VPN/IPSec、防火墙/WAF/IDS-IPS、正反向代理、DDoS 防护等家族指向族词条，TLS 与 NAT 指向已有专条，并串起纵深防御的层次。

**通俗类比：** 像快递的多重安保——防拆封（加密）、防伪造（认证）、防替换（完整性）、有监控（IDS / 蜜罐）、有门岗（防火墙）；本页是把每道防线指向详情的目录。

## 为什么需要它

安全要靠纵深防御，单点挡不住所有威胁；且各机制（IPSec / 防火墙 / WAF / DDoS / 代理 / TLS / NAT）已多有专条。需要一张地图说清"某类攻击 / 防护属于哪一层、去哪深入"，本页承担这个角色。

## 核心机制

- **隧道与网络层加密：** IPSec 传输 / 隧道模式、WireGuard / OpenVPN 等见 [[VPN与隧道加密]]。
- **访问控制与入侵检测：** 包过滤 / 状态检测 / WAF、IDS vs IPS 见 [[防火墙与WAF]]。
- **代理：** 正向隐藏客户端、反向隐藏后端并做负载均衡 / SSL 终结，见 [[代理与正向反向代理]]。
- **可用性防护：** 流量 / 协议 / 应用层 DDoS 与清洗、SYN Cookie 见 [[DDoS攻击与防护]]。
- **加密与寻址：** TLS 握手与证书管理见 [[HTTPS 与 TLS]]；SNAT / DNAT 与端口转发见 [[网络地址转换]]。
- **主动防御：** 蜜罐 / 蜜网 / 蜜标（Honeytoken）以诱饵换取攻击情报与早期预警，属主动防御，按需查阅。

## 具体示例

对外 Web 的纵深：CDN / DDoS 清洗 → 云 WAF → 防火墙（默认拒绝 + 状态检测）→ 反向代理（SSL 终结 + LB）→ 应用（参数化查询）→ 内网 IDS 监控、旁挂蜜罐预警——任一层失守仍有下一层兜底。

## 何时用与何时不用

- **用：** 按威胁选层——窃听用 TLS / IPSec、非授权用防火墙、Web 攻击用 WAF、流量洪峰用 DDoS 防护、远程组网用 VPN。
- **注意：** 安全是纵深不是单点；WAF / IPS 不能替代代码层输入校验与最小暴露原则。

## 优劣与代价

✅ 分层织网，把攻击挡在源站之外，兼顾保密、完整性、可用性与可审计。
⚠️ 每层都有误杀 / 绕过与维护成本；规则与证书需持续治理；整体配置复杂、易出错。

## 与相关概念的区别

vs [[网络基础]]：那讲连通与寻址、本讲其上的安全防护；vs [[应用层协议]]：SSH / HTTPS 等协议自身的安全部分，由 [[HTTPS 与 TLS]] / [[SSH与远程登录]] 与本文机制配合。

## 常见误区

- 上一套防火墙 / VPN 就"安全了"，不必再分层。
- 有了加密（VPN / TLS）就等价于做了访问控制和输入校验。
