# 网络诊断与性能

> 📌 **导航**：本文是 **网络诊断与性能** 词条，由 [[网络基础]] 拆分而来。

## 定义

**一句话定义：** 网络诊断与性能回答"通不通、走哪条路、跑多快"——Ping 用 ICMP 测连通与 RTT、Traceroute / MTR 逐跳追路径、带宽（理论容量）与吞吐量（实际速率）加延迟 / 抖动衡量性能。

**通俗类比：** Ping 像打电话看接不接得通，Traceroute 像给包裹装 GPS 记录每一站；带宽是公路设计车道数、吞吐量是高峰期真正通过了多少车。

## 为什么需要它

排障要按"连通 → 路径 → 性能"逐层定位：先确认能否到达，再看断在哪一跳，最后量化是否带宽 / 延迟不达标。Ping、Traceroute、iperf 三组工具正好对应这三问。

## 核心机制

- **Ping：** 发 ICMP Echo、看回包、往返时间与 TTL；`ping -c/-n` 控制次数。
- **Traceroute / tracert / MTR：** 用递增 TTL 触发 ICMP 超时来逐跳显路，MTR 持续观测每跳丢包与延迟。
- **性能度量：** 带宽（bps 理论最大）、吞吐量（实测）、延迟 RTT、抖动（延迟波动）；iperf3 测吞吐、speedtest 测公网。

## 具体示例

"网页打不开"：`ping 8.8.8.8` 看 IP 层是否通、`ping 域名` 看 DNS、`traceroute 站点` 定位哪一跳丢包、`iperf3` 量链路吞吐——从连通到路径到性能逐层收敛。

## 何时用与何时不用

- **用：** 故障排查首查 Ping、定位中间跳用 Traceroute / MTR、容量评估用 iperf3。
- **注意：** 不少设备禁 / 限速 ICMP，ping 不通不代表业务不通；traceroute 中间跳超时可能只是限速、未必真故障。

## 优劣与代价

✅ 用标准工具把"通不通 / 走哪 / 多快"量化，是网络排障与调优的基本面。
⚠️ ICMP 被禁 / 限速会误导；吞吐量受拥塞控制与缓冲膨胀影响，单次测速不等于真实体验。

## 与相关概念的区别

vs [[IP 协议]]：ICMP 封装在 IP 之上、是这些工具用的报文；vs [[路由协议]]：Traceroute 只"观测"路径、不改选路。本文是诊断与度量的工具集，而非协议本身。

## 常见误区

- ping 不通就说明对方主机宕了、业务不可用。
- 带宽就等于实际下载速度。
- traceroute 某一跳超时一定意味着网络故障。
