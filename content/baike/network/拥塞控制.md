# 拥塞控制


> 📌 **导航**：本文是 **拥塞控制** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 拥塞控制(Congestion Control)是网络(尤其 TCP)为防止过多数据注入网络、导致路由器过载、丢包甚至"拥塞崩溃",而动态调节发送速率的一套机制,目标是让网络吞吐最大化同时避免雪崩。

**通俗类比：** 像高速公路的车流调控——车太多会堵死,于是用匝道信号灯(限速)控制上路车辆;一旦某路段拥堵(丢包),就减少放行,等疏通后再逐步增加,避免整条路瘫痪。

> 多义说明:拥塞控制(全局,防网络过载)≠ 流量控制(点对点,防接收方缓冲溢出,靠滑动窗口);二者常配合使用。本文讲拥塞控制。

## 原理与机制

- **拥塞信号:** 传统上以丢包(和/或 RTT 时延上升)作为网络拥塞的信号。
- **TCP Reno 经典算法:** 慢启动(指数增大窗口)→ 拥塞避免(线性增大)→ 快重传 + 快恢复(收到 3 个重复 ACK 时窗口减半而非从头开始)。
- **拥塞窗口(cwnd):** 由发送方维护,与接收窗口(rwnd)取较小值决定实际可发送量。
- **现代算法:** CUBIC(Linux 默认,窗口按三次函数增长)、BBR(基于带宽与时延建模,而非仅依赖丢包)。

## 关键组成

| 组成 | 作用 |
|------|------|
| 拥塞窗口 cwnd | 发送方的拥塞预算 |
| 慢启动阈值 ssthresh | 慢启动与拥塞避免的分界 |
| 慢启动 | 初始指数增窗探测带宽 |
| 拥塞避免 | 接近容量时线性增窗 |
| 快重传 / 快恢复 | 丢包后温和退避 |

## 应用场景

- TCP 数据传输、文件下载与流媒体
- 跨广域网传输、数据中心网络(DCTCP)
- 实时通信(结合 UDP 的算法,如 GCC、QUIC 的拥塞控制)

## 优点与局限

- 优点:防止拥塞崩溃、公平共享带宽、提升整体吞吐与稳定性。
- 局限:基于丢包的算法在高带宽高时延链路上效率低;缓冲膨胀(bufferbloat)问题;多流公平性与算法调优复杂。

## 常见误区

- 拥塞控制 ≠ 流量控制:前者防网络过载,后者防接收方溢出。
- 丢包并不总意味着拥塞(也可能是链路误码,无线网络尤其如此)。
- BBR 不以丢包为主要信号,而是基于带宽与时延的模型。
