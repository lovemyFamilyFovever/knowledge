# 滑动窗口


> 📌 **导航**：本文是 **滑动窗口** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 滑动窗口(Sliding Window)是 TCP 等可靠传输协议实现流量控制与高效传输的机制:发送方在未收到确认前可连续发送"窗口大小"内的多个字节/报文,窗口边界随发送与确认向前滑动,从而无需逐包停等、充分利用信道。

**通俗类比：** 像流水线上允许同时"在途"的工件数量——你不必做完一个、等对方签收再做下一个,而是一口气发出窗口内的多个;对方确认后窗口向前挪,既高效又不超过对方的处理能力。

> 多义说明:滑动窗口既用于**流量控制**(接收窗口 rwnd,防压垮接收方),也与**拥塞控制**(拥塞窗口 cwnd)配合;它还是算法题里"滑动窗口/双指针"技巧的同名词(不同语境)。本文讨论网络传输中的滑动窗口。

## 原理与机制

- **窗口大小:** 发送方维护发送窗口,大小 = min(接收窗口 rwnd, 拥塞窗口 cwnd)。
- **滑动:** 数据"已发送未确认"位于窗口内;收到 ACK 后窗口左边界前移;接收方通过通告 rwnd(剩余缓冲)控制发送速率。
- **丢包处理:** 累计确认 + 选择性确认(SACK)高效处理重传。
- **意义:** 相比停止等待(窗口=1),滑动窗口实现流水线化,显著提升吞吐(尤其在高带宽时延积链路上)。

## 关键组成

| 组成 | 作用 |
|------|------|
| 发送 / 接收窗口 | 允许在途的数据范围 |
| rwnd(接收窗口) | 流量控制,匹配接收能力 |
| cwnd(拥塞窗口) | 拥塞控制,匹配网络能力 |
| ACK / SACK | 确认与选择性重传 |

## 应用场景

- TCP 可靠传输与流量控制
- 高吞吐网络传输
- QUIC 等现代传输协议

## 优点与局限

- 优点:无需停等、提升信道利用率与吞吐,同时兼顾流量控制。
- 局限:窗口过大会压垮接收方或加剧拥塞;需与拥塞控制配合;丢包恢复复杂;缓冲区管理有开销。

## 常见误区

- 滑动窗口(流量控制,防接收方溢出)≠ 拥塞控制(防网络过载),二者共同决定实际发送窗口。
- 窗口不是固定大小,而是随 ACK 与 rwnd 动态滑动。
- "滑动窗口"在算法题中是另一种含义(双指针技巧),勿混淆。
