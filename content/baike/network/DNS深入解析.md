# DNS深入解析


> 📌 **导航**：本文是 **DNS深入解析** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** DNS（Domain Name System，域名系统）是把人类易记的域名（如 www.example.com）解析为机器可路由的 IP 地址的分布式分层命名系统，是互联网的基础设施之一。

**通俗类比：** DNS 就像手机通讯录 / 电话簿——你只需记住名字（域名），系统自动帮你查到对应号码（IP 地址）。

> 多义说明：DNS 查询默认走 UDP 53（报文短小），但区域传输与超大响应会用 TCP 53；本文侧重解析流程、记录类型与安全。

## 为什么需要它

IP 是数字、难记难写，人更习惯用名字。DNS 提供全局的"名字 ↔ 地址"翻译，并用分层 + 缓存的分布式结构扛住互联网规模的查询量，是"输入网址就能访问"的前提。

## 核心机制

- **解析链路（先本地后迭代）：** 浏览器缓存 → 操作系统缓存 / hosts 文件 → 本地 DNS（递归解析器）；本地未命中则迭代问：根域 `.` → 返回 `.com` 的 TLD 服务器 → 返回 example.com 权威 NS → 权威返回 A/AAAA 记录，逐级按 TTL 缓存后回给客户端。
- **递归 vs 迭代：** 客户端只问本地 DNS 一次、由它查到底返回最终结果（递归）；本地 DNS 对根 / TLD / 权威则是每次拿"下一步该问谁"（迭代）。
- **记录类型：** A（→IPv4）、AAAA（→IPv6）、CNAME（别名指向另一域名）、MX（邮件服务器含优先级）、TXT（SPF / DKIM / DMARC）、NS（权威服务器）、SOA（区域参数）、PTR（反向解析 IP→域名）。
- **DNS 负载均衡：** 同一域名配多条 A 记录、按轮询 / 地理 / 权重返回不同 IP，是粗粒度全局负载均衡（GSLB）；更精细的就近调度见 [[内容分发网络]]、[[负载均衡]]。
- **安全：** DNS 劫持（篡改 / 重定向解析路径）与缓存投毒（向解析器缓存注入伪造记录）是主要威胁，靠 DNSSEC（记录数字签名验证）、DoH（DNS over HTTPS）、DoT（DNS over TLS）防护。

## 具体示例

`dig +trace www.example.com` 从根服务器开始，把 `.` → `.com` → example.com 权威每一跳都打出来，直观展示迭代解析全程；`dig @8.8.8.8 +short` 则指定 Google 公共 DNS、只返回最终 A 记录。

## 何时用与何时不用

- **用：** 域名访问、邮件路由（MX）、CDN 就近调度、服务发现（如 Kubernetes CoreDNS）、按解析切流的灰度 / 多活。
- **不用：** 需要"即时生效、强一致"的映射别放 DNS（受各级 TTL 缓存）；高频查询应在客户端 / 解析器侧加缓存。

## 优劣与代价

✅ 分层可扩展、缓存高效，把"记 IP"变成"记名字"，是互联网可用的前提。
⚠️ 首次多级解析有延迟；缓存使变更不即时（受 TTL 影响）；默认明文易被劫持 / 投毒，需 DNSSEC / DoH / DoT 加固。

## 与相关概念的区别

vs [[内容分发网络]]：CDN 常借 DNS（CNAME 到边缘节点）做就近调度，但 CDN 还含实际边缘缓存与回源；vs 服务发现：K8s CoreDNS 把 DNS 当服务发现接口，本质仍是"名字→地址"解析。

## 常见误区

- DNS 查询只用 UDP、绝不会用 TCP。
- 修改 DNS 记录后会立刻全球生效。
- DNS 劫持和缓存投毒是同一回事。

## 面试速答

> 🎯 DNS = 分布式分层的"域名→IP"系统：浏览器 / OS / 本地解析器逐级查缓存，未命中就 根→TLD→权威 迭代查询并按 TTL 缓存；记录有 A/AAAA/CNAME/MX/TXT/NS/SOA/PTR，安全靠 DNSSEC/DoH/DoT，查询走 UDP、区域传输走 TCP。
