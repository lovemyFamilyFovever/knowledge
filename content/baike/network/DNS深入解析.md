# DNS深入解析


> 📌 **导航**：本文是 **DNS深入解析** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** DNS（Domain Name System，域名系统）是把人类易记的域名（如 www.example.com）解析为机器可路由的 IP 地址的**分布式分层命名系统**，是互联网的基础设施之一。

**通俗类比：** DNS 就像手机通讯录/电话簿——你只需记住名字（域名），系统自动帮你查到对应号码（IP 地址）。

> 多义说明：DNS 查询默认走 **UDP 53**（报文短小），但**区域传输**与超大响应会用 **TCP 53**；本文侧重解析流程、记录类型与安全。

## 原理与机制

### 解析过程（递归 + 迭代）

```
用户输入 www.example.com
    ↓
1. 浏览器缓存 → 命中则直接返回
    ↓ (未命中)
2. 操作系统缓存 / hosts 文件(/etc/hosts)
    ↓ (未命中)
3. 本地 DNS 服务器(递归解析器，通常为运营商/公共 DNS)
    ↓ (未命中，开始迭代查询)
4. 根 DNS(.)     → 返回 .com 顶级域服务器地址
5. 顶级域(.com)  → 返回 example.com 的权威 DNS 地址
6. 权威 DNS      → 返回 www.example.com 的 A/AAAA 记录
    ↓
7. 逐级缓存(按 TTL)，返回给用户
```

- **递归查询**：客户端只问本地 DNS 一次，由它负责查到底并返回最终结果。
- **迭代查询**：本地 DNS 依次询问 根 → TLD → 权威，每步得到「下一步该问谁」。
- **缓存与 TTL**：各级按记录 TTL 缓存，减少重复查询；TTL 越短生效越快、查询越频繁。

## 关键组成：记录类型

| 类型 | 说明 | 示例 |
|------|------|------|
| A | 域名 → IPv4 | 93.184.216.34 |
| AAAA | 域名 → IPv6 | 2606:2800:220:1:: |
| CNAME | 别名指向另一域名 | www → cdn.example.com |
| MX | 邮件服务器（含优先级） | mail.example.com |
| TXT | 文本记录 | SPF / DKIM / DMARC 验证 |
| NS | 该域的权威 DNS 服务器 | ns1.example.com |
| SOA | 区域权威与默认参数 | 主 NS、序列号、刷新/TTL |
| PTR | 反向解析（IP → 域名） | 反垃圾邮件、日志溯源 |

### DNS 负载均衡

同一域名配置多条 A/AAAA 记录，解析时返回不同 IP（或按地理/权重），把用户分散到多台服务器：

```
www.example.com → A: 1.2.3.4
                → A: 5.6.7.8
                → A: 9.10.11.12
```

> 这是一种粗粒度的全局负载均衡（GSLB）手段；更精细的就近调度见 [[内容分发网络]] 与 [[负载均衡]]。

### DNS 安全

- **DNS 劫持**：篡改解析路径/结果，把用户引向假站点。
- **DNS 缓存投毒**：向解析器缓存注入伪造记录。
- **防护**：DNSSEC（对记录做数字签名验证）、DoH（DNS over HTTPS）、DoT（DNS over TLS）。

## 应用场景

- 域名访问、邮件路由（MX）、CDN 就近调度、微服务发现（如 Kubernetes 的 CoreDNS）、灰度/多活（按解析切流）。
- 常用排查命令：`nslookup`、`dig`（`dig +trace` 追踪完整链路、`dig @8.8.8.8` 指定服务器、`dig +short` 只看结果）。

## 优点与局限

- 优点：分层可扩展、缓存高效，把「记 IP」变成「记名字」，是互联网可用的前提。
- 局限：首次多级解析有延迟；缓存导致变更不即时（受 TTL 影响）；默认明文易被劫持/投毒，需 DNSSEC/DoH/DoT 加固。

## 常见误区

- 「DNS 只用 UDP」：查询多用 UDP 53，但**区域传输**和超过 512 字节（或经 EDNS0 协商更大）的响应会用 **TCP 53**。
- 「改了 DNS 立刻全球生效」：受各级缓存 TTL 影响，传播需要时间。
- 把 DNS 劫持与缓存投毒混为一谈：前者篡改/重定向解析路径，后者污染缓存中的记录。
