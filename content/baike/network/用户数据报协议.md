# 用户数据报协议


> 📌 **导航**：本文是 **用户数据报协议** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** 用户数据报协议（UDP，User Datagram Protocol）是 TCP/IP 传输层的一种无连接协议，它在 IP 之上仅提供端口复用与可选的差错校验，不做握手、不保证送达、不保证顺序、不做拥塞控制，以最小开销实现"尽力而为"的数据报传输。

**通俗类比：** 像寄明信片——写好地址就投出去，不确认对方是否收到、也不管先后顺序；好处是快、手续少，适合"丢一两封无所谓、但要快"的沟通（TCP 则像挂号信，要签收、要补寄）。

## 为什么需要它

并非所有场景都愿为可靠性付出握手与重传的延迟——实时音视频、在线游戏丢一两帧，远不如卡顿致命。UDP 把传输层的"保证"省到最少，换取极低延迟与开销，把可靠性按需交给应用层。

## 核心机制

- **无连接：** 发送前无需建立连接（无三次握手），每个数据报独立寻址发送。
- **尽力而为交付：** 不重传、不排序，丢包 / 乱序 / 重复由上层自行处理。
- **报文结构精简：** UDP 头部仅 8 字节，含源端口、目的端口、长度、校验和四个字段，远小于 TCP 的 20+ 字节。
- **保留消息边界：** 面向数据报，应用层写一次即一个 UDP 包（不像 TCP 是字节流）。
- 校验和可选（IPv4），用于检测数据损坏。

| 对比项 | UDP | TCP |
|--------|-----|-----|
| 连接 | 无连接 | 面向连接（三次握手） |
| 可靠性 | 不保证送达 / 顺序 | 可靠、有序、重传 |
| 头部开销 | 8 字节 | 20 字节起 |
| 拥塞 / 流量控制 | 无 | 有 |
| 传输语义 | 数据报（保留边界） | 字节流 |

## 具体示例

DNS 查询用 UDP：一次请求一次响应、报文小、追求快，个别丢包上层重试即可，省掉 TCP 三次握手的额外往返；VoIP / 视频会议同理，宁可丢帧也不让延迟累积。

## 何时用与何时不用

- **用：** 实时音视频 / VoIP / 视频会议、在线游戏、DNS / DHCP / NTP / SNMP、QUIC（在 UDP 之上自建可靠性）。
- **不用：** 要求数据完整、有序、不能丢的场景（文件传输、交易、普通网页）应选 TCP。

## 优劣与代价

✅ 开销小、延迟低、无连接建立 / 拆除成本、支持一对多（广播 / 多播）、头部简单。
⚠️ 不保证可靠与有序；无拥塞控制、滥用可能加剧网络拥塞；可靠性需应用层自行实现。

## 与相关概念的区别

vs [[TCP深入]]：TCP 面向连接、可靠有序、有流量与拥塞控制、字节流；UDP 无连接、尽力而为、数据报；vs [[QUIC]]：QUIC 不是 TCP 改名，而是在 UDP 之上用用户态重建可靠传输与多路复用（避开 TCP 队头阻塞）。

## 常见误区

- UDP 不可靠所以没什么用。
- UDP 完全没有差错校验。
- QUIC 就是 TCP 改了个名字。

## 面试速答

> 🎯 UDP = 传输层无连接、尽力而为的数据报协议：头部仅 8 字节（源/目的端口/长度/校验和），不握手、不重传、不排序、无拥塞控制，保留消息边界；胜在低开销低延迟，适合 DNS/音视频/游戏，可靠性交应用层（QUIC 即在 UDP 上自建）。
