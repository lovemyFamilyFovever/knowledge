# 用户数据报协议

## 定义

**一句话定义：** 用户数据报协议(UDP,User Datagram Protocol)是 TCP/IP 传输层的一种**无连接**协议,它在 IP 之上仅提供端口复用与可选的差错校验,不做握手、不保证送达、不保证顺序、不做拥塞控制,以最小开销实现"尽力而为"的数据报传输。

**通俗类比：** 像寄明信片——写好地址就投出去,不确认对方是否收到、也不管先后顺序;好处是快、手续少,适合"丢一两封无所谓、但要快"的沟通(对比 TCP 像挂号信,要签收、要补寄)。

## 原理与机制

- **无连接:** 发送前无需建立连接(无三次握手),每个数据报独立寻址发送。
- **尽力而为交付:** 不重传、不排序;丢包、乱序、重复由上层自行处理。
- **报文结构精简:** UDP 头部仅 **8 字节**,含 4 个字段:源端口、目的端口、长度(Length)、校验和(Checksum);相比 TCP 20+ 字节头部开销更小。
- **保留消息边界:** 面向数据报,应用层写一次即一个 UDP 包(不像 TCP 是字节流)。
- 校验和可选(IPv4),用于检测数据损坏。

| 对比项 | UDP | TCP |
|--------|-----|-----|
| 连接 | 无连接 | 面向连接(三次握手) |
| 可靠性 | 不保证送达/顺序 | 可靠、有序、重传 |
| 头部开销 | 8 字节 | 20 字节起 |
| 拥塞/流量控制 | 无 | 有 |
| 传输语义 | 数据报(保留边界) | 字节流 |

## 应用场景

- 实时音视频、VoIP、视频会议(容忍丢包、忌延迟)
- 在线游戏、实时协作(状态频繁刷新)
- DNS 查询、DHCP、SNMP、NTP
- QUIC(HTTP/3)在 UDP 之上自建可靠性

## 优点与局限

- 优点:开销小、延迟低、无连接建立/拆除成本、支持一对多(广播/多播)、头部简单。
- 局限:不保证可靠与有序;无拥塞控制,滥用可能加剧网络拥塞;可靠性需应用层自行实现(如自定义重传/序号)。

## 常见误区

- 认为"UDP 不可靠所以没用":实时场景下低延迟比可靠更重要,UDP 恰是首选。
- 把 UDP 当作"没有校验":UDP 有校验和,只是不做重传与排序。
- 以为 QUIC 就是 TCP 改名:QUIC 是在 UDP 上重新实现可靠传输与多路复用的新协议。
