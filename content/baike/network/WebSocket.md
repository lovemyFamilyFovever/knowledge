# WebSocket


> 📌 **导航**：本文是 **WebSocket** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** WebSocket 是一种在单个 TCP 连接上进行全双工通信的应用层协议，允许服务器与客户端（如浏览器）建立持久连接后双向实时推送数据，突破了 HTTP"只能由客户端发起请求"的限制。

**通俗类比：** HTTP 像"你问我答"的对讲机——每次都得客户端先喊话、服务器才能应答；WebSocket 像打通的电话，一次接通后双方随时都能开口，服务器也能主动说话。

> 多义说明：WebSocket 既指协议（`ws://` / 加密的 `wss://`），也指浏览器提供的 WebSocket API；本文以协议与机制为主。

## 为什么需要它

HTTP 请求—响应单向、无状态，服务器要主动推消息只能靠轮询 / 长轮询，延迟高、头部开销大、连接频繁。很多实时场景（聊天、行情、协同）需要一条长期在线、双向低开销的通道，WebSocket 正是为此而生。

## 核心机制

- **握手：** 客户端发送带 `Upgrade: websocket` 与 `Sec-WebSocket-Key` 的 HTTP 请求，服务器返回 `101 Switching Protocols` 完成升级，此后同一条 TCP 连接改用 WebSocket 帧协议。
- **全双工通信：** 连接建立后，双方均可随时发送数据帧（frame），支持文本与二进制。
- **帧结构：** 含 FIN、opcode、掩码位、payload 长度等；客户端发往服务器的帧必须做掩码处理（防代理缓存投毒）。
- **保活与关闭：** 用 ping/pong 帧维持连接、探测存活，close 帧协商关闭。

## 具体示例

在线聊天：页面加载时建一次 WebSocket（HTTP 升级），之后用户发消息直接经该连接的双向通道送达服务器、服务器再推给其他成员，无需每次新建 HTTP 请求；空闲时用 ping/pong 探活、断线由前端重连。

## 何时用与何时不用

- **用：** 实时聊天 / 客服、协同编辑 / 白板、实时行情与比分、通知推送、多人游戏与直播弹幕等双向低延迟场景。
- **不用：** 只需"客户端拉一次数据"用普通 HTTP 即可；超大规模长连接水平扩展要配消息总线 / 网关，且需自行处理心跳与重连。

## 优劣与代价

✅ 全双工、低延迟、头部开销远小于反复 HTTP 请求、服务器可主动推送、复用单条连接。
⚠️ 有状态长连接占用服务器资源；需自行处理断线重连与心跳；部分代理 / 防火墙支持不佳；大规模水平扩展要额外架构配合。

## 与相关概念的区别

vs HTTP 轮询 / 长轮询：后者本质仍是客户端反复发起的 HTTP 请求、服务器不能真正主动推，WebSocket 握手借用 HTTP 但升级后传的是 WebSocket 帧、真正全双工；vs SSE：SSE 只单向（服务器 → 客户端）推送，双向交互更适合 WebSocket。

## 常见误区

- WebSocket 就是 HTTP 长轮询的高级说法。
- 握手成功后传输的仍然是 HTTP 报文。
- 用了 WebSocket 就一定绝对实时。

## 面试速答

> 🎯 WebSocket = 在一条 TCP 上经 HTTP Upgrade（101）升级后的全双工应用层协议，用帧（opcode text/binary/ping/pong/close、客户端帧掩码）双向实时通信、突破 HTTP 只能客户端发起的限制；区别于长轮询，需自行处理心跳重连。
