# WebSocket

## 定义

**一句话定义：** WebSocket 是一种在单个 TCP 连接上进行**全双工**通信的应用层协议,允许服务器与客户端(如浏览器)建立持久连接后双向实时推送数据,突破了 HTTP "只能由客户端发起请求"的限制。

**通俗类比：** HTTP 像"你问我答"的对讲机——每次都得客户端先喊话,服务器才能应答;WebSocket 像打通的电话,一次接通后双方随时都能开口,服务器也能主动说话。

> 多义说明:WebSocket 既指**协议**(`ws://` / 加密的 `wss://`),也指浏览器提供的 WebSocket **API**;本文以协议与机制为主。

## 原理与机制

- **握手:** 客户端发送带 `Upgrade: websocket` 与 `Sec-WebSocket-Key` 的 HTTP 请求;服务器返回 `101 Switching Protocols` 完成升级,此后同一条 TCP 连接改用 WebSocket 帧协议。
- **全双工通信:** 连接建立后,双方均可随时发送数据帧(frame),支持文本与二进制。
- **帧结构:** 含 FIN、opcode、掩码位、payload 长度等;客户端发往服务器的帧必须做掩码处理。
- **保活与关闭:** 用 ping/pong 帧维持连接、探测存活;close 帧协商关闭。

## 关键组成

| 组成 | 说明 |
|------|------|
| 握手(Upgrade) | 由 HTTP 升级为 WebSocket |
| 数据帧(frame) | 传输的最小单位 |
| opcode | 帧类型:text/binary/ping/pong/close |
| 掩码(mask) | 客户端帧防代理缓存投毒 |
| 子协议 | 通过 Sec-WebSocket-Protocol 协商 |

## 应用场景

- 实时聊天、在线客服
- 协同编辑、白板、在线文档
- 实时行情、体育比分、通知推送
- 多人在线游戏、直播弹幕、Web IDE

## 优点与局限

- 优点:全双工、低延迟、头部开销远小于反复 HTTP 请求、服务器可主动推送、复用单条连接。
- 局限:有状态长连接占用服务器资源;需自行处理断线重连与心跳;部分代理/防火墙支持不佳;大规模水平扩展需配合消息总线等方案。

## 常见误区

- WebSocket ≠ HTTP 轮询/长轮询:后者本质仍是客户端反复发起的 HTTP 请求。
- 握手借用 HTTP,但升级之后传输的**不是** HTTP 报文,而是 WebSocket 帧。
- 用了 WebSocket 不等于"绝对实时":仍受网络、后端处理与浏览器调度限制。
