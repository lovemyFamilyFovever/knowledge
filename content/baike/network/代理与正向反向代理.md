# 代理与正向反向代理

> 📌 **导航**：本文是 **代理与正向反向代理** 词条，由 [[网络安全协议]] 拆分而来。

## 定义

**一句话定义：** 正向代理代表客户端出站访问、隐藏客户端身份；反向代理代表服务器接入站、隐藏后端拓扑——两者都是"中间人"，只是代理的对象与部署侧不同。

**通俗类比：** 正向代理像"托朋友去店里买东西"（店家不知买家是你）；反向代理像"门店前台接待"（顾客不知具体哪个店员服务）。

## 为什么需要它

客户端侧需要匿名 / 出网管控 / 缓存时用正向代理；服务端需要统一入口、负载均衡、SSL 终结、安全隔离时，把反向代理顶在前面、让后端对公网不可见。

## 核心机制

- **正向代理：** 部署在客户端侧、由客户端配置，隐藏客户端 IP；用于匿名、访问控制、缓存（Squid 等）。
- **反向代理：** 部署在服务端、对外是一个入口，隐藏后端；做负载均衡、SSL 终结、缓存、路径路由（Nginx / HAProxy）。
- **透传真实信息：** 反代用 X-Real-IP / X-Forwarded-For / X-Forwarded-Proto 把头传给后端，否则后端看到的是代理 IP。

## 具体示例

Nginx 作反向代理：`upstream backend { server 10.0.0.1; server 10.0.0.2; }` + `location / { proxy_pass http://backend; }`，对外只暴露 Nginx:443、终结 SSL 并轮询转发到多台应用，后端 IP 对客户端不可见。

## 何时用与何时不用

- **用：** 对外服务的统一入口 / 负载均衡 / SSL 终结用反向代理；企业出网管控 / 匿名用正向代理。
- **注意：** 反代必须正确透传 X-Forwarded-*，否则后端拿到的是代理 IP；"取真实客户端 IP"要防伪造头部绕过。

## 优劣与代价

✅ 隐藏真实端点、集中做负载均衡 / 加密 / 缓存 / 安全、简化后端。
⚠️ 代理层是性能与单点、需高可用；透传配置易错；多级代理链让排障更复杂。

## 与相关概念的区别

vs [[负载均衡]]：反代天然带 L7 负载分发，但负载均衡是更泛的分发概念；vs [[防火墙与WAF]]：WAF 常以反代形态承载、职责是内容检测；vs [[API网关]]：都作入口，网关偏南北向治理与协议转换、反代偏转发与终结。

## 常见误区

- 正向代理和反向代理是一回事，只是方向不同。
- 经反向代理后，后端看到的客户端 IP 仍是真实公网 IP。
- 用了反向代理就不需要负载均衡了。

## 面试速答

> 🎯 代理：正向代理在客户端侧、代表客户端出站、隐藏客户端(匿名/管控)；反向代理在服务端、代表后端接入、隐藏后端(Nginx/HAProxy 做 L7 负载均衡 + SSL 终结)；反代须用 X-Forwarded-For 透传真实 IP，否则后端只见代理地址。
