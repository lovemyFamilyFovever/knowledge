# HTTPS 与 TLS


> 📌 **导航**：本文是 **HTTPS 与 TLS** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** HTTPS 是运行在 TLS/SSL 之上的 HTTP,用于在客户端与服务器之间建立加密通道;TLS(Transport Layer Security,前身 SSL)是传输层安全协议,提供机密性、完整性与身份认证,防止窃听、篡改与中间人攻击。

**通俗类比：** HTTP 像寄明信片(内容公开、可被任何人看和改);HTTPS 像把信装进带锁的保险箱再寄——只有持钥匙的收发双方能打开,途中被截也读不懂、被改会发现,而且能确认对方确实是本人。

> 多义说明:TLS 是 SSL 的后继(SSL 已废弃);HTTPS = HTTP over TLS。本文以现代 TLS(1.2 / 1.3)为主。

## 原理与机制

- **TLS 握手:** 协商版本与密码套件;服务器出示证书并经 PKI 验证身份;通过密钥交换(如 ECDHE)协商出共享的对称会话密钥。
- **数据传输:** 握手后用对称加密(如 AES-GCM)加密应用数据,并以 AEAD/MAC 保证完整性。
- **TLS 1.3:** 握手简化为 1-RTT(甚至 0-RTT),移除不安全旧算法,强制前向保密(forward secrecy)。
- **端口:** HTTPS 默认使用 443(HTTP 为 80)。

## 关键组成

| 组成 | 作用 |
|------|------|
| TLS 握手 | 协商参数、认证、建立密钥 |
| 证书与 PKI | 绑定服务器身份与公钥 |
| 密码套件 | 约定加密/MAC/密钥交换算法 |
| 密钥交换(ECDHE/RSA) | 协商会话密钥 |
| 对称会话密钥 + AEAD | 加密并校验应用数据 |

## 应用场景

- 网站与 API 的加密通信
- 保护登录、支付等敏感数据
- 防窃听、防篡改、防中间人
- SEO(搜索引擎偏好 HTTPS)

## 优点与局限

- 优点:同时提供机密性、完整性与认证;防窃听篡改;已成为 Web 事实标配。
- 局限:握手带来额外延迟与计算开销;证书需管理与续期;配置不当(旧协议/弱套件)仍有风险;无法防护端点被入侵等情况。

## 常见误区

- HTTPS 只加密"传输通道",不加密两端(端点上的数据仍可能是明文)。
- 有 HTTPS ≠ 网站可信:还需验证证书有效性、警惕钓鱼站点。
- TLS ≠ SSL(SSL 已过时);HTTPS 使用 443 端口。
