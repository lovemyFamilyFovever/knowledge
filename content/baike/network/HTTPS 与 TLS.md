# HTTPS 与 TLS


> 📌 **导航**：本文是 **HTTPS 与 TLS** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** HTTPS 是运行在 TLS/SSL 之上的 HTTP，用于在客户端与服务器之间建立加密通道；TLS（Transport Layer Security，前身 SSL）是传输层安全协议，提供机密性、完整性与身份认证，防止窃听、篡改与中间人攻击。

**通俗类比：** HTTP 像寄明信片（内容公开、任何人可看可改）；HTTPS 像把信装进带锁的保险箱再寄——只有持钥匙的收发双方能打开，途中被截也读不懂、被改会发现，还能确认对方确实是本人。

> 多义说明：TLS 是 SSL 的后继（SSL 已废弃）；HTTPS = HTTP over TLS。本文以现代 TLS 1.2 / 1.3 为主。

## 为什么需要它

HTTP 明文传输，链路上任何一跳都能窃听、篡改甚至冒充。TLS 在传输层补上加密、完整性校验与身份认证三件事，让公开网络上也能建立一条只有通信双方能读懂、且能确认对方身份的信道，是登录、支付等安全通信的地基。

## 核心机制

- **TLS 握手：** 协商版本与密码套件；服务器出示证书、经 PKI（CA 签名链）验证身份；通过密钥交换（如 ECDHE）协商出共享的对称会话密钥。
- **数据传输：** 握手完成后用对称加密（如 AES-GCM）加密应用数据，并以 AEAD 同时保证机密性与完整性。
- **TLS 1.3：** 握手简化到 1-RTT（配合会话恢复可 0-RTT），移除不安全的旧算法，强制前向保密（forward secrecy）。
- **端口：** HTTPS 默认使用 443（HTTP 为 80）。

## 具体示例

浏览器访问 `https://`：ClientHello 报支持的版本 / 套件 → 服务器回证书链与选定套件 → 浏览器用系统内置 CA 公钥验签、确认域名匹配 → 双方用 ECDHE 算出会话密钥 → 之后用对称密钥高速加密通信。

## 何时用与何时不用

- **用：** 网站与 API 的加密通信、保护登录 / 支付等敏感数据、防窃听篡改与中间人、SEO（搜索引擎偏好 HTTPS）。
- **不用：** 极少数纯内网、无敏感数据且已有其他隔离的场景可省；但现代实践几乎一律上 HTTPS（Let's Encrypt 让证书近乎免费）。

## 优劣与代价

✅ 同时提供机密性、完整性与认证，防窃听篡改，已成 Web 事实标配。
⚠️ 握手带来额外延迟与计算开销；证书需管理与续期；配置不当（旧协议 / 弱套件）仍有风险；无法防护端点被入侵。

## 与相关概念的区别

vs HTTP：HTTPS = HTTP + TLS，前者明文、后者加密并认证；vs 端到端加密：TLS 只加密传输通道、服务器仍以明文持有数据，端点被入侵时 TLS 救不了；vs [[公钥基础设施]]：PKI 提供证书信任链，是 TLS 身份认证的前提。

## 常见误区

- HTTPS 加密了数据从端点到端点的全过程。
- 只要网站用 HTTPS 就一定可信、安全。
- TLS 和 SSL 是同一个东西。

## 面试速答

> 🎯 HTTPS = HTTP over TLS：握手时协商套件、用证书 + PKI 验服务器身份、ECDHE 交换出对称会话密钥（1.3 做到 1-RTT/0-RTT 并强制前向保密），之后用 AES-GCM 加密；提供机密性 + 完整性 + 认证，但只加密通道、不加密端点。
