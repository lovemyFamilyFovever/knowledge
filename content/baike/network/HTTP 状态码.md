# HTTP 状态码


> 📌 **导航**：本文是 **HTTP 状态码** 词条，属于 network 术语集。相关枢纽：[[DNS深入解析]]、[[TCP深入]]、[[网络基础]]。

## 定义

**一句话定义：** HTTP 状态码（HTTP Status Code）是服务器响应 HTTP 请求时返回的三位数字代码，用于表示请求处理结果的类别（成功、重定向、客户端错误、服务器错误等），是客户端判断如何处理响应的依据。

**通俗类比：** 像快递单上的状态标记——"已签收(200)""地址变更请转寄(3xx)""你填错了地址(4xx)""仓库出问题了(5xx)"，一个三位数就告诉你这单的结果类别。

> 多义说明：状态码分五类（1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务器错误）。本文按类讲解常见码。

## 为什么需要它

HTTP 是无状态短连接协议，客户端需要一种标准化的轻量方式知道"这次请求到底成没成、接下来怎么处理"。三位状态码把结果归类（成功 / 重定向 / 是谁的错），让浏览器与程序据此决定跳转、重试、提示或降级。

## 核心机制

| 类别 | 含义 | 常见码与用途 |
|------|------|--------------|
| 1xx | 信息 | 100 Continue、101 Switching Protocols（WebSocket 升级） |
| 2xx | 成功 | 200 OK、201 Created、204 No Content |
| 3xx | 重定向 | 301 永久、302 临时、304 Not Modified（缓存命中、不返回体） |
| 4xx | 客户端错误 | 400 请求无效、401 未认证、403 无权限、404 未找到、405 方法不允许、429 请求过多 |
| 5xx | 服务器错误 | 500 内部错误、502 Bad Gateway、503 不可用、504 网关超时 |

## 具体示例

`POST /api/order` 成功建资源回 201 Created + Location 头；用户未登录访问受保护接口回 401 提示认证、已认证但越权回 403；命中协商缓存则回 304、不重复传输响应体。

## 何时用与何时不用

- **用：** RESTful 接口设计、Web / API 开发、错误处理、缓存（304）、限流（429）、调试与监控。
- **不用（误用反面）：** 别把一切业务失败都塞进 200 只靠响应体区分（丢失 HTTP 语义、代理与客户端无法据此处理）；也别滥回 500 掩盖真实原因。

## 优劣与代价

✅ 标准化、用一位数前缀表达结果类别、直接指导客户端行为。
⚠️ 状态码有限、细节需响应体补充；易被误用（全 200 或滥用 500）；不同实现对个别码语义略有差异。

## 与相关概念的区别

vs 业务错误码：状态码是传输 / 协议层的结果类别，业务码是应用层细分，二者配合而非互相替代；401 vs 403：401 是"没认证（你是谁）"、403 是"认证了但无权限"。

## 常见误区

- 401 和 403 都表示"没权限"、二者没区别。
- 所有请求都返回 200、把业务错误放响应体就好。
- 304 Not Modified 表示服务器处理出错。

## 面试速答

> 🎯 HTTP 状态码 = 三位数按前缀分类：1xx 信息、2xx 成功(200/201/204)、3xx 重定向(301 永久/302 临时/304 缓存命中)、4xx 客户端错(401 未认证/403 无权限/404/429 限流)、5xx 服务器错(500/502/503/504)。
