# HTTP 状态码

## 定义

**一句话定义：** HTTP 状态码(HTTP Status Code)是服务器响应 HTTP 请求时返回的三位数字代码,用于表示请求处理结果的类别(成功、重定向、客户端错误、服务器错误等),是客户端判断如何处理响应的依据。

**通俗类比：** 像快递单上的状态标记——"已签收(200)""地址变更请转寄(3xx)""你填错了地址(4xx)""仓库出问题了(5xx)";一个三位数就告诉你这单的结果类别。

> 多义说明:状态码分五类(1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务器错误)。本文按类讲解常见码。

## 原理与机制

- **1xx(信息):** 100 Continue、101 Switching Protocols(如 WebSocket 升级)。
- **2xx(成功):** 200 OK、201 Created、204 No Content。
- **3xx(重定向):** 301 永久重定向、302 临时重定向、304 Not Modified(缓存命中)。
- **4xx(客户端错误):** 400 Bad Request、401 Unauthorized(未认证)、403 Forbidden(无权限)、404 Not Found、405 Method Not Allowed、429 Too Many Requests(限流)。
- **5xx(服务器错误):** 500 Internal Server Error、502 Bad Gateway、503 Service Unavailable、504 Gateway Timeout。

## 关键组成

| 类别 | 含义 | 常见码 |
|------|------|--------|
| 1xx | 信息 | 100、101 |
| 2xx | 成功 | 200、201、204 |
| 3xx | 重定向 | 301、302、304 |
| 4xx | 客户端错误 | 400、401、403、404、429 |
| 5xx | 服务器错误 | 500、502、503、504 |

## 应用场景

- Web / API 开发
- RESTful 接口设计
- 错误处理、缓存(304)、限流(429)
- 调试与监控

## 优点与局限

- 优点:标准化、简洁表达结果类别、指导客户端行为。
- 局限:状态码有限(细节需响应体补充);易被误用(如全返回 200,或滥用 500);不同实现语义略有差异。

## 常见误区

- 401(未认证,你没登录)≠ 403(已认证但无权限)。
- 301(永久)与 302(临时)对 SEO/缓存的影响不同。
- 304 表示缓存有效(不返回响应体)。
- 429 是限流(见 [[限流]]);不要把业务错误都塞进 200。
