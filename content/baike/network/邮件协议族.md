# 邮件协议族

> 📌 **导航**：本文是 **邮件协议族** 词条，由 [[应用层协议]] 拆分而来。

## 定义

**一句话定义：** 邮件协议族按职能分工——SMTP 负责发出与服务器间投递（25 / 465 / 587），POP3 与 IMAP 负责收取（110 / 995、143 / 993）：POP3 下载到本地、默认删服务器副本，IMAP 在服务器端同步状态、支持多设备。

**通俗类比：** SMTP 像寄信，POP3 像去邮局把信取走、信箱就空，IMAP 像云端信箱——在哪台设备打开都保持同一状态。

## 为什么需要它

邮件天然分"发"和"收"两个动作，而"收"又有离线单设备与在线多设备同步两种需求，单个协议无法覆盖，于是 SMTP / POP3 / IMAP 各司其职。

## 核心机制

- **SMTP（发）：** 会话按 HELO → MAIL FROM → RCPT TO → DATA 逐条投递；加密用 465（SMTPS）或 587（STARTTLS，推荐）。
- **POP3（收）：** 把邮件下到本地、默认删服务器副本，离线、单设备友好、不占服务器存储。
- **IMAP（同步收）：** 邮件留在服务器，多设备状态一致，支持服务端文件夹与 \Seen 等标志同步。

## 具体示例

手机上把邮件标已读或归档，换电脑用 IMAP 仍看到同样状态；用 POP3 则两端各自下载、状态互不同步。发信优先 587 + STARTTLS，兼顾兼容与加密。

## 何时用与何时不用

- **用：** 现代邮件客户端默认 IMAP（收）+ 587 STARTTLS（发）；确要离线单设备、省服务器空间才用 POP3。
- **不用：** 多设备场景别用 POP3（会丢同步）；生产不要用 25 明文发信。

## 优劣与代价

✅ 收发解耦，可按离线（POP3）或同步（IMAP）需求选型。
⚠️ POP3 多设备不同步、易误删；IMAP 占用服务器存储；明文端口必须配 SSL / TLS。

## 与相关概念的区别

vs [[DNS深入解析]] / [[动态主机配置协议]]：那些是域名解析与网络接入基础设施，本文是应用层邮件协议；POP3 与 IMAP 的取舍核心是"离线单设备 vs 在线多设备同步"。

## 常见误区

- IMAP 和 POP3 只是端口不同、功能一样。
- POP3 一定比 IMAP 好，因为省服务器空间。
- 发信用 25 端口明文最方便、不必加密。
