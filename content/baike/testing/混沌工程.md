# 混沌工程

## 核心原则

1. 建立稳态假设（正常时的指标基线）
2. 引入真实事件（服务器宕机、网络延迟、磁盘满）
3. 在生产环境运行（或预发布）
4. 自动化持续运行
5. 最小化爆炸半径

## 常见故障注入

| 类型 | 工具 | 示例 |
|------|------|------|
| 进程终止 | kill -9 | 随机杀Pod |
| 网络延迟 | tc/netem | 延迟+100ms |
| 网络丢包 | tc/netem | 丢包50% |
| 磁盘满 | dd | 写满磁盘 |
| CPU满载 | stress | 100% CPU |
| 依赖故障 | Mock | 下游超时 |

## Chaos Monkey

Netflix的混沌工具：
- Chaos Monkey: 随机杀实例
- Latency Monkey: 注入延迟
- Chaos Kong: 模拟整个区域故障

## GameDay

```
准备 -> 演练(注入故障、观察系统、团队响应) -> 复盘(改进点)
```
