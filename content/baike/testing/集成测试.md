# 集成测试


> 📌 **导航**：本文是 **集成测试** 词条，属于 testing 术语集。相关枢纽：[[01 - 测试基础]]、[[02 - 测试工具]]、[[03 - 性能测试]]、[[单元测试]]、[[性能测试]]。

## 定义

**一句话定义：** 集成测试(Integration Testing)是在单元测试之后,把多个已测试的模块/组件组合起来,验证它们之间的接口、数据传递与协作是否正确的测试层级,用于发现模块集成后才暴露的交互问题。

**通俗类比：** 像汽车零件各自检验合格后,把它们组装起来试跑——单个零件(单元)没问题,不代表装在一起就顺(接口不匹配、时序错乱);集成测试就是检查"组装后各部件配合是否正常"。

> 多义说明:集成测试介于单元测试与系统测试之间;策略有自顶向下、自底向上、大爆炸(big bang)、三明治/增量式。本文讨论集成测试。

## 原理与机制

- **关注点:** 模块间接口、数据流、调用时序、依赖协作、跨层交互(如服务 ↔ 数据库 ↔ 缓存)。
- **策略:** 自顶向下(先测上层,下层用桩 stub)、自底向上(先测下层,上层用驱动 driver)、增量集成。
- **边界:** 单元测单个组件(隔离)、集成测组件协作、系统测整体端到端。
- **配套:** 契约测试(如 Pact)、测试容器(Testcontainers)、内存数据库/模拟服务。

## 关键组成

| 组成 | 说明 |
|------|------|
| 模块接口 | 集成测试的核心对象 |
| 桩(stub)/ 驱动(driver) | 模拟未就绪的模块 |
| 集成策略 | 自顶向下 / 自底向上 / 增量 |
| 契约测试 | 验证服务间接口约定 |

## 应用场景

- 微服务间集成
- 服务与数据库/中间件集成
- API 契约验证
- CI 中的集成测试阶段

## 优点与局限

- 优点:发现单元测不到的接口/协作问题、更接近真实运行、验证集成正确性。
- 局限:定位问题比单元测试难(涉及多模块);环境与依赖搭建成本高;速度慢于单元测试;组合可能爆炸。

## 常见误区

- 集成测试 ≠ 单元测试:单元隔离依赖,集成验证协作。
- 集成测试 ≠ 系统/E2E 测试:集成聚焦模块间,系统聚焦整体。
- 依赖真实外部服务会使测试不稳定(常用替身/容器)。
- "大爆炸"式一次全集成难定位问题,宜增量集成。
