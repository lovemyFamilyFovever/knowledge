# 负载测试工具（JMeter·K6·Locust）

> 📌 **导航**：本文是 **负载测试工具（JMeter·K6·Locust）** 词条，属 [[03 - 性能测试]] 子词条。指标口径见 [[性能测试指标]]，结果分析见 [[性能报告与瓶颈分析]]。

## 定义

**一句话定义：** 负载测试工具是"造压—采集—报告"的引擎——JMeter（Java/GUI，企业级）、k6（JS 脚本 + CLI，现代 DevOps）、Locust（Python 代码定义用户行为）用不同心智驱动并发、发送请求、收集指标并出报告。

**通俗类比：** 像三家不同品牌的"健身房陪练"：JMeter 器材全、界面化；k6 轻量、写脚本跑进 CI；Locust 用 Python 描述"用户怎么动"，代码即场景。

## 为什么需要它

手工点根本压不出成百上千并发，也测不准响应分布。负载工具把"虚拟用户、请求脚本、加压节奏、指标采集、结果报告"标准化，让性能测试可复现、可 CI 化、可分布式扩压，是拿到可信 [[性能测试指标]] 的前提。

## 核心机制

- **JMeter**：测试计划 = 线程组（模拟并发）+ 取样器 Sampler（发 HTTP 等请求）+ 监听器（收集）+ 断言（验正确）+ 配置元件（HTTP 默认值/头管理器/Cookie）+ 定时器（控节奏/思考时间）；GUI 编排、CLI/分布式跑；插件生态丰富。
- **k6**：JS 写 `export default function(){ http.get(...) }`，`stages` 声明式加压（预热→升压）；阈值 `thresholds` 直接当 CI 门禁（如 `p(95)<500`）；CLI 友好、单机性能高。
- **Locust**：Python 类 `class User: tasks=[...]` 定义用户行为，Web UI 实时看 RPS/失败；`--headless` 进 CI；靠多进程/分布式 master-worker 扩压。
- **共通**：都要真实业务模型（请求比例、思考时间）、预热、参数化与关联（取 token 回填）、分布式扩压。

## 具体示例

| 特性 | JMeter | k6 | Locust |
|---|---|---|---|
| 脚本 | XML/GUI | JavaScript | Python |
| 学习曲线 | 中 | 低 | 低 |
| 单机性能 | 一般 | 优秀 | 良好 |
| CI 集成 | 可 | 强（CLI+阈值） | 强 |
| 适合 | 企业复杂/GUI | 现代应用/DevOps | Python 项目 |

## 何时用与何时不用

- **用**：按栈与习惯选——Java 企业级/需 GUI/复杂协议→JMeter；JS/TS 团队、要 CI 阈值门禁→k6；Python 团队、想用代码写复杂用户行为→Locust。
- **不用**：别用 GUI 硬扛超大并发（JMeter 单机内存开销大，用 CLI/分布式或换 k6）；别拿单元/接口功能工具（[[Postman 与接口测试]]）当压测器测吞吐；工具不等于结论——脚本无预热/无思考时间照样测出假象。

## 优劣与代价

✅ 三件套覆盖"界面化企业 / 代码化 DevOps / Python 原生"主流取向，皆可分布式扩压、可入 CI。
✅ k6 阈值、Locust 代码、JMeter 插件各把"可维护压测脚本"落到团队熟悉的形态。
⚠️ 工具自身是瓶颈源（发起端 CPU/带宽不足会低估被测系统上限）——需监控压测机本身。
⚠️ 学习曲线与心智不一：JMeter XML 笨重、k6/Locust 需能写代码；选错栈维护成本高。

## 与相关概念的区别

- **GUI 模式 vs CLI 模式**：JMeter GUI 调试用、正式跑必用 CLI（GUI 极耗资源）。
- **脚本式（k6/Locust） vs 组件式（JMeter）**：代码描述行为 vs 拖拽元件拼装。
- **负载工具 vs 监控/APM**：工具造压取端侧指标，[[性能报告与瓶颈分析]] 里的资源侧要看服务器监控与剖析。

## 常见误区

- 用 JMeter GUI 跑 1000 并发压测，结果和被测系统真实上限一致。
- 压测脚本不写思考时间、参数化，也能反映真实用户负载。
- 压测机 CPU 打满不影响结论，反正测的是服务端。

## 面试速答

> 🎯 三大负载工具：JMeter(线程组+取样器+监听器+断言+定时器，GUI/CLI，企业复杂协议)、k6(JS+stages 加压+thresholds 当 CI 门禁，轻量高性能)、Locust(Python 定义用户行为、可分布式)。按栈选；正式跑用 CLI 非 GUI、监控压测机自身、脚本要预热与参数化。
