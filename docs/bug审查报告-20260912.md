## S1 · 数据损坏 / 核心功能失效

### B1. 收藏切换会损坏嵌套 YAML frontmatter 的文档 ——【实测存在 41 个受害文件】
- 链路：`routes_edit.api_favorite:80-82` 读 fm → 改 favorite → `store.dump_frontmatter` 整文件重写。
- `parse_frontmatter`（store.py:144）是行级 `key: value` 扁平解析器，不是 YAML 子集：
  `handbook/index.md`、`projects/index.md` 等 41 个文件含 `hero:` / `features:` 多行嵌套块，
  解析时嵌套行被压成垃圾键（`"- title": 面试摘录`），dump 回写后原始结构**不可逆损坏**。
- 复现路径：阅读器打开 `handbook` 域总览 → 点「收藏」→ 文件即坏（git 可救，但用户无提示）。
- 同一炸弹还有第二个引信：**BOM**。`FM_RE = \A---\n`（store.py:25）不认 `\ufeff` 前缀，
  JS 侧已处理 `\uFEFF?`（app.js fetchFmRaw），Python 侧没有。当前语料 BOM 文件 = 0【实测】，
  但 Obsidian/Notepad 在 Windows 上随时可能给文件加 BOM——加上的瞬间，收藏切换 =
  在原文前面再叠一个新的 `--- favorite: true ---` 块（双 frontmatter）。
- 修复方向：dump 前校验「parse→dump 往返无损」，不无损就拒绝重写并提示；FM_RE 加 `\ufeff?` 与 `\r?\n`。

### B2. `.notes.md` 备注旁挂会被当成正文文档（幽灵文档）——【实测复现】
- 探针：建 `articles/doc.md` + `doc.md.notes.md`，`scan_corpus` 输出 docs = `['doc', 'doc.md.notes']`。
- 根因：`_scan_sub`（store.py:245）按 `p.suffix in SERVABLE_EXTS` 收文件，不排除 `.notes.md`；
  `md_files`（fts 索引同口径）也不排除。当前语料备注数 = 0【实测】所以没爆，
  用户在 UI 写第一条备注的那一刻：列表出现幽灵文档、FTS 出幽灵搜索结果、
  `/doc/<…>/doc.md.notes` 居然**可路由**（find_doc 候选 `name+'.md'` 直接命中旁挂文件）。
- 附带：幽灵文档会进标签统计、收藏计数、全局统计，污染面大。
- 修复方向：`_scan_sub` 与 `md_files` 统一 `if fn.endswith(".notes.md"): continue`。

### B3. 子目录内嵌套 `_` 目录 / SKIP_DIRS 之外的 `_trash` 子域泄漏进树 ——【实测复现】
- 探针：`baike/algorithms/_tmp/leak.md` 出现在树里，name=`_tmp/leak`，且 find_doc 可解析可路由。
- 根因三处口径不一致：
  1. `_scan_sub` 的 `sdir.rglob("*")` 不剪 `_` 目录（store.py:245）；
  2. 子域列表只排除 `SKIP_DIRS = {_inbox,_assets,_unfiled}`，该集合**不含 `_trash`/`_meta`**（store.py:26, 229）——域内如有 `_trash` 目录会被列为子域；
  3. `md_files` / `_tree_sig` / rag `md_corpus_files` 都会剪 `_` 目录。
- 后果：同一文件在「分类树 / FTS / 向量 / 统计签名」四套扫描里可见性不同，违反不变量 2，
  且用户永远搜不到这篇「看得见」的文档。
- 修复方向：抽一个共享的 `is_hidden_rel(parts)` 谓词，四处扫描统一调用。

### B4. 正文里的 [[双链]] 渲染成死文本，不可点击 ——【静态，确凿】
- `renderArticle`（app.js:133）直接 `DOMPurify.sanitize(marked.parse(DOC.md))`，全仓库没有任何
  把 `[[目标]]` 转 `<a>` 的步骤（grep 证实仅右键菜单/双链面板用到 wikilink 概念）。
- 双链是本产品核心卖点（fts.py 专门建 links 表、右栏专门做面板），但**阅读视图里点不动**，
  只有「它引用 / 谁引用了它」面板能跳转。语料里成百上千条 `[[...]]` 在阅读页全是方括号生肉。
- 修复方向：sanitize 后对 `.a-body` 文本节点做 `[[x|别名]]` → `docUrl` 链接替换（代码块内跳过）。

### B5. 闪卡「跳转原文」的锚点深链 100% 失效 ——【静态，确凿】
- 卡片携带 anchor（`## 定义` / `题目N：xxx` / `### 三、HTTP`），learn.js `anchorHash()`（:111）
  拼成 `#定义`、`#题目3-xxx` 形式的 fragment。
- 但阅读页正文由 marked 客户端渲染：marked v12+ 默认**不生成标题 id**（bundle 内无 headerIds），
  `buildToc` 赋的 id 是 `sec-0/1/2`（app.js:168）。fragment 与任何元素 id 都不匹配。
- 结果：复习卡跳原文只能落在文档顶部，「定位到该题所在章节」的承诺（cards.py:113 NO_ANSWER_HINT
  文案原文写着）不成立。glossary 详情、today 卡的 url 同理。
- 修复方向：renderArticle 内给 h1-h4 生成 `id = 标题文本规范化`，与 anchorHash 用同一函数（前后端共享规则）。

## S2 · 特定条件下的功能错误

### B6. 清空正文后保存，frontmatter 被整体重置 ——【静态】
`api_save`（routes_edit:49-55）：body 无 fm → 自动 stamp `title=文件名`，原 tags/source/collected/status 全丢。
编辑器全选删除 → 保存 → 文档身世抹掉。修复：仅当「文件原本就没有 fm」时才 stamp（后端读原文件判断）。

### B7. 移动目标处已有同名旁挂 → 主文件已搬、旁挂炸 500（半迁移）——【静态】
`_do_move`（routes_files:69-77）：`src.rename(dst)` 成功后 `sib.rename(sib_dst)` 若
`x.notes.md`/`x.html` 在目标目录已存在 → Windows FileExistsError 上抛 → HTTP 500，
但主文件已经走了，FTS/rag 更新也没执行。`_resolve_dst` 只检查主文件 dst 存在性。
同理 `api_delete`（routes_files:51）同秒二次删除同一文档 → 目标已存在 → 500。
回收站恢复后再删一次同样撞（同 rel 同秒概率低，但不同日同秒 = `time.strftime` 到秒，会撞）。
修复：旁挂冲突加 `_n` 后缀或整事务化（预检全部路径再动盘）。

### B8. 文档移动后「已读完/已掌握」标记丢失 ——【静态】
doc_marks 以 path 为主键（reading.py:30-36），`_do_move` 级联了 FTS 和 rag 但**没有 UPDATE reading.db**。
整理语料（高频操作，AGENTS 明确说「用户整理语料是常态」）后读完状态、月度事件归属全部断链。
对照：卡片复习进度刻意设计为路径无关（cards.py:13-14），两套状态的健壮性哲学相反。
修复：_do_move 中 `UPDATE doc_marks SET path=? WHERE path=?`（事件表同理可选）。

### B9. 复习页空队列误报「今日已复习完」——【静态，逻辑链明确】
learn.js boot：`loadQueue().then(S.loaded=true; showCard())`（:477-480），无卡时 `showDone()` 的
`first = !S.loaded && doneN===0`（:275）恒为 false → 全新用户零卡片零复习，看到的是
「今日已复习完 —— 这批到期的卡已经过完」。空态文案撒谎。

### B10. 编辑器每次保存触发 N 次全库断链扫描 ——【静态】
`wikilink_check`（learn.py:1043-1052）对**每个死链**调一次 `wikilink_suggest`，后者打开 FTS 连接、
全表扫 docs + cards 打分。一篇 12 条死链的草稿，400ms 防抖后一次全扫 12 遍全库；
输入停顿连续触发时放大。修复：一次取回候选集，本地匹配 Top1。

### B11. 三套同步全部只认 mtime 前进，外部删除/恢复不感知 ——【静态】
- `index_is_stale`（fts.py:80-87）：`newest > built_at`，删除文件不改任何 mtime → FTS 幽灵行长期残留；
- 从 `_trash` 手动恢复文档：rename 保留**旧 mtime** → 恢复后搜不到，直到重新编辑保存一次；
- `sync_rag` 的 `known[rel] < mt` 同理（rag.py:489），但至少有 `deleted` 集合兜住删除，恢复仍不可见。
- 对比：`ensure_synced`（learn.py:352）用候选篇数补了删除盲区，FTS/RAG 没抄这个作业。
修复：统一用 `_tree_sig`（含文件清单）做失效判据，或 watcher 里比对 `files` 表 vs 磁盘集合。

### B12. 保存后 30 秒窗口内：绝对路径双链误标「未解析」+ 反向链暂缺 ——【静态】
`upsert_doc_in_index`（fts.py:174-176）把 `by_path` 建成 **stem 键**，而 `build_index`
（fts.py:59）是完整路径键——`[[career/journal/xxx]]` 这类路径式目标在外科手术更新时永远解析失败；
`remove_doc_from_index` 删 `dst=?` 行会把**其他文档指向它**的反向链一并删掉，要等 30s watcher
全量重建才回来。右栏双链面板、全局统计「死链数」在这个窗口内读数失真。
修复：upsert 用完整路径键 + 反向行重解析（dst 方向 UPDATE 而非 DELETE-忽略）。

### B13. get_rag 惰性初始化存在并发竞态 ——【静态】
`app.py:107-120`：`tried=True` 先置、随后同步下载模型（最长 120s×2）。期间并发请求看到
`tried=True, embedder=None` → 误报「语义检索不可用」；两个线程同时走到初始化 →
同写 `model.onnx.part` 竞态。watcher 线程与请求线程同样可撞。修复：`get_rag` 加锁。

### B14. 删除时编辑器留在原地，可把已删文档「复活」回原路径 ——【静态，工作区并发修复未覆盖】
`deleteDoc`（app.js 乐观更新分支）不清理 `#editor`：经编辑器工具条的删除按钮操作后，
textarea 仍开着；此时点保存 → `api_save` 对已移入 `_trash` 的原路径 `write_text` → **文档在原地重建**，
回收站里还留着一份。另 `DOC=null` 后编辑器 Ctrl+S 直接 TypeError。
修复：deleteDoc 首行 `tryCloseEditor()`（或丢弃快照强关）。

### B17. make_card_id 与文档无关 → 跨文档同名术语互相覆盖 ——【静态，设计取舍未设防】
cards.py:123-126：`baike_def` 的 front 由 term 模板生成，**同 term 两张卡在两个文件里 → card_id 相同**，
后扫到的文件直接 UPDATE 前者的 back/source_rel——复习进度被悄悄「换文档」。改名不丢进度是刻意设计，
但同名术语跨文档（ baike 汇篇 vs 单词条，语料里真实存在同名概率）是未设防的碰撞。至少应 detect 并 warning。

### B18. 统计接口全库 read_text 风暴 ——【静态】
`/api/globalstats`、`/api/dir/tree`、`/api/substats`（routes_stats）每次打开弹窗都全库逐篇
read_text+parse（2000+ 文件、几十 MB IO），三处各写一遍同一逻辑。目录统计弹窗里切兄弟目录
= 再来一轮全库。修复：字数/标签分布并入 `_tree_sig` 缓存周期内计算（scan_corpus 顺手统计），或加 TTL。

### B19. 搜索 facets 前后端语义分裂（= 交互方案 P0-5 的根因）
search.js 多选只把第一个值传后端、其余本地过滤，meta 却显示后端 total（search.py:380 total=过滤前 items 数）。
后端 `/api/search` 的 domain/sub/tag 都是单值参数——要么后端支持多值，要么前端 UI 改单选，现状两头不靠。
