> 「`E:\GitHub\library-archive\小说` 和 `E:\GitHub\library-archive\漫画` 这两个目录清掉吧，
> 我本地已经有备份了，所以我需要将这两个内容彻底删除，以后就不要这两个目录的内容了。」

任务 = 物理删除那两个归档目录，并把"文档里还写着它们在 library-archive"这句话改对。

## ③ 现在卡在哪

没卡住。有一件**必须让用户知道、但本轮故意没做**的事：

**"彻底删除"没有真的彻底。** 这些文件仍在 knowledge 仓库的 git 历史里，
`git show <旧提交>:content/小说/...` 随时取回来；`.git` 目前约 **318MB**，其中 pack 265MB 基本就是书库。
要真正从仓库里抹掉，只能 `git filter-repo`（或 BFG）改写历史 + 强推 —— 而 `AGENTS.md` 禁区明写
「禁止 `git push -f`、禁止改写 main 历史」，且改写会让用户其它机器上的克隆全部作废。
所以这是**用户单独拍板**的事，不是我能顺手做的。

## ⑤ 踩过的坑 / 该记住的判断

1. **"删掉副本"和"删掉数据"是两件事。** 用户说"彻底删除"时，先把"哪些地方还留着副本"讲清楚
   （git 历史、`.git` 体积、其它克隆），再决定动作 —— 否则他会以为已经没了。
2. **删大批文件前先扫 reparse point。** 这个仓库有过 junction 链（`tests/test_known_defects.py` 里
   专门测"rmtree 前要摘链"），一次穿透就是别人的数据。
3. **删除要留物证**：数量、字节数、清单哈希。事后他说"我明明让你留了清单"，拿得出来。
4. **文档里写过的路径，东西没了就得改文档。** 上一轮我刚在 AGENTS 写"移到 library-archive"，
   这轮删完若不改，那条就成了假线索（台账 §6 第 104 行同族）。
