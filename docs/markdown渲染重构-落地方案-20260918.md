# Markdown 渲染重构 · 落地方案（过目后再动手）

> 目标：把阅读器 markdown 正文（`.a-body`）重做成参考页 / `.iv` 那套观感，**markdown 保持唯一事实源**，放弃“内容转 HTML”路线。本文只做方案，不含已执行改动。

## 0. 一句话范围

改两处：`static/style.css` 的 `.a-body` 样式块（重设计）＋ `static/app.js::enhanceArticleDOM`（加“标题分组成卡片 / 随机主题条 / 徽章 / 提示框”四步后处理）。**影响所有 markdown 文档**（阅读/复习/术语/百科/文章等），不止面试。`.txt/.pdf/.epub/.xlsx` 走 `renderLibraryDoc` 另一条路，不受影响。

## 1. 设计映射（参考页 → `.a-body`）

| 元素 | 现状 | 目标（照参考页/.iv） |
|---|---|---|
| h1 | 左对齐、衬线、下边框 | 居中、`padding 2rem 0`、底部 3px 主题色下划线 |
| h2（章节/主题条） | 左边框+下划线 | **整条渐变底 + 白字 + 圆角**；**渐变色随机**（见 §3） |
| h3 | § 前缀 | 主题色文字 + 左侧 4px 主题色竖条 |
| 小节卡片 | 无 | **每个 `##` 下内容包成 `.sec-card`**：浅底 + 边框 + 圆角 + `padding` + 卡间 `margin-bottom`（隔离感来源） |
| 列表 | 默认 | `padding-left 2rem`、`li margin .5rem`、圆点；嵌套缩进清晰 |
| 提示框 | blockquote + 💡/️ | 扩为 tip/warn/kp(关键要点)/fu(追问) 四类，各自主题色左边条+浅底 |
| 代码块 | 固定深色 LCD | **随主题翻转**：浅色主题→浅底深字，暗色主题→深底（含语法高亮配色，见 §4） |
| 行内码 | 主题色底 | 保留，随主题 |
| 表格 | 已有斑马纹/包壳 | 微调对齐参考页（th 浅底、hover） |
| 字体 | 系统栈 | **中文 `梦源黑体 CN`、英文/代码 `Consolas`**（见 §5） |

## 2. 颜色 / 主题策略（核心原则：不写死）

- 所有色值取自阅读器**现有主题变量**：`--c-acc`（域强调色，taxonomy 驱动）、`--c-ink/--muted`、`--c-line/--c-line2`、`--c-panel/--c-sunk`（卡片底）、`--c-info/--c-warn`。→ 自动跟随明暗主题 + 当前域色相，**零硬编码**。
- h2 渐变：`linear-gradient(135deg, var(--g1), var(--g2))`，`--g1/--g2` 由 JS 注入（§3）。

## 3. 随机主题条（h2）——必须 JS 做

- CSS 无法随机，故在 `enhanceArticleDOM` 里给每个 `.a-body h2` 注入 `--g1/--g2`。
- **决策点（待你选）**：随机策略——
  - (A) 每次刷新都不同（纯随机）；
  - (B) 按标题文字 hash 取色（同一标题恒定、不同标题各异，**推荐**，避免刷新跳色）。
- 色相取“高饱和、彼此区分”的一段，明度随主题（暗色下压暗避免刺眼）。

## 4. 代码块随主题翻转（最易翻车项，需你确认）

- 现状 `--plate` 是**固定暗色 LCD**，hljs 也按暗色配色。要浅色主题用浅底，必须**同时换一整套 hljs 浅色语法配色**，否则浅底+暗色 token 会糊。
- 方案：`html[data-theme]` 下分别定义 `--code-bg/--code-fg` + hljs token 色；或引入一份 hljs light 主题 CSS 按主题切换。
- **决策点**：代码块浅色主题要不要连语法高亮一起翻（工作量在此），还是“浅底但保留克制单色高亮”。

## 5. 字体

- 正文栈：`font-family: Consolas, "梦源黑体 CN", "Microsoft YaHei", sans-serif;`（拉丁走 Consolas、CJK 回退梦源黑体 CN）。代码 `pre/code` 同用 Consolas。
- 已核实系统装有：`梦源黑体 CN`（W1–W27 多字重）、`Consolas`。
- **待落地验证**：梦源黑体 CN 每字重独立命名，正文/标题各取哪个 W 实测后定（默认正文中细、标题中粗）。

## 6. 必须新增的 JS 后处理（`enhanceArticleDOM` 内，顺序敏感）

1. **标题分组 → `.sec-card`**：遍历 `.a-body` 直接子节点，遇 `h2`（或约定层级）开一张卡，把该标题后、到下一个同级/更高级标题前的所有兄弟节点移入 `<div class="sec-card">`。**幂等**：已包过的跳过；标题 id 保留在标题元素上（不影响 buildToc/锚点）。
2. **随机主题条**：给每个 `h2` 注入 `--g1/--g2`（§3）。
3. **难度徽章**：识别约定（§7）→ 在标题右侧插 `<span class="iv-badge">`。
4. **提示框分类**：扩展既有首行约定，把 `>` 归入 tip/warn/kp/fu。

## 7. 需要的 markdown 约定（作者侧，尽量轻）

- 小节卡片：正常写 `## 小节标题` 即可，零负担。
- 提示框：沿用首行 emoji——`> 💡` tip、`> ⚠️` warn；新增 `> 🎯`/首行`关键知识点` → kp、`> 🔍`/`追问` → fu。
- 难度徽章（**可选**，仅题库类需要）：约定题干行含 `｜中级` 或标题尾 `<!-- 中级 -->`，JS 解析成 pill。若不要徽章，此条跳过、零约定。

## 8. 改动文件与影响面

- `static/style.css`：重写 `.a-body` 相关规则 + 新增 `.sec-card`/四类提示框/徽章/代码主题变量/字体。
- `static/app.js`：扩 `enhanceArticleDOM`（§6）。
- 不改：`app/templates/*`（共享模板，除非徽章 DOM 需要）、渲染管线、语料。
- **影响**：所有 markdown 文档外观统一变样（即目标）；须多域回归。

## 9. 实施顺序与验证（小步、每步跑）

1. 先只改 `.a-body` 的**排版/字体/提示框/代码主题**（不分组），拿 3 篇不同域文档（一篇技术含代码表格、一篇含多级标题、一篇长文）截图对比 → 你确认基调。
2. 再加 `enhanceArticleDOM` 的**分组 + 随机主题条**，同批文档复验（重点：卡片隔离、buildToc 仍正常、锚点/mermaid/代码复制不坏）。
3. 加徽章（若你要）。
4. 明暗两套主题各截图；`python tests/test_reader.py` + `node --check`；pre-commit。
5. 全绿后再谈“面试内容退回 markdown + 补全到宣称题数”（那是内容层，独立于本渲染层）。

## 10. 回滚

改动全在 `style.css`/`app.js` 两文件、git 跟踪，`git revert`/丢弃即可回退；语料零改动，无数据风险。

### 11.1 代码块主题 CSS 片段（交给 Prompt-R 直接落地）

**现状**：`base.html:11` 固定载 `hljs-github-dark.min.css`（永远暗色），`app.js` 用 `hljs.highlightElement` 打 `hljs-*` 类；`style.css:450` 的 `.a-body pre` 背景是**固定暗色 `--plate`**（原设计“不随主题翻转”）。本改动**有意推翻该决定**：代码块随明暗主题、且“克制单色”。

**做法（不换 hljs 主题文件、不加第二套高亮）**：靠高特异性覆盖压过 github-dark 的 `.hljs-*{}`（其特异性 0,1,0，被 `.a-body pre code .hljs-*` 的 0,2,2 击败）。

**① 在 `style.css` 的 [2] token 定义区**（raw hex 只允许出现在此区）新增变量：

```css
/* :root 浅色段 */
--code-bg:#f6f8fa; --code-fg:#24292f; --code-com:#6a737d;
--code-key:#0b6e4f; --code-str:#0a5c46; --code-num:#8a4b00;
```
```css
/* html[data-theme="dark"] 段 */
--code-bg:#161b22; --code-fg:#c9d1d9; --code-com:#8b949e;
--code-key:#7ee787; --code-str:#a5d6ff; --code-num:#f2cc60;
```

**② 在 `.a-body` 样式区**改代码块底色并做克制单色：

```css
/* 底色随主题（取代固定暗色 --plate；--plate 仍留给其它消费者） */
.a-body pre{ background:var(--code-bg); border:1px solid var(--c-line);
  border-radius:var(--rd-card); padding:16px 18px; margin:16px 0; overflow-x:auto; }
.a-body pre code{ background:none; border:none; color:var(--code-fg);
  font-family:Consolas,monospace; font-size:13px; line-height:1.75; }
.a-body pre code.hljs{ background:transparent; padding:0; }

/* 克制单色：先把所有 hljs token 归位到继承前景，再只给 4 类上色 */
.a-body pre code span{ color:inherit; font-style:normal; font-weight:inherit; }
.a-body pre code .hljs-comment,
.a-body pre code .hljs-quote,
.a-body pre code .hljs-doctag{ color:var(--code-com); font-style:italic; }
.a-body pre code .hljs-keyword,
.a-body pre code .hljs-built_in,
.a-body pre code .hljs-literal,
.a-body pre code .hljs-type,
.a-body pre code .hljs-symbol,
.a-body pre code .hljs-params{ color:var(--code-key); font-weight:600; }
.a-body pre code .hljs-string,
.a-body pre code .hljs-regexp,
.a-body pre code .hljs-char\\.escape{ color:var(--code-str); }
.a-body pre code .hljs-number,
.a-body pre code .hljs-boolean{ color:var(--code-num); }
```

**为什么这样对**：`.a-body pre code span`（0,1,3）压过 github-dark 的 `.hljs-attr`/`.hljs-tag` 等（0,1,0）→ 其余 token 一律继承 `--code-fg`，不花；四类 `.hljs-*`（0,2,2）再单独上色。变量走主题，`data-theme` 一切换整套底色与 token 色随之翻转。

**验证**：明、暗两主题各看一段含 注释/字符串/关键字/数字/属性 的代码，确认浅底可读、暗底可读、只有 4 类着色、无 github-dark 残留色。
