## ⑤ 踩过的坑（绝对不要再踩）

1. **给派生缓存加"版本章"时，最大的风险是把用户已有的一次成功变成两次。** 所以迁移判据
   （`stamp_legacy`）和"相符就免嵌"的集成用例必须先写，并且要用真库跑一遍确认
   `changed=0`。没有这一步，"可续跑"就成了一次强制重跑。
2. **同一规则两份实现会让度量失明。** 原来的 `meta.code_version` 全局闸门与新的逐篇 `embed_ver`
   表达的是同一件事；留着任何一个，拆掉另一个都不会红。做法：删掉旧闸门，并加一条
   "改 meta.code_version 不触发任何重嵌"的**反向断言**来证明它真的不再是判据。
3. **度量工具的退出码分类要按"这套怎么报红"来定。** 我把「跑不出汇总行」一律当"运行异常"，
   而裸 assert 套件（`test_rag`）红的时候**就是** traceback + 非零退出，于是 3 个真杀掉的变异体
   被记成异常 —— 和轮次 49 那次（把没跑读成存活）方向相反，同一个 `if 汇总行 in out` 的两种错法。
   分类顺序应是：有汇总行看 rc → 没汇总行但有 `AssertionError`/`FAIL` 就是具名红 → 两者皆无才是异常（§6 第 98 行）。
4. **写 SQL 探针别漏 `FROM`。** 我查真库盖章数时写了 `SELECT COUNT(*), SUM(embed_ver=?)` 没接
   `FROM files`，SQLite 报 `no such column: embed_ver`，一眼看去像"库没迁移成功"，实际是我的探针漏了表名。
   读回数字前先确认查询本身合法（同一轮里 `PRAGMA table_info` 已经证明列在）。
5. **改判定逻辑时先把判定从 IO 里剥出来。** `plan_sync` 是纯函数，所以 16 条真值表断言在 CI 上
   不需要 numpy/sqlite-vec/模型也能真跑；集成用例（要 sqlite-vec）随 `test_rag` 既有 SKIP 口径走。
6. 延续上一轮的教训：**中文串里不嵌 ASCII 双引号**、**文本手术用独立 .py 文件 + 锚点 count==1**、
   **测试输出与度量脚本都要 GBK 安全**、**GBK 档与 UTF-8 档各跑一遍**（本轮 test_predicates/test_rag 两档都跑）。
