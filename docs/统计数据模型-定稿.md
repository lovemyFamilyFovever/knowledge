# 月度阅读统计数据模型 —— 设计定稿

> 状态：**定稿（v1，2026-09-08）** · 依据：AGENTS.md 不变量 6「frontmatter 不存运行时数据」
> 实现位置：`app/reading.py`（新增，独立于语料层）+ `/api/track` 端点 + `/stats` 月度页

## 一、为什么这样设计

| 备选方案 | 结论 | 理由 |
|---|---|---|
| 写进 frontmatter（`read_at` 等字段） | **否决** | 违反「frontmatter 只存身世元数据」约束；每次阅读都改写语料文件 → git diff 被统计噪声淹没 → 「写完即 commit」纪律报废；Obsidian 侧会看到频繁无意义变更 |
| 存 SQLite 单表（本地库） | **采用** | 高频追加写入、按月聚合查询都是 SQLite 主场；与语料完全隔离，删库不影响真相 |
| 单独 JSON 日志文件 | 否决 | 无索引，聚合要全量扫描；并发写有截断风险 |

## 二、数据模型（v1）

库位置：`indexes/reading.db`（**派生数据**——丢了只丢统计，语料无损；但有意不给自动重建，统计是只增日志）。

```sql
CREATE TABLE IF NOT EXISTS reading_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    path TEXT NOT NULL,          -- content/ 相对 posix 路径（语料身份键）
    title TEXT,                  -- 冗余存标题（文档可能后改/删除，报表仍可读）
    event TEXT NOT NULL,         -- 'open' | 'read_minute' | 'finish'
    seconds INTEGER DEFAULT 0,   -- read_minute 事件的增量阅读秒数
    ts REAL NOT NULL,            -- 事件时间戳（unix）
    ym TEXT NOT NULL,            -- 冗余月份键 'YYYY-MM'（聚合索引用）
    day TEXT NOT NULL            -- 冗余日期键 'YYYY-MM-DD'
);
CREATE INDEX IF NOT EXISTS idx_events_ym ON reading_events(ym);
CREATE INDEX IF NOT EXISTS idx_events_path ON reading_events(path);
```

**事件语义（v1 只收三种，克制）**：
- `open`：文档打开（前端 `openDoc` 成功后发一次；同文档 10 分钟内去重）
- `read_minute`：前端每 60 秒心跳，页面可见且停留在该文档才发；`seconds=60`
- `finish`：阅读时长 ≥ 文档字数/400 分钟（中文阅读速 400 字/分）或手动标记完成

**口径定义（报表用）**：
- 阅读时长 = Σ read_minute.seconds（finish 不计秒）
- 已读 = 当月有 open 事件
- 月度行 = 按文档聚合：打开次数 / 累计分钟 / 字数快照
- 月度 KPI：活跃天数（有事件的天数）、总时长、新开文档数、完成数

## 三、隐私与边界

- 全部本地，无上报。`indexes/` 已 gitignore，统计不入库。
- 统计不是事实源：文档删除后 events 保留（title 冗余可读），报表标注「已删除」。
- v1 不做：阅读进度百分比、断点续读位置、热力图——先让月度报表跑起来，避免过度设计。

## 四、API 与页面

- `POST /api/track`：`{path, event, seconds?}`；服务端补 title/ts/ym/day；10 分钟内同文档 open 去重。
- `GET /stats?ym=YYYY-MM`：月度报表页（默认当月）：KPI 行 + 文档榜（时长降序 Top 50）+ 每日分布条形（纯 CSS）。
- 前端埋点：`openDoc()` 成功后 `track('open')`；`setInterval` 60s 心跳（`document.visibilityState==='visible'` 才发）。
