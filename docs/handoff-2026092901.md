## ⑤ 踩过的坑（绝对不要再踩）

1. **诊断工具的一句模糊文案，比没有文案更糟。** `HTTP 0 读不到 run 列表` 三种成因共用一句
   （代理不通 / 被限流 / 真没 run），下一个人会去查错的方向。规则：把「读不到」按成因**分退出码**，
   且各成因的关键词**互不出现在对方的输出里**（这套的四条互斥断言就是钉这个的）。
2. **凡是「A 不通就走 B」的降级，必须有一条"没降级时不许打降级标记"的护栏。** 否则标记是恒真的废话，
   判据看着绿其实什么都没咬（本套 B2 专干这件事）。
3. **判据的 oracle 别用被测对象自己印的字。** 本套的"降级真发生过"是拿**桩记下的请求次数**（列表/jobs/annotations
   各一趟 = 3）证的；代理那一趟到不了 API，所以计数不会因为文案好看而虚报。
4. **失败路径上的元组 arity 会崩在第一步。** `get()` 的"两条都不通"分支少回一个元素，主循环四元组解包
   → `ValueError`。A/B/C/D 四组全走成功分支，只有新加的 E 组到过它。多返回值函数每条 return 都要同形。
5. **「半红」先分清是哪一种，再动手。** 变异体「不点名够不着」第一轮期望 E1+E2 红、实际只红 E2 ——
   改坏后仍落到 `st != 200` 那条，退出码仍是 4，E1 断的就是码，**它不该红**。是我名单写错，不是判据失职。
   同族教训（三种存活成因）见跨会话记忆 `mutation-survivor-check-corpus-shape`。
6. **在中文串里嵌 ASCII 双引号会把 Python 字符串切断。** 本轮又踩第三次（`check("A2 输出点名"已改直连"")` →
   SyntaxError，且 `Write` 之后的字符串替换会静默吃掉字符）。规则：正文里的引用一律用「」，
   改文档/脚本用**独立的 .py 文件**而不是 heredoc，锚点 count 必须 == 1 才落笔。
7. **`indexes/rag.db` 的 `meta` 表列名是 `k`/`v`**，不是 `key`/`value`；`vec_docs` 是 sqlite-vec 虚表，
   **不带扩展的连接查它会 `no such module: vec0`** —— 那不是你库里没向量，数向量要看 `vec_docs_rowids`。

8. **终端绿 ≠ 钩子里绿：控制台编码要把两档都跑过才算验过。** 本套第一次进 pre-commit 就红了：
   钩子那侧没有 `PYTHONIOENCODING`，被测脚本往管道里打印中文时按 locale（cp936）编码，
   而测试按 utf-8 解码 —— 「已改直连」这类中文标记全成替换符，5 条断言假红；紧接着一条 FAIL
   的详情被 print 到 GBK 控制台，`UnicodeEncodeError` 把**套件自己**崩掉，门禁只看到 rc=1。
   做法：给被测子进程显式钉 `PYTHONIOENCODING=utf-8`，测试自己的 stdout 走 `errors=replace`
   （与 `tests/_ci.py::_safe`、`check_ledger_counts.py` 同口径），**并且两档各跑一遍**；
   对照组要写进去（H3：不兜底的 strict GBK 打印确实会炸），否则那条护栏是空转。
9. **度量脚本「先报名、后还原」= 会把目标留在变异态。** 自变异第一版打印结论那句被 GBK 崩了，
   `TARGET.write_bytes(ORIG)` 没执行，`tests/test_watch_ci.py` 就停在「摘掉编码钉」的变异态退出；
   下一趟控制组读出 5 条红，看着像「套件不稳定」，实际是我上一趟没还原。
   做法：破坏性写入之后立刻 `try/finally` 还原 + assert 字节一致，**还原完了再 print 结论**；
   并且每次变异跑完做一次物证复核（grep 三处锚点还在不在），别只信脚本自己说的「已还原」。
