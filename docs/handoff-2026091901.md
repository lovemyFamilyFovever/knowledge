## ⑤ 踩过的坑（绝对不要再踩）

1. **`tests/test_learn.py` 硬编码了 KMP 卡内容** —— `tests/test_learn.py:57/59/61` 断言 `baike/algorithms/KMP 算法.md` 的 term == "KMP 算法"、front 模板、def back 含子串「字符串匹配算法」。分片3 重写时把定义改成「单模式串匹配算法」→ 全库 pre-commit 恒红，**并连带阻塞了分片4 的 testing/tools 提交**（滞留工作区数小时）。**改任何 baike 语料前先 `grep -rn "<文件名或关键词>" tests/`**，看有没有测试把它当契约。
2. **check_rewrite 的 ⑦ frontmatter 比对对已提交文件是空转** —— 它比工作区 vs `git show HEAD:<file>`；分片按子域提交后 HEAD 就是重写稿，恒等通过。要真验"批量阶段禁改 frontmatter"，收尾必须与**批前基线 commit** 比（本轮 `67ada4e`）。
3. **check_rewrite 的 ⑧ 双链 warning 会误报，分片自报的"双链均解析"也不可信** —— ⑧ 用朴素正则 `\[\[([^\]|#]+)`，代码围栏里的 bash 条件 `[[ -f "$file" ]]` 会被记为悬空双链；反过来，分片1 在 status 里写「原链均解析」，实际 `[[Agent 与数据库交互]]` 的目标早在 2026-09-12 就软删进了 `content/_trash/`。**权威口径只有一个**：`python scripts/build_index.py` 后查 `index.db` 的 `links` 表 `resolved=0`（`app/fts.py::extract_wikilinks` 已剔除围栏与行内代码）。
4. **公共 ledger 并发写会互相扫入在途行** —— `split-candidates.md` / `sN.md` 被多片共享时，`git commit -- <file>` 会把别片尚未提交的行一起带走（分片3 三次提交均遇到）。Mission 后期已改成"split 写各片自己的 status"，二期务必沿用，**不要用共享账本**。
5. **status 台账会漏行、会重复行，不能当事实源** —— s3 漏登 `database/读写分离.md`（文件其实已重写、已提交、PASS），同时把 `middleware/Kafka深入.md` 登了两行；结果分片回传的计数（14 done）反而是对的、台账是错的。**核账要用集合差集**：`语料清单 − 试点` vs `status 登记`，双向查缺 + 查重复。
6. **Windows 控制台是 GBK，批量脚本输出会 mojibake 到看错文件名** —— 我第一遍把 `Kafka深入` 读成 `Kafka核心`、把 `Shell脚本编程` 读成 `Shell脚本详解`，差点误判问题归属。**一律 `PYTHONIOENCODING=utf-8` 跑 Python，git 路径一律 `-c core.quotepath=false`**。
7. **文件名含空格 + 中文时别用 bash 通配/`$(cat list)` 传参** —— `check_cards.py $(cat sample.txt)` 在空格处断词，`AI Agent 开发最佳实践.md` 被截成 `...\AI` 直接 FileNotFoundError。**改用 Python `subprocess.run([sys.executable, script, *paths])` 传 list**。
8. **规范歧义各片自决必然漂** —— 同一类"术语汇编"在 s1 判枢纽重写、在 s3 判拆分，理由都是自洽的，但口径不一致。二期开工前判据必须先成文（§3 表）。
9. **多会话并发时 `index.lock` / pre-commit 指向片外文件的失败 = 别片在途写入**，等 60s 重试即可；**绝不用 `git reset/checkout/restore` 去"清理"别人的 WIP**。本轮分片2 与分片4 都正确照此处理，无一例误伤。

## 关键约定（本轮生效，二期沿用）

- 每子域做完提交一次；**显式 pathspec**，禁 `git add -A` / `git add .`；禁 `--no-verify`；禁 `reset` / `checkout` / `restore`；禁 push。

- 一次一篇：读完 → 写盘 → 验收 → 再读下一篇（避免上下文串味与半写状态）。
