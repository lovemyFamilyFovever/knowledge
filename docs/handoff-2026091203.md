## ⑤ 踩过的坑（绝对不要再踩）

1. **Windows `Path.write_text` 把 `\n` 转 `\r\n`；对已含 `\r\n` 的文本再写会产出 `\r\r\n`**。
   任何「字节保真」写回必须 `read_bytes`/`write_bytes`（本轮 store.py 行级手术即此法）。
2. **静态推断定级前必须探针实测**。本轮据此推翻了自己的 CRLF 破坏后端解析的假设
   （Python 文本模式 universal-newlines 会归一，真正受害面是 BOM 与写回侧），也坐实了
   sidecar/嵌套 `_` 目录泄漏。报告里「实测/静态」证据等级不是装饰。
3. **回归探针文件别放进会被索引的域目录**：把测试文档建到 `content/handbook/` 会改变树序、
   打翻三条依赖树序的既有断言；放 `_` 前缀目录（不进树）即可。测试自建的临时文件用完即清，
   并且注意它会污染后续断言（test_reader 的 B6 断言清空 A.md 后必须恢复原文）。
4. **本仓库有并行会话同时改代码**（交互重构阶段 0-3、content 批量重写都是另一会话提交的）。
   动手前 `git log`/`git status` 看现场；报告里的行号会漂移，**定位用 grep 锚点不用行号**；
   只 stage 自己碰过的文件（`git add <paths>`，禁 `-A`）。
5. `git diff/status` 输出被 `head` 截断会误判「我的改动不见了」——用内容 grep（如
   `grep -n set_fm_scalar app/store.py`）而非截断式 diff 做存在性确认。
6. 编辑既有测试大文件时插断言要看清**上下文变量复用**：往 `j = r.get_json()` 序列中间插请求
   会把后续断言的响应对象换掉（本轮真实发生并返工一次）。
