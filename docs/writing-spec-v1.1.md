## 1. 枢纽重写 vs 拆分的判据（修订 v1.0 §6）

v1.0 §6 只给了拆分的正面条件（"压到 2200 会毁掉面试必需信息 且 ≥3 个独立子概念"），没说同类"术语汇编"何时该收敛成枢纽。一期因此出现同类语料各片各判：s1 把 `AI 应用详解`、`Prompt 工程与 Agent 详解` 判枢纽重写，s3 把 `数据库内核原理深度解析`、`搜索引擎技术详解` 判拆分——两边理由都自洽，口径不一致。

**定案判据（成文）**：看子概念在 `content/baike/` 下**是否已有专条可双链**。

| 情形 | 处理 |
|---|---|
| 子概念**已有专条**（或本批已产出专条） | **枢纽重写**：保留为索引页，正文压到 ≤2200（满足 §4 信号①②可豁免至 ≤3400）；「核心机制」节改写为**子词条索引表 + 关系图**，逐子概念的深度内容删掉、改由双链指向专条 |
| 子概念**无专条，且各自需 ≥300 字才能讲清** | **拆分**：不重写、不新建，登记 `docs/refactor/split-candidates.md`，二期串行拆 |
| 子概念无专条，但每个 100–300 字即可讲清 | 普通重写：作为单篇的并列子概念写进「核心机制」，不必拆 |

**机器辅助（登记纪律）**：拆分候选登记时**必须列出"拟拆出的子概念名"**（写在 `split-candidates.md` 的 `子概念预览` 列，逗号分隔）。收尾会话据此校验是否已存在专条：

```sh
grep -rl "title: \"<子概念名>\"" content/baike/
```

命中即为"已有专条"，该子概念二期**不新建文件**，改为在父文档里双链指向已有专条（去重规则见 `split-candidates.md` 顶部的「重叠去重队列」）。

## 2. 折叠式枢纽的豁免信号②（修订 v1.0 §4 与 §8-⑥）

v1.0 §4 的信号② 是"覆盖 ≥3 个具名子概念（H2/H3 或编号粗体领起，各带 ≥100 字叙述）"。多定义汇编收敛成枢纽时，子概念通常写进「核心机制」的**项目符号**里而不是独立 H3，`subconcept_count` 数不到 → 拿不到 3400 豁免 → 被迫压到 2200（一期 `ESB 与服务网格` 即因此压到 2198 字，牺牲了 xDS/治理细节）。

**定案**：信号② 改为**两条 OR**，满足任一即可：

- **②a（原判定，不变）**：≥3 个 H2/H3 或编号粗体领起的具名子概念，各带 ≥100 字叙述；
- **②b（新增，折叠式枢纽）**：**「核心机制」节内**（含 §3 变体名：核心机制/核心流程/做法/计算逻辑/核心能力）含 ≥3 个由 `- **<子概念名>**：`、`- **<子概念名>：**` 或 `N. **<子概念名>**：` 领起的列表项，且**每项自身叙述 ≥70 字**（代码常量 `check_rewrite.BOLD_ITEM_MIN`）。

②b 的计数口径：只数核心机制节内的粗体领起项；每项的叙述长度取"本项起、到下一个粗体领起项或本节结束"之间的文字，**不含表格行与代码围栏**（避免靠塞表格凑豁免）。

**阈值为什么是 70 而不是 ②a 的 100**（2026-09-19 定案）：折叠式枢纽的每个子概念本就写得紧凑，实测 motivating case `ESB 与服务网格` 的四项叙述为 **107 / 91 / 75 / 46** 字——沿用 100 只有 1 项达标，正主反而拿不到豁免，规则失去意义。全库 319 篇 done 的敏感度：阈值 100 → 8 篇满足 ②b，80 → 15 篇，**70 → 21 篇**，60 → 38 篇。取 70 既让 ESB 这类（3 项达标）过，又不至于松到让普通词条轻易拿到 3400 额度。②a 的 100 字口径不变。

信号①（≥1 个 ≥4 数据行的对比表 或 ≥1 个 mermaid）与理由登记③不变。

## 3. 过薄叶必须充实（修订 v1.0 §4）

v1.0 §4 写"普通词条目标 500–1200"，一期出现 285–370 字的极薄叶（`Rust基础`、`TS深入`、`性能测试`、`TDD`、`混沌工程`），执行者不确定能否增补，分片4 自行充实到 1100–1400 字并回报请裁。

**定案**：**500 字是目标密度下限，不是硬性截断；过薄必须充实，且允许且鼓励增补。**

- 原稿 <500 字 → 执行者**必须**按 §2 骨架补全缺失节（尤其「为什么需要它」「具体示例」「常见误区」「与相关概念的区别」），落到 **500–1200 字**区间。
- 允许基于**通用工程常识**补全标准骨架内容；**禁止注水**（同义反复、把一句话拆成三句、堆形容词）。
- 增补的事实性内容仍受 §5 约束：不得编造作者/年份/量级数字/基准分数；拿不准的具体数字宁可不写。
- 上限不变：普通 ≤2200，枢纽 ≤3400。

## 4. 有限事实订正权（修订 v1.0 §5）

v1.0 §5 只要求"保留原稿可核验引用、禁编造"，没说原稿本身写错了怎么办。一期两例：分片1 把 `语音AI技术` 里自相矛盾的 Whisper large-v3「1.55M」改为 1.55B（同文又称其"最大/最慢"）；分片4 把 `云服务详解` 的「ECS 是 AWS 托管容器服务」订正为 EKS。

**定案：执行者有有限订正权，但必须留痕。**

| 情形 | 处理 |
|---|---|
| 原稿**自相矛盾**（同一文内两处互斥），或**公认事实错误**（可被官方文档一句话否证） | 可订正，取内部自洽/公认正确值；**必须**在 status 台账该行备注 `fact-fix: <原值>→<新值>` |
| 无法确认孰是孰非（版本差异、口径不同、来源冲突） | **保留原文**，备注 `fact-uncertain`，不猜、不改 |
| 只是"过时"而非"错"（如某库最新版本号） | 不改数字，改为不绑定版本的表述或标注时间点 |

`fact-fix:` 行是收尾抽样审计的入口：收尾会话按此清单复核订正是否站得住。未登记 `fact-fix:` 的事实改动视为越权。

## 5. 第三类处理：`exempt-reference`（修订 v1.0 §6 的二分法）

v1.0 §6 只有"重写"与"拆分"两条路。一期 `Linux 命令速查手册` 被判 split，但它本质是**参考手册**而非词条——拆开也没有"一句话定义"可抽卡，硬套骨架只会造出低质词条。

**定案：设立第三类 `exempt-reference`（豁免重写）。**

- **判据**：文档本质是"命令速查 / API 参考 / 配置清单 / 参数表"，特征为**全文 >70% 是代码块、表格或参数列表**，且没有叙事性的「为什么需要它」可写。
- **处理**：**不重写、不拆分、文件原样保留**；在 `docs/refactor/status/sN.md` 登记状态 `exempt-reference`，并把路径追加到 `docs/refactor/exempt-reference.md`（一行一路径，机器门据此跳过检查）。
- **不改 frontmatter**（v1.0 §6 明令批量阶段 frontmatter 逐字不动，加 tag 的路子被否）。
- **抽卡影响**：无需特殊处理。`app/cards.py` 对没有 `## 定义` / `**一句话定义：**` / `## 常见误区` 锚点的文档本就抽不出 def/trap 卡，属**自然过滤**——参考手册不进复习系统正是期望行为。
- **机器门**：`check_rewrite.py` 对 exempt 清单内的路径**直接 PASS 并跳过全部检查**，输出 `EXEMPT`（见 §9）。
- **收尾**：单独列 exempt 清单，与 done/split/failed 并列计数；exempt 篇不计入 done。

## 6. 误区段强制纯错误陈述（明确 v1.0 §1）

v1.0 §1 已写"误区列表项写'错误陈述'本身（卡面自动加'判断正误：'），不写纠正后话"，但一期原稿大量是 `X≠Y：解释` 这种**纠正式**陈述，各片改写口径不一，有片还担心"把定义性内容上移算不算结构越界"。

**定案**：

- **强制纯错误陈述**。原稿的 `X≠Y：解释` 必须改写成错误断言本身，如「X 就是 Y」「X 和 Y 没有区别」「只要 X 就不需要 Y」。卡面由 parser 自动加「判断正误：」，卡背自动接「✗ 这是常见误区。正解：{一句话定义}」。
- 定义性/解释性内容**上移到「核心机制」或「与相关概念的区别」是合规的结构调整**，不算越界，无需报备。
- 条数与排序不变：2–3 条，最有价值的两条必须在前两位（只有前 2 条进闪卡）。
- 禁止把误区写成疑问句、禁止写成"注意/提醒"式建议——那样卡面读不通。

## 7. 正文标点全角化（补充 v1.0 §6）

v1.0 §6 只禁弯引号，没管半角标点。一期原稿多用 ASCII 半角逗号/句号/括号与「」，分片3 自行统一转全角并回报请裁。

**定案：不强制，但推荐。**

- 中文正文内的 ASCII 半角逗号、句号、分号、冒号、括号，**可**统一转全角以提升阅读一致性；`「」` 可转 `""`（直引号）。
- **严禁改动的三处**：① 代码围栏内的任何字符；② frontmatter 内的任何字符；③ 双链 `[[...]]` 内的任何字符（改了会断链）。
- 英文术语内部的标点不动（`C++`、`TCP/IP`、`Node.js`、`0.05%`、`arXiv:1706.03762`）。
- **回退规则**：若转换导致 `check_rewrite.py` 的 ⑤（arXiv/DOI 保留）或 ⑧（双链可解析）报错/报警，**回退该行的标点转换**，以通过机器门为准。

## 8. status 台账登记口径（修订 v1.0 §4-③ 与 §7）

一期五片台账格式各不相同（路径前缀三种、备注列写满自由文本、有片写了"具枢纽信号但未触发豁免"这类模糊标注），收尾核账要靠集合差集才抓出漏登与重复行。

**定案：台账定式五列，逐篇一行，不许漏不许重。**

```
| 路径 | 状态 | 字数 | 围栏 | 备注 |
```

- **路径**：统一 `content/baike/<子域>/<文件名>.md`（仓库根相对、正斜杠）。不再用 `子域/xxx.md` 或 `baike/子域/xxx.md`。
- **状态**：`done` / `split` / `failed` / `exempt-reference` / `pending` / `doing` 六值之一。
- **字数 / 围栏**：取 `check_rewrite.py` 输出的实际值（如 `1832/2200`、`1块7行`）；split 与 exempt 篇填原稿实测值。
- **备注列只允许以下五种前缀**，无则填 `-`：
  1. `hub: <理由>` —— 触发 3400 豁免时**必填**；
  2. `fact-fix: <原值>→<新值>` —— 见 §4；
  3. `fact-uncertain` —— 见 §4；
  4. `exempt-reference` —— 见 §5；
  5. `merged-into: <目标文件>` —— 二期去重合并时填（见 `split-candidates.md` 重叠去重队列）。
- **禁止**写"具枢纽信号但未触发豁免""接近上限"这类模糊标注：**要么满足信号①②拿到豁免并写 `hub:`，要么就是普通篇**，不存在中间态。
- **登记纪律**：每处理完一篇立即追加一行；**一个文件只准一行**（一期 `middleware/Kafka深入.md` 登了两行、`database/读写分离.md` 漏登，都是收尾才发现）。
- **账本归属**：逐篇状态只写**本片自己的** `docs/refactor/status/sN.md`；跨片共享的 `docs/refactor/split-candidates.md` 只做拆分候选汇总，并发期由收尾会话统一归一，分片不直接改（`git commit -- <共享文件>` 会把别片在途行一并带走）。

## 9. 机器门变更清单（`scripts/agent/check_rewrite.py`）

| v1.0 §8 检查项 | v1.1 变更 |
|---|---|
| ⑥ 篇幅预算的枢纽信号② | 增加 ②b：核心机制节内 ≥3 个粗体领起列表项、各带 ≥100 字叙述（不含表格行与围栏）；②a 与 ②b 满足其一即算信号② 成立 |
| 新增：exempt 跳过 | `--exempt <path>...` 显式豁免；或自动读取 `docs/refactor/exempt-reference.md`（一行一路径，`#` 开头为注释，文件不存在则视为空清单）。命中者输出 `EXEMPT`、跳过全部检查、计入 PASS |
| ①②③④⑤⑦⑧ | 不变 |

**收尾复检的两条补充口径**（一期实测出的验收器盲区，写进规范以免重犯）：

- ⑦ 的 frontmatter 比对是"工作区 vs `HEAD`"，分片提交后 HEAD 已是新稿，**该项对已提交文件恒等通过**。批量收尾必须另做"**与批前基线 commit 逐篇比对**"（一期基线 `67ada4e`）。
- ⑧ 的悬空双链是朴素正则，会把代码围栏里的 bash 条件 `[[ -f "$x" ]]` 误报为悬空双链；**权威口径是 `indexes/index.db` 的 `links` 表 `resolved=0`**（`app/fts.py::extract_wikilinks` 已剔除围栏与行内代码），先 `python scripts/build_index.py` 再查。
