# 标签治理与重命名工具 — 解决方案说明

> 2026-09-08 · 对应 BACKLOG「标签合并/重命名工具（taxonomy 治理闭环）」· 供复核

## 一、交付了什么

| 文件 | 角色 |
|---|---|
| `app/store.py`（新增原语段） | 语料层：`tag_census`（普查）、`find_similar_tags`（疑似重叠检测）、`merge_tag`（合并）、`rename_sub`（子域重命名）、`rename_doc`/`sidecars_of`（单文档搬移原语） |
| `scripts/govern_tags.py` | 命令行入口：census / similar / merge / rename-sub 四个子命令 |
| `/api/tag/merge` | HTTP 端点：标签管理页「并入…」按钮的后端（apply=false 预览 / true 执行） |
| `tests/test_govern.py` | 3 组断言：普查+降噪、合并 dry-run→apply、统计事件与聚合 |
| `docs/标签普查-2026-09-08.txt` | 当日全库 56 个标签的普查存档 |

## 二、关键设计决策（复核重点）

1. **一切变更默认 dry-run**：`merge_tag`/`rename_sub` 不传 `apply=True` 只返回计划/预览，不碰文件。CLI 与页面按钮都是「先预览 → 确认 → 再执行」两段式。
2. **合并的大小写语义**：匹配大小写不敏感（`AI` 与 `ai` 互相命中），写入统一为目标标签写法并去重。普查（census）则保留原写法键——普查如实反映现状，合并才做归一。
3. **降噪规则**（`find_similar_tags`，第一版误报过多被推翻重写）：
   - 大小写差异 → 置信 1.0（必报）
   - 包含关系 → 0.9（短词含 ASCII，如 AI/AI资产）；纯中文包含对降为 0.7
   - 编辑距离 → 只对 ASCII 词、阈值 ≤1（Vue2/Vue3）；**中文词不比编辑距离**（中文双字词距离普遍 ≤2，第一版把「源码/算法」全配成了对）
   - 实测：118 个标签降噪后仅 3 对候选，其中 AI/AI资产 为真重叠，Vue2/Vue3、DOM/BOM 属正常并存
4. **`rename_sub` 级联范围**：目录内全部文档 + 旁挂（.notes.md/.html）+ `content/_meta/taxonomy.json` 的 scoped 键（`域/旧子域 → 域/新子域`）。**FTS 由调用方重建**（build_index 全量 <1s）；向量索引靠 mtime 扫描自动把新路径当新增、旧路径当删除对齐——这是一致性设计里最弱的一环，见「已知限制」。
5. **不动语料正文**：所有操作只改 frontmatter 的 tags 键或文件路径，正文零改动，git diff 干净。

## 三、如何使用（复核路径）

```sh

# 或在应用内：标签管理页 → 任意标签行「并入…」按钮 → 预览确认框 → 执行
```

## 四、已知限制（如实）

- `rename_sub` 后向量索引的对齐依赖后台 30 秒扫描；窗口期内语义搜索可能同时报新路径（新块）与旧路径（残留块）。CLI 已在 apply 后主动重建 FTS，向量侧留给 watcher 是有意取舍（避免每次 rename 全量重嵌 1.5 万块）。
- 「AI→AI资产」这类合并我**没有擅自执行**——涉及 9 篇文档的写盘，按约定留给你复核后决定（预览命令已验证可用）。
- census/similar 每次全库扫 frontmatter，515 篇 ~1s；语料到 5000 篇后如需常驻可加缓存。
