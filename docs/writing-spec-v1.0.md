# 知识库 baike 写作规范 v1.0
生效 2026-09-19。适用：content/baike/ 原地重写。抽卡契约对齐 app/cards.py v3。

## 0. 三目标（冲突时按序取舍）
1. 可复习：必出卡（1 def + 2 trap），锚点精确。
2. 面试可讲：30 秒抓住、1 分钟讲完、扛住一层追问。
3. 可读可归档：叙述完整、出处可溯、语料与 frontmatter 零污染。

## 1. 硬锚点（抽卡契约，缺一 FAIL）
- `## 定义` H2 精确；其内 `**一句话定义：** 值` 同行、≥8 字、不换行，值内无列表/表格/围栏。
- `**通俗类比：** 值` 同行（进卡 hint）。
- `## 常见误区` H2 精确；下挂 2–3 条 `- ` 单行列表（≥4 字），按易错程度排序；**仅前 2 条进闪卡**，第 3 条是正文补充——最有价值的两条必须放前两位。批量完成后评估将 trap 上限提至 3（parser +1 版本，card_id 不变）。
- `## 相关术语` H2 精确；原双链全保留，新增只指向已存在词条。
- 误区列表项写"错误陈述"本身（卡面自动加"判断正误："），不写纠正后话。

## 2. 骨架（节序固定）
定义 / 为什么需要它 / 核心机制 / 具体示例 / 何时用与何时不用 / 优劣与代价 / 与相关概念的区别 / 常见误区 / 面试速答 / 相关术语 / 参考资料(可选)
- 面试速答 = `> 🎯 ` 速答段(30–60字) + 2–3 行 `> 🔍 追问：…`。
- 大节一律 `##`；列表内不嵌套更深标题。
- 「与相关概念的区别」最少形态 = ≥1 个具名相邻概念 + 一句边界，表格可选——给批量期一条低成本合规路径，防凑数式对比。

## 3. 类型变体（仅"核心机制"节名与呈现方式可变）
- 机制/算法 → 核心机制|核心流程：叙述+步骤/mermaid/表格；控制流可用 ≤15 行伪代码。
- 实践/方法论 → 做法：角色/时机/流程/输出物；原则零代码。
- 指标 → 计算逻辑：公式文字化+数值例子+阈值。
- 框架/工具 → 核心能力：定位/能力清单/选型对比。
- 枢纽/总览 → 核心机制：关系图+子文档索引；枢纽自身仍按 §1 出卡。

## 4. 篇幅与代码预算（机械检查）
- 计数字径：正文字数（去空白）= 全文 − frontmatter − `> 📌` 导航行 − `## 相关术语` 整节 − `## 参考资料` 整节。预算管叙述密度；出处与双链不占预算。
- 上限两档：普通词条 ≤2200；枢纽型 ≤3400。
- 枢纽型判定（机械，须同时满足）：
  ① 含 ≥1 个 ≥4 数据行的对比表 或 ≥1 个 mermaid 图；
  ② 覆盖 ≥3 个具名子概念（H2/H3 或编号粗体领起，各带 ≥100 字叙述）；
  ③ 执行者登记一行理由：批量期写本分片 status 行（`path | done | hub: 理由`），单会话期写进当次 commit 消息。
- 普通词条目标 500–1200。
- 代码围栏 ≤2 块且合计 ≤20 行；伪代码优先；真实代码仅限"API/配置本身即知识"；每块围栏前后须有一句散文解释它演示什么。
- 禁 `<details>` 自测块（自测未来自动出题）。

## 5. 信息保留规则（重写 ≠ 信息缩减）
- 原稿可核验引用（arXiv/DOI/官方文档 URL）必须全保留；新增引用仅限高置信经典；否则省略或标"待核验"。禁编造作者/年份/量级数字。
- 出处归属（哪篇论文/哪个团队工程实践/年份）是一等信息，必须保留。
- 每个子概念保留至少一层"追问级"细节（角色/步骤/公式/阈值）。
- 最小改动原则：原稿已合规的段落保留原文，只修不合规部分。

## 6. 语料约定
- 只用直引号；禁弯引号 “ ” ‘ ’。
- 批量阶段：frontmatter 逐字不动、不改 title、不 rename、不新建/拆分文档。
- 需拆分判定：压到 2200 字会毁掉面试必需信息 且 ≥3 个独立子概念 → 不重写，登记 docs/refactor/split-candidates.md（路径+理由）。
- UTF-8 无 BOM、LF、结尾换行。

## 7. 交付自检
每篇 `python scripts/agent/check_rewrite.py <path>` 全 PASS；连败 3 次 → 回写原文并记 failed。

## 8. check_rewrite.py 检查项（实现契约）
① def 卡==1 且 trap 卡==2；误区列表条数∈[2,3]；② 一句话定义同行且≥8字；③ 必备 H2 齐全（核心机制允许 §3 变体名）；④ 无弯引号、无 `<details>`；⑤ git HEAD 版 arXiv/DOI ⊆ 工作版；⑥ 围栏与篇幅预算（按 §4 新字径计；超 2200 时先验枢纽信号①②，通过则按 3400 判，不通过仍 FAIL；枢纽理由③为审计项，不进机器检查）；⑦ frontmatter 与 HEAD 一致；⑧ `[[双链]]` basename 在 content/ 可解析（warning 级）。非零退出=FAIL。
