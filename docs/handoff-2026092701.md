## ⑤ 踩过的坑（绝对不要再踩）

1. **`open(p,'r+b')` 成功 ≠ 可删**。Windows 删除要 DELETE 权限，对方以 READ|WRITE 共享打开时 unlink 照样
   `WinError 32`。判断"是否被占用"要么真 unlink 一次，要么用原地改名试探（本会话用它扫过全仓 1930 个文件，
   并且**先跑对照组**：临时文件被打开时改名确实被拒）。
2. **别猜占用者，拿物证**：`netstat -ano` 找 PID → `Get-CimInstance Win32_Process -Filter 'ProcessId=N'`
   取 CommandLine/CreationDate 与文件 mtime 对齐。上一轮我把 index.db 重建归因给"用户的 5001"，
   真凶是另一会话遗留的 42171 临时实例（`create_app(); a.run(port=42171)`，跑了 31 小时，还锁着日志）。
3. **终态扫描必须排在所有验证之后**：任何一次 `git commit` 都会让钩子重新长出 `.qa/gate/*` 与 `__pycache__`，
   反过来做必然得出"没删干净"的假结论。
4. **中文文档写的第 N 次坑**：Python 源里中文串夹裸 ASCII 双引号会直接把语法打断；
   而 `「 + VAR + 」` 这种拼接符漏进字符串，产物里就留下字面量 `+ D +`（本轮全程用「」，且产物里加了断言检查）。
   另外 `git commit -m "...反引号..."` 会被 bash 做命令替换吃掉一段 —— 提交信息一律写文件后 `-F`（写到 %TEMP%，
   别落在仓库里当新临时物）。PowerShell 命令里的 `$_` 在双引号里会被 bash 展开，用单引号包整条命令。
