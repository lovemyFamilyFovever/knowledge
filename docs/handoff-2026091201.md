## 5. 踩过的坑 —— 绝对不要再踩

1. **共享索引竞态（本会话最大教训）**：与并发进程共用工作区，`git commit`（不带 pathspec）会提交**整个索引**，把它已 `git add` 的新文件一并卷入（`0dc0bd0` 误纳 12 个文件）。**铁律**：① 用 `git commit -F <msg文件> -- <显式文件路径…>` 只提交指定文件；② **核对与提交分成两条命令**（先 `git diff --cached --name-only` / `git status` 看清，再单独 commit），绝不 `git add … ; git commit` 串联。
2. **Windows PowerShell 控制台是 GBK**：git/命令的**中文输出显示为乱码**，但**文件与提交内容本身是正确 UTF-8**——别凭终端显示判断文件损坏。校验中文用 Read 工具或程序化布尔比较（如 `$title -eq $h1`）。
3. **中文 commit message**：用 Write 工具写成 UTF-8 文件再 `git commit -F 文件`；**不要**用 `git commit -m "中文"`（控制台参数编码可能破坏）。
4. **Write 工具报 `save file failed, reason: unknown` 多为假警报**：文件通常已写入成功；重试若报 `the model made no changes` 即证实内容已在，别反复折腾。
5. **中文路径经 PowerShell 管道传给 `Select-String -LiteralPath $_` 会编码损坏**（报 `Could not find file`）。列目录/查文件用 `git -c core.quotepath=false ls-files` 与 `git grep`，或用字面量数组 `@('名1','名2')` 直接 `Get-Content -LiteralPath`。
6. **单篇 > 1000 行会超 Write 上限**：用「Write 主体 + SearchReplace 续写」；对优质大稿只做**外科式 SearchReplace**（tags + 导航 + 末尾章节 + 定点纠错），不要整篇重打（省时且降低转录错误）。
7. **SearchReplace 锚点**：注意标题后**有无空行**（`\n` vs `\n\n`）——合集文档 `### 小标题` 后常**无空行**；锚点要唯一、避开歧义引号与尾随空格，否则匹配失败（多替换项中一项失败会导致该项未应用）。
8. **只提交本轮所改文件**：绝不混入并发进程未跟踪的新稿、他人长期修改的 `content/_meta/taxonomy.json`。
9. **AGENTS.md 禁区**：禁止改写 main 历史（即便误提交，也优先保留现状、除非用户明确授权）；禁止 `git push -f`；不要没跑测试就宣称完成。
10. **本会话修过的准确性硬伤（重写时逐一核对同类问题）**：Unicode≠UTF-8（是字符集非编码）；内存 MHz vs MT/s（DDR 双沿）；「南桥/北桥」已过时（并入 CPU=PCH）；CUDA 核心数跨厂商不可比；ZooKeeper 用 ZAB 非 Paxos；Hystrix 支持信号量隔离、Resilience4j 有 RateLimiter；Istio 1.5 起 Pilot/Citadel/Galley 合并为 istiod；PG 无内置 `chinese` 分词；停机问题「不可判定」≠「NP-hard」（两条不同的轴）；`RabbitMQ vs Kafka vs Pulsar` 曾 H1≠title。**H1 必须与 front matter title 逐字一致。**
