## ⑤ 踩过的坑（绝对不要再踩）

1. **批准也是会错的，尤其是被我的判据带偏的那种**。用户批"全删 121 个"是照着我说"与已归档正本逐字节重复"
   批的，而那句话是从 **50 组重复样本外推到 108 份整体**的以偏概全；动手前逐份哈希回查才发现
   58 份全库仅此一家，而 `_inbox` 被 .gitignore 排除 —— 删了连 git 历史都回不来。
   **规则：删任何 gitignore 覆盖位置里的文件前，必须把"有第二份"从我的断言变成机器的当场核对。**
2. **整目录 rmtree 是陷阱**。`indexes/scripts/tests/app` 这些顶层目录下也有 A 段文件（`__pycache__`），
   我第一版按"顶层目录名"整目录删，差点把源码目录连锅端；当场改成探针 `apply_a.py` **逐文件删 + 护栏**
   （名单里出现 `app/`、`tests/`、`static/` 等前缀且不是缓存 → 直接 exit 1）。
3. **删完的"没删干净"多半是自动长回来的**。72 个 A 段残留不是漏删，是我随后跑门禁重新生成的缓存；
   对账脚本要显式区分"没删"与"删了又长出来"，否则会把自己的验证动作误报成失败。
4. **Windows 保留设备名删不掉**：`.qa/ui-demo/mobile-ui/nul` 普通 `unlink` 报 WinError 5，
   要走 `\\?\` 扩展路径。清理这类目录时记得加这条兜底。
5. **"文件存在"与"配置生效"都不等于事实**：`echarts.min.js` 躺在 `static/` 里、还在 `check_dangling_tokens.py`
   的跳过名单中出现，看起来像在用；`stylelint.config.mjs` 写得比生效的 `.stylelintrc.json` 更严，却从没被读过
   （`.stylelintrc.json` 在发现顺序里优先）。工具链判据要用 `--print-config` / 引用反查这类**工具自己的输出**。
   台账 §6 第 51 行。
6. **删跟踪文件前先查"它里面有没有唯一未完成的事"**：`docs/BACKLOG.md` 是过期文件，但里面那条
   「_inbox 抓取对超长文的硬截断」是唯一没做完的待办，且 `writing-spec-v1.2.md` 有两处指针指向它。
