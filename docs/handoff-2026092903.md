## ② 已经完成了什么

**推送**：`b91defe..2a56aa7` 已上 GitHub main。路径细节：先试直连 `git push` → `Recv failure: Connection was reset`；
`netstat` 显示 10810 已 LISTENING → 带 `-c http.proxy/https.proxy` 一次推成。
**结论不是"直连可用"，而是"哪条通要看这一次实测"**（当晚 00:44 直连 1.16s 通、01:5x 直连被 reset）。

**CI 的真相（run #56）**：红在**第 6 步 `Install node tooling (eslint + stylelint)`**，
其后 **20 步全部 skipped**，包括 14 套 Python 测试 —— 也就是说 run #56 一条断言都没跑。
根因与本轮代码无关：`package.json` 声明 `stylelint: ^16.25.0`，而 `stylelint-config-standard@40`
的 peer 要 `^17.0.0`；本地 `node_modules` 是带冲突装出来的（`npm ls stylelint` 一直报 invalid），
所以本地钩子一切正常，**只有干净 checkout 里的 `npm ci` 会硬拒**。

**修 1（工具链）**：`stylelint` 对齐到 `^17.15.0`（config-standard 保持 40 = 官方配对），重生成 `package-lock.json`。
本机取证：`npm ci --dry-run` rc=0、`npm ls` 无 invalid、`npm run lint:css` 仍 **0 告警**、
`npm run lint:js` 0 errors（warning 115 → 116，来自 eslint 9.39.2 → 9.39.4 的补丁版解析，不致失败）。

**修 2（watch_ci 的第 ④ 类读不到）**：真跑第一次撞到的崩栈 —— 走 CONNECT 代理时旧写法把响应头指到 `-`，
curl 把隧道应答 `HTTP/1.1 200 Connection established` 一起吐进 stdout，按空行切「头部/正文」整个错位，
正文混着响应头 → JSON 解析不出来 → 主循环 `d.get("workflow_runs")` 抛 `AttributeError`，退出码 1、零句人话。
改法两条：响应头**单独落临时文件**；新增专属出口 `HTTP 200 但正文不是 JSON` = **退出 6**，
文案明写「回话被代理/网关改写，不是 CI 的结论」。jobs 那一路同样加了守卫。

**判据**：`tests/test_watch_ci.py` 31 → **38 条**。新增 I 组 6 条（专属退出码 6、文案含「不是 JSON」、
**输出里不许有 Traceback**、且不谎报另外三类）+ F4 形态断言（源码里不许再把 `-D` 指到 `-`）。
GBK 与 UTF-8 两档各 38 全绿，本机 24 秒。
定点变异 3 处全杀（摘第④类出口 / 响应头并回 stdout / 头文件读了又丢掉），控制组先绿 38 passed。
其中第 2 处第一轮记成**半红** —— 又是我的期望名单写错（该变异下 A2 的降级标记与 I1 的退出码本就不该动），
改正名单复跑即杀掉。

**文档**：台账 §0 轮次 52 / §6 第 99~100 行 / §7 那行数字与口径（四类退出码）；AGENTS 两处（38 断言、四类读不到）。

**同轮第二批（第一次门禁直接拦下两处，COMMIT_EXIT=1）**
- `tests/test_ai_config.py` 的 **B13**「域名解析不了 → unreachable」红成 `http_error`，代码一行没动。
  真因是用户此刻开着系统代理，而 **Windows 的代理写在注册表里、不在环境变量里**：`os.environ` 搜不到 proxy 键，
  `urllib.request.getproxies()` 照样返回 `127.0.0.1:10810`。那次发往 `.invalid` 的请求由代理解析，
  代理回了 503 → 分类被改写。取证两条：带代理 → `HTTPError 503`；进程内设 `no_proxy=*` → 真 `getaddrinfo failed`。
  修法只在**测试进程内**钉死 no_proxy（用户真实出站照旧走他的代理），并加 A0 前提自证；
  摘掉钉死复跑 → A0+B13 同时红（78 passed, 2 failed）证明这条判据有牙，逐字节还原后回绿。
- **I4 拦下 `watch_ci.py` 新增的 `os.unlink`**（删自己 `mkstemp` 出来的响应头临时文件）。
  这不是噪声，是门禁按设计工作：每个物理删除调用点都要写清「为什么删不到真实语料」。
  白名单加一条并注明理由后 `test_invariants` 87 条全绿。

## ⑤ 踩过的坑（绝对不要再踩）

1. **分类清单要按「还有什么读得到但用不了」重排，而不是按当时想到的几种。** 上一轮我写「三类读不到分开点名」
   并以为穷尽了，真机第一次跑就撞上第四种（200 + 非 JSON 正文）。**能返回 200 不等于能用**；
   而漏掉这一类的后果比文案误导更糟 —— 直接崩栈，连分类都没有。
2. **不要在一条流里同时取响应头和正文。** `curl -D -` 在 CONNECT 代理下会多吐一段隧道应答，
   任何"按空行切分"的口径都会整体错位。头归头文件、正文归正文、状态码归 `-w`，三者分开。
3. **本地 `node_modules` 带冲突装好 = CI 的雷。** 新增 CI 步骤必须**当场拿一个真 run 号回执**，
   否则账上只能写「接了但没验」。§7 早就立了这条口径，本轮 §6 第 100 行是它第一次被实物验证。
4. **代理与直连哪条通，每小时都可能不一样。** 别把上一小时的实测当这一小时的用：
   先看 `netstat` 里 10810 在不在监听，在就带代理推；不在就用一条只读 `git ls-remote` 实测直连再下结论。
5. **「半红」先分清是哪一种**（本轮又踩一次期望名单写错）：改坏后哪几条**必然**变形，
   是拿变异语义推出来的，不是拿断言名字联想出来的。
6. 老账新账都提醒一遍：**中文串里嵌 ASCII 双引号会把 Python 字符串切断**、
   **度量脚本自己也要 GBK 安全**、**破坏性写入要 `try/finally` 先还原再报名**。

7. **判据的结论不能取决于这台机器此刻开没开代理。** Windows 系统代理写在注册表里，
   `env | grep proxy` 查不出来，却照常劫持 `urllib`。凡断言「某种网络失败形态」的判据，
   都要在测试进程内钉死 `no_proxy`（或改用回环上的关闭端口），并配一条前提自证（A0 那种）。
   本轮 B13 就是这么红的：同一条断言，代理开着 = `http_error`，钉死 = `unreachable`。
8. **新增删除类调用点会被 I4 拦下，这是特性不是 bug。** 白名单那条要写清「为什么删不到真实语料」
   （路径来源、是否接受入参、在不在 `content/` 下），删掉调用点时也要同步删条目，否则 stale 也报红。
